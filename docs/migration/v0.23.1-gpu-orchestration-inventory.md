# P0 Inventory · GPU Orchestration (7 legacy modules)

> Baseline: v0.23.0 release commit `0f4d7362` (branch `feat/26-07-18` at P0 start).
> Generated as part of the v0.23.1 GPU arbitration orchestration modularization
> (see `docs/plans/2026-07-17-v0.23.1-gpu-arbitration-orchestration-modularization.md`).
>
> This file freezes the baseline `__all__`, in-repo named imports, public-looking
> result types, module-object / monkeypatch targets, and the target symbol → new
> module mapping used to define the safe facade contracts for the 7 GPU
> orchestration modules. The new `gpu_arbitration` package must re-export every
> facade member with unchanged identity, signature, enum value, and dataclass
> shape; private symbols move to the new package internals.

## I. Dependency direction (target DAG)

```
contracts  (leaf)
   ↑
policy  ← contracts
signing        (leaf)        rollout_state  (leaf)        collector_database (leaf)
   ↑                              ↑
fences ← policy             [ml_client ← contracts, policy, rollout_state]
   ↑
proofs ← contracts, policy, fences, ledger
   ↑
control_preparation ← contracts, fences, proofs
   ↑                              ↑
reconciliation            retirement ← (proofs, fences, ledger, ml_client)
← policy, fences, proofs, ledger
   ↑
dispatch ← contracts, policy, signing, fences, proofs, ledger, ml_client
membership_activation ← contracts, signing, fences, proofs, control_preparation, ml_client
rollout_control ← contracts, signing, rollout_state, fences, proofs, control_preparation, ml_client
```

No edge may point upward against this DAG; no function-local import may mask a cycle;
`ml_client` imports only `contracts`, `policy`, `rollout_state`.

## J. Frozen runtime contracts (no-change surface)

1. HTTP/WS paths, status codes, error bodies, `Retry-After`.
2. Celery task names, queue routes, worker registration, dispatch order.
3. SQL text, params, row-lock order, transaction commit boundaries, DB clock reads.
4. Redis keys, Lua SHA-256, KEYS/ARGV order, TTL, CAS atomicity.
5. generation / control epoch / membership epoch / token horizon / retirement proof monotonicity.
6. Admission token alg/kid/aud/scope/claims/JTI/expiry + signing key read behavior.
7. Public function/class object identity, call signature, defaults, exception types, enum values, dataclass field order.
8. rollout state / membership promotion / reset-mode ACK / dispatch outcome / tombstone receipt reason+status.
9. Structured log event names, reason, status, `gpu_arbiter` doc fields.
10. old→new + new→old cold-import order; cold start of `app.main`, API routes, worker entries, validation script.

Allowed to change: `__module__`, traceback file path, default logger module name; private test patch paths (repointed to new modules); version number in the release commit (OpenAPI must be byte-identical except `info.version`).
