## 4. Real defect and fix **[F]**

`apps/web/src/hooks/useTaskViews.ts::useDataManagerSchema` now sets `retryOnMount: false`.

- **Symptom:** when the schema request fails, `ProjectDataManagerPage` shows the loading shell because `schemaQ.isLoading` is true; it unmounts the error branch; remounting that branch makes React Query retry the errored query (`retryOnMount` default `true`), which returns to loading and repeats. Locally this produced hundreds of schema requests and the retry UI never appeared.
- **Regression:** `apps/web/src/pages/Projects/ProjectDataManagerPage.schemaError.test.tsx` renders the page against a 500 schema response and asserts the retry action appears, exactly one schema request is made, and no task query is issued unintentionally.
- **Failing-before / passing-after [V]:** with the `retryOnMount: false` line removed (pre-fix behavior) the regression fails in 13.6s with `Unable to find role="alert"` as the page cycles loading ↔ error; with the fix restored it passes in ~0.3s and the MSW handler records two schema requests (initial load + explicit retry). Captured in `/tmp/aap-p3-schema-before.log`.
- **Commit:** separate `fix(web): ...` commit from the test refactor, including the `CHANGELOG.md` Fixed entry and the `docs-site/user-guide/projects/data-manager.md` retry note.

## 7. Rollback boundary

- The refactored tests and fixtures are additive/isolated; reverting the P3 test commit restores the previous page flow suite without touching product behavior.
- The defect fix is one hook option; `git revert` removes it and the regression test documents the expected behavior if it is reverted deliberately.
- No migration, lockfile, generated type, API contract or CI workflow was changed.
