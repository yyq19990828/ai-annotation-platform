# v0.20.14 · 父子标注画布同胞高亮

状态：**已落地（v0.20.14）**。补 v0.20.9 首版显式延后的画布呈现——「选中父框 → 其子框在画布上描边高亮」。
**依赖 v0.20.9**（父子数据模型 + 侧栏缩进呈现）。ROADMAP §C.3（P3）对应项。

> 落地记：探查发现 `BoxRenderer`（DOM 层）**已无消费方 = 死代码**，图片任务只走 `ImageStage`（Konva）单栈——
> plan 里「跨 DOM/Konva 双栈」顾虑消解。且未逐 shape 穿 prop，改用**统一高亮环 overlay**（绕子框 bbox
> 画细点线，一处搞定所有几何类型），比原设想更省。派生逻辑抽 `siblingHighlightChildren` 纯函数 + 单测。

## 背景

v0.20.9 落地了父子标注的**侧栏缩进呈现** + 后端一层约束 + 级联删，但画布上「某父框的子框归属」只能靠
选中态高亮父框本身，一眼看不清它有哪些子框。v0.20.11–13 的选中框二次推理会让子框**在画布上批量出现**
（车牌等），同胞高亮的价值此时变实。当时延后的理由是「跨组件横切」——要把新 prop 串进
`KonvaBox` / `KonvaPolygon` / `KonvaRotatedBox` 等多种 shape、跨 `BoxRenderer`（DOM 层）
/ `ImageStageShapes`（Konva 层）/ video / 3D 多处调用点。

## 关键抓手（已核实）

- **可复用即将退役的 group outline 视觉槽**：`ImageStageShapes.tsx` 里 shape 已有基于 `b.group_id` 的
  二级描边（`groupOutlineColor(b.group_id)`，独立于选中态的 stroke）。组框功能 v0.20.9 已声明即将退役
  → 这条「同胞关系描边」的渲染路径正好可**改挂到 `parent_annotation_id`**，避免新增第三层描边逻辑。
- shape 组件已统一吃 `selected: boolean`；同胞高亮同理加一个派生 flag（如 `siblingHighlighted`）。
- 选中集来自上层派生；子框集 = `annotations.filter(a => a.parent_annotation_id === selectedId)`。

## 工作项

### WS1 · 派生「选中父框的子框 id 集」

- 在标注列表派生层（`transforms` / shell model）算出 `highlightedChildIds: Set<string>`：
  当且仅当选中的是单个框时，取其直接子框 id。选中的是子框时可选高亮其父（对称，待定，见风险）。

### WS2 · shape 层描边

- 给 `BoxRenderer`（DOM）+ `ImageStageShapes`（Konva 的 KonvaBox/Polygon/RotatedBox/keypoint）
  加 `siblingHighlighted?: boolean`，命中时画一条区别于选中/组的描边（虚线或异色，复用/改造
  `groupOutlineColor` 那条 Rect 的挂载点）。
- video / 3D：本版**仅图片任务**（父子当前限帧内，video 走 track；3D 暂不做），video/3D 的 shape
  加 prop 但恒 false，避免签名分叉。

### WS3 · 视觉规范

- 同胞描边要与「选中态」「（退役中的）组描边」在视觉上可区分，写进 `design-system.md` 的画布描边语义。

## 风险

- **跨组件签名扩散**：这是延后的主因。控制在「加一个可选 bool prop + 一条描边」，不改选中/命中判定主逻辑。
- group outline 与 parent-child outline 若共存一段过渡期，需明确二者视觉与优先级；组退役后该槽单一归父子。
- 选中子框时是否反向高亮父框：对称好用但增加派生复杂度，**首版只做「选父高亮子」单向**，反向列后续。

## 验收

- 选中一个有子框的父框 → 画布上其所有子框出现同胞描边；选中无子框的框 → 无描边。
- 切换选中 / 取消选中 → 描边即时更新。
- video / 3D 任务不受影响（prop 恒 false）。

## 依赖 / 不在范围

- **依赖 v0.20.9**；与 v0.20.11–13 子框产出联动价值更实。
- 不做：反向（选子高亮父）、video/3D 同胞高亮、Alt 拖动联动（→ v0.20.15）。
