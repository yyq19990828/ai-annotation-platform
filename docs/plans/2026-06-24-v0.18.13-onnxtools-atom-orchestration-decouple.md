# v0.18.13 — onnxtools 原子类直架单模型 + 删 visibility 改 composition 过滤 + 单阶段配置修复

> 状态:**已细化 / 待启动**。前置依赖 [[2026-06-24-v0.18.12-gsam2-box-to-mask-atom-geometry-prompt]] 已完成。
> 关联:onnxtools 原子化(v0.18.9)、composition 维度(v0.18.12)、staged-preannotate epic。

## 1. 背景

onnxtools backend 在 `/setup` 广播三个 model(v0.18.12 后已带 `composition`):

| model | task | composition | visibility(现状) | 用途 |
|---|---|---|---|---|
| `vehicle-attr`(一锅端:检测+属性) | detection | composite | internal | 单后端开箱即用 |
| `vehicle-detect`(纯检测) | detection | atom | public | 多阶段上游 |
| `vehicle-attr-classify`(纯分类) | classification | atom | public | 多阶段下游 |

**当前实现的问题(原子层架在 pipeline 上,而非单模型类):**
`VehicleAttributePredictor`(`predictor.py:135`)只持有一个 `VehicleAttributePipeline`,三个 model 共用之:
- `predict_one` → `self._pipeline(img)`(一锅端,`:153`)
- `detect_one` → `self._pipeline.detector(img)`(`:172`,**伸手进 pipeline**)
- `classify_one` → `self._pipeline.va_classifier(img)`(`:198`,**伸手进 pipeline**)

构造时(`main.py:66-72`)一次性 new 整个 pipeline → **rtdetr 与 va_classifier 永远同时加载**。
原子只是从 pipeline "借"子模型,与内部编排类强耦合。

**单阶段 UI 连带症状(原 Issue 1):**
- `vehicle-attr` 为 `internal` → v0.18.12 起被「默认模型 + 几何模型列表 + 工作台选择器 + 属性导入」四处统一过滤,
  单阶段也连带过滤掉一锅端。
- 配置 UI 单阶段「模型任务」下拉门槛是 `taskModels.length > 1`(`PreannotateConfigForm.tsx:142`);
  internal 过滤后 onnxtools 单阶段只剩 `vehicle-detect` 一个 → 下拉**不渲染** → "没有模型显示"。
- 单阶段实际下发 `vehicle-detect` → **只出框、无属性**。即 v0.18.9 拆原子时,把单后端"检测+属性一把梭"
  从单阶段路径弄丢了,用户无感。

## 2. 决策(本轮已对齐)

- ✅ **原子层直架单模型推理类**:`detect` 原子直接构造 `RtdetrORT`(经 `create_detector`),`classify` 原子直接构造
  `VehicleAttributeORT`,各自独立实例,**不再绕 `self._pipeline.detector / va_classifier`**。这是真解耦——原子获得应有的
  轻量性:配合懒加载,只用 detect 的部署只加载 `RtdetrORT`、只用 classify 只加载 `VehicleAttributeORT`(同一镜像内即可,
  **不做精简镜像变体**)。
- ✅ **composite 仍跑 `VehicleAttributePipeline`(过渡保留)**:`VehicleAttributePipeline` 是 0.18.0 为跑通链路的实验类,
  **迟早退役**(待平台层把「detect 原子 → classify 原子」两阶段编排做熟后,一锅端改由平台编排两原子)。退役的**仅此一个类**,
  单模型原子类是长期地基。过渡期 `predict_one` 继续整跑 pipeline,**不把 ROI / 机动车判定逻辑搬进 backend**(那是 pipeline 的事,
  它要退役,不值得搬)。
- ✅ **删 `visibility` 字段**:`visibility` 是「拿全局可见性当 composition 用」的重载 hack,且全平台仅 onnxtools 一处声明
  `internal`(yolo/gsam2/sam3 均无)。v0.18.12 引入 `composition` 后该字段冗余,**整字段删除**(协议 / schema / 前端 / 测试)。
- ✅ **过滤改 composition 轴**:`vehicle-attr` 不再靠 internal 隐藏。**编排下游 stage 选择器**按 `composition !== "composite"` 过滤
  (编排只组合 atom,不把任何一锅端——含 gsam2/sam3 的 composite——塞进来当 stage);**单阶段 / 工作台**不过滤,全显示。
- ✅ **单阶段默认走一锅端**:单阶段选 onnxtools,「模型任务」下拉出 **`vehicle-attr`(composite,默认)+ `vehicle-detect`(atom)**,
  默认选一锅端(出框+属性,开箱即用)。**排除 `vehicle-attr-classify`**——纯分类需上游框做输入,单阶段独立跑无意义。
- ✅ **永远显示当前 model**:配置面板加一行只读"当前模型:xxx",不依赖 `> 1` 才出下拉。
- ✅ **本版加 `/unload` + idle-unload**(原 Issue 2):rtdetr+va 常驻占显存,与 gsam2/yolo 共享 GPU,值得加;
  加了就自动出现在 ModelMarket 卸载按钮,UI 零改动。运行态管理仍归 ModelMarket 一处,预标配置面板不内嵌 load/unload。

## 3. 前置确认 —— 已核实(favorable)

单模型推理类在 onnxtools 包(运行时 `pip install git+https://github.com/yyq19990828/onnxtools.git@main`;
源码工作副本在仓库 `third-party/onnxtools/onnxtools/`)中**作为顶层符号可独立构造**:

- `onnxtools.create_detector(model_type, onnx_path, conf_thres, iou_thres, **kwargs)` → 内部按 type 返回
  `RtdetrORT`(`infer_onnx/onnx_rtdetr.py:119`) / `YoloORT` / `RfdetrORT`,只给检测权重独立 new。
- `onnxtools.VehicleAttributeORT(onnx_path, type_map, color_map, conf_thres, providers)`(`infer_onnx/onnx_cls.py:595`)
  → 只给分类权重独立 new;`__call__(vehicle_crop)` 出车型/颜色。
- `BaseORT.class_names`(`infer_onnx/onnx_base.py:84`,读 ONNX metadata)→ `RtdetrORT` 实例**直接有 `.class_names`**,
  detect 原子取类名不必再绕 pipeline 的 `_resolve_class_names`。
- `VehicleAttributePipeline.__init__` 内部即 `create_detector(...)` + `VehicleAttributeORT(...)` 两行;composite 路径继续用它。

⟹ 不需要给 onnxtools 包提 PR。

## 4. 改动面

### 4.1 onnxtools backend
- `predictor.py`:`VehicleAttributePredictor` 改为持有三类句柄——`detector`(`RtdetrORT`)、`va_classifier`(`VehicleAttributeORT`)、
  `pipeline`(`VehicleAttributePipeline`,composite 用)。`detect_one` → `self.detector(img)` + 读 `self.detector.class_names`;
  `classify_one` → `self.va_classifier(crop)`;`predict_one` → `self.pipeline(img)`。
- `main.py` lifespan:按 model_id **懒加载**对应句柄——detect-only 请求不触发 va_classifier / pipeline 加载,反之亦然;
  composite 请求才加载 pipeline。避免无谓加载。
  ⚠️ 双加载提示:若同进程既调 composite(pipeline 内部自建 detector+va)又调 atom(独立 detector+va),同型模型会各加载一份。
  过渡期可接受(composite 终退役);若显存吃紧,后续可让 pipeline 复用 atom 实例(动 pipeline 构造,不在本版)。
- `/setup`:删 `vehicle-attr` 的 `visibility` 行(及相关注释);三 model 保留 `composition`。
- `/unload` 端点 + idle-unload 计时器(参考 gsam2/yolo 既有实现),按 model 粒度释放各自句柄。
- 三个 model 的 `predict` 路由对外不变(`model_id` 路由)。

### 4.2 协议 / 平台(删 visibility)
- `apps/api/app/schemas/ml_backend.py:116`、`ml_capabilities.py:100`:删 `visibility` 字段。
- `services/ml_capabilities.py`:`_normalize_model` / `_shape_models` 删 `visibility` 透传。
- 测试:删 visibility 相关断言。

### 4.3 前端(删 visibility + 过滤改 composition + 单阶段)
- 删 `MLModelCapability.visibility`(`api/ml-backends.ts`、`api/mlCapabilities.ts:80`)+ `ModelCard.tsx:60` 的「内部」徽标。
- **5 个过滤点改造**(逐处定轴,见 §5.1):
  - 编排下游 stage(`StageCard.tsx:197`)→ 改 `composition !== "composite"`。
  - 单阶段(`usePreannotateConfig.ts:142/149/175`)→ 取消 visibility 过滤(全显示;onnxtools 出 attr+detect+classify,
    其中 classify 由「单阶段排除纯分类 task」规则再滤掉)。
  - 工作台(`Workbench/state/useMLCapabilities.ts:66`)→ 取消 visibility 过滤(保留 composite 可手动选)。
- 单阶段 onnxtools 选项:`vehicle-attr`(默认)+ `vehicle-detect`,排除 classification task 的纯分类(需上游框)。
- `PreannotateConfigForm` / `usePreannotateConfig`:新增"当前模型"只读展示(单 model 也显示,去 `> 1` 门槛约束);
  多 public model 时仍走下拉显式选。
