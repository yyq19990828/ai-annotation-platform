## 1. 审核结论

初稿方向成立，但不能按原文直接开工。仓库当前已经具备以下基线，后续只做增量强化：

- `useRasterMaskRecords` 已按 crop alpha + bitmap 估算字节，默认预算 128 MiB、并发 4，并在淘汰、
  scope 切换和卸载时关闭 `ImageBitmap`；不再存在“只有固定 96 条”的实现。
- RLE 分析已经在 Worker 中完成，主线程稳定态只保留 cropped alpha / bitmap；单项失败不会清空整帧记录。
- Worker 返回的 alpha / instance plan 已使用 transferable buffer；当前主要浪费来自每次调用新建 Worker、
  输入 RLE 的结构化克隆，以及编辑会话没有复用计算上下文。
- history 当前保存最多 20 组 before / after COCO RLE，不是全帧 `Uint8Array` snapshot；但是 noise、
  morphology 和大画布仍会产生高额复制与 JS 数组开销。
- `MaskOverlayLayer` 每个编辑会话仍创建整图 canvas，`MaskBuffer` 仍分配 `width × height` alpha；这两处连同
  Pydantic / API codec 的 4096 上限，才是 5K / 8K 的真实阻断点。

因此本版不重做既有 crop/cache，而是完成四个闭环：**硬预算 admission、可复用 Worker pool、XOR tile
history、图片专用 sparse tile editor**。图片持久格式继续是 canonical COCO RLE；视频和交互式 AI 的尺寸
边界不随图片上限放大。

## 2. 成功定义

v0.23.10 完成时必须同时满足：

1. 720p / 1080p / 4K 视频 Mask 在快速切帧和多实例显示下，缓存字节、活跃 bitmap 和 Worker 数进入稳态；
   task / frame / version 变化后的旧结果零回写。
2. 小画布的 brush、lasso、高级操作与保存语义不变；历史不再为每个 stroke 构造前后两份 RLE。
3. 图片宽高可到 8192、总像素可到 67,108,864；超过 dense 门槛时进入 tiled 模式，brush / erase /
   lasso add / subtract 不分配整图 alpha 或整图 overlay canvas。
4. tiled 模式保存仍生成 canonical COCO RLE，刷新后逐像素一致；未访问 tile 直接复用 base RLE，不先
   materialize 全图。
5. 全图操作超过预算时显式进入 ROI / 不支持状态，不静默回退主线程，也不让页面冻结或 OOM。
6. Worker crash、timeout、取消和低内存降级都保留当前稿件，且有稳定错误原因与重试路径。

## 3. 冻结预算与尺寸合同

### 3.1 持久内容与媒体边界

| 合同 | 冻结值 |
|---|---:|
| 图片 Mask 最大单边 | 8192 px |
| 图片 Mask 最大像素 | 67,108,864 |
| 视频 Mask 最大单边 | 4096 px，保持不变 |
| 交互式 AI inline Mask 最大单边 | 4096 px，保持不变 |
| canonical RLE 最大 runs | 1,000,000，保持不变 |
| canonical JSON 最大 bytes | 4 MiB，保持不变 |
| dense editor / 全图同步代数最大像素 | 16,777,216 |
| tile 边长 | 512 px |
| morphology 最大 halo | 32 px，与现有 radius 上限一致 |

`CocoRleMaskRef` / `CocoRleContent` 的结构级尺寸允许 8192；真正的媒体边界由 task-aware validator 再
收窄。`raster_mask` 可用图片上限，`video_track_mask` 继续拒绝任一边超过 4096。`ml_interaction_proxy`
使用独立 AI 常量，不能因为共享 codec 放宽而接受 8K inline 候选。

8K 50% noise / 棋盘格会超过 runs 或 4 MiB 合同；它们是稳定拒绝和内存保护 fixture，不是承诺可持久化的
生产内容。稀疏工业缺陷、全景小目标和普通实心区域才是本版 8K 写路径。

### 3.2 浏览器设备档位

`navigator.deviceMemory` 缺失时使用 Standard，不根据一次运行中的 heap 临时抬高预算。

| 档位 | 判定 | 只读记录缓存 | 下载 / decode 并发 | Worker pool | tile 缓存 | history |
|---|---|---:|---:|---:|---:|---:|
| Low | `deviceMemory <= 2` | 64 MiB | 1 | 1 | 32 MiB | 16 MiB |
| Standard | 未知或 `2 < deviceMemory < 8` | 128 MiB | 2 | 2 | 64 MiB | 32 MiB |
| High | `deviceMemory >= 8` | 192 MiB | 4 | 2 | 128 MiB | 64 MiB |

所有预算是硬上限，不允许因为 active descriptors 全部被视为 pinned 而持续突破。只有当前选中 / 编辑对象
可以 pin；新对象无法 admission 时进入 `deferred` 或 `budget_exceeded`，保留轻量 bounds / 状态并在被选中、
预算释放或显式重试时重新排队。单个对象也不能突破硬上限；超大 dense 对象使用低分辨率 preview + RLE
精确点命中，设备仍不足时进入只读说明态。

history 最多 100 条命令，同时受字节预算约束；淘汰顺序始终是最旧 undo。redo 在新写入后整体释放并计入
预算，不得成为第二个无界队列。

### 3.3 Worker 生命周期

- pool queue 最大 32；编辑 / 当前帧高于预取，FIFO 只在同优先级内成立。
- analyze timeout 15 秒，普通 operation 30 秒，8K tile merge / encode 60 秒。
- abort / timeout 会终止执行该 job 的 Worker 并补充新 Worker；其它 slot 不受影响。
- task / route 卸载后 pool 终止；HMR / test dispose 也必须归零。
- 结果仍绑定 `sessionId + generation + operationId`；过期结果即使计算完成也不能回写。

## 4. 关键技术合同

### 4.1 缓存 admission 与精确释放

`useRasterMaskRecords` 保留现有 crop 结果，但拆开 `active` 与 `pinned`：

1. descriptor 按「正在编辑 → selected → 当前帧 → 相邻预取」排序。
2. admission 前按 crop alpha、bitmap RGBA、RLE typed counts 和预览索引估算 retained bytes。
3. 先淘汰未 pin LRU；仍超预算则不插入，不能先插入后等待下一轮清理。
4. cache replace、scope / version 变化、错误、unmount 均只 close 一次 bitmap。
5. 增加 live records / alpha bytes / bitmap bytes / queued / in-flight / created / closed 计数器；测试不依赖
   浏览器是否把 GPU external memory 计入 `usedJSHeapSize`。

Mask 内容 URL 已返回 immutable sha256 ETag 和 `Cache-Control`。本版验证浏览器条件缓存，不在 React Query
中复制第二份长期 RLE cache；相同 sha256 的并发请求必须 single-flight。

### 4.2 可复用 Worker 与 transferable 输入

新增 `RasterMaskWorkerPool`，统一承载 analyze、operation、instance operation、tile decode 和 tile merge：

- COCO counts 在边界转换为 `Uint32Array` 后 transfer；Worker 内部不长期保留调用方 JS `number[]` 副本。
- analyze 输出 crop alpha、operation / instance 输出继续 transfer；不得把同一 ArrayBuffer 同时留在两端。
- 测试 fallback 仍显式 `createWorker: null`；生产环境无 Worker 时返回稳定 error，不偷偷在主线程执行大操作。
- pool 支持注入 Worker factory / clock，确定性验证 queue、优先级、timeout、abort、crash replacement 和 dispose。
- 会话可注册 immutable base RLE；同一 sha256 的 tile decode 复用 counts / run index，切 version 后释放。

### 4.3 XOR tile history

history command 不存 before / after RLE，而存 512 tile 粒度的 XOR bitset：

```text
MaskHistoryCommand
  name
  sourceRevision
  patches[] = { tileX, tileY, width, height, xorBits }
  changedPixels
  chargedBytes
```

- `xorBits` 每像素 1 bit；undo / redo 对当前二值 tile 执行同一个 XOR，天然双向。
- brush stroke 第一次触碰 tile 时只捕获该 tile 的局部基线；结束时生成 XOR 并释放临时 alpha，不复制整图。
- lasso / operation 以 changed tile 生成 XOR；no-op 不入历史。
- 一个 8192² 全图 XOR 上限约 8 MiB，可被所有档位容纳；命令还必须满足 tile / changed-pixel 预算。
- history 淘汰不修改已提交 annotation history；保存失败、Worker 失败和取消均保留本地命令。

### 4.4 Sparse tile store 与 canonical RLE merge

`SparseMaskTileStore` 的真值由 immutable `baseRle` 加 materialized tile override 组成：

- blank base 使用单个全零 run；已有 Mask 按 counts cumulative index 对单个 tile 解码，不先生成全图 alpha。
- tile key 是 `tileY:tileX`，边缘 tile 记录真实宽高；空 override 可回收，但 history 引用期间不能提前丢失。
- brush / erase / lasso 只 materialize 相交 tile；跨 tile 坐标使用全图像素坐标，边界规则与 dense editor 相同。
- viewport 只 pin 可见 tile + 1 tile 预取环；缩放到全图时使用受限 overview preview，preview 不参与写入或命中真值。
- 选中大 Mask 的精确 picking 通过 RLE run index / 已 materialize tile 完成，不用 overview 像素冒充真值。
- tiled overlay 使用每 tile canvas / bitmap；禁止创建 `width × height` canvas、ImageData 或 alpha。

保存时在 Worker 中按 COCO column-major 顺序合并：未 materialize 区间直接复用 base RLE，override 区间读取
tile 列并合并相邻同值 run。算法复杂度与 base runs + materialized tile pixels 成正比，而不是固定扫描 8K
全图；输出再次校验总像素、runs 和 canonical bytes 后才上传。取消 / timeout 不 detach 主 store，也不清 history。

### 4.5 大操作降级

- 图片任一边超过 4096 或像素超过 16,777,216 时进入 tiled editor。
- brush / erase / lasso add / subtract 必须可用；保存、撤销、重做和刷新 round-trip 必须可用。
- morphology 可在显式「当前视口 ROI」执行：读取 `ROI + halo`，只把 core 写回；结果必须与 dense 全图算法
  在该 core 完全一致。
- flood fill、component / hole、split / join / overlap 和全图 morphology 若需要扫描超过 16,777,216
  像素，则禁用并显示稳定原因 `large_mask_full_scan_required`；本版不伪装成局部等价，也不新增后台 job。
- Low 档位若 overview + 当前可见 tile 仍无法 admission，则保持只读 preview，并显示建议放大 ROI / 换高内存
  设备；不能崩溃或无限重试。

## 6. 性能退出门

在 M0 基准机、Playwright 自带 Chromium、2 次 warmup + 20 次记录下至少满足：

| 场景 | 通过条件 |
|---|---|
| 1080p，20 个 SAM 风格 Mask，播放 300 帧 | record cache 不超过档位预算；warmup 后 GC heap 墧量 ≤ 16 MiB；live bitmap / Worker 回到基线 |
| 4K，5 个 Mask，20 strokes + undo / redo | pointer p95 ≤ 16 ms；pointer-up 主线程 p95 ≤ 50 ms；history 不出现全图 RLE 双份增长 |
| 快速切换 50 帧 / 10 task | stale commit = 0；in-flight 不超过档位；最终 queue = 0；GC heap 增量 ≤ 16 MiB |
| 8K sparse 图片，20 次局部 brush / lasso | 主线程不存在 `width × height` alpha / canvas；materialized tile 仅为相交 tile；单次交互无 >50 ms 连续 Long Task |
| 8K sparse save / reload | Worker merge p95 ≤ 5 s；canonical RLE 逐像素一致；取消 / 失败保留 tile 与 history |
| Worker crash / timeout | 1 个 slot 被替换，其它 job 可继续；UI 1 s 内恢复响应并提供重试 |

`usedJSHeapSize` 不是 bitmap 泄漏的唯一证据。退出门同时使用显式 created / closed / live counters；heap
snapshot 只用于归因，不把 committed heap 未立刻归还等同于可达对象泄漏。

## 7. 浏览器验收矩阵

1. 1080p 图片显示 20 个真实形状 Mask，反复显隐 / 选中后 cache 不突破档位预算，淘汰对象显示 deferred
   而不是无限 reload。
2. 视频播放 300 帧并快速 seek 50 帧，旧响应不回写当前帧；bitmap、request、Worker 计数回稳。
3. 一个 Mask 404 / 409 corrupt / 500 时其它对象继续 ready；retry 只重试目标对象。
4. 4K brush、erase、lasso 跨 512 边界，20 次 undo / redo 后与初始 / 最终 RLE 逐像素一致。
5. history 超预算只淘汰最旧 undo；新 stroke 清 redo，当前稿件和服务端 history 不受影响。
6. 高级操作连续执行 20 次只复用固定 Worker；取消、timeout、crash 均保留输入和 history。
7. 8192×8192 blank Mask 在四角与 tile 交界绘制，只创建相交 tile；保存刷新后像素一致。
8. 7680×4320 已有 sparse RLE 只加载当前 viewport + 预取环；在未访问区域保存时原 base 内容不变。
9. 8K lasso subtract / erase 能覆盖 base RLE 前景；exact picking 不使用 overview preview 的近似像素。
10. 8K viewport morphology 的 core 与 dense golden 一致；全图 hole / component / split 显示
    `large_mask_full_scan_required` 且不会启动 Worker。
11. Low 档位模拟下超预算对象进入只读 / deferred，切回可 admission 对象后正常编辑，没有 OOM 或请求风暴。
12. 图片 8192 内容可上传读取；视频 / AI 4097 稳定拒绝；runs、bytes、总像素边界保持稳定原因。
13. 保存期间取消、切题和版本冲突均保留 dirty tile；显式丢弃后才释放 tile / history / Worker session。

## 8. 非目标

- 不承诺无限分辨率、无限实例或 8K dense noise 可持久化。
- 不把 tile 暴露为 AAP / COCO / 对象存储格式，不迁移既有 RLE object。
- 不引入 WebGPU、WASM 或新的图像处理依赖作为硬要求；CPU / Worker 是唯一必需路径。
- 不做 8K 全帧视频 tracker、语义 / 全景 class-map、软笔刷、羽化 alpha 或颜色容差 fill。
- 不新增后台 Mask operation job；超预算全图操作只做显式 ROI / 禁用。
- 不借本版重写 Konva 工作台、通用 annotation bulk API 或 v0.23.9 的原子 mutation 语义。
