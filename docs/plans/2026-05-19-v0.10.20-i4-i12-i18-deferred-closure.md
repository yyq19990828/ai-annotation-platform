# v0.10.20 · I4 / I12 / I18 deferred 收口 + ADR-0027 第二段

> 版本目标:v0.10.19 epic 留下的 **5 项 deferred** 在 v0.10.20 一次性收口,与 ADR-0027 三段式迁移的"第二段(view + 双写)"对齐落地。本期**不引入新 epic**,只补齐 v0.10.19 已铺好的契约。

---

## Context — 为什么在本期一次性收口

v0.10.19 把 I4/I12/I18 的**后端契约 + 前端核心 UI**一次落地,但为了控制单 PR 体量,5 项 UI 完善与 ADR-0027 第二段迁移延期。后端契约已固化:

- `annotation_feedbacks` 表 + GET/POST/PATCH/DELETE/replies 路由(`apps/api/app/api/v1/annotation_feedbacks.py`)
- `annotations.group_id` + `tasks.next_group_seq` + `POST /annotations/group|ungroup|bulk-update`(`apps/api/app/api/v1/annotations.py`)
- `GET /tasks/{id}/comments/page` / `GET /tasks/{id}/audit-history`(任务级聚合读端点)
- `useAnnotationGroup` / `useAnnotationUngroup` / `useAnnotationBulkUpdate` hook
- `useTaskCommentsInfinite` / `useTaskAuditHistory` hook
- `useFeedbacks` / `useCreateFeedback` / `usePatchFeedback` hook
- `Ctrl+G` / `Ctrl+Shift+G` 快捷键 + `ImageStageShapes` group 虚线外圈渲染

剩 5 项**纯 UI / 双写迁移**工作未做,本期把它们闭合,让 ROADMAP §C.7 三项工作台扩展真正可用。

## 5 项 deferred 清单与决策

### D1 · I4 完整拆分 — DiscussionPanel + 右栏两段 + 任务级评论

**目标**:把 `CommentsPanel` 从 `AIInspectorPanel` 内嵌升级为独立 `DiscussionPanel.tsx`,`WorkbenchLayout` 右栏改为 flex 两段(上检查器 / 下讨论),并打通**任务级评论**写入(未选中标注时直接发"对整张图打条评论")。

**任务级评论的后端落点(决策)**:**不**新加 `POST /tasks/{id}/comments` 端点,直接复用 v0.10.19 已落的 `POST /feedbacks`(kind=`comment`, anchor_type=`task`, task_id=current)。理由:
- ADR-0027 明确"未来所有反馈写入都走 `annotation_feedbacks`"。新增任务级评论是新写入路径,应该一开始就走新表,不污染旧 `annotation_comments` 表(annotation_id NOT NULL 也需要破坏现有约束)。
- 减少端点数量,DiscussionPanel 在 annotationId 为 null 时直接 `useCreateFeedback({ kind:"comment", anchor_type:"task" })`。
- 任务级 GET 走"组合读":`useTaskCommentsInfinite`(读旧 annotation_comments,聚合 task 下所有 annotation 评论)+ `useFeedbacks({ task_id, kind:"comment", anchor_type:"task" })`(读新 task 级评论),前端按 created_at merge。v0.10.20 落 view 之后切到 view 统一读。

**前端拆分**:
- 新建 `apps/web/src/pages/Workbench/shell/DiscussionPanel.tsx`
  - props: `{ projectId, taskId, annotationId: string | null, currentUserId, taskFileUrl?, ... }`
  - 内含 Tabs: `comments | history | issues`(issues tab 复用 IssueListPanel 现有逻辑,只是从 panel 内联到 Discussion tab)
  - annotationId 非 null → 标注级模式:CommentsPanel(原)/ AnnotationHistoryTimeline(annotation 级)
  - annotationId null → 任务级模式:merged comments(annotation_comments 聚合 + task 级 feedback)+ task audit history;CommentInput 始终显示,提交时按 mode 决定走 `POST /annotations/{id}/comments` 还是 `POST /feedbacks`
- 改 `AIInspectorPanel.tsx`:删 `CommentsPanel` 渲染与相关 props(`backgroundUrl` / `enableCanvasDrawing` / `liveCanvas` / `commentAnchor` / `onSeekFrame` 全部下放到 DiscussionPanel)
- 改 `WorkbenchLayout.tsx`:右栏从单 slot 升级为 `<RightColumn>` flex column,top = `AIInspectorPanel`,middle = `<ResizeHandle vertical>`,bottom = `<DiscussionPanel>`;比例 localStorage key 用 `workbench.rightColumn.splitRatio`,默认 0.55(检查器略大于讨论)。
- 改 `WorkbenchShell.tsx`:派发 DiscussionPanel 需要的 props,并把原传给 AIInspectorPanel 的 comment 相关 prop 转到 DiscussionPanel。

**关键文件**:

### D2 · I12 完整 UI — BoxList group 折叠 + AttributeForm batch banner

**目标**:把 v0.10.19 后端的 group / bulk API 在 UI 层暴露出来,标注员看得见、用得到。

**BoxList group 折叠卡片**(在 `AIInspectorPanel.tsx`):

### D4 · ADR-0027 第二段 — view + 旧三表双写

**目标**:落实 ADR-0027 三段式迁移的第二段,准备 v0.10.21 切单源。

**视图**:
- 新建 alembic migration `0077_annotation_feedback_unified_view.py`(revision=0077, revises=0076)
- 创建 `v_annotation_feedback_unified` 视图(UNION ALL 4 个数据源):

  | 列 | annotation_feedbacks | bug_reports | annotation_comments | tasks.reject_reason |
  |---|---|---|---|---|
  | id | `id` | `id` | `id` | `gen 'reject-' \|\| task.id` UUID5 |
  | kind | `kind` | `'bug'` | `'comment'` | `'reject'` |
  | anchor_type | `anchor_type` | `task_id?'task':'project'` | `'annotation'` | `'task'` |
  | project_id | `project_id` | `project_id` | (via annotation.task.project_id) | `project_id` |
  | task_id | `task_id` | `task_id` | (via annotation.task_id) | `id` |
  | annotation_id | `annotation_id` | NULL | `annotation_id` | NULL |
  | anchor_position | `anchor_position` | NULL | NULL | NULL |
  | status | `status` | `status` | `'open' or 'resolved' from is_active` | `'open'` |
  | severity | `severity` | `severity` | NULL | `reject_reason_type` |
  | title | `title` | `title` | NULL | NULL |
  | body | `body` | `description` | `body` | `reject_reason` |
  | author_id | `author_id` | `reporter_id` | `author_id` | `reviewer_id` |
  | created_at | `created_at` | `created_at` | `created_at` | `reviewed_at` |
  | source_table | `'annotation_feedbacks'` | `'bug_reports'` | `'annotation_comments'` | `'tasks_reject'` |

  - 视图加 `source_table` 列方便对账 / 双写一致性校验
  - `reject_reason` 行仅在 `task.status='rejected' AND reject_reason IS NOT NULL` 时出现
  - `annotation_comments` 行仅 `is_active=true` 时出现(deleted=false)
  - 注意:DROP 视图在 downgrade 必须先于 DROP 关联表,否则会因依赖失败

**双写**:在 3 处旧写入路径加 mirror INSERT 到 `annotation_feedbacks`(同事务):
- `apps/api/app/services/bug_report.py`(`BugReportService.create`): legacy 写 + `feedback_service.create(kind="bug", anchor_type="project" or "task", project_id=..., task_id=...)`。复用 description 作为 body,title=bug.title,severity=bug.severity,author=reporter。
- `apps/api/app/api/v1/annotation_comments.py:create_comment`:legacy 写 + `feedback_service.create(kind="comment", anchor_type="annotation", annotation_id=..., body=...)`。
- `apps/api/app/api/v1/tasks.py` reject 写路径(line 1664-1665 附近):`task.reject_reason = ...` 之后调 `feedback_service.create(kind="reject", anchor_type="task", task_id=task.id, severity=task.reject_reason_type, body=task.reject_reason)`。
- 三处都用同一 SQLAlchemy session,事务保证一致性。失败回滚,不留半边写。
- 反向(feedback → 旧表)**不双写**,新增 task 级 feedback 不会回写到旧表(那是 v0.10.21 切单源后的旧表清理工作)。

**前端只读切换**(可选,优先级低):
- `useFeedbacks` 当前直接读 `annotation_feedbacks` 表;暂**不切**到 view 读,理由:view 读会让"老 bug_reports / reject"也出现在 DiscussionPanel 列表,UX 上未必合适。view 用于**后端对账脚本** + 未来 v0.10.21 切单源时的过渡。
- 如果 UX 决定要让 DiscussionPanel 同时展示旧 bug/reject 历史,加一个 `useFeedbacksUnified()` hook 走 `GET /feedbacks?include_legacy=1` 查 view,本期作为预留入口但 UI 不开放。

**关键文件**:
- 新建: `apps/api/alembic/versions/0077_annotation_feedback_unified_view.py`
- 改: `apps/api/app/services/bug_report.py`(双写)
- 改: `apps/api/app/api/v1/annotation_comments.py:create_comment`(双写)
- 改: `apps/api/app/api/v1/tasks.py:reject_task`(双写)
- 改: `apps/api/app/services/feedback.py`(暴露 `create` 给上述 3 处复用,统一 audit_log)
- 新增 pytest: `test_view_unions_legacy_tables`(4 张源表各插一行,view SELECT 出 4 行 + source_table 列正确);`test_double_write_bug_report` / `test_double_write_comment` / `test_double_write_reject`

## 风险与权衡

- **双写一致性**:三处 legacy 写入路径需同事务调 feedback_service.create。失败处理:整个事务回滚,不留半边写。监控:加日志 `[ADR-0027 double-write] {source} → feedback {id}`,运行一周后看是否有不一致行。
- **DiscussionPanel 右栏拥挤(<1280px 屏)**:沿用 v0.10.19 plan 备忘的"折叠到底栏 chip"方案,但本期先不做 chip 模式;ResizeHandle 让用户自行调整即可。
- **IssueLayer 与现有 Konva 工具栈冲突**:Pin 工具需要确保 `listening=true`(接收点击)而 IssueLayer 的图钉 `listening=true`(接收 hover/click) 但其余 group 是 `listening=false`(不阻挡 hit-test);沿用 `ImageStageShapes` 现有 listening 模式。
- **batch banner 与单条 PATCH 的状态同步**:多选改 class 后,react-query 需 invalidate 所有受影响 annotation 的 cache;`useAnnotationBulkUpdate` 已在 v0.10.19 处理,直接复用 mutation.onSuccess。
