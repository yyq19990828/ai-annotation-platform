# v0.20.17 · 二次推理参数持久化

状态：草案（draft）。补 v0.20.13 列为「不做」的用户偏好——单框二次推理调过的参数下次记住，
不必每次重调。**依赖 v0.20.13**（`SecondaryInferenceBar` 参数面板）。

## 背景

v0.20.13 给二次推理加了参数面板（⚙ + `SchemaForm`），但参数是**组件内 state**：切框、重挂载即丢，
用户每次都从模型默认重调阈值。高频用同一能力时很烦。

## 关键抓手（已核实，直接复用）

- 平台已有成熟的**用户级参数偏好服务端范式** `useAiToolParamPrefs.ts`：
  - 存 `User.preferences.ai.params_by_backend`（`authApi.getPreferences` / 保存），**按 backend id 分桶**，
    debounce 保存，多账户天然隔离。
  - v0.18.31 已把交互后端选择等从 localStorage 迁到服务端偏好（`useInteractiveBackendPref.ts`），
    跨设备一致——二次推理参数走同一路子，不要再引 localStorage。
- 读取优先级链现成：**用户偏好 → 模型 `SchemaForm` 默认（`deriveDefaults`）**。

## 工作项

### WS1 · 偏好读写 hook

- 新增（或扩展 `useAiToolParamPrefs`）一个 `useSecondaryParamPrefs`：读写
  `User.preferences.ai.secondary_params_by_model`（按 `backendId:modelId` 分桶——二次推理选具体
  model，比 backend 粒度更细，避免同 backend 多 model 串味）。debounce 保存，复用现有 preferences API。
- 后端 `User.preferences` 是自由 JSONB，加子键即可，**无需 alembic**。

### WS2 · Bar 接入

- `SecondaryInferenceBar` 的 `paramsByKey` 初值链：**用户偏好（本 hook）→ `deriveDefaults(model.params)`**。
- 用户在参数面板改动 → 除更新组件 state 外，debounce 写回偏好（按 `backendId:modelId`）。
- 「恢复默认」小动作（可选）：一键清该 model 偏好、回落 `deriveDefaults`。

## 风险

- **分桶粒度**：必须按 `backendId:modelId`（非仅 backend），否则同 backend 下检测/分类多 model 的参数互相
  覆盖。与 `useAiToolParamPrefs` 的 backend 粒度并存、互不干扰（不同子键）。
- 偏好 schema 随模型 params schema 变化：存的是自由 KV，模型换 params 时旧键无害忽略（`SchemaForm`
  只渲染当前 schema 的键），无需迁移。
- 保存失败要静默降级（仍用组件内 state），不阻断推理。

## 验收

- 调某能力的 `score_threshold` → 跑 → 切换到别的框再回来 / 刷新页面 → 该能力参数保留上次值。
- 不同 model 的参数互不串。
- 换设备登录同账户 → 偏好一致（服务端存储）。

## 依赖 / 不在范围

- **依赖 v0.20.13**；复用 `useAiToolParamPrefs` 的 `User.preferences` 服务端范式。
- 不做：项目级/团队级共享参数预设（用户级足够）、参数版本历史。
