# v0.18.18 · 交互分割 mask_input 回灌增量(迭代精修质量优化)

> 草案 (2026-06-25). 本 epic 第 2/3 版。**依赖 [v0.18.17](2026-06-25-v0.18.17-interactive-seg-dual-backend-sam-iterative.md) 已落地。**
> **可砍范围**: mask_input 回灌(§5.1–5.4)若 v0.18.17 纯累加点多击质量已达标可整体跳过; 但**会话点位可视化(§5.5)无论如何都要做** —— 它是 v0.18.17 多点精修可用性的必要补齐, 不受第 2 节量化判据约束。

---

## 1. 背景

v0.18.17 用「前端累加全量点、每次重发、`multimask_output` 候选」实现迭代精修, backend 无状态。但 SAM2/SAM3 的 `predict()` 还有一个 `mask_input` 参数(上轮 256×256 low-res logits 回灌), 在多次点击精修时能显著提升 mask 稳定性与边界质量 —— 这是 v0.18.17 故意推迟的增量。

源码证据(两 backend 同签名):
- gsam2 `SAM2ImagePredictor.predict(..., mask_input=...)` 返回三元组的第三项 `low_res_masks` 即可回灌。
- sam3 `SAM3InteractiveImagePredictor.predict(..., mask_input=...)`(`sam1_task_predictor.py:250-270`)同样接收 `mask_input` 1×H×W(H=W=256), 返回 `low_res_masks_np` 供下一轮。

## 2. 决策前置(先量化再做)

**进入本版前必须先量化 v0.18.17 纯累加点的多击精修质量**(取 20~30 张代表图, 对比「有/无 mask_input」的 5-click IoU)。判据:
- 若 mask_input 带来的 IoU 提升中位 < ~2% → **砍掉本版**, 不值往返开销。
- 若提升明显(尤其细长/镂空对象)→ 按下文落地。

## 3. 范围

- ✅ 两 backend 返回体携带 low-res logits; `context.mask_input` 接收回灌。
- ✅ 前端存上一轮 logits, 下次点击回传。
- ✅ **会话正/负点可视化**(纯前端, 不依赖 mask_input, 见 §5.5)。即便第 2 节判据砍掉 mask_input 回灌, 本项仍应落地。
- ❌ 不引入服务端会话(仍然无状态, logits 由前端携带)。

## 4. 承载方式取舍

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A 前端携带 logits(选)** | 返回体加 base64 low-res logits(256×256 float16 ≈ 128KB, base64 ~175KB/轮); 前端回传 | 无状态、可水平扩展; 代价是每轮多一次 logits 往返 |
| B 服务端会话缓存 | backend 按 session_id 存上轮 logits | 破坏无状态、idle-unload/多 worker 复杂, **不采用** |

压缩: low-res logits 用 float16 + 可选 zlib; 评估往返体积是否需进一步量化到 int8。

## 5. 任务分解

### 5.1 协议
- `apps/_shared/protocol_v2/` 或各 `schemas.py`: `Context` 加 `mask_input: str | None`(base64 编码 256×256 logits); 响应 `PredictionResult` 加可选 `mask_input_next`(同编码), 仅交互单实例路径返回。
- 约定编码格式写入 `ml-backend-protocol.md` §2(dtype/shape/base64/可选压缩)。

### 5.2 sam3-backend
- `predictor.py` `predict_interactive`: 入参 `mask_input` 解码 → `predict_inst(..., mask_input=arr)`; 出参带 `low_res_masks` 编码回 `mask_input_next`。
- 注意 `multimask_output=True` 时 low-res 有 3 张; 回灌只取被前端采纳的那张 → 前端回传时需带「采纳候选 index」, 或仅在 `multimask_output=False`(多点精修阶段)启用回灌。**建议: 仅 ≥2 点的非候选阶段启用 mask_input**, 首点候选阶段不回灌, 规避 index 歧义。

### 5.3 grounded-sam2-backend
- `predictor.py` `predict_point` / `interactive_box`: 同样 `mask_input` 解码透传 + `low_res_masks` 编码回传。

### 5.4 前端
- 交互会话: 存 `mask_input_next`, 下一次点击回传; 撤销/换候选时正确失效/重置。
- 仅在多点精修阶段(≥2 点)回灌, 与 5.2 约定一致。

### 5.5 前端 · 会话点位可视化(独立项, 不依赖 mask_input)
**问题**: v0.18.17 的多点精修中, 已落的正/负点存在 `useInteractiveAI` 的 `pointSessionRef`(内部 ref, 既非 state 也未对外暴露), 画布上**不渲染** —— 用户加第 2、3 点时看不到自己点过哪、哪些正/哪些负, 多点精修近似"盲点"操作。

- `useInteractiveAI`: 把 `pointSessionRef` 提升为可订阅状态(或额外 `sessionPoints` state)并在返回值暴露; `runPoint` 累加、`consume`/`cancel`/切 task·backend 时同步清空(复用现有 `resetPointSession`)。
- ImageStage: 新增轻量 overlay 渲染会话点 —— 正点绿色实心圆、负点红色叉(或红圈), 跟随视口缩放/平移; 仅 `smart-point` 工具激活且会话非空时显示。
- 会话结束(Enter 接受 / Esc 取消 / 切换)随候选一起消失。

## 6. 验收

1. 协议编码往返单测(encode→decode 等价)。
2. GPU 机: 同图 5-click 精修, 开 mask_input 的 mask 边界比关闭时更稳定(对比截图 + IoU)。
3. 往返体积实测 ≤ 目标阈值(建议 < 200KB/轮); 超标则量化到 int8 复测。
4. 候选阶段不回灌、不报 index 歧义。
5. (§5.5)多点精修时画布显示正/负点标记, 会话结束随之清除; 切 task/backend 不残留。

## 7. 风险

- **往返体积**: 高频点击下 logits 往返可能成为交互延迟瓶颈; 需实测并决定是否 int8 量化。
- **候选 index 歧义**: multimask 阶段回灌易错; 用「仅多点阶段启用」规避。
- **ROI**: 整版属增量优化, 必须用第 2 节量化判据守住「不值则砍」, 避免过度工程。
