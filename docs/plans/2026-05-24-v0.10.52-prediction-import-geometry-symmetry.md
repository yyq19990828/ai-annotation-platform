## 1. 背景与问题

当前预测导入链路（AAP JSON + COCO）只支持 **bbox / polygon / multi_polygon** 三种几何，其余 kind 在 `internal_geometry_to_ls_shape`（[predictions_import.py:46](../../apps/api/app/services/predictions_import.py)）返回 `None` → 累计进 `errors[]` 跳过。`rotated_bbox / polyline / keypoint` 三种平台已支持的几何无法导入。**本版交付 rotated_bbox + polyline（LS 有干净标准 type）；keypoint 因 LS 无「多点带可见性」标准结构，拆至 v0.10.53。**

**关键发现（本版核心约束）：补齐导入是「双向」工程，不是单点。**

预测的几何要在前端正确渲染，必须走通三段：

| 段 | 文件 | 现状 |
|---|---|---|
| ① 写路径：内部 geometry → LS shape，存入 `prediction.result`（JSONB，LS 标准格式） | `internal_geometry_to_ls_shape` (predictions_import.py:46) | 仅 bbox/polygon/multi_polygon |
| ② 读路径：`prediction.result` 的 LS shape → 内部 `{type,class_name,geometry,confidence}` | `to_internal_shape` (prediction.py:30) | **仅 rectanglelabels/polygonlabels；其余 type 返回 `geometry={}`** |
| ③ 前端渲染：内部 geometry → 画布 shape | `geometryToShape` (transforms.ts:75) | **已支持全部 kind**（rotated_bbox/polyline/keypoint 见 transforms.ts:87-136） |

也就是说：前端渲染早已就绪，真正的瓶颈在**读路径 ②**。即便只补写路径 ①，导入存进 DB 后前端 GET 读回来仍会因 `to_internal_shape` 不认识而拿到空 geometry → 渲染失败。

**额外收益**：补齐读路径 ② 也顺带修复 ML backend 直接产出 keypointlabels/polylinelabels 时被 [prediction.py:15](../../apps/api/app/services/prediction.py) 注释承认的「当前归 bbox 占位」缺陷——同一个 `to_internal_shape` 是两条来源（`ml_backend` / `external_import`）的共享读路径。

第二个问题：导入入口只在 AI 预标页（`ProjectDetailPanel.tsx`），该页仅列出绑定了 ML backend 的项目；而预测导入对**无模型项目**（`ml_backend_id=NULL`）同样有效却无入口可达。导出入口在 Dashboard 项目卡片 ⋮ 菜单（`ProjectGrid.tsx`），导入应与之对称。

## 3. 设计决策

### 3.1 LS shape 映射方案：优先走 LabelStudio 标准（Strategy A）

平台 `prediction.result` JSONB 的存储不变量是 **LabelStudio 标准格式**（docstring 明确，为 CVAT 等通用工具兼容）。因此新几何也优先映射到 LS 标准 type：

| 内部 geometry | LS shape `type` | LS `value` 关键字段 | 备注 |
|---|---|---|---|
| `polyline` `{points:[[x,y]...]}` | `polylinelabels` | `{points:[[x*100,y*100]...], polylinelabels:[cls]}` | LS 有标准 type，最干净 |
| `rotated_bbox` `{cx,cy,w,h,angle}` | `rectanglelabels` | `{x,y,width,height,rotation, rectanglelabels:[cls]}` | **见 3.2 旋转锚点换算** |

> keypoint 拆至 v0.10.53——LS 无「多点带可见性」标准结构，映射方案需单独决策，不混入本版（详见 v0.10.53 ROI-6）。

读路径 `to_internal_shape` 反向：
- `polylinelabels` → `{type:"polyline", points:[[x/100,y/100]...]}`
- `rectanglelabels` **带非空 `rotation` 字段** → `rotated_bbox`；`rotation` 缺失 → 仍 `bbox`（保持现有 bbox 不回归，同时让 angle=0 的 rotated_bbox 可 round-trip）

### 3.2 rotated_bbox 旋转锚点换算（实现重点 / 易错点）

内部 `RotatedBboxGeometry` 用**中心** `(cx,cy)` + `w,h` + `angle`（顺时针度，[0,360)）。
LabelStudio `rectanglelabels` 的 `rotation` 绕**左上角 `(x,y)`** 旋转，`x,y` 是**未旋转**矩形的左上角。

因此不能直接 `x=cx-w/2`。换算（θ 为弧度）：
```
未旋转左上角相对中心偏移 = (-w/2, -h/2)
旋转后左上角 = (cx + (-w/2)cosθ - (-h/2)sinθ,  cy + (-w/2)sinθ + (-h/2)cosθ)
LS: x = 旋转后左上角.x, y = 旋转后左上角.y, rotation = angle
```
读回时逆运算：由 LS `(x,y,width,height,rotation)` 还原 `(cx,cy)`：
```
cx = x + (w/2)cosθ - (h/2)sinθ   （把左上角沿 +(w/2,h/2) 反推回中心）
cy = y + (w/2)sinθ + (h/2)cosθ
```
> ⚠️ 坐标系：归一化 [0,1] × LS [0,100] 的缩放只作用于平移分量（x/y/w/h *100），angle 不缩放。前端 `geometryToShape` 的 rotated_bbox 分支（transforms.ts:127）用的就是中心+角度，可作为换算正确性的交叉验证基准。round-trip 单测必须覆盖 angle ∈ {0, 30, 90, 180, 270, 359}。

> **keypoint 已拆出**（2026-05-24 决策）。LS 无「多点带可见性」标准结构，映射方案有岔路（`keypointlabels` 扩展 `value.points` vs 内部格式直存），单独在 v0.10.53 ROI-6 决策与交付，不进本版。

## 4. 实施步骤

### Step 1 — 写路径：`internal_geometry_to_ls_shape` 增两分支
- 文件：[apps/api/app/services/predictions_import.py:46](../../apps/api/app/services/predictions_import.py)
- 在现有 bbox/polygon/multi_polygon 之后、`return None` 之前增 `polyline` / `rotated_bbox` 分支，按 §3 映射表 + §3.2 换算实现。
- 防御：polyline `points<2` → None；rotated_bbox `w<=0/h<=0` → None（与现有 None→errors[] 累计语义一致）。
- **验证**：单测构造两种内部 geometry，断言输出 LS shape 的 type/value 结构与坐标 *100 正确。

### Step 2 — 读路径：`to_internal_shape` 增反向分支
- 文件：[apps/api/app/services/prediction.py:30](../../apps/api/app/services/prediction.py)
- 在 `rectanglelabels`/`polygonlabels` 分支基础上：
  - `rectanglelabels` 分支内：若 `value.rotation` 存在且非 null → 产出 `rotated_bbox`（§3.2 逆运算），否则维持 `bbox`。
  - 新增 `polylinelabels` → `polyline`。
- 同步 `derive_tool_unit_from_ls_type`（prediction.py:11）：为 `polylinelabels`/带 rotation 的 rectanglelabels 派生正确 `tool_unit_id`（参照 toolUnits 常量；polyline 的 unit id 以前端 `ToolUnitId` 为准）。注：注释中「keypointlabels 当前归 bbox 占位」本版暂不动，随 v0.10.53 keypoint 一并修。
- **验证**：round-trip 单测 —— 内部 geometry →(Step1)→ LS shape →(Step2)→ 内部 geometry，断言恒等（坐标浮点容差 1e-6；angle 边界集见 §3.2）。

### Step 3 — Dashboard 对称导入入口
- 文件：[apps/web/src/pages/Dashboard/ProjectGrid.tsx](../../apps/web/src/pages/Dashboard/ProjectGrid.tsx)（导出入口同处 ⋮ 菜单）
- ⋮ 菜单在「导出」附近加「导入预测」项 → 打开复用的 [`PredictionImportWizard`](../../apps/web/src/components/predictions/PredictionImportWizard.tsx)（已是自洽 Modal，传 `projectId`）。
- 权限：与导入端点一致（`require_project_owner`）；非 owner 隐藏/禁用该菜单项（沿用卡片现有权限判断）。
- 保留 AI 预标页 `ProjectDetailPanel.tsx` 旧入口不动（surgical）。
- **验证**：preview 起前端 → Dashboard 卡片 ⋮ → 「导入预测」打开 wizard → 选 AAP JSON dry_run → 预览计数 → 确认导入 → 进工作台看渲染。

### Step 4 — 单测与 fixture
- 后端单测：`apps/api/tests/`（参照现有 predictions_import 测试位置）补 round-trip + importer 端到端（dry_run 计数、errors[] 累计、overwrite 语义不回归）。
- AAP JSON fixture：新增含 rotated_bbox / polyline 的样例。
