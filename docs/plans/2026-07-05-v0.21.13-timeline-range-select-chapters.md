# v0.21.13 · 时间轴区间选择基建 + 刷选建章节 + 章节双向联动

状态：**计划（2026-07-05）**。补齐视频工作台**「章节只能在侧栏用数字表单建/改、无法在时间轴上直接圈选」**的
易用性缺口，并把这套「时间轴区间刷选」抽成**可复用基建**（供 v0.21.14 的传播范围联动复用）。
**前端为主**，章节起止改动复用既有 `PATCH /videos/{item}/chapters/{id}`，不改 schema、无 alembic。

三个 UX 头脑风暴的第二个（章节×时间轴）。**关键前提纠正**：章节和时间轴**已经联动**——时间轴已渲染每条
章节色条且点击可 seek（`VideoPlaybackOverlay.tsx:448-479`）；缺的是**反向**：在时间轴上圈选来建/改章节范围。

## 动机（现状：已有单向联动，缺时间轴侧圈选与编辑）

### 已有联动（不是「无」，别重复造）
- **时间轴渲染章节色条**：`stage/VideoPlaybackOverlay.tsx:448-479`，`chaptersTrack`（时间轴上方一条），每章节按
  `(endFrame-startFrame+1)/(maxFrame+1)` 宽度、章节 `color` 着色。
- **点击章节条 seek**：`chapterMarker` 是 `<button>`，`onClick → onSeekChapter(id, startFrame)`；接线
  `stage/VideoKonvaStage.tsx:817` → `seekToFrame(frame, {recordHistory:true})`。
- **数据流**：`state/useWorkbenchShellModel.tsx:429-439` 把 `VideoChapter[]` 映射成
  `VideoTimelineChapter{id,startFrame,endFrame,title,color}` → `WorkbenchStageHost` → `VideoWorkbench` → overlay。
- **PageDown/PageUp 章节跳转**：`useWorkbenchShellModel.tsx:446-467` 窗口 keydown，`pickChapterTargetFrame`
  （`VideoChapterSidebar.tsx:389-411`）算目标帧。

### 缺口 1 · 新建/编辑章节范围只能「数字填」
`startCreate`（`stage/VideoChapterSidebar.tsx:109-118`）默认 `startFrame=frameIndex`、`endFrame=min(maxFrame,
frameIndex+round(maxFrame*0.1))`（约 10%），弹内联表单**手填起止帧号**或点「当前」按钮设为当前帧。要圈一段
就得脑算帧号或反复试——「拖一下」这个最自然的动作反而做不到。

### 缺口 2 · 时间轴章节条不可拖拽改起止
章节色条仅响应 `click`（seek），无 drag-resize handle；改范围只能回侧栏表单。「看范围」和「改范围」割裂在两处。

### 缺口 3 · 时间轴刷选手势被 loopRegion 独占
时间轴 Shift+拖已经能刷出一个区间——但那是「循环播放区间 loopRegion」（`VideoPlaybackOverlay.tsx:335-350`
draft、`:441-447` 渲染），产物只喂给循环播放，未泛化给「章节草稿 / 传播范围」等其它「圈一段帧」的需求。
刷选的**手势与坐标反解已完备**（`frameFromPointer` `:210-214`、`rangeStyle` `:225-232`），只差把产物通用化。

### 缺口 4 · 时间轴章节条 ↔ 侧栏章节行无双向高亮
侧栏点章节走 `onSeekFrame`、时间轴点章节走 `onSeekChapter`，两条独立回调，彼此 hover/选中不联动
（侧栏用 `isInside` 高亮当前所在章节 `VideoChapterSidebar.tsx:216`，但与时间轴条无 hover 呼应）。

### 缺口 5（顺带）· 章节侧栏头是老硬编码样式
`VideoChapterSidebar.tsx:179-201` 仍是 `<b>章节</b>` + 手拼卡片，与 v0.21 已统一的「轨迹 / AI 待审 / 人工」
分组头规范不一致（后者 `SECTION_CARD_CLASS` + 折叠箭头 + 字重/计数统一）。

## 定稿决策（拟）

- **基建 → 把 loopRegion 泛化成通用「时间轴区间选择」primitive。** 抽出一个带**用途标签**的区间刷选
  （`purpose: "loop" | "chapter-draft" | "propagate-range"`），复用现有 `frameFromPointer` + `rangeStyle` +
  draft 状态机。不同用途决定：松手后把 `{from,to}` 交给谁、区间条用什么颜色/样式渲染。**loop 行为零回归**。
- **缺口 1 → 时间轴刷选一键建章节。** 在时间轴刷出「chapter-draft」区间后，浮出一枚小动作（「＋存为章节」）
  或右键项：把 `{from,to}` 预填进章节表单（只剩填标题/选色），提交走既有 `create`。把「建章节」从脑算帧号
  变成「拖一下 + 起名」。
- **缺口 2 → 章节色条加 drag-resize handle。** 章节条左右边界加把手，拖动改 `start_frame/end_frame`，松手
  debounce 后 `PATCH`。复用 `rangeStyle` 坐标系；handle 命中区与「点击 seek」明确分区（边缘拖、中间点）。
- **缺口 4 → 双向 hover 联动。** 时间轴章节条 hover ↔ 侧栏对应行高亮互通（共用 `hoveredChapterId`），
  seek 口径统一（侧栏与时间轴都能定位到章节）。
- **缺口 5 → 章节头对齐分组头规范。** 复用「轨迹」头刚统一的卡片外观（可含折叠，但章节是否要折叠持久待定；
  首版至少对齐视觉，折叠可留 TODO）。

## 定稿架构

## 实现分阶段

- **WS1 · 时间轴区间选择基建**：把 `VideoPlaybackOverlay` 的 loopRegion draft 机制抽成带 `purpose` 的通用
  区间刷选（`:335-350` draft、`:441-447` 渲染泛化）；`loop` 保持原手势与样式。产出 `{purpose,from,to}` 回调。
- **WS2 · 刷选建章节**：`chapter-draft` 区间松手 → 浮出「存为章节」动作 → 预填 `VideoChapterSidebar` 的
  `startCreate` 表单（`:109-118`）start/end。手势与 loop 的区分策略（修饰键 or 模式切换）在此定稿。
- **WS3 · 章节条 resize**：章节色条加 handle，拖动改起止 → `useVideoChapters` 的 update（debounce）→
  `PATCH /videos/{item}/chapters/{id}`（后端 `videos.py:393` 已在）。命中区与 seek 点击分区。
- **WS4 · 双向 hover + 头样式**：`hoveredChapterId` 打通时间轴条 ↔ 侧栏行；章节侧栏头对齐分组头规范
  （`VideoChapterSidebar.tsx:179-201`）。
- **WS5 · 验证 + 版本**：E2E ① 时间轴刷一段 → 存为章节 → 时间轴出现色条、侧栏出现行；② 拖章节条边界改范围
  → 侧栏帧号同步、刷新保留；③ loop 循环播放不回归；④ hover 时间轴条 → 侧栏行高亮，反之亦然；⑤ 章节头视觉
  与轨迹头一致。CHANGELOG（Added + Changed）+ 版本 bump。

## 不在范围

- **章节嵌套 / 重叠**：后端 `UniqueConstraint(item,start,end)` + `CheckConstraint(end>=start)`（`video_chapters`
  表）约束不变；重叠/嵌套章节语义另议。
- **章节 metadata / frame_step / sampled 派生**：`schemas/video_chapter.py` 的 `_derive_from_metadata` /
  `snap_chapter_to_grid` 逻辑不动（采样网格对齐、来源标记保持）。
- **传播范围接时间轴**：本计划只建「区间选择」基建 + 章节用法；传播用法在 v0.21.14 复用本基建，不在此实现。
- **时间轴横向缩放（zoom）**：时间轴仍全域等宽（`maxFrame`），长视频精细圈选的缩放另议。

## 风险

- **loop vs chapter-draft 手势冲突**：两者都想用「Shift+拖」。必须明确区分——或用不同修饰键（如 Shift=loop、
  Alt=chapter），或用一个「时间轴模式」切换，或松手后统一浮出菜单让用户选「循环 / 建章节」。定稿前需在 WS1
  拍板，避免误建章节或误设循环。
- **resize handle 与 seek 点击争抢**：章节条既要能点（seek）又要能拖边界（resize）。命中区要清晰（边缘 N px
  为 handle、中间为 seek），且拖 handle 时阻止冒泡到时间轴 shell 的 seek。
- **PATCH 频繁**：resize 拖动过程别每帧 PATCH，须 debounce（拖动中本地预览、松手才落库），并处理并发/失败回滚。
- **坐标系一致性**：章节条现用 `leftPct/widthPct` 自算（`:429-437`），与 `rangeStyle`（`:225-232`）、密度条
  （`bin.index/binCount`）三套坐标细节略有出入；泛化基建时统一到一套，避免圈选落点与渲染错位。
- **依赖下游**：v0.21.14 的传播范围联动依赖本计划的区间选择基建；本计划的 `{purpose,from,to}` 回调契约要留好
  `propagate-range` 用法位，避免下游再改基建签名。
