# v0.20.5 · OCR/doc 预标路径 model-first 统一化

状态:草案 · 2026-06-30

## 背景

用户在画布跑 OCR 单图推理,反馈预标注配置面板四个问题。逐条调研后确认根因一致:
**OCR/doc(`isDocMode`)这条路径当初是「静态提示 + 单个自动选中模型」草草接上的,
从没拿到 v0.18.12 给 geometric(yolo)和 text(gsam2/sam3)两条路的 model-first 改造。**

共享代码:`apps/web/src/pages/AIPreAnnotate/components/usePreannotateConfig.ts`(状态)、
`PreannotateConfigForm.tsx`(纯渲染)、`utils/panelShape.ts`(能力派生)。批量页与工作台 AI 面板共用。

## 四点根因(证据)

1. **没有统一格式 / 端到端 OCR 不出现** — `PreannotateConfigForm.tsx:72-76` 的 `taskModels`
   三元只覆盖 `geometric`/`text`,**doc 模式恒为 `[]`** → 模型选择器(142-164 行)整段不渲染,
   连只读「当前模型」都没有。用户看不到/选不了 det/e2e。
   - 附:rapidocr 三 model 的 `task` 是 `detection`(ocr-det)/`ocr`(ocr-rec, ocr-e2e),
     现有分类会让 ocr-det 落进 geometric 路、rec/e2e 落进 doc 路 —— 跨路径散落本身就是「格式不统一」。

2. **参数不可调(两 bug 叠加)**
   - `PreannotateConfigForm.tsx:251` 把 variant+params 块 gated 在 `hasAnyParams`(只看 `model.params`)。
     rapidocr catalog **没声明 `params`**,可调项全在 `supported_variants`(version v5/v6 × size × lang)。
     `deriveVariantSource` 对 doc 模式确实返回了变体轴(`panelShape.ts:136-141`),但因 `hasAnyParams=false`
     整块被「该任务无可调参数」吞掉 → 变体选择器从不渲染。
   - `usePreannotateConfig.ts:477-484` 的 **doc-mode buildArgs 不下发 `model_variants`**
     (geometric/text 两路都发了,见 468/493 行)→ 后端 `resolve()` 读不到 variants,永远跑默认 v5/mobile/universal。

3. **类别白名单/预热只有 yolo** — `PreannotateConfigForm.tsx:175` 的 `ClassWhitelistRow` `if isGeometricBackend`
   才渲染。这是**闭集**概念(yolo COCO `model.names`),OCR/开集本无类别表 —— 属「按能力差异化」而非缺失,
   但 UI 没讲清,看着像「只有 yolo 能用」。

## 设计决策(已与用户确认 — 最终版)

**彻底移除 OCR/版面专属的「任务类型」tab 层**,把该 backend 全部可批量预标的 full_image 模型
(几何检测/分割 + OCR/版面,排除交互式与 crop-only 原子)铺进**同一个「模型任务」下拉**,与所有
其它 backend 完全一致。选中 model 后由其 `task` 派发到内部三路机制(`selectTaskModel`:ocr/doc_layout
→ docTaskId + taskType;其余 → geometric/text id + taskType="text")。内部三路的 prompt / 类别白名单 /
变体 / 输出 / buildArgs 不变,只统一了**选择层**。纯 OCR backend(无几何/文本 model)由默认选中 effect
落到第一个可选 model(端到端),避免面板悬空。

> 初版曾误保留「任务类型」tab(只在 OCR tab 下加下拉),与「和其它 backend 统一」不符,已纠正。

## 改动清单

### 1. `usePreannotateConfig.ts` — doc 模式 model-first 状态

- 新增 `docModels`:`models.filter(task ∈ {ocr, doc_layout} && supportsFullImageInput)`(已有 `supportsFullImageInput`)。
- 新增 `docTaskId` / `setDocTaskId` 选中态 + 默认(优先 e2e/composite,回退第一个);随 backend / taskType 重置。
- `activeDocModel` 从「`.find` 第一个」改为「`docModels.find(id===docTaskId) ?? docModels[0]`」。
- `ocrModel`/`docLayoutModel` 仍用于 `availableTaskTypes` 派生(决定 OCR/doc tab 是否出现),保留 full_image 过滤。
- **buildArgs doc 分支(477-484)补 `model_variants: variantSlice`**,并像 geometric/text 那样把变体轴从 `params` 拆出
  (`nonVariantParams`),`params: nonVariantParams`。

### 2. `PreannotateConfigForm.tsx` — 表单接 doc 模式

- `taskModels`/`taskModel`/`setTaskModelId` 三元加 doc 分支(`cfg.isDocMode ? cfg.docModels / cfg.docModel / cfg.setDocTaskId`)。
  → OCR 也走统一「模型任务」下拉(单 model 时只读「当前模型」),det/e2e 可见可选。
- params 块 gating(245-252):`无可调参数` 判定从 `isDocMode && !hasAnyParams` 改为
  **`isDocMode && !hasAnyParams && variantGroups 为空`**(无 params 且无变体轴才算无可调)。
- (点 3)在闭集白名单区(175 行)旁补一行能力说明:闭集才有类别白名单,OCR/开集用 prompt / 文本属性 —— 消除「只有 yolo」错觉。

### 3. 测试

- `supportsFullImageInput.test.ts` 已覆盖选择过滤。
- 新增 doc-mode buildArgs 单测:选中变体 → `model_variants` 正确下发、变体轴不混进 `params`。
- 表单测试:OCR 任务下「模型任务」下拉/只读「当前模型」出现;有 `supported_variants` 时变体选择器渲染(不再「无可调参数」)。

### 4. 不在本次范围

- ocr-det(task=detection)跨路径归类的彻底重构(它现在落 geometric 路)。本次先让 OCR 任务下 e2e 正常可见可调;
  det 单独检测留待后续(或在「模型任务」下拉显式纳入 task=detection 的 OCR 家族 model,需要更大改动)。

## 验收

- 画布/批量页 OCR 任务:能看到并选择 `端到端 OCR`(e2e);能调 version/size/lang;选了变体后端实际生效(非默认档)。
- `pnpm typecheck` / `pnpm lint` / `pnpm vitest run src/pages/AIPreAnnotate` 全过。
- 后端实跑:OCR e2e 出框 + 文字,画布渲染。
