# v0.14.13 · 预标注交互闭环（yolo variant 选择 + 推理参数 + 反馈 UX）

> Created: 2026-06-08
> Status: Draft
> 依赖：v0.14.12（yolo-backend 接入 + 协议 v2 富表达）

## 0. 背景与动机

v0.14.12 已经把 yolo-backend / gsam2 / sam3 在「能力目录」UI 上展现得很丰富：每个物理 variant 一行、跨 task 聚合、URL 去重。但调研发现 **「能力目录好看，预标注用不上」** —— 富表达只在 ModelMarket 停留，没有贯通到工作台 / 批量预标的实际调用：

| 现状 | 问题 |
| ---- | ---- |
| yolo `/predict` 期望 `context.variants.{series,size}`，前端 `usePreannotation` 不传 | 永远跑 backend env 默认值，富表达失效 |
| gsam2 / sam3 已有 `VariantSelector` + 工作台 `useInteractiveAI` 的变体切换 toast | yolo 没复用、批量预标 UI 也没用 |
| backend `/predict` 响应无 `cache_hit` / `model_load_ms` | 用户首次切 variant 卡 5-15s 没有任何提示 |
| 推理参数（conf/iou/max_det、box_threshold、score_threshold）在 `/setup.params` 已经声明 | 但 ProjectDetailPanel 的 SchemaForm 渲染时把 `enum/variant` 类字段也混进去，参数与变体没分层 |
| variant 偏好分散：`useAiToolParamPrefs`（localStorage，按 backend 分桶） + 项目 `ai_model`（冗余字段） + 无 backend 级 default | 工作台跨设备 / 重装浏览器后偏好丢失，且没人持久化 |
| variant 命名跨 backend 不统一：yolo 用 `series/size`，gsam2 用 `sam_variant/dino_variant`，sam3 无 | 前端必须为每个 backend 写一套传参逻辑 |

本版本聚焦 **「让能力目录里看到的 variant，真能在预标注链路上被用上」**，同时把推理参数面板与变体选择器分层、补上冷启动反馈的最小可用 UX。协议层的字段名统一与可观测性增强放到 v0.14.14 / v0.14.15。

## 1. 目标 & 验收

### 1.1 用户视角

- [ ] **yolo 预标可选 variant**：在「AI 预标注」页面，选中绑定 yolo-backend 的项目后，参数面板第一行出现「series × size」联动选择器，默认值从项目级偏好读取，提交批次时 variant 显式传入 backend。
- [ ] **工作台沿用偏好**：进 workbench、第一次触发 yolo 预标，自动用上次在「AI 预标注」页选定的 variant；切换后写回项目级偏好。
- [ ] **冷启动有可见反馈**：首次切到尚未加载的 variant 时，按钮变 `加载模型中…（约 8s）`，请求完成切回正常态；二次以上不再提示。
- [ ] **推理参数面板与变体分层**：SchemaForm 渲染的 params 面板只显示「非 variant」字段（conf/iou/max_det/threshold/...），variant 字段被 VariantSelector 接管，不重复出现。

### 1.2 协议 / 数据视角

- [ ] `MLBackendCapabilities` 引入 `default_variants: Record<axis, value>` 字段（backend 自报默认值），三个 backend 都填上当前 env 默认。
- [ ] `projects` 表新增 `default_variants JSONB`（按 backend_id 分桶），替代 localStorage 持久化。`ai_model` 字段标记 deprecated 但保留一版，下一版删除。
- [ ] 后端 `/predict` 接受 variant 缺省，回退顺序：`request.context.variants` > `project.default_variants[backend_id]` > `backend env`。注意：服务端 fallback 在 v0.14.13 只 ship "request 缺省时走 env 默认"（不解析 project 级），项目级回退由前端在调用时填好再发，避免 API 层耦合 project 概念。

### 1.3 验收

- [ ] 后端单测：yolo / gsam2 / sam3 各加一组测，验证 `/predict` 收到合法 variant 走对应权重、收到非法 variant 返回 400/422、缺省时落到 env 默认。
- [ ] 前端单测：`VariantSelector` 在 yolo / gsam2 / sam3 三种能力 schema 下的渲染快照；`usePreannotation` mutation payload 包含 variants 字段。
- [ ] 手测脚本：见 §5。
- [ ] 文档：`docs-site/user-guide/workbench/pre-annotation.md` 新增「选择模型变体」一节；`docs-site/dev/reference/ml-backend-protocol.md` §4.1 补 `default_variants`。
- [ ] CHANGELOG v0.14.13 段落（4 个子段：Added / Changed / Tests / Docs）。

## 2. 范围 & 不做的事

### 2.1 In scope

- yolo / gsam2 / sam3 三个 backend 的 `/setup` 补 `default_variants`，`/predict` 处理 variant 缺省回退到 env 默认。
- 前端 `VariantSelector` 通用化（从 `useInteractiveAI` 抽出，能吃任意 capability 的 supported_variants/variant_combinations）。
- 「AI 预标注」页面：项目详情面板顶部加变体选择器（按 backend 能力动态渲染）。
- workbench 工具栏：yolo 类工具加变体快速切换 popover（沿用 gsam2 那套）。
- `projects` 表迁移：加 `default_variants JSONB`。
- 冷启动 UX：predict 响应回来前，按钮文案/loading 态根据「是否首次用此 variant」分两态（前端本地内存判定即可，不依赖 backend）。

### 2.2 Out of scope（明确推到后续版本）

- **协议层字段名统一**（`series/size` vs `sam_variant/dino_variant` → 统一为扁平 `model_variants: Record<axis, value>`）→ v0.14.15。涉及 backend 兼容期与前端迁移，单独版本处理。
- **backend `/predict` 响应加 `cache_hit` / `model_load_ms`** + 前端基于这俩字段给"真"冷启动反馈 → v0.14.14。本版只做"前端本地猜测"。
- **`/health.pool.*` 三 backend 格式统一** → v0.14.14。
- **校验错误码 400 vs 422 统一** → v0.14.15 协议层一起改。
- 删除 `projects.ai_model` 冗余字段 → v0.14.15（先 deprecate，给一版迁移窗口）。
- 推理参数预设（presets）：保存"这组 conf/iou"为可复用模板 → 不在本版考虑，后续按需。

## 3. 任务清单

### 3.1 Backend：default_variants 透传

**文件**：
- `apps/_shared/protocol_v2/setup.py`（或 schema 定义处）
- `apps/yolo-backend/main.py`
- `apps/grounded-sam2-backend/main.py`
- `apps/sam3-backend/main.py`

**任务**：
1. 协议 schema 加 `default_variants?: dict[str, str]`（每个 model 一份；axis_key → 默认 value）。
2. yolo-backend：`/setup` 每个 model 填 `default_variants = {"series": settings.YOLO_DEFAULT_SERIES, "size": settings.YOLO_DEFAULT_SIZE}`，按 task 取首个合法组合做兜底。

5. `/predict` 不变（已经支持 variant 缺省 → env fallback），只补 docstring 说明优先级。

**验证**：`curl http://localhost:8003/setup | jq '.models[0].default_variants'` 三 backend 都返回非空。

### 3.3 前端：通用 VariantSelector

**文件**：
- `apps/web/src/components/ml/VariantSelector.tsx`（新建 / 抽取）
- `apps/web/src/components/ml/__tests__/VariantSelector.test.tsx`（新）

**任务**：
1. 从 `useInteractiveAI` 或 ProjectDetailPanel 的内嵌实现抽出独立组件。
2. 输入：
   ```ts
   {
     supportedVariants: InstanceVariantGroup[];
     variantCombinations?: string[][];  // 非笛卡尔积约束
     value: Record<string, string>;
     defaults: Record<string, string>;  // 来自 backend default_variants
     onChange: (next: Record<string, string>) => void;
   }
   ```
3. 渲染规则：
   - 单轴 → 单 select。
   - 多轴 + 无 `variant_combinations` → N 个独立 select（笛卡尔积）。
   - 多轴 + 有 `variant_combinations` → 第一轴 select 决定第二轴可选项（联动），如 yolo 的 series 决定 size 列表。
4. value 为空时显示 defaults 的值作为 placeholder，提交时一并发出。

**验证**：vitest snapshot 三种 schema（yolo / gsam2 / sam3）。

### 3.4 前端：AI 预标注页接入

**文件**：
- `apps/web/src/pages/AIPreAnnotate/components/ProjectDetailPanel.tsx`

## 6. 风险 & Tradeoff

- **冷启动反馈是"前端本地猜测"**：仅根据 sessionStorage 缓存判断"是否首次切此 variant"，可能误判（如 backend pool 已 evict 但前端缓存还在）。tradeoff：等 v0.14.14 后端 `/predict` 加 `cache_hit` 真信号后替换。本版不阻塞。
- **variant 字段名跨 backend 不统一**：本版仍是 yolo `series/size` vs gsam2 `sam_variant/dino_variant`，前端 VariantSelector 只是泛化渲染，不做归一化。v0.14.15 协议层统一时再迁移。
- **`projects.default_variants` 与 `projects.ai_model` 共存**：本版双写不删，避免老数据破坏；v0.14.15 评估 ai_model 是否可删。
- **localStorage 偏好迁移**：v0.14.13 仍读 localStorage 作为 fallback（迁移期），但写只走数据库；v0.14.14 起完全脱离 localStorage。
