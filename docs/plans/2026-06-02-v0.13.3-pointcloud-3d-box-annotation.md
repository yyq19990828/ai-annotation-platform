# v0.13.3 · 点云 3D 框标注（可写）

> Epic：[点云 + 图像联合标注工作台](./2026-06-02-v0.13.x-point-cloud-workbench-epic.md) 第四切片。
> 主题：把 v0.13.2 的**只读**点云查看器升级为**可标注** —— 在 Three.js 工作台里画 / 选 / 编辑 **3D 框**（`Box3DGeometry`），类别 / 属性复用 `tool_bindings["lidar_box_3d"]`，经现有标注 API 持久化。
> 依赖：v0.13.2（点云查看器 MVP + manifest API + Three.js 双栈）。
> 调研对应：research §14.7.1（SUSTechPOINTS 框几何 / 投影内核）、§14.7.2（xtreme1 PSR 数据模型）、§14.10.4（裸 Three.js 命令式编辑器决策）、§14.8.4（前端是工作量大头）。

## 背景

v0.13.0~v0.13.2 已把「后端数据地基 → scene 导入 → 前端只读渲染」打通：点云任务能在 3D 工作台看见点云 + 相机图，但**不能标注**。本切片首次让用户**画 3D 框**：在点云里放置 / 编辑长方体（中心 + 尺寸 + yaw），绑类别与属性，保存为 `Box3DGeometry` 标注。投影到相机视图、跨模态 `group_id` 聚合留给 v0.13.4，避免一次吞太多。

**关键判断：后端几乎零改动。** 标注 CRUD 链路（端点 / schema / service / 类别校验 / group_id）在 v0.13.0 已为 `Box3DGeometry` + `lidar_box_3d` 工具单位备好；本切片是**纯前端 + 一处前端设置解禁**，无新后端端点、无迁移。

- **manifest**：`GET /tasks/{id}/point-cloud/manifest` 已出点云 URL + 各相机（含标定），前端渲染不缺接口。

**前端（v0.13.2 现状）**
- 3D 模块目录 [`src/pages/Workbench/stages/three-d/`](../../apps/web/src/pages/Workbench/stages/three-d/)：`PointCloudScene.ts`（命令式 Three.js 薄封装：`WebGLRenderer`/`Scene`/`PerspectiveCamera`/`OrbitControls`、`loadPcd`、>50 万点抽稀、`dispose`，相机 up=`[0,0,1]` 自动驾驶 Z-up 惯例）、`ThreeDWorkbench.tsx`（拉 manifest + 渲染，**无编辑 UI**）、`usePointCloudManifest.ts`。
- 壳层分流：[`useWorkbenchShellModel.tsx:272`](../../apps/web/src/pages/Workbench/state/useWorkbenchShellModel.tsx#L272) `stageKind = type_key==="lidar" ? "3d" : ...`；3D 分支 `readOnly: isLocked`（随锁定态，不是写死 true —— 缺的是**编辑能力**，不是被强制只读）。3D 分支当前**无 toolDock / pendingDrawing / class-picker** 接线。

- **三方库**：`three` 自带 `examples/jsm/controls/TransformControls.js`（裸 Three.js addon，非 r3f）—— 平移 / 旋转 / 缩放 gizmo 开箱即用。

### 3D 框数据表示（与后端对齐）

`Box3DGeometry`：`center=[x,y,z]`（米）、`size=[长,宽,高]`、`rotation=[rx,ry,rz]`（弧度，绕各轴）。本切片用 **7-DoF**：仅 `rotation[2]`（yaw，绕 Z）可编辑，`rx=ry=0`。坐标系沿用点云 Z-up。SUSTechPOINTS / xtreme1 同构（PSR：Position/Scale/Rotation）。

## 范围（做什么）

### 0.13.3-1 解禁 `lidar_box_3d` 工具单位配置（前端设置，小）
- 取消 [`Step1DataTypeAndTools.tsx:109`](../../apps/web/src/components/projects/steps/Step1DataTypeAndTools.tsx#L109) 与 [`UnitTabs.tsx`](../../apps/web/src/components/projects/steps/UnitTabs.tsx) 对 `lidar_box_3d` 的「占位隐藏」，让建项目向导 / 项目设置能给 `lidar` 项目启用该单位并配类别（复用现有 `ClassesSection` / `useProjectToolBindings`，本就支持任意 unit）。
- **无后端改动**（`tool_bindings` 通用结构；`toolUnits.ts` 映射已就位）。
- 验证：建一个 lidar 项目 → 设置里配 3D 框类别 → `tool_bindings["lidar_box_3d"].classes` 落库（与 `seed_pointcloud.py` 写法一致）。

### 0.13.3-2 3D 工具系统 + 渲染已存框 + 选中（前端，中）
- three-d 模块引入**独立的工具态**（`select` / `box`，**不复用 Konva 的 `TOOL_REGISTRY`**，双栈隔离），最小工具浮条 + 快捷键。
- **渲染已存标注**：从 `useAnnotations(taskId)` 取 `geometry.type==="box_3d"`，用 Three.js 盒线框（`LineSegments` / `BoxHelper`）按 class 上色挂进场景；`PointCloudScene` 扩展「框图层」管理（add/update/remove，每框 geometry/material 在移除时 `dispose`）。
- **选中**：射线拾取（`Raycaster`）选框，选中态高亮，驱动 `selectedId`（复用 `useWorkbenchState`）。

### 0.13.3-3 放置 + 编辑 3D 框（前端，**本切片大头**）
- **放置**：建议提供**俯视（BEV）正交相机切换**便于精确 —— 点-拖画地面足迹 → 默认高度（可后续拖拽设高）→ 生成 PSR（`center/size`，初始 `yaw=0`）。
- **编辑**：选中框后用官方 `TransformControls`（translate / 绕 Z rotate / scale，W/E/R 切换）+ 数值面板；**不自写 8 角点 handle**（精度留给 B 的三视图，见设计决策 D2）。
- **数值面板**：PSR 精确数值（center / size / yaw 输入），与 gizmo **双向同步**（透视拖拽不准时兜底）。
- **移植 SUSTechPOINTS 纯函数**：`util.js` 的 `psr_to_xyz` / `euler_angle_to_rotate_matrix` / `matmul`（无框架依赖）算 8 角点与朝向线，抽到 `three-d/geometry/box3d.ts` + 单测（为 v0.13.4 投影复用同一套）。
- **性能 / 资源**：复用 v0.13.2 抽稀 + `dispose`；编辑只更新选中框 mesh，不重建点云。

### 0.13.3-4 类别 / 属性绑定 + 持久化 + 接线（前端，中）
- 画完框 → 复用 `ClassPickerPopover`（改 fixed 定位）选类别（`useToolBindings` 读 `tool_bindings["lidar_box_3d"].classes`）+ `AttributeForm` 属性。
- **保存 / 更新 / 删除**：直接复用 `useCreateAnnotation/useUpdateAnnotation/useDeleteAnnotation`，payload：
  ```json
  { "annotation_type": "box_3d", "tool_unit_id": "lidar_box_3d",
    "class_name": "car", "geometry": { "type": "box_3d",
      "center": [x,y,z], "size": [l,w,h], "rotation": [0,0,yaw] },
    "attributes": { ... } }
  ```
  乐观更新 / 失效已内建。撤销 / 重做复用 `useAnnotationHistory`。
- **壳层接线**：把 3D 分支接上工具栏 + 浮层调度（`WorkbenchOverlays` 的 pending / class-picker 对 `stageKind==="3d"` 生效），`useWorkbenchShellModel` 输出 3D 的 `toolDock` 分组。锁定 task / viewer 角色仍只读（`readOnly: isLocked` 不变）。

## 设计决策（已定）

**D1 · 编辑交互形态 → 方案 A（本切片）；方案 B 列为独立后续切片**
- **方案 A（本切片做）**：主 3D 视图内编辑 —— `TransformControls`（translate + 绕 Z rotate + scale 三模式，W/E/R 切换）+ 数值面板；BEV 正交相机切换辅助精确放置。
- **方案 B（SUSTechPOINTS 式三正交视图：俯/侧/正视图边线 + 方向线拖拽精修）**：体验最好，但工作量 ≈ 甚至 > A 之和（`side_view_op.js` ~1100 行 + `box_editor.js` ~1800 行的单框版）。**单独切片**（v0.13.3+，另写计划）。
- **A 不是一次性投入，B 建在 A 之上**：SUSTechPOINTS/xtreme1 里主 3D 视图（导航/放置/选中）与三视图（精修）并存 —— 主视图建/选框，三视图是「选中框的聚焦精修面板」。迁到 B = 在 A 上**加一个三视图面板**，A 的 PSR 纯函数 / 框数据模型 / 主视图放置选中 / 类别属性持久化全部复用。

**D2 · gizmo → 官方 `TransformControls`（轻），不自写 8 角点 handle**
- `TransformControls` 是 three 官方 addon（裸 Three.js，非 r3f），translate/rotate/scale 开箱即用，配数值面板足够精确。
- **正因为 B 是终点，主视图 gizmo 保持轻**：自写 8 角点精修 handle 会被 B 的三正交视图取代，本切片不做 —— 精度活儿留给 B。主视图只需 translate + yaw + scale + 数值面板。
- 设计要求：选中框的 PSR 作为单一真值同时驱动「主视图 gizmo / 数值面板」，并为将来三视图预留同一驱动入口（B 插进来零改数据层）。

## 不做（明确排除）
- 投影到相机视图 / 3D→2D 实时联动高亮、最佳相机选择（**v0.13.4**）。
- `group_id` 跨模态聚合（v0.13.4，需 2D 框先存在）。
- `point_mask_3d` 3D 语义 / 实例分割（v0.13.5+）。
- 跨帧轨迹 / 插值（SUSTechPOINTS `BoxEditorManager` 那套）、多帧序列播放。
- 点云自动拟合 / 贴合（`fit_bottom` / `auto_shrink` / 框内点高亮）—— 列 stretch，不进核心。
- AI 辅助 3D 预标。
- 三正交视图精修编辑器（设计决策 D1 方案 B）。
- 不动 2D Konva / 视频工作台；不动后端（无新端点、无迁移）。

## 风险
- **透视拖拽精度**：透视视图里拖框易不准 → BEV 相机 + 数值面板兜底（核心缓解）。
- **坐标系 / 欧拉角约定**：点云 Z-up；`yaw=rotation[2]` 绕 Z。移植 SUSTechPOINTS 矩阵时须统一欧拉角顺序，并写**纯函数单测**锁定 PSR↔8 角点（v0.13.4 投影要复用，约定一旦漂移投影必偏）。
- **WebGL 资源泄漏**：每框 mesh / handle 的 geometry/material 在删除 / 切任务 / 卸载时 `dispose`，生命周期在 `PointCloudScene` 收口（承 v0.13.2 风险条）。
- **只读回归**：editable 化不得破坏 v0.13.2 只读路径（锁定 task / viewer 仍只读）。
- **bundle**：新增编辑逻辑仍走 lazy 的 `vendor-three` chunk，不进主 bundle（`pnpm build` 核验）。

## 验证（成功标准）
- **设置**：lidar 项目能在 UI 配 `lidar_box_3d` 类别，`tool_bindings` 落库。
- **端到端**：打开 `P-PC01` 的 lidar 任务（seed 数据）→ 画一个 3D 框 → 选类别 / 填属性 → 保存 → 刷新后框还在（`GET annotations` 返回 `box_3d`，渲染一致）；编辑（平移 / 缩放 / yaw）→ `PATCH` 持久化；删除 → 软删消失。
- **数值面板 ↔ gizmo 双向同步**；非 `tool_bindings` 内类别被后端 **422** 拒。
- **无泄漏**：切任务 / 反复进出 console 无 context lost，内存稳定（chrome-devtools MCP 实测截图）。
- **前端**：PSR↔8 角点纯函数单测、payload 构造单测；`typecheck` / `lint` / `build`（确认 three 仍独立 chunk、主 bundle 不含 three）。
- **后端**：无新端点 → 加一条 `box_3d` 创建 + `lidar_box_3d` 类别校验的 service/API pytest（夹具 `P-PC01` 或测试库）。
- 2D / 视频工作台回归无影响。
