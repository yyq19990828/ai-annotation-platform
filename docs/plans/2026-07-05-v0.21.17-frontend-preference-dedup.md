# v0.21.17 · 前端随手优化批（preference 共享 query 去重 + 可选 PipelineGraphCanvas 引用稳定）

状态：**计划（2026-07-05）**。两个纯前端「随手优化」——① 交互工具 preference 三/四个 hook 各自裸拉
`getPreferences()`、进工作台并发多次相同 GET，收敛到共享 react-query；②（可选尾项）PipelineGraphCanvas 运行态
轮询每 1.5s 无条件 `setNodes` 的一次无谓 re-render。**纯前端**，非 bug，不改后端 / schema，无 alembic。

源自 §C.1 两条 P3。**关键前提纠正**（调研更正）：优化点 ② 的原始命题「每 tick 重置节点态 / 跳视口 / 闪烁」
**已被前序优化修复**（`fitView` 改依赖 `topoFingerprint` 只在拓扑变时触发、measured 尺寸按 id 保留），仅剩一次
无谓 re-render，低收益且回归面广，故降级为**可选尾项**。本计划主体是优化点 ①。

## 定稿决策（拟）

- **① → 共享 `useUserPreferences()` query。** 新增 `useQuery({queryKey:["me","preferences",userId], queryFn:
  authApi.getPreferences, enabled:!!userId, staleTime: 长})`；四个 hook 改从 `data.ai?.<子键>` 派生 saved 值，
  删各自 `useState`+`useEffect([userId])` 拉取块（react-query 自动对同 key 去重 → 3 并发 GET 收敛为 1）。切账号
  由 query key 带 `userId` 自然隔离，替代现有手动清空逻辑。
- **① writer → 优先 `invalidateQueries` 而非手写深合并 `setQueryData`。** writer 仍走 600ms 节流
  `updatePreferences({ai:{子键:payload}})`，成功后 `invalidateQueries(["me","preferences",userId])` 重新 GET
  （牺牲一次请求换缓存层正确性）。**不手写 `setQueryData` 浅替换 `ai`**——那会在缓存层重现「改一键吹没相邻键」
  （后端已防，前端乐观浅替换会短暂显错值）。unmount flush pending（各 hook 现有 flush effect）行为须等价保留，
  否则重现跨用户脏写（P1）。
- **② → 上游引用稳定化（可选，验证手感后再定是否做）。** 让 `graphNodes` / `flow.nodes` 在按 id data 签名浅相等
  时复用旧节点对象引用（结构共享），使 `:264` effect 的 map 产物引用稳定、react-flow diff 短路。**不碰**
  `:266-270` measured 保留逻辑、**不把** `fitView` 改回依赖 `flow.nodes`。签名须覆盖所有 tick 变字段
  （`ok`/`targeted`/`runState`/`warning` 等，见 `pipelineGraph.ts:431` `StageNodeData`），漏字段会致运行进度不刷新
  （比丢一次 re-render 更糟）。

## 实现分阶段

- **WS1 · 共享 preferences query**：新增 `useUserPreferences`；四个 hook 切到共享 query 派生 saved 值 + `invalidate`
  写回；保留节流 + unmount flush。删各自裸拉取块。
- **WS2 · 验证 ①**：网络面板确认 Workbench 首屏只 1 次 `/me/preferences`；四类偏好（交互后端/工具模型/二次推理
  参数/预标参数）写回后重新进入仍生效、跨用户切换不串（重点回归 P1 跨用户脏写）；相邻子键互不覆盖。
- **WS3 ·（可选）PipelineGraphCanvas 引用稳定**：`graphNodes` 结构共享；回归 DAG 交互（拖拽改父/键冲突）、运行
  进度每 1.5s 实时刷新、measured 不丢、视口不跳。若验证成本/风险偏高可整段跳过，只发 ① 。
- **WS4 · 版本**：CHANGELOG（Changed / Performance 归 Changed）+ 版本 bump。

## 风险

- **缓存层深合并正确性（① 主风险）**：writer 若手写 `setQueryData` 浅替换 `ai` 会短暂显错值；故走 `invalidate`。
  若为省请求要做乐观 `setQueryData`，必须**按子键深合并**（复用后端同款逻辑），且注意 `me.py:173` list 覆盖语义
  （提交完整列表）。
- **切账号隔离 / pending flush**：query key 带 `userId` 隔离拉取，但各 hook 的节流 pending 写在 key 切换/登出时
  仍须 flush 或丢弃（现有 unmount flush effect：`useInteractiveBackendPref.ts:55-71`、`useAiToolModelPref.ts:53-69`
  等价保留），否则重现跨用户脏写 P1。
- **② 低收益高回归**：拓扑稳定时 react-flow 已 shallow-eq 吸收大部分开销，本改只省 map+setState 调度；验证要覆盖
  运行进度实时性 + DAG 交互 + measured 不丢，成本不低。故列可选，主体只保 ①。
- **收益量级诚实**：① 省 2-3 个**已并发**（非串行阻塞）的 GET，属「随手」级；价值在减少冗余请求与统一 preferences
  数据源，不是性能瓶颈修复。
