# v0.20.18 · 二次推理:开集文本输入 + 参数浮层(popover)重排

状态：**已落地（v0.20.18）**。用户实测 v0.20.17 后反馈的两个即时问题合到一版。
（注：v0.20.18 原计划是「能力按类别过滤」，用户已明确先跳过，该计划重编号到 v0.20.20；本号顶上给这两个
即时修复，保持 CHANGELOG 顺序连续。）**依赖 v0.20.11/17**。

## 问题

1. **开集（开放词表）检测/分割没地方输入文本**：`supported_prompts` 含 `text` 的模型（Grounded-SAM-2 系）
   需要一个文本查询（如 `car . person`）才能工作，但二次推理条只有能力下拉 / 档位 / 参数，没有文本框——
   这类能力等于选了也用不了。
2. **参数面板被拉成又长又空的一整行**：能力多时工具条变宽，展开 ⚙ 参数后，`SchemaForm` 的滑块
   （置信度 / IoU 阈值 / 最大检出数，`w-full`）与枚举下拉跟着面板铺满整行、稀疏难看。
   （初版误判为「enum 下拉被 flex stretch」，实际 YOLO 参数全是滑块——根因是**面板本身没限宽**，
   随工具条变宽而变宽。）

## 核实（决定方案，均零后端改动）

- **后端已全链路支持文本**：`SecondaryInferenceRequest.prompt`（`annotation.py:103`）+
  `run_secondary_inference(prompt=...)`（`secondary_inference.py`）+ 前端 `SecondaryInferenceRequest.prompt`
  都已存在。缺的只是 UI 文本框 + `buildSecondaryInferencePayload` 没设 `prompt`。
- **开集判定现成**：批量预标用 `(m.supported_prompts ?? []).includes("text")` 判文本模型
  （`usePreannotateConfig.ts`）。二次推理复用同判据 `needsTextPrompt(cap)`。
- **面板全宽根因 + 最终方案**：`SchemaForm` 是共享组件（批量预标也用），不宜全局改宽度。
  初版把面板挂在工具条底部（先全宽、后限宽左列），用户实测均嫌丑（全宽太长空 / 窄列孤零零）。
  **最终改为 `⚙` 按钮下方的独立 popover**（`absolute right-0 top-full`，固定 `w-72`），彻底脱离工具条宽度，
  像正常「下拉参数」。`[&_select]:self-start` 保留（枚举下拉按内容宽）。齿轮从 emoji ⚙ 换成 `Icon settings`。

## 改动

- `useSecondaryInference.ts`：`buildSecondaryInferencePayload` 加第 4 参 `prompt`（trim 后非空才带，否则 null）；
  导出 `needsTextPrompt(cap)`。
- `SecondaryInferenceBar.tsx`：
  - `promptByKey` 组件 state（按能力；每次运行的临时查询，**不持久化**——文本是内容相关的一次性查询）。
  - 开集能力（`needsTextPrompt`）在能力行加「文本」输入框；空文本时「运行」禁用 + 提示。
  - payload 传 `promptByKey[key]`。
  - 参数面板改为 `⚙` 下方独立 popover（`absolute right-0 top-full w-72 [&_select]:self-start`），
    从工具条底部移出；齿轮换 `Icon settings`（#2）。

## 验收

- 选开集检测/分割能力 → 出现文本框；空 → 运行禁用；填 `car . person` → 可运行且 payload.prompt=该值。
- 闭集能力 → 无文本框。
- 点 ⚙ 在其下方弹出固定宽度参数 popover（滑块 / 下拉不再随工具条铺满整行）；批量预标的 SchemaForm 不受影响。

## 不在范围

- 文本查询持久化（一次性内容查询，无需记住）。
- alias 快捷勾选（批量预标那套 prompt alias frequency）——二次推理先纯文本框，够用。
