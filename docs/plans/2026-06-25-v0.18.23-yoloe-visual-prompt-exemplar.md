## 1. 背景 / API 事实

YOLOE visual prompt (`model.py:351` `predict(...)`):
```python
model.predict(source,
  visual_prompts={"bboxes": [[x1,y1,x2,y2],...], "cls": [0,...]},
  refer_image=参考图,
  predictor=YOLOEVPDetectPredictor)   # 或 YOLOEVPSegPredictor (分割)
```
即「在参考图上给若干框样例 + 类别索引 → 找全图同类目标」，输出 bbox 或 mask。这与平台 sam3 exemplar (拖框样例找全图同类) **概念一致**，是 `third-party/plan` 所说 yoloe「应该有带交互的模式」。

源码: `YOLOEVPDetectPredictor` / `YOLOEVPSegPredictor`
(`third-party/onnxtools/third_party/ultralytics/ultralytics/models/yolo/yoloe/predict.py:11,159`)。

## 2. 与 sam3 exemplar 的对齐 (复用 / 差异)

平台 exemplar 链路已完整 (sam3)，**协议词 `exemplar` 已是一等公民** (`apps/_shared/protocol_v2/src/aap_protocol_v2/vocab.py:50-58` `PROMPT_VALUES` 含 `exemplar`)。

| 维度 | sam3 exemplar | YOLOE visual prompt | 处理 |
|---|---|---|---|
| 协议词 | `type="exemplar"` | 同 | **复用 `exemplar`** |
| 正样例框 | `exemplars[].bbox` (xyxy) + `label=True` | `visual_prompts.bboxes[]` | bbox 复用 |
| 负样例框 | `label=False` 支持 | **YOLOE 无负框** | 工具栏对 yoloe **隐藏负极性** |
| 类别 | 无 (用 text/默认) | `cls[]` 类别索引 | yoloe 特有，MVP 用单类 `object` |
| 参考图 | 同图 (编码器缓存) | `refer_image` | yoloe 同图: `refer_image=source` |
| 输出形态 | box/mask/both | det→box / seg→mask | 映射 box/polygon |
| 阈值迭代 | `score_threshold` per-req | yoloe `conf` | 复用阈值机制 |
| 平台转发 | `/interactive-annotating` 直通 context | 同 | **平台零改** |
| 前端会话 | `useInteractiveAI` exemplar 会话 | 同 | **复用 hook** |

**平台侧零改动**: 交互端点 `/interactive-annotating` (`apps/api/app/api/v1/ml_backends.py:474-516`) 与 `predict_interactive` (`apps/api/app/services/ml_client.py:218-262`) 把 `context` 直通 backend，无任何转换。

**前端基本复用**:
- 会话 hook `apps/web/src/pages/Workbench/state/useInteractiveAI.ts:64-507` (sessionExemplars / 每次重发全量 / dispatchExemplar)。
- 工具 `apps/web/src/pages/Workbench/stage/tools/ExemplarTool.ts:12-45` (`requiredPrompt: "exemplar"` → backend 声明即自动启用)。
- 控件 `apps/web/src/pages/Workbench/shell/AIToolDrawer.tsx` (极性/输出/阈值)。
- 画布 overlay (正框绿 / 候选紫虚线)。

## 3. 目标 / 非目标

**目标**: 工作台拖框样例 → yoloe 找全图同类，输出框/mask；复用 exemplar 工具与会话；同图样例 MVP。

**非目标**
- 不做跨图 refer_image (同图优先；跨图后续)。
- 不做负样例框 (YOLOE 不支持)。
- 不做多类别精细管理 (MVP 单类 `object`，类别选择器后续)。

## 4. 设计与改动

### 4.1 后端 yolo-backend
- `schemas.py` `Context`: 新增 exemplar 字段 —— `exemplars: list[{bbox, cls?}] | None` (复用 sam3 字段名以统一)；`output: Literal["box","mask"]`。同图: 不强制传 `refer_image`，缺省取 source。
- `predictor.py`: 新增 `predict_visual_prompt()` —— 组装 `visual_prompts={"bboxes":[...], "cls":[...]}`，det 用 `YOLOEVPDetectPredictor`、seg 用 `YOLOEVPSegPredictor`，`refer_image=source`；映射 `rectanglelabels`/`polygonlabels`。
- `main.py` `/predict` (或 `/predict/interactive`): 新增 `type=="exemplar"` 分支；`/setup` 给 yoloe model 的 `supported_prompts` 加 `"exemplar"`，backend `is_interactive` → **true**。

### 4.2 前端
- `ExemplarTool` 已按 `requiredPrompt:"exemplar"` 启用 —— yoloe 声明后自动可用。
- yoloe 分支**隐藏负极性按钮** (无负框)；`AIToolDrawer` 极性 UI 按当前 backend 能力条件渲染。
- 会话 dispatch 复用 `dispatchExemplar`，cls 暂固定单类。

### 4.3 双 exemplar backend 路由 (关键开放问题)
sam3 与 yoloe 若同项目都声明 `exemplar`，交互工具该路由到哪个 backend？现有 capability 路由按 backend，**需在实现期确认**: 是按用户选定的当前交互 backend、还是需新增选择 UI。先以「单一交互 backend」假设落地，冲突再处理。

## 5. 验收
- yoloe `/setup` 含 `exemplar`，`is_interactive=true`。
- 工作台拖框样例 → 返回同类候选框/mask；改阈值重跑生效。
- 负极性在 yoloe 下不出现；sam3 exemplar 回归不受影响。

## 6. 风险
- **refer_image 语义**: 同图样例需确认 `YOLOEVPDetectPredictor` 同图 (source==refer) 行为正确。
- **cls 映射**: MVP 单类，多类需求出现时再设计类别选择。
- **双 exemplar 路由** (§4.3) 未决，可能需额外 UI。
- 显存: VP predictor 加载 + 推理，8G 卡 s 档为主。
