> 规划日期 2026-06-14 · 范围:把 v0.15.18 邻帧点云叠加的「动态目标必留拖影」做一个**开关式简化收口**——邻帧点落在当前帧 tracked box 内的直接剔除,只叠静止背景。ROADMAP §C.8-B 原话「比 A 简单(只判点-在-框内,不做逐目标变换),可作为 A 的开关式简化版先上」。
>
> **版本号约定**:当前已发布 v0.15.20,在途未进 CHANGELOG 的浮窗/PSR 面板修复算 v0.15.21;本 3D 前线系列从 v0.15.22 起,如有偏移顺延。
>

## 1. 背景与现状

### 1.1 要解决的问题

v0.15.18 用 **ego-only 刚体补偿**叠邻帧点云:静止背景重合加密(✅),动态目标(其它车/行人)因只抵消了车自身运动、抵消不了目标自身运动,**必然沿运动方向留拖影**。v0.15.18 已做视觉缓解(前/后帧分色 + 时序淡出),但拖影仍会遮挡当前帧标注。本版给一个「干脆不显示动态点」的开关:**把落在已标注 box 内的邻帧点剔除**,只留有价值的静止背景加密。

### 1.2 现状(已读源码)

- 邻帧点云组装:`ThreeDWorkbench.tsx:2057-2086` —— `neighborPcds`(ISO ego 系,已下采样到 `pcdDecimate/8`、上限 8 万/帧)→ 每帧算 `frameRelMatrix(邻帧 pose, 当前 pose)` → `{positions, matrix, dir, distance}` 喂 `scene.setNeighborPoints(frames)`。
- `PointCloudScene.setNeighborPoints`(`PointCloudScene.ts:801-831`)把 `matrix` 作为 **Points 对象矩阵在 GPU 端施加**(无逐点 CPU 开销)。
- 当前帧 boxes 在 `ThreeDWorkbench.tsx:919` 经 `scene.setBoxes(boxes)` 同源可用;组装邻帧点云的同一组件作用域内即可拿到。
- `geometry/box3d.ts` 已有 `psrToCorners`;点-在-OBB 测试可直接用 PSR 构 box-local 变换。

### 1.3 做 / 不做

**做**:
- 新增纯函数 `geometry/cullDynamicPoints.ts`:`cullPointsInBoxes(positions, relMatrix, boxes, opts)` —— 每个邻帧点经 `relMatrix` 对齐到当前帧 ego 系后,做 point-in-OBB 测试,落在任一当前帧 box 内即剔除,返回过滤后的 `Float32Array`(原始 ISO ego 坐标,GPU 仍按 `relMatrix` 渲染)。
- 设置项 `workbench.pointcloud.neighborPointCull`(枚举:`keep` 保留拖影 / `cull` 剔除动态点),进 `workbenchSettingsFields.ts` 注册表 + 抽屉 + 个人设置页。**默认 `keep`**(= v0.15.18 现状,零回归)。
- 剔除点数在 UI 透出(呼应「no silent caps」)。

**不做**(留 v0.15.23 §C.8-A):
- 逐目标位姿补偿(把动态点对齐到当前位置一起加密)。本版动态点是**剔除**不是**搬运**。
- 未标注动态物:无 box 即无从判定,仍走 ego(留拖影)。这是 B 的固有局限,文档讲清。
- 不引入运动模型 / 学习式动静分割(§C.8-D)。

### 1.4 成功判据

1. **默认零回归**:`neighborPointCull=keep` 时渲染与 v0.15.18/19 完全一致。
2. **剔除生效**:scene-0061 开 `cull` + K=3,一辆行驶车辆的邻帧拖影点消失,周边静止路面/墙点仍加密。
3. **框外守恒**:静止背景点(不在任何 box 内)无论开关如何都保留。
4. **透明度**:UI 显示本次剔除点数(如「邻帧点:剔除 1.2k 动态点」)。
5. **性能**:开 `cull` 后交互帧率与 `keep` 无显著差异(剔除是一次性 per-overlay-rebuild,见 §3.3)。
6. `pnpm test` / `pnpm lint` 全绿;新纯函数单测覆盖。

## 3. 设计要点

### 3.1 point-in-OBB 核心(`cullDynamicPoints.ts`)

```
cullPointsInBoxes(positions: Float32Array, relMatrix: Matrix4,
                  boxes: {center,size,rotation}[], opts?: {margin?: number})
  → { kept: Float32Array, culledCount: number }
```

- 预计算:每个 box 一个 `inv(worldMatrix)`(由 PSR `compose(center, eulerXYZ(rotation), 1)` 求逆);`half = size/2 + margin`。
- 对每个点 `p`(ISO ego 邻帧系):`p_cur = relMatrix · p`(对齐到当前帧 ego);再对每个 box `q = invBox · p_cur`,若 `|q.x|≤half.x && |q.y|≤half.y && |q.z|≤half.z` → 命中 → 剔除,early-out 下一个点。
- `relMatrix` 复用 `ThreeDWorkbench` 已算好的同一矩阵(不重复算)。`margin` 默认 0,可留小正值(如 0.1m)吃标注松边。

### 3.2 接入点(`ThreeDWorkbench.tsx:2072`)

- 在 `.map()` 构 `NeighborFrame` 时,若 `neighborPointCull==='cull'` 且 `boxes.length>0`,把 `pcd.positions` 换成 `cullPointsInBoxes(pcd.positions, matrix, boxes).kept`;累加 `culledCount` 透出。
- **boxes 进 useEffect 依赖的代价**:当前邻帧点云 useEffect deps 不含 `boxes`;加剔除需让其感知 box 变化。为避免拖框时每帧重剔(重建邻帧层),**只在 box 集合「提交态」变化时重算**——用 `boxes` 的稳定签名(id+PSR 量化)或仅监听非拖拽态;拖拽进行中沿用上次剔除结果(邻帧层是参考辅助,容许 1 帧滞后)。实施时优先简单方案(依赖 `boxes` + 拖拽中 early-return),手感不行再上 debounce。

### 3.3 性能

- 邻帧点已下采样(≤8 万/帧),box 数量为十级;point-in-OBB 是 矩阵×向量 + 3 比较,early-out。最坏 8万×3帧×30框 ≈ 7M 次,主线程一次性 < 50ms,可接受。
- 仅在邻帧层重建时跑(非每渲染帧)。若实测卡,下沉到 `pointcloud.worker.ts`(邻帧加载已在 worker 链路)。

### 3.4 设置与门控

- `neighborPointCull` 仅在 `neighborPointOverlay` 开启时有意义;抽屉里作为其子项呈现。
- 无 box 时 `cull` 等同 `keep`(无可剔除),不报错。

## 5. 风险 / 未尽

- **仅对已标注目标有效**:未画 box 的动态物仍拖影。文档讲清「先标完动态目标再开剔除最干净」。这是 B 与 A 的共同前置。
- **box 与点不严丝合缝**:松框会漏剔边缘点、紧框会误剔贴边背景点;`margin` 调参,默认偏保守(0~0.1m)。
- **拖拽实时性**:拖框时邻帧剔除滞后一帧可接受;若手感差再 debounce。
- **与 §C.8-A 的关系**:A 落地后,设置升级为三态(`keep` / `cull` / `align`),B 的 point-in-box 路由被 A 复用。本版先把路由 + 设置骨架立起来。

## 6. 验证策略

- **纯函数单测**:轴对齐框 + 旋转 45° 框,断言框内点被剔、框外点保留;`relMatrix=identity` + 框在原点的退化用例;空 boxes 返回原数组(引用或等值)。
- **真实数据**:scene-0061 回填 pose,K=3,`cull` 开/关对比——行驶车辆拖影点消失、静止结构加密不变;剔除计数 > 0 且合理。
- **回归红线**:`keep` 默认渲染与 v0.15.19 逐像素一致;当前帧点云不受影响(只过滤邻帧)。
