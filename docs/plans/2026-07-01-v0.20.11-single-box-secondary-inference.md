# v0.20.11 · 选中框单框二次推理入口

状态：草案（draft）。四问探讨 Q1 的交互入口。**依赖 v0.20.9（子框呈现）+ v0.20.10（AI 属性溯源）**。

## 背景

用户诉求：画完一个标注（通常是矩形框）后，基于这个框在**小图上做二次推理**——在框内检测子物、
或分类出属性、或 OCR。现在平台只有「整图批量预标注」和「整图交互出新对象」，缺「选中一个框 → 在
这个框内跑某能力」的**单框手动入口**。

调查结论：这**不是新引擎**——批量 pipeline 的 crop→二次推理链、以及交互端点都已存在，本版只是把
能力下探成「单框手动触发」，复用现有链路。

## 现状（已核实）

- **交互端点已存在**：`POST /projects/{id}/ml-backends/{bid}/interactive-annotating`
  （`ml_backends.py:536`），同步吃 `task_id + context{type, points/bbox}`，现语义是「在整图上
  交互出新对象」。
- **crop 二次推理链已存在**：batch pipeline 下游阶段裁父框 ROI → 上传 → `/predict` → 写属性 /
  出子几何（`roi.py` 的 `crop_inputs_from_boxes` / `geometry_prompts_from_boxes`）。
- **画布上下文条**：[[project_interactive_toolbar_redesign]] 已把 AI 工具收进画布顶部上下文条，
  上下文可从「当前题」切到「当前选中的框」。
- 缺的只是：选中框 → 列出「对这个框能跑什么」→ 触发 → 产物按类型归位。

## 目标

选中一个标注 → 右键 / 上下文条列出「当前对象支持的能力」→ 在框的小图上跑 → 属性型写回原框、
几何型建子框，全部带 AI 溯源。

## 工作项

### WS1 · 入口与能力筛选

- 选中框时，画布顶部上下文条（复用 [[project_interactive_toolbar_redesign]]）列「当前对象支持的
  能力」。
- **能力筛选**：按 backend `supported_inputs` 含 `image_region` / `crop` 过滤（依赖 v0.21.0 的
  `INPUT_VALUES` 词表化；若本版早于 0.21.0，先本地判定、待 0.21.0 收编到统一词表）。

### WS2 · 调用（复用 crop 投递）

- 把**选中框的 bbox 当 ROI**：复用 pipeline crop 投递的单框版——裁 ROI → 上传 import 桶 →
  presigned URL → 调 backend。可直接调 `interactive-annotating`（扩一个 `roi` 模式），或复用
  batch crop 路径的单框分支。**避免另起一套投递逻辑**。
- 同步返回（单框推理快），产物回填画布。

### WS3 · 产物归属（接 Q2 + Q1a）

- **属性型**（分类 / OCR / 文本）→ 写回选中框 `attributes`，`attributes_meta` 标 `origin=ai` +
  model_ref（走 v0.20.10）。
- **几何型**（子检测 / 子分割）→ 建**子框**，`parent_annotation_id=选中框`（走 v0.20.9），
  `source="prediction"`。

### WS4 · 坐标换算

- ROI 结果映回原图坐标（或相对子框）——**严格走归一化**，backend 交互候选归一化 0-1、批量入库
  百分比 0-100 的区分见 [[project_interactive_candidate_coords]]（yolo exemplar 误发百分比致候选
  飞出画布的教训，本版是同一类坐标陷阱）。

## 风险

- **与批量 pipeline 是「同一能力两个触发面」**：单框入口和批量二次推理的产物 schema、溯源写法
  必须一致，不能分叉两套（否则审核 / 导出要 case-by-case）。
- ROI 太小 / 贴边时的 padding 与坐标回映边界。

## 验收

- 选中一个车框 → 上下文条出现「车牌检测 / 属性分类」等该框可跑的能力。
- 跑属性分类 → 原框 attributes 多出 AI 属性、带溯源 chip。
- 跑子检测 → 框内出现子框、挂在父框下（侧栏缩进可见）。
- 单框入口与批量 pipeline 跑同一能力，产物结构一致。

## 依赖 / 不在范围

- **强依赖 v0.20.9（子框呈现）+ v0.20.10（属性溯源）**；受益于 v0.21.0 `supported_inputs` 词表化。
- 不做：`image_sequence` / `video_range` 源（见 Q4 串 v0.21.1）、多能力串成流水线（那是编排选择器
  v0.21.0 的事，单框入口只跑单个能力）。
