> 规划日期 2026-06-16 · 范围:画布栈统一 epic 的**硬前置地基版**。本版**不动任何用户可见行为**——只立测试基建、量化帧合成性能、抽公共 stage 原语、定架构决策。Epic 见 [`2026-06-16-v0.16.x-canvas-unification-epic.md`](2026-06-16-v0.16.x-canvas-unification-epic.md)。

> **前置依赖**:无(本版是 epic 的起点)。
> **后置**:v0.16.1(视频媒体层进 Konva)硬依赖本版三件产出。

## 1. 背景与目标

把视频迁到 Konva 之前,有三件事不先做好,后面每一版都在沙地上盖楼:

1. **测试基建缺位**:视频现有大量 RTL 测试查 SVG DOM 节点(`VideoStage.test.tsx` 用 `getByTestId("video-overlay"/"video-track-shape"/"video-selected-shape")` + `fireEvent` 指针事件),Konva 渲染到 canvas **无 DOM 可查**会整片失效;而图片侧 `vitest.setup.ts` **没有 react-konva mock**、`imageStageSettings.test.ts` 只测纯函数——**全仓库没有一个 Konva 组件交互测试的范式**。迁移前必须立起。
2. **帧合成性能未知**:决策 A(`Konva.Image` 以 `<video>` 为 source 逐帧重绘)是否扛得住 1080p@30 / 4K@60,纯靠推断不能下注,要实测。
3. **viewport 逻辑锁在 ImageStage 里**:缩放/平移/fit-to-canvas/滚轮步长/scale 抵消散落在 `ImageStage.tsx`(`fitNow()` `:412`、滚轮 `:453-483`、`wheelZoomFactor`),视频要复用必须先抽公共。

### 1.1 本版三件产出 + 一份决策

| 产出 | 交付物 | 验收 |
|---|---|---|
| Konva 测试基建 | `react-konva` mock(DOM stand-in)+ Playwright 冒烟脚手架 + 一个图片侧样板组件测试 | 能对 Konva 组件跑 `fireEvent` 交互断言;Playwright 能截图比对画布 |

| 架构决策 | 新增 ADR + 扩写 ADR-0004 | 团队可据此实施 v0.16.1+ |

## 3. 设计要点

### 3.1 react-konva mock 形态(决策 C 的工程落地)

- `vi.mock("react-konva")`,把每个 Konva 组件映射成一个 `<div data-konva="Rect" data-testid={props.name} ...透传几何/样式 props>`,事件 props(`onMouseDown`/`onClick`/`onPointerDown`)挂到 DOM 上,使 `fireEvent` 可触发。
- 目的:**保住现有 RTL 断言风格**(`fireEvent` + `getByTestId` + 回调断言),迁移视频测试时改动量最小。
- 局限明示:mock 不验证真实 canvas 绘制(那交给 Playwright)。文档写清「mock 测交互/props,Playwright 测真渲染」的分工。
- 给 `name` prop 约定:所有需被测的 Konva 形状传 `name="..."`,mock 转 `data-testid`,与现有 `data-testid` 选择器对接。

### 3.2 帧合成 spike 怎么做才有说服力

- 隔离 demo 不接生产数据;造一个 N×M 视频源(或现有 seed 视频),挂 `Konva.Image`,`Konva.Animation` 里每帧 `layer.batchDraw()`,用 `performance.now()` 采样**单帧绘制耗时**与**掉帧率**。
- **必测分层方案(推荐主路径)**:视频放**单独一个 Konva Layer**(独立 canvas),标注放另一层;播放时只 `videoLayer.batchDraw()`,标注层不动。对照「单层混画(视频+标注同层每帧重绘)」量化分层收益——这是 A1 能否成立的关键变量,不能只测单层。
- 矩阵:{720p, 1080p, 4K} × {30fps, 60fps} × {分层 vs 单层} × {纯底图, 底图+20 个框}。
- 对照基线:同条件下旧栈(`<video>` + SVG)的帧表现。
- 结论判据:若**分层下** 1080p@30(标注主力场景)视频层单帧 < 8ms 且无明显掉帧 → A1 通过;4K@60 仅作上限参考,可结合「暂停态走 bitmap 缓存、播放态才重绘」的实际使用模式放宽。仅当分层都救不回来才转 A2。
- 产出写 `docs/plans/_spike-results/`,ADR 引用。

### 3.3 公共 viewport 原语边界

- 只抽**纯计算**:`fit.ts`(`Math.min(vp/content)` 居中,等价 `ImageStage.tsx:412-416`)、`zoom.ts`(光标定点缩放,等价 `:475-479`)、`scaleCancel.ts`(`px/scale`)。
- **不抽** React 状态/事件绑定(那是 stage 各自的)。视频 v0.16.1 复用这些纯函数,自己接事件。
- 图片先迁过去当「第一个消费者」验证等价,降低视频复用风险。

### 3.4 ADR 要钉死的契约

- 决策 A 结论(A1 or A2)+ 触发降级的量化阈值。
- 决策 B:存储归一化、渲染像素、Konva transform;废弃 SVG CTM。
- 决策 C:三层测试分工(纯函数 / konva mock / Playwright)。
- 视频 Layer 结构提案(对齐图片 5 Layer:media-bg / track / overlay-draft / issue),供 v0.16.2 落地。

## 5. 已知风险 / 未尽事项

- **react-konva mock 维护成本**:Konva 组件多,mock 要覆盖视频/图片用到的全集;先覆盖样板所需,v0.16.2/.3 按需补。明确 mock 是「交互/props 验证」非「渲染验证」,避免被误用为渲染回归网。
- **spike 结论可能推翻 A1**:若 perf 不达标转 A2(透明 Konva 盖 `<video>`),则 v0.16.1 起坐标需同步两个 transform——ADR 要把 A2 的同步契约也写清,作为正式契约而非临时补丁。
- **Playwright 在 CI 的稳定性/耗时**:截图比对易因字体/抗锯齿环境差异 flaky;基线截图固定容器尺寸 + 容差阈值,冒烟只跑关键路径(非全量)。
- **viewport 抽取漏改**:`ImageStage` 缩放/fit 散落多处(`:412/430/444/475`),抽取后 grep 验证无残留内联计算;图片手工验收滚轮/双击 fit/翻页 fit/拖宽边栏 autoFit 四条路径。

## 6. 验证策略

- **纯函数单测**:viewport fit/zoom/scaleCancel 各覆盖边界(超宽/超高内容、缩放上下限、光标定点不漂移)。
- **konva mock 样板测**:画框 pointerdown→move→up 触发 `onCreate`;选中态 props 变化可断言。
- **Playwright 冒烟**:图片任务画框 + 截图基线(本版只立图片基线,视频基线 v0.16.1 起补)。
- **图片零回归**:viewport 收口后,现有图片相关测试全绿 + 手工四路径(滚轮/双击/翻页/边栏 autoFit)。
- `pnpm lint`(含 `lint:css-tokens`)、`uv run pytest -q`(本版后端零改动,跑一遍确认无连带)。
