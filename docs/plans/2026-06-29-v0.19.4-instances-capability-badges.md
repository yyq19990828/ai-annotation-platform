# v0.19.4 · 模型市场 instances 视图能力徽标

状态：草案（draft）。纯前端小增量，吃 v0.19.2 WS0 刚透传到 `/instances` 的字段。无后端改动。

## 背景

v0.19.2 WS0 让 `GET /v1/ml-capabilities/instances` 补透传了 `supported_inputs` + `resource_profile`
（原被裁掉）。但消费方 `CapabilityCatalogPanel`（协议卡视图）还没用上这两个字段——徽标信息停在
v0.19.2 之前的水平。这是「数据已到、UI 没接」的纯红利项。

## 目标

把新到的两个字段在模型市场 instances 卡片上渲染成可读徽标，让用户一眼看出「这个 model 能批量吗 /
能吃什么投递形态」，无需进项目编排才发现。

## 落点

- `apps/web/src/pages/.../CapabilityCatalogPanel`（协议卡视图，`source` 徽标已在此渲染）—— 子卡补：
  - **批量徽标**：`resource_profile.batchable===true` → 「可批量」chip；`false` → 「交互/有状态」chip；缺省不显示。
  - **设备徽标**：`resource_profile.device`（`gpu`/`cpu`）→ 小 chip；缺省不显示。
  - **可接受输入**：`supported_inputs`（`full_image`/`crop`/`bbox_prompt`/`point_prompt`）→ 「整图/裁剪/框/点」图标行（与协议 reference §3.1 措辞一致）。
- 前端 `MLModelCapability` 类型已含 `supported_inputs` / `resource_profile`（`apps/web/src/api/ml-backends.ts:61,84`），openapi 重生成后 instances 响应也带这俩，无需手改类型。
- 复用项目编排里「可接受输入」既有渲染（`ModelCard` 已展示部分），保持视觉一致。

## 风险

极低（纯展示、缺省即隐藏、向后兼容）。唯一注意：颜色用语义 token（CLAUDE.md §6），不写裸色。

## 验收

- 注册一个 `batchable=true` + `supported_inputs=["full_image","crop"]` 的 backend → 模型市场卡片显示「可批量」+「整图/裁剪」徽标。
- `batchable=false`（交互/tracker）→ 显示「交互/有状态」。
- 老 backend（`resource_profile={}` / `supported_inputs=[]`）→ 不显示相关徽标，无报错。

## 排期与依赖

- 强依赖 v0.19.2 WS0（已落）。与其它计划无耦合，可随时穿插。
- 半天量级，纯前端，无 alembic。
