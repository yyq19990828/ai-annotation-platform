# v0.15.7 · 项目级规范下沉 + 性能档位(设置体系收尾)

> 规划日期 2026-06-11 · 范围:把「影响标注产出一致性」的三项配置下沉为项目级规范(3D 默认框尺寸、视频传播覆盖策略、tracker 默认模型——顺手修掉 `mock_bbox` 硬编码默认的准 bug),并把视频缓存/预取与点云降采样等性能常量归并为 `common.performanceTier` 三档。本版收尾整个设置 epic。Epic 见 [`2026-06-11-v0.15.x-workbench-settings-epic.md`](2026-06-11-v0.15.x-workbench-settings-epic.md)。
>
> **前置依赖(硬)**:v0.15.3(锁定映射与注册表)。**软依赖**:v0.15.5(tracker 对话框初值解析函数插入点)、v0.15.6(DECIMATE 消费点形态)——若乱序实施,对应项顺延到后发版本,不阻塞本版其余内容。

## 1. 背景与目标

### 1.1 为什么这三项必须是项目级

| 配置 | 现状 | 配错的后果(用户级不可接受的原因) |
|---|---|---|
| 3D 新框默认尺寸 | 硬编码 `[4.0, 1.8, 1.6]`(轿车),`ThreeDWorkbench.tsx:108` | 行人数据集上每个框都从轿车尺寸改起;两个标注员若各自设不同默认值,初始框差异引入系统性偏差 |
| 传播覆盖已有关键帧 | 对话框默认 false,`VideoKeyframesPropagateDialog.tsx:44`(v0.15.5 起用户粘性) | 覆盖策略是团队标注规范:有人覆盖有人不覆盖 → 同一项目的关键帧语义不一致 |
| Tracker 默认模型 | 硬编码 `"mock_bbox"`(测试用!),`VideoTrackerPropagateDialog.tsx:71` | 生产项目用户不改选会拿 mock 结果;模型可用性本就由项目绑定的 ML backend 决定,默认值理应同源 |

### 1.2 本版两件事

**A. 项目级规范(`ProjectRenderingConfig` 扩展 + 锁定)**

| 项目字段 | 语义 | 用户侧交互 |
|---|---|---|
| `box3dDefaultSize: [l,w,h]?` | 设了 → 该项目新建 3D 框用此尺寸 | 纯覆盖,无对应用户字段(用户不可调,显示在抽屉只读区) |
| `propagateOverwrite: bool?` | 设了 → 两个传播对话框 overwrite 固定此值并禁用 | 锁定式(复用 `LockableField` 交互:控件禁用 + 项目锁定 badge) |
| `trackerDefaultModel: str?` | 设了 → tracker 对话框默认选中此模型 | 默认值式:用户仍可改选;初值解析 = **项目默认 > 用户粘性记忆(v0.15.5)> 现状回退** |
| 未设 `trackerDefaultModel` 时 | 默认值改为「项目可用模型列表第一个非 mock 项,否则 mock_bbox」 | 修准 bug:mock_bbox 仅在无真实 backend 时兜底 |

**B. 性能档位(`workbench.common.performanceTier`)**

| 常量(现硬编码) | light | standard(=现状) | aggressive |
|---|---|---|---|
| 视频 bitmap 缓存,`useVideoBitmapCache.ts:25` | 24 | **48** | 96 |
| WebCodecs 帧缓存,`useVideoChunkDecoder.ts:56` | 24 | **48** | 96 |
| 缩略图缓存,`useVideoFramePreview.ts:56` | 60 | **120** | 240 |
| 拖拽预取半窗,`useVideoFramePreview.ts:60` | 1 | **3** | 6 |
| 锚点预取数,`useVideoFramePreview.ts:62` | 4 | **8** | 16 |
| 点云降采样阈值,`PointCloudScene.ts:22` | 250k | **500k** | 1M |

控件:select(轻量 / 标准 / 性能优先),默认 standard;放抽屉「通用」组 + Settings 页,旁注内存影响。**只暴露档位,不暴露原始数值**(epic 原则 3)。

### 1.3 不在本版本

- 项目级配置的**批量管理 UI**(模板库联动、跨项目复制):项目模板体系(v0.10.14)的事,这里只在项目设置页加一张卡片。
- `largeFrameStep` / 播放速率等纯手感项的项目锁定:无产出一致性影响,不下沉。
- 性能档位的设备自动探测(按内存/GPU 自动选档):先观察手动三档够不够。
- per-项目用户偏好(同一用户分项目存手感):epic §5 已明确不做。

### 1.4 成功判据

1. **默认零回归**:未配置项目规范的项目、performanceTier=standard 的用户,行为与 v0.15.6 byte 级一致。
2. 项目设 `box3dDefaultSize=[0.6,0.6,1.7]`(行人)后,该项目新建 3D 框为该尺寸;其他项目仍 `[4.0,1.8,1.6]`。
3. 项目设 `propagateOverwrite=true` 后,两个传播对话框 overwrite 勾选且禁用、带锁定 badge;用户粘性记忆不生效也不被污染。
4. tracker 对话框初值:绑定了真实 backend 且未设项目默认的项目,不再默认 mock_bbox;设了项目默认的尊重之;用户改选过的(粘性)在项目默认缺位时优先。
5. performanceTier 三档切换后,六个消费点取对应档位值(单测断言映射表);切 light 后视频缓存上限立即收缩(LRU 逐出可观察)。
6. 项目设置页「工作台规范」卡片可编辑上述三字段,权限沿用项目配置既有门槛(项目管理员)。
7. `uv run pytest -q` / `pnpm test` / `pnpm lint` 全绿;openapi 快照随 pre-commit 再生。

## 3. 设计要点

### 3.1 三种项目级语义(合并器显式建模)

v0.10.10 的 `LockableField` 只有「锁定式」。本版扩展为三种,合并器(`applyProjectOverride`)按字段声明分流:

- **锁定式**(propagateOverwrite + 既有 4 字段):项目设值 → 覆盖用户值 + UI 禁用。
- **默认值式**(trackerDefaultModel):项目设值 → 作为初值参与解析链,用户可临时改选,不禁用。
- **纯覆盖式**(box3dDefaultSize):无对应用户字段,项目不设则用代码默认;抽屉只读展示当前生效值(让标注员知道为什么是这个尺寸)。

注册表字段声明加 `projectOverride?: "lock" | "default" | "value"`,三种语义代码中各一处实现,不散落。

### 3.2 performanceTier 映射(`perfTier.ts`)

```ts
export const PERF_TIERS = {
  light:      { videoBitmapCache: 24, videoDecoderCache: 24, previewCache: 60,  prefetchHalfWindow: 1, anchorPrefetch: 4,  pcdDecimate: 250_000 },
  standard:   { videoBitmapCache: 48, videoDecoderCache: 48, previewCache: 120, prefetchHalfWindow: 3, anchorPrefetch: 8,  pcdDecimate: 500_000 },
  aggressive: { videoBitmapCache: 96, videoDecoderCache: 96, previewCache: 240, prefetchHalfWindow: 6, anchorPrefetch: 16, pcdDecimate: 1_000_000 },
} as const;
```

standard 行必须等于现硬编码值(单测断言,防漂移)。消费点全部走 hook 入参/构造参数,**不**让底层 hook 自己读 store(保持可测试性;`useVideoBitmapCache.ts:55` / `useVideoChunkDecoder.ts:169` 的 maxItems 入参已就位)。

### 3.3 tracker 初值解析链(收口 v0.15.5 留的插入点)

```
项目.trackerDefaultModel(若在可用列表)
  > 用户粘性记忆(若在可用列表,v0.15.5)
  > 列表第一个非 mock 项(项目绑定了真实 backend 时)
  > mock_bbox(兜底)
```
独立纯函数 + 全矩阵单测。「可用列表」沿用对话框现有 MODELS 来源;若后续模型列表改为后端能力下发(v0.14.11 capability catalog 方向),此函数签名不变。

### 3.4 项目设置页卡片

放在项目设置既有 rendering/锁定配置同区(v0.10.10 入口),三字段 + 「留空 = 不限制」提示;box3dDefaultSize 提供常见预设快捷填充(轿车/行人/骑行者),纯前端 sugar。

## 5. 已知风险 / 未尽事项

- **降采样阈值运行中切换**:点云已按旧 stride 构建 → 改档位后需重建几何。简化:切档位后**下次载帧/任务生效**,抽屉旁注说明;不做在线重建。
- **aggressive 档的内存风险**:4K 视频 96 帧 bitmap 是真实内存压力;文档与控件旁注明确「需 16G+ 内存设备」,且这是用户显式选择。
- **项目规范与导出/审计无关**:box3dDefaultSize 只影响新建初值,不写入标注数据语义,无迁移问题——但 PR 描述里要讲清,避免被误解为数据 schema 变更。
- **三种 override 语义的复杂度**:这是本版最大的设计面;若实现中发现「默认值式」只有 tracker 一个消费者且别扭,允许降级为该对话框内联逻辑,合并器只保留两种语义(实现时定,PR 说明)。

## 6. 验证策略

- **单测**(最重):tracker 解析链全矩阵(项目默认 × 粘性 × backend 有无 × 列表成员资格);三 override 语义合并器;PERF_TIERS.standard === 现硬编码值。
- **API 测**:ProjectRenderingConfig 新字段校验(负尺寸 422、超长模型名 422、留空合法)。
- **手工端到端**:建两个项目(行人项目设尺寸/覆盖/模型,对照项目全空)→ 同一账号来回切,验证规范只在配置项目生效、对照项目走用户偏好;切三档 performanceTier 观察视频拖拽流畅度与内存(devtools);项目管理员页卡片编辑往返。
- **回归红线**:v0.10.10 既有 4 字段锁定行为不变;v0.15.5 粘性记忆在无项目规范的项目不变;全部既有测试绿。
