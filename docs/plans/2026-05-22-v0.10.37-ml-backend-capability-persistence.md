# v0.10.37 · ML Backend 能力协商落库 + 模态派生（epic 阶段 1）

> 落地 [ML Backend 能力协商 epic](../../ROADMAP/2026-05-22-ml-backend-modality-and-ai-preannotate-redesign.md) **阶段 1** 全部 5 子项。视频 roadmap [§3.2](../../ROADMAP/2026-05-21-video-workbench-roadmap.md) 的 R23 剩余诉求（能力只读展示）也归口于此。
>
> **核心**：把 v0.10.35/36 让 `/setup` 自报的 `supported_prompts`/`supported_trackers`/`is_interactive` **存下来并消费**，让平台第一次对 backend 的「能力 / 模态」有持久化感知。后两阶段（ai-pre 模态化、video-jobs 并入）都依赖本版。

## 决策（2026-05-22 与用户确认）

- **能力快照落 `health_meta` 子键**（`HealthMeta` schema 已 `extra="allow"`，**无 alembic 迁移**），复用 `check_health` 周期刷新通道。不给 `MLBackend` 加 modality/能力列。
- **绑定校验 fail-open**：`PATCH /projects/{id}` 绑定时**实时探一次 `/setup`**，能力不兼容 data_type → 422 拒绝；探测失败（backend 暂不可达）→ **放行**（不因瞬时宕机卡住绑定，mismatch 留到 predict 时暴露）。
- **modality 派生不入库**：`supported_trackers` 非空 ⇒ 支持 video；`supported_prompts` 非空 ⇒ 支持 image。读时由能力快照算。
- **is_interactive 改派生对账**：以 `/setup.is_interactive` 为真值，在 `check_health` 时回写 `backend.is_interactive`；注册表单砍掉手填 checkbox。

---

## §A 能力快照落库 + is_interactive 派生（后端）

1. **`apps/api/app/services/ml_client.py`**：`health_meta()` 不动；新增轻量 `capabilities()`（或在 service 直接复用现有 `setup()`）。
2. **`apps/api/app/services/ml_backend.py` `check_health()`**（97-111）：拉完 health_meta 后，**best-effort 再探一次 `/setup`**（异常吞掉不影响 health 结果）：
   - 抽能力快照 `{is_interactive, supported_prompts, supported_trackers, supported_text_outputs, supported_geometric_outputs}`，派生 `modalities`，塞进 `meta["capabilities"]`。
   - 探测成功时回写 `backend.is_interactive = bool(setup.is_interactive)`（对账）。
3. **新增派生 helper** `derive_modalities(caps) -> list[str]`（放 `app/services/ml_backend.py` 或 `app/services/ml_capabilities.py`）：`["image"?] + ["video"?]`。
4. **`apps/api/app/schemas/ml_backend.py`**：加 `BackendCapabilities` 子模型 + `HealthMeta.capabilities` 字段（供前端 codegen 派生类型）。
5. 重生成 `openapi.snapshot.json` + `docs-site/api/openapi.json`。

**验收**：注册视频 backend 跑一次健康检查后，`health_meta.capabilities.supported_trackers` 非空、`modalities` 含 `video`、`is_interactive` 与 backend 自报一致。

## §B 绑定按 data_type 校验（后端）

6. **`apps/api/app/api/v1/projects.py`** PATCH 绑定（约 459）：新增 `_validate_backend_modality(db, project, backend_id)`：
   - 实时 `MLBackendClient.setup()`（best-effort）；派生 modalities。
   - `project.data_type` ∈ {image, video} 时要求对应 modality 在派生集合内，否则 422（`lidar` 暂无 backend 支持，跳过校验）。
   - 探测失败 → 放行（fail-open）。
7. 测试：`apps/api/tests/test_projects.py`（或新建）— 视频项目绑只支持图片的 backend → 422；绑视频 backend → 通过；探测失败 → 放行。

**验收**：视频项目绑只支持图片的 backend 被拒；`is_interactive` 与 backend 自报一致。

## §C 注册表单收敛 + 能力只读展示（前端）

8. **`apps/web/src/components/projects/MlBackendFormModal.tsx`**：删手填 `is_interactive` checkbox；改为「健康检查后自动探测」提示。表单仅留 name/url/auth/extra_params。
9. **已注册 backend 卡片**（`MlBackendsSection` / `RegisteredBackendsTab`）：只读展示检测到的能力（supported_prompts / supported_trackers / modalities / is_interactive），数据来自 `health_meta.capabilities`。
10. codegen 类型同步（`MLBackendCreatePayload` 去 is_interactive；`HealthMeta.capabilities`）。

## §D Step4 wizard 按模态过滤推荐（前端）

11. **`apps/web/src/components/projects/steps/Step4Ai.tsx`**：`BackendSourceSelect` 按 `form.data_type` 过滤 / 高亮推荐——视频项目优先列出 video-capable backend（从 `GlobalBackendItem.health_meta.capabilities` 派生 modality）。不兼容的标灰或下沉，不硬隐藏（保留用户兜底选择）。

**验收**：建视频项目时 wizard 优先推荐 video-capable backend；图片 backend 被标为不匹配。

## 不做（边界）

- 不动两套 job 模型 / ai-pre 路由（那是阶段 2/3）。
