# v0.16.8 选中标注浮动信息卡(图片 / 视频对齐 3D)— Epic

> 目标:把 3D 工作台"选中即现、可拖、可快速操作"的标注信息窗口体验,统一带到图片与视频工作台。
> 顺带修复图片属性编辑"看似改了实则没保存"的 BUG。

## 1. 背景与现状

三端选中标注后的"信息/操作面板"成熟度不齐:

| 端 | 现状 | 形态 | 可拖 | 痛点 |
|---|---|---|---|---|
| 3D(样板) | `ThreeDWorkbench.tsx` 内 PSR 编辑面板,选中即现 | 画布右上浮层,自写 pointer 拖动 + CSS 变量偏移 + 按 user 持久化 | ✅ | 拖动逻辑是 3D 内联自写,未复用通用基座 |
| 图片 | `ClassPickerPopover` 改类时内联 `AttributeForm` + 右栏 `attrDock` | 画布弹层 / 右栏分栏 | ❌ | ① 非"选中即现的信息卡" ② **属性保存 BUG** ③ 不可拖 |
| 视频 | `<details>` 关键帧跳转面板 + 右栏 `VideoTrackPanel` | 画布硬编码 `top/right` 浮层 / 右栏 | ❌ | ① 跳转面板不可拖 ② 轨迹操作全压在右栏,出不来 |

### 关键基础设施(全部复用,不造轮子)

- **`FloatingPanelShell`**(`shell/FloatingPanelShell.tsx`):可拖 + 可缩放 + 折叠/关闭/合并回栏,位置经 `--floating-panel-x/y/w/h` 注入。Props:`position{x,y,w,h}` / `min/maxSize` / `bounds` / `onPositionChange` / `onCollapse` / `onClose` / `onMergeBack` / `variant`。
- **`useDragMove`**(`shell/useDragMove.ts`):拖动 hook,自动跳过交互控件(`button/input/[data-floating-panel-no-drag]`),含视口 clamp。
- **浮窗状态体系**(`state/useWorkbenchShellModel.tsx` + `workbenchLayout`):已有 `floatingTaskQueue / floatingClassPalette / floatingInspector / floatingDiscussion`,统一管理 `detached` 标志 + 位置持久化 + detach/merge 动作。**本 epic 只新增一个同构成员 `floatingSelection`。**
- **`AttributeForm`**(`shell/AttributeForm.tsx`):已具备 `dirtyTracker` 的 blur-flush 机制(v0.10.6),问题仅在未传 `dirtyTracker` 的防抖路径上(详见 Phase 0)。

### 决策(已与需求方确认)

1. **实现路线**:复用 `FloatingPanelShell` 统一基座,图片/视频共用一个 `SelectedAnnotationCard` 组件;3D 后续可收敛(本 epic 不强制改 3D)。
2. **视频轨迹卡**:把右栏 `VideoTrackPanel` 的完整能力搬进浮窗(轨迹操作 / 当前帧操作 / 关键帧列表跳转 / 属性),关键帧跳转面板并入卡内。
3. **与右栏关系**:浮窗 + 右栏**共存**(对齐 3D 现状),不删右栏。
4. **定位形态(方案 A,对齐 3D)**:固定位置可拖——选中即在固定屏幕位置出现,用户拖到哪是哪、位置记忆;**不**采用"锚定跟随框"(像 `SelectionOverlay` 那样贴框、随画布平移/缩放联动)的方案 B。A 与 3D PSR 面板同类、实现最省,且与现有四个浮窗一致。

## 2. 目标 / 非目标

**目标**
- 图片、视频:选中标注即在画布上浮出一张可拖动、可折叠、记住位置的信息卡。
- 卡内承载该端"当前选中对象"的高频浏览与操作。
- 修复图片属性保存 BUG。

**非目标**
- 不重写 3D PSR 面板(可选收敛留作 Phase 4)。
- 不删除/精简现有右栏(共存)。
- 不改后端业务 API 与数据模型(annotation / task 等)。**例外**:为支持卡位置/折叠态**跨设备**记忆,在
  用户偏好 schema `WorkbenchLayoutPreferences` 新增一个**纯加性、可选**子字段 `floatingSelection`
  (`FloatingSelectionState`:`collapsed` + `x/y/w/h`,无 `detached`)。这是每个浮窗都有的既有模式的同构扩展,
  向后兼容、无迁移,不属于"改数据结构"。

## 3. 分阶段实施

### Phase 0 — 修复图片属性保存 BUG(独立可先发)✅(已实现,方案 B)

> 落地:采用方案 B(治本于卸载机制)。`AttributeForm` 卸载 cleanup 在仍有未到点的防抖时,用最新 `draftRef`
> 经 `onChangeRef`(避免闭包捕获旧 onChange)补 flush 一次;无 pending 时不触发,杜绝重复提交。覆盖所有走防抖路径
> 的调用方(含 `ClassPickerPopover` 内联属性)。已加单测:卸载补 flush、无 pending 不触发、定时器不二次触发。

**根因**:`AttributeForm` 在未传 `dirtyTracker` 时走 400ms 防抖(`AttributeForm.tsx:108-112`),而卸载 cleanup 仅 `clearTimeout` 不 flush(`line 125`)。`ClassPickerPopover` 内联属性编辑走的就是这条路径——用户改完属性、不到 400ms 就关闭弹层 → 组件卸载 → 待提交的 `onChange` 被丢弃。

**修法(二选一,推荐 A)**
- **A(治本)**:给 `ClassPickerPopover` 内联的 `AttributeForm` 接入 `dirtyTracker`(复用右栏 attrDock 已用的同一 tracker),走 blur-flush;并在 popover 关闭前显式触发一次 flush。
- **B(兜底)**:`AttributeForm` 卸载 cleanup 改为"clearTimeout 前先用最新 `draftRef.current` 调 `onChange`"——即防抖未到点也在卸载时补提交。B 可作为 A 的双保险一起做。

**验证**
- 复现:落框选类 → 内联改属性 → <400ms 内点其他类别/Esc/点外部关闭 → 重新选中该标注,属性应已保存。
- 回归:右栏 attrDock 改属性仍正常;切换选中不串值。
- 加单测:`AttributeForm` 卸载时 flush;`ClassPickerPopover` 关闭时属性已上抛。

### Phase 1 — 通用 `SelectedAnnotationCard` 基座 + `floatingSelection` 状态 ✅(已实现)

实现要点(与原计划的差异已落地):

1. **状态形态**:`floatingSelection` 没有"合并回边栏"语义,故**不用** `FloatingPanelState`(它带 `detached`),
   而是新增专用 `FloatingSelectionState`(`collapsed` + `x/y/w/h`)。形态对齐 3D 三视图浮层 `TriViewFloatState`
   (折叠态而非 detach)。
2. **跨设备持久化**:走既有用户偏好通道(`WorkbenchLayoutPreferences` → 后端 PATCH + localStorage 缓存),
   而非 localStorage-only。涉及:
   - 后端 `apps/api/app/schemas/user.py` 新增 `FloatingSelectionState` + `floating_selection` 字段(加性、可选)。
   - 前端 `api/auth.ts` 类型 + 默认值;`useWorkbenchConfig.ts` 的 KEY 名单 / patch 类型 / read·write localStorage /
     `mergeFloatingSelection` / `mergeLayout` / `applyLayoutPatch` 各处接入(与四个浮窗同构)。
3. `useWorkbenchShellModel` 增派生与动作:`floatingSelectionPosition`(默认贴画布右上)、`onSelectionPositionChange`、
   `collapseSelectionCard`/`expandSelectionCard`。
4. 新建 `shell/SelectedAnnotationCard.tsx`:展开态 = `FloatingPanelShell`(`variant="no-merge"`,可拖/缩放/折叠)+
   `children` 插槽;折叠态 = 一枚可拖小标签(对齐 3D 三视图收起体验)。标题随选中对象动态。
   附 `SelectionCardPlaceholder`(Phase 1 占位摘要,Phase 2/3 替换)。
5. **显隐规则**:图片 / 视频选中即现(3D 用自有 PSR 面板,不显示);单选 = 类别标题 + 内容;
   多选 = "N 个已选中 · 批量"精简态;无选中 = 隐藏。位置 / 折叠态跨刷新 + 跨设备记忆,跨选中保留。

**验证**:图片/视频任一端能浮出空壳卡、可拖、可折叠、刷新后位置记忆(且跨设备);不选中时不显示。

## 4. 风险与注意

- **坐标系(方案 A)**:卡为视口级浮窗(`FloatingPanelShell` 用 viewport 坐标 + bounds clamp),与画布(图片归一化 / 视频 Konva 归一化)解耦——选中即在固定位置出现、由用户拖定并记忆,**不跟随标注框在画布里平移/缩放联动**。与 3D PSR 面板同属"固定位置可拖"一类(技术差别仅在锚点:3D 锚画布容器右上、本卡锚浏览器视口并 clamp 在视口内,对使用者基本无感),且与现有四个浮窗一致。
- **共存重复**:视频右栏 + 浮窗同操作,务必共享回调,杜绝两套逻辑漂移。
- **CSS token**:新组件 CSS 仅用 `tokens.css` 既有 `--color-*`,禁 fallback/硬编码(CLAUDE.md §6,`pnpm lint:css-tokens` 把关)。
- **持久化键**:`floatingSelection` 位置 + 折叠态按 user 存,沿用现有浮窗持久化通道(后端 PATCH + localStorage 缓存,
  **跨设备**)。因后端 `WorkbenchLayoutPreferences` 为 `extra:"forbid"`,新增子字段必须同步后端 schema(见非目标例外),
  否则整棵 workbench PATCH 422。
- **文档同步**:完成后更新 `docs-site/user-guide/`(工作台章节)与必要的 concept 文档;BUG 修复按惯例不进 CHANGELOG,功能进 CHANGELOG。
