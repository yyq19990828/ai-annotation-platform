# v0.15.9 · SDK `aap` TUI 美化 + CLI 帮助细化

- 日期：2026-06-11
- 目标版本：**v0.15.9**（当前最新 0.15.8）
- 范围：A `aap tui` 易用性 / 美观度深度优化（不只是套皮）；B `aap` CLI `--help` / `-h` 细化
- 状态：**已实现**（TUI + CLI + 文档 + CHANGELOG + 版本号全部落地，101 SDK 测试通过）
- 关联：`packages/python-sdk/src/ai_annotation/tui/app.py`、`packages/python-sdk/src/ai_annotation/cli/*.py`、`docs-site/dev/sdk/tui.md`、`docs-site/dev/sdk/cli.md`

## 背景

`aap tui`（Textual 8.2.7）与 `aap` CLI（Typer 0.26.7 + Rich）功能已完整（监控四 tab + 导出/取消动作；CLI 全工作流命令），但呈现层只是「能用」：

- **TUI**：没有 `Header` / `Footer`（标题栏未渲染，按键提示靠手写 `#status-bar` 字符串拼出 `r=刷新 e=导出…`）；表格无斑马纹、无边框标题/计数；详情面板是裸 `key: value` 文本 dump；无主题、无加载态反馈；导出/取消只在特定 tab 可用，但 footer 不体现上下文（用户得记住「e 只在 Projects」）。
- **CLI**：未启用 `rich_markup_mode`，帮助无配色 / 分组 / 示例；顶层 8 个命令平铺一栏；子命令 help 仅一行，缺 `-h` 短选项、缺示例 epilog、缺 env 变量说明。

## 不可破的红线（沿用 v0.15.8）

1. **TUI 只消费 SDK 公开 API**，不碰 `_http` / 内部实现；本版纯呈现层改动，**不新增任何网络调用、不改 `client.py`**。
2. TUI 限定在 `[tui]` extra 内，**可整体删除而不影响 SDK / CLI**；只用 Textual 公开 widget。
3. **不破坏现有测试契约**（见下「测试硬约束」），美化是叠加而非重写。

## 测试硬约束（实现时逐条尊重）

`tests/test_tui_app.py`（10 用例）断言了具体结构，必须保留：

- 四个 `TabPane` 的 id：`tab-projects` / `tab-datasets` / `tab-jobs` / `tab-ml-backends`，顺序不变。
- `#status-bar` 这个 `Static` 必须存在，且 `render()` 文本中**含 base_url**；状态翻转时**含「完成」**。
- 表格 id 与列内容不变：`#projects-table` 行 `["P-1","demo-project","active","3/10"]`；jobs 行 `[0]="export"`、`[1]="running"`、`[2]` 含 `40%`；ml `[2].plain="connected"` 且 `style="green"`。
- 详情面板 id 与文本格式：`#ml-detail` 含 `model_version: v1.2` / `util 73%`；`#project-detail` / `#job-detail` 保留。
- `ConfirmModal` 仍走 `y` 确认 / `n`·`esc` 取消；终态 job 按 `c` 不弹框、状态栏含「不可取消」。
- `q` 退出 `return_code == 0`。

`tests/test_cli*.py` 只断言行为 / 输出内容 / 退出码，**不校验 help 文本** → 帮助美化安全。
注意：启用 `rich_markup_mode="rich"` 后 help 字符串里的 `[...]` 会被当 markup 解析，凡 extras 写法（`[tui]`）一律转义 `\[tui]` 或避开。

## 范围 A · TUI 深度优化

### A1 标准 Header / Footer 取代手写提示

- 顶部加 `Header()`（渲染 `TITLE`，可带时钟）；底部加 `Footer()`，由 Textual 自动渲染 `BINDINGS` 的按键，配色与高亮专业、统一。
- `#status-bar` **保留**（测试依赖），但去掉里面手写的 `r=刷新 e=导出…` 按键串（交给 Footer），改为承载动态信息：`{base_url} · jobs 每 Ns 轮询 · 上次刷新 hh:mm:ss` + 瞬态消息。三者并存不冲突。

### A2 上下文感知按键（易用性核心）

- 用 Textual `check_action` 让 `e`（导出）仅在 Projects tab 可用、`c`（取消）仅在 Jobs tab 可用——不可用时 Footer 自动灰掉对应键。
- 切 tab 时 `refresh_bindings()` 触发 Footer 重算。这样用户「看 footer 就知道当前能干什么」，无需记忆。
- 行为不变：在错 tab 按键仍走原有「仅在 X tab 可用」状态栏提示路径（双保险），现有测试不受影响。

### A3 表格与详情美化（不改内容，只改呈现）

- DataTable 开 `zebra_stripes`；容器加 `border-title`（如「项目」「任务」）并在标题右侧拼**行数计数**（如 `任务 · 3`）——计数随刷新更新。
- 详情面板：加 `border-title`「详情」，正文格式**保持原 `key: value` 文本**（测试依赖子串），仅靠容器 padding / 边框提升可读性。
- 统一 CSS：accent / panel / muted 走 Textual 主题变量（`$accent` `$panel` `$text-muted`），避免硬编码颜色。

### A4 主题与一致性

- `App` 设一个内置深色主题（如 `textual-dark` / `nord`，最终目测定）作为基线，保证配色协调；不自造调色板。
- `ConfirmModal` 微调：加 `border-title`，标题/正文/提示分层（仍 `y`/`n`/`esc`，测试不变）。

### A5 反馈细节

- worker 发起刷新时状态栏给「加载中…」轻提示，落地后清除（不阻塞、不弹窗）。
- 状态翻转保留整行高亮 + `✔` + 状态栏「N 个 job 刚完成」（测试依赖），可叠加一次 `self.notify()` toast 增强可见性。

## 范围 B · CLI 帮助细化

### B1 全局开关

- 主 `Typer` 与各子 `Typer` 设 `rich_markup_mode="rich"`，启用配色 / 加粗 / 链接。
- 所有命令支持 `-h` 短选项（`context_settings={"help_option_names": ["-h", "--help"]}`）。

### B2 命令分组（顶层 help 分栏）

`add_typer(..., rich_help_panel=...)` 把 8 个命令归类：

- **配置与交互**：`login`、`tui`
- **资源管理**：`projects`、`datasets`
- **标注流水线**：`predictions`、`export`、`jobs`
- **监控**：`ml-backends`

### B3 帮助文案 + 示例 epilog

- 主 callback docstring 扩成简短介绍 + env 变量说明（`AAP_BASE_URL` / `AAP_API_KEY` 与 `aap login` 二选一）。
- 每个子命令补 `epilog`（Rich 面板）给 1–2 条**可复制示例**，并把关键 Argument / Option 的 `help` 写清（含默认值、取值枚举来源）。
- 示例里凡含 `[...]` 一律转义，避免被 rich markup 吞掉。
