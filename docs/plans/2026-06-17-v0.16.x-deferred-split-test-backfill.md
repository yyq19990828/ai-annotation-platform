# v0.16.x · 缓拆迁移「补测试再拆」计划(解锁巨石文件拆分 Epic 的遗留项)

> 规划日期 2026-06-17 · 本文是 [`2026-06-17-v0.16.x-large-file-component-split-epic.md`](./2026-06-17-v0.16.x-large-file-component-split-epic.md) 的续作。
>
> Epic §8 把若干子模块标为 🟡「缓拆」,**首要原因是「测试覆盖不足以守护行为不变」**(红线 §2.2)。本文回答:**对这些缓拆迁移,如何先补齐守护测试、再安全开拆。**
>
> 全程仍守 Epic §2 三条红线:行为零变化、测试不回退、各刀独立可回滚。

## 1. 核心判断:缓拆原因分两类,补测试只解锁第一类

摸底(2026-06-17,三路只读探查后端 pytest 基建 / 前端 vitest 基建 / 缓拆代码结构)后,把缓拆项按「补测试能否解锁」分成两类:

| 类别 | 缓拆的真实原因 | 补测试能否解锁 |
|---|---|---|
| **A. 纯逻辑外圈** | 单纯测试覆盖不足,不敢动 | ✅ **能** —— 补表征测试(characterization test)后即可放心拆 |
| **B. 渲染时序 / 竞态内核** | jsdom 无 WebGL;rAF/paint 时机测不到;多 ref 竞态脆 | ❌ **补单测也解锁不了** —— 只能靠 Playwright 视觉基线 + 字段契约 + 人工值守 |

**诚实前提:不要指望「补齐测试」能把 B 类(`usePsrEditor`、`useStageViewport`、`usePredictionPropagation`)变成后台代理可自动拆的对象。它们的内核本质上单测不到。** 本文把 A、B 分开排,A 类可放心(甚至后台代理)做,B 类必须留人工值守。

## 2. 通用方法:每刀拆成「两个独立 commit」

这把 Epic §2.2(测试先绿、后绿)落地,并优雅绕开「红线 2 不准新增/修改断言」的表面冲突 —— 关键是把「补测试」和「拆分」分成两次提交:

1. **Commit ①(补测试)**:针对**当前未拆**代码写新表征测试 → 对现状必须全绿。本身就是覆盖率提升,独立有价值、独立可回滚。
2. **Commit ②(拆分)**:搬代码 + 改 import / monkeypatch target → **同一套测试一字不改仍全绿**。

> 这就是 Feathers《Working Effectively with Legacy Code》的 golden-master/characterization-test 守护重构标准姿势:先把网补上,再动结构。红线 2「不新增/不删除/不修改断言」约束的是 Commit ②(拆分本身不动断言);新增守护测试是 Commit ① 的前置动作,二者分提交即无冲突。

### 3.1 目标 1️⃣ `batch_permissions.py` — 行号 / 测试矩阵

- 搬迁成员(均纯判定、零 DB 依赖):`_is_owner`(`batch.py` 73–74)/`_is_reviewer`(77–78)/`_is_annotator_assigned`(81–85)/`assert_can_transition`(88–170)。
- 测试矩阵思路:提取 `VALID_TRANSITIONS` 全部 (src, dst) 边,每条 × {SUPER_ADMIN, REVIEWER, ANNOTATOR} 参数化,断言放行 / 抛 403。关键样例:
  - `(ANNOTATOR, ANNOTATING→REVIEWING)` 放行;`(REVIEWER, 同)` 403。
  - `(SUPER_ADMIN, DRAFT→ACTIVE)` 放行;`(REVIEWER/ANNOTATOR, 同)` 403(owner-only)。
  - 逆向转移 `(*, APPROVED→REVIEWING)` owner-only。
- 难度:**最简**。纯函数 + 参数化,搬迁零副作用风险。

## 6. 统一验证口径(沿用 Epic §4,补一条覆盖率注意)

每刀 PR 必须满足:

1. 后端:`uv run pytest`(目标子集 + 回归)全绿 + **OpenAPI 快照零 diff**(本批后端三刀均不碰路由,快照不应变);前端:`pnpm build`(tsc)+ `pnpm lint`(含 `check-css-tokens`)+ `pnpm test:coverage` 全绿。
2. **行为不变证据**:后端 = OpenAPI 快照零 diff + 现有测试不动断言仍绿;前端 = hook 返回字段集 / 组件 props 前后一致(`Object.keys` 对比)。
3. **覆盖率门槛注意**(`vite.config.ts`:lines/statements/functions 45%、branches 70%,当前实测 ~47.64% 仅剩 ~2.6pt 缓冲):第 2 批补纯函数测试会**抬高**覆盖率(好事);但拆 hook 时注意别把逻辑挪进已被 coverage **排除**的 `stages/three-d/*` 而平白丢覆盖。
4. 每刀 `cloc <file>` 实测前后 SLOC,PR 描述贴「拆前 N → 拆后 M + 新增 k 个子文件各 x 行」。
5. 按 memory `feedback_changelog_bugfix`:内部重构可不进 CHANGELOG,但同步受影响的 docs(若 `docs-site/dev/concepts/` 有引用这些文件路径/结构)。

## 7. 顺序与风险

```
第 1 批(后端 A 类,可后台代理):
  1️⃣ batch_permissions   → 最稳,纯函数+参数化,双守护,先做立信心
  2️⃣ annotation_propagation → 补 5 纯函数单测 → 抽协作类
  3️⃣ media_chunks/frames  → patch target 迁移核对为主;改完重启 worker

第 2 批(前端 A 类,中风险,靠纯函数单测 + 字段契约):
  useIssuePins / useCameraPanels / usePsrFloatingPanel / ImageStage 纯几何外圈

第 3 批(前端 B 类,补单测解锁不了,人工值守):
  usePsrEditor / usePointMask / useStageViewport / usePredictionPropagation
  —— 留有人值守时手动回归;不在后台代理可安全验证范围
```

- **不并行**:均触碰工作台 / worker 热路径,串行做便于隔离回归。
- **A 类每刀严格两段式 commit**(先测试后拆),任一可独立 revert。
- **若 A 类某刀拆到一半发现职责其实纠缠**(无法在不改行为前提下干净切分):停下,记入 issue,该刀缩小范围或退回 B 类缓拆,绝不为「拆干净」引入行为变化(Epic §5)。
- **子代理纪律**:若用 `Agent` 派子代理改代码,按 CLAUDE.md「Parallel Subagent Worktree Rule」加 `isolation: "worktree"` 并要求其提交到 `worktree-agent-*` 分支;验证(`uv run pytest` / `pnpm`)在主进程合并后跑(worktree 无运行环境)。
