# v0.15.23 · 邻帧点云叠加 · 逐目标位姿补偿(§C.8-A)

> 规划日期 2026-06-14 · 范围:把 v0.15.22 的「剔除动态点」升级为「**搬运**动态点」——落在 tracked box 内的邻帧点,用该目标 box 的「邻帧→当前帧」位姿变换替代 ego 变换对齐到当前位置一起加密;框外点仍走 ego。**真·消除拖影**(动态目标也加密、无拖影),等于用已有 track 数据做 lite 版 scene flow。ROADMAP §C.8-A。
>
> **前置依赖(硬)**:v0.15.22(`cullDynamicPoints` 的 point-in-box 路由 + `neighborPointCull` 设置骨架)、v0.15.17(批量端点已拉**邻帧标注含 `group_id` + PSR**,见 `ThreeDWorkbench.tsx:1952-2033` `referenceBoxes`)、v0.15.1(`egoAlign`)。

## 1. 背景与现状

### 1.1 要解决的问题

v0.15.22 §C.8-B 对动态点是「剔除」——干净但**动态目标完全不显示**。§C.8-A 更进一步:对**已标注**的动态目标,把它的邻帧点**搬到当前帧位置**一起渲染——静止背景照旧 ego 加密,动态目标也对齐加密、**无拖影**。代价是只对有 track 的目标有效。

### 1.2 现状(已读源码)——数据大半已就位

- **邻帧标注已加载**:v0.15.17 批量端点(`ThreeDWorkbench.tsx:1952`)按 scope 拉邻帧 box 标注,`referenceBoxes`(`:1977-2033`)已含每个邻帧框的 PSR + `group_id`。**§C.8-A 不需新增网络请求**,复用这份数据即可。
- **跨帧链已建**:`group_id` 跨帧链由 propagate/interpolate 维护(v0.15.1),同一目标在邻帧与当前帧共享 `group_id`(`selectedGroupId` 高亮逻辑 `:1925-1931` 已在用)。
- **邻帧点云**:v0.15.18 的 `neighborPcds`(ISO ego 系,下采样)+ `frameRelMatrix`(ego 变换)。
- **point-in-box 路由**:v0.15.22 `cullDynamicPoints` 已实现点-在-OBB 判定,本版扩成「判定 + 按目标改变换」。

### 1.3 做 / 不做

**做**:
- `neighborPointCull` 设置升级为**三态** `keep`(ego 拖影)/ `cull`(剔除,v0.15.22)/ `align`(逐目标对齐,本版)。默认仍 `keep`。
- 新增 `geometry/perObjectAlign.ts`:`alignNeighborPointsPerObject(positions, relMatrix, neighborBoxes, currentBoxes)` —— 背景点走 `relMatrix`,命中某邻帧 box 的点走该目标的 `M_curObj · inv(M_nbrObj)`,返回**已变换到当前帧 ego 系**的 `Float32Array`(GPU 端用 identity 矩阵渲染,因点不再共享单一变换)。
- 邻帧 box 与当前 box 按 `group_id` 配对;只搬「两帧都有该 group」的目标点。

**不做**:
- **未标注动态物**:无邻帧 box 即无从搬运 → 按 fallback 策略处理(见 §3.3,默认当作 `cull` 剔除,避免又冒出拖影)。
- **缺一端的目标**(仅邻帧有 / 仅当前有 group):无法算配对变换 → 同 fallback。
- 运动模型 / Kalman / 学习式动静分割(§C.8-D)。

### 1.4 成功判据

1. **默认零回归**:`keep` 与 v0.15.18/19 一致;`cull` 与 v0.15.22 一致。
2. **动态目标加密无拖影**:scene-0061 选 `align` + K=3,一辆行驶车辆的邻帧点**叠到它当前帧位置**(随当前帧车点加密),不再沿运动方向拖影。
3. **静止背景不变**:背景点仍走 ego 加密,与 `keep`/`cull` 对静止区表现一致。
4. **未标注动态物**:按 fallback 不冒拖影(默认剔除)。
5. **性能**:CPU 逐点变换(邻帧已下采样)增量 < 一次性 80ms;交互帧率无显著恶化。
6. `pnpm test` / `pnpm lint` 全绿;`perObjectAlign` 纯函数单测覆盖。

## 3. 设计要点

### 3.1 逐目标变换核心(`perObjectAlign.ts`)

```
alignNeighborPointsPerObject(
  positions: Float32Array,          # 邻帧 ISO ego 系点
  relMatrix: Matrix4,               # ego: inv(T_cur)·T_nbr(背景用)
  neighborBoxes: {groupId, psr}[],  # 该邻帧的 box(原始邻帧 ego 系 PSR)
  currentBoxes: Map<groupId, psr>,  # 当前帧 box(当前 ego 系 PSR)
) → Float32Array  # 已对齐到当前帧 ego 系
```

- 预计算每个可配对目标(`neighborBox.groupId ∈ currentBoxes`)的:`M_nbrObj = compose(nbrPsr)`、`invM_nbrObj`、`M_curObj = compose(curPsr)`、`T_obj = M_curObj · invM_nbrObj`,以及 `invM_nbrObj`(point-in-box 用)。
- 每个点 `p`:先判定属于哪个目标(point-in-OBB,复用 v0.15.22 路由,用邻帧 box 的 `invM_nbrObj`);命中 → `p_out = T_obj · p`;未命中任何目标 → `p_out = relMatrix · p`(背景)。
- 输出已是当前帧 ego 系坐标 → `setNeighborPoints` 走 identity 矩阵。

### 3.2 渲染路径(`PointCloudScene.setNeighborPoints`)

- v0.15.18 是「ISO 坐标 + GPU 端 matrix」。`align` 模式点已是异构变换,无法用单一对象矩阵 → 传**已预变换的 positions + identity**。给 `NeighborFrame` 加 `preTransformed?: boolean`,scene 据此跳过 GPU 矩阵。分色/淡出样式不变。

### 3.3 fallback(未配对目标点)

- 设置项 `neighborAlignFallback`(内部默认,不一定暴露 UI):`cull`(默认,剔除——避免冒拖影)/ `ego`(退背景,留拖影)。
- 缺一端 group、或邻帧有 box 但当前帧该 group 已删 → 按 fallback。默认 `cull` 让 `align` 模式视觉最干净。

### 3.4 性能

- 邻帧点已下采样(≤8 万/帧);逐点 = 1 次 point-in-box 路由 + 1 次 矩阵×向量。最坏与 v0.15.22 同量级 + 一次额外变换,主线程一次性 < 80ms,仅在邻帧层重建时跑。
- box 编辑触发重算的处理同 v0.15.22(拖拽中沿用上次结果)。

## 5. 风险 / 未尽

- **仅对已标注且跨帧成链的目标有效**:漏标 / 未 propagate 的动态物仍按 fallback(默认剔除)。文档讲清「先把动态目标 propagate 成 track 再用 align 最佳」。
- **track 质量**:邻帧 box 不准 → 搬运后错位。依赖 v0.15.1 propagate/interpolate 的位姿质量。
- **box 边界点归属**:贴边背景点可能误判进目标被一起搬;`margin` 沿用 v0.15.22 调参,`align` 下宜更紧(避免把背景点搬走)。
- **异构变换不能 GPU 化**:`align` 比 `keep`/`cull` 多一遍 CPU 变换;实测卡再下沉 worker。
- **与 §C.8-D 学习式动静分割的边界**:A 解决「已标注」动态物;未标注的留给将来 D(性价比低,非必要不做)。

- **纯函数单测**:构造两帧 pose + 一个沿 X 平移的目标 box(邻帧/当前帧各一 PSR,同 group)——断言目标内点搬到当前 box 位置、背景点 = ego 结果、未配对 group 走 fallback;`relMatrix=identity` + 同帧 box 退化恒等。
- **真实数据**:scene-0061,选 `align` K=3:行驶车辆邻帧点叠到当前位置加密、无拖影;静止结构与 `keep` 一致;删掉某车的 box 后其点按 fallback 不再拖影。
- **回归红线**:`keep`/`cull` 行为与 v0.15.22 逐像素一致;当前帧点云不受影响。
