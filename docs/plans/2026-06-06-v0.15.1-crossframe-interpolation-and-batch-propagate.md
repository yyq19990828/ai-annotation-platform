# v0.15.1 · 跨帧插值 + 多目标批量 propagate(把 ego 地基变成标注效率)

> 规划日期 2026-06-06 · 范围:在 v0.15.0 的逐帧 ego pose 之上,把 v0.14.1 的「`Shift+→` 逐帧手搬框」升级成「ego 运动补偿 + 关键帧插值 + 批量」,大幅减少长 scene 的逐帧重复劳动。Roadmap 见 [`2026-06-06-v0.15-temporal-fusion-roadmap.md`](2026-06-06-v0.15-temporal-fusion-roadmap.md)。
>
> **前置依赖(硬)**:v0.15.0(`scene_frame_poses` 表 + `get_trajectory`)——没有逐帧 ego pose,运动补偿/插值只能退化为「假设车没动」。v0.14.1(propagate 端点 + `cross_frame_group_seq` + `box_3d.convention_at_create` 契约)。

## 1. 背景与目标

### 1.1 v0.14.1 跨帧 UX 的天花板

v0.14.1 的 `Shift+→` 把选中 box_3d 的 PSR **原样复制**到下一帧(共享 `group_id`)。两个问题:

- **车在动 → 复制的框是错的**:nuScenes 车以 ~10m/s 行驶,0.5s/帧 → 相邻帧地物在 lidar 系平移数米;原样复制的框落在目标后方,每帧都要手动追平。
- **逐帧手搬,长 scene 累**:scene-0061 有 39 帧,一个目标贯穿全程要按 38 次 `Shift+→` + 38 次微调。

### 1.2 本版三件事

| 能力 | 用 ego 地基做什么 | 替代了什么手工活 |
|---|---|---|
| **A. 运动补偿 propagate** | `Shift+→` 时用 `pose[i]`→`pose[j]` 的相对位姿,把框的世界位置保持不变(静止物自动对齐) | 每帧追平静止物的平移 |
| **B. 关键帧插值** | 标注者只标帧 i 和帧 k(k>i+1),中间帧自动线性插值(世界系内插 + ego 补偿) | 逐帧标中间所有帧 |
| **C. 多目标批量 propagate** | 一次把当前帧**所有** box_3d 运动补偿延续到下一帧 | 逐个目标 `Shift+→` |

### 1.3 不在本版本

- **`point_mask_3d` 跨帧**:点掩码是逐帧点索引集合,跨帧无法平移复用(目标点在不同帧是不同点)。本版**明确不做**;若要,需「按世界系框重新分割」的另一套机制,留更后。
- **Kalman / 非线性运动模型**:本版插值用**线性 + ego 补偿**(恒速假设);Kalman(处理加减速/转弯)作为本版**可选 stretch**,默认关。
- **跨相机 timestamp 微秒补偿**(v0.14.2 `timestamp_delta_us`):作为 stretch,见 §3.5;不达成不阻塞主线。
- 多 lidar / 跨 dataset scene(v0.15.2+)。

### 1.4 成功判据

1. **A 运动补偿**:`Shift+→` propagate 时,若目标 scene 两帧都有 ego pose,则新框 PSR 由「世界系位置不变 + 目标帧 ego 系」反算(静止物在下一帧 BEV 里仍套住目标,无需手动追平)。无 ego pose 的 scene 自动退化为 v0.14.1 原样复制(零回归)。
2. **B 插值**:选中同 `group_id` 链上帧 i 与帧 k 的两个框,触发「插值填充」→ 中间帧 (i,k) 各生成一个插值框(世界系线性内插中心 + slerp 朝向 + 线性插值尺寸,再投回各帧 ego 系),共享同 `group_id`。生成的框 source 标记可区分(便于审核/批量删)。
3. **C 批量**:一个动作把当前帧所有(或选中多个)box_3d 运动补偿 propagate 到下一帧,各自延续 `group_id` 链;返回新建数量。
4. **后端**:propagate 端点扩展支持「批量 + 运动补偿参数」;新增「区间插值」端点。几何变换有纯函数单测(给定两帧 pose + 框,断言世界位置守恒 / 插值中点正确)。
5. **前端**:`Shift+→` 默认走运动补偿(有 pose 时);新增「插值填充区间」与「批量延续」入口(快捷键/工具栏);邻帧 overlay 的参考框按 ego 对齐(静止物的历史框叠加后重合)。
6. `uv run pytest -q` / `pnpm lint` / `pnpm test` 全绿;真实 nuScenes scene-0061(本机,需先 v0.15.0 回填 pose)端到端:贯穿全 scene 的车,标首尾两帧 + 插值,中间帧框肉眼贴合。

## 3. 各模块设计要点

### 3.1 几何核心(`ego_transform.py`,纯函数 + 重点单测)

所有变换在「世界系(ego→global)」里做,框在各帧的 PSR 是「该帧 ego 系」:

- `box_ego_to_world(psr, pose)`:`pose`=该帧 ego→global;返回世界系框中心/朝向。
- `box_world_to_ego(world_box, pose)`:逆变换,回某帧 ego 系。
- **运动补偿 propagate**:`world = ego_to_world(psr_i, pose_i)` → `psr_j = world_to_ego(world, pose_j)`。静止物 world 不变 → psr_j 自动「追平」ego 运动。
- **区间插值**:对帧 i、k 的两框各 `ego_to_world` → 世界系内线性插值中心、**slerp** 插值朝向、线性插值尺寸,按 `t=(m-i)/(k-i)` 取中间帧 m → `world_to_ego(·, pose_m)`。
- **无 pose 降级**:任一帧缺 pose → world 变换退化为恒等(等价 v0.14.1 原样复制),且响应标记 `motion_compensated=false`,前端可提示「该 scene 无 ego 轨迹,跨帧未做运动补偿」。
- **坐标系**:延续 v0.13.11 契约——DB 内 PSR 永远 ISO 字节;`convention_at_create` 取目标 dataset 约定。ego 变换在 ISO 世界系做,与 `axis_convention` 正交(若 v0.14.3 已让 nuScenes 落 ego/ISO 系,则世界系即点云系,最自洽)。

### 3.2 端点扩展(`annotation.py` + `tasks.py`)

- **运动补偿**:现有 `propagate` 内部,若源/目标帧均有 pose,走 `ego_transform` 算目标 PSR(替代原样复制);否则原样。复用现有 `cross_frame_group_seq` group 分配。
- **批量**:`POST /tasks/{id}/annotations/propagate-batch` body `{ target_task_id, annotation_ids[]|"all_box_3d" }` → 循环单条 propagate 复用同一目标帧 pose;返回 `[{src_id, new_annotation}]`。原子性:整批一个事务。
- **插值**:`POST /tasks/{id}/annotations/interpolate-range` body `{ group_id, from_task_id, to_task_id }` → 服务端查该 group 在两端帧的框 + 区间内各帧 task(走 neighbors/scene 反查)+ 各帧 pose → 生成中间帧框。生成框 `source="interpolated"`(区别于 `manual`),便于审核与批量撤销。
- 几何类型仍限 `PROPAGATABLE_GEOMETRY_TYPES`(v0.14.1);`point_mask_3d` 仍拒。

### 3.3 前端编排

- `Shift+→`:默认走「运动补偿 propagate」(后端有 pose 即补偿);`motion_compensated=false` 时 toast 一次轻提示。
- **批量延续**:新键位(如 `Shift+Ctrl+→`)→ `propagate-batch all_box_3d`;toast 报「N 个目标已延续到下一帧」。
- **插值填充**:`CrossFrameInterpolateBar`——选中某 group 链、给定首尾帧,点「插值填充中间 K 帧」→ `interpolate-range`;完成后跳首帧预览,中间帧框可逐帧微调。
- **overlay ego 对齐**:`useNeighborAnnotations` 取到的邻帧框,经 `egoAlign.ts` 用 `trajectory` 把历史/未来框变换到**当前帧 ego 系**再叠加 → 静止物的邻帧参考框与当前帧重合(而非沿 ego 运动方向拖一串影子)。`PointCloudScene.setReferenceBoxes` 接对齐后位姿。

### 3.4 source 标记与审核

- 插值生成的框 `source="interpolated"`、运动补偿 propagate 的 `source="manual"`(用户主动延续,视为人工)。
- 审核侧可按 source 过滤批量删插值框(避免「插值错了逐个删」);本版不新建审核 UI,只保证 source 可区分(为后续审核增强留口)。

### 3.5 Stretch(可选,不阻塞主线)

- **Kalman**:对 ≥3 关键帧用恒速 Kalman 平滑/预测,处理转弯加减速;默认关,开关在设置。
- **跨相机 timestamp 补偿**:投影时,用 `trajectory` 把 ego pose 插值到**各相机的 timestamp**(而非统一用 LIDAR_TOP 时刻),消除 v0.14.2 记录的 ~50ms 偏差。需 v0.15.0 frame timestamp + 逐相机 timestamp(后者本版若做需补一列/旁路)。

## 5. 已知风险 / 未尽事项

- **插值只对「同 group 链两端都有框」有效**:目标必须先手标首尾两帧并共享 group_id(`Shift+→` 一次即建链)。文档需讲清工作流。
- **恒速假设的误差**:急转弯/加减速时线性插值会偏,留 Kalman(stretch)或人工微调中间帧兜底。
- **无 ego pose 的 scene(SUSTech demo)**:全自动降级为 v0.14.1 行为,运动补偿/插值不可用——这是数据缺位,不是 bug;UI 提示而非报错。
- **`point_mask_3d` 跨帧明确不做**(见 §1.3)。
- **batch propagate 的目标帧锁/可见性**:复用 v0.14.1 的 `_assert_task_editable`;批量里有不可编辑目标 → 整批拒或跳过(设计时定,倾向「整批前置校验,有不可编辑则 422 列出」)。

## 6. 验证策略

- **几何单测**(最重)：`test_ego_transform.py` —— 给两帧 pose(造一段平移+小转向),断言静止世界点经 propagate 后 world 坐标守恒;插值中点 t=0.5 的世界中心 = 两端中点;slerp 朝向单位四元数;缺 pose 时恒等降级。
- **端点测**:批量返回数量、插值生成中间帧数 = k-i-1、source 标记正确、`point_mask_3d` 仍 422。
- **真实数据**:v0.15.0 回填 pose 后,scene-0061 取一辆贯穿全程的车:帧 0 与帧 38 各标一框(共享 group)→ interpolate-range → 抽查帧 19 的插值框肉眼套住该车;`Shift+→` 单帧延续对静止路边物自动对齐。
- **回归红线**:无 pose 的 scene(SUSTech)`Shift+→` 行为与 v0.14.1 byte 级一致(`test_annotation_propagate.py` 既有用例守);`point_mask_3d` 仍被拒。
