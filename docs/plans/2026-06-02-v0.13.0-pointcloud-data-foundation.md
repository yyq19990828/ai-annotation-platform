# v0.13.0 · 点云联合标注后端数据地基

> Epic:[点云 + 图像联合标注工作台](./2026-06-02-v0.13.x-point-cloud-workbench-epic.md) 第一切片。
> 主题:落地**多文件关联** + **3D 几何类型**,纯后端,无前端可见变化。
> 风险中(新中间表 + 迁移),但全部为**新增**,不动现有 2D 流程。

## 背景

支持点云+图像联合标注的六个缺口里,本切片解掉**后端可独立完成、且是后续一切前提**的四个:G1(任务-数据项 1:N)、G3(3D 几何)、G4(file_type / 工具单位)、G6(跨模态 ID 约定)。标定(G2)与前端 3D(G5)分别留给 v0.13.1 / v0.13.2+。

调研对应:research §14.8.3 第 1 / 3 / 4 层。

## 范围(做什么)

### 0.13.0-1 多文件关联 · G1(`apps/api`,有迁移)
- 新模型 `TaskDatasetItemLink`(`task_id` → tasks.id、`dataset_item_id` → dataset_items.id、`role: str`、`sensor_name: str | None`)+ alembic 迁移。
- `role` 约定值:`primary_lidar` / `camera_<name>`(如 `camera_front`);先用字符串 + service 层校验,不急于上 enum。
- **共存策略**:2D 单文件 task 继续用 `task.dataset_item_id`(1:1);3D 多文件 task 用 link 表。两条路径在 service 层按 `project.data_type` 分流,互不影响。
- service 层提供 `link_items(task, [(dataset_item_id, role, sensor_name)])` 与按 task 取回关联项的查询。

### 0.13.0-2 3D 几何类型 · G3(`_jsonb_types.py`,无迁移)
- Geometry discriminated union 新增 `Box3DGeometry`(`center[3]` / `size[3]` / `rotation[3]`,`extra="allow"`)与 `PointMaskGeometry`(`point_indices: list[int]`)。
- 前端 `apps/web/src/types/index.ts` 的 `Geometry` union 同步加 TS 成员(由 OpenAPI codegen 产出,勿手写漂移)。

### 0.13.0-3 工具单位 + file_type · G4
- `ToolUnitId` 的 `lidar_box_3d` 从「留位」转为后端可用;新增 `point_mask_3d`(对应 `TOOL_UNIT_IDS` 同步)。
- `Task.file_type` 校验放开点云扩展名:`.pcd` / `.bin` / `.las` / `.ply`。
- `ProjectTypeKey` 已含 `"lidar"`,本切片不新增类型键(留给 epic 后续按需加 `lidar-det` 等)。

### 0.13.0-4 跨模态 ID 约定 · G6
- **不改模型** —— 复用 `Annotation.group_id`。仅在 `docs-site/dev/reference/` 写明约定:同一物体的 3D 框与各相机 2D 框共享同一 `group_id`。

## 不做(明确排除)
- 不做标定 schema 与导入管线(v0.13.1)。
- 不做任何前端 3D 渲染 / 投影(v0.13.2+)。
- 不做 `point_mask_3d` 的前端工具(仅后端 schema 就位)。
- 不动现有 2D task 的 1:1 关联路径。

## 风险
- **中间表与 1:1 共存**:导出 / 查询 / 调度若假设「task 必有单一 dataset_item」,需排查并兼容多 item;本切片只建表 + service 接口,消费方改造随 v0.13.1 导入落地时验证。
- **迁移影响面**:仅新增一张表,不改 `tasks` / `dataset_items` 结构,对存量大表无锁风险。

## 验证(成功标准)
- `uv run pytest`:新增 `TaskDatasetItemLink` 模型 / service 测试;`Box3DGeometry` / `PointMaskGeometry` 的序列化 ↔ 反序列化 round-trip。
- `alembic upgrade head` 后 `downgrade -1` 往返干净。
- Geometry union 判别:给定 `{"type":"box_3d",...}` 能正确解析到 `Box3DGeometry`,且旧 2D 类型不受影响。
- OpenAPI snapshot 经 pre-commit 钩子重新生成(`Box3DGeometry` 等出现在 schema),前端 codegen 同步。
- `uvx ruff check` / `pnpm lint`。
