## 背景

后端项目维度的可观测数据远比 SDK 暴露的丰富。你点名的两块——**批次**与**项目成员**——后端早有只读端点，但 SDK 完全没有，TUI 项目详情屏（[app.py:422](../../packages/python-sdk/src/ai_annotation/tui/app.py:422) `ProjectDetailScreen`）当前只有「概览 / 任务 / Backends」三个子 tab，看不到批次进度和成员构成。

本版按 SDK/TUI 既定节奏：**TUI 要用而 Client 没有的能力，先补进 `client.py`（顺带进 CLI），TUI 再消费**，不让 TUI 直接拼 HTTP。

顺带补 `client.me()`——返回当前 principal 的 role/scopes，**为本版及后续的「角色感知 UI」打底**（很多观测端点限 admin/reviewer，需要先知道自己是谁才能决定显示哪些视图、避免点进去吃 403）。

## 红线（沿用 SDK/TUI 既有三条）

1. **TUI 只消费 `Client` 公开 API**，不碰 `_http`。
2. TUI 限定在 `[tui]` extra，可整体删除。
3. **只读为主**：批次/成员本版只做查询展示，不做增删改（成员 CRUD 留在 web）。

## 数据可行性（待落地前核对 OpenAPI）

| 端点 | 用途 | 关键字段（待核对） | 分页 |
|---|---|---|---|
| `GET /projects/{id}/batches?status=` | 批次列表 | `id` `display_id` `name` `status` `total_tasks` `completed_tasks` `review_tasks` `rejected_tasks` `approved_tasks` `progress_pct` `annotator` `reviewer` | 否 |
| `GET /projects/{id}/batches/{batch_id}` | 批次详情 | 同上 | 否 |
| `GET /projects/{id}/members` | 成员列表 | `id` `user_id` `user_name` `user_email` `role` `assigned_at` | 否 |
| `GET /me`（或 `/auth/me` / `/users/me`）| 当前用户 | `id` `name` `email` `role` `scopes?` | 否 |

> **核对点**：
> 1. `me` 端点的确切路径（SDK 已用 `/me/api-keys` 前缀，但当前用户本体端点需确认是 `/me` / `/auth/me` / `/users/me`）。
> 2. 成员列表的角色门控——若 annotator 角色 key 不可读，SDK 抛清晰 `PermissionError`，TUI 降级（见 C 档）。
> 3. 字段名以源码为准；模型用 `extra="allow"` 容忍差异。

## 范围 A · SDK 模型 + 命名空间

**`models.py` 新增**（只声明稳定字段，`extra="allow"` 前向兼容）：

- `Batch`：`id` / `display_id` / `name` / `status` / `total_tasks` / `completed_tasks` / `review_tasks` / `rejected_tasks` / `approved_tasks` / `progress_pct`，`annotator` / `reviewer` 用宽松类型（dict | str | None，待核对结构）。
- `Member`：`id` / `user_id` / `user_name` / `user_email` / `role` / `assigned_at`。
- `Me`（principal）：`id` / `name` / `email` / `role` / `scopes`（list，缺省空）。

**`client.py` 新增命名空间**：

- `class Batches`：`list(project_id, status=None) -> list[Batch]`、`get(project_id, batch_id) -> Batch`。
- `class Members`：`list(project_id) -> list[Member]`。
- `Client.me() -> Me`（直接挂在 Client 上，或 `client.me` 资源；倾向方法 `client.me()`，调用直观）。
- 在 `Client.__init__` 注册 `self.batches` / `self.members`。
- `__init__.py` 导出新模型（与现有 `Project` / `Job` 等并列）。

**错误语义**：`_http.request` 已把非 2xx 转 `AAPError`；本版确保 403 携带可读信息（必要时在 `errors.py` 细分 `PermissionError(AAPError)`，供 TUI 区分「无权限」与「网络错误」）。

## 范围 B · CLI

- `aap batches list <project_id> [--status ...] [--json]`：表格列 名称/状态/进度(完成/总)/审核/退回/标注员/审核员。
- `aap members list <project_id> [--json]`：表格列 用户/邮箱/角色/加入时间。
- `aap me [--json]`：打印当前 role/scopes（自检凭据用，CI 友好）。
- 注册进 `cli/main.py`：`batches`/`members` 归 `PANEL_RESOURCE`，`me` 归 `PANEL_CONFIG`。

## 范围 C · TUI 项目详情子 tab + 角色感知

`ProjectDetailScreen`（[app.py:422](../../packages/python-sdk/src/ai_annotation/tui/app.py:422)）现有 `TabbedContent`（概览/任务/Backends），加两个 `TabPane`：

- **「📦 批次」**：`DataTable`，列 `name / status / progress / 标注员 / 审核员 / 退回`；`status` 着色复用 `_STATUS_STYLE` 范式，`progress` 用 `_progress_cell(progress_pct)`。`_load_worker` 内增 `client.batches.list(project_id)`（与现有 jobs/backends 同一 worker 串行聚合，避免新增 worker）。
- **「👥 成员」**：`DataTable`，列 `用户 / 邮箱 / 角色 / 加入时间`。
- **下钻（可选）**：批次行回车 → `DetailScreen` 展示批次字段（复用 `_format_fields`）；不引入批次审计日志（留后续）。
- **角色感知降级**：`AapTuiApp.on_mount` 启动时 `client.me()` 缓存 `self._role`；成员/批次端点若 403 → 子 tab 显示「（当前角色无权查看）」而非崩。`me()` 失败（老后端无端点）→ 整体降级为「不预判角色，端点 403 时局部提示」，不阻塞主流程（红线：可降级）。

## 不在本版范围

- 成员增删改（add/remove member）→ 写操作，留 web。
- 批次审计日志（`/projects/{id}/batches/{batch_id}/audit-logs`）→ 留待审计专版。
- 全局跨项目批次总览 → 避免重蹈 ml-backends 的 N+1，本版只在单项目详情屏内。

## 风险与取舍

- **角色门控不确定**：成员/批次端点对各角色的开放度需核对后端。策略是「先 `me()` 探角色 + 端点级 403 兜底」双保险，最坏情况只是局部提示，不阻塞。
- **`annotator`/`reviewer` 字段结构未知**：批次行的标注员/审核员可能是嵌套对象或字符串，模型用宽松类型 + 渲染时 `getattr`/`.get` 兜底，避免硬假设。
- **N+1**：批次/成员是 project-scoped，严格放在「单项目详情屏」内、并入现有 `_load_worker` 串行，不做全局聚合。
- **`me()` 增加一次启动请求**：缓存一次、不轮询；失败不阻塞主流程。
