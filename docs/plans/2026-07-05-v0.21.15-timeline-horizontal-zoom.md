# v0.21.15 · 时间轴横向缩放（zoom）+ 可见帧窗口坐标统一

状态：**计划（2026-07-05）**。补齐视频工作台**「时间轴恒等宽铺满、长视频无法精细定位/圈选」**的缺口——引入
可见帧窗口 `[visibleFrom, visibleTo]` + 缩放/平移手势，并把散落的帧↔像素换算收敛到单一 util，让 v0.21.13 的
区间刷选、v0.21.14 的传播范围在放大态下仍正确落点。**纯前端**（视频时间轴层），不改后端 / schema / 落库，无 alembic。

承接视频 UX 三连（v0.21.12/13/14）的延后项。**基建性**：zoom 与 v0.21.13 的区间选择基建**强共享**
`frameFromPointer` / `rangeStyle` 两个函数，二者必须同一坐标基准；本计划把窗口坐标换算抽成单一 util 供两者共用，
故排在 v0.21.13/14 之后收口。

## 动机（现状：恒等宽全域映射，无任何 zoom/viewport，带证据）

调研结论先行：**时间轴当前恒等宽全域铺满，无任何横向 zoom/pan/viewport 状态；所有按帧定位都直接以 `maxFrame`
为分母做 `frame/maxFrame`（点位/区间类）或 `bin.index/binCount`（密度类）线性映射。** 全部证据在
`apps/web/src/pages/Workbench/stage/VideoPlaybackOverlay.tsx`。

### 缺口 1 · 长视频无精细定位/圈选
时间轴容器宽度固定（`VideoPlaybackOverlay.module.css:15` `width: min(820px, calc(100% - 28px))`），`maxFrame`
直接对应 100% 宽度。335 帧视频每帧约 2.4px、上千帧视频每帧不足 1px——seek、刷选区间、章节边界、传播范围全靠
在极窄像素带里点，长视频精细操作几乎不可能。v0.21.13「不在范围」已点名此项（`时间轴横向缩放（zoom）` 另议）。

### 缺口 2 · 两套映射基准并存，靠「都铺满全宽」偶然对齐
- **点位/区间类**：`frameLeft(frame) = frame/maxFrame*100`（`VideoPlaybackOverlay.tsx:216`）、`rangeStyle(from,to)`
  （`:232-239`）、`frameFromPointer`（`:217-221`，指针→帧唯一反解，`round(ratio*maxFrame)`）。
- **密度条类**：人工密度 `bin.index/binCount`（`:524-525`）、AI 预测密度 `bin.index/binCount`（`:546-547`），
  bin 帧区间由 `videoTrackTimeline.ts:125-126`/`:160-161` 算，但渲染按 **bin 序号等宽切片**（`:519-521` 注释：
  为与网格坐标系对齐而刻意等宽）。
两套坐标当前恰好铺满同一容器宽度、视觉对齐；**引入 zoom 后必须各自独立换算，否则密度条与关键帧点/网格错位**
（`:519-521` 注释正是历史上为消除类似错位而把密度改等宽的证据——zoom 会重新引入该风险）。

### 缺口 3 · 区间刷选/传播范围与 zoom 强耦合，必须同坐标基准
v0.21.13 区间刷选、v0.21.14 传播范围都复用 `frameFromPointer`（反解）+ `rangeStyle`（渲染）。**一旦 zoom 生效
但这两函数未同步改，刷选反解会把指针错映射到全域帧，而渲染带若已改成窗口坐标——草稿带画在错误位置、与指针脱节。**
二者必须原子化同时改到同一窗口基准。

### 缺口 4 · 章节条自算坐标 + range input 全域语义，是 zoom 的两处「漏网」
- 章节条 `leftPct/widthPct`（`:459-461`）**未走 `rangeStyle`**、自算，且分母不一致（left 用 `maxFrame`，width 用
  `maxFrame+1`）——zoom 改造若只改三个核心函数，章节条不跟随。
- 原生 `<input type=range max={maxFrame}>`（`:408`）覆盖全域，与可视窗口冲突（其可视 thumb 已 `width:0` 隐藏，
  CSS `:115-124`）。

## 定稿决策（拟）

- **核心 → 引入可见帧窗口 `[visibleFrom, visibleTo]` + 单一坐标 util。** 新增视口窗口状态；把帧↔百分比换算抽成
  单一 util（如 `frameToPct(frame, win)` / `pctToFrame(pct, win)`，`win = {from,to}`），`frameLeft` / `rangeStyle` /
  `frameFromPointer` 全部改为调它。**v0.21.13 区间基建与本 util 共用**，从根上保证刷选/seek/渲染同基准。
- **缩放手势 → Ctrl/⌘ + 滚轮缩放（以指针帧为锚），拖拽平移。** 与既有手势矩阵错开：普通拖=seek、Shift+拖=区间
  刷选（loop/chapter/propagate）、Ctrl+滚轮=zoom、空格/中键或滚动条=pan。缩放以指针所在帧为不动点（体感自然）。
  全窗口（`from=0,to=maxFrame`）时行为**零回归**（等价当前恒等宽）。
- **密度条改窗口映射 + 窗口外裁剪。** 两条密度轨从 `bin.index/binCount` 改为用 bin 帧区间
  （`videoTrackTimeline.ts:125-126`/`:160-161`）经 util 映射 + 窗口外 bin 裁剪/隐藏，与点位类回到同一基准。
- **章节条改复用 `rangeStyle`。** 顺带修 left/width 分母不一致的既有偏差。
- **窗口重置 + 双击复位。** 双击时间轴空白/专用「适配全部」按钮把窗口复位到 `[0, maxFrame]`；窗口状态是否持久化
  （类比 `parseStoredLoopRegion`，`videoNavigationState.ts:98`）默认**不持久**（换任务/刷新回全窗口），避免跨视频
  帧数不同导致窗口越界。

## 实现分阶段

- **WS1 · 坐标 util 抽取（零行为变更）**：把 `frameLeft`/`rangeStyle`/`frameFromPointer` 内联公式抽成
  `timelineCoords.ts` 的 `frameToPct/pctToFrame`，先以固定 `win={0,maxFrame}` 注入——**此步不引入 zoom，纯重构**，
  跑通现有测试（`VideoPlaybackOverlay.test.tsx` / `videoKonvaCoordinates.test.ts`）确认零回归。若 v0.21.13 已落地，
  其区间基建一并切到此 util。
- **WS2 · 视口窗口状态 + 缩放/平移手势**：新增 `[visibleFrom, visibleTo]` 状态；Ctrl+滚轮缩放（指针帧为锚）、
  拖拽/滚动条平移；双击/按钮复位。全窗口时零回归。
- **WS3 · 全图层跟随窗口**：章节条改走 `rangeStyle`；两条密度轨改窗口映射 + 窗口外裁剪；采样网格抽稀
  （`gridTicks` `:203-214`，`>200` 抽稀）按可见窗口重算；hover/tooltip clamp 到窗口；窗口外书签/issue/关键帧的
  裁剪或边缘聚簇策略。原生 range：弃用可视 thumb（已隐藏）改自绘播放头，或让 range 映射到窗口区间。
- **WS4 · 验证 + 版本**：E2E ① 全窗口态所有图层与当前像素级一致（零回归）；② Ctrl+滚轮放大后 seek/刷选落点准、
  密度条不与关键帧点错位；③ 放大态区间刷选（loop/chapter/propagate）草稿带与指针一致；④ 平移后窗口外元素正确
  裁剪；⑤ 双击复位回全窗口。补 `timelineCoords` 单测（窗口映射/反解/边界）。CHANGELOG（Added）+ 版本 bump。

## 不在范围

- **时间轴纵向缩放 / 多轨道展开**：本计划只做横向帧轴缩放。
- **改帧步进语义**：键盘 ←/→ 仍按全域帧步进（`:264-268`），zoom 只改视觉不改步进；「按可视像素步进」另议。
- **窗口状态跨设备持久化**：默认不持久（换视频帧数不同易越界）；如需按任务记忆窗口另立。
- **v0.21.13 区间基建 / v0.21.14 传播本体**：本计划只提供并共用坐标 util，不实现区间/传播用法。

## 风险

- **双坐标基准放大错位**：点位类 `frame/maxFrame` 与密度类 `bin.index/binCount` 当前靠「都铺满全宽」偶然对齐，
  zoom 后必须统一到窗口映射，否则密度条与关键帧点/网格错位（`:519-521` 注释是历史踩坑证据）。WS1 先统一 util 是
  防线。
- **`frameFromPointer` 与 `rangeStyle` 必须原子化同改**：二者被 seek（`:344/:359/:418`）、hover、loop 刷选、
  v0.21.13 区间基建（`:450/:571/:579` 渲染）共享；只改一半 → 指针落点与视觉草稿脱节。
- **手势矩阵拥挤**：`timelineShell` 已对 pointerId 做 capture（`:349/:355`）用于 seek/loop 拖拽；新增 pan 会争用
  同一指针流。zoom=Ctrl+滚轮、pan=拖拽/滚动条，与普通拖 seek、Shift+拖刷选明确分区，避免误触。
- **章节条既有分母偏差**（`:460` 用 `maxFrame+1`、`:461` 用 `maxFrame`）：改造照搬会把偏差带进窗口坐标、放大后
  更明显；WS3 顺带统一。
- **测试基线波及**：`VideoPlaybackOverlay.test.tsx`、`videoKonvaCoordinates.test.ts` 大量断言基于「全域等宽=百分比」
  假设；WS1 保持 `win={0,maxFrame}` 零回归是关键，坐标改造分步落以隔离回归。
- **放大无性能收益**：长视频放大若不做窗口裁剪，书签/issue/关键帧/密度 bin 仍全量渲染（`:485-593`），DOM 数不随
  zoom 下降；WS3 的窗口外裁剪同时是性能项。
