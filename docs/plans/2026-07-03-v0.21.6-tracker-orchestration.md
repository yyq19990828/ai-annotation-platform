## 设计对齐（v0.21.5 落差 → 母计划终态）

v0.21.5 把输入节点实现成「第一个模型阶段」（绑源模型 + 源元数据），是**中间态**；本版按用户决策
（2026-07-03）落**母计划终态**：**输入节点退成纯数据源（图像 + 视频统一），源/tracker 模型都作其子
stage**。tracker 因此作为「video 输入节点下游的首模型 stage」（原 WS1），后端单阶段派发已就绪。

**终态图模型：**
```
[输入节点]  parentSid=null, source:{kind,data_type,execution_unit}, 无模型, depth=0
  └── [首模型 stage]  parentSid=输入节点, 整图检测/tracker, depth=1  → 后端 stage 0(parent_stage=null)
        └── [下游 stage]  crop 分类/子检测, depth=2/3
```
- **深度**：输入节点=0（不计模型层），模型 stage 1..3（`MAX_DEPTH=3` 仍指模型层，保 3 层不缩水）。
- **Inspector 按父分型**：输入节点→数据源检查器（data_type 只读 + execution_unit）；父=输入节点的
  stage→整图源式配置（`PreannotateConfigForm`/`cfg`，含 backend/model/variants/prompt/类别白名单/阈值）；
  父=模型 stage 的下游→`StageCard`（crop 式）。
- **序列化**：输入节点**不作后端 stage**（纯 UI 数据源）；首模型 stage=后端 stage 0（`parent_stage=null`），
  下游=stage 1+；`source:{}` 元数据挂到后端 stage 0（供后续 execution_unit 派发，本版透传）。
- **本版单首模型 stage**：`cfg` 仍单实例，绑唯一首模型 stage；母计划的 frame/video 双分支（多首模型
  stage）留 v0.21.7。

  输入节点恒 true 不变（可挂模型子）；`canAddChild(输入节点)` 允许多子（分支）。
- `usePipelineComposer.ts`：输入节点 payload 恒 null（纯数据源，不进后端 stage）；`allDownstreamReady` /

- `ProjectDetailPanel.tsx` / `GlobalPipelineLibraryPage.tsx`：
  - 初始 graph 除输入节点外，**自动补一个首模型 stage**（父=输入节点），承接原 v0.21.5 输入节点的源模型

### WS3 · 后端：tracker 软超时护栏

- 后端 yolo tracker **已有 900 帧上限**（`predictor.py:424` `YOLO_TRACKER_MAX_FRAMES`），单任务时长有界。
- 补 celery 软超时兜底：含 tracker stage 的派发在 `batch_predict.apply_async`（`projects.py:1766`）传
  `soft_time_limit`（新增可配 `settings.tracker_soft_time_limit`，默认如 1800s），防单任务占死 worker。
  不改全局 conf、不新增队列（帧上限已限时长，队列隔离范围偏大留后续）。

## 风险

- **长任务超时**：当前全局无 `time_limit`，tracker 整段视频可能跑很久；护栏（WS3）是硬项，
  否则 worker 被单任务占死。
- **队列争用**：tracker 与普通预标共 `ml` 队列，需独立队列或限并发（WS3）。
- **依赖 v0.21.5**：无输入节点 data_type=video 地基则 tracker stage 无处挂。

## 验收

- 视频项目经编排画布配 tracker stage → 派发 → 落一批 `VideoTrackGeometry` 预标注。
- 工作台渲染审核轨迹（渲染复用 v0.21.1 现成）；track_id 为 `trk_<uuid>` + 语义标签。
- 长视频 tracker 有超时护栏，不饿死普通预标队列。
- 端到端跑通真实 yolo tracker backend。

## 不在范围

- 逐帧单帧检测批量（v0.21.7）。
- 交互式 SAM2/SAM3 video tracker（两条链并存，不动）。
- track 下游逐帧 crop 分类（frame × track 二维，后续）。
