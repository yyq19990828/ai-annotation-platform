# v0.21.6 · 视频序列分支（detect-then-track）接入编排派发

状态：**定案（accepted，2026-07-03）**。母计划 [`2026-07-03-video-project-orchestration.md`](2026-07-03-video-project-orchestration.md)
Phase 3 的独立落地。**backend + 落库已就绪（v0.21.1 验证过），仅缺编排派发接线 + 队列/超时护栏。**
依赖 v0.21.5（输入节点 data_type=video 地基）。track_id 相关已随 v0.21.2 完成，本版无迁移负担。

## 背景与动机

v0.21.1 已做完 detect-then-track 全链路（backend `type=tracker` + `_remap_track_ids` +
`to_internal_shape`→`VideoTrackGeometry`），**唯一缺 UI 入口**：视频项目进不了编排器派发 tracker。
v0.21.5 已让 video 项目进编排（输入节点 data_type=video / execution_unit=video），本版在其下游接
tracker stage 并打通派发。

**已就绪、无需改的闭环**（探查核实）：
- `_build_predict_context`（`workers/tasks.py:56`）v2 分支：`task_type="tracker"` + `model_variants is not None`
  自动产 wire `{"type":"tracker", ...}`——**无需改**。
- `create_from_ml_result`（`prediction.py:364`）→ `_remap_track_ids`（`:333`）→ 读路径
  `to_internal_shape`→`VideoTrackGeometry`（`:130/455`）——**无需改**。

## 工作项

### WS1 · 前端：编排画布加 tracker stage（video 输入下游）

- 在输入节点（`data_type=video` / `execution_unit=video`）下游允许添加 `task_type=tracker` 的 stage。
  复用 v0.21.5 的统一画布 + 受控词表：tracker backend（yolo `/setup` 的 `track` 模型，
  `task=tracker`、仅接受 video 输入、自报 `bytetrack`/`botsort`）作为该分支唯一可选。
- Inspector 暴露 tracker 参数：`conf` / `iou` / 追踪算法（bytetrack/botsort）/ 类别白名单
  （复用 v0.21.1 backend 已支持的入参）。

### WS2 · 后端：派发侧接受 tracker stage

- `projects.py` preannotate stage 归一化（`:1691`）+ `batch_predict.apply_async`（`:1762`）确认能接
  `task_type="tracker"` 的 stage 并正确透传 `model_variants` / `params`（conf/iou/algo/classes）。
  探查表明投递侧「几乎不改」——核实 stage payload 到 `_build_predict_context` 的透传链无断点。

### WS3 · 后端：tracker 专属队列 + 超时护栏（风险项）

- **现状缺口**：detect-then-track 走 preannotate → 落 `ml`（GPU）队列，与普通检测预标**共用队列、
  无独立限并发、无 `time_limit`**（全局未设 `task_time_limit`/`soft_time_limit`）。
- 加 tracker 专属超时（tracker 逐帧关联整段视频，远长于单图 predict）：给 tracker 分支设
  `soft_time_limit`（`celery_app.py` conf 或 `apply_async(soft_time_limit=...)`）。
- 独立 queue / 限并发：评估把 tracker 派发路由到独立队列（参考交互式
  `run_video_tracker_job` 已用的 `gpu` 队列），或 per-backend `max_concurrency` 收紧
  （`services/ml_client.py:17`）。**避免一条长视频 tracker 饿死普通预标批。**

## 风险

- **长任务超时**：当前全局无 `time_limit`，tracker 整段视频可能跑很久；护栏（WS3）是硬项，
  否则 worker 被单任务占死。
- **队列争用**：tracker 与普通预标共 `ml` 队列，需独立队列或限并发（WS3）。
- **依赖 v0.21.5**：无输入节点 data_type=video 地基则 tracker stage 无处挂。

## 验收

- 视频项目经编排画布配 tracker stage → 派发 → 落一批 `VideoTrackGeometry` 预标注。
- 工作台渲染审核轨迹（渲染复用 v0.21.1 现成）；track_id 为 `trk_<uuid>` + 语义标签。
- 长视频 tracker 有超时护栏，不饿死普通预标队列。
- 端到端跑通真实 yolo tracker backend。

## 不在范围

- 逐帧单帧检测批量（v0.21.7）。
- 交互式 SAM2/SAM3 video tracker（两条链并存，不动）。
- track 下游逐帧 crop 分类（frame × track 二维，后续）。
