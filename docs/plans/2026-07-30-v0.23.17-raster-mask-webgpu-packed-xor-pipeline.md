# v0.23.17 · Raster Mask WebGPU packed 输入与 XOR 回读优化

> Status: Released · default-off candidate · 2026-07-30
>
> 父计划：[v0.23.16 Raster Mask 持久计算会话与 WebGPU 有界试运行](2026-07-29-v0.23.16-raster-mask-persistent-compute-webgpu.md)
>
> 证据输入：[WebGPU 在视频工作台中的适用性调研](../research/21-webgpu-video-workbench.md)
>
> 固定基线：`096108b6`（v0.23.16 封版提交）

## 1. 本版结论

v0.23.17 继续优化 Raster Mask 客户端 WebGPU morphology，但不扩大产品面。本版只处理
v0.23.16 已通过 production provider A/B 的 `square dilate`，目标是消除成功 GPU 请求中仍然存在的
整 ROI dense alpha、逐像素 bit-pack 和逐像素 before / after diff。

冻结决策如下：

1. **先优化数据路径，不先增加 kernel。** 不新增 erode、open、close、disk morphology 或视频合成。
2. **Worker 直接构造 row-aligned packed source。** GPU-ready 请求不再先生成 `width × height`
   `Uint8Array`，也不再由 provider 对 alpha 做第二次逐像素 pack。
3. **shader 直接输出 core XOR plane。** 不回读完整 after plane；Worker 按 non-zero XOR words 构造现有
   `MaskHistoryPatch[]`、changed pixels 与 bounds。
4. **CPU 正确性路径不变。** gate 关闭、provider 未 ready、预算不足、不支持操作、device lost 和 runtime
   error 都继续使用 production `applyMaskMorphology()`；GPU 中途失败时才惰性 materialize alpha。
5. **不建立第二份可写 session 真值。** Worker 不长期维护与主线程同步的 GPU mask 或 packed current
   shadow；immutable base RLE + 请求携带的 dirty overrides 仍是计算输入合同。
6. **不靠可选 WebGPU 扩展维持正确性。** `timestamp-query` 只可用于 benchmark 诊断；subgroups、
   `linear_indexing` 等扩展不进入必需路径。
7. **默认 gate 继续关闭。** Linux RTX 3090 强制 Vulkan 的结果可证明工程收益，不能替代 macOS、
   Wayland、Windows 无 flag 资格矩阵，也不能据此默认开启。
8. **新路径未达退出门就撤回。** 保留 v0.23.16 provider 与新增分段测量，删除未带来稳定端到端收益的
   packed / XOR 实现，不留下平行 shader 或不可达死代码。

## 2. 目的与成功定义

### 2.1 本版目的

v0.23.16 已把 morphology 移到持久 Worker，并证明 WebGPU 计算可用；但 GPU 成功路径仍是：

```text
base RLE + dirty overrides
  → dense Uint8 alpha                 O(input pixels)
  → row-aligned Uint32 bit-pack       O(input pixels)
  → GPU dilate full input
  → readback full after words
  → source alpha vs after 逐像素 diff O(core pixels)
  → XOR tile patches
```

这里 GPU 真正计算只占链路的一部分。v0.23.17 要把它收敛为：

```text
base RLE + dirty overrides
  → row-aligned packed source
  → GPU dilate + source XOR（只写 core）
  → readback core XOR words
  → 扫描 non-zero words / set bits
  → XOR tile patches
```

### 2.2 完成条件

本版只有同时满足以下条件才算完成：

1. GPU-ready 成功请求不分配 input-sized alpha，不调用 `packRasterMaskRows()`，也不扫描每个 core
   pixel 做 diff。
2. packed source 对任意合法 input origin、非 32 对齐宽度、图片边缘 halo 和 dirty override 都与现有
   dense source 逐像素一致。
3. shader 只回写 core XOR，core 外没有 patch；最后一 word 的无效尾位恒为 0。
4. Worker 从 XOR words 产生的 patch、changed pixels、bounds、history、undo / redo 和保存结果与
   v0.23.16 CPU golden 完全一致。
5. GPU 请求任何阶段失败时，只 materialize 一次 alpha 后走 CPU；store 在成功响应前保持零部分写入。
6. 默认构建仍不加载 provider、不调用 `requestAdapter()`，不新增用户可见开关。
7. `2048²` 与 `3840×2160` 在同机、同浏览器、同输入、交替基线 / 候选的两轮正式样本中，候选端到端
   p95 相对 v0.23.16 WebGPU 至少改善 15%，且任一轮不得低于 10%。
8. gate-off CPU、adapter-unavailable CPU 和 GPU runtime fallback 不得比 v0.23.16 p95 恶化 5% 以上。
9. 主线程 Long Task 继续为 0；GPU owner 始终最多 1；重复运行的 JS / GPU 显式字节进入 plateau，
   dispose 后 session、Worker、buffer 与 owner 归零。
10. 若性能门失败，撤回本版 packed / XOR production 路径，仅保留不会制造双实现的分段诊断改进与
    失败结论。

## 4. 当前瓶颈与证据缺口

### 4.1 已由代码确认的重复工作

当前 `runMorphologyRoi()` 在判断 provider 是否 ready 前调用
`prepareRasterMaskMorphologyRoi()`，因此所有候选请求都会先得到 dense alpha。GPU provider 随后再次
逐像素 pack；GPU 回读后 `diffRasterMaskMorphologyRoi()` 又逐像素比较 source / after。

对于 4K input，这至少意味着：

- 一份约 7.91 MiB 的 dense alpha；
- 约 1.00 MiB 的 JS packed source；
- 约 1.00 MiB 的 JS readback result；
- 三段与 input / core pixels 线性相关的 JS 循环；
- GPU 侧 source / target / readback 三个 grow-only buffer。

### 4.2 现有指标不足以直接归因

protocol 已记录 `materializeMs`、`computeMs` 和 `diffMs`，但 production operation runner 目前主要持久化
total / Worker total，没有完整拆出：

- packed source 构造；
- `queue.writeBuffer()` 与 command encode / submit；
- GPU pass；
- copy + `mapAsync()` wait；
- mapped range clone；
- XOR words → tile patch；
- CPU fallback 的惰性 alpha materialize。

因此 M0 必须先补观测。不能只因 WGSL kernel 很快就认定所有尾延迟来自 pack，也不能用 GPU timestamp
替代用户可见 wall time。

## 6. 目标架构

### 6.1 成功 GPU 路径

```text
SparseMaskTileStore.morphologyRoi
  → core / input / operation / dirty packed overrides / revision
  → RasterMaskWorkerPool affinity slot 0
  → Worker provider preflight
      ├─ not ready / unsupported / over budget → existing CPU path
      └─ ready
          → base RLE + dirty overrides → packed input words
          → queue.writeBuffer(source)
          → square dilate shader
          → XOR with packed source in shader
          → write core-only XOR words
          → copy to dedicated MAP_READ buffer
          → non-zero words → tile XOR patches + summary
          → transfer patches to main thread
  → existing response validation
  → existing alpha/currentBits/history application
```

### 6.2 GPU 运行中失败

```text
packed source 已构造
  → upload / submit / map / device lost / runtime error
  → 丢弃全部 GPU output
  → 惰性 prepare dense alpha（仅一次）
  → production CPU morphology + existing dense diff
  → backend=cpu-fallback
```

失败路径不得把 packed source 反解成 alpha；它直接复用既有 base RLE + dirty overrides dense helper，减少
新的正确性表面。

## 7. packed source 合同

### 7.1 统一布局

GPU input 使用 row-aligned `Uint32Array`：

```ts
interface RasterMaskPackedPlane {
  words: Uint32Array;
  width: number;
  height: number;
  wordsPerRow: number; // ceil(width / 32)
}
```

规则：

- bit `x & 31` 对应 row 内 x；最低位是较小 x；
- row 从 `wordsPerRow` 的整数边界开始；
- input 的 `(0, 0)` 对应请求 `input.x / input.y`，不对应整图原点；
- 每行最后一 word 超过 width 的位必须为 0；
- 乘法、byteLength 与 offset 都必须先做 safe-integer / ROI limit 校验；
- helper 只接受已通过现有 session / rect / operation 校验的请求。

### 7.2 base RLE 直接写入 packed plane

新增 runtime helper，按 COCO RLE 的 column-major run index 遍历 input 相交区，并直接设置 row-aligned
word：

```ts
preparePackedRasterMaskMorphologyRoi(session, request): {
  sourceWords: Uint32Array;
  wordsPerRow: number;
  packedPrepareMs: number;
}
```

实现要求：

- 每个 source column 只做一次 `runIndexAt()`；
- 跳过 background run，不先写 alpha 再 pack；
- foreground span 只写相交 input rows；
- 不缓存完整 base mask；
- 不在 session 中保存另一份 current truth；
- repeated request 仍从 immutable RLE + 本次 overrides 精确重建，避免 revision 同步协议。

若 M0 / M4 证明 RLE → packed prepare 在优化后仍占候选 p95 的 25% 以上，packed base tile LRU 另立后续
计划；本版不提前增加无界 session cache。

### 7.3 dirty override 优先级

dirty override 继续由主线程 `currentBits` 产生，并覆盖 base RLE：

- 先沿用现有 duplicate、tile grid、revision、dimensions 和 byteLength 校验；
- 只处理与 input 相交的行和列；
- override 的连续 tile bitset 可用 word helper 读取，但不得假设边缘 tile width 为 32 的倍数；
- override 的 0 和 1 都必须覆盖 base，不能只 OR foreground；
- input / tile 任一侧不对齐时，首尾 word 使用 mask，不能污染相邻像素；
- 尾位必须在覆盖后再次清零。

## 8. provider 与 shader 合同

### 8.1 provider API

将当前 alpha API 改为 packed API：

```ts
runSquareDilateXor(options: {
  sourceWords: Uint32Array;
  inputWidth: number;
  inputHeight: number;
  sourceWordsPerRow: number;
  coreOffsetX: number;
  coreOffsetY: number;
  coreWidth: number;
  coreHeight: number;
  radius: number;
  budgetBytes: number;
}): Promise<
  | {
      ok: true;
      xorWords: Uint32Array;
      xorWordsPerRow: number;
      metrics: RasterMaskWebGpuRunMetrics;
    }
  | ExistingFallback
>;
```

删除 production `packRasterMaskRows()`；测试若需要从 alpha 构造 packed golden，应放在 test helper，不保留
第二条 production pack 路径。

### 8.2 core-only XOR shader

shader 每个 invocation 仍处理一个 `u32` word × 一行，但 dispatch dimensions 改为：

```text
ceil(coreWordsPerRow / workgroup.x) × ceil(coreHeight / workgroup.y)
```

参数至少包含：

```text
input_width / input_height / source_words_per_row
core_offset_x / core_offset_y
core_width / core_height / xor_words_per_row
radius
```

每个 output word：

1. 以 `coreOffsetX + outputWordX * 32` 为 bit origin，从一到两个 source words 提取对齐 center；
2. 对 `dy ∈ [-radius, radius]` 读取 center / previous / next，执行现有 square dilation；
3. 读取同位置原 source center；
4. 写 `dilated ^ source`；
5. 对 core 最后一 word 施加有效位 mask。

边界规则：

- input 已含所需 halo；shader 读出 input 时返回 0；
- `shift = 0` 单独处理，禁止产生 WGSL 的 32-bit shift 边界歧义；
- radius 继续限制为 1–31；
- 只写 core，不把 halo 差异带入 history；
- all-zero / all-one / no-op、贴图边缘和非对齐 core 必须 exact。

### 8.3 buffer 所有权与预算

WebGPU 规范要求 `MAP_READ` buffer 只能与 `COPY_DST` 组合，因此继续保留独立 readback buffer，不尝试
直接 map storage output。provider 改为分别记录容量：

```text
GPU source capacity
GPU xor target capacity
GPU readback capacity
params / optional benchmark query resources
JS source words
JS xor words
response patch bytes
```

规则：

- source、xor target、readback 分别 grow-only，不再假设三者 capacity 相同；
- 扩容前以 next capacity 做 admission；
- snapshot 报告实际总和，不用 `capacity × 3` 近似；
- mapped range 只 clone 有效 core XOR bytes；
- params 变化后同步更新 byte accounting；
- device lost、reset、Worker replace、gate teardown 和 dispose 销毁全部 GPU resources；
- 当前串行编辑合同下不增加双 / 三 readback ring；只有 `mapAsync` 经测量占 p95 30% 以上且能证明安全
  overlap 时，才另立计划。

## 9. XOR words → history patch

新增 Worker runtime helper：

```ts
buildRasterMaskMorphologyPatchesFromXorWords(
  session,
  request,
  xorWords,
  xorWordsPerRow,
): RasterMaskMorphologyRoiDiff
```

算法合同：

1. 逐 word 跳过 0；
2. 对 non-zero word 使用 `remaining &= remaining - 1` 枚举 set bits；
3. set bit 映射到 core local x/y，再映射到绝对 image x/y；
4. 按 512 tile 懒创建 `MaskHistoryPatch`；
5. 设置 tile-linear XOR bit；
6. 同时累计 changed pixels 与绝对 bounds；
7. 忽略最后一 word 的无效位视为错误，而不是静默生成越界 patch；
8. empty XOR 返回 `patches=[]`、`changedPixels=0`、`changedBounds=null`。

本版不在 GPU 上用 atomic count / min / max 产生 summary。WGSL 提供 `countOneBits` 与整数 atomic，但
XOR words 本来就必须回读以构造 history；CPU 只扫描 words 与实际 changed bits，先避免增加第二个
summary buffer、初始化 pass 和跨设备 atomic 性能差异。只有 patch build 成为新的显著瓶颈时再评估。

## 10. 路由与 fallback

### 10.1 路由顺序

当前“先 dense materialize、再问 GPU”的顺序必须改为：

1. 校验 session、request、core、input、operation 和预算；
2. 执行现有静态 route gate；
3. 获取 provider 并做无分配 preflight；
4. 非 ready 直接 dense CPU；
5. ready 才构造 packed source；
6. provider 成功则用 XOR words；
7. provider 失败才 dense CPU fallback。

provider preflight 只返回有界状态和估算，不创建 job buffer、不改变 store。warming 请求不等待初始化。

### 10.2 fallback reason

沿用 v0.23.16 枚举，不为优化细节增加用户可见状态。内部 metrics 可额外记录失败 stage：

```text
preflight
packed-prepare
upload-submit
readback
patch-build
```

packed prepare 或 patch build 的输入合同错误属于 Worker request / implementation error，不伪装成
`gpu-runtime-failed`。GPU validation / submit / map / lost 才进入现有 GPU fallback。

### 10.3 取消与 stale

- Worker pool 继续以现有 job id、timeout 和 slot replacement 处理取消；
- GPU 提交后浏览器 API 不能保证物理取消，结果回来后仍按 stale / abort 丢弃；
- main store 的 mutation generation、tile revision、session / sha / source revision 校验全部保留；
- 任何丢弃的结果不得 apply patch、retain history 或提升 revision；
- Worker replacement 重放 base session 后 provider 回到 idle，不复用旧 device / buffer。

## 11. 可观测性

### 11.1 Worker response metrics

将 morphology metrics 扩展为：

```ts
interface RasterMaskMorphologyMetrics {
  totalMs: number;
  backendPrepareMs: number; // packed 或 dense source
  computeMs: number; // CPU kernel 或 GPU wall total
  diffOrPatchMs: number;
  gpuUploadSubmitMs: number | null;
  gpuReadbackMs: number | null;
  gpuPassMs: number | null; // 仅 timestamp-query 可用时
  fallbackMaterializeMs: number | null;
  inputAlphaBytes: number;
  packedSourceBytes: number;
  xorReadbackBytes: number;
  allocatedGpuBytes: number;
}
```

命名可按现有代码风格调整，但必须能直接证明：成功 GPU 路径 `inputAlphaBytes=0`，且 response 不再以
core pixel 数做 diff scan。

### 11.2 timestamp query

`timestamp-query` 是 optional adapter feature，且 device 创建时必须显式请求。本版只允许 benchmark
模式在 feature 存在时启用：

- 不可用时 `gpuPassMs=null`，测试与产品行为不降级；
- 正式资格仍以 Worker round-trip / operation end-to-end wall time为主；
- timestamp 数值只用于区分 GPU pass 与 queue / readback，不用作绝对 SLA；
- 不要求用户开启 WebGPU Developer Features；
- 不持久化 adapter name、driver 或额外高熵硬件字段。

### 11.3 计数器

资源快照至少增加：

```text
packedGpuJobs
packedPrepareBytes / peakPackedPrepareBytes
xorReadbackBytes / peakXorReadbackBytes
gpuAlphaMaterializations（成功 GPU 应为 0）
gpuRuntimeFallbackMaterializations
sourceCapacityBytes / xorCapacityBytes / readbackCapacityBytes
```

测试不得只用 `performance.memory` 推断释放；显式 buffer / session / owner 计数仍是主证据。

## 12. WebGPU 能力采用边界

### 12.1 本版采用的标准能力

- storage buffer；
- `GPUQueue.writeBuffer()`；
- compute pass；
- `copyBufferToBuffer()`；
- dedicated `MAP_READ | COPY_DST` readback；
- `mapAsync()` / `getMappedRange()` / `unmap()`；
- WGSL `u32` bit operation。

参考：

- [WebGPU specification](https://gpuweb.github.io/gpuweb/)
- [WebGPU Shading Language specification](https://gpuweb.github.io/gpuweb/wgsl/)

### 12.2 只做可选诊断

- [Chrome WebGPU timestamp queries](https://developer.chrome.com/blog/new-in-webgpu-121#timestamp_queries_in_compute_and_render_passes)

### 12.3 本版拒绝作为依赖

- subgroups：adapter optional feature，WGSL 需要显式 enable，且跨后端实现仍有差异；
- `subgroup_id` / `linear_indexing`：只减少索引样板，不解决当前 dense materialize / diff；
- shader-f16：当前数据是 exact 1-bit mask，没有精度或吞吐收益；
- external texture：用于已解码图像 / 视频，不适用于 packed mask compute；
- GPU memory heap 明细：不是稳定产品预算 API，也会扩大硬件指纹面。

参考：

- [Chrome WebGPU subgroups](https://developer.chrome.com/blog/new-in-webgpu-134#improve_machine-learning_workloads_with_subgroups)

## 15. 性能资格方法

### 15.1 canonical run

- 有头 Chromium；
- 固定 viewport / source / operation；
- `square dilate r2` 主场景，`r31` 只做补充压力样本；
- `2048²` 与 `3840×2160`；
- baseline / candidate 交替，避免先跑完一种实现产生温度和频率偏差；
- 每个 case 每轮 3 次预热 + 至少 10 次记录，建议 20 次；
- 两轮之间重建 page / pool / store；
- 每轮保存 raw samples、聚合值、checksums、backend、fallback、显式 bytes。

### 15.2 必过门

1. 两个 ROI、两轮都命中 WebGPU；
2. patch 与 save exact；
3. 相对同轮 v0.23.16 WebGPU p95 改善至少 15%，任一轮不低于 10%；
4. p50 不得恶化 5% 以上；
5. gate-off CPU 和 default-X11 CPU p95 不恶化 5% 以上；
6. successful GPU alpha bytes = 0；
7. GPU path 不执行 core-wide dense diff；
8. Long Task = 0；
9. owner <= 1；
10. warm resources plateau，dispose 全归零。

### 15.3 结论规则

| 结果                             | 决策                                                |
| -------------------------------- | --------------------------------------------------- |
| exact 且全部性能 / 资源门通过    | 保留 packed XOR 路径，继续 default-off              |
| exact，但任一 ROI 任一轮低于 10% | 撤回 packed XOR production 路径，保留测量与失败结论 |
| 10–15% 波动                      | 增加一轮同机复测；仍不稳定则按失败处理              |
| parity、history 或 save 不一致   | 立即失败，不用性能收益抵消                          |
| 资源不 plateau 或 dispose 不归零 | 立即失败，不进入跨平台测试                          |
| macOS 无 adapter / 性能不达门    | Linux 工程优化可封版；默认开启继续阻断              |

## 18. 风险与缓解

| 风险                           | 后果                           | 缓解                                      |
| ------------------------------ | ------------------------------ | ----------------------------------------- |
| core x 非 32 对齐              | XOR 串位、越界 patch           | 对齐提取 helper + 1/31/32 边界 golden     |
| edge tile width 非 512         | override 读取错误              | 不假设 row alignment，按 tile width 提取  |
| shader 尾位未清                | changed pixels / bounds 假增   | shader mask + Worker 尾位拒绝             |
| GPU failure 后重复 materialize | fallback 尾延迟和内存抖动      | 单一 lazy dense helper + metrics count    |
| buffer 容量仍按同值增长        | 浪费显存、预算误拒绝           | source / xor / readback 独立 capacity     |
| timestamp feature 降低可用性   | adapter 可用但 device 创建失败 | 仅 benchmark 显式请求，普通 device 不要求 |
| packed prepare 仍是 O(N)       | 总收益不足                     | 性能门失败即撤回；cache 另立计划          |
| 新 metrics 过度膨胀            | 协议复杂、维护成本上升         | 只保留能驱动决策的阶段与字节字段          |
| Mac 单机被误作全平台证据       | 错误默认开启                   | release / default-enable 两套门明确分离   |

## 20. 后续决策，不在本版顺带实现

v0.23.17 只回答“能否用 packed input + XOR readback 进一步降低已验证 WebGPU 路径延迟”。完成后按
新的阶段占比决定下一步：

1. **upload 成为主瓶颈**：评估 GPU-resident immutable tile / session cache与增量 dirty patch，但必须先
   设计 revision、预算和 Worker replacement replay；
2. **readback / map 成为主瓶颈**：评估有界 readback ring 或 GPU patch compaction，但不能破坏串行编辑
   与取消合同；
3. **GPU pass 成为主瓶颈**：再对 workgroup、subgroups 或分离横纵 pass 做 A/B；
4. **patch build 成为主瓶颈**：评估 GPU count / bounds 或 word-level tile scatter；
5. **跨平台矩阵通过**：另立默认开启决策，不在性能提交中顺带翻转 gate；
6. **用户确有更多 morphology 性能需求**：逐个 kernel 建 exact golden 和 crossover，不批量移植。

这六条都需要新的测量结果触发，不作为本版预先承诺。
