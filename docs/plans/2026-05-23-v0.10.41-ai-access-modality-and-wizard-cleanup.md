- 持久化 `health_meta.capabilities.modalities`（v0.10.37 `derive_modalities` 落库）当前**只有** `Step4Ai.tsx:146-153` 在用（标"⚠ 不支持本项目模态"）。

**点 2 — Step4 AI 步骤真实链路**（`CreateProjectWizard.tsx:463-470`）：
- `ai_enabled` / `text_output_default` / `ml_backend_source_id` 真实提交。
- `ml_backend_source_id` → 后端 `_clone_backend_to_new_project`（`projects.py:378-388`）真把源 backend 行复制到新项目。**真实功能，保留**。

## 2. 决策底线（本版守住）

- 能力消费**收敛到持久化 `modalities` 快照**为主（`derive_modalities` 单一真值）；`/setup` 仅用于取变体 enum 具体值，不再作模态门控真值。

- 不改 `MAX_ML_BACKENDS_PER_PROJECT` 默认值、不删多 backend 选择器（dev=1 / prod 调高，有意为之）。
- 不做多模型对比、不碰 `async_jobs`。

## 3. 实施步骤（带验收）

### 步骤 1 · VariantPanel 模态门控收敛到 modalities（点 1）
- 读 `backend.health_meta?.capabilities?.modalities`：图像组仅当 `modalities.includes("image")` 渲染；视频组仅当 `includes("video")` 渲染——**不支持的模态组整段隐藏**（取代当前"视频组永远显示+提示"）。
- 组内变体 enum 仍来自 `/setup.params`（取具体变体名填下拉，逻辑不变）。
- **回落**：`modalities` 为空（backend 未健康检查过）→ 回落当前 `/setup` 存在性门控，**不要把没探测过的 backend 整组藏掉**（避免误判"无能力"）。
- **verify**：纯图像 backend → 视频组消失；视频 backend → 图像组消失；双模态 → 两组都在；未健康检查 backend → 回落旧行为、不空白。

### 步骤 2 · 删假「模型」下拉（向导 Step4 + 设置页 GeneralSection）（点 2）
- `Step4Ai.tsx`：删模型 `<select>`（`PRESET_AI_MODELS`/`CUSTOM_MODEL_KEY`/`aiModelChoice`/`aiModelCustom`/`resolvedAiModel`/「当前模型」Badge）。
- `CreateProjectWizard.tsx`：FormState 删 `aiModelChoice`/`aiModelCustom`，提交 payload 的 `ai_model` 改为不发（让后端落 null；若复用 backend，`_apply_backend_display_hint` 会用 backend.name 回填）。
- **设置页 `GeneralSection.tsx`（用户截图指出的「高级:手动指定模型名 hint」）**：删同款下拉 + 自定义输入 + `aiChoice`/`aiCustom`/`resolvedAiModel`（`L33-37,47,67,84,256-261`）。保存时 `ai_model` 只剩 `boundBackendName || null`（去掉 `effectiveAiModel = boundBackendName || resolvedAiModel` 里的手填分支，`L106,118`）。
- 保留：`aiEnabled` 开关、`TextOutputDefaultSelect`（真实 `text_output_default`）、`BackendSourceSelect`（复用 backend，真实 clone）、AI 框去重阈值等真实字段。
