## 背景

v0.13.3(方案 A)已让用户在主 3D 视图放置 / 选中 / 编辑 3D 框 + 数值面板。已知短板(ADR-0032 负向):**透视视图里纯 gizmo 拖拽精度不够**,复杂遮挡场景精修慢。SUSTechPOINTS / xtreme1 标注员的主力精修方式是**三正交视图**:选中框后开俯 / 侧 / 正三个小窗,对着"框内点"拖边 / 拖角 / 拖方向线把框贴准。本切片补上这块,是整个 epic 体验上的关键一跃,也是前端最重切片之一。

**为什么排在 0.13.4 后**:0.13.4 投影联动上线 = 联合标注 MVP,标注质量要求随之抬高;此时精修效率成为瓶颈,三视图收益最大。且 B 复用 0.13.4 已稳定的 PSR↔角点 / 投影约定,坐标系不会再漂。

## B 建在 A 之上(数据层零改)

ADR-0032 已铺好接缝,B 是**纯增量**:
- 复用选中框 **PSR 单一真值驱动入口**(A 已预留:同一份 PSR 同时驱动主视图 gizmo / 数值面板,B 再挂一路三视图)。
- 复用 [`geometry/box3d.ts`](../../apps/web/src/pages/Workbench/stages/three-d/geometry/box3d.ts) 的 PSR↔矩阵 / 8 角点纯函数(欧拉角顺序 `XYZ`、yaw=`rotation[2]`,与投影同一套)。
- 复用持久化(`useUpdateAnnotation` 防抖 PATCH)、撤销重做、`Box3DGeometry` 数据模型 —— **不动后端、不改数据模型**。

## 范围(大概做什么)

### B-1 三视图面板布局
- 选中框 → 出三个正交小窗(top / side / front);无选中 → 面板空。
- 布局:主 3D 视图 + 一侧三联视图(参考 SUSTechPOINTS 右侧栏)。每窗一个标题 + 旋转/平移微调按钮(可后置)。

### B-2 每视图正交相机 + 框内点裁切渲染
- 每窗一个 `OrthographicCamera`,对齐框 **local 轴**:top 俯视(看 -Z,出 X-Y)、side(看 X,出 Y-Z 之类)、front(看 Y),相机框住框 + margin。
- **框内点裁切**:只画落在框 local AABB(带 margin)内的点投到该视图平面 —— 这是"贴准"的关键(看得见目标轮廓)。
- **渲染方案倾向**:共享一个 `WebGLRenderer`,用 `setViewport` / `setScissor` 在不同区域画各视图(SUSTech 思路),**避免多 WebGL context**(上限 / 泄漏风险)。

### B-3 边 / 角 / 方向线拖拽精修(核心移植)
- 把框投成各视图的 2D 矩形:**拖边**改一维尺寸 + 平移(对侧固定)、**拖角**改两维、**拖方向线**改 yaw(仅 top)。
- 拖拽数学:屏幕 delta → 视图平面 local delta → 更新 PSR 对应分量 → 回写单一真值。
- 移植 SUSTechPOINTS [`side_view_op.js`](../../third-party/SUSTechPOINTS/) 的边 / 角 / 方向线 hit-test + 拖拽算子。

### B-4 双向同步 + 持久化
- 三视图编辑 → 更新 PSR → 主视图 gizmo / 数值面板 / 三视图三方同步;松手走 A 的防抖 PATCH。

| 文件 | 量级 | 处理 |

## 设计决策(草案)
- **裸 Three.js 命令式**(承 ADR-0031 / 0032),不引 r3f。
- **多视图 = 单 renderer + viewport/scissor**(非多 context),资源生命周期在 `PointCloudScene` 收口。
- **框内点裁切 = CPU 端按 local AABB 过滤生成小 buffer**(选中时算一次,PSR 变才重算),实现简单;点数大 / 卡顿再上 GPU clipping planes。

## 不做(明确排除)
- 多框批量 / 跨帧轨迹(SUSTech `BoxEditorManager`)。
- 自动拟合 / 贴合(`fit_bottom` / `auto_shrink` / 框内点高亮)—— 列 stretch。
- `point_mask_3d` 分割(另切片,v0.13.6+)。
- 后端 / 数据模型改动(B 纯前端增量)。

## 风险
- **移植量大**:本 epic 最重前端切片之一,需独立排期、可能再拆子切片。
- **坐标系一致性**:三视图 local↔world↔screen 多层变换,欧拉角顺序须与 `box3d.ts` / 0.13.4 投影**严格统一**,否则三视图 / 主视图 / 投影互相对不上。
- **性能**:框内点裁切重算频率 + 多 viewport 渲染开销(大点云尤甚)。
- **WebGL 资源**:多 viewport / 裁切 buffer 的 dispose 生命周期(承既有风险条)。

## 验证(成功标准 · 草案)
- 三视图拖边 / 角 / 方向线 → 框 PSR 变 → 主视图 gizmo / 数值面板 / 投影(0.13.4)**三方同步一致**。
- 与 SUSTechPOINTS 同 scene 对拍:同样操作后框 PSR 接近。
- 拖拽数学纯函数单测;典型 scene e2e;切任务 / 反复进出无 WebGL context lost、内存稳定。
