# Plan · Data Manager 对象 / 轨迹级探索器

状态：**草拟 2026-07-11 · 版本锚点 v0.21.30 · 已确定为 v0.21.29 后续切片**。

> 上游：[v0.21.29 Data Manager 聚合、结构化搜索与模态化视图](2026-07-11-v0.21.29-data-manager-aggregation-search-and-modality-views.md)。本版只在上游 task-centric 查询、capability schema、权限 scope、匹配对象 read model 和性能基线稳定后开始。

## 1. 目标

v0.21.29 回答“哪些任务包含目标对象/轨迹”，结果仍以 task 为一行。本版增加 object-centric lens，让用户可以跨任务直接探索 annotation 与 track：

- 一行就是一个对象或一条逻辑轨迹；
- 可按类别、来源、属性、track ID、关键帧来源和时空范围筛选；
- 可保存对象级视图；
- 可从结果稳定跳转到对应工作台、任务、Scene 帧或视频帧；
- 与 task lens 复用权限范围、字段 schema 和过滤语义。

## 2. 已锁边界

- 继续使用 `/projects/:id/data-manager`，新增任务 / 对象 / 轨迹 lens，不创建另一套项目页面。
- v0.21.29 的任务视图保持默认入口；项目启用相关能力时才出现对象/轨迹 lens。
- 对象和轨迹是不同 grain，不能把跨帧轨迹简单展开成重复对象行后假装是一条轨迹。
- 本版仍以探索、定位和审阅为主；批量改类、改属性、拆分/合并轨迹等写操作另行评估，不因增加列表而默认开放。
- 不改变 annotation、prediction 和 tracker candidate 的权威写模型；新增的是查询/read-model 契约。

## 3. 行模型

### 3.1 Object lens

适用于 image、单帧 video shape、lidar frame annotation：

- annotation ID、task/display ID、文件/Scene/帧定位；
- class、tool unit、geometry type；
- annotation source、imported、AI parent/candidate lineage；
- track ID（若有）；
- schema 驱动的属性值和逐键 attribute origin；
- confidence、创建者、创建/更新时间、反馈摘要；
- 工作台 deep link。

### 3.2 Track lens

按项目形态使用不同的聚合器，但输出统一的基础契约：

- **compact video track**：一条 track annotation 为主实体，汇总 keyframe 数、跨度、outside/occluded、keyframe source 和 mutable attributes。
- **scene image/lidar track**：多条跨 task annotation 共享 `track_id`，按 `(project_id, track_id)` 聚合帧覆盖、缺帧、类别/属性一致性、manual/AI/interpolated 来源。

统一字段包括 track ID、class、轨迹类型、起止范围、对象/关键帧数、来源摘要、属性摘要、质量异常和定位入口；模态专属字段由 capability schema 注入。

## 4. Saved view 与 URL 状态

扩展保存视图模型：

```text
entity_scope = tasks | objects | tracks
filter_json
sort_json
columns_json
```

规则：

- 旧视图默认 `entity_scope=tasks`，迁移后行为不变。
- 不同 scope 使用独立的字段/列白名单；切换 scope 时只迁移明确兼容的公共规则。
- 不兼容条件显示为“当前视图不可用”，由用户确认移除，不能静默改写。
- scope、搜索、筛选、排序、列和选中实体写入 URL，刷新和分享后可恢复；仍受接收者权限限制。

## 5. API 草案

复用 v0.21.29 的 visible task scope 与 capability schema，新增：

```text
POST /projects/{project_id}/data-manager/objects/query
POST /projects/{project_id}/data-manager/tracks/query
GET  /projects/{project_id}/data-manager/objects/{annotation_id}/location
GET  /projects/{project_id}/data-manager/tracks/{track_id}/detail
```

要求：

- object query 直接在 active annotation grain 分页，不能先分页 tasks 再展开对象。
- track query 在逻辑轨迹 grain 分页；scene track 使用 project + track ID 聚合，video track 使用 compact annotation 实体。
- 计数、排序和 facets 必须发生在对应 grain，不能复用 task total 冒充。
- 所有结果先与 visible task scope join，避免对象/轨迹数量和属性泄露。
- 工作台 location 返回稳定 task/frame/entity 定位信息，不返回完整 raw geometry。

## 6. 页面交互

- Data Manager 主区增加 `任务 / 对象 / 轨迹` lens switcher；不支持轨迹的项目隐藏轨迹入口。
- 每个 lens 拥有自己的 saved views、默认列和列设置。
- 对象表重点展示类别、来源、轨迹归属、属性、任务/帧和反馈。
- 轨迹表重点展示跨度、覆盖、关键帧/实例数、outside/occluded、来源和属性一致性。
- 点击行打开详情抽屉；抽屉提供“在工作台打开”，并精确定位对象、视频帧或 Scene 帧。
- 属性列默认只显示项目常用字段，其余通过列设置启用，避免属性多时横向失控。
- 大结果集使用服务端排序与虚拟化；不得把全部 annotation/track 拉到浏览器聚合。

## 7. 性能与索引门槛

- 复用 v0.21.29 已验证的 track ID 一致性和项目/任务复合索引。
- object query 针对 project、active、class/source/tool unit、track ID 建立可解释的组合/partial index。
- scene track aggregation 必须检查 `count(distinct track_id)`、帧范围和属性汇总的执行计划。
- compact video keyframe/outside 深度过滤若 JSONB 展开不达标，建立受控派生 projection；不在请求内重复展开同一 geometry。
- 对象/轨迹常用查询使用至少 1,000,000 annotations 的种子集保存 `EXPLAIN (ANALYZE, BUFFERS)` 前后对比。
- 第一页常用查询目标 P95 ≤ 1 s；详情目标 P95 ≤ 500 ms；不允许 N+1。

## 8. 实施分期

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| **OT-0 上游验收** | 验证 v0.21.29 schema、scope、match read model、track ID 和性能基线 | 上游契约稳定，无需复制查询逻辑 |
| **OT-1 数据契约** | `entity_scope` 迁移、object/track schema、query/detail/location API | 旧 task saved view 无行为变化 |
| **OT-2 Object lens** | 对象级筛选、排序、列、saved view、抽屉和工作台定位 | image/video/lidar 对象结果准确 |
| **OT-3 Track lens** | compact video 与 scene track 聚合器、专属字段和详情 | 两种轨迹 grain 均无重复/漏计 |
| **OT-4 性能与文档** | 索引、规模基准、权限回归、用户/开发文档、CHANGELOG | 达到性能门槛且无可见范围泄露 |

## 9. 验收重点

- task/object/track 三种 total 与 grain 一致。
- 相同 class + attribute 条件在 object lens 中严格命中同一 annotation。
- scene track 跨 task 合并正确；compact video track 不按 keyframe 重复成多行。
- attribute origin、keyframe source、annotation source 不混桶。
- 普通用户无法通过搜索、facet、total、详情或 deep link 获取不可见 batch 的对象。
- 旧 task saved views 迁移后仍可打开、查询和保存。
- 工作台跳转能定位 image object、video frame/track、lidar Scene frame/object。

## 11. 非本版事项

- 跨项目对象搜索和组织级数据仓库。
- 批量改类、批量改属性、轨迹拆分/合并/完成状态。
- 几何相似度、向量搜索或自然语言搜索。
- 在 Data Manager 内直接编辑 raw geometry。
