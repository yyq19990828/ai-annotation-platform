# v0.21.2 · 跨帧对象 id 统一（group_id 链 → track_id）

状态：**定案（accepted，2026-07-03，已审核核验）**。四问探讨 Q3 的**大重构**部分——含数据迁移，
独立于 v0.20.12（命名消解，纯 rename）。**紧接 v0.21.1（检测式 tracking）之后**，与它协调 track_id
落点（见「与其他串的协同」），体量大、建议独立 ADR。

> **行号说明**：本文行号为撰写时快照，代码已漂移（如 `propagate` 实际 `annotation.py:638`、
> `interpolate_range` `annotation.py:926`）；实现时**按符号定位**，行号仅供参考。承重断言（值域切分 /
> track_id 仅在 geometry / box_3d 无 track_id / 导出用法 / 前端分裂）已逐条核验属实（2026-07-03）。

## 背景

「跨帧同一对象」现在用**两套 id**：
- `annotation.group_id`（本是 per-task 图像编组，Ctrl+G）被**高位段借用**做跨帧链——`propagate` /
  `interpolate_range` 从 `cross_frame_group_seq`（START `1000000000`）分配 group_id 串同一对象的多帧。
- `track_id` 只存在于 `video_track_bbox` geometry 内（VideoTrackerJob + `_new_track_id()`）。

目标：跨帧对象延续**统一到 `track_id`**，`group_id` 回归纯图像编组，消除「一个字段两种语义」的债。

## 现状（已核实）

- **可靠区分存量**：`cross_frame_group_seq START 1000000000`（`0097_project_prefer_scene_and_group_seq.py:46`），
  故 `group_id >= 1e9` = 跨帧链、`< 1e9` = 图像编组，迁移可精确筛选（`WHERE group_id >= 1000000000`）。
- **两套并存**：`propagate`（`annotation.py:651`）分配 group_id 串跨帧链，**不写 track_id**；track_id
  只在 `video_track_bbox`。所以**静态几何（box_3d）的跨帧链只有 group_id、没有 track_id**。
- `interpolate_range`（`annotation.py:794-885`）按 `group_id` 查两端框插值，**仅支持 box_3d**。
- **前端 video 工作台完全靠 track_id** 认同一对象（`VideoTrackSidebar.tsx`、`videoKonvaInteraction.ts`）
  → 迁移后自然契合；**3D 工作台跨帧高亮靠 group_id**（`perObjectAlign.ts` / 3D workbench）→ 要改。
- **导出**：MOT/KITTI 已用 track_id（`export_video.py` + `derive_track_number`，**零改动**）；
  COCO `__group_id`（`export.py:718`）、LiDAR `instance_token`（`export_lidar.py:234`）用 group_id → **要改**。

## 立项要先定的架构决策：track_id 提升为 annotation 表列？

现在 track_id 只在 geometry JSON 内（`video_track_bbox`）。跨帧对象标识**本该是 annotation 级、与
几何类型无关**。建议：

- **推荐**：把 `track_id` 提升为 **`annotation.track_id` 表列**（通用跨帧标识，所有几何类型可用），
  `interpolate_range` / `propagate` / 导出统一读表列；`video_track_bbox` geometry 内的 track_id 与
  表列同步或迁入。这直接解掉「box_3d 无 track_id」的卡点（表列对所有类型可用）。
- 备选：track_id 继续留 geometry 内、box_3d 也往 geometry 塞——但每种几何各自维护，散、易漂移。

**这个决策值得单独 ADR**（数据模型 + 分步迁移）。

## 关键卡点（迁移地基）

- 🔴 **box_3d 无 track_id**：3D 跨帧链目前只有 group_id。任何迁移前必须先给存量跨帧 box_3d 链补
  track_id（若采纳「提升为表列」，这一步即「回填 `annotation.track_id`」）。

## 分步方案

1. **Phase 1（地基）**：确定 track_id 落点（推荐表列）；为存量跨帧链（`group_id >= 1e9`）回填 track_id。
   - **track_id 格式须全局统一**（审核补，2026-07-03）：现有三处各造 id——v0.21.1 检测式 track 用
     `trk_<uuid>`（`_remap_track_ids`）、交互式 VideoTrackerJob 用 `_new_track_id()`、本版 3D 存量回填是
     第三套。提升为表列后**必须收敛到同一格式**（建议统一 `trk_<uuid>`，`_new_track_id` 作单一工厂），
     否则 `annotation.track_id` 列里混形态、跨类型查询/去重失据。回填时按 `(project, group_id>=1e9)` 链
     生成稳定 track_id，同链多帧共享一个。
2. **Phase 2**：`propagate` / `propagate_batch` 改分配 track_id，`group_id` 归 NULL；停用
   `cross_frame_group_seq`。
3. **Phase 3**：`interpolate_range` 改按 track_id 查询（充分单测：缺 track_id、同 track_id 多框）。
4. **Phase 4**：导出 COCO（`__group_id` → track_id attr）、LiDAR（`instance_token` 改 track_id）；
   MOT/KITTI 不动。
5. **Phase 5**：前端 3D 工作台跨帧配对 / 关键帧插值 UI 改用 track_id；重测运动补偿。
6. **Phase 6**：数据迁移收尾 + 废弃 `cross_frame_group_seq`。

数据迁移草案（`group_id >= 1e9` → track_id，其余 group_id 保留为图像编组）——精确值域筛选，无误伤。

## 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| box_3d 无 track_id | 🔴 | Phase 1 先回填，是所有后续的地基 |
| interpolate 查询改动 | 🟡 | 充分单测覆盖边界 |
| LiDAR instance_token 变化 | 🟡 | 历史导出兼容策略；新导出用新逻辑 |
| 3D 工作台运动补偿配对（`perObjectAlign.ts` 按 group_id） | 🟡 | 改 track_id 后重测多帧匹配 |
| audit log 旧 group_id 冻结 | 🟠 | 跨帧链历史查询适配 |

## 与其他串的协同

- **v0.21.1 检测式 tracking（直接上游）**：会**大量产出 track_id**（`VideoTrackGeometry`）。它和本版
  方向一致——都在把 track_id 推成跨帧一等标识。本版**紧接 v0.21.1**，正是为了让 track_id「提升为表列」
  在检测式 track 落地后一次做到位：**v0.21.1 先落一批只在 geometry 内的 track_id，v0.21.2 随即把
  track_id 提升为 `annotation.track_id` 表列并统一存量**，避免迁两遍。两版的 track_id 落点应在 v0.21.1
  的 ADR 里就预留一致方向。
- **v0.21.3 删除标注编组（下游收尾）**：本版把 `group_id` 的跨帧语义迁到 `track_id` 后，`group_id`
  只剩「图像批量编辑」这一角色；v0.21.3 紧接着删掉它（批量编辑退化为前端临时多选）。本版是 v0.21.3
  的**硬前提**，顺序不可颠倒。

## 排期

- **v0.21.2**，紧接 v0.21.1。独立 ADR（track_id 表列决策 + 分步迁移）。前置：v0.21.1 的 track_id 落点
  方向须与本版一致（geometry 内先行、表列随后统一），在 v0.21.1 ADR 里预留，避免迁两遍。
