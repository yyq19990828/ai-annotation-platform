## 1. 独立交付结果

本版将仍由各自坐标、拖动和 resize 逻辑管理的两个大型工作浮层接入 v0.25.0 的 panel registry：

- AI 单题运行 / 审阅面板 `ai-task`，内容来自现有 `AIPredictionPopover`。
- 视频追踪配置 / 运行面板 `video-tracker`，内容来自现有 `VideoTrackerPropagateDialog`。

两个 panel 都能停靠、组成标签、在同一浏览器窗口内浮动、隐藏、从“布局 / 面板”菜单恢复，并在重复打开时聚焦已有实例。新增“图片 AI 审阅”和“视频追踪”两组上下文预设。

本版不把业务任务交给 Dockview。AI mutation、视频 tracker job、种子、范围、当前帧、候选与草稿仍由 `useWorkbenchShellModel` 及现有 hooks 所有；布局只保存 panel 身份和空间结构。

预估量级为 4–6 个工程日。v0.25.1 若因 Stage 生命周期门取消，本版仍在固定中心 canvas 周围完整工作。

## 2. 当前基线与问题

| 组件                          | 当前空间所有权                                                                          | 当前业务所有权                                             | 本版变化                                                        |
| ----------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------- |
| `AIPredictionPopover`         | 自己读取 viewport，使用 `useAiPopoverFrame` 保存全局 localStorage 坐标 / 尺寸           | `useWorkbenchShellModel` 的 open、模型配置、运行与采纳回调 | 拆出无定位内容，由 `ai-task` panel 承载；业务状态不迁移         |
| `VideoTrackerPropagateDialog` | 作为 `stageOverlay`，使用 `useVideoTrackerPanelFrame` 保存全局 localStorage 坐标 / 尺寸 | Shell 的传播 session、种子、范围、job 与 review 流程       | 拆出无定位内容，由 `video-tracker` panel 承载；job owner 不迁移 |
| AI / 视频旧坐标 hooks         | 每类一组未按账号、mode、stageKind 分桶且无法证明 owner 的 key                           | 不拥有业务状态                                             | 新布局不读取、不上传；停止新写入但保留 key 供旧构建回滚         |

当前两套浮层能拖动和缩放，但不能与工作台外围面板组成统一布局，坐标也不能跨设备恢复。各自实现 viewport 夹取和 pointer capture，继续叠加会产生 z-index、窄屏和快捷键竞争。

## 3. 目标、非目标与实体增量

### 3.1 目标

- 两个 panel 使用 v0.25.0 的 registry、snapshot writer、mode / stageKind 结构过滤、menu 命令和 Dockview 主题，不建第二套布局状态。
- 重复工具入口执行 show / focus existing，不产生重复 panel、重复 AI session 或重复 tracker session。
- 隐藏、停靠、浮动、成组、切 tab、应用预设和恢复布局都不取消正在运行的任务，不重置表单草稿。
- 新 panel 使用确定的 context 默认位置；无 owner 的旧全局坐标不得进入账号级 workspace 或跨设备同步。
- 图片、视频两组新预设是一次性布局命令，可撤销到应用前的会话布局。

### 3.2 明确不做

- 不迁移 `SelectedAnnotationCard`、桌宠、对象锚定菜单、SAM / 选区操作、确认框、抽屉、Toast 或快捷键帮助。
- 不迁移 `VideoTrackerReviewBar`、`VideoMaskCorrectionDialog`、`MaskConversionDialog` 等锚定当前 Stage 交互的 review / modal 层。
- 不迁移 3D 三视图、相机放大、PSR 面板或其内部预设；顶层菜单只提供到既有 3D 预设的入口。
- 不修改 AI pipeline、tracker API、job 生命周期、模型发现、传播范围、种子采集、候选采纳或视频 review 业务规则。
- 不新增用户命名预设、预设 CRUD、跨项目共享、多显示器 popout 或多个同类 panel。

### 3.3 实体与维护增量

Entity delta：`+0 / -0`。本版复用 v0.25.0 的 `dockview-react`、`workspace` schema、API、registry 与 writer，不增依赖、endpoint、数据库迁移、环境变量、长期 feature flag、后台任务或外部账号。

本版客户端读取 v1 / v2 / v3，并在任一布局 mutation 时写 v3。v3 grammar 含两个新 panel ID，并同时接受固定与可移动 canvas，因此实现不依赖 v0.25.1 是否发布。后端验证和版本降级 409 已由 v0.25.0 预留，本版不改 API；旧客户端不能解释 v3 时进入只读标准布局，不能过滤后原子覆盖。回滚不要求数据清理。

## 4. Panel 与交互合同

### 4.1 能力注册

| Panel ID        | 结构注册条件                                                        | renderer | 默认打开方式                                                      | 禁止项                               |
| --------------- | ------------------------------------------------------------------- | -------- | ----------------------------------------------------------------- | ------------------------------------ |
| `ai-task`       | 现有 AI action registry 支持的 mode / stageKind；不依赖瞬时权限结果 | `always` | 原 AI 入口 show / focus existing；图片 AI 预设放在 inspector 同组 | 重复实例、popout、越过既有能力 gate  |
| `video-tracker` | 仅 video context；不依赖 tracker 能力发现当前是否成功               | `always` | 原追踪入口 show / focus existing；视频追踪预设停靠在 canvas 侧边  | 重复实例、popout、在 image / 3d 注册 |

`always` 用于保留组件内尚未上提的配置草稿、AI 冷启动计时和视频 tracker session UI。panel 不可见时暂停非必要动画与纯展示轮询，但不卸载内容，也不终止由业务 owner 管理的请求或 job。

能力判断只复用现有 toolbar / action gate，并显式区分 `loading | available | unavailable`；`unavailable` 还必须标记为可恢复的探测失败或权威权限撤销。sanitizer 只按 mode / stageKind 的结构 allowlist 判断节点是否合法，不因权限、只读、能力 loading 或后端暂时不可达而删除结构合法的 panel：

- 非 `available` 时，panel 记录原 group / index / floating rect 与用户 `visibilityIntent`，以 dormant 状态进入 parking，不展示布局菜单或预设入口，也不触发新的 AI / tracker 请求。冷启动后从未进入过 `available` 的 panel 不挂载业务内容；已经挂载的 panel 遇到 `loading` 或可恢复的探测失败时，必须保留同一 `renderer: always` 内容实例，以不可见、`inert` 且禁用交互的方式留在 parking，并暂停纯展示轮询，不执行 effect cleanup、业务 cancel 或 owner 持有的 request / job 终止。
- 权威权限撤销不是上述瞬时 dormant：业务 owner 先按既有权限切换合同取消未授权 session、清除组件内敏感草稿并确认完成，之后才允许卸载内容；布局节点、`visibilityIntent` 和返回描述仍保留，恢复权限时建立新的业务 session，不能复活已清理状态。
- 单纯的能力投影抑制 writer；用户随后移动其他面板时，serializer 仍完整保留 dormant panel、返回描述和 `visibilityIntent`，不得裁剪节点。
- 桌面模式恢复 `available` 时，`visibilityIntent = shown` 的 panel 按返回描述恢复；目标已失效则使用第 4.3 节确定默认位置。用户原本主动隐藏的 panel 保持隐藏。
- 紧凑模式恢复 `available` 时不得执行桌面返回描述或改写锁存桌面模型：若该实例在进入 dormant 前正显示于 `compact-overlay` 且 `visibilityIntent = shown`，只把同一实例恢复到该 overlay；否则留在 parking，重新开放“面板”菜单，并把桌面恢复记为内存中的 pending action。退出紧凑模式完成锁存树重放后，才按桌面返回描述执行 pending action；用户可在退出前通过紧凑菜单显式 show / hide，hide 同时清除 pending action。
- 只有结构上不允许的组合才判非法，例如 image / 3d 中的 `video-tracker`；后端 grammar 与前端 sanitizer 对此拒绝整份 context 快照并回退标准布局。

### 4.2 打开、隐藏与业务取消

布局可见性和业务 session 是两条独立状态：

1. 工具栏或业务入口第一次打开时建立业务 session，并在默认位置显示 panel。
2. 再次从任意入口打开时聚焦同一 panel；不得创建第二份 React 内容或再次提交请求。
3. Dockview tab 的关闭动作统一命名为“隐藏面板”，只改变布局可见性，不调用 AI `onClose`、tracker `onCancel` 或 job cancel。
4. panel 内容中的“取消配置 / 结束当前操作”继续调用既有业务回调；业务结束后可按现有规则隐藏 panel，但不删除其最后空间位置。
5. 切换 task 时继续执行现有 session 清理合同；布局中的 panel 位置保留，下一题重新打开时复用。
6. tracker 已提交并进入后台运行后，隐藏 panel、切 tab 或切换预设都不取消 job；结果、失败与 review 仍由现有 job owner 推进。

同一 panel 在布局树中最多一个实例。sanitizer 与后端 grammar 遇到任何重复 ID 都拒绝整份 context 快照并回退标准布局，不采用“保留第一项”；show / focus API 必须幂等。

### 4.3 拖动竞争与菜单等价能力

- AI 和视频 panel 都只从 Dockview header 开始拖动；表单、slider、select、种子按钮和 scroll 区域不启动布局拖动。
- 第一次打开且没有返回描述时使用唯一决策顺序：若当前聚焦的 floating group 已含另一个大型编辑 panel 且接受目标 ID，就以 center move 加入该 floating tab group；否则 `ai-task` 加入现有 inspector group，inspector 不可用时创建 canvas 右侧 sibling，`video-tracker` 创建 / 复用 canvas 右侧 sibling。不得按距离猜测 group，也不自动制造两个浮窗。已有返回描述始终优先于本默认规则；用户仍可通过明确“浮动”命令调整。
- 每个 drag 动作都有“移到左 / 右 / 底部、加入当前标签组、浮动、隐藏”的菜单入口。
- panel 的表单或 Dockview tab 获得焦点时，画布单键快捷键不响应；drag overlay 截止 pointer / dblclick，不把事件泄漏到 Stage。
- `<=1024px` 使用 v0.25.0 紧凑投影，两个工具 panel 复用唯一 `compact-overlay`，由“面板”菜单切换同一实例，不覆盖 canvas 关键操作；该投影不写回桌面快照。

## 5. 组件边界与状态流

```text
toolbar / preset / panel menu
  -> open-or-focus stable panel ID
  -> WorkbenchDockWorkspace                space only
       ├── ai-task
       │    └── AIPredictionPanelContent
       └── video-tracker
            └── VideoTrackerPanelContent
                    │
                    ▼
useWorkbenchShellModel                     business owner
  ├── AI config / mutation / candidates / accept callbacks
  └── tracker session / seeds / range / job / review callbacks
                    │
                    └── no business data enters snapshot
```

实施时将两个现有组件分离出无定位内容：

- `AIPredictionPanelContent` 保留配置、运行状态、采纳和统计 UI，移除 fixed 定位、drag、resize 与 viewport clamp。
- `VideoTrackerPanelContent` 保留传播配置、种子、进度、范围和提交 UI，移除 overlay 定位、drag、resize 与 parent rect clamp。
- v0.25.2 的正常路径只渲染 registry 内容；浏览器中的旧坐标 key 保留到本 minor 结束，但新构建不保留无调用的读取 / 写入 helper 或已被替代的 drag / resize adapter。前端版本回滚依靠旧构建，不依赖同一构建中的双壳。

`VideoTrackerReviewBar` 和其余 modal 继续留在 `WorkbenchShell.stageOverlay`。把 review bar 移入可隐藏 panel 会改变画布锚定和验收流，不在本版范围。

## 6. 快照、预设与旧坐标隔离

### 6.1 快照规则

v0.25.2 sanitizer 读取 v1 / v2 后保留既有结构，写入时升级为 v3；v3 继续执行：

- mode / stageKind 结构 allowlist、64 KiB 和节点上限；瞬时权限 / 能力状态不得参与节点删除。
- 删除所有业务 `params`，拒绝 popout、非有限尺寸和重复 panel。
- 浮窗矩形按 `WorkbenchDockWorkspace` client rect 夹取。
- 恰好一个 canvas；本版同时兼容 v0.25.0 的固定中心 canvas 与 v0.25.1 的合法非中心 canvas。
- 每个可选工具 panel 保存 `visibilityIntent` 与 parking return descriptor；能力不可用时允许 runtime dormant，但序列化结果必须保留节点及返回位置。
- 旧 v1 / v2 标签页向已存 v3 context 写入时，后端返回 `409 layout_schema_downgrade`；旧 writer 切换只读且不得重试、裁剪或覆盖 v3。

快照不得包含 AI backend、model、threshold、pipeline、候选、tracker source、seed、range、job ID、进度、currentTime、播放态或 review 结果。

### 6.2 旧坐标隔离与回滚

旧 key `wb:ai-popover-position` / `size` 与 `wb:video-tracker-panel-position` / `size` 是浏览器级全局值，没有 `userId`、mode 或 stageKind，无法证明由当前登录账号创建。为避免把账号 A 的界面偏好上传给账号 B，本版选择不迁移：

1. 新构建不读取这些 key，不把它们放入本地 workspace cache，也不经 preferences PATCH 上传。
2. `ai-task` / `video-tracker` 首次显示使用当前 context 的确定默认停靠位置；用户第一次移动后，由 v0.25.0 writer 正常保存账号级快照。
3. 切换账号、context、设备或清空 workspace 时，旧 key 都不能改变新 panel 的位置或可见性。
4. 整个 v0.25.x 不调用 `removeItem` 删除旧 key，也不继续更新它们；回滚到旧构建时仍恢复升级前最后坐标。
5. 若未来确需迁移，必须先有可验证的 owner 元数据并单独评审；本版不增加猜测式归属或迁移标记。

### 6.3 新增预设

| 预设         | context                                                  | 一次性空间结果                                                                    | 必须保持                              |
| ------------ | -------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------- |
| 图片 AI 审阅 | `annotate:image`、`review:image` 且 `ai-task` 可用       | canvas 可见；`ai-task` 与 inspector 同组，讨论停靠底部，任务 / 类别作为次级 panel | 候选、配置、选中、工具、未提交标注    |
| 视频追踪     | `annotate:video`、`review:video` 且 `video-tracker` 可用 | canvas 与 tracker 并排，inspector 作为相邻 tab，时间线保持可操作                  | job、种子、范围、帧、播放态、轨迹草稿 |

能力不满足时对应预设从菜单隐藏，不生成残缺树。应用预设使用 runtime move / visibility API，保留现有 panel 实例；成功 toast 提供一次会话级撤销。

顶层“布局”菜单可列出 3D 既有“框体精修 / 传感器融合 / 点级分割”入口，但调用仍交给 `ThreeDWorkbench`；顶层 snapshot 不读取或覆盖三视图、相机和 PSR 状态。

### 9.2 行为与故障矩阵

| 维度     | 必测合同                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------ |
| 单例     | 工具栏、预设和菜单连续打开只产生一个 panel / React 内容 / business session                       |
| 生命周期 | dock / tab / float / hide / restore 及瞬时能力失败不卸载草稿；权限撤销由 owner 清理后才卸载      |
| AI       | 配置、backend、threshold、pipeline、cold-start、候选和采纳路径不因布局改变                       |
| 视频     | currentTime、播放态、decoder / cache、seed、range、brush、track draft、job / review 不因布局改变 |
| 旧值隔离 | 注入正常 / 损坏旧 key，切换账号与 context；新 workspace 不读取、不上传且不删除旧 key             |
| 版本保真 | v1 / v2 陈旧标签页写已存 v3 得到 409；v3 panel、group、tab、位置与可见性均不被裁剪或覆盖         |
| context  | image / video / 3d × annotate / review；冷 / 热 dormant、权限撤销均不越权且返回位置不丢          |
| 布局     | 两组预设、撤销、冷恢复、固定 / 可移动 canvas；紧凑能力恢复不改锁存树且退出后再恢复桌面位置       |
| 交互     | 表单与 tab 焦点快捷键隔离，拖动不点中画布，所有 drag 有菜单等价操作                              |
| 视觉     | 1366×768、1920×1080、`<=1024px`、light / dark、浏览器缩放、浮窗层级与最小尺寸                    |

### 9.3 发布阻断条件

- 任一入口可创建重复 `ai-task` / `video-tracker`，或重复发起 AI / tracker 请求。
- 隐藏、切 tab、应用预设或 layout hydrate 会调用业务 cancel、清空配置、种子、范围、候选或 job。
- tracker panel 变化重置 currentTime、播放态、decoder / bitmap cache 或轨迹草稿。
- AI panel 变化丢失 backend / config / threshold，运行中的 mutation 被取消，或采纳行为改变。
- 非 available panel 越权显示 / 发请求，或被 sanitizer / 同版本 writer 裁剪而丢失 dormant 节点、可见性意图或返回位置。
- 已挂载 panel 因 loading / 可恢复探测失败而卸载、清空草稿或取消 owner 请求 / job；或权威权限撤销后仍保留可交互内容与敏感组件状态。
- 紧凑模式中的能力恢复创建桌面 sibling、执行桌面返回描述或改写锁存模型；退出后漏执行 pending 恢复，或用户紧凑 hide 后仍自动恢复。
- v1 / v2 客户端能覆盖 v3 context，或旧客户端过滤 `ai-task` / `video-tracker` 后仍写回布局。
- 重复 panel 快照被“保留第一项”而非整树拒绝，或首次打开使用不确定的“最近 group”。
- 预设运行时使用整树 `fromJSON` 并重建 Stage，或 v0.25.1 未发布时布局无法工作。
- Dockview pointer 泄漏到 canvas、输入控件触发标注快捷键、紧凑模式覆盖桌面快照，或关键提交入口不可达。
- 3D 顶层菜单改写内部三视图 / 相机 / PSR 状态，或 review / modal overlay 被意外纳入 panel。

## 10. 成功指标

1. 用户从任意现有入口一次操作即可显示或聚焦唯一 AI / tracker panel，并能用拖放或菜单调整位置。
2. “图片 AI 审阅”和“视频追踪”预设一键形成可工作的空间，撤销精确回到应用前布局。
3. 连续 20 次显示、隐藏、dock、tab、float 和预设后，AI / tracker session、视频资源和 Stage mount 计数保持。
4. 新 panel 第一次进入时使用确定默认位置；能力 loading / 不可达 / 恢复不丢已挂载实例、`visibilityIntent` 和返回位置，紧凑期间不改锁存树；任何旧全局 frame key 都不影响账号 workspace、不上传且不被删除。
5. 本版不新增 API / 数据库 / 依赖，不改变 AI / tracker mutation 数量和 payload。

## 11. 最脆弱假设、失败路径与回滚

本版最脆弱的假设是：两个大浮层的配置 / session 能在不改变业务 owner 的前提下拆成无定位内容，并可由 `renderer: "always"` 在隐藏 tab 中保留，而其副作用不会依赖 `position: fixed` 或“可见即业务打开”。

实施 Slice A / B 时分别先做组件生命周期探针。v0.25.2 的发布合同包含两个 panel，不做静默部分发版。若某个面板无法解耦空间可见性与业务取消：

- 该 panel 保留旧浮层实现，不为统一外观上移 job、候选或 tracker session。
- 对应新预设不发布；另一个已通过的切片可保留为可审查提交，但不得单独打 v0.25.2 标签。
- 在 ADR-0072 记录未迁移原因和保持旧 owner 的边界，不留下双壳同时写坐标。
- 若要把已通过切片单独发布，必须先更新父 Epic、另建明确版本计划并重新审批；否则从发布分支撤回该切片，继续使用两个旧浮层。

回滚前端到 v0.25.0 / v0.25.1 后，客户端看到 v3 会显示只读“标准标注”临时布局并提示升级，不过滤或写回两个新 panel；服务端 v3 原树完整保留。旧 frame key 未删除，若回滚构建启用旧 AI / tracker 浮层，它们回到升级前最后坐标。重新部署 v0.25.2 后恢复原 v3 布局，无数据库清理或后端部署顺序要求。
