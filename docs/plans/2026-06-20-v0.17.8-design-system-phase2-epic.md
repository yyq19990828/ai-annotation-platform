## 1. 背景与目标

### 1.1 为什么做(承接 Epic 收官)

shadcn 迁移把视觉从「CSS Modules + tokens.css」搬到了「Tailwind + shadcn token」,但搬运过程产生了一类**新债**:大量设计决策(状态色、字号、层级)是逐处写成 className 里的**任意值 / 重复字面量**,没有进入 token / scale 层。

Epic §1.1 的痛点是「双套暗色靠人工纪律」。迁移后纪律的载体从 `var(--color-*)` 变成了 className 里的 `text-rose-600 dark:text-rose-400` / `text-[11px]` / `z-[1000]` —— **本质问题(无单一真值源约束,靠每个调用点自觉)换了形态继续存在**。本阶段把它们收敛回机制层(altitude 修复:把 bandaid 提升到机制)。

> 这是 `/simplify` 审查 `UI-refactor` 分支(vs origin/main,489 文件)后的结论:迁移代码在死代码 / 复用 / 效率上是干净的,剩下的实质问题都是设计系统层面的散点决策,需独立有范围地推进。

### 1.2 现状盘点(实测计数,`apps/web/src`)

| 散点债 | 计数 | 现状 | 收敛目标 | 子计划 |
|---|---|---|---|---|
| 状态色暗色对 `dark:text-<hue>-(400\|300)` | **183**(rose 86 / amber 41 / violet 26 / emerald 25 / sky 4) | 每处手写 light/dark 两条 | 语义工具类 `text-status-*` | v0.17.8 |
| badge 软底 `bg-<hue>-500/10` | **68**(rose 22 / amber 20 / violet 14 / emerald 11) | 与上成对手写 | `bg-status-*-soft` | v0.17.8 |
| 任意字号 `text-[Npx]` | **734**(11px×290 / 13px×216 / 10px×61 / 11.5px×56 / 12.5px×47…) | 每处拍一个 px,无梯度 | 命名字号 scale | v0.17.9 |
| z-index `z-NN` / `z-[N]` | 无标尺(z-50×18 / z-[1000]×6 / z-60 / z-61 / z-[201] / z-[55]…) | 各浮层各猜一层 | 语义 z 标尺 | v0.17.10 |
| 任意 padding `p?-[Npx]` | **157** | 一次性像素值 | 归并 Tailwind spacing | v0.17.10 |
| 局部 `const *_CLASS` | **207** | 各文件本地常量(迁移既定约定) | 仅抽真 verbatim 跨文件复用 | v0.17.11 |
| `cssVarToHex` per-render(画布层) | 2 层 | 每帧 `getComputedStyle` 样式重算 | `useTheme`-keyed memo | v0.17.11 |

### 1.3 终态成功判据

1. 状态色 / 字号 / z-index 全部走 token / scale / 语义类;新增调用点不再出现裸 `text-<hue>-600` 对、`text-[Npx]`、裸 `z-[四位数]`。
2. `check-tw-tokens.mjs` 增「禁任意字号」「禁任意 z」规则(warning→blocking,沿用 Epic §4 范式)。
3. 行为零回退;亮 / 暗双主题 Playwright 截图基线全绿;`pnpm lint && pnpm typecheck && pnpm test` 全绿。

### 1.4 红线(贯穿全程,各子计划默认继承)

- **默认 = 现状**:token / scale 取值**精确等于**当前实际呈现值,先做等价替换,不顺手调视觉;刻意微调单独拎出、单独过截图。
- **逐版本独立可上线**:每版本一类散点债,互不阻塞,出问题停在该版本。
- **截图把关**:状态色 / 字号是全站性改动,回归面广,严格走亮暗双基线。
- **不碰画布渲染逻辑**:沿用 Epic 红线;唯一画布相关项是 `cssVarToHex` 的**读取时机**(v0.17.11),不动渲染。
- **尊重迁移既定约定**:207 个局部 `*_CLASS` 是迁移有意的一致约定,**不**为消重批量改共享模块;只抽极少数真 verbatim + 有自然归属者。

## 3. 关键决策记录

- **2026-06-20 · 状态色语义化范式 = 路线 A(语义工具类)**。在 `shadcn.css` 把状态色真正 token 化并映射出 `text-status-*` / `bg-status-*-soft` 工具类,className 一处定义暗色;放弃路线 B(共享 TS tonemap)。细则见 v0.17.8 子计划。
- **2026-06-20 · 字号命名 = 方案 A(沿用 Tailwind 名并覆盖默认值)**。在 `@theme inline` 重定义 `--text-xs: 11px` / `--text-sm: 13px` + 新增 `--text-2xs: 10px`,调用点用标准 `text-xs/sm`。**已知代价**:`components/shadcn/ui/` 等 vendored 组件内部的 `text-sm/xs` 会一并收紧一档(期望 14/12 → 实得 13/11),需纳入 v0.17.9 截图回归。细则见 v0.17.9 子计划。
- **待定(v0.17.8 内子决策)**:现有语义 `--sc-destructive`(#dc2626,red 系)与散点实用的 `text-rose-600`(rose 系)**并非同色**。本阶段「默认=现状」→ 状态 token 取 **rose/amber/emerald/violet** 真值;「red/rose 两套近义状态色是否统一为一套」是更深决策,记入待定、**不**在本阶段强行合并。
