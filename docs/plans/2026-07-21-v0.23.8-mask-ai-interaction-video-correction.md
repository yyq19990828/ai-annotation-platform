## 1. 基线、目标与成功定义

v0.23.7 已完成共享 RLE 内容层、图片 `raster_mask`、图片 / 视频共用 renderer、对象级错误隔离、
图片创建 / 重载 / 再编辑和显式双向转换。当前交互 SAM 已支持正负点、多候选和 low-resolution
logits 回灌，但图片与视频单帧候选仍先被 polygon 化；视频 Tracker 已有原生 Mask staged result、
源版本冲突保护和整 job 接受 / 丢弃，但不能只接受或重算某个目标的局部窗口。

本版本成功必须同时满足：

- 图片与视频单帧 SAM 可显式请求原生 Mask，候选、预览、接受与刷新保持逐像素一致。
- 已存 Mask 可作为下一轮 prompt，并可叠加正 / 负点、框与 scribble；网络失败不清空会话。
- Tracker 候选可按目标和帧窗口接受 / 拒绝；人工纠错可只保存关键帧或按方向重传播。
- 服务端在接受和重传播边界复核任务权限、写入能力、源 annotation version、segment lease 与
  manual keyframe 保护，冲突稳定返回 409，不使用 last-writer-wins。
- backend `/setup` 声明与真实请求 / 响应一致；不支持原生 Mask 时只允许显式 polygon fallback。
- 每个 AI 结果保留实际 backend instance / requested pool、模型、prompt 摘要、输出几何、源版本、
  fallback 和人工修正 lineage，普通日志不写完整图片、RLE counts 或 logits。

## 2. 冻结合同

### 2.1 Capability truth 与兼容规则

- capability registry 的 prompt 受控值包含 `point`、`interactive_box`、`mask`、`scribble` 和
  `correction_frame`；共享 protocol mirror、snapshot、生成类型和文档必须同源更新。
- backend 只有对应代码路径通过 contract test 时，才能在相关 `models[]` 条目声明：
  - `supported_geometric_outputs` 含 `mask`；
  - `supported_prompts` 含 `mask` / `scribble` / `correction_frame`；
  - `supported_inputs` 含本版本新增的 `mask_prompt` / `scribble_prompt` / `video`。
- `mask` 是共享 COCO RLE 二值提示；`scribble` 是正 / 负二值笔迹提示；`correction_frame` 是
  视频纠错种子，不等同于单帧图片 prompt，也不能借 `bbox` 名称伪装。
- `point` / `interactive_box` / `mask` / `scribble` 请求显式携带
  `context.output_geometry = "mask" | "polygon"`。新工作台在能力允许时传 `mask`；旧客户端或
  缺字段请求继续按 polygon 兼容，避免旧 reader 意外收到新 shape。
- 请求 `mask` 而目标 model 未声明 `mask` 时，平台在调用 backend 前返回稳定
  `unsupported_output_geometry`，并附 `supported_geometric_outputs`；前端可由用户明确切到 polygon，
  不自动静默回落。
- `/setup` 顶层能力仍是 `models[]` 的受控并集；不能用 tracker 支持 `mask` 推导图片
  interactive model 也支持 `mask`。

### 2.2 单帧原生 Mask wire contract

- 原生候选使用现有非压缩 COCO RLE 规范，row / column-major 转换统一走共享 codec：

  ```json
  {
    "type": "mask",
    "value": {
      "rle": {
        "encoding": "coco_rle",
        "size": [1080, 1920],
        "counts": [42, 8, 190, 12]
      },
      "masklabels": ["object"]
    },
    "score": 0.97,
    "candidate_id": "sha256:<digest>"
  }
  ```

- `candidate_id` 由 canonical RLE digest、prompt revision 与候选序号稳定派生，仅用于会话幂等和
  诊断；它不是可读取的对象 key，也不授权跨任务访问。
- 空前景返回 `result=[]` 和稳定 `empty_mask` diagnostic；视频 Tracker 的空帧继续使用
  `outside=true`。不得返回零 bbox、空 polygon 或全图占位 geometry 冒充 Mask。
- multimask 每个候选分别编码完整像素，score 只控制展示顺序，不改变 RLE counts；hole、孤岛和
  多连通区域不再经过 `pickPrimaryRing` 或 simplify。
- 候选 RLE 只存在于受限 HTTP 响应和浏览器当前 session；未接受候选不写不可变内容对象、
  Prediction 或 Annotation。切题、取消、prompt revision 变化或 session TTL 到期即释放；
  服务端 / 浏览器 cache 都必须有字节预算和 TTL，不能只按候选数量限流。
- 单候选 canonical RLE、整个候选响应、mask prompt、scribble payload 和 logits 分别执行前置上限；
  沿用图片 Mask 的 4096×4096、16M 像素、1,000,000 runs、4 MiB canonical object 红线，
  整个交互响应最大 16 MiB，超限返回 413 + 稳定 reason。

### 2.3 接受、持久化与 lineage

- 前端接受原生候选时不自行拼两次独立 mutation，而调用任务级 AI Mask accept API，提交：
  `candidate_id`、选中候选 RLE、类别、prompt summary、实际 backend / pool / model、
  inference metadata、source annotation id / version（如有）和客户端 idempotency key。
- 服务端重新验证 RLE、任务媒体尺寸、有效 Raster Mask 写闸、类别、assignment / task 状态和锁；
  对已有 Mask 精修还必须用 `If-Match` / source version 复核。
- 服务端先写不可变 RLE；随后在单个数据库事务中创建或更新 Prediction / PredictionMeta、写入
  接受 decision、创建或更新 Annotation、关联 `parent_prediction_id` 与内容引用，并记录审计。
  DB 事务失败时不可变对象保持 orphan，由既有宽限期 GC 回收；不能留下半个 Prediction 决策。
- 同一个任务 + idempotency key + candidate digest 重试返回同一结果；同 key 不同 digest 返回 409。
- 图片新建结果是 `raster_mask`；视频单帧接受不新增 `video_mask`，而是创建或更新
  `video_track_mask` 的当前帧 manual / prediction keyframe。
- 接受响应返回 Prediction、Annotation、source / result version 与内容 digest；前端只有收到成功响应
  才清候选和 prompt。网络错误保留当前 Mask、笔迹、候选与 idempotency key，重试不得重复标注。

### 2.4 Mask-as-prompt、scribble 与 logits

- 已存 `raster_mask` 或 `video_track_mask` 当前帧可作为 `context.mask_prompt`：服务端读取并鉴权后
  将受控 inline RLE 转给 backend，客户端不能提交任意 object key 让 backend 读取。
- Mask prompt 可以叠加 point、interactive box 或 scribble；prompt revision 包含源 digest、
  source annotation version、点 / 框 / 笔迹和模型参数。任一变化只使当前候选失效，不修改已存 Mask。
- scribble wire 形状固定为归一化折线，不传整幅 bitmap：

  ```json
  {
    "type": "scribble",
    "scribbles": [
      {
        "polarity": 1,
        "points": [
          [0.1, 0.2],
          [0.2, 0.25]
        ],
        "width": 0.008
      },
      {
        "polarity": 0,
        "points": [
          [0.4, 0.3],
          [0.45, 0.35]
        ],
        "width": 0.008
      }
    ],
    "output_geometry": "mask"
  }
  ```

- 坐标必须有限且位于 `[0,1]`；单条至少 2 点。每请求最多 64 条、8,192 点、2,000,000 个
  rasterized prompt pixels、512 KiB JSON。线宽归一化后在 backend 依据原图尺寸栅格化。
- backend 若底层只接受 point / mask input，可在 backend 内将 scribble 采样 / 栅格化为模型输入，
  但 `/setup` 只有在该适配通过正负笔迹 consumer test 后才声明 `scribble`。
- `mask_input_next` low-resolution logits 继续作为不透明短生命周期 token，只绑定当前 task / frame、
  backend、model、prompt revision 和候选。不得写数据库、对象存储、普通日志或跨帧复用；取消、
  接受、切题、切帧、切模型和 TTL 到期都释放。

### 2.5 视频候选局部决策

- Tracker preview 为每条 result 暴露稳定 `candidate_key = instance_id + frame_index + digest`、
  source / target annotation、frame index、outside、confidence、geometry digest 与是否 manual-protected。
- accept / reject 请求使用显式选择器：
  - `instance_ids[]`：目标集合；
  - `from_frame` / `to_frame`：闭区间；
  - `decision = accept | reject`；
  - `expected_source_versions` 与 job revision。
- 第一次局部决定后 job 进入 `partially_reviewed`，staged result 保留未决集合；全部候选决定完后才进入
  `accepted` / `discarded`。同一 `candidate_key` 重复同决策幂等，反向改判必须创建新审计事件。
- 接受只把所选目标 / 帧窗口合并到 Annotation；拒绝只移除 staged 选择。窗口外、其它 instance、
  其它轨迹和未决候选保持字节级不变。
- manual keyframe 默认不可被候选覆盖。请求命中人工帧返回 409
  `manual_keyframe_protected`；只有 `override_manual=true` 且当前用户具备编辑权限并再次确认时允许，
  审计必须保存 before / after digest、帧、actor、job 和 source version。
- 所有局部 decision 在事务内锁 job、task、segment 与受影响 annotations，复核源版本后再写入；
  job revision 或源 version 漂移返回 409，响应给出冲突对象和当前版本。

### 2.6 局部纠错与重传播

- 在 `video_track_mask` 当前帧进入共享 Mask editor，保存时写一个 `source="manual"` 的纠错关键帧；
  用户可选择：仅保存、向前、向后、双向重传播。
- 重传播使用独立 correction job，输入冻结为：目标 annotation / track、纠错帧、窗口、方向、
  corrected RLE digest、源 annotation version、backend / pool / model、segment lease 和
  `protect_manual=true`。同一 track 同时只允许一个 active correction job。
- backend 支持 `correction_frame` / `mask` 时优先传 corrected RLE；支持同 session logits 时可在本次
  job 内使用，但不持久化。backend 不支持 Mask seed 时只有用户确认后才转 bbox fallback，并把
  `fallback_reason=mask_prompt_unsupported`、seed digest 和 bbox 写入 lineage。
- correction job 只产生所选窗口、所选目标的 staged candidate，不直接覆盖 annotation；继续走
  局部 preview / accept / reject 和 manual 保护。取消保留已经保存的纠错关键帧，丢弃 staged 结果。
- 重传播接受后 Annotation version 单调递增；窗口外 keyframe / outside / occluded 段和其它轨迹
  不变。direction 不得越过请求窗口或 segment 边界。

### 2.7 可观测性与隐私

- 低基数指标记录：operation（single-frame / refine / correction）、prompt family、output geometry、
  candidate count bucket、decision、fallback reason、outcome，以及 decode / inference / encode /
  upload / commit duration。不得把 task、annotation、object key、candidate digest 放进 label。
- 结构化审计可记录 backend / pool / model、受影响对象、窗口、源 / 结果 version、digest、prompt 计数、
  fallback 和 before / after；普通应用日志不记录图片正文、RLE counts、scribble 点集或 logits。
- UI 必须同时展示目标 model 的 Mask / prompt 能力、当前输出类型、fallback 原因和是否会保护人工帧；
  polygon fallback 不得使用“原生 Mask”文案。

## 4. 非目标

- 不实现文本到全场 semantic class-map 或 panoptic 合成。
- 不做自动光流 / morphing；跨帧序列仍由 backend Tracker 产生。
- 不实现套索、形态学、连通域拆并、非重叠绘制或批量几何转换；这些属于 v0.23.9。
- 不实现 5K / 8K tile editor 或大画布性能重构；这些属于 v0.23.10。
- 不持久化 logits，不建立长生命周期 SAM inference state 服务。
- 不自动覆盖 manual keyframe，不让前端本地 patch 绕过服务端 decision / version / lock。
- 不把图片 `raster_mask` 和视频 `video_track_mask` 合并为一个 geometry，也不新增 `video_mask`。

## 5. 浏览器与发布验收场景

1. 图片单个正点产生三组原生 Mask 候选，Tab 切换不改变像素；接受后 hole 与三个小岛保持。
2. 已存图片 Mask + 负点 + 负 scribble 去除错误区域，保存、刷新和再次读取逐像素一致。
3. Backend model 不支持 Mask 时，UI 显示稳定原因并由用户切到 polygon；数据库不生成
   `raster_mask` 假结果。
4. 视频当前帧 SAM 创建 `video_track_mask` keyframe，可继续以该 Mask 启动 Tracker。
5. 网络在接受响应前中断，候选与 prompt 保留；用同 idempotency key 重试只产生一个 Prediction
   decision 和一个 Annotation mutation。
6. Tracker 对两个实例、20 帧候选只接受实例 A 的 F10–F15；实例 B 与 A 的窗口外 staged / annotation
   均保持不变，之后可继续决定剩余候选。
7. Tracker 某帧漂移 → 人工修正 → 向后重传播 → 接受所选窗口，只替换该目标窗口。
8. manual keyframe 默认保护；显式覆盖必须二次确认并产生 before / after 审计。
9. 同一轨迹并发 correction job、源 annotation version 漂移和 segment lease 变化均返回稳定 409，
   刷新后可恢复，不出现部分写入。
10. 取消 correction job 保留已保存的人工纠错帧，释放 staged 候选与临时引用。
11. 未接受的单帧候选在取消 / 切题 / TTL 后无内容对象泄漏；Tracker staged Mask 在决定 / TTL 后由
    引用扫描与 GC 正确保留或回收。
12. grounded-SAM2、SAM3 image、SAM3 multiplex、SAM3 PVS 的 `/setup` 与实际 Mask consumer 输出一致。

## 6. 退出门

v0.23.9 进入前必须有直接证据证明：

- M0–M6 均有独立验证记录和独立提交，工作区无本版本遗留未提交修改。
- 三类 backend capability 声明与实际输出一致；单帧 AI 在 Mask 模式不再强制矢量化。
- candidate 与 committed annotation 逐像素一致，多轮 Mask / scribble 会话失败可恢复且无重复提交。
- 局部 decision 与 correction job 不覆盖窗口外、其它轨迹或受保护 manual keyframe。
- 单帧候选、Tracker staged refs 与 logits 生命周期无泄漏，日志 / 指标不包含敏感正文或高基数标识。
- 12 条浏览器场景全绿，后端 / 前端 / OpenAPI / 文档 / backend 包 / 迁移 / 运行态版本全量门禁通过。
