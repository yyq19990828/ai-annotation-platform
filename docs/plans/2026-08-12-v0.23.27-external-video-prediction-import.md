>
> 上游：[macOS 视频工作台资格验收与下版收口](2026-08-12-v0.23.26-macos-video-workbench-qualification.md)

> 路线：[视频工作台路线](../../ROADMAP/2026-05-21-video-workbench-roadmap.md)

## 1. 目标

让项目管理员通过现有“导入预测”入口，把 AAP JSON 中的视频 bbox 和 bbox / polygon / polyline / mask
轨迹作为 `Prediction` 候选导入视频工作台；标注员逐帧查看、接受或驳回后，才形成正式
`Annotation`。

本版完成时必须打通以下用户链路：

1. `dry_run` 能校验视频任务、帧范围、几何与 mask 对象，不写数据库或对象存储；
2. 正式导入写入 `source=external_import` 的候选，不直接写正式标注；
3. 视频工作台按当前帧解析并绘制候选，bbox / polygon / polyline / mask 都可见；
4. 现有单条接受、驳回、来源过滤、置信度过滤与预测密度导航继续工作；
5. 接受后生成同类型视频 Annotation，并保留轨迹身份、outside、置信度和候选溯源。

## 2. 范围与非目标

### 2.1 本版范围

仅扩展 AAP JSON `tasks[].predictions[]`，支持：

- `video_bbox`；
- `video_track_bbox`；
- `video_track_polygon`；
- `video_track_polyline`；
- `video_track_mask`，正文继续由 AAP JSON 1.3 的 `mask_objects` 携带。

### 2.2 非目标

- 不扩展 COCO / YOLO 的视频语义；
- 不消费 `annotations[]`，现有标注导入 API 继续独立；
- 不支持视频单帧 polygon / polyline / mask 或 rotated bbox / keypoint 预测；
- 不新增数据库表、迁移、AAP schema 版本或第二个导入向导；
- 不做批量自动接受、tracker 执行、轨迹合并或跨 task Re-ID；
- 不为 mask 暴露对象存储 key 的直读能力。

## 3. 已确认现状

- AAP JSON 1.3 已能表达所有目标 Geometry 和 portable `mask_objects`，无需升 schema。
- 预测导入当前把图片内部 Geometry 转成 Label Studio shape；视频 Geometry 在
  `internal_geometry_to_ls_shape()` 末尾被明确拒绝。
- `PredictionService.to_internal_shape()` 已对含 `geometry` 的内部 shape 直接透传，接受预测也已复用
  mask 写入门和 compact track identity。
- 后端 `_tool_unit_from_internal_geometry()` 已识别视频 bbox / mask，但遗漏视频 polygon / polyline 单位。
- 前端 `predictionsToBoxes()` 已能携带任意已知 Geometry；候选帧解析和 Konva 候选层目前只正确处理
  `video_bbox` / `video_track_bbox`。
- 已落库 Annotation 的 polygon / polyline / mask 轨迹已有逐帧解析、插值、RLE 解码、缓存和像素命中逻辑，
  本版应复用这些路径。

## 4. 实现决策

### 4.1 写入仍是 Prediction 候选

AAP JSON 视频 Geometry 不绕回 Label Studio 百分比结构，而是写成现有内部 prediction shape：

```json
{
  "type": "video_track_polygon",
  "class_name": "car",
  "geometry": { "type": "video_track_polygon", "track_id": "trk_...", "keyframes": [] },
  "confidence": 0.91,
  "tool_unit_id": "region",
  "attributes": {}
}
```

图片 Geometry 继续走当前适配器，不做相邻重构。`PredictionService.create_from_ml_result()`、现有列表 API 和
接受 / 驳回端点保持单一写入与审阅路径。

每个视频 shape 的工具单位固定为：bbox → `bbox`，polygon / mask → `region`，polyline → `polyline`。
同一 `predictions[i].shapes[]` 若混合不同工具单位，整条 entry 进入 `errors[]`，避免一条 Prediction 的行级
`tool_unit_id` 与部分 shape 不一致。

### 4.2 信任边界与帧合同

所有目标视频 Geometry 在写入前必须通过现有 `Geometry` TypeAdapter，并额外验证：

- 命中的 Task / DatasetItem 必须是 video；task block 的 `media_type` 必须为 `video`；
- 单帧和所有 keyframe 的 `frame_index` 必须小于源视频 `frame_count`；
- outside range 必须合法且位于视频范围内；
- track keyframe 严格递增且不重复；
- 导入候选的 keyframe / outside `source` 归一为 `prediction`，不接受外部文件冒充人工来源；
- mask 继续复用尺寸、摘要、空前景、写入 gate、配额和 `mask_objects` 内容校验。

缺少 `frame_count` 时拒绝该 task block 的视频预测，不新增 warnings 协议或猜测范围。逐 shape 错误保持现有
best-effort 语义，但单条 entry 内通过的 shapes 必须属于同一工具单位。

### 4.3 当前帧候选渲染

扩展现有 `aiBoxFrames` 单一入口：

- bbox track 继续使用 `resolveTrackAtFrame()`；
- polygon / polyline track 复用 `resolveVideoPolygonTrackAtFrame()` /
  `resolveVideoPolylineTrackAtFrame()`，返回当前帧 points 和 AABB；
- `collectPredictedFrames()` 收集所有目标类型的单帧或关键帧索引；
- outside 帧返回 `null`，侧栏当前帧计数、画布、快捷键与预测密度使用同一判定。

`VideoKonvaAiLayer` 在现有虚线候选样式内增加 `Line` 渲染：polygon 闭合、polyline 开放；bbox 继续使用
`Rect`，不建立第二套候选组件。

### 4.4 Mask 候选内容读取

增加一个 task-scoped、鉴权的只读端点，按 `prediction_id + shape_index + frame_index` 返回该候选当前帧的
COCO RLE。端点必须验证 Prediction 属于 URL 中的 Task、shape 是 `video_track_mask`、该帧可见，并只读取
Geometry 已引用的内容地址；不接受客户端传 object key。

前端把 mask prediction 作为 `useVideoMaskFrames()` 的第三种 descriptor，复用既有 RLE decode、裁剪、缓存、
真实像素命中和 `VideoKonvaMaskLayer`。record id 使用现有 AI box id，使画布选中、侧栏选中和接受 / 驳回
继续使用同一 `(predictionId, shapeIndex)`。

## 6. 实施顺序与验收

### 步骤 1：后端导入与接受闭环

- 增加五种视频 Geometry 的校验与内部 shape 写入；
- 补齐 tool unit 派生和同 entry 单位约束；
- 复用 portable mask 对象写入；
- 导入后逐类型调用现有 accept endpoint。

验收：每种类型 `dry_run` 无副作用，正式导入返回候选，接受后 Annotation Geometry exact；越界帧、图片任务、
混合工具单位、坏 mask 引用只进入明确错误且不留下孤儿对象。

### 步骤 2：当前帧候选可视与可选

- 扩展 polygon / polyline 逐帧解析和 Konva 渲染；
- 增加 mask candidate 内容读取、缓存与像素命中；
- 保持当前帧计数、快捷键和预测密度同源。

验收：关键帧、插值帧、outside 帧分别显示正确；bbox / polygon / polyline / mask 均能从画布或 AI 面板选中，
接受 / 驳回单个 shape 不波及同 Prediction 的其他 shape。

### 步骤 3：真实用户链路与文档

- 用一份包含四种轨迹的 AAP JSON 在视频项目执行 dry-run → import → 工作台审阅；
- 接受一条、驳回一条、刷新后核对候选和 Annotation；
- 更新导入指南、候选审阅说明和路线图。

## 7. 回滚与风险

- 无迁移；回滚 importer 分支、只读 mask endpoint 和候选渲染即可，既有图片预测不受影响。
- 最大风险是 mask candidate 的 RLE 下载量；先复用当前 96 项 LRU 和逐帧 descriptor，不增加预取。只有实测切帧
  产生请求瓶颈时再设计相邻帧预取。
- 第二风险是 `shapes[]` 行级 tool unit；本版明确拒绝混合单位，不为兼容少数 payload 改 Prediction 数据模型。
- Edge / Safari 兼容资格与本功能分开记录，不把 Chrome 功能 E2E 外推为浏览器矩阵通过。

## 8. 实施结果

- AAP JSON 预测导入已支持目标五种视频 Geometry，复用现有 Prediction、Mask 存储和接受 / 驳回路径；未新增 schema、迁移或依赖。
- 视频候选已复用既有逐帧解析、Konva 层、Mask 解码缓存和像素命中，当前帧计数与预测密度使用同一可见性判定。
- 后端定向测试、前端逐帧与渲染测试，以及系统 Chrome 的 dry-run → import → 工作台选择 → 接受 / 忽略 → 刷新 E2E 均通过。
