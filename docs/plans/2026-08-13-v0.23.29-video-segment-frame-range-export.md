# v0.23.29 · 视频 Segment / Frame Range 聚合导出

> Status: implemented · 2026-08-13
>
> 路线：[视频工作台路线](../../ROADMAP/2026-05-21-video-workbench-roadmap.md) Phase 4.6。
>
> 本版只完成范围导出；长视频 overlap 协同、可恢复 tracker context 与 Track 级质量指标继续拆版。

## 1. 现状与问题

当前导出链已经具备项目 / 批次级异步任务、缓存、预检、Video JSON / AAP JSON，以及 MOT、KITTI、
YOLO Frames、COCO Frames、DAVIS、YouTube-VOS、MOTS 等视频格式，但范围只有 project 或 batch：

- `POST /projects/{project_id}/export` 与 batch export 没有 task / segment / frame range 参数；
- `ExportService._load_data()`、`iter_export_chunks()` 和视频打包器会读取范围内的整条视频；
- `VideoSegment` 已按 `DatasetItem` 保存连续的 `start_frame / end_frame`，工作台已有查询、claim、heartbeat、
  release API，但导出链没有消费它；
- 帧格式各自从完整 `frame_count` 建采样网格。若只在 Video JSON 层过滤，MOT / DAVIS 等目标仍会导出全片，
  预检、作业结果和实际文件也会失配。

本版必须把“选择范围”作为同一份合同贯穿预检、异步任务、缓存、查询、轨迹裁剪、格式打包和 manifest，
同时保持未传范围时的现有行为不变。

## 2. Delivered

视频项目导出新增两种单 task 范围：

1. **按 Segment**：选择起始 segment 与结束 segment，自动聚合二者之间按 `segment_index` 连续的全部 segment；
2. **按 Frame Range**：选择同一 task 内的闭区间 `[from_frame, to_frame]`。

范围适用于项目导出与批次导出 API，并覆盖当前全部视频导出目标。Dashboard 导出弹窗提供项目级默认与单视频范围
两种入口；批次导出本版只补 API 对称性，不新增第二套 UI。

完成标准：同一范围传给预检和正式导出后，任务、单帧标注、轨迹关键帧、outside、抽帧 manifest、文件帧号与估算
均指向同一批源帧；跨 segment 聚合按源 `frame_index` 排序，人工 / prediction 关键帧和 outside 来源不丢失。

## 3. Not building

- 不允许一次范围导出跨多个视频 task；不同视频的 frame 0 没有可合并语义；
- 不支持跳选不连续 segment；起止 segment 之间全部纳入，避免导出几何在缺口两端错误插值；
- 不做 segment overlap、多人 presence、通用写入门禁、IAA / IDF1；
- 不做 tracker backend session / context token；
- 不做 MOTA / IDF1 / HOTA worker 或时间轴质量定位；
- 不修改 `VideoSegment` 表、不拆 Task、不新增迁移或依赖；
- 不把打包器重构为“先序列化 Video JSON、再反序列化生成各格式”。各格式继续复用现有纯函数，只共享同一范围与采样帧集；
- 不改变完整项目 / 批次导出的输出结构、默认帧号或缓存语义。

## 4. 对外合同

### 4.1 可选请求体

保留现有 query options；project / batch export 的 POST 只增加可选 JSON 请求体。无请求体或 `scope` 为空时继续完整导出。
预检请求增加同形 `scope` 字段，前端必须把完全相同的 scope 同时发给预检与正式导出。

`scope` 固定包含 `task_id` 和一个可辨识 selection：

| selection  | 字段                                 | 语义                               |
| ---------- | ------------------------------------ | ---------------------------------- |
| `segments` | `start_segment_id`, `end_segment_id` | 两端均包含；相同 ID 表示单 segment |
| `frames`   | `from_frame`, `to_frame`             | 源视频帧闭区间，两端均包含         |

服务端在入队前完成规范化：

- task 必须属于当前 project；batch export 时还必须属于当前 batch；
- 仅视频项目接受 scope；图片 / 点云项目传 scope 返回 422；
- segment 必须属于该 task 的 `dataset_item_id`，起始 `segment_index <=` 结束索引；
- frame range 满足 `0 <= from_frame <= to_frame < frame_count`；
- Segment 模式解析出中间全部 segment，并折叠为一个有效 frame range；
- 规范化结果写入 async job payload、audit detail 和 worker opts；缓存继续复用现有 `options_digest`，无需新缓存表或新 key 参数。

### 4.2 输出范围元数据

仅部分导出增加 `export_scope`，完整导出不新增字段：

- Video JSON 顶层写 task、selection kind 与有效源帧闭区间；Segment 模式附所选 segment 的 id / index / 边界；
- AAP JSON 写入对应 task 的 `video.export_scope`；
- ZIP `manifest.json` 的视频条目写同一范围，并继续用 `grid_source_frames` 表达实际抽取源帧；
- 源视频的 `frame_count / fps / duration` 保留原始元数据，不伪装成裁剪后视频；选中帧数由 scope / grid 单独表达。

## 5. 范围与几何语义

### 5.1 单帧 Geometry

`video_bbox / video_polygon / video_polyline / video_rotated_bbox / video_keypoint / video_mask` 仅在
`frame_index` 落入闭区间时导出，Geometry 本身继续保存源帧号，不重置为 0。

### 5.2 Track 裁剪

新增一个无 DB 的共享裁剪函数，供 Video JSON、AAP JSON 和格式打包共同消费；输入原 Geometry 与闭区间，输出自包含的
裁剪 Geometry 或 `None`：

- 原始关键帧在范围内全部保留并按 `frame_index` 排序，包括被 outside 覆盖的关键帧；`source=manual | prediction`
  与 `occluded / attributes` 原样保留；
- outside 区间与选择范围求交，裁剪端点但保留 `source=manual | prediction`，再走现有同源区间规范化；
- 为每个可见子区间的首尾补边界状态，只有该帧没有原始关键帧时才合成。bbox / polygon / polyline 使用现有
  `resolve_track_at_frame()` 结果并标为 `interpolated`；mask 复用 resolved keyframe 的内容引用与原 source；
- 原始关键帧优先于同帧边界状态，按帧去重；整个范围内既无原始关键帧、outside 语义也无可见状态的 track 省略；
- `video_frame_mode=all_frames` 只展开有效闭区间内的源帧；`keyframes` 输出裁剪后的紧凑 keyframe / outside；
- flattened `keyframes[]` 从裁剪后 track 生成，不能再从原 annotation 单独生成第二份结果。

以上规则让“范围从两个原始关键帧中间开始 / 结束”时仍有自包含几何，也避免丢失范围内 prediction keyframe 或 outside。

### 5.3 AAP Predictions

AAP JSON 的 `annotations[]` 与 `predictions[]` 使用同一范围过滤。Prediction shape 转为内部 Geometry 后再裁剪；
范围外单帧 shape 省略，轨迹 shape 遵守同一关键帧 / outside 规则，避免预检与正式导出的对象数不一致。

## 6. 采样与专业格式

先从原视频全局采样网格派生，再过滤到有效闭区间；不以 `from_frame` 重新锚定采样。例如 `step=6`、范围 `5..15`
仍选择源帧 `6, 12`，而不是 `5, 11`。

过滤后的 `selected_source_frames` 是所有帧格式的唯一帧集：

| 输出                  | 部分导出帧号                                             |
| --------------------- | -------------------------------------------------------- |
| Video JSON / AAP JSON | 保留源 `frame_index`                                     |
| MOT                   | 选中采样帧密集重排为 1..N                                |
| KITTI                 | 选中采样帧密集重排为 0..N-1                              |
| DAVIS / MOTS          | 按现有 base 密集编号，manifest 保存源帧映射              |
| YouTube-VOS           | 保留裁剪后的紧凑 mask keyframe，再密集编号并保存源帧映射 |

现有 `source_to_grid()`、MOT / KITTI、YOLO / COCO、DAVIS / MOTS helpers 增加可选的已选源帧列表；缺省继续从
`frame_count + step` 计算，保证完整导出零行为变化。`fetch_frames.py` 继续消费 manifest，无需第二套脚本。

## 8. 前端交互

只在 video-track 项目的现有 `ExportModal` 增加“导出范围”：

- 默认“整个项目”，保持当前一键导出；
- 选择“单个视频范围”后，使用现有 task cursor API 分页加载视频 task，不一次拉完整项目；
- 选定 task 后二选一“按 Segment / 按帧”；
- Segment 模式复用现有 `videoTrackerApi.segments(taskId)`，用两个原生 select 选择起止段；
- Frame 模式使用两个原生 number input，最大值取 segment 列表末段的 `end_frame`；
- task / mode 变化时清空旧边界与旧 preflight；反向范围、缺边界或越界时前端即时禁用提交，服务端仍独立校验；
- 预检报告与正式导出调用共享同一个构造后的 scope 对象，不各写一套映射。

不新增通用 RangePicker、task 搜索组件或状态管理层。项目包含超过当前页的 task 时提供“加载更多”，复用现有 cursor。

## 12. 风险、脆弱假设与回滚

- **最脆弱假设**：当前 `VideoSegment` 对同一 dataset item 按 `segment_index` 连续覆盖视频，且不会在导出排队后重建。
  入队时把 segment 解析成确定的源帧闭区间并写入 job，worker 不重新按可变配置切段；若未来支持重建 / overlap，
  job 仍导出用户提交时看到的范围。
- 最大实现风险是不同格式自行重建采样网格造成帧号漂移。只允许一个 `selected_source_frames` 真值进入 helpers，
  manifest 回归逐项核对 source → output 映射。
- Track 边界状态可能把范围外关键帧的解析结果带入范围内，但不会携带范围外帧号；这是让裁剪轨迹自包含所必需的上下文，
  并由纯函数测试固定。
- 无数据库迁移。回滚可按 Phase C → B → A 逆序进行；旧客户端不发 scope，完整导出合同不变；已下载的部分导出包
  带源帧范围与映射，可独立解释。
