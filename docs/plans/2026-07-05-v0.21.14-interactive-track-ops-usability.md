# v0.21.14 · 交互式轨迹操作易用性收口（默认模型 / 快捷键 / 传播范围联动）

状态：**计划（2026-07-05）**。收口视频工作台**交互式轨迹操作**的一批易用性问题：AI 传播默认落在测试模型、
快捷键文案与实际绑定不符、传播范围盲填与时间轴脱节、两类「传播」概念易混、跳连/合并禁用无引导。
**纯前端**，不改后端 / schema / 传播 job 链路，无 alembic。

三个 UX 头脑风暴的第三个（交互式轨迹操作 + 「删 mock」）。**关键前提纠正**：交互操作里**几乎没有前端 mock
可删**——传播/跳连/合并/拆分/复制粘贴全部真实接后端 REST + WebSocket。唯一叫 mock 的是 `mock_bbox`，它是
**后端一个真实的测试用 tracker 模型**（不依赖 ML backend），问题不是「假数据」而是「被设成了默认值」。

WS3（传播范围接时间轴）**依赖 [v0.21.13 时间轴区间选择基建](2026-07-05-v0.21.13-timeline-range-select-chapters.md)**，
故排在其后。其余 WS 可独立先做。

## 动机（现状，逐条带证据）

### 断点 1 · AI 传播默认选中测试模型 `mock_bbox`
`stage/VideoTrackerPropagateDialog.tsx`：模型下拉 `TRACKER_MODEL_OPTIONS`（`:34-38`）含 `mock_bbox`（测试用，
后端跑一个不依赖 ML backend 的假框传播器）、`sam2_video`、`sam3_video`；`DEFAULT_TRACKER_MEMORY.modelKey =
"mock_bbox"`（`:52`）、`useState<string>("mock_bbox")`（`:144`）初值即 mock；`resolveTrackerDefaultModel`
（`:56-75`）仅当 `preferNonMockModel=true` 才优先真实模型，而该 flag 默认 `false`（`:137`）。
**后果**：用户打开 AI 传播对话框、不手动改模型，默认就跑测试模型、得到假框结果。这就是「删 mock」的真实靶点——
不是删前端假数据，而是**把默认切到项目绑定的真实模型 + 生产环境隐藏 mock 选项**。（传播 job / 进度 / WS /
结果全真实：`api/videoTracker.ts:45-55`、`hooks/useVideoTrackerJobs.ts:76-200`、`VideoTrackerJobBadge.tsx`。）

### 断点 2 · 快捷键文案与实际绑定冲突
浮卡与对话框标题都写「AI 传播 (Shift+T)」（`shell/selectionCard/VideoTrackCardContent.tsx:423`、
`VideoTrackerPropagateDialog.tsx:232`），但 `state/hotkeys.ts:79,243` 实际绑定是 **`Ctrl+B`**
（`videoPropagateTrack`）。文案对不上按键，属明显 UX bug。

### 断点 3 · 传播范围盲填、与时间轴脱节
传播范围只在对话框内以文字 `F{from} → F{to}` 表示（`VideoTrackerPropagateDialog.tsx:276-287`；关键帧传播
`VideoKeyframesPropagateDialog.tsx:161-172` 同样只有文字）。时间轴上**看不到「将影响哪段帧」**，也不能在时间轴
**刷选**一个 from/to 喂给对话框——而时间轴的区间刷选能力（loopRegion，v0.21.13 已泛化为通用区间选择）现成却
没接给传播。步骤上「选轨迹→开对话框→选方向→选范围预设→选模型→(可能再选 SAM 尺寸)→提交」至少 4~6 步、多层
对话框，全程盲算帧数。

### 断点 4 · 两个「传播」概念易混
浮卡上「AI 传播」（`VideoTrackerPropagateDialog`，后端 SAM job）与「复制后续」（`VideoKeyframesPropagateDialog`，
纯前端几何铺帧，`state/videoTrackCommands.ts:139-172`）并排（`VideoTrackCardContent.tsx:419-436`），
命名/图标（bot vs layers）对新用户区分度不够——一个真调模型、一个只复制框，代价与效果天差地别。

### 断点 5 · 跳连 / 合并禁用无引导
跳连/合并要求「恰好 2 条、同类、可见帧不重叠」（`stage/VideoTrackSidebar.tsx:194` `canJoin`、`:334-348`），
不满足时按钮 disabled 但**不说为什么**，用户不易判断为何点不动。

## 定稿决策（拟）

- **断点 1 → 默认模型换真实 + 生产隐藏 mock。**（这是「删 mock」的正解）
  - 默认优先项目绑定的真实 tracker 模型：`preferNonMockModel` 默认 `true`、`projectDefaultModel` 由上游注入
    （从项目已绑定的 ML backend 能力解析当前项目可用的 sam2/sam3 tracker）。
  - `mock_bbox` **不删后端模型**（测试仍需），但在**生产/已绑定真实后端的项目**里从下拉过滤掉（按 env flag 或
    项目能力）；仅测试环境保留可见。
- **断点 2 → 快捷键文案纠正。** 统一为实际绑定 `Ctrl+B`（改文案），或把绑定改成文案宣称的 `Shift+T`（改
  keymap，需查无冲突）。首选**改文案对齐 Ctrl+B**（不动肌肉记忆），一处 keymap 为准、多处文案引用它。
- **断点 3 → 传播范围接时间轴（复用 v0.21.13 基建）。** 打开传播对话框时在时间轴**高亮 from→to 区间**
  （`propagate-range` 用途）；反向支持在时间轴**刷选**直接喂 from/to 给对话框。传播完成后接 0.21.11 的
  `focusObject` / 自动前进，定位到传播结果帧。
- **断点 4 → 两类传播命名/图标区分。** 明确措辞（如「AI 追踪传播」vs「复制到后续帧」）+ 图标/副标区分「调模型」
  与「纯复制」的代价差异，避免误点重操作。
- **断点 5 → 禁用原因 tooltip。** 跳连/合并 disabled 时给出原因（「需恰好选 2 条同类且帧不重叠的轨迹」），
  按当前选择态动态提示差在哪。

## 定稿架构

```

  下拉: 生产/已绑后端项目过滤 mock_bbox (env/能力 gate)

  「AI 追踪传播」(调模型) vs「复制到后续帧」(纯几何) 命名/图标区分

  跳连/合并 disabled → title=动态原因
```

- **WS1 · 默认模型换真实 + 隐藏 mock**：`VideoTrackerPropagateDialog.tsx`（`:52,137,144`、
  `resolveTrackerDefaultModel :56-75`）默认 `preferNonMockModel=true`；上游填 `projectDefaultModel`（解析项目
  绑定的 tracker 能力）；下拉按 env/项目能力过滤 `mock_bbox`。确认后端仍保留 mock_bbox 供测试。
- **WS2 · 快捷键文案纠正**：以 `hotkeys.ts:79`（Ctrl+B）为准，改 `VideoTrackCardContent.tsx:423` /
  `VideoTrackerPropagateDialog.tsx:232` 文案；排查是否还有别处写 Shift+T。
- **WS3 · 传播范围接时间轴（依赖 v0.21.13）**：用 v0.21.13 的区间选择基建，对话框打开高亮 `propagate-range`、
  时间轴刷选回填 from/to；`VideoTrackerPropagateDialog.tsx:276-287` 的纯文字范围升级为时间轴可视 + 可刷选。
- **WS4 · 两类传播区分 + 禁用引导**：`VideoTrackCardContent.tsx:419-436` 两个传播入口命名/图标区分；
  `VideoTrackSidebar.tsx:194,334-348` 跳连/合并 disabled 原因 tooltip。
- **WS5 · 验证 + 版本**：E2E ① 已绑真实后端的项目开 AI 传播 → 默认选真实模型、下拉无 mock；② 测试环境仍见
  mock_bbox；③ 快捷键提示与实际 Ctrl+B 一致；④ 传播对话框 ↔ 时间轴范围联动（高亮 + 刷选回填）；⑤ 跳连/合并
  禁用时有原因提示。CHANGELOG（Changed + Fixed）+ 版本 bump。

## 不在范围

- **删后端 `mock_bbox` 模型**：测试环境仍需（server 端不依赖 ML backend 的传播器）。本计划只改前端默认与可见性。
- **重构传播 job 链路**：REST + WS 已真实、稳定（`useVideoTrackerJobs.ts`），不动。
- **组合/拆分入口收敛**：拆分现散在右键 / 浮卡按钮 / 「更多」下拉 / 关键帧表行 4 处（`videoContextMenuItems.ts`、
  `VideoTrackCardContent.tsx` 多处），scope/frameMode 各异，收敛为一处是更大重构，另议。
- **多选轨迹浮卡退化**：多选时浮卡显占位（`useWorkbenchShellModel.tsx:1881,1906-1909`）、批量走 roster，入口
  割裂问题另议。
- **v0.21.13 的区间选择基建本体**：本计划复用，不实现。

## 风险

- **`projectDefaultModel` 数据源**：默认换真实模型的前提是「知道项目绑定了哪个 tracker」。上游能否稳定拿到项目
  tracker 能力需先确认；拿不到时的回退（无绑定项目仍需可用默认）要定义，别把无后端项目卡死。
- **过滤 mock 误伤测试**：按 env/能力隐藏 mock_bbox 时，别把测试环境或未绑后端的开发流也挡掉——gate 条件要
  精确（如「项目已绑真实 tracker 后端」才隐藏）。
- **快捷键改动的连锁**：若选择改 keymap 到 Shift+T（而非改文案），须全量查 Shift+T 是否与既有绑定冲突
  （`hotkeys.ts` keymap）；首选改文案规避此风险。
- **依赖 v0.21.13**：WS3 强依赖区间选择基建的 `propagate-range` 用途；若 v0.21.13 未先落地，WS3 顺延，WS1/2/4
  可先行发布。
- **两类传播改名的迁移**：命名变更别影响既有文档/测试对旧文案的断言；改名同步 grep 更新引用。
