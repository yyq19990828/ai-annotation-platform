# Epic · 数据集导入能力扩展：服务端拉取连接器

> 切片索引 · 横跨 v0.11.14 / v0.11.15 / v0.11.16 三个版本

## 背景

当前数据集导入只有两条路径：

1. **浏览器上传**：单文件预签名 PUT + ZIP 包（≤200MB / ≤5000 文件），`ImportDatasetWizard.tsx`。
2. **扫描内置桶**：`POST /datasets/{id}/items/scan` → `DatasetService.scan_and_import()`（`apps/api/app/services/dataset.py`），**同步**扫描该数据集自己在 `minio-datasets` 的 prefix，无桶/路径选择、无异步 job。

诉求：新增**服务端主动拉取**类导入——从**外部对象存储（S3/OSS/兼容 MinIO）**和 **SFTP/SSH 目标（宿主机 & 同网段其他服务器统一当 SSH 目标）** 把数据拉进平台。

## 已锁定的设计基线

| 维度 | 决策 |
|---|---|
| 新增渠道 | 外部对象存储(S3/OSS) + SFTP/SSH |
| 入库方式 | **复制**进 `minio-datasets`，复用现有去重 / 缩略图 / 视频元数据 / Task 关联管线（不做外部引用） |
| 执行方式 | Celery 异步 `AsyncJob(kind="dataset_import")`，流式落盘（不整文件进内存），前端轮询进度，支持 cancel |
| 凭据 | 可复用 `storage_connections` 表，Fernet 加密落库（新 env `CONNECTOR_ENCRYPTION_KEY`），API 永不回吐明文 |
| 权限 | 项目管理员可建 project-scope 连接器，超管可建 global-scope |
| SSRF 防护 | **超管主机白名单**——项目管理员只能连白名单内 host/endpoint；DNS 解析后校验真实 IP（防 rebinding） |
| 新依赖 | `paramiko`（SFTP）；`boto3` / `cryptography` 已有 |

## 统一抽象

```
SourceAdapter (接口)
  ├─ list(path, recursive) -> Iterator[SourceObject{relpath, size, mtime}]
  └─ open(relpath) -> stream（流式，分块读）

实现：S3CompatibleSource / SftpSource
入库管线复用：hash 去重 → 写 minio-datasets → 读尺寸 → 建 DatasetItem → 关联 Task → 派发缩略图/视频元数据
```

Adapter 只负责"从哪读、吐出 (relpath, stream)"；"怎么入库"沿用 `DatasetService` 既有逻辑。

## 跨切片约束

- **安全是贯穿主线**：连接器创建、test、import 三处都必须过白名单 + SSRF 校验，不能只在创建时校验（白名单可能被超管收紧，存量连接器在 test/import 时需复检）。
- **密钥隔离**：`secret_enc` 永不出 service 层；任何 schema/response 不含密钥字段。
- **文档同步**：env 变更（`CONNECTOR_ENCRYPTION_KEY`）→ `.env.example` + `pnpm docs:gen-env-vars`；新表/新协议 → `docs-site/dev/`，新 API → `docs-site/api/`（OpenAPI 自动）；架构决策（复制而非引用、白名单 SSRF 模型）→ 考虑补一条 ADR。
- **CHANGELOG**：三版各自一段 `## [0.11.x] - 2026-xx-xx`（feature，记 CHANGELOG）。
