# v0.11.17 · JobsBell 浮层清理：全部/进行中筛选 + 清空已结束（P3）

> 独立小切片 · 纯前端 · 依赖：无硬依赖（但排在 [v0.11.16](2026-05-26-v0.11.16-connector-frontend.md) 之后做，因导入 epic 新增的 `dataset_import` 任务会进同一个铃铛、放大终态拥挤问题）

## 背景

`JobsBell`（`apps/web/src/components/shell/JobsBell.tsx`，~185 行）5s 轮询 `GET /async-jobs?limit=20`，把进行中进度 + 最近完成历史都塞进 drawer。终态任务（`completed/failed/cancelled`）会长期占据浮层。数据层已有 30 天终态清理（Celery beat `purge_old_async_jobs`），**不应为了 UI 清爽直接删 job**——历史是有价值的运营/取证数据。

v0.11.15/16 的连接器导入新增了 `dataset_import` 这一类 async_job，进一步加剧浮层拥挤，使本项更值得做。

## 目标

纯前端把浮层"看得清"：加 `全部 / 进行中` 筛选 + 终态任务本地 dismiss，不动后端、不调任何删除接口。真正历史仍走 `/ai-pre/jobs`。

## 现状

- `JobsBell.tsx`：轮询 `/async-jobs?limit=20`，覆盖所有 kind；`KIND_LABEL` / `STATUS_LABEL` 映射文案；`StatusPill` / `ProgressBar` 子组件。
- 状态枚举 `AsyncJobStatus`：`pending / running / completed / failed / cancelled`。
- `dataset_import` kind（v0.11.15 引入）：确认 `KIND_LABEL` 是否已含其中文名（v0.11.16 应已补；若无，本版补）。

## 前端改动（仅 `JobsBell.tsx` + 其 module.css）

### 1. 全部 / 进行中筛选
- drawer 顶部加分段控件 `全部 | 进行中`，默认 `全部`。
- `进行中` = 只显示 `pending / running`。
- 选择持久化到 localStorage（`wb:jobsbell:filter`），刷新保留。

### 2. 终态本地 dismiss
- 每条终态任务（`completed / failed / cancelled`）加单条 ✕ dismiss；drawer 顶部加「清空已结束」批量按钮（一次 dismiss 当前所有终态项）。
- dismiss 集合存 localStorage（`wb:jobsbell:dismissed`，存 job id 列表）。
- 渲染时：轮询结果先按 filter 过滤，再剔除 dismiss 集合内的终态项。
- **硬约束**：`pending / running` 永不隐藏、无 ✕、不受「清空已结束」影响——防止用户误以为任务消失。
- 「清空已结束」与单条 dismiss 都**只影响本地显示**，不发任何请求。

### 3. dismiss 集合维护
- 轮询只返回最近 20 条；被 dismiss 的 id 若已滑出窗口，集合会无限增长——加一步**收敛**：每次轮询后，用返回的 job id 集合 ∩ dismiss 集合，丢弃已不在窗口内的 id（它们本就不会再渲染）。避免 localStorage 膨胀。
- 终态不会回退（`completed` 不会变回 `running`），故 dismiss 后无需担心"任务又活了"。

### 4. dataset_import 文案兜底
- 若 v0.11.16 未补，`KIND_LABEL` 加 `dataset_import: "数据集导入"`（否则铃铛显示原始 kind 串）。

## 验证

- `pnpm --filter web typecheck` + `pnpm --filter web lint`（含 `lint:css-tokens`：新增筛选/按钮 CSS 只用 `tokens.css` 既有 `--color-*`，无 fallback、无 hardcode）。
- dark mode 走查（B-32/36/38/39 教训：筛选控件、dismiss ✕、清空按钮）。
- 单测（vitest + MSW）：
  - `进行中` 筛选只剩 pending/running。
  - dismiss 一条 completed → 该条消失；running 无 ✕ 且不被「清空已结束」移除。
  - dismiss 持久化：重渲染后仍隐藏；filter 选择持久化。
  - dismiss 集合收敛：滑出窗口的 id 从 localStorage 清掉。
- 手测：起一个 dataset_import / export job → running 期间不可 dismiss → 完成后可单条/批量清 → 刷新后保持已清 → `/ai-pre/jobs` 仍能看到全部历史。

## 回退

纯前端、改动集中在 `JobsBell.tsx`。回退 = 移除筛选 + dismiss 逻辑，恢复直接渲染轮询结果。无后端/数据影响。

## 备注

- 不引入"已读/未读"等更重的状态机；本版只做显示层 dismiss。若后续要跨设备同步 dismiss，再考虑落到 `User.preferences`（当前 localStorage 足够，P3 不值得上后端）。
