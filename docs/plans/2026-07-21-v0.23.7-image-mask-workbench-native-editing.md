>

>

## 1. 目标

- 图片工作台直接渲染、选择、创建、保存和再次编辑 `raster_mask`。
- Mask 工具从“隐式转最大 polygon”切换为“原生 Mask 默认真值”。
- polygon / multi_polygon 与 Mask 的转换变成显式、可预览、可撤销的操作。
- hole、多连通区域、像素面积与边界在刷新和历史操作后保持一致。
- 完成“部署总闸 + 项目 opt-in + region 工具绑定”的项目级灰度，不影响旧 polygon 项目。

## 2. 冻结合同

### 2.1 灰度与能力握手

- `RASTER_MASK_READ_ENABLED` 继续作为部署级 reader 总闸；`RASTER_MASK_CREATE_ENABLED` 约束所有图片 `raster_mask` 持久写入，包括 direct create / geometry PATCH、prediction 落库 / accept 和 import。
- Project 新增默认 `false` 的 `raster_mask_native_editing_enabled` opt-in；它只控制图片原生 Mask 写入，不复用 `tool_bindings.region.enabled` 代替，因为关闭 region 会同时关闭 polygon。
- 前端通过受任务权限保护的强类型 `GET /tasks/{task_id}/mask-capabilities` 读取 `read_enabled`、`write_enabled`、`legacy_polygon_commit_enabled`、稳定 `reason`、项目 opt-in 和尺寸 / bytes / runs 上限；不得复制环境变量或猜测后端配置。
- 有效写条件固定为：部署 read / create 总闸开启、项目 opt-in 开启、region 工具单元启用、任务与 annotation 可编辑；`read=false` 必须隐含 `write=false`。任一条件不满足时，前端不得先上传对象再等待 annotation API 拒绝。
- `read=true / create=false` 时已有 `raster_mask` 可渲染、选择、诊断和导出，但不能进入像素编辑、创建或转换；旧 polygon Mask 工具保持原路径。监控与真实 E2E 退出门满足后，部署 create 总闸默认开启，仍可作为紧急 kill switch 显式关闭。

### 2.2 持久化与原子转换

- `annotation.annotation_type` 必须与 `geometry.type` 一致；geometry PATCH 在同一事务内重派生 `annotation_type`，禁止 polygon → raster 后留下 `annotation_type=polygon` 的漂移记录。
- 本版只允许同一 `region` tool unit 内的 `polygon | multi_polygon | raster_mask` 原位转换；跨 tool unit 转换不借通用 PATCH 偷渡。
- 已存 Mask 保存顺序固定为 `GET → decode → edit → upload immutable RLE → PATCH geometry + If-Match`。替换 raster 内容或 geometry 类型转换缺少 `If-Match` 返回 428，版本冲突返回稳定 409；PATCH 保留 annotation id、label、attributes、source、parent / lineage 与 z-order，失败后保留 Buffer 和 stroke history。
- 空白创建顺序固定为 `edit → non-empty check → upload → POST raster_mask`；服务端成功前不退出 session。对象上传成功但 annotation mutation 失败时，由宽限期 GC 回收，不回滚不可变对象。
- prediction create / accept、AAP / COCO import、direct POST / PATCH 必须复用一个 write gate；删除、纯 metadata PATCH 和从 `raster_mask` 转出为 polygon 不被 create gate 误阻断。

### 2.3 渲染、命中与对象状态

- 共享 renderer 核消费 row-major alpha，生成 cropped alpha / bitmap、像素面积、真实 AABB、组件数和边界；图片与视频不得各自维护一份行列序或 alpha picking 算法。
- 图片 committed Mask 层固定在 image bg 之后、AI / vector user 层之前；Mask 内部按 `z_order` 稳定排序。矢量精确 shape 命中优先，只有落到 Stage 背景时才按 cropped alpha 选择 Mask，透明 AABB 与 hole 不得命中。
- cache key 至少包含 annotation id、version、sha256、类别色 revision；选择状态不进入 key。切 task / version / object 时立即撤下不再有效的 record，迟到请求只能释放自身资源，不能闪回旧 Mask。
- 每个对象独立维护 `loading | ready | error`；单对象 corrupt / 403 / 404 / 5xx 不清空其它对象。retry 只重拉目标对象，前端规范化错误状态固定为 `reason + retryable + message`，并提供诊断复制；后端提供稳定原因时原样保留到诊断输出。
- 编辑已存 Mask 时隐藏对应 committed bitmap，只显示当前 `MaskBuffer`，避免双层叠色。空 / corrupt 对象不生成全图或左上角虚假 bbox。

### 2.4 转换边界

- 本版交付单对象 `polygon | multi_polygon ↔ raster_mask`：vector → Mask 按原图分辨率、even-odd hole 与所有外环栅格化；Mask → multi_polygon 输出所有组件 / hole，默认不简化。
- 两个方向都先给预览和结构化报告：`sourceType / targetType`、前后面积与 delta、前后组件 / hole 数、顶点数、`changedPixels / droppedPixels`、过滤组件 / hole、容差和 `reasons[]`。`lossy=false` 定义为按同一 pixel-center 规则重新栅格化后的 XOR `changedPixels=0`；有损必须二次确认，取消不产生上传或 mutation。
- annotation history 的一次 conversion command 保存 before / after geometry 与类型，undo / redo 走同一原子 PATCH 并带最新 version，不创建新的 annotation identity。
- 批量 dry-run、视频 polygon track 转换、Mask → bbox / rotated bbox 和组件拆分 / 合并归 v0.23.9；不能在本版用最大外环或 bbox 代替完整单对象转换。

## 3. 实施切片

### P-1 · 开闸前安全与可观测前置

- 修复 prediction create / accept 等绕过 create gate 的持久入口，并用失败不落库 / 不关联对象测试冻结。
- 增加低基数 Prometheus 指标：内容 read / decode / verify / store 的 outcome、corrupt / digest / size / missing-object 错误计数，以及由 GC / 巡检刷新出的 active raster annotation / prediction gauge。
- 增加告警与运维查询，能从错误计数定位到 request / task 日志；指标不可携带 annotation id、task id 或 object key label。
- 增加 Project opt-in、任务能力响应和前端 gate；create 总闸在本切片验收前不得打开。

### P0 · 共享 renderer 核与 cache

- 抽取共享 RLE render record、cropped alpha / bitmap、AABB / area / component 分析和 picker，先用纯函数 fixture 冻结非正方形、hole、多组件与 z-order。
- 建立限并发、逐对象 settled 的共享加载 hook；cache eviction、task 切换、失败与 unmount 都必须 exactly-once close bitmap。
- RLE decode、AABB / area / component / hole 分析放入专用 Worker，向主线程传 transferable cropped alpha；无 Worker 环境只能用于测试或明确降级，不能用同步全图 flood-fill 阻塞生产交互。
- 视频 descriptor 适配共享核心且行为不回归；图片新增 `RasterMaskView`，复用类别色和 Mask opacity。
- 加载中明确占位，不复用上一 task / annotation Buffer；内容错误显示对象级状态、重试和诊断，不让整层消失。

### P1 · 图片 renderer、Alpha picking 与列表

- hover、选择、右键使用 cropped alpha picking；透明外接框区域不能命中。
- Annotation 列表显示 Mask 类型、像素面积、AABB、组件数和内容状态。
- viewport fit 使用 AABB；空 / corrupt Mask 不生成虚假全图 bbox。
- 选中态轮廓与填充分别可见，暗色 / 亮色主题使用语义 token。

### P2 · 原生创建与再次编辑

- 空白 session 只有在涂出非空前景后才能创建 `raster_mask`；保存成功后才退出 session。
- 已存 Mask GET → decode → edit → upload → PATCH，保持 annotation id、label、attributes、source 和 version。
- 图片逐 stroke undo / redo 与视频一致；annotation commit history 可撤回整个保存。
- 擦空已有 Mask 时弹出“删除对象 / 撤销本次擦空 / 保持空白继续编辑”，不保存不可见 annotation。
- 项目 `raster_mask_native_editing_enabled` 关闭时保持旧工具行为或隐藏原生创建入口，不能发新 geometry。

### P3 · 单对象双向显式转换

- polygon / multi_polygon → Mask：按图片原始分辨率栅格化，hole 使用 even-odd，转换前后显示面积差。
- Mask → polygon / multi_polygon：预览所有组件和 hole，展示顶点数、面积误差与被过滤区域。
- 默认不自动简化；用户选择容差后才生成矢量结果。
- 有损转换必须二次确认并生成结构化 loss report；不再只 toast“保留最大外环”。
- 同一 annotation geometry 转换保留 identity / attributes / lineage，并可 annotation undo。

### P4 · 入口、恢复与兼容

- ToolDock 的 Mask 工具在支持 `region` 的图片项目出现；暂不拆 tool binding。
- 已有 polygon 的“精修”入口明确显示“将转为栅格 Mask”，首次确认后进入编辑。
- prediction polygon refine 走服务端 lineage；候选接受后创建 Mask，不做本地-only dismiss。
- 旧 polygon 创建、编辑、导出仍可用；不批量迁移历史数据。
- toolbar 展示 loading / error / saving，提供 retry、stroke undo / redo；擦空已有 Mask 时复用删除 / 撤销擦空 / 保持编辑三态选择。

## 4. 非目标

- 不接单帧 SAM 原生 RLE；仍可从 polygon 候选显式转 Mask。
- 不实现套索、形态学、连通域高级操作或非重叠绘制。
- 不实现大于 4096 的 tile editor。
- 不拆分 `region` tool unit；项目 schema 仅增加默认关闭的原生 Mask rollout 字段，不扩展新的几何工具单位。
- 不实现 semantic / panoptic class-map。
- 不做批量、视频或 bbox / rotated bbox 转换，不做组件拆分 / 合并；这些属于高级实例操作版本。

## 5. E2E 验收

1. 空白 Mask 创建、刷新、再编辑后逐像素一致。
2. hole + 三组件 Mask 保存后全部保留。
3. 保存失败保留 Buffer 和 history，retry 后只写一次。
4. 快速切题 / 切对象没有旧 Mask 闪回。
5. 锁定 Mask 经快捷键、pointer、Enter、Delete 均不可修改。
6. polygon with holes → Mask → undo，几何与 annotation identity 恢复。
7. Mask → multi_polygon 保留所有组件 / hole；显示损失报告，取消不修改数据，确认后 annotation type 与 geometry 同步。
8. corrupt RLE 只影响单对象，列表和画布可诊断。
9. read flag on / create flag off 时只读渲染可用、创建不可用。
10. create flag 灰度开启后旧 polygon 流程无回归。
11. prediction create / accept、import 与 direct API 在有效 gate 关闭时都不落库、不关联对象。
12. 一个损坏 Mask 只进入自身 error；其它 Mask 仍可见、可选，retry 不重复加载健康对象。

## 6. 性能与无障碍门

- 先用非正方形、稀疏 / 密集、hole / 多组件 fixture 记录 1080p 单 Mask decode / analyze / bitmap 的 p50 / p95、峰值临时内存和稳定 cache bytes，再冻结数字预算；不得声称前序版本已经给出不存在的基准。
- 同图 20 个 Mask、连续切换 50 题后 cache bytes 不持续增长；加载并发有硬上限，所有 cache eviction 有 bitmap close 测试。
- 任一主线程任务超过 50ms 必须在基准报告中定位；Worker 不得因测试环境或兼容 fallback 被生产路径静默绕过。
- 工具栏状态、错误、加载和选中不能只靠颜色表达。
- 所有按钮有键盘操作和可读 label；dirty guard 可聚焦并能 Esc 返回编辑。

## 8. Outcome

- P-1 至 P4 已完成：prediction create / accept、direct API、AAP / COCO import 与工作台上传前检查共用有效写闸；项目 opt-in、任务能力握手、图片原生创建 / 重载 / 再编辑、对象级错误恢复和单对象双向转换均已落地。
- 共享 renderer 输出 cropped alpha / bitmap、AABB、像素面积、组件、hole 与边界；逐对象加载器使用 Worker、有界并发和 128 MiB 估算字节预算，淘汰、迟到结果、切题和卸载均有 exactly-once bitmap close 回归。
- 12 条真实浏览器退出场景已在独立 read-on/create-off 与 read-on/create-on 矩阵全部通过；完整 Playwright 同时通过图片、视频、点云和旧 polygon 兼容回归。视觉基线固定到真实 DatasetItem，点云相邻预取不再把 PCD 错签到 annotations 桶。
- [1080p 基准报告](../research/17-image-raster-mask-workbench-benchmark.md)记录稀疏、密集、hole 与三组件 fixture：主线程 bitmap 阶段最大 `41.60 ms`，混合 20 Mask 稳态为 `118,457,200` bytes，低于 128 MiB 预算，浏览器 heap 在回收后无增长；超过 50 ms 的拓扑分析只在 Worker 内执行。
- Prometheus 告警覆盖内容损坏、存储不可用与活跃几何指标缺失，Grafana 面板展示内容操作、错误和活跃 annotation / prediction；运维文档给出阈值、查询与排查路径。
- 后端全量 Pytest、迁移 `upgrade → downgrade base → upgrade`、Ruff、前端 coverage / TypeScript / ESLint / CSS token / build / size、OpenAPI drift、文档规则 / 死链 / 构建和四个附属 Python 包均通过；运行态 `/health` 返回 `0.23.7`。
- 版本源、OpenAPI 快照、CHANGELOG、用户 / 开发 / 运维文档和 migration `0135` 已同步。`RASTER_MASK_CREATE_ENABLED` 默认开启，项目级 `raster_mask_native_editing_enabled` 仍默认关闭；生产放量继续按部署总闸与项目 opt-in 两层执行。
