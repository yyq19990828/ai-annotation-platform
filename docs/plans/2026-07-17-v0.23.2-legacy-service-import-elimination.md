# v0.23.2 · 旧 Service 导入路径彻底清零计划

> Status: draft; blocked on the v0.23.1 release and deployment baseline · 2026-07-17
>
> 前序计划：[v0.23.1 GPU Arbitration 编排领域化完整收口](2026-07-17-v0.23.1-gpu-arbitration-orchestration-modularization.md)

## 1. 结论

v0.23.2 不再继续延长兼容 facade 生命周期。本版本的单一主题是：

1. 清除可执行代码、测试、脚本、配置和当前态文档中的全部旧 service 导入形式。
2. 物理删除 23 个旧模块，使它们在干净 Python 进程和生产镜像内真正不可导入。
3. 将兼容测试转为永久的 removed-module 负向守卫，防止旧路径以 alias、stub、`sys.modules` 或 package fallback 形式回流。

“彻底清零”不是“第一方代码不再使用，但旧文件继续存在”。完成后，23 个旧路径不存在 `.py` / `.pyi` / `.pyc`，不可通过任何 Python 导入形式恢复。

## 2. 硬前置

v0.23.2 只能从已发布并稳定部署的 v0.23.1 release commit 开始。进入条件：

- v0.23.1 计划 P0–P8 全部完成，Outcome 不再有 `1/N` 或未落地的 GPU sibling。
- 7 个 GPU 旧实现文件已经是纯 facade，不含真实业务实现。
- 第一方生产代码已经全部直接导入领域 package。
- v0.23.1 tag、release commit、部署镜像和运行态 `/health` 版本一致。
- v0.23.1 在目标部署环境完成预先写入 D0 证据清单的观察窗口；清单必须给出起止时间、环境、部署错误 / 支持工单 / 运维脚本变更信号和具名批准人，不能用无 telemetry 的 facade 导入本身证明“无人使用”。

任一条不满足，可以继续完善本计划和扫描工具，但不得删除 facade。

## 4. “旧导入形式”的定义

以上 23 个 exact module path 的下列使用全部属于旧形式：

1. `import app.services.<legacy>`。
2. `from app.services.<legacy> import Symbol`。
3. `from app.services import <legacy>` 与后续模块属性访问。
4. `importlib.import_module()`、`__import__()` 或其它动态导入字符串。
5. `monkeypatch`、`mock.patch`、故障注入、序列化配置和启动脚本中指向旧模块的 target 字符串。
6. package `__getattr__`、`sys.modules` alias、`.pyi` stub、tombstone module 或其它能让旧导入继续成功的隐式兼容。
7. 当前态文档、运维手册和可复制代码片段中的旧导入示例。

仅更换 `from` 句式、但仍保留旧模块字符串，不算完成。

## 5. 扫描边界与唯一豁免

### 5.1 必须归零的活跃范围

扫描边界不是一份容易漏项的目录白名单。扫描器默认遍历 `git ls-files` 返回的全部 tracked 文本、配置和构建文件，deny-by-default；只允许显式排除二进制、vendor、generated 和 §5.2 逐命中审核过的历史材料。至少覆盖：

- `apps/**`，包括 API 的 `app` / `tests` / `scripts` / `alembic`、Web、五个真实 ML Backend 与 `_shared`。
- `packages/**`、根 `scripts/**`、`infra/**`、`config/**`、Docker / Compose、启动与部署配置。
- `.github/**`、所有根配置文件、`README.md`、`DEV.md`。
- `docs-site/**`、`docs/**`、`docs/migration/**`、`ROADMAP.md` 与 `ROADMAP/**`。

任何新 tracked 路径自动进入扫描，不得因为目录未列出而获得豁免。

### 5.2 历史材料

`docs/plans/**`、`docs/changelogs/**`、`docs/adr/archive/**` 可以保留当时的路径事实，但必须满足：

- 不存在指向已删文件的 Markdown 链接。
- 旧代码片段不能被当作当前可复制用法。
- 每个命中进入一份具名 historical allowlist，逐项记录文件路径、exact old module、命中类型（文本 / 代码块 / 链接）、预期命中数、链接目标或规范化片段摘要、原因、审核日期和审核人。禁止整文件通配豁免。

允许活跃源树出现旧 exact path 的文件只有两类：

1. removed-module 负向测试使用的单一 machine-readable manifest。
2. 当次迁移说明中的 old → new 映射表。

禁止在多个测试文件和脚本中复制 23 项字符串，也禁止通过拼字符串逃避扫描。另设 manifest 驱动的历史链接守卫，只核对指向 23 个删除目标的链接；不能依赖默认会跳过历史目录的通用 dead-link 检查。

## 6. 外部依赖判定

`app.services.*` 是应用内部实现，不是 Python SDK 或受支持插件 API。当前未发现 PyPI 发布的 `anno-api`、Python entry point 或对外扩展合同；但这不能证明私有 fork、运维脚本或关联仓库不存在。

D0 必须保存以下可复核证据：

- 记录搜索日期、执行账号和该账号可见的组织 / 私有仓权限边界；对 23 个 exact path 保存全局、组织内和关联仓库的 exact query、原始结果 URL / JSON、结果数与本仓历史排除规则。
- 逐项搜索部署仓、运维仓、issue、支持工单、已知私有扩展和脚本变更记录；五个仓内 ML Backend、两个示例、Python SDK、Web、API 启动与 worker / beat 路径均有明确结果。
- 下游 owner 与 release operator 具名确认；无法访问的私有仓库和私人 clone 明确记录为 residual risk，不得表述成“已证明不存在”。
- 固定 §2 的观察窗口、环境和检查信号，并保存结论与批准人。
- 在 `docs/migration/2026-07-17-v0.23.2-service-import-cutover.md` 提供完整 old symbol → exact defining module 迁移表。

如果发现受支持的下游仍使用旧路径，立即阻断删除；先为下游提供迁移提交。如果这些路径已被承诺为支持中的公共 API，则不能以 patch release 删除，必须停止 v0.23.2 并重新决定版本边界。

## 7. 非目标

- 不改 HTTP / WebSocket API、OpenAPI schema、数据库 schema 或环境变量。
- 不改 Celery task 注册名、queue route、signature 或 beat schedule。
- 不改 GPU Redis key、Lua、SQL、锁序、事务、token 或状态机。
- 不继续拆分 GPU ledger / dispatch 或其他领域实现。
- 不通过 DeprecationWarning、stub 或友好异常延长旧模块存活。
- 不夹带业务 bugfix、格式化或无关重构。

## 8. 永久守卫

建立一份 23 项 machine-readable removed-module manifest，由所有扫描和负向测试共用。对每个旧模块，独立冷进程必须验证：

1. `import app.services.<legacy>` 失败。
2. `from app.services import <legacy>` 失败。
3. `from app.services.<legacy> import <frozen-symbol>` 失败。
4. `importlib.import_module()` 与 `__import__()` 失败。
5. `importlib.util.find_spec(old_path) is None`。
6. `app.services` 不暴露同名属性。
7. 源码树和生产镜像内不存在 exact relative path `app/services/<legacy>.py`、`.pyi` 或 `app/services/__pycache__/<legacy>.*.pyc`；不能按 basename 扫描，以免误报 API、worker 或 DB model 中合法的同名文件。
8. 仓库与发布产物不主动注册旧路径的 `sys.modules` alias、package `__getattr__`、meta-path finder 或其它 import hook；在没有第三方自定义 import hook 的干净进程中旧路径自然失败。

当前 API 没有 `[build-system]`，项目也不发布 wheel，因此 wheel 不是本计划的虚构 release gate。若 D0 发现实际 wheel 下游，立即停止删除，先定义 build backend、临时 venv 安装和空工作目录验收合同，再把 wheel 纳入范围。

同时保留并加强架构守卫：

- AST 同时解析绝对、相对、package attribute 和函数内导入。
- 字符串扫描覆盖 dynamic import、patch target、logger name、配置和文档片段。
- 删除 facade 后，`legacy_facades` 规则不得随之删除，而是改名为 `removed_modules` 并永久禁止回流。
- 为扫描器保留合成负例，包含五种导入形式、patch 字符串、项目主动注册的 `sys.modules` alias 和 package fallback。
- 负向导入必须核对失败原因：直接导入断言 `ModuleNotFoundError.name == old_path`；package import 断言对应 `ImportError` 且 `app.services` 无同名属性。相同探针还要成功导入新模块与真实消费方，避免因整个依赖树损坏而假阳性通过。

## 10. 验证矩阵

### 10.1 结构和导入

- 23 个 exact service path 不在 Git index 或生产镜像中。
- 23 个 `find_spec` 全部为 `None`。
- 五种 Python 导入形式全部冷进程失败。

上述脚本名在 D0 落地后即成为仓库合同。release 前仍要求仓库当时的全部 required CI checks 通过；clean checkout 不得依赖预先存在的 `.venv`、`node_modules`、开发数据库或运行栈 Redis。

## 13. 回滚和停止条件

### 13.1 回滚

- **发布前阶段回滚**：按 D6 → D2 逆序 revert 完整删除提交；不能只捞回 `.py` 文件。每个 revert 同步恢复 `ACTIVE_FACADES` / `REMOVED_MODULES`、identity / negative tests、扫描规则、docs-impact matcher、直接关联文档与迁移记录。
- **发布后部署回滚**：直接部署 v0.23.1 tag 对应镜像，核对 image digest、`/health`、API / worker / beat 冷启动和 GPU latch / effective mode；不在 v0.23.2 镜像中临时注入模块。
- **发布后向前修复**：后续 patch 若恢复纯 facade，必须在同一提交原子更新 facade 文件、两套 manifest / 测试、扫描豁免、迁移文档、CHANGELOG、docs-impact 与 production image。
- 禁止用 `sys.modules`、package fallback、meta-path hook 或 wrapper 当作回滚方案。
- 本计划没有数据库或 Redis schema 变更，无需数据回滚；恢复文件后重启已加载 service module 的 API / worker，不依赖旧进程缓存。

### 13.2 立即停止

- v0.23.1 未完整发布、未稳定部署或仍有真实 GPU 实现留在旧文件。
- 发现受支持的外部下游仍使用旧路径。
- 删除需要改变公开 API、Celery 合同、SQL、Redis / Lua 或业务行为才能通过。
- 任一旧路径需要 stub、alias、wrapper 或 import hook 才能继续运行。
- 冷启动、完整测试、required CI 或生产镜像扫描不能全绿。
- 任一删除提交混入业务修复或无关重构。

## 14. 成功标准

- 23 个旧 service 模块全部从源树和发布产物中消失。
- 所有旧导入形式在无第三方 import hook 的冷进程中因目标模块确实不存在而失败，仓库与产物没有主动隐式兼容通道。
- 第一方活跃代码、测试、脚本、配置和当前态文档零 old exact path。
- 历史材料只在具名 allowlist 中保留当时事实，没有坏链或当前可复制用法。
- 领域 package 是唯一实现和导入边界，永久守卫阻止旧路径回流。
- API、WebSocket、Celery、SQL、Redis / Lua 与用户行为零变化。logger namespace 允许从旧 service path 改为新模块 `__name__`，但日志事件、level、字段和消息模板不变，依赖 namespace 的查询 / 告警已同步迁移。
- 文档、CHANGELOG、版本源、生产镜像与运行态版本同步。
