# v0.21.0 · 全局跨项目编排选择器

状态：草案(draft)。minor 版本——v0.19.2 WS0 的**正主消费方**。把现在逐项目、临时的编排搭建
升级为全局、可命名、可复用的跨项目流水线选择器。是这一系列 plan 的 capstone。

## 背景

- v0.19.2 WS0 让 `/instances` 透传 `supported_inputs` + `resource_profile`,计划里写明这是
  **「全局编排选择器的前置」**——前置已就位,选择器未建。
- 现状编排(`StageCard` / `ProjectDetailPanel`,`apps/web/src/pages/AIPreAnnotate/`)走**项目级**
  `/capabilities`,每个项目从零搭流水线,无法跨项目复用「检测→车辆属性」这类常用编排。
- v0.18.27 落地方案 A(`Project.preannotate_pipeline` 单列 JSONB,一项目一条,
  `apps/api/app/db/models/project.py:53-55`)。ROADMAP §75 明确升级触发条件是「≥2 例多命名
  或跨项目复用需求出现」,并警告「不要因『灵活性』提前建表」。

### 触发用例(承接 ROADMAP §75 触发线)

命名沿用 M-N 供后续跟踪:

- **M-1** 「detect → 车辆属性」(乘用车项目)
- **M-2** 「detect → OCR」(车牌/工牌项目)
- **M-3** 「detect → 属性 + tracking」(视频侧,下游 v0.21.1 消费)

三条已由业务侧提出,命中触发线,非「灵活性推测建表」。

## 目标

基于全局 `/instances` 建一个编排选择器:从全局池选 backend/model 搭流水线,
存为**命名可复用**的编排(三级 scope),跨项目套用。把 WS0 数据用起来。

## 沿用的既有决策(不新开 ADR)

### ADR-0023 项目模板 vs 克隆策略

本版编排模板全部沿用其骨架:

- **三级 scope**:`private` / `organization` / `public`(显式 enum 列,**不用 nullable 判语义**)。
- **copy-on-write**:套用即 `deepcopy`,模板改不追杀已实例(`docs/adr/archive/0023-project-template-vs-clone.md:29`,
  显式否决 by-reference,§Alternatives)。
- **权限判据**:`assert_template_visible` / `can_edit_template` / `assert_can_create_scope`
  (`apps/api/app/services/project_template.py:43-80`)直接抄成 pipeline 版。
- **写权限**:`public` 仅 super_admin;`organization` 组织成员;`private` 由创建者/超管。
- **usage_count 运营信号**:沿用。

### ADR-0044 全局注册表 + 项目启用

本版编排「未启用 backend」降级沿用其二层模式:

- **派发期硬拦**:404 backend 未启用(`apps/api/app/api/v1/projects.py:1557-1560`)。
- **保存期软提示**:能力软 warning(`_compute_pipeline_capability_warnings`,`projects.py:1490-1541`)。
- **套用期同姿态**:套用瞬间校验,缺则 422 + 提示去启用(不新决策)。

### WS1 · 数据模型:命名编排表(复用 project_templates 骨架)

**新表 `project_pipelines`**:

- `id UUID PK`
- `scope enum('private','organization','public')` —— 显式列,不用 nullable 判语义
- `project_id UUID FK`(`scope=private` 非空,其他为空)
- `organization_id UUID FK`(`scope=organization` 非空,其他为空)
- `name String(255)`
- `stages JSONB`(同现 `PreannotateRequest.pipeline_stages` 结构)
- `is_default Boolean`(每项目至多一条 true,DB partial unique + service 原子切换)
- `created_by UUID FK`
- `usage_count Integer default 0`
- `created_at / updated_at`

**Alembic 迁移**:

- 建表 + 索引 + partial unique(`WHERE is_default = true`,按 project_id)。
- **Backfill**:`Project.preannotate_pipeline` 非空 → 建一条 `scope=private, is_default=true` 行。
  列**保留一版做读兼容**,下版删。
- **顺带清理 `Project.ml_backend_id` FK**:「项目主 backend」是冗余第二真值,改由 `is_default`
  命名编排的源阶段派生。同版删 FK + 调 dispatch wire——
  `PreannotateRequest` 顶层 `ml_backend_id` 与 `pipeline_stages[0].ml_backend_id` 强绑
  (`projects.py:1304-1305`)改为**自动从源阶段派生**。

**权限**:直接抄 `apps/api/app/services/project_template.py:43-80` 到
`apps/api/app/services/pipeline_template.py`(`assert_pipeline_visible` /
`can_edit_pipeline` / `assert_can_create_pipeline_scope`)。

**校验**:

- 结构 → `_validate_saved_pipeline`(v0.18.27,`projects.py:1398-1427`)搬到新端点。
- 能力 → `pipeline_validation.py`(v0.19.3)直接复用,不动。
- `is_default` 唯一性 → DB partial unique + service 原子切换。

**API**:

- `GET /v1/project-pipelines?scope=&project_id=&organization_id=`
- `POST /v1/project-pipelines`(body 带 scope)
- `PUT /v1/project-pipelines/{id}`
- `DELETE /v1/project-pipelines/{id}`
- `POST /v1/projects/{project_id}/pipelines/apply`(套用一条模板)
  - body:`{pipeline_id, set_default: bool}`
  - 语义:copy-on-write(`stages` deepcopy 到 `scope=private` 的新行);`usage_count += 1` 原子递增
  - 校验:源阶段 backend 未在项目启用 → 422,body 列出 `unenabled_backends`(UI 提示去启用)

## 风险(收敛后)

- **YAGNI 挑战**:由 §触发用例三条命名需求承接(ROADMAP §75 触发线已达)。
- **失效降级**:沿用 ADR-0044 二层模式,无新机制;套用瞬间校验缺则 422 + 提示去启用。
- **老 backend 无 `supported_inputs`**:WS0 明确 `_synthesize` 不合成 video,兜底安全。
- **`Project.ml_backend_id` FK 清理**:与命名编排表迁移**同版**做,避免留两个真值漂移。
  dispatch 期强绑约束改为自动派生。
- **backend/model 下线**:`pipeline_validation` 已是 SSOT(v0.19.3),套用/编辑期跑判据即可;
  无新表。
- **权限**:抄 project_template 三个 assert;super_admin 建 public,无新维度。
- **跨端契约**:`apps/web/src/__fixtures__/capability-validation-cases.json` +
  `apps/api/tests/test_pipeline_validation.py` 双端 fixture 已就位;WS0 加 `INPUT_IDS` 时
  同步扩 case,新增词表判据只加 code,不改判据结构。

## 验收

- 从全局选择器搭一条「detect→classify」编排、命名保存为 `scope=public`,套用到两个不同项目均生效。
- 选择器内全程有 v0.19.2 配置期校验(可达 / class / batchable / 属性落点全部前移到画布)。
- 套用时引用未启用 backend → 422,body 列出 `unenabled_backends`,UI 明确提示去启用(不静默失败)。
- 全局池里 `state=error` backend 展示但打「探测失败」标 + 禁用选择。
- v0.18.27 现存 `Project.preannotate_pipeline` 数据经迁移变为 `scope=private, is_default=true`,
  popover 行为无回归。
- PR-A 完成后:v0.21.1 detect-tracking 可基于 `INPUT_IDS` + `default_input_type` 开工,无回改。
