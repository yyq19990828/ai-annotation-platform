## 1. 本版目的

v0.23.25 只在新的分段数据证明有必要时，优化已有客户端 WebGPU `square dilate` kernel，并完成
整个超大图 Tile × Raster Mask 客户端计算 Epic 的跨平台资格与 rollout 决策。

当前 WGSL 对每个输出 word：

```text
for dy in -radius..radius
  read previous/center/next words
  for shift in 1..radius
    horizontal OR shifts
  vertical OR
```

操作数随 radius 接近 `O(radius²)`。候选是：

```text
Pass H: source packed words
  → input-height × core-word horizontal dilation intermediate

Pass V: intermediate
  → vertical OR over radius
  → XOR with source core center
  → existing dense XOR target/readback
  → existing CPU word-scatter history patches
```

两 pass 会增加 intermediate buffer、第二次 dispatch/barrier 与 pipeline complexity。当前
v0.23.19 的 WebGPU operation total 已经很低，因此不能仅凭理论复杂度保留。M0 必须先证明：

- radius 增大时 GPU stage 已成为主要瓶颈；
- background tile/Mask resource coordinator 下仍有 intermediate budget；
- 两 pass 的端到端收益足以抵消新 buffer/dispatch；
- 不同客户端平台没有不可接受的回归。

若证据不成立，本版的正确结果是记录 no-go、删除 candidate、以当前 one-pass winner 封版。

## 2. 冻结产品边界

WebGPU 继续是：

> 客户端大尺寸 Raster Mask 方形膨胀的可选计算后端。

本版明确不扩展：

- `square erode`；
- `open/close`；
- disk kernel；
- component/hole/topology；
- brush/lasso tint；
- background image tile；
- video decode；
- server-side GPU。

原因：

- UI 默认/真实操作使用率需另有产品数据；
- erode 的画布外语义、open/close 两形态 halo/intermediate 合同需要独立资格；
- 本 Epic 的目标是优化并封住当前 backend，不扩大 shader 面。

## 4. Candidate 合同

### 4.1 Intermediate coverage

不能只对 final core rows 做 horizontal pass。vertical pass 为每个 core y 需要读取
`y-radius..y+radius`，因此 intermediate 至少覆盖：

```text
widthWords = ceil(coreWidth / 32)
height = inputHeight
x coverage = final core x span（source read 使用既有 x halo）
y coverage = full input y span
```

Pass H：

- 对 input 的每一行生成 core x span 的水平 dilation；
- source x origin 可非 32 对齐；
- previous/center/next word 与 tail 规则复用 one-pass helper；
- intermediate row tail 无效 bit 清零；
- image x 外部为 0。

Pass V：

- 对 final core y 聚合 intermediate rows；
- image y 外部为 0；
- 与 aligned source center XOR；
- final core row tail 清零；
- 输出现有 `xorWordsPerRow × coreHeight`。

### 4.2 单 command submission

production candidate 使用一个 command encoder：

1. Pass H dispatch；
2. storage write → read synchronization 由 WebGPU pass/usage 合同表达；
3. Pass V dispatch；
4. copy XOR target → existing MAP_READ buffer；
5. submit once；
6. map once。

不在 H/V 中间 readback，不建立 JS intermediate。

### 4.3 Pipeline

候选可采用：

- 一个 WGSL module、`horizontal`/`verticalXor` 两 entry points；
- 两个 compute pipelines；
- shared params 或明确分开的 uniform；
- one-pass baseline 继续保留到 winner 决策。

最终：

- separable 全范围 no-win：删除两个 entry/pipeline/intermediate；
- 只在 radius/ROI 子区间 winner：保留 one-pass + separable，并冻结唯一 crossover table；
- 全范围 winner：删除 one-pass production shader，只把其 oracle 留在 test/benchmark；
- 不允许存在无 route 可达的 shader/pipeline/buffer。

### 4.4 Budget

新增：

```text
intermediateLogicalBytes =
  ceil(coreWidth / 32) × inputHeight × 4
```

实际 capacity 可 grow，但必须：

- 检查 `maxBufferSize`/`maxStorageBufferBindingSize`/dispatch limits；
- 纳入 v0.23.24 coordinator `gpu-buffer`；
- grow 前 prospective reserve；
- single-pass admission 成功但 separable intermediate 不可接纳时走 one-pass，不回 CPU；
- device lost/dispose/pressure release 后 logical bytes 对账归零；
- 不同时保留多个不同 capacity intermediate。

## 6. Winner 规则

### 6.1 实施前置

只有 M0 同时满足以下条件才进入 M1：

1. radius ≥8 至少一个 production ROI 的 GPU-related stage 占 total ≥30%，或随 radius 呈稳定增长；
2. v0.23.24 global budget 能接纳 intermediate，不触发 P0/P1 eviction；
3. no-GPU/CPU fallback 已封版，不依赖 candidate 解决 correctness；
4. current one-pass baseline 在同 bundle 重跑完成。

否则：

- 不实现 candidate；
- 记录 no-go；
- 直接进入跨平台/rollout/文档封版；
- 不留空 shader 文件/TODO。

### 6.2 Candidate 进入 production

对最终 route 覆盖的每个 radius/ROI bucket：

- operation total p95 相对 one-pass 的两轮改善率算术平均 ≥15%，且每轮改善均 ≥10%；
- radius 1/4 若仍走 one-pass，separable 不计回归；
- 若统一切 separable，小 radius p95 不得恶化 >5%；
- coordinator `committed + outstanding reserved` charged peak 不突破预算；
- GPU buffer peak增量符合 M0 冻结门；
- Long Task = 0；
- exact patch/undo/redo/save/reload；
- dispose 后 buffer/session/owner/coordinator bytes 归零。

局部 shader/pass 改善但 total 未过门：拒绝并删除 candidate。

### 6.3 跨平台

- static crossover 不按 adapter vendor 分叉；
- 计划中每个可用且拟声明 qualified 的平台，都必须对最终 universal radius/ROI route 通过
  6.2 的平均改善与单轮 floor；
- 某平台未过门时可缩小 universal radius/ROI route 并对全部平台重跑；不能以“回归不超过 5%”
  代替 candidate 的正向收益资格；
- 缺少计划平台机器时，该平台记 `not tested`，separable 保持 benchmark-only；这不影响既有
  one-pass gate 按其独立基线封版；
- 无法形成所有已测目标平台都通过的 universal route 时删除 separable production candidate，
  保留 one-pass；
- 不通过读取 adapter name 建 workaround。

## 7. Fallback 与故障

| 故障点                                            | 行为                                                                       |
| ------------------------------------------------- | -------------------------------------------------------------------------- |
| separable limits/budget 不满足                    | one-pass 若可接纳，否则 CPU                                                |
| separable shader compile/pipeline create          | 当前 provider generation 禁用 separable；one-pass 若健康且可接纳，否则 CPU |
| intermediate buffer create/admission              | 当前 provider generation 禁用 separable；one-pass 若健康且可接纳，否则 CPU |
| Pass H/V candidate encode validation              | 丢弃 encoder 并禁用 separable；same-request one-pass，失败再 CPU           |
| queue submit/device invalid                       | provider circuit + same-request packed CPU，零 GPU patch                   |
| map/readback 或 GPU result/tail invariant invalid | source 可信时 same-request packed CPU；provider 进入 cooldown              |
| shared word-patch builder invariant/exception     | fail closed，零 commit；不得用同一 builder 重试并宣称 CPU recovery         |
| device lost                                       | release all GPU owner bytes；CPU；cooldown                                 |
| cancel/stale after submit                         | GPU 可完成但结果丢弃；零 commit                                            |
| background pressure                               | pause prefetch；若 intermediate admission 失败，one-pass/CPU               |
| no navigator.gpu                                  | v0.23.21 CPU winner                                                        |
| WebGPU gate off                                   | 零 provider chunk/requestAdapter；tile 正常                                |

same-request CPU recovery 必须复用已有 packed source；只有 operation 不受 packed CPU 支持时才使用
dense CPU。packed source 或 shared patch builder 不可信时 fail closed，不能用同一数据面“恢复”。

## 9. Rollout 决策

### 9.1 Image pyramid

v0.23.25 固定：

- auto-generation threshold；
- required/optional threshold；
- client tile gate 默认值；
- unsafe original fallback policy；
- generator/platform/format 未验证项；
- backfill/GC 运维方式。

### 9.2 Raster Mask WebGPU

当前 capability-first build gate 缺省 true。封版决策：

- **既有 one-pass**：default true 是进入本版时的基线；已测平台未出现 correctness/resource 问题时
  可保持。缺少机器的平台明确 `not tested/unqualified` 并保留 kill switch，不把“fallback 稳定”
  写成该平台性能资格；
- **separable candidate**：只有 6.2/6.3 的 correctness、resource 与端到端 p95 矩阵全部通过才进入
  production；平台证据不足时保持 benchmark-only，并删除 production route；
- 既有 one-pass 在任一已测平台出现 correctness/resource 问题时，全局 gate default false 或按
  部署回滚；不能按 adapter name 黑名单；
- separable no-go 不等于关闭现有 one-pass WebGPU；
- WebGPU 任意结果都不影响背景 tile 默认值。

### 9.3 独立 kill switches

- `IMAGE_PYRAMID_AUTO_GENERATE`
- `VITE_EXPERIMENTAL_LARGE_IMAGE_TILES`
- `VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU`

验证：

- 三个开关 2³ 组合中的关键状态；
- 关闭 tile 不改变 WebGPU；
- 关闭 WebGPU 不改变 tile；
- 关闭 generator 后已 ready pyramid 读取策略明确；
- 所有开关不改 annotation/RLE 格式。

## 11. 最终验收门

### Correctness

1. one-pass/separable/packed CPU/dense oracle bit-exact。
2. no GPU、GPU failure、tile failure 不产生 partial Mask/history。
3. background tile 与 vector/Mask/Issue/full-resolution coordinate exact。
4. 任务/generation/page lifecycle stale commit=0。
5. save/reload canonical RLE exact。
6. 超过 native Raster Mask 上限时 UI 不宣称可编辑。

### Performance/resource

1. separable 仅按 winner 门保留。
2. background pan/zoom FPS ≥30、Long Task=0。
3. foreground Mask p95 不被 tile prefetch 恶化 >5%。
4. 应用逻辑 `committed + outstanding reserved` charged bytes ≤ v0.23.24 hard budget。
5. 长会话进入 plateau。
6. dispose 后 bitmap/tile request/Worker/session/GPU owner/buffer/coordinator bytes 归零。
7. small image/single path p95 不回归 >5%。

### Fallback

1. no GPU 客户端可完整浏览超大图并使用 CPU Mask path。
2. adapter 初始化不阻塞当次操作。
3. device lost/runtime failure 同请求 exact CPU。
4. required pyramid pending/failed 不自动整图 OOM。
5. tile/Mask/generator/WebGPU gates 独立可回滚。

## 12. Dead-code 完成门

全仓确认：

- 无 `dense-per-bit` production selector；
- 无 rejected sparse records/prefix sum bindings；
- separable no-go 时无 H/V shader/pipeline/intermediate/metrics；
- separable partial winner 时每条 retained path 均有 production route/test；
- 无 unused whole-image background component/hook 绕过 source resolver；
- required large image 的 Minimap/comment/prefetch 不回原图；
- 历史 default-off 文案都有时点附注；
- 不存在“服务端 GPU 决定浏览器 WebGPU”的错误文档。

## Outcome

- **版本与基线：**从 v0.23.24 release `ae7199a0` 实施；本计划所在提交为封版提交。M0 在
  2048²、radius 8/31 观察到 GPU-related provider 阶段约占 total 48%–51%，满足“先实现再测”的
  30% 前置门。已有 packed CPU fallback、task-scoped coordinator 和 one-pass exact route 不依赖候选。
- **候选实现：**资格模块采用水平 full-input-height intermediate 与纵向 core XOR 两个 WGSL pass，共用
  一个 encoder/submit，只 map 一次 final XOR。50 组 tail、非 32 对齐、edge、dense、checker 和
  确定性随机输入与 one-pass 逐 word exact；4096² candidate buffer plateau 为 8,388,656 bytes，
  one-pass 为 6,291,504 bytes，差值为 2 MiB intermediate，dispose 后均归零。
- **性能 no-go：**Linux X11、Chrome 150、RTX 3090、有头强制 Vulkan 下，2048²、3840×2160、
  4096² × radius `8/16/31` × 四类图案共 36 个 bucket，各两轮 3 warmup + 10 measured。只有 9/36
  同时满足“每轮 ≥10%、两轮平均 ≥15%”，27/36 未过门；2048² 的 12 个 bucket 全部失败，4K/4096²
  的局部收益也不能跨图案稳定成立。production 因此没有 separable route、crossover、intermediate、
  protocol selector 或 adapter-name workaround，继续只用 one-pass。
- **final one-pass：**2048²/4K、radius 31 各执行 100 次完整 production operation，p95 分别约
  28.1/48.9 ms，GPU capacity 稳定为 1,572,912/3,145,776 bytes，owner 始终为 1，Long Task 为 0，
  patch/save/reload exact，dispose 后 owner/buffer/session 归零。X11 默认无 flag 的 20 次请求全部以
  `adapter-unavailable` 使用 packed CPU，GPU allocation 为 0 且保存精确。
