## 背景与动机

`annotation.group_id`（Ctrl+G 把 ≥2 个框绑成一组）承担了两个角色，应拆开处置：

- **角色 A · 批量编辑操作**（选中多框一起改 class/属性/锁定/隐藏）：**刚需，但不需要 group_id
  持久化**——前端多选（shift 点选 / 框选）即可「临时选区批量改」，改完即散。
- **角色 B · 持久的平等分组关系**（重开仍是一组、导出 `__group_id`、同色虚线圈）：**语义弱、场景
  罕见**。现实里「几个框相关」基本是三态：有主从→父子（v0.20.9）、同一对象跨帧→track（v0.21.2）、
  同类→class 相同。纯「平等且要持久绑」的中间态几乎无真实场景。

**决策：删角色 B（持久化 group_id），保留角色 A（退化为前端临时多选）。** 顺带**消解原命名冲突**
（系统里删掉标注 group 后只剩「用户组」一个 group，不再撞名）——故原 v0.20.12「用户组 `groups`
→ `user_groups` 改名」**作废**，不再需要。

**数据佐证（弱证据，需生产复核）**：本地库 17 条 active 标注，`group_id` 使用为 0（图像编组 + 跨帧
均为 0）。样本小、非生产结论，但方向一致：连开发过程都未使用该功能。**删列前须查生产库
`group_id < 1e9` 的真实用量复核。**

## 依赖（硬前提）

- **必须在 v0.21.2 之后**。删除前 `group_id` 还背着视频/3D 跨帧对齐（`interpolateRange` +
  `propagate` 高位段 `>= 1e9`）。v0.21.2 把这块迁到 `track_id` 之前动 group_id 会**砸掉视频/3D 跨帧
  插值**。本版是 v0.21.2 的收尾。

## 工作项

### WS1 · 前端：批量编辑退化为临时多选

- 移除 / 改写 Ctrl+G、Ctrl+Shift+G（`hotkeys.ts:55-56`）——不再产生持久 group。
- 批量改 class/attributes 复用**现有多选 + `bulk-update`**（去掉 group 相关字段），保住「一次改多框」
  这个刚需（角色 A）。
- 移除同 group 的同色虚线外圈渲染（`groupOutlineColor`，`ImageStageShapes.tsx:84-98`）。

### WS2 · 前端：侧栏去 group 分桶

- `AIInspectorPanel`（`AIInspectorPanel.tsx:963-996`）去掉 `group_id` 分桶逻辑，纯平铺——**与
  v0.20.9 的父子缩进天然协同**（那一版本就要重构这段分桶，本版顺势移除 group 维度）。

### WS3 · API 下线

- 下线 `POST /annotations/group`、`POST /annotations/ungroup`（`annotations.py`）。
- `bulk-update` 去掉 `group_id` / `group_id_explicit_clear` 字段（`annotationGroup.ts` + 后端），
  保留批量改 class/attributes/z_order/lock/hide 的能力。

### WS4 · 导出

### WS5 · 数据模型（破坏性，放最后）

- 新建 alembic 迁移：`drop column annotations.group_id`、`drop column tasks.next_group_seq`、

  0075/0097**（新建 drop 迁移）。
- **前提闸**：v0.21.2 已把 `group_id >= 1e9` 跨帧迁 `track_id`；`group_id < 1e9` 图像编组经生产
  复核确认可弃。
- 稳妥起见可分两步：先停止写入（WS1-3 上线，前端/API 不再产生 group_id）→ 观察一个版本 →
  再 drop column。dev 零使用可直接删；生产按复核结果定。

## 风险

- **强依赖 v0.21.2 先行**——顺序颠倒会砸视频/3D 跨帧。
- **删列不可逆**：建议「先停写、后删列」两步；生产用量删前必须复核（本地样本不足）。
- `bulk-update` 去 group 字段时，**批量改属性能力不能丢**（那是保留的角色 A）。
- 侧栏去 group 分桶要和 v0.20.9 父子缩进的改造合并做，避免两次动同一段。

## 验收

- 多选多个框仍能一次改 class/属性（临时选区，不落库）。
- Ctrl+G 不再产生持久 group；侧栏纯平铺 + 父子缩进。
- 导出无 `__group_id`；`/annotations/group`、`/ungroup` 返回 404。
- `annotations` 表无 `group_id` 列，跨帧语义全在 `track_id`。

## 不在范围

- 父子（v0.20.9）、track（v0.21.1/v0.21.2）——那是**保留**的关系表达，本版只删「平等持久分组」。
- 用户组 `groups` 表：本版删标注 group 后已无命名冲突，用户组维持原样（原 v0.20.12 改名作废）。
