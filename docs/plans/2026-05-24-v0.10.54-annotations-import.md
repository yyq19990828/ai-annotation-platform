## 1. 背景与问题

AAP JSON envelope 是**双数组**：`predictions[]` 已可导入（v0.10.15+），`annotations[]` 至今**只导出、导入仅警告日志**（[predictions_import.py:211-218](../../apps/api/app/services/predictions_import.py) 警告后跳过）。这导致「导出 → 迁移 → 导入」无法重建**人工标注**，只能重建预测——跨实例完整复制的最后一块缺口。

`AAPAnnotationEntry`（[aap_json.py:53-70](../../apps/api/app/schemas/aap_json.py)）导出端已写满字段：`geometry / class_name / tool_unit_id / attributes / confidence / source / user_id / created_at / external_id`。导入端要把这些落回 `Annotation` 表——难点不在 geometry（与预测导入共享 `internal_geometry_to_ls_shape` / `to_internal_shape`），**而在元数据归属与一致性语义**。

## 2. ADR 决策（已 Accepted）

6 点语义已在 **[ADR-0028 annotations 导入语义](../adr/0028-annotations-import-semantics.md)** 定调（2026-05-24 Accepted）：

| # | 决策点 | 结论 |
|---|---|---|
| D1 | user_id 归属 | 归当前操作者；源 user_id 存 `attributes._imported_user_id` |
| D2 | source 语义 | 保留 entry 原始 source（manual/prediction_based）+ `attributes._imported=true` |
| D3 | 冲突/去重 | append 默认；显式 overwrite 只清 `attributes._imported=true` 的标注，不碰人工；不做 external_id upsert |
| D4 | 审计 | 新增 `ANNOTATION_IMPORT`，每次导入汇总一条 |
| D5 | 过程元数据 | 只导 envelope 携带字段；was_cancelled=False、lead_time=null；created_at 有则保留 |
| D6 | 状态机 | 更新计数+is_labeled+pending→in_progress；**抑制 batch 自动流转** |

端点形态：**独立** `POST /projects/{project_id}/annotations/import`（权限/审计/响应与 predictions 不同）。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| user_id 跨实例无意义导致脏归属 | ADR 先定映射策略；默认不信任源 user_id |
| 覆盖/去重策略误删人工标注 | ADR 定保守默认（如 skip-if-exists）；overwrite 显式开关 + 二次确认 |
| 导入触发状态机产生意外副作用 | ADR 明确「静默落库 vs 走副作用」；测试覆盖 task 计数/状态 |
| 审计缺失导致大批导入不可追溯 | 复用 audit 动作；至少汇总一条 + 操作者记录 |
