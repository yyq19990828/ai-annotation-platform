# v0.21.11 · 审阅流水线：当前帧对象统一循环 + 焦点联动

状态：**计划（2026-07-05）**。修复视频工作台审阅时**「三类标注对象（AI 待审 / 人工 / 轨迹）循环割裂」**的
交互痛点：现在审一帧要在三套快捷键之间切心智，切完画布还不居中、右栏还不滚到对应行，找不到"我在处理哪个"。
**纯前端**（视频工作台交互层），不改后端 / schema / 落库路径，无 alembic。

与 [v0.21.9 视频预测审阅联动](2026-07-05-v0.21.9-video-prediction-review-linkage.md) 主题相关但量级不同：
v0.21.9 是"AI 结果**怎么呈现**"（时间轴密度 / 画布渲染 / 关键帧来源可辨），本计划是"审阅时**怎么在对象间
流转/决策**"。v0.21.9 呈现补齐后，本计划把审阅动作串成流水线。两者可独立排期；本计划的焦点联动（WS2）是
v0.21.9 侧栏高亮的自然延伸，落地时注意口径复用。

## 动机（现状：三套割裂循环 + 无焦点联动，全带证据）

### 断点 1 · 三类对象循环彼此割裂，无统一「当前帧对象环」
当前帧下的三类标注对象各有各的循环键，遍历各自的列表，**互不连通**：
- **Tab / Shift+Tab / J / K → `cycleUser`**：只循环人工框（`annotationsRef` 全量），
  `useWorkbenchHotkeys.ts:511-524`；keymap `hotkeys.ts:392-394`、`:44-47`。
- **X / Shift+X → `cycleAi`**：只循环 AI 待审框（遍历 `aiBoxes`），`useWorkbenchHotkeys.ts:526-534`；
  keymap `hotkeys.ts:398`、`:91-92`。
- **视频 Tab / Shift+Tab → `videoCycleTrack`**：只循环 `video_track_bbox` 轨迹，
  `useWorkbenchHotkeys.ts:416-424`；keymap `hotkeys.ts:320`、`:86-87`。

三者**共用同一个 `selectedId`**（`state/useWorkbenchState.ts:145-146`，注释 `:143`「选 AI 框时永远单选」），
但**没有一个键能在三类之间连续流转**——从人工框 Tab 不会跳到 AI 候选，审一帧要记住"人工用 Tab、AI 用 X、
轨迹用 Tab（视频）"三套心智。审阅节奏被键位切换打断。

### 断点 2 · 选中/循环切换后无「焦点对象」联动（画布不居中、右栏不滚动）
`cycleUser` / `cycleAi` / `videoCycleTrack` 切换时**只改 `selectedId`，不动 viewport**
（`useWorkbenchHotkeys.ts:511-534, 416-424`）。全 repo **无 `focusObject` / `centerOn` / `zoomToSelected` /
`scrollIntoView` 类联动**（仅 issue `highlightId` 沾边：`VideoKonvaStage.tsx:728`、`ImageStage.tsx:1818`）。
后果：
- 切到一个当前视口外 / 很小的对象，画布**不会把它居中或缩放对准**——视口操作是独立手动键（F=fit /
  0=实际尺寸，`VideoKonvaStage.tsx:547-555`；fitTick `useWorkbenchHotkeys.ts:326`）。
- 右栏 roster 是**单向**联动（读 `selectedId` 高亮行，`VideoTrackPanel.tsx:240-241`），但选中后**不会把该行
  `scrollIntoView`**——长列表里选中项可能在滚动区外，看不见高亮。
`selectedId` 事实上就是"当前处理对象"，但它只是"选中"，没升级成"焦点"（居中 + 滚动可见 + 高亮三合一）。

### 断点 3 · 采纳/拒绝后不自动前进，审阅无流水线手感
采纳/拒绝 AI 候选的键已有：**A → `acceptAi` / D → `rejectAi`**（`hotkeys.ts:447-448`，消费
`useWorkbenchHotkeys.ts:633-647` → `handleAcceptPrediction` / `handleRejectPrediction`）。但决策后
`selectedId` 或置空（reject 后 `setSelectedId(null)`，`:645`）或停在原地，**不自动前进到下一个未决对象**。
审阅 N 个候选要"选一个→按 A→再手动 X 选下一个→再按 A"，来回切键，无"看一个→决一个→自动下一个"的流。

## 定稿决策（拟）

- **断点 1 → 新增「当前帧对象环」统一循环**。把当前帧的三类对象合并成**一个有序环**：AI 待审
  （`frameAiBoxes`，当前帧 `video_bbox`，`VideoKonvaStage.tsx:300-306`）+ 当前帧人工框 + `resolveTrackAtFrame`
  命中的轨迹当前帧视图。一个键顺/逆循环，共用 `selectedId`。排序按空间位置（如左上→右下扫描）稳定可复现。
  **保留**现有 Tab/X/videoCycleTrack 分类键（老肌肉记忆不破坏），新增一个"全类环"键作上层流转。
- **断点 2 → 引入「焦点对象」联动**（本计划新基建，收益最大）。在 `videoStageControls.ts` 增
  `focusObject(id)`：把对象**居中到画布**（缩放策略：仅当对象出视口或过小才调，避免过度缩放丢上下文）+
  右栏对应行 `scrollIntoView` + 高亮。统一环循环 / 单类循环 / 侧栏点选**都走 `focusObject`**，让"选中"升级为
  "焦点"。与 v0.21.9 的侧栏高亮口径复用（同一 `selectedId` 驱动，别各写一套）。
- **断点 3 → 采纳/拒绝后自动前进**。`acceptAi` / `rejectAi` 决策后，把 `selectedId` 推进到"当前帧对象环"里
  下一个**未决**对象（跳过已决/已隐），并 `focusObject` 定位。形成"看一个→决一个→自动下一个"的审阅流水线。
  可配置开关（默认开），到环尾提示"本帧已审完"。

## 定稿架构（当前帧对象环 + 焦点联动）

```
useWorkbenchHotkeys / hotkeys.ts
  ├─ 现有分类循环 (保留): cycleUser(Tab/J/K) | cycleAi(X) | videoCycleTrack(视频Tab)
  └─ 新增: cycleAllInFrame(新键)  ← 当前帧对象环
        buildFrameObjectRing(frameIndex):
          [ ...frameAiBoxes(video_bbox@frame),
            ...当前帧人工框,
            ...resolveTrackAtFrame 命中的轨迹 ]
          → 空间排序 (左上→右下) → 稳定有序 id 列表
        next/prev → setSelectedId + focusObject(id)

videoStageControls.ts (新增 focusObject)
  focusObject(id):
    - 解出对象当前帧几何 (video_bbox / 轨迹插值框 / 人工框)
    - 出视口或过小 → 居中 + 适度缩放 (不过度)
    - 右栏 scrollIntoView 对应行 + 高亮 (复用 selectedId 驱动)

acceptAi / rejectAi (改: 决策后自动前进)
  handleAcceptPrediction / handleRejectPrediction 后:
    next = 环里下一个未决对象
    setSelectedId(next) + focusObject(next)  (环尾 → 提示"本帧已审完")
```

## 实现分阶段

- **WS1 · 当前帧对象环 + 统一循环键（断点 1）**：`buildFrameObjectRing(frameIndex)` 合并三类 + 空间排序；
  新增 `cycleAllInFrame` action 接进 `hotkeys.ts` keymap（择一不冲突的键，避开 Tab/X/A/D/,/./Home/End/F/0）
  + `useWorkbenchHotkeys.ts` 的 `dispatchKey` switch（`:309-319`）。保留现有分类循环键。
- **WS2 · 焦点对象联动（断点 2，新基建）**：`videoStageControls.ts` 增 `focusObject(id)`（居中 + 适度缩放 +
  右栏 `scrollIntoView` + 高亮）；统一环 / 单类循环 / 侧栏点选统一调用。缩放策略保守（出视口/过小才动）。
  与 v0.21.9 侧栏高亮口径复用。
- **WS3 · 采纳/拒绝自动前进（断点 3）**：`acceptAi`/`rejectAi` 决策后推进到环里下一个未决对象 + `focusObject`；
  环尾提示；配置开关（默认开）。
- **WS4 · 验证 + 版本**：E2E ① 统一键在当前帧三类对象间连续流转、切换即居中 + 右栏滚动可见；② 焦点联动在
  出视口/过小对象上正确居中、不过度缩放；③ 采纳一个 AI 候选后自动跳下一个未决、环尾正确收束；④ 现有
  Tab/X/videoCycleTrack/A/D 不回归。CHANGELOG + 版本 bump。

## 不在范围

- **图片任务的统一环**：首版聚焦视频工作台（三类对象 + 轨迹当前帧视图是视频特有语义）；图片任务的
  AI/人工两类合并环可后续复用同骨架，本计划不铺开。
- **v0.21.9 的呈现补齐**（时间轴预测密度 / 画布轨迹候选渲染 / 关键帧来源可辨）：正交，独立排期。
- **跨帧的审阅流水线**（审完本帧自动跳下一有内容帧继续）：本计划环只在**当前帧**内流转；跨帧续审是更大的
  流水线，另议（可与 v0.21.9 的"跳到下一个有预测的帧"导航拼接）。

## 风险

- **键位冲突**：Tab（人工/轨迹）、X（AI）、A/D（采纳/拒绝）、,/./Home/End（帧导航）、F/0（视口）已占
  （`hotkeys.ts` keymap）。统一环键须择空位，或复用某语义键并明确优先级，勿覆盖既有行为。
- **图片 vs 视频语义差**：`cycleUser` 是图片/通用、`videoCycleTrack` 是视频；统一环是**视频专属**新键，须与
  `ctx.videoMode` 分支对齐，别污染图片模式。
- **焦点缩放的"过度缩放"**：`focusObject` 居中若无脑缩放对准，会把上下文（相邻对象/整帧）挤出视口，反而
  更难审。策略必须保守：仅出视口 / 过小才调，且保留边距，优先"平移居中"而非"放大填满"。
- **自动前进的误操作感**：采纳后自动跳走，若用户想复看刚采纳的对象会措手不及。需开关 + 环尾明确提示 +
  可 Shift 反向回退，把"自动"做成"可控自动"。
- **环的稳定性**：`buildFrameObjectRing` 排序须稳定可复现（同一帧同一集合每次同序），否则循环顺序抖动、
  "下一个"不可预期。空间排序键要确定性（坐标 tie-break 到 id）。
