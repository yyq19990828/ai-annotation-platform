# v0.20.7 · 工作台桌宠像素化小人 + 皮肤扩展基座

状态：已实现 · 2026-06-30

## 背景

v0.20.6 已上线实验性的工作台桌宠：它替代选中信息卡的折叠小条，常驻画布，可拖动并记忆位置；
无选中时呼吸 / 眨眼，久坐冒泡，手工新增标注时短暂开心，标注数踩到里程碑时庆祝。

当前实现保持了正确边界：

- 入口：`apps/web/src/pages/Workbench/shell/pet/WorkbenchPet.tsx`
- 情绪状态机：`apps/web/src/pages/Workbench/shell/pet/usePetMood.ts`
- 文案池：`apps/web/src/pages/Workbench/shell/pet/petLines.ts`
- 默认外观：`apps/web/src/pages/Workbench/shell/pet/PixelSprite.tsx`
- 设置项：`apps/web/src/pages/Workbench/state/workbenchSettingsFields.ts` 的 `common.petEnabled`

问题是默认外观仍偏“紫色史莱姆小精灵”。用户希望工作台桌宠首先呈现为一个**像素化小人**，
后续可以支持自定义或切换皮肤。本版目标是收敛外观方向，并铺一层足够轻的皮肤扩展基座。
功能增强另拆到 v0.20.8，避免外观重塑和状态代理能力混在同一版里。

## 产品判断

工作台桌宠不是独立聊天助手，也不是 AI 面板或 `/ai-pre` 编排入口。它应继续是工作台里的低干扰状态代理：

- 有选中对象时，辅助表达当前选中信息卡的折叠态。
- 无选中对象时，以低频动效表达“工作台还在”。
- 对标注新增 / 里程碑给短反馈。
- 不触碰标注数据，不挂 mutation，不自动改项目配置。

外观上改成像素化小人后，应更像“标注员小助手”，而不是游戏角色或营销吉祥物。

## 目标

1. 默认桌宠从史莱姆式图形改为**像素化小人**。
2. 保留现有桌宠行为：举牌、点击展开、拖动、位置记忆、开心 / 庆祝 / 久坐冒泡、关闭开关、减少动态。
3. 把 sprite 渲染从单个 `PixelSprite` 拆成可扩展的皮肤基座，默认只启用 `pixel-human`。
4. 为后续“切换皮肤 / 自定义皮肤”留清晰接口，但本版不做复杂资产管理。

## 视觉方向

默认 `pixel-human` 建议：

- 尺寸：仍以 56px 视觉盒为主，避免侵占画布。
- 风格：清晰像素化小人，整图保持方块感，不走写实插画。
- 身份：小标注员 / 工作台助手，优先表达“专注、可靠、轻量陪伴”。
- 轮廓：大头小身，面部和手臂动作在小尺寸下可读。
- 配色：装扮以黑白为主，皮肤 / 头发只保留必要识别色，避免整只宠物只剩单一紫色或平台品牌色。
- 道具：可选一支小标注笔或小框选板；不要加文字、logo、复杂工具。

状态映射：

| mood | 外观表现 |
|---|---|
| `idle` | 站立、轻微呼吸、眨眼 |
| `idleTalk` | 轻微抬手或歪头，配气泡 |
| `holding` | 双手举牌或抱牌，牌面显示 `selectionTitle` |
| `happy` | 眯眼笑、轻微跳动 |
| `celebrate` | 开心跳起，保留小型庆祝符号 |

## 实现方案

### WS1 · 默认像素小人 sprite

- 新建 `PixelHumanSprite.tsx`，取代当前 `PixelSprite.tsx` 的默认使用。
- 继续用内联 SVG 或 CSS box/pixel 绘制，不引入图片资产首版依赖。
- 动效继续只用 `transform` / `opacity`，尊重 `prefers-reduced-motion`。
- 去掉当前落地阴影或改成极弱、硬边的像素底部暗块，避免画布上像浮层脏点。
- 庆祝符号必须小、短、贴近角色，不做大范围粒子。

### WS2 · 皮肤扩展基座

- 增加轻量注册文件，例如 `petSkins.ts`：
  - `id`
  - `label`
  - `renderSprite({ mood })`
  - 可选 `supportsReducedMotion`
- `WorkbenchPet` 不直接 import 某个 sprite，而是读取默认 skin 并渲染。
- 本版只注册一个可用 skin：`pixel-human`。
- 保留旧 `PixelSprite` 作为临时 fallback 或删除；若删除，需要同步测试快照和引用。

暂不把 skinId 写入后端偏好。后续真正有多个皮肤时，再把 `common.petSkin` 纳入 workbench config；
本版只把内部结构准备好，避免引入一个用户看不到的配置字段。

### WS3 · 气泡和举牌适配

- 像素小人举牌时，气泡仍显示 `selectionTitle`，但视觉上应像“举牌”而不是普通聊天气泡。
- 桌宠模式下，选中信息卡从举牌态展开后应遮住桌宠上半身，只露出下半身，呈现“桌宠驮着信息卡”的关系；展开 / 收起的视觉变化从中心发生；拖动桌宠时面板跟随，拖动展开面板时反推更新桌宠位置。
- 非桌宠模式下，选中信息卡缩起态不继续使用朴素文字小条，应改为按标题长度自适应的短信息胶囊：状态图标 + 选中标题 + 展开图标，保留拖动和键盘可达；胶囊应以展开面板中心定位，避免展开 / 收起时中心漂移。
- 多字类别继续单行省略，不撑大画布。
- `holding` 点击展开信息卡的行为不变。
- `aria-label` 继续说明“展开选中信息卡 / 工作台桌宠”。

### WS4 · 设置与文案

- `common.petEnabled` 设置说明从“常驻像素小精灵”调整为“常驻像素小人 / 工作台助手”。
- 文案池可保留，但建议删掉过度卖萌的句子，让它更像生产力工具：
  - 保留：喝水、休息、慢慢来、眨眼提醒。
  - 弱化：太拟人化、太游戏化、过度撒娇的语气。
- `CHANGELOG.md` 若落实现，应写到 `Unreleased`，描述当前系统状态，不写成后续版本说明。

### WS5 · 测试与验收

- 单测：
  - `WorkbenchPet` 仍能渲染默认皮肤。
  - `holding` 态点击仍触发 `onExpand`。
  - `common.petEnabled=false` 时仍回退纯文字折叠小条。
  - `usePetMood` 行为不变。
- 视觉检查：
  - 桌宠不会挡住右下隐藏 FAB 热区。
  - 折叠信息卡、举牌文字、气泡在深浅主题都清楚。
  - reduced-motion 下不再持续 bob / sparkle。
- 工程检查：
  - `pnpm typecheck`
  - `pnpm lint:css-tokens`
  - 相关 Vitest：`pnpm vitest run src/pages/Workbench`

## 后续扩展

### 皮肤切换

等至少有两个内置皮肤时再加：

- `common.petSkin`
- 设置里下拉或 segmented control
- 皮肤预览
- 默认值迁移

候选内置皮肤：

- `pixel-human`：像素标注员小人，默认。
- `pixel-cursor`：光标 / 框选锚点小人，偏工具感。
- `data-block`：数据块 / bbox 小助手，偏平台感。

### 自定义皮肤

不要在近期直接做“用户上传任意图片”。更稳的路线：

1. 先支持内置皮肤切换。
2. 再支持管理员注册静态皮肤包。
3. 最后再讨论用户上传。

自定义皮肤至少需要定义：

- 允许的资产格式：SVG 组件、spritesheet、或受控 JSON 描述。
- 每个 mood 的必需状态。
- 尺寸、透明背景、暗色主题可读性、reduced-motion fallback。
- 存储位置和权限边界。

## 不在范围

- 不做聊天输入框。
- 不接 LLM。
- 不自动修正标注。
- 不把 AI 面板能力搬进桌宠。
- 不把 `/ai-pre` 编排入口塞进桌宠。
- 不做用户上传皮肤。
- 不引入后端表或 migration。

## 验收

- 默认打开工作台时看到的是像素化小人，而不是当前史莱姆外观。
- 选中信息卡折叠后，小人举牌显示类别名，点击能展开完整信息卡。
- 手工新增一个标注仍触发短暂开心；里程碑仍触发庆祝。
- 关闭“工作台桌宠”后，折叠态回退纯文字小条。
- 代码结构已经能新增第二个内置 skin，而不需要改 `WorkbenchPet` 主逻辑。

- 新增 `petSkins.tsx`，默认注册 `pixel-human`，`WorkbenchPet` 通过 skin 渲染 sprite。
