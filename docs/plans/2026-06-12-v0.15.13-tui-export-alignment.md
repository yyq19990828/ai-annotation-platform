## 背景

当前 TUI 导出极简：`_do_export` 硬编码 `targets=["aap_json"]`（[app.py:1058](../../packages/python-sdk/src/ai_annotation/tui/app.py:1058)），无格式选择、无 `include_attributes`、无 `video_frame_mode` / `axis_frame`。而 web `ExportModal.tsx` 已支持按项目类型自适应的多格式多选 + 属性开关 + 帧模式。两点断层：

1. **选项断层**：后端 `POST /projects/{id}/export` 接受 `targets`（按模态分目录）、`include_attributes`、`video_frame_mode`、`axis_frame`，TUI 一个都没暴露。
2. **闭环断层**：TUI 触发导出后只跳 Jobs tab，job 详情屏（[app.py:184](../../packages/python-sdk/src/ai_annotation/tui/app.py:184) `_job_detail`）把 `result` 当裸 dict 打印，并提示「请用 `client.exports.download(...)`」——TUI 自己持有 client，完全可以自己下载。

另：`ConfirmModal`（[app.py:138](../../packages/python-sdk/src/ai_annotation/tui/app.py:138)）只有键盘 `y/n/esc`，**无按钮**，而 `DetailScreen` 已全按钮，风格不统一。

## 红线（沿用 SDK/TUI 既有三条）

1. **TUI 只消费 `Client` 公开 API**，绝不碰 `_http` / 内部实现。
2. TUI 限定在 `[tui]` extra，**可整体删除而不影响 SDK / CLI**。
3. **不复刻 web 表单**：导出框是「选格式 + 落地路径」这类轻配置，不引入项目/数据集创建等重表单。

## 数据可行性（待落地前核对 OpenAPI / `apps/api/app/api/v1/projects.py`）

后端 `POST /projects/{id}/export`（约 projects.py:1072）已确认接受：

- `targets: list[str]`，按 `project.data_type` 分模态校验（跨模态 target 后端 400）：
  - **image**：`coco` / `yolo-det` / `yolo-obb` / `yolo-seg` / `aap_json` / `voc`（voc 走同步返回，不建 job）
  - **video**：`video_json` / `mot` / `kitti` / `yolo-frames-det` / `aap_json`
  - **lidar**：`aap_json` / `kitti` / `nuscenes` / `pointmask`
- `include_attributes: bool`（默认 True）
- `video_frame_mode: "keyframes" | "all_frames"`（仅 video + 选 video_json 生效）
- `axis_frame: "iso" | "source"`（仅 lidar 3D box 生效；**web 尚未做，TUI 可领先**）
- 异步完成后 `job.result`：`download_url` / `expires_at` / `file_count` / `size_bytes` / `object_key` / `cache_hit`

> 核对点：上述取值全集 + result 字段名以源码/OpenAPI 为准；voc 同步返回路径本版**不在 TUI 暴露**（避免特例分支），TUI 格式目录排除 voc。

## 范围 A · 导出配置悬浮框 `ExportConfigModal`

新增 `ExportConfigModal(ModalScreen[dict | None])`，按 `project.data_type` 自适应渲染，确认时 `dismiss(config)`、取消 `dismiss(None)`。

- **格式目录**：模块级常量 `_EXPORT_TARGETS: dict[str, list[tuple[str, str]]]`（data_type → `[(target_id, 中文标签)]`），默认勾选项对齐 web（image→coco，video→video_json，lidar→aap_json）。
- **控件**（均为 Textual 公开 widget）：
  - 格式多选 → `SelectionList`（标题显示已选计数）
  - `include_attributes` → `Switch`（默认开）
  - `video_frame_mode` → `RadioSet`（keyframes / all_frames），**仅 video 且勾了 video_json 时挂载**
  - `axis_frame` → `RadioSet`（iso / source），**仅 lidar 时挂载**
  - 输出路径 → `Input`，默认 `./{project.display_id}-export.zip`
- **接线**：`action_export` / `_confirm_and_export` 改为 push `ExportConfigModal`；回调拿到 config（含 targets/选项/out 路径）→ thread worker `_do_export(project, config)`。
- `_do_export` 改为读取 config：`exports.create(project.id, targets=config["targets"], include_attributes=..., video_frame_mode=..., axis_frame=...)`（None 的选项不传，沿用 `create()` 的 `_drop_none`/缺省语义）。config 里记下 `out` 路径，供 B 档「完成后下载」。
- 空选校验：未勾任何格式 → 确认按钮禁用 / 状态栏提示，不发请求。

## 范围 B · 导出闭环（详情屏内下载 + result 结构化）

- **result 结构化**：新增 `_export_result_summary(job)`，把 `file_count` / `size_bytes`（走 `_fmt_size`）/ `cache_hit` / `expires_at` 排版展示，替换 `_job_detail` 里裸 `result` dict 的打印（仅对 `kind=="export"` 的 job 用结构化分支，其它 job 保持原样）。
- **下载按钮**：`push_job_detail` 对「`kind=="export"` 且 `status=="completed"` 且 `result.download_url` 存在」的 job，加动作按钮 `("download", "⬇ 下载到本地", "success")`。
- **下载流**：点击 → 弹一个轻量 `PathInputModal`（`Input` + 确认/取消，默认 `./{job.id}.zip`）→ thread worker `client.exports.download(job, dest)` → 状态栏回显落地路径；失败进状态栏。
- **可选「完成后自动下载」**：A 档导出框加一个 `Switch`，勾选则 `_do_export` 里 `exports.wait(job_id)` 后直接 `download` 到 config["out"]（放同一 thread worker，带 `on_progress` 回状态栏）。默认关，避免长任务阻塞 worker 的预期外行为。

## 范围 C · `ConfirmModal` 按钮化 + `FormModal` 基类

- **`ConfirmModal` 加按钮行**：`compose` 内加 `Horizontal`，`Button("确认", id="ok", variant=...)` + `Button("取消", id="cancel")`，`on_button_pressed` → `dismiss(True/False)`；键盘 `y/n/esc` 保留（双通道）。
- **默认聚焦**：破坏性动作（取消 job）默认聚焦「取消」按钮、良性（导出）默认聚焦「确认」；回车 = 默认动作，降低误触。
- **抽 `FormModal` 基类**（轻量重构）：把「居中盒子 + border-title + 确认/取消按钮栏 + 双通道键盘」抽成基类，`ConfirmModal`（退化为纯文案）、`ExportConfigModal`、`PathInputModal` 复用。CSS 收敛到一处（参照现有 `_DETAIL_CSS` 集中式）。

## 范围 D · CLI `aap export` 对齐

`cli/export.py` 当前只接受单个 `--target`、无选项（[export.py:23](../../packages/python-sdk/src/ai_annotation/cli/export.py:23)）。改为：

- `--target` 可重复（`list[str]`），对齐多格式
- `--include-attributes / --no-include-attributes`（默认 True，对齐后端缺省）
- `--video-frame-mode [keyframes|all_frames]`
- `--axis-frame [iso|source]`
- `--wait / --no-wait`（默认 wait；`--no-wait` 只 create 返回 job_id，配合 `aap jobs wait` 异步跟）
- `--json` 保留

## 不在本版范围（明确划走）

- **按批次导出**（后端 `ExportService` 内部支持 `batch_id`、但端点未接该 query 参）→ 需后端协同，留 v0.16.x。
- voc 同步返回路径 → TUI 不暴露（CLI 经 `--target voc` 仍可用，但走后端同步分支，本版 CLI 不特判，若后端返回非 job 结构则报错提示，文档注明）。
- 导出预设保存 / 导出历史列表 → 留待后续（历史可借 `aap jobs list --kind export`，本版不做专用 UI）。

## 风险与取舍

- **定位漂移**：导出框越做越像 web。守住「选格式 + 路径」轻配置，不引入过滤/筛选等重表单（那些留给后续 + 需后端支持）。
- **自动下载阻塞 worker**：长导出 `wait` 会占住 thread worker。默认关闭「完成后自动下载」，默认仍是「触发 → Jobs tab 跟进 → 详情屏手动下载」，把长阻塞设为显式 opt-in。
- **voc 特例**：后端同步返回非 job 结构，TUI 不暴露、CLI 不特判；文档注明 `--target voc` 行为差异，避免引入分支复杂度。
- **Textual widget 依赖**：`SelectionList` / `RadioSet` / `Switch` 均为 Textual 公开 widget，维持「可整体删除」。
