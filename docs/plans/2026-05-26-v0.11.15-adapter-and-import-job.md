# v0.11.15 · SourceAdapter + 异步导入 Job + import API

> [epic 索引](2026-05-26-v0.11.14-16-dataset-import-connectors-epic.md) · 切片 2/3 · 依赖：[v0.11.14](2026-05-26-v0.11.14-connector-foundation.md)

> 本切片打通**端到端服务端拉取**——经 API 即可用连接器把数据导入数据集；前端 UI 在 v0.11.16。

## 目标

实现 `SourceAdapter` 抽象与两个实现（S3 / SFTP），把"从源读字节"接到现有数据集入库管线上，整个导入跑在 Celery 异步 job 里、可轮询进度、可取消。完成后用 `curl`/HTTP client 即可：选连接器 + 源路径 → 起 job → 进度推进 → 文件落 `minio-datasets` 并生成 DatasetItem/Task/缩略图。

## 现状

- 异步 job 基建已就绪：`apps/api/app/db/models/async_job.py::AsyncJob`（kind/status/progress_pct/payload/result/celery_task_id）、`apps/api/app/api/v1/async_jobs.py`（list/detail/cancel）、`apps/api/app/workers/signals.py`（生命周期兜底）。
- 入库管线已存在但耦合在同步 scan 里：`apps/api/app/services/dataset.py::scan_and_import()`（line ~241）做了"list 桶 → 去重(content_hash) → 推断类型 → 读尺寸 → 建 DatasetItem → 建 Task → 派发缩略图/视频元数据"。需**抽出可复用的"单对象入库"函数**。
- Celery 媒体任务：`apps/api/app/workers/media.py`（generate_thumbnail / generate_video_metadata）；app 配置 `apps/api/app/workers/celery_app.py`。
- 连接器：v0.11.14 的 `StorageConnection` + `connector_guard` + 解密。

## 后端改动

### 1. SourceAdapter 抽象
- 新建 `apps/api/app/services/sources/base.py`：
  - `SourceObject` dataclass：`relpath, size, mtime, etag?`
  - `SourceAdapter` 抽象：`list(path, recursive, include_globs) -> Iterator[SourceObject]`、`open(relpath) -> IO[bytes]`（流式）、`close()`。
- `apps/api/app/services/sources/s3.py::S3CompatibleSource`：boto3 自定义 endpoint/凭据（参考 `StorageService`），`list_objects_v2` 分页，`get_object` 流式 body。
- `apps/api/app/services/sources/sftp.py::SftpSource`：paramiko `SSHClient`+`SFTPClient`，密码或 private_key，`listdir_attr` 递归遍历，`open()` 返回 SFTP 文件流。host key 校验（见安全）。
- `apps/api/app/services/sources/__init__.py::build_adapter(connection)`：解密凭据 → 过 `connector_guard`（白名单+SSRF 复检）→ 实例化对应 adapter。

### 2. 入库管线抽取（复用，不重写）
- 在 `DatasetService` 抽出 `ingest_one(dataset, relpath, stream, size) -> IngestOutcome("added"|"skipped"|"error")`：
  - content_hash 去重（流式算 hash 同时分块 upload 到 `minio-datasets`，避免整文件进内存）
  - 文件名冲突后缀处理、类型推断、读图像尺寸、建 DatasetItem（+file_count）、为已关联项目建 Task、派发 `generate_thumbnail`/`generate_video_metadata`。
  - 现有同步 `scan_and_import` 改为调用 `ingest_one`（行为不变，仅去重内部逻辑），保证两条路径单一真相。

### 3. Celery 导入 task
- 新建 `apps/api/app/workers/dataset_import.py::run_dataset_import(job_id)`：
  - 置 job running → `build_adapter` → `list()` 先数总数（或边扫边记，超大目录用估算）→ 逐对象 `open`+`ingest_one` → 每 N 个 / 每 X% 更新 `progress_pct` → 收集 `{added, skipped, errors[], total}` 写 `result` → completed/failed。
  - 协作式 cancel：循环内查 job.status，被 cancel 则停止并置 cancelled。
  - 上限护栏：`max_files` / `max_total_bytes`（config 配，默认如 50k 文件 / 200GB），超限失败并报清晰原因。
- 注册到 `celery_app.py` include 列表，跑在 `media`（或新 `import`）队列。

### 4. import API
- `apps/api/app/api/v1/datasets.py` 新增 `POST /datasets/{id}/import-from-connection`：
  - body：`{connection_id, source_path, recursive=true, include_globs?[]}`
  - 校验：调用者对 dataset 有权限 + 对 connection 可见 + `connector_guard` 预检 → 建 `AsyncJob(kind="dataset_import", payload={connection_id, dataset_id, source_path, ...})`（**payload 不含密钥**，task 内按 connection_id 重新解密）→ 派发 task → 返回 `{job_id}`。
- `async_jobs` cancel 白名单加入 `dataset_import`（`apps/api/app/api/v1/async_jobs.py`）。
- 前端 API/hook 留到 v0.11.16；本版只暴露 HTTP 接口。

## 安全

- **三处复检**：build_adapter / test / import 入口都过 `connector_guard`（白名单可能在连接器创建后被超管收紧）。
- **SFTP host key**：默认 `RejectPolicy` + 维护 known_hosts；首版可超管预置，或 TOFU 首次记录（在 system_settings 存指纹）。**不要用 `AutoAddPolicy` 静默接受**（MITM 风险）。
- **path 锁定**：`source_path` 必须在 connection 的 `base_prefix`/`base_path` 之下，规范化后再校验，拒绝 `..` 穿越。
- payload 落库不含任何明文密钥。

## 验证

- `uv run pytest`：
  - adapter 单测——S3 list/open（moto 或 mock）、SFTP list/open（mock paramiko）、path 穿越被拒、include_globs 过滤。
  - `ingest_one` 去重幂等（重复导入同 hash → skipped）、大文件流式不 OOM（断言不整读）。
  - import API 建 job + 鉴权 + 不可见连接器 403。
  - cancel：job 标记 cancelled 后 task 停止。
- 集成手测（docker）：超管建 S3+SFTP 连接器各一 → `POST import-from-connection` → 轮询 `GET /async-jobs/{id}` 进度推进 → 完成后 DatasetItem 数正确、缩略图生成、`minio-datasets` 有对象 → 重跑同源 job 全 skipped（幂等）。
- **改了 worker 业务代码 + 新 Celery 模块**：`docker restart` worker（本版未改 deps，无需 rebuild）；用 CLAUDE.md 的 `inspect.signature` 法确认 worker 跑的是新代码。

## 回退

import 路径独立，回退 = 删 import 路由 + dataset_import task + sources 包；`ingest_one` 抽取是内部重构，若需回退把 `scan_and_import` 还原即可（建议保留抽取，它本身无行为变化）。

## 备注

- 不做 `/browse`（源目录浏览）——本版让调用方手填 `source_path`，浏览作为 v0.11.16 或后续按需补。
- 视频/大文件走现有 media 管线，无需特殊处理；只要 `ingest_one` 流式上传即可。
