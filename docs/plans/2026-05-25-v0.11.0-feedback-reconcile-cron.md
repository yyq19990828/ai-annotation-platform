# v0.11.0 · 双写一致性对账 cron

> [epic 索引](2026-05-25-v0.11-annotation-feedback-convergence.md) · A 组（安全网）· 依赖：无 · 可与 B 组并行

## 目标

补上 ADR-0027 负向风险一节承诺、但从未实现的"每日对账"。双写过渡态可能横跨整个 v0.11，这是后续任何切单源动作的**前置安全网**——切单源前必须有证据证明双写长期一致，否则 backfill/停双写即引入静默数据丢失。

## 背景

- v0.10.20 已建 `v_annotation_feedback_unified`（UNION ALL 4 源 + `source_table` 列，alembic 0077）与三路双写 mirror，但一致性**裸奔无监控**。
- 现有 celery beat 参照：`ensure_future_prediction_partitions`（每月 25 日 03:30 UTC）。

## 后端改动

拆成两个可分别单测的部分：

1. **纯函数** `compute_feedback_drift(db) -> dict[str, DriftRow]`（建议落 `app/services/feedback.py` 或新 `app/services/feedback_reconcile.py`）：
   - 对 `v_annotation_feedback_unified` 按 `source_table` 分组计数，与各旧表"应 mirror 行数"对比，返回每源 `{expected, actual, missing_ids[]}`。
   - **drift 口径写进 docstring**，排除按设计就不该出现的行，避免误报：
     - `bug_reports.project_id IS NULL`（无项目归属，设计上不 mirror）
     - `annotation_comments.is_active = false`
     - `tasks.status != 'rejected' OR reject_reason IS NULL`
   - 纯查询、无副作用，便于单测断言。

2. **beat 包装** `reconcile_annotation_feedback`（每日 03:00 UTC，避开 03:30 的分区任务）：
   - 调 `compute_feedback_drift`；drift>0 时写 `audit_logs`（新 action 常量 `FEEDBACK_RECONCILE_DRIFT`，加到 `app/services/audit.py`）+ 调 `notification.notify_many` 通知所有 superadmin（payload 带各源 missing 计数）。
   - 在 celery beat schedule 注册（参照 `ensure_future_prediction_partitions` 注册位置）。

**改动文件**：`app/services/feedback_reconcile.py`（新）、celery beat 配置、`app/services/audit.py`（action 常量）。无 schema 变更、无 alembic。

## 验证

- `cd apps/api && uv run pytest tests/test_annotation_feedbacks.py`：补 2 例——
  - 正常态：4 源齐全 → `compute_feedback_drift` 全 0。
  - 人为制造 drift（插一条 bug 但不 mirror）→ 断言检出该源 missing=1 + `notify_many` 被调用。
- 手动：`docker restart ai-annotation-platform-celery-beat-1`（业务码挂载，无需 rebuild）后确认任务进调度；`uv run python -c "...compute_feedback_drift..."` 对 dev 库跑一次。

## 回退

纯新增 beat 任务 + 纯函数，无 schema 变更。回退 = 删任务 + 注销 schedule。低风险。

## 备注

refined-C（v0.11.8）下双写很快被拆：v0.11.9 撤掉 bug/reject 双写，仅剩 comment 双写到 v0.11.10 切完。所以本 cron 的核心价值是**为 comment 切单源前积累 drift=0 证据**，使命在 v0.11.11 收尾时终结（届时已无任何双写，连同 cron 一并删除；view 转为永久读表面、保留）。

> 即便价值窗口变窄，仍值得做：drop `annotation_comments` 不可逆，切前必须有"comment 双写长期一致"的客观证据。
