# v0.21.33 · 视频 `coco-frames-seg`

状态：**已实施（2026-07-12）**。启动闸门以 **COCO API（pycocotools）标准 instance segmentation** 作为
事实消费方满足并冻结字段合同（见下）——与已交付、无闸门的 `yolo-frames-seg` 对称：同样把视频逐帧多边形导成
标准分割数据集，只是编码从 YOLO txt 换成 COCO JSON。技术上是"帧展开机制 + COCO 编码机制"两套现成实现的桥接。

上游索引：[多几何 track 剩余切片](2026-07-12-multi-geometry-track-remaining-slices.md)。

## 启动闸门（已冻结）

- **消费方名称与版本**：COCO instance segmentation 标准，官方 reader `pycocotools`（`COCO(ann_file)` /
  `COCOeval`）；Detectron2 / MMDetection / Ultralytics 的 COCO 载入器均读同一 schema。
- **用途**：训练 / 评测 / 数据交换（通用 COCO 分割数据集）。
- **必需字段**：`images[]`（`id` / `file_name` / `width` / `height`）、`annotations[]`（`id` / `image_id` /
  `category_id` / `bbox` / `area` / `iscrowd` / `segmentation`）、`categories[]`（`id` / `name`）。
  **允许扩展字段**：image 的 `source_frame_index`、annotation 的 `attributes`（含 `__track_id`）——pycocotools
  `createIndex` 忽略未知字段，不影响加载。
- **是否接受 `attributes.__track_id`**：接受，作为可选扩展。仅 `include_attributes=True` 时输出，且仅当 track 有
  `track_id`（对齐图片 `export_coco` 的 `attributes.__track_id`）。`source` / `occluded` 不输出（无标准字段，
  不为猜测需求造扩展）。
- **是否需要所有采样帧包含空 `images[]` 记录**：需要。每个采样帧都建 image 记录（即使无 annotation），保证
  negative frame 参与训练、且 image 与 `fetch_frames.py` 抽帧结果一一对应。
- **读取产物的验证方式**：`pycocotools` 已加入 `apps/api` 的 **test extra 依赖**（`[project.optional-dependencies].test`，
  仅测试环境安装，不进运行时镜像）。测试用官方 `COCO` reader 实读产物：`createIndex()` 建索引验证引用完整、
  `annToMask()` 用官方 `maskUtils.frPyObjects` 解码我们写的 flat-ring `segmentation` 成掩码，证明格式合法可消费。
  同时保留轻量 **COCO 结构契约**断言（`image_id` / `category_id` 引用、`bbox` 4 元、`iscrowd ∈ {0,1}`）作快速回归。

## 背景与命名（已核对代码）

- 图片项目 `coco` 由 `ExportService.export_coco`（`export.py:579`）生成；视频项目当前不接受该 target。
- 视频已有 `yolo-frames-det` / `yolo-frames-seg`（`export_video.py`），帧按项目采样网格（`source_to_grid` +
  `resolved_track_frames`）展开，`fetch_frames.py` 抽取。
- 新格式命名固定为 `coco-frames-seg`，不复用 `coco`，避免同一 target 随 data type 改目录与帧语义。
- 首版只消费已存在的 `video_polygon` / `video_track_polygon`；raster mask 在 `v0.22.0` 后按合同扩展。

## 格式合同（冻结）

### `images[]`

每个采样帧一条：

- 全导出范围内确定且唯一的整数 `id`（按 sequence 顺序 × 网格帧升序自增，不依赖 Python `hash` 或未排序 DB 结果）；
- 真实 `width` / `height`（取 `video_metadata`，缺失回退 `FALLBACK_W/H`）；
- `file_name = images/{sequence}/{frame_no:06d}.jpg`，`frame_no` 与 yolo-frames 同为 **1-based**（`frame_start_number=1`）；
- 扩展字段 `source_frame_index` = 该网格帧对应的原视频帧号（`derive_sampled_frames` 序列）；
- 无标注的采样帧仍保留 image 记录。

### `annotations[]`

- `video_polygon`：`points ≥ 3` 且 `frame_index` 落网格才生成；
- `video_track_polygon`：经 `resolved_track_frames(all_frames)` 展开（outside 帧天然省略），每帧 `points ≥ 3` 且落网格才生成；
- `segmentation` = COCO 像素坐标 flat ring（归一化顶点 × `width/height`，单外环 `[[x1,y1,x2,y2,…]]`）；
- `bbox` = 顶点归一化外接框（`points_to_bbox_norm`）× 像素，`[x,y,w,h]` round 2；
- `area` = **`bbox` 的 `w_px * h_px`**（对齐图片 `export_coco:722`，**不**引入 shoelace 第二套 area 语义）；
- `iscrowd = 0`；`category_id` 由扁平 `cat_map`（`class_name → id`）查得；
- `include_attributes=True` 时写 `attributes`（含 track 的 `__track_id`）；bbox / polyline / `points < 3` 跳过，不伪装成 segmentation。

### `categories[]`

- `[{"id": i, "name": name}]`，`name` 取 `derive_classes_list(tool_bindings)` 顺序，与 yolo-frames 的 `cat_map` 同源；
- 不写 `supercategory`（视频扁平类别无可靠 tool-unit 来源，不猜）。

### 确定性

- writer 为**无时间戳纯函数**：`info` 不含 `date_created`（图片 `export_coco` 的 `info.date_created` 会让字节随时间漂移；
  本格式验收要求"相同输入字节稳定"，故省略）。相同输入两次调用输出字节相等。

### ZIP 布局

- 单 target：`annotations.json` 落包根；多 target：`coco-frames-seg/annotations.json`；
- 图片输出目录 `[{prefix}]images/{sequence}`（进 `frame_output_dirs`，供 `fetch_frames.py` 抽帧）；
- 复用根 `manifest.json` / `fetch_videos.py` / `fetch_frames.py`，不打包真实帧图。

## 工作项

### WS1 · 纯函数 writer（`export_video.py`）

- 新增 `build_coco_frames_seg(sequences, cat_map, *, include_attributes, description) -> dict`：
  - `sequences`：有序 `list`，每项 `{seq, tracks, bboxes, frame_count, step, img_w, img_h}`；`tracks`/`bboxes` 元素
    `(class_name, geometry, attributes, track_id)`；
  - 复用 `source_to_grid` / `resolved_track_frames` / `points_to_bbox_norm`（本模块内），**禁止**从 `export.py`
    反向 import（`export_packaging` 已依赖本模块，反向 import 成环）；像素 ring / area 用本模块内联小函数（不引 `export.py`
    的 `_flatten_ring`）；
  - image id / annotation id 稳定自增；空网格帧建 image、不建 annotation；
  - 返回 `{"images", "annotations", "categories", "info"}`，`info` 无时间戳。
- 非法 polygon（`points < 3`）、未知类别（`cat_map` 缺 → 0，对齐 yolo-frames）、缺视频尺寸（回退常量）与现有导出兜底一致。

### WS2 · 打包、target 与 manifest（`export_packaging.py`）

- `VIDEO_EXPORT_FORMATS` 增 `coco-frames-seg`（`clean_export_targets` 自动对视频接受、对图片/点云拒绝 400）；
- `build_export_zip` 的 `needs_ann` 集合（`:421`）增 `coco-frames-seg`（单文档需 per-task annotation）；
- `_build_video_export_zip`：
  - `has_coco_frames_seg` + 并入 `has_frame_sequences`（带 `fetch_frames.py`）与 `frame_start_number`（1-based）；
  - chunk 流式循环内累积 `coco_seq_records`（每 task 一条），`frame_output_dirs` 增 `{prefix}images/{seq}`；
  - 循环结束后写 `{prefix}annotations.json = json.dumps(build_coco_frames_seg(...), ensure_ascii=False, indent=2)`，
    `file_count += 1`；
- worker cache_key 用 `",".join(sorted(targets))`（`workers/export.py:203/297`），新 target 自动进 key，不新增旁路。

## 验收

- 两个视频、同名叶子文件、不同采样 step 的 image / annotation id 与路径确定且不冲突；
- 单帧 polygon、polygon track 插值、outside、off-grid、空帧、未知类别、混合几何（bbox / polyline 跳过）均有纯函数测试；
- 官方 `pycocotools.COCO` 实读产物：`createIndex()` 无异常、`annToMask()` 把每条 `segmentation` 解码成非空掩码；
  并保留结构契约断言（image_id / category_id 引用完整、字段齐全）；
- ZIP 集成测试覆盖单 target / 多 target、`annotations.json` 路径、`frame_output_dirs` 含 `images/{seq}`；
- 相同输入重复调用 writer 字节稳定（cache 友好 + 下游 diff 稳定）。
