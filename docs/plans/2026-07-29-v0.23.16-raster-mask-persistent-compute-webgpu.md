## 1. 本版决策

v0.23.16 不将 WebGPU 视为视频解码器，也不改动 Konva 视频底图。本版只处理已有数据
支持的 Raster Mask 大 ROI morphology，并把当前主线程同步路径改成持久 Dedicated
Worker 会话。

冻结决策如下：

1. **CPU Worker 会话是必交付项。** 即使 WebGPU 退出门失败，大图 tiled ROI
   morphology 也必须离开主线程，返回可直接进入 XOR history 的 tile patch。
2. **WebGPU 只做有界候选后端。** 首批只加速有实测证据的 `square dilate`，其他
   morphology 继续走 CPU Worker，不扩张 shader 面。
3. **默认构建不启用 WebGPU。** 不增加标注员可见开关；仅提供运维级实验环境变量，
   默认 false。默认路径不得调用 `requestAdapter()`。
4. **生产路由线不采用 R1.1 的 `1024²`。** 只有 ROI 至少 `2048²`、会话预算允许、
   adapter / device 已 ready 且 operation 受支持时，才可候选 WebGPU。
5. **首次操作不等 GPU 冷启动。** adapter / device 初始化可需 3–5 秒；初始化未完成时，
   当次操作立即走 CPU Worker，不阻塞编辑。
6. **不在每次 tiled morphology 后做整图 RLE 或全量 topology analysis。** 现有
   sparse editor 本就在保存时才 merge canonical COCO RLE；本版保持该合同，只返回
   exact changed pixels / bounds 与 XOR patches。
7. **WebGPU 候选退出门失败时删除生产实现。** 不保留一套默认不可达、无测试维护者
   的 shader 死代码；CPU Worker 收益独立保留。

## 2. 本版目的与成功定义

本版的目的不是“为了用 WebGPU 而用 WebGPU”，而是消除 tiled ROI morphology 的三类已知
成本：

- 主线程逐像素 materialize 和同步 morphology；
- 每次操作往返整幅 alpha 的 clone / pack / unpack；
- 计算结果与 XOR history 之间的二次扫描与重复存储。

v0.23.16 完成时必须同时满足：

1. 大图 `SparseMaskTileStore.morphologyRoi()` 不再在主线程调用
   `applyMaskMorphology()`。
2. Worker 以 immutable base RLE session + packed dirty tile overrides 重建精确 ROI，结果只回传
   non-empty `MaskHistoryPatch[]`。
3. Worker 返回的 XOR patch 同时是 UI 应用差量和 undo / redo 真值，不再为 morphology
   建 before checkpoint 后又扫描 after。
4. 开关关闭、无 `navigator.gpu`、adapter 为 null、device lost、预算不足、不支持的
   operation 都稳定走 CPU Worker，不变更标注语义。
5. WebGPU 中间失败时，同一请求可在 Worker 中使用已有 source 回退 CPU；若 CPU 也
   失败，store 零部分写入、history 零变化。
6. 默认构建在网络、GPU、Worker 请求数上与本版前等价，且不请求 adapter。
7. 实验构建在 `2048²` 和 4K 的两轮 10 次样本中，端到端 p95 相对新 CPU Worker
   至少改善 20%，且不得有单轮低于 15%。
8. 任何时刻每个 Raster Mask Worker pool 最多一个 GPU device 所有者；dispose 后 device、
   buffer、pending job 和 session 全部归零。
9. 20 次交替 CPU / GPU、取消、undo / redo 和保存后，资源计数进入 plateau，不以
   `performance.memory` 单一数值替代显式 buffer / session 计账。

## 3. 实测基线与准入理由

### 3.1 R1 / R1.1 计算核与 Worker 证据

RTX 3090 + 强制 Vulkan 的 `square dilate r2` 证明：

- 4K / 8K 单核 WebGPU p95 改善 68.1–69.0% / 77.3–77.5%；
- bit pack / unpack 移入 Dedicated Worker 后，两轮单核 crossover 均为 `1024²`；
- `512²` 单 tile 使用 WebGPU 比 CPU Worker 慢 46.3–67.6%；
- `GPUDevice.destroy()` 后 CPU fallback、取消、Worker 重建和 dispose 合同已通过。

### 3.2 R1.2 生产语义最坏路径

加入 512 tile transfer / materialize、production analysis / report、COCO RLE 和结果回传后：

| ROI         |  CPU p95 | WebGPU p95 | p95 改善 | 保守准入字节 |
| ----------- | -------: | ---------: | -------: | -----------: |
| `1024²`     |  50.5 ms |    41.0 ms |    18.8% |     9.50 MiB |
| `2048²`     | 162.7 ms |   116.3 ms |    28.5% |    38.00 MiB |
| `3840×2160` | 302.8 ms |   210.4 ms |    30.5% |    75.15 MiB |

同时存在两个不能忽略的反例：

- `1024²` 短样本两轮均出现 pack / unpack 尾延迟，p95 反而慢 96.2% / 108.7%；
- 单独 4K 运行中曾有一轮收益只有 17.7%。

因此 `1024²` 只能留在 CPU Worker；`2048²` 是下一阶段候选线，不是已承诺的生产
默认值。

### 3.3 为什么不照搬 R1.2 pipeline

R1.2 故意把 full analysis / report / RLE 纳入同一请求，用于测量最坏的 production-like
下限；但当前 tiled editor 的真实合同是：

- morphology 立即更新当前 ROI 和 XOR history；
- UI 只需要 changed / no-op 结果，不展示每次操作的全图 component / hole 报告；
- canonical RLE 在显式保存时由 `mergeTiles()` 生成；
- 未访问 tile 必须继续复用 immutable base RLE。

本版不得为了复刻 benchmark 而退化这些合同。

## 4. 范围与非目标

### 4.1 本版范围

- `SparseMaskTileStore` 的 current packed bits 与字节计费；
- Worker protocol 的 packed dirty override + ROI morphology job；
- Worker 内 CPU morphology 与 XOR patch 产生；
- morphology 结果直接构造 `MaskHistoryCommand`；
- Worker pool 内单一 morphology / GPU 所有者槽位；
- `square dilate` WebGPU packed bitset kernel；
- GPU buffer 懒初始化、容量复用、字节准入和释放；
- 运维级默认关闭的实验环境变量；
- capability-first routing、CPU fallback、device lost 与取消；
- 显式资源计数、分段延迟与基准；
- unit / Worker / store / browser 回归、开发与运维文档；
- 版本同步与 Unreleased CHANGELOG。

### 4.2 本版非目标

- 不用 WebGPU 解码 H.264 / HEVC；
- 不调用 Linux API / Celery 部署机器的 GPU；
- 不改造 Konva 视频底图或引入第二套视频 canvas；
- 不加速 dense editor、视频 Mask 或交互式 AI inline Mask；
- 不将 `512²` 单 tile 发送给 GPU；
- 不在 WebGPU 中实现 disk morphology、component labeling、hole counting 或 COCO RLE；
- 不把 `erode` / `open` / `close` 静默路由到只经过 `dilate` 验证的 shader；
- 不为标注员增加 WebGPU 开关或硬件明细 UI；
- 不保存 adapter name、driver 或其他高熵硬件指纹；
- 不使用 SharedArrayBuffer，不为此改造 COOP / COEP；
- 不用主线程同步大 ROI fallback 掩盖 Worker 故障；
- 不在未达退出门时默认开启。

## 5. 冻结语义与资源合同

### 5.1 ROI 与 halo

- core rect 继续由当前 viewport 裁剪到 image bounds；
- input rect 为 core 加 halo；`dilate` 的 halo = radius；
- 开放型操作不因贴边 tile 产生画布外前景；
- input pixels 继续受 `16,777,216` 上限保护；
- core 之外只是读取 halo，不得回写 history 或 dirty tile。

### 5.2 packed tile

`SparseMaskTile` 从只有 `baseBits` 扩展为：

```ts
interface SparseMaskTile {
  alpha: Uint8Array;
  baseBits: Uint8Array;
  currentBits: Uint8Array;
  revision: number;
  // existing ownership and budget fields...
}
```

规则：

- `alpha` 仍是 canvas / brush / picking 的当前 tile 真值；
- `currentBits` 是 Worker / history 传输真值，与 alpha 必须同 revision；
- brush / lasso 只更新 touched bounds 对应 bit，不每次重 pack 整 tile；
- undo / redo 对 `alpha` 和 `currentBits` 应用同一 XOR patch；
- dirty 判定直接比较 `currentBits` 与 `baseBits`，不扫描整个 alpha；
- `currentBits.byteLength` 进入 tile cache 字节预算，不得作为“免费镜像”。

### 5.3 计算预算

不修改 v0.23.10 的 tile cache 32 / 64 / 128 MiB 合同；新增独立的计算瞬时预算：

| 设备档位 | WebGPU compute budget | 候选最大 ROI | 路由                         |
| -------- | --------------------: | -----------: | ---------------------------- |
| Low      |                 0 MiB |          CPU | 不请求 adapter               |
| Standard |                64 MiB |      `2048²` | 只在实验 gate 开启时候选 GPU |
| High     |               128 MiB |           4K | 只在实验 gate 开启时候选 GPU |

说明：

- compute budget 是上限，不是预分配；
- 计费至少包含 JS packed source / output、GPU source / target / readback、uniform 与对齐开销；
- GPU buffer 只按容量增长，不随每个 job 重建；
- 容量增长前先准入；准入失败时当次 CPU Worker，不先分配再回滚；
- 降低设备档位、关闭 gate、device lost、Worker 替换和 dispose 立即销毁 GPU buffers；
- 运行时诊断同时报告 allocated bytes 与 budget bytes。

### 5.4 history 与保存

- Worker 回传的 non-zero XOR patch 使用现有 `chargeMaskHistoryPatches()` 计费；
- no-op 不创建 command，不提升 revision；
- command 进入现有 100 条 + 16 / 32 / 64 MiB history 上限；
- undo / redo 后 Worker 不保存隐式另一份可写 tile 真值；下一次请求继续以 store 传入的
  packed dirty overrides 为准；
- 保存仍只调用现有 `mergeTiles()`，本版不修改 canonical RLE 序列化和 API。

## 6. 架构与所有权

### 6.1 数据流

```text
useMaskEditor.runOperation
  → SparseMaskTileStore.morphologyRoi
      │  core / halo / budget / sourceRevision
      │  packed dirty tile overrides
      ▼
    RasterMaskWorkerPool.morphologyRoi
      → affinity slot 0
      → immutable base RLE session + on-demand ROI source
      → CPU Worker
          或 experimental WebGPU square-dilate
      → exact XOR tile patches + changed summary
      ▼
    SparseMaskTileStore.applyMorphologyPatches
      → alpha + currentBits + dirty + revision
      → MaskHistoryCommand
      ▼
    existing history / render / save
```

主线程不再构造连续 ROI alpha，也不接收整幅 ROI alpha。

### 6.2 Worker pool affinity

现有 pool 有 1–2 个 Worker。为避免两个 Worker 各自创建 adapter / device / buffer：

- `morphology_roi` 和 `webgpu_warmup` 只能调度到 slot 0；
- 任何时刻只有 slot 0 可以持有 GPU resources；
- slot 1 继续服务 analyze / compare / prefetch，不加载 WebGPU module；
- Low 档单 Worker 下，morphology 保持 editing 最高优先级；
- slot 0 crash / timeout 后用现有 replace 机制重建，重放 base RLE session，GPU 回到 idle；
- 正在运行的失败 job 不自动无限重试，store 保持未变。

### 6.3 WebGPU 模块边界

新增 Worker-only 模块：

```text
apps/web/src/pages/Workbench/stage/shared/rasterMaskWebGpu.ts
apps/web/src/pages/Workbench/stage/shared/rasterMaskWebGpu.test.ts
```

该模块只负责：

- adapter / device / pipeline 懒初始化；
- packed row-aligned bitset 的 `square dilate`；
- 单组可增长、可销毁的 source / target / readback / params buffers；
- device lost 通知、分段计时与字节快照；
- 幂等 `dispose()`。

它不读 React store、不管 history、不编码 RLE、不直接修改 tile store。

### 6.4 实验 gate

新增运维级环境变量：

```text
VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU=false
```

合同：

- 默认 / 空 / 非 `true` 值均为 false；
- false 时不 dynamic-import WebGPU module，不请求 adapter，诊断状态为 `disabled`；
- true 只表示“允许进入 capability 与路由判定”，不保证最终使用 GPU；
- 不增加 URL query、localStorage 或用户偏好开关；
- `.env.example` 与生成的 env reference 必须同步；
- 文档明确 WebGPU 使用浏览器客户端 GPU，不使用 Linux 服务端 GPU。

## 7. Worker 协议

### 7.1 请求

在 `rasterMaskWorkerProtocol.ts` 新增：

```ts
type RasterMaskMorphologyBackendPolicy = "cpu" | "webgpu-candidate";

interface RasterMaskPackedTileOverride extends RasterMaskTileRect {
  tileX: number;
  tileY: number;
  revision: number;
  bits: Uint8Array;
}

interface RasterMaskMorphologyRoiRequest {
  kind: "morphology_roi";
  id: number;
  sessionId: string;
  sha256: string;
  sourceRevision: number;
  core: RasterMaskTileRect;
  input: RasterMaskTileRect;
  operation: {
    operation: MaskMorphologyOperation;
    kernelShape: MaskKernelShape;
    radius: number;
  };
  dirtyOverrides: RasterMaskPackedTileOverride[];
  backendPolicy: RasterMaskMorphologyBackendPolicy;
  computeBudgetBytes: number;
}
```

请求中不传连续 alpha、canonical RLE 副本、GPU 信息或主线程回调。base RLE 继续由已注册
session 所有。

### 7.2 响应

```ts
interface RasterMaskMorphologyRoiResponse {
  kind: "morphology_roi";
  id: number;
  ok: true;
  sessionId: string;
  sha256: string;
  sourceRevision: number;
  backend: "cpu" | "webgpu" | "cpu-fallback";
  fallbackReason: RasterMaskWebGpuFallbackReason | null;
  changedPixels: number;
  changedBounds: RasterMaskTileRect | null;
  patches: MaskHistoryPatch[];
  metrics: {
    totalMs: number;
    materializeMs: number;
    computeMs: number;
    diffMs: number;
    allocatedGpuBytes: number;
  };
}
```

所有 `xorBits.buffer` 通过 transfer list 回传。响应必须通过 session / sha / sourceRevision / tile
dimensions 校验后才能应用。任一校验失败时丢弃整个响应，不部分应用 patch。

### 7.3 fallback reason

使用有界枚举：

```text
gate-disabled
unsupported-operation
below-pixel-threshold
budget-insufficient
navigator-gpu-unavailable
adapter-unavailable
initializing
initialization-failed
device-lost
gpu-runtime-failed
```

用户取消、Worker timeout / crash 与 stale response 继续使用现有 Worker error 类，不伪装成 GPU
fallback。

## 8. 路由、预热与恢复

### 8.1 候选 WebGPU 的全部条件

仅当以下条件同时成立时返回 `backend=webgpu`：

1. `VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU=true`；
2. secure context 且 Worker 内可访问 `navigator.gpu`；
3. operation = `dilate`、kernel = `square`、radius 在现有 `[1, 31]` 合同内；
4. input ROI pixels 至少 `4,194,304`；
5. input ROI pixels 不超过 `16,777,216`；
6. 设备档位不是 Low；
7. 估算 GPU bytes 不超过 compute budget；
8. device / pipeline 已 ready；
9. Worker 未 disposed，当前 job 未 abort。

任一条不成立就走 CPU Worker。

### 8.2 预热

- 只在 tiled editor 已安装、当前选中 morphology 且 viewport 达候选线时触发；
- 通过 `requestIdleCallback` 或同等可取消调度发送 `webgpu_warmup`；
- Worker 发起初始化后立即回复 `warming`，不 await adapter / device；
- 预热期间到来的 editing job 继续 CPU；
- 离开 tiled editor、切 task、取消工具或 gate 关闭时取消尚未开始的预热；
- adapter 不可用的结果在当前 Worker 生命周期内记忆，不每次操作重试。

### 8.3 device lost 与 runtime error

- `device.lost` 立即清空 pipeline / buffers，状态变为 `lost`；
- 若当前 GPU job 在 source packed bits 仍可用时失败，同请求改走 CPU 并返回
  `cpu-fallback`；
- fallback 之前不得应用任何 partial output；
- 一次 lost 后当前 Worker 生命周期不自动重建 device；更换 Worker 或显式诊断重试才可重新
  进入 idle；
- CPU fallback 也失败时返回稳定 Worker error，store / history 不变。

### 9.2 指标规则

- 只保留最新分段耗时与有界计数，不保留逐操作无界数组；

- 开关 false 时 `initAttempts` 必须始终为 0。

## 10. 故障矩阵

| 场景                         | 当次行为                          | 后续状态     | 必要断言                              |
| ---------------------------- | --------------------------------- | ------------ | ------------------------------------- |
| gate off                     | CPU Worker                        | disabled     | 零 adapter 请求                       |
| Low 档 / ROI 小于 `2048²`    | CPU Worker                        | 原状态不变   | 不触发预热                            |
| operation 非 square dilate   | CPU Worker                        | 原状态不变   | exact parity                          |
| `navigator.gpu` 缺失         | CPU Worker                        | unavailable  | reason 稳定                           |
| adapter = null               | CPU Worker                        | unavailable  | 当前 Worker 不重试                    |
| 初始化未完成                 | CPU Worker                        | warming      | 首次操作不等待                        |
| compute budget 不足          | CPU Worker                        | ready / idle | GPU 零超额分配                        |
| shader / pipeline 初始化失败 | CPU Worker                        | unavailable  | 不反复 toast                          |
| GPU job 中 device lost       | 同请求 CPU fallback               | lost         | 无 partial patch                      |
| GPU runtime error            | 同请求 CPU fallback               | unavailable  | reason = `gpu-runtime-failed`         |
| CPU fallback 也失败          | 操作失败                          | store 保留   | history 零写入                        |
| Abort / 切 task              | 终止 job                          | 旧响应丢弃   | next healthy job 可恢复               |
| slot 0 crash / timeout       | 拒绝当前 job、替换 Worker         | GPU idle     | base session 重放，旧 override 不残留 |
| dispose                      | 终止 pending / 销毁 GPU resources | closed       | owner / bytes / sessions 归零         |

## 11. 实施里程碑

### M0：基线冻结与实验代码收口

1. 先提交 R1 / R1.1 / R1.2 基准脚本、聚合数据与调研报告。
2. 固定 CPU golden、`2048²` 候选线、字节估算和 default-adapter fallback。
3. 为当前主线程 `morphologyRoi` 增加分段基准，记录 materialize / compute / apply /
   history，不只记总时间。
4. 审核实验 Worker 中哪些代码可转为 production module，不直接复制第二份 WGSL。

**M0 退出门：** 同一命令可重现研究数据，旧实验代码的去留有明确清单。

### M1：packed tile 真值与 XOR 应用

1. 为 `SparseMaskTile` 加入 `currentBits`。
2. brush / lasso / history 只更新 touched bits，dirty 改为 bits 比较。
3. 增加从 Worker XOR patch 原子应用 tile 的 store API。
4. 直接从 patches 构造 `MaskHistoryCommand`，复用现有计费和 retain / release 生命周期。
5. 将 `currentBits` 纳入 tile admission / eviction 测试。

**M1 退出门：** brush、lasso、undo / redo、保存 / 刷新逐像素一致；无预算逃逸；无双份
可写真值漂移。

### M2：CPU Worker ROI morphology

1. 扩展 protocol / runtime / pool 的 `morphology_roi` job 和 slot affinity。
2. Worker 用 base session + packed dirty overrides 重建 input ROI。
3. Worker CPU 路径复用 production `applyMaskMorphology()`。
4. 对 core 计算 XOR tile patches、changed pixels / bounds，只返回 non-zero patch。
5. `SparseMaskTileStore.morphologyRoi()` 切换到 Worker，移除主线程连续 ROI materialize /
   morphology / after scan。
6. 保留 MAX ROI、halo、abort、stale session 和 no-partial-write 合同。

**M2 退出门：** gate off 的生产默认路径已无大 ROI 主线程 Long Task；方形 / 圆形核与
dilate / erode / open / close 语义都与旧路径 exact parity。

### M3：WebGPU 候选后端

1. 从实验脚本抽取唯一 production WGSL 与 buffer owner。
2. 实现 Worker-only 懒初始化、single owner、buffer grow / reuse / dispose。
3. 实现 packed ROI assembly、`square dilate`、core diff 和 XOR patch 回传。
4. 接入环境 gate、`2048²` 门槛、Low / Standard / High 字节准入。
5. 实现 initializing / adapter unavailable / device lost / runtime error 的同请求 CPU fallback。
6. 使 benchmark 直接测量 production provider，不继续运行独立的实验 shader 副本。

**M3 退出门：** exact parity、默认零 adapter 请求、两轮 p95 性能门、失败矩阵和资源归零
全部通过。若失败，删除 production WebGPU module 与 gate，保留 M1 / M2。

### M4：长会话、E2E 与诊断

1. 补齐 slot 0 crash / replace、device lost、abort、切 task、关 gate、降档与 dispose 测试。
2. 以 8K sparse base 运行 20 次混合 brush / morphology / undo / redo / save。
3. 验证 worker / session / GPU owner / allocated bytes / history / tile cache 进入 plateau。
4. 在真实 Chromium 中验证操作期间无主线程 Long Task、取消后可恢复、保存刷新 exact。
5. 将资源快照接入现有 Raster Mask 诊断，不暴露 mask 内容。

**M4 退出门：** 20 次会话矩阵无资源单调增长；全部失败场景零部分写入；下一个健康
job 不需整页刷新即可恢复。

### M5：客户端资格、文档与发版

1. Linux X11 默认 Chrome 执行 adapter-unavailable + CPU fallback 矩阵。
2. Linux RTX 3090 强制 Vulkan 只作工程性能证据，不作生产支持声明。
3. 若可使用 MacBook，用无 Chrome flags 的原生有头 Chrome 访问 HTTPS 部署或 Mac 本地完整栈，
   跑 `2048²` / 4K 同一矩阵。
4. macOS 未验证不阻断 default-off 发版，但必须写入未验证项；它会阻断未来默认开启或
   客户端支持声明。
5. 同步 ADR、开发 / 运维文档、ROADMAP、Unreleased CHANGELOG 和版本源。
6. 完成运行栈版本验证、清理测试产物，在计划末尾补 `## Outcome`。

## 12. 测试计划

### 12.1 纯函数与 store

必须覆盖：

- bit set / clear / XOR 与 alpha exact parity；
- 31 / 32 / 33 位 word boundary；
- 511 / 512 / 513 位 tile boundary；
- 图像四边、裁剪 tile、空 Mask、全满 Mask、稀疏点和空洞 fixture；
- radius 1 / 2 / 31；
- core 与 halo 分离，halo 零回写；
- no-op 零 command / revision；
- patch 维度、sourceRevision、session / sha 不匹配时原子拒绝；
- currentBits / baseBits / alpha 在 brush、lasso、morphology、undo / redo 后始终一致；
- currentBits 字节进入 admission / eviction。

### 12.2 Worker / pool

- morphology affinity 始终为 slot 0；
- gate off 不 dynamic-import module，init attempts = 0；
- CPU 覆盖 square / disk + dilate / erode / open / close；
- WebGPU 只命中 square dilate，其余 stable CPU reason；
- adapter null / initialization failure / device lost / runtime failure 的同请求 fallback；
- 预算拒绝先于 GPU buffer grow；
- abort / timeout 替换 Worker 后 base session 重放；
- dispose 幂等、重复调用安全；
- transfer list 只包含 dirty packed overrides 与 non-zero XOR patches；
- 队列上限、editing priority 和既有 analyze / compare 调度不回归。

### 12.3 React / 用户链路

- tiled morphology 中 computing / cancel / idle / error 状态；
- stale result 不写入新 task；
- changed result 只建一条 history command；
- undo / redo 后 canvas / picking / dirty / save 一致；
- Worker / GPU 失败不丢失已有 draft；
- 保存 single-flight 期间仍禁止继续编辑；
- gate false 时不展示任何 WebGPU UI。

### 12.4 真浏览器矩阵

| 环境                         | gate | 必验证结果                                        |
| ---------------------------- | ---- | ------------------------------------------------- |
| Chromium default / X11       | off  | 零 adapter 请求、CPU Worker exact                 |
| Chromium default / X11       | on   | adapter unavailable、CPU fallback exact           |
| Chromium + unsafe Vulkan/RTX | on   | `2048²` / 4K WebGPU candidate exact + performance |
| Chromium + unsafe Vulkan/RTX | on   | device lost / cancel / dispose / budget matrix    |
| macOS Chrome no flags        | on   | 可用时精确 + 性能，不可用时精确 fallback          |

Mac 矩阵未执行必须标记 `not tested`，不得写成 fallback verified。

### 12.5 性能门

每轮 3 次预热 + 10 次记录，至少两轮：

- CPU Worker 对照与 WebGPU 使用同一 source / ROI / history 合同；
- 延迟从 UI 请求开始到 XOR patches 已应用、history 已入栈为止；
- `2048²` 与 4K p95 相对 CPU Worker 至少改善 20%；
- 任一单轮改善不得低于 15%；
- `1024²` 必须路由 CPU；
- 主线程 Long Task 为 0；
- 初始化未 ready 时的首次操作不得超过 CPU p95 + 10%；
- 20 次长会话后 GPU allocated bytes 不超预算，owner workers 始终 `<= 1`；
- dispose 后 allocated bytes / owners / sessions / pending = 0。

## 16. 风险与回滚

| 风险                           | 预防 / 检测                                            | 回滚                                        |
| ------------------------------ | ------------------------------------------------------ | ------------------------------------------- |
| alpha / currentBits 双真值漂移 | touched-bound 更新 + 全矩阵 parity + revision 断言     | 切回 Worker 内临时 pack，保留 CPU 正确性    |
| affinity 导致 slot 0 阻塞      | warmup 立即回复；editing priority；queue 诊断          | 关闭 GPU gate，保留 CPU morphology affinity |
| device / buffer 占用过高       | single owner + explicit bytes + admission-before-grow  | gate false 重建前端                         |
| WebGPU 语义边界不一致          | word / tile / image edge golden，radius 1 / 2 / 31     | 删除候选后端，CPU Worker 继续               |
| pack / unpack 尾延迟依然存在   | production 会话保持 packed truth；两轮 p95 和单轮下限  | WebGPU no-go，不以 p50 绕过 p95             |
| 取消 / stale 响应部分写入      | 响应先全量校验，然后单次应用 patches                   | 丢弃整个响应，draft 不变                    |
| Worker 替换后缓存过期          | base session 重放；dirty overrides 每请求由 store 传入 | 下一请求 CPU，不复用旧 GPU state            |
| 没有 macOS 无 flag 证据        | 文档标记 not tested；默认 false                        | 阻断默认开启和支持声明                      |

运行时回滚是将 `VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU=false` 后重建前端。这只回滚
WebGPU 候选路由；CPU Worker ROI 是本版的主交付，不依赖 GPU gate。
