## ⚠️ 已知回退缺口（已修，原始分析备查）

v0.11.2 复用 `CommentsPanel` 作 DiscussionPanel 子渲染器时，**未透传** 5 个 canvas/seek 相关 props：`backgroundUrl(taskFileUrl)` / `enableCanvasDrawing(enableCommentCanvasDrawing)` / `liveCanvas(liveCommentCanvas)` / `commentAnchor` / `onSeekFrame`。旧 flag-off 路径由 AIInspectorPanel 内嵌的 CommentsPanel 带着这些 props；v0.11.5 去 flag + AIInspectorPanel 瘦身后，旧路径消失，于是以下功能在新 DiscussionPanel 下断开：

1. **评论内画布批注（live drawing）**：从评论里"在画布上画标注"——`liveCommentCanvas` 桥接连到 image stage 的 CanvasDrawingLayer，源头在 `ImageWorkbench` 链路，DiscussionPanel 挂在 WorkbenchLayout 右栏属不同子树，需重新接线。
2. **画布批注预览背景**：`backgroundUrl` + `imageWidth/Height`（imageWidth/Height 在 model 中仍可得）。
3. **点评论跳帧（video）**：`onSeekFrame = s.setVideoFrameIndex`，model 中可得，低风险。

**风险分级**：③ + ② 低风险（值在 shell model 可得，透传即可）；① 高风险（跨 ImageWorkbench 重接 live 桥接）。

**为何没在本轮盲修**：① 跨组件树重接线，且 typecheck/eslint 通不过等于无保护——必须运行时验证（实际在工作台画一笔提交、video 点评论跳帧）才有信心。留作 v0.11 收尾前的独立修复切片 + 手动/e2e 验证，避免盲改引新 bug。
