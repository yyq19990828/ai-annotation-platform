## 1. 任务目标与背景

### 1.1 要做什么
给视频工作台画布加**右键上下文菜单**：右键**轻点**画布上的一条轨迹框 → 在光标处弹出该轨迹的常用操作菜单（标记消失/遮挡、锁定/隐藏、AI 传播、改类、拆框、删除当前关键帧 / 删除整条轨迹）。

### 1.2 为什么做（背景）
当前视频轨迹的几乎所有操作都集中在右侧 `VideoTrackPanel`，不常看侧栏的标注员每次都要把鼠标移到侧栏，效率低。CVAT 的解法是给同一操作多条到达路径（侧栏按钮 / 快捷键 / **右键菜单** / 画布内按钮），让用户不依赖侧栏也能干完活。

**关键事实**：右键菜单不是"视频侧没做"，而是**整个工作台都没有**——图片与视频三个 stage 的 `onContextMenu` 全都只是 `evt.preventDefault()`，全仓无任何坐标定位的 ContextMenu 组件。因此本任务做**通用右键菜单基建**（图片 stage 后续可复用），视频轨迹菜单是第一个消费者。

### 1.3 已就位的依赖（直接复用，勿重造）
> 以下件均已在 **v0.10.32**（commit `feat(web): move video track ops out of sidebar`，已在 `claude/video` 分支）落地——侧栏/画布浮动条/键盘快捷键三方已共用同一组 `trackActions`。本任务**只补"右键"这第四条路径，复用同一实现，不新增写入逻辑**。

- **`useVideoTrackActions`**（[stage/useVideoTrackActions.ts](../../apps/web/src/pages/Workbench/stage/useVideoTrackActions.ts)）：帧级状态变更的共享 hook，已在 [VideoStage.tsx:293](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx) 实例化为 `trackActions`，并经命令式 handle（[VideoStage.tsx:717-753](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)）暴露给快捷键。返回值（**你的菜单项直接调它们，写入逻辑不用自己写**）：
  ```ts
  trackActions = {
    selectedTrackHidden, selectedTrackLocked,
    currentFrameOutside, currentFrameOccluded,
    canEditSelectedTrack,                   // !readOnly && !locked && 有选中
    markSelectedTrack(patch),               // 底层
    toggleSelectedTrackOutside(),           // 标记消失/恢复
    toggleSelectedTrackOccluded(),          // 标记遮挡/恢复
    toggleSelectedTrackHidden(),
    toggleSelectedTrackLocked(),
    propagateSelectedTrack(),               // AI 传播 (需上游传 onPropagateTrack)
  }
  ```
  ⚠️ `trackActions` 的所有 toggle 都作用于**当前选中轨迹** `selectedTrack`。所以右键命中某轨迹后，**必须先把它选中**（见 §3.2 步骤 3），再让菜单项生效。
- **`VideoSelectionActions`**（[stage/VideoSelectionActions.tsx](../../apps/web/src/pages/Workbench/stage/VideoSelectionActions.tsx)）：已有的画布浮动按钮条，已接 `onChangeUserBoxClass` / `onDelete` / `onConvertToBboxes` / 上述 toggle。**它接收的 props 就是你菜单要用的同一组回调来源**，照搬即可。
- **`DropdownItem` 类型**（[components/ui/DropdownMenu.tsx:14](../../apps/web/src/components/ui/DropdownMenu.tsx)）：`{ id, label, icon?, kbd?, active?, onSelect?, divider?, disabled? }`，菜单项数据结构直接复用。⚠️ `DropdownMenu` 组件本身是**触发器锚定**（绑在某个按钮上），**不能**用于"光标坐标处弹出"，所以定位外壳要新建（§3.1）。
- **picking**：`pickTopVideoEntryAt<T>(entries, point)`（[stage/videoStagePicking.ts:19](../../apps/web/src/pages/Workbench/stage/videoStagePicking.ts)）做命中判定；`clientPointToVideoPoint(svg, {x,y}, viewBoxHeight)` 把屏幕坐标转视频坐标。VideoStage 内已有 `currentFrameEntries`、`selectedTrackGhost`、`overlayRef`、`pointFromEvent`。

## 2. 硬约束（回归红线）：右键 = 按住平移画布，宏观概念不能变

### 2.1 现状机制（务必先理解）
右键平移有**两个入口**，都最终调用 `beginPan`：
1. **视频画面内（SVG overlay）**：[VideoInteractionLayer.tsx:138-143](../../apps/web/src/pages/Workbench/stage/VideoInteractionLayer.tsx) `onPointerDown` 里 `evt.button === 2 → onBeginPan(evt)`。
2. **画面外 letterbox（黑边）**：[VideoStage.tsx:1197-1208](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx) root div `onPointerDown`，`button===2` 且不在 overlay 内 → `beginPan(evt)`。

`beginPan`（[VideoStage.tsx:1033](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)）：
```ts
const beginPan = useCallback((evt) => {
  evt.currentTarget.setPointerCapture?.(evt.pointerId);
  pausePlayback();
  setPlaybackOverlayVisible(false);
  setDrag({ kind: "pan", sx: evt.clientX, sy: evt.clientY });   // 记录起点
}, [pausePlayback]);
```
`onContextMenu` 在 overlay（[VideoInteractionLayer.tsx:174](../../apps/web/src/pages/Workbench/stage/VideoInteractionLayer.tsx)）和 root div（[VideoStage.tsx:1191](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)）都 `preventDefault()`，正是为右键拖拽平移时不弹浏览器菜单。

### 2.2 必须满足的判定表
| 操作 | 判定 | 结果 |
|---|---|---|
| 右键**拖拽** | 按下→抬起位移 ≥ 阈值（建议 5px） | 平移画布，**不弹菜单**（现状原样保留） |
| 右键**轻点**且命中轨迹框 | 位移 < 阈值 + 命中 | 在光标处弹菜单 |
| 右键轻点空白处 | 位移 < 阈值 + 未命中 | 不弹（本版本先不做空白菜单） |
| 任何情况 | — | 浏览器原生菜单始终被 `preventDefault` 抑制（现状不变） |

## 3. 实现方案

### 3.1 通用基建（一次性，平台级）

**新建 `components/ui/ContextMenu.tsx`（+ `.module.css`）**——坐标锚定的通用菜单外壳：
- Props：`{ open: boolean; x: number; y: number; items: DropdownItem[]; onClose: () => void; }`（`DropdownItem` 从 `DropdownMenu.tsx` 导入复用）。
- 用 `position: fixed` 定位到 `(x, y)`；**视口边界翻转**：若 `x + menuWidth > innerWidth` 则向左展开，`y` 同理向上。
- 关闭：`Esc`、点击菜单外部（document mousedown 监听）、选中某项后自动关闭。
- 渲染建议用 portal（`createPortal` 到 body）避免被 stage 的 `overflow` / transform 裁剪。
- 视觉尽量复用 `DropdownMenu.module.css` 的菜单项样式（icon + label + kbd + divider + disabled），保持一致；颜色**只用 `tokens.css` 已有 `--color-*`，禁止硬编码 / 禁止 fallback**（CLAUDE.md §6）。
- **不绑任何视频/轨迹概念**，纯展示，确保图片 stage 可作第二个消费者。

**新建 `pages/Workbench/stage/useCanvasContextMenu.ts`**——菜单开合状态 hook：
- 状态：`{ open, x, y }`，方法：`openAt(x, y)` / `close()`。
- 单纯管状态，不含业务，供各 stage 复用。

### 3.2 视频 track 接入（第一个消费者）

改 [VideoStage.tsx](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)，**只在 root div 的 `onContextMenu` 做菜单判定**（因为 contextmenu 事件从 overlay 冒泡到 root，root 一处即可同时覆盖画面内与 letterbox；overlay 的 `preventDefault` 保留不动）：

1. **记录右键按下坐标**：在 `beginPan`（§2.1）里加一行，写入新 ref：
   ```ts
   const rightDownRef = useRef<{ x: number; y: number } | null>(null);
   // beginPan 内：
   rightDownRef.current = { x: evt.clientX, y: evt.clientY };
   ```
   （`beginPan` 是两个平移入口的公共出口，一处记录即可覆盖 overlay + letterbox。）

2. **在 root div `onContextMenu`（[:1191](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)）替换 `preventDefault` 逻辑**：
   ```ts
   onContextMenu={(evt) => {
     evt.preventDefault();                       // 始终抑制浏览器菜单 (现状不变)
     const down = rightDownRef.current;
     rightDownRef.current = null;
     // 位移 ≥ 阈值 → 视为拖拽平移, 不弹菜单
     if (down && Math.hypot(evt.clientX - down.x, evt.clientY - down.y) >= 5) return;
     if (readOnly) return;
     // 命中判定: 用 contextmenu 坐标换算视频坐标后 pick
     const svg = overlayRef.current;
     if (!svg) return;
     const pt = clientPointToVideoPoint(svg, { x: evt.clientX, y: evt.clientY }, viewBoxHeight);
     const hit = pickTopVideoEntryAt(
       [...currentFrameEntries, ...(selectedTrackGhost ? [selectedTrackGhost] : [])],
       pt,
     );
     if (!hit || !isVideoTrack(hit.ann)) return;  // 仅轨迹弹菜单, 本版本不处理 video_bbox/空白
     onSelect(hit.ann.id);                         // 关键: 先选中, 让 trackActions 指向它
     contextMenu.openAt(evt.clientX, evt.clientY);
   }}
   ```
   - `viewBoxHeight` 的算法照搬 `pointFromEvent`（[VideoStage.tsx:1019-1024](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)）：`Number.isFinite(videoAspectRatio) && videoAspectRatio > 0 ? 1/videoAspectRatio : 9/16`。
   - `contextMenu = useCanvasContextMenu()`。
   - **不要动 [:1197 的 `onPointerDown`](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)、`beginPan`/`finishDrag` 的平移逻辑**——只加 ref 写入和 contextmenu 判定。

3. **构造菜单项并渲染**：在 `VideoSelectionActions` 渲染处附近（[VideoStage.tsx:1280](../../apps/web/src/pages/Workbench/stage/VideoSelectionActions.tsx)）加 `<ContextMenu>`，items 用 `trackActions` + 现有回调拼装（与浮动条同源）。**`kbd` 列填 v0.10.32 已存在的同义快捷键**（CVAT 风格，提升可发现性；这些键由 [hotkeys.ts](../../apps/web/src/pages/Workbench/state/hotkeys.ts) 处理，菜单仅做提示，**键位变了要同步**）：

   | 菜单项 label（按当前态切换文案） | onSelect | kbd | disabled 条件 |
   |---|---|---|---|
   | 标记消失 / 恢复显示 | `trackActions.toggleSelectedTrackOutside` | `O` | `!trackActions.canEditSelectedTrack` |
   | 标记遮挡 / 取消遮挡 | `trackActions.toggleSelectedTrackOccluded` | `Q` | `!trackActions.canEditSelectedTrack` |
   | （divider） | | | |
   | 锁定 / 解锁轨迹 | `trackActions.toggleSelectedTrackLocked` | `L` | `!onToggleLockedTrack` |
   | 隐藏 / 显示轨迹 | `trackActions.toggleSelectedTrackHidden` | `H` | `!onToggleHiddenTrack` |
   | AI 传播 | `trackActions.propagateSelectedTrack` | `Ctrl+B` | `!trackActions.canEditSelectedTrack \|\| !onPropagateTrack` |
   | （divider） | | | |
   | 改类别 | `() => onChangeUserBoxClass?.(selectedAnnotation.id)` | — | `readOnly \|\| !onChangeUserBoxClass` |
   | 拆当前帧为独立框 | `() => onConvertToBboxes?.(sel, { operation:"split", scope:"frame", frameIndex })` | — | `readOnly \|\| !onConvertToBboxes` |
   | 删除当前关键帧 | `deleteSelectedTrackKeyframe` | `Del` | `readOnly \|\| locked \|\| 当前帧无精确关键帧 \|\| 仅剩 1 个关键帧` |
   | 删除整条轨迹 | `() => onDelete?.(selectedAnnotation)` | `Ctrl+Del` | `readOnly \|\| !onDelete` |

   - 文案随当前态切换：`trackActions.currentFrameOutside ? "恢复显示" : "标记消失"`，遮挡/锁定/隐藏同理用 `currentFrameOccluded`/`selectedTrackLocked`/`selectedTrackHidden`。
   - icon 用既有 `Icon` 名（参考 `VideoTrackPanel`：`eyeOff`/`rect`/`lock`/`eye`/`bot`/`tag`/`scissors`/`trash`）。
   - 由于步骤 2 已 `onSelect(hit.ann.id)`，菜单打开后 `trackActions`/`selectedAnnotation` 已指向被右键的轨迹（React 下一次渲染生效；菜单项点击发生在打开之后，状态已更新，无时序问题）。

## 4. 验收口径
1. **回归红线**：右键**拖拽**（移动 ≥5px）画布平移行为完全不变——不弹菜单、不触发任何 track 操作、不弹浏览器原生菜单；letterbox 黑边处右键拖拽同样正常平移。
2. 右键**轻点**命中轨迹框 → 光标处弹菜单；该轨迹被选中（与左键点击一致）。
3. 菜单内每个操作的写入结果与侧栏 / 浮动条**完全一致**（同一 `trackActions` / 回调，无重复实现）。
4. `readOnly` 时 contextmenu 不弹菜单；轨迹锁定时"标记消失/遮挡/拆/删/改类/传播"相应 disabled，"解锁"仍可用。
5. 菜单超出视口边界自动翻转；`Esc` / 点击菜单外部 / 选中某项后关闭。
6. 暗色模式下菜单配色正确（`pnpm lint:css-tokens` 通过）。

## 7. 实现注意（踩坑提示）
- **时序**：`onSelect` 后 `trackActions` 在下一次渲染才更新；菜单项的 onSelect 在用户点击时才执行（此时已是后续渲染），故无需手动传 annotation，依赖选中态即可。若担心，可让 ContextMenu 渲染读最新 `trackActions`（它本就是 VideoStage 内的值，重渲染自然刷新）。
- **pointer capture**：平移时 `beginPan` 调了 `setPointerCapture`。验证 contextmenu 事件在 capture 释放后仍按预期在 root 触发；若个别浏览器不触发，改为在 `finishDrag` 里用 `rightDownRef` + 抬起坐标判定 tap 并打开菜单（备选路径）。
- **别破坏 letterbox 平移**：root `onPointerDown`（[:1197](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx)）的 `if (drag) return; if (button!==2) return; if (overlay.contains(target)) return;` 守卫保持原样。
- **最小改动**：除新建两个文件外，VideoStage 只加 `rightDownRef`、改 root `onContextMenu`、加 `<ContextMenu>` 渲染；不重构 drag 状态机、不动 VideoInteractionLayer 的平移分支。
