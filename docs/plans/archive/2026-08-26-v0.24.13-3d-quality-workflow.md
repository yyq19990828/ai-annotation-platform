## 1. 结论

本版本建立独立的 `PointCloudQualityRun / PointCloudQualityIssue` 领域，完整打通“冻结输入、异步扫描、结构化问题、工作台定位、人工处置与讨论”的质量闭环。它复用 `AsyncJob`、权限、审计和 `AnnotationFeedback`，但不复用 Mask QC 的二维区域表，也不把机器发现的问题降格为普通评论。

质量规则只产出证据和建议，不修改标注、SceneTrack 或存在区间。SceneTrack 的 `scene_track_id + revision + interval` 是轨迹类规则的权威合同；Annotation 是逐帧几何和版本的权威合同。

## 2. 转定稿核对

- 当前版本真值仍为 `0.24.11`，上一实现提交为 `90967693`；本计划分配下一个功能版本 `0.24.13`，本阶段只实现和提交，不在未授权时发版。
- 转定稿时工作树干净，没有需要覆盖的用户改动；Alembic head 为 `0156`，本版本迁移使用 `0157` 与 `0158`。
- SceneTrack 已具备 revision、显式/推断存在区间、成员外键和诊断器，轨迹缺口、类别漂移、重复帧成员可以依据领域真值计算。
- 现有 `MaskQC` 与 `VideoTrackQuality` 证明了 Run/Issue + AsyncJob 模式，但 locator、stale 与三维指标需要独立实现。
- 点云空间流式加载尚未提供稳定全局点 ID，因此“点掩码重叠”不在本版本产出；多相机投影残差等待持久化多模态对象合同。

## 4. 持久化合同

### 4.1 Run

`point_cloud_quality_runs` 保存：project、requester、AsyncJob、状态与进度、scope、规则配置 revision/digest/snapshot、source snapshot/digest、singleflight key、逐规则摘要、错误和时间戳。

scope 支持 `project / scene_ids / task_ids / annotation_ids`。创建时冻结以下信息：

- Annotation id、version、geometry digest、task、scene/frame、class、track 外键；
- SceneTrack id、track id、class、revision、presence mode 与 interval 版本；
- 点云 item id、content hash/file path 与轴约定；
- 规则 schema/version、阈值和启用状态。

`project / scene_ids` scope 拥有完整 Scene 成员，可执行逐框与轨迹规则；`task_ids / annotation_ids` 只执行所选标注可独立判定的逐框规则。窄 scope 不会用轨迹片段推断整轨事实，轨迹规则会以 `track_rules:scope_incomplete` 进入 run skip。

相同 singleflight key 的 pending/running/completed run 直接复用。worker 启动前复核 source digest；不一致进入 stale，不在过期输入上生成新事实。

### 4.2 Issue

`point_cloud_quality_issues` 保存 run / last_seen_run、project、scene、task、annotation、annotation version、SceneTrack revision、相关 annotation、source versions、规则 code/version、severity/status、frame 范围、metric/threshold/evidence、locator、suggested command、稳定 dedupe key、处置人/原因/时间戳。

状态为 `open / resolved / wont_fix / stale`。再次扫描命中同一 dedupe key 时更新 `last_seen_run` 和证据；源版本或配置变化时，读取问题会按持久化证据将旧问题标为 stale。局部规则跳过不会批量淘汰同 Scene 的其它问题。`resolved / wont_fix / reopen` 由 API 写审计，不执行建议命令。

locator 最少包含 scene、frame、task、annotation、SceneTrack、相机和辅助层；工作台必须可恢复问题现场。

## 5. 首批确定性规则

| code                     | 证据                                     | 默认行为与边界                                                                       |
| ------------------------ | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| `low_point_count`        | 框内有效点数                             | 二进制 PCD 精确计数；无法解析或抽样未知时记录 run skip，不制造 issue                 |
| `size_outlier`           | 同类长宽高稳健范围                       | 样本数达到下限后按 median/MAD 判断；统计异常不升级为 blocker                         |
| `ground_clearance`       | 框底面与局部地面分位差                   | 地面样本/置信度不足时 skip；区分穿地与悬浮                                           |
| `temporal_jump`          | 相邻成员 pose 补偿后的中心、尺寸、yaw 差 | 只比较同一存在区间的相邻成员；pose 缺失时证据显式标 `pose_mode=uncompensated` 并降级 |
| `track_gap`              | 声明存在区间内无成员的帧段               | explicit/inferred 均报告，但证据写明 presence mode；建议命令，不自动补帧             |
| `track_identity_drift`   | 轨迹级类别/外部 ID 与成员不一致          | 复用 SceneTrack 权威关系；定位首个漂移帧                                             |
| `duplicate_track_member` | 同一 SceneTrack 同帧多个活跃成员         | 列出所有冲突 annotation，不自动删除                                                  |

阈值来自冻结的 schema revision 1 配置。规则内核为无数据库副作用的纯函数，正反例固定夹具保证确定性。

## 7. API 与权限

- `POST /projects/{project_id}/point-cloud-quality/runs`：reviewer 及以上；project scope 仅项目管理员。
- `GET /projects/{project_id}/point-cloud-quality/runs/{run_id}`：读取进度和摘要。
- `GET /projects/{project_id}/point-cloud-quality/issues`：按 scene/task/annotation/track/frame/code/severity/status 过滤。
- `GET /point-cloud-quality/issues/{issue_id}`：返回完整 evidence/locator。
- `PATCH /point-cloud-quality/issues/{issue_id}`：`resolved / wont_fix / open`，wont-fix 必须填写原因。
- 通用 AsyncJob 取消端点支持 `point_cloud_quality`；worker 每个标注/轨迹边界直接读取数据库中的最新取消状态，不依赖长会话 identity map 缓存。

非项目管理员只能扫描和读取自己有权访问的 task；所有批量 scope 都在创建 run 时完整校验，不能把不可见对象泄漏进 source snapshot。

## 8. stale、幂等与失败语义

- source/config digest 决定 singleflight；同一快照重跑得到相同 code、metric、threshold 与 dedupe key。
- Annotation version、SceneTrack revision/interval version、点云 content hash 或配置变化都会使旧证据 stale。
- 取消、worker crash、输入过期和部分规则 skip 都有明确终态；skip 数和 reason 进入 run summary。
- 单帧点云无法读取时记录 scoped skip，继续处理其它帧；此类 skip 不影响无需点云的尺寸规则，也不会令既有问题失效。未处理异常才使 run failed。
- issue 写入采用稳定 upsert；worker 重试不制造重复问题。
- worker 只保留当前帧的解析点云；切换点云源即释放上一缓存，避免项目级扫描随帧数线性占用内存。

### 固定数据与浏览器

- nuScenes mini seed 中准备每条规则至少一个真阳性和一个真阴性，不把测试数据搬入仓库；规则单测使用等价的小型内存点集。
- 启动 project、scene、task 和 annotation scope run，观察 pending/running/completed/cancelled/stale。
- 问题面板按严重度/规则过滤；点击 issue 后时间轴定位到正确帧、选中正确框/轨迹并启用所需辅助层。
- 修改标注后旧 issue 显示 stale；resolve、wont-fix、reopen 和反馈讨论均保留审计。
- 运行前后 Annotation、SceneTrack 与 operation 数量除人工验收动作外不变，证明质量扫描没有写真值。

## 10. 非范围与后续触发

- 不自动修框、补帧、拆分/合并/终止轨迹或接受候选。
- 不实现 GT/Consensus、多相机投影残差或总分评级。
- 稳定全局点 ID 落地后再实现点掩码重叠；持久化多模态对象落地后再实现跨相机投影残差。
- 阈值评估未达解释性要求的规则保持关闭，不以“功能完整”为理由默认开启。
