# v0.11.9 · 撤除 bug/reject 冗余双写

> [epic 索引](2026-05-25-v0.11-annotation-feedback-convergence.md) · D 组（切单源）· 依赖：**v0.11.8 ADR 决策（refined-C）**

## 背景：决策反推的第一步

v0.11.8 决策（refined-C）确定：**bug 权威留 `bug_reports`、reject 权威留 `tasks`，统一读走 `v_annotation_feedback_unified` view**。它们**不**单源进 `annotation_feedbacks`。

那么 v0.10.20 加的两条 mirror（`mirror_bug_report` / `mirror_task_reject`）就成了纯负担——它们往 `annotation_feedbacks` 写入我们**不想要**的 bug/reject 行（该表最终只应装 comment + issue 原生反馈），且增加每条旧写路径的维护成本。本版撤掉。

> view 本来就 UNION ALL 了 `bug_reports` 和 `tasks(reject)` 源，所以**统一读完全不受影响**——这正是不需要物理合并的关键。

## 步骤

1. **删 mirror 调用**：移除 `tasks.py:1679` 的 `mirror_task_reject` 与 `bug_report.py:37` 的 `mirror_bug_report`。
2. **清理已 mirror 的存量行**：一次性 migration 删除 `annotation_feedbacks` 里 `kind IN ('bug','reject')` 的行（v0.10.20→现在被 mirror 进来的）。删完该表只剩 `kind IN ('comment','issue')`。
3. **mirror helper 处置**：`feedback.py` 的 `mirror_bug_report` / `mirror_task_reject` 函数可删（comment 的 `mirror_annotation_comment` 暂留，v0.11.10 切完再删）。

## 验证

- `cd apps/api && uv run pytest tests/test_annotation_feedbacks.py`（更新：删 bug/reject mirror 的测试，保留 view 仍能从源表 UNION 出 bug/reject 的断言）。
- `SELECT DISTINCT kind FROM annotation_feedbacks` → 只剩 comment / issue。
- `v_annotation_feedback_unified` 仍返回 4 类（bug/reject 来自源表）。
- BugReportDrawer 提交 / reject 流 e2e 不回归（源表写路径**完全没动**）。

## 回退

无损可逆：源表（`bug_reports` / `tasks`）从未被触碰；回退 = 恢复 mirror 调用（被删的 annotation_feedbacks 行可由后续 mirror 重新产生，或不恢复亦无影响）。

## 备注

本版**不动任何权威数据**，只是撤掉一个事后判定为多余的中间层。这是 refined-C 相比原 ADR「全表物理合并」省下的最大一块——bug 的 15 字段 / `BugComment` / `display_id` / `project_id IS NULL`、reject 的 task 状态机耦合，**全部不再是迁移对象**。
