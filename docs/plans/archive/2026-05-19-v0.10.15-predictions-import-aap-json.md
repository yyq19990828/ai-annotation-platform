# v0.10.15 · Predictions Import 端点 + 平台原生 AAP JSON

> 计划日期 2026-05-19 · 估 ~5d 合并窗口 · ROADMAP §A AI/模型 · 取经合集 §1.5 + §2.6 · P2

## Context

**为什么做.** 当前 `predictions` 行只能由内部 ML backend（Celery worker `_run_batch` → `PredictionService.create_from_ml_result`）写入。客户自家训好的模型 / 不愿托管在平台 backend 的场景（学术、初创、合规客户）无法把外部模型结果灌进来做"AI 预标 → 人工修正 → 导出"工作流。同时，平台目前导出只支持 COCO/YOLO/VOC 三种**有损**格式（attribute_schema、video keyframe source、prediction confidence、annotation_guide 都丢失），缺一个**无损**中间格式（AAP JSON）作为跨实例迁移 / SDK / Plugin / dataset snapshot 的稳定锚点。

**结合做的理由.** ROADMAP 明确"强烈建议同窗口做"：单做 Import 1.5d，合并 ~5d，多 ~3.5d 但顺手为 §3.1 SDK / §3.4 Plugin / §2.5 项目快照 / dataset snapshot 铺路；schema 一次性定型，避免后续二次破窗。

**预期结果.**
1. 新端点 `POST /projects/{id}/predictions/import`（COCO + AAP JSON 两种 input format），写入 `predictions` 表，`source='external_import'`。
2. AAP JSON 导出（project 级 + batch 级两个端点都接 `format=aap_json`）—— 双数组（`annotations[]` + `predictions[]` 分开，**不混 type 字段**），导出严格写满 null，导入 lenient 忽略未知字段。
3. AIPreAnnotate ProjectDetailPanel 加「导入预测」按钮 + 多步 Modal Wizard。
4. Dashboard ExportSection 加 AAP JSON 选项。
5. ADR-0024 记录 AAP JSON schema 决策（schema_version / 双数组 / lenient import / 与 datumaro 边界）。

**不在范围内**（已与用户对齐，留后续 epic）：
- `POST /annotations/import` 端点（AAP JSON `annotations[]` 字段保留导出，导入时只警告日志不入库；annotations import 单列下一版做，涉及 batch/owner/audit 协议复杂度）。
- Task 表加 `external_id` 字段（取经合集决策底线 §6"内部主键当稳定 ID"，本期用 `display_id` + `(project, file_path)` 两元组匹配够；external_id 留 v0.11+ 单列 epic）。
- ProjectTemplate 进 AAP JSON manifest（ROADMAP §A 单列触发条件，与 AAP JSON epic 同窗口仅约定 manifest schema 预留位）。
- datumaro 链转换（其他格式走 datumaro 中转，本期不引入）。

## 关键设计决策

### D1 · AAP JSON Schema v1.0 envelope

```json
{
  "schema_version": "1.0",
  "exported_at": "2026-05-19T10:00:00Z",
  "exported_from": {
    "platform": "aap",
    "platform_version": "0.10.15",
    "project_display_id": "P-12",
    "batch_display_id": "BT-3"
  },
  "project": {
    "name": "Traffic Sign",
    "type_key": "image-det",
    "classes_config": { "...": "..." },
    "attribute_schema": { "fields": [] },
    "rendering_config": {},
    "annotation_guide": "..."
  },
  "tasks": [
    {
      "task_match": {
        "display_id": "T-101",
        "file_path": "datasets/foo/img_001.jpg"
      },
      "external_id": null,
      "annotations": [
        {
          "geometry": { "type": "bbox", "x": 0.1, "y": 0.2, "w": 0.3, "h": 0.4 },
          "class_name": "stop_sign",
          "attributes": {},
          "confidence": null,
          "source": "manual",
          "created_at": "2026-05-18T..."
        }
      ],
      "predictions": [
        {
          "geometry": { "type": "bbox", "x": 0.1, "y": 0.2, "w": 0.3, "h": 0.4 },
          "class_name": "stop_sign",
          "confidence": 0.92,
          "model_version": "ext-yolov8-v1",
          "source": "external_import"
        }
      ]
    }
  ]
}
```

**决策要点（对照取经合集 §6 决策底线）：**
- `schema_version` 必备；breaking change 升 major（1.x → 2.0）。lenient 解析时 `schema_version > 1.x` 直接 422。
- `annotations[]` / `predictions[]` **分开两个数组**，不混 type 字段（CVAT 部分格式踩过坑）。
- 导出端写满 null（`"confidence": null` 而非省略），导入端 lenient 忽略未知 + 缺失按默认值。
- `geometry` 使用平台**内部格式**（与 `annotation.geometry` JSONB 对齐），不走 LabelStudio shape 的 `{type, value: {...}}` 嵌套。
- `task_match` 是 oneof：`{display_id}` 优先，`{file_path}` fallback；都给则 display_id 胜出（display_id 全局唯一，最稳）。

### D2 · Predictions 表 `source` 字段（alembic 0069）

```python
# apps/api/app/db/models/prediction.py
source: Mapped[str] = mapped_column(
    String(20), nullable=False, server_default="ml_backend", default="ml_backend", index=True
)
# 枚举值：'ml_backend' | 'external_import' | 'unknown'
```

**alembic 0069** 加列 + 老数据按 server_default 填 `'ml_backend'`（当前唯一出口是 ML backend，含义准确）。index 用于 admin failed-predictions tab 后续按来源筛。**不**加 pydantic Enum 类（保持轻量字符串，与 annotation.source 风格一致）。

### D3 · Task 匹配三段式服务

新建 `apps/api/app/services/task_matcher.py`：

```python
async def resolve_task(
    db: AsyncSession,
    project_id: UUID,
    match: dict,  # {"display_id": "T-101"} or {"file_path": "..."}
) -> Task | None:
    if display_id := match.get("display_id"):
        task = await db.scalar(select(Task).where(Task.display_id == display_id))
        if task and task.project_id == project_id:
            return task
    if file_path := match.get("file_path"):
        return await db.scalar(
            select(Task).where(Task.project_id == project_id, Task.file_path == file_path)
        )
    return None
```

匹配失败的 entry 进 `result.errors[]` 累计返回，不让整批失败（lenient import 精神）。

### D4 · Import 适配器：内部 geometry → LabelStudio result shape

现有 `PredictionService.create_from_ml_result(result: list[dict])` 接收 LS 格式（`[{type, value, score}]`），写入 `predictions.result` JSONB（apps/api/app/services/prediction.py:92-135）。

新建 `apps/api/app/services/predictions_import.py`：

```python
def _internal_geometry_to_ls_shape(geometry: dict, class_name: str, confidence: float | None) -> dict:
    """把内部 Geometry（bbox/polygon/multi_polygon）反向适配为 LabelStudio shape，
    以便复用 PredictionService.create_from_ml_result 的写入路径。"""
    kind = geometry.get("type")
    if kind == "bbox":
        return {
            "type": "rectanglelabels",
            "value": {
                "x": geometry["x"] * 100, "y": geometry["y"] * 100,
                "width": geometry["w"] * 100, "height": geometry["h"] * 100,
                "rectanglelabels": [class_name],
            },
            "score": confidence,
        }
    elif kind == "polygon":
        ...  # 同理
    elif kind == "multi_polygon":
        ...  # 复用 v0.9.14 已有 multi_polygon → LS 路径
```

**COCO importer**：复用 pycocotools 解析 → 转 internal Geometry → 走同一适配器。
**AAP JSON importer**：直接读 `predictions[].geometry` 内部格式 → 走适配器。

### D5 · 端点契约

```http
POST /projects/{project_id}/predictions/import?format={aap_json|coco}&dry_run={true|false}
Content-Type: multipart/form-data
  file: <JSON file>
  model_version: <optional string>  # AAP JSON 内 model_version 缺失时的兜底
  overwrite_existing: <bool default=false>  # 同 task 已有 external_import prediction 时是否替换

Response 200:
{
  "imported": 42,
  "skipped": 3,
  "errors": [
    {"task_match": {"display_id": "T-999"}, "reason": "task not found in project"},
    {"task_match": {"file_path": "x.jpg"}, "reason": "geometry kind 'polyline' not supported in v1.0"}
  ],
  "dry_run": false
}
```

`dry_run=true` 走全部校验路径但不入库，给前端 wizard 预览用。

**导出端点**：`/projects/{id}/export?format=aap_json` + `/projects/{id}/batches/{bid}/export?format=aap_json`，沿用现有 `apps/api/app/api/v1/projects.py:687` + `apps/api/app/api/v1/batches.py:843` 的 router 装配，仅在 `ExportService` 加 `export_aap_json()` 方法。

## 复用现成能力（不要重写）

- **`PredictionService.create_from_ml_result`**（`apps/api/app/services/prediction.py:92-135`）：写入路径直接复用，import 服务负责适配 geometry → LS shape 后调它。
- **`ExportService._load_data` / `_load_dataset_items`**（`apps/api/app/services/export.py:77-117`）：AAP JSON 导出共用现成数据加载。
- **Geometry pydantic union**（`apps/api/app/schemas/_jsonb_types.py:170-300`）：AAP JSON envelope 内 geometry 字段直接复用 discriminated union（但要派生一个 `extra="ignore"` 的镜像类供导入端 lenient 解析；导出端用原 strict 版本）。
- **AttributeSchema / ClassesConfig pydantic 类**（`_jsonb_types.py:81+`）：envelope `project` 字段直接复用。
- **`ImportDatasetWizard` drop 区交互**（`apps/web/src/components/datasets/ImportDatasetWizard.tsx`）：参考其文件 drop + progress 模式，但单文件、不分包，无需复用 `uploadQueue`。
- **`ExportSection`**（`apps/web/src/pages/Dashboard/ExportSection.tsx`）：加选项即可，不动结构。

## 不引入的反模式（决策底线 §6）

- ❌ AAP JSON `annotations[]` 和 `predictions[]` 混用 type 字段区分（CVAT 部分格式踩过）—— 永远双数组。
- ❌ 用 prediction.id / task.id 数字 UUID 跨实例匹配 —— 永远走 `display_id` + `file_path`。
- ❌ 导入端严格校验未知字段 —— 永远 lenient `extra="ignore"`。
- ❌ 把 predictor / pycocotools 加进 `apps/api` 主进程 —— pycocotools 是纯解析库可加，但**真实 ML 推理 / GPU 计算永远不在 apps/api**（ADR-0012）。
- ❌ 为了"灵活性"在 AAP JSON 里嵌 XML DSL / 自定义表达式 —— JSON Schema + JSONB classes_config 已经够。
