# Plan · 视频 AI 追踪「候选 / 接受」交互（方案 A · 暂存在 job 结果）

状态：**草拟 2026-07-10 · 版本锚点 v0.21.28**。接续 [v0.21.27 收尾](2026-07-10-v0.21.27-ai-propagation-ui-unify-and-pvs-full-interaction.md) 的 deferred 项「真正候选/接受纠偏」。用户已定 **方案 A（真候选流：先暂存、后接受/丢弃）**。

## 现状（为何要做）

视频 tracker 现在**直接落库**：job 完成时 runner 调 `_persist_tracker_results`（回填源轨迹 + 建 `source=ai_tracker` 新轨迹）→ `COMPLETED` → 前端 `invalidateQueries(["annotations"])` 重拉即见。**没有审阅环节**——传错了（漂移/跟错目标）已经污染 committed 数据。图片侧对比：AI 输出进独立 `predictions` 表（候选）→「接受」才转 annotation。

## 已锁决策

- **方案 A**（用户定）。子模型选 **暂存在 job 结果 JSONB**（非 A1 predictions 表 / 非 A2 候选 source）：
  - predictions 表逐帧、与视频多帧 `video_track_bbox` 几何不契合（A1 弃）；
  - 候选 source 标在 annotation 上，源轨迹回填只改**部分帧**、无法整条标 pending（A2 弃）；
  - **暂存 job 结果**：源轨迹回填 + 新轨迹**统一暂存**，committed annotations 零污染直到接受。
- **粒度**：整个 job 一个候选单元（接受全部 / 丢弃全部）。逐轨迹 / 逐帧接受留后续。

## 设计

### 数据流
```
QUEUED → RUNNING → PENDING_REVIEW (追踪完, 结果暂存 staged_result, 不碰 annotation)
                       ├─ accept  → ACCEPTED  (此时才 _persist_tracker_results → 落 annotation)
                       └─ discard → DISCARDED (annotation 零改动, 丢弃 staged_result)
        (FAILED / CANCELLED 仍为终态; CANCELLED 保留 staged 部分结果 → 也可 accept/discard)
```

### 后端
- **迁移**（alembic）：`video_tracker_jobs` 加 `staged_result JSONB NULL`；status 枚举加 `PENDING_REVIEW` / `ACCEPTED` / `DISCARDED`。
- **runner `run_tracker_job`**：完成 / 取消时**不再** `_persist_tracker_results`，改 `_stage_tracker_results`——把累计 `results`（每条 `{frame_index, geometry, confidence, outside, instance_id, primary}`）序列化进 `job.staged_result`，status=`PENDING_REVIEW`（取消=`CANCELLED` 但也存 staged）。事件仍发 `job_completed`（前端据此拉候选）。
- **accept 端点** `POST .../video/tracker-jobs/{job_id}/accept`：加载 job（须 PENDING_REVIEW / CANCELLED-with-staged）→ 反序列化 staged_result → `TrackerFrameResult` → 加载源 annotation → `_persist_tracker_results`（复用现有落库）→ status=`ACCEPTED` → commit → 发 `job_accepted`。幂等：已 ACCEPTED 直接返回。
- **discard 端点** `POST .../video/tracker-jobs/{job_id}/discard`：status=`DISCARDED`、清 staged_result、annotation 零改动 → 发 `job_discarded`。
- **单测**：`test_video_tracker_runner`/新测——完成后 annotation **未变** + job.staged_result 有内容 + status PENDING_REVIEW；accept 后 annotation 落库（主实例回填 + 新轨迹建）+ status ACCEPTED；discard 后 annotation 未变 + status DISCARDED；accept 幂等。

### 前端
- **`useVideoTrackerJobs`**：job 到 `PENDING_REVIEW`（原 COMPLETED）时**不再直接 invalidate annotations**，改拉 `staged_result` 候选、置候选态。
- **候选预览渲染**：把 staged 的源轨迹「将回填的帧」+ 新轨迹在画布 / 时间轴以**候选样式**（虚线 / 半透 / 「候选」角标）叠加渲染，与 committed 轨迹区分。复用视频轨迹渲染管线。
- **接受 / 丢弃 UI**：job badge 或轻量审阅条给「接受」/「丢弃」；接受 → 调 accept 端点 → 成功后 invalidate annotations（此刻才真正落库可见）；丢弃 → 调 discard 端点 → 清候选态。
- **组件测试**：候选态渲染 + 接受/丢弃调用 + 接受后 invalidate。

### E2E
- 真机：sam3_video_interactive / sam2_video 落点 → 发起 → job PENDING_REVIEW → 画布见候选预览（源 annotation 未改）→ 接受 → 落库可见；另一轮 → 丢弃 → annotation 零改动。

## 风险 / 边界
- **源轨迹回填的候选性**：源轨迹是既有 annotation，回填只改范围内帧。暂存模型把「将改的帧」留在 staged_result、accept 时才 merge，天然规避「整条标 pending」难题。
- **取消 + 部分结果**：CANCELLED 保留 staged（可 accept 部分）—— 与旧「取消即持久化部分」行为的差异：改为「取消即暂存部分、待审」。
- **跨窗续追不依赖落库**：relay 用内存 `last_geom_by_instance`（非 annotation），故延后落库到 accept **不影响**续追（已确认 `run_tracker_job` 逻辑）。
- **并发 / 幂等**：accept/discard 用 `with_for_update` 锁 job；重复 accept 幂等（已 ACCEPTED 短路）。
- **前端候选样式别与现有 AI 候选（图片侧虚线蚂蚁线）/ outside 渲染撞语义**。
