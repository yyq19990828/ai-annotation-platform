## 头号缺陷 · 打包层几何白名单把非 bbox 几何全丢了（已发版功能宣称不成立）

`export_packaging.py:1112-1121`（`_build_video_export_zip` 内按 task 分组）是**严格 `if/elif`、无 `else`**：

```python
geometry_type = (ann.geometry or {}).get("type")
if geometry_type == "video_track_bbox":
    tracks_by_task.setdefault(ann.task_id, []).append(ann)
elif geometry_type == "video_bbox":
    bboxes_by_task.setdefault(ann.task_id, []).append(ann)
# ← video_track_polygon / video_track_polyline / video_polygon / video_polyline 全部静默丢弃
```

**连锁后果（三条，逐条有据）：**

1. **v0.21.20 的 CHANGELOG 宣称不成立。** 该版本写道「polygon / polyline 轨迹可导出到 bbox 格式……逐帧降级为顶点外接框」。
   实际上 `points_to_bbox_norm`（`export_video.py:55-66`）+ `_frame_bbox`（`:69-74`）的 `points` 分支
   **在端到端链路上是死代码**——数据在打包层就被丢了，永远到不了这两个函数。它们只被纯函数单测覆盖
   （`test_export_video.py:193-240`），而 `test_export_packaging.py` 对 `video_track_polygon` **0 命中**，无集成测试防护。
2. **v0.21.21 的单帧 polygon/polyline 同样导不出**（本 epic 自己挖的坑）。
3. **目前唯一能导出非 bbox 视频几何的格式是 `aap_json`**（`export.py:908-915` raw geometry 透传，不做类型判别）。
   `video_json` 也丢（`export.py:477/523` 同款 if/elif）。

**因此：任何新序列化器都必须先放宽这个白名单，否则和 v0.21.20 的降级逻辑一样够不着数据。这是 PR1，性质是 `Fixed` 而非 `Added`。**

## 定稿决策

### 1 · PR1 先修白名单（`Fixed`），让既有降级逻辑生效

放宽 `export_packaging.py:1117-1121` 与 `export.py:477/523` 的类型判别，让 4 种 points 几何进入分组：

- 轨迹 points 几何 → `tracks_by_task`（`_frame_bbox` 的 `points` 分支随即生效，MOT/KITTI/yolo-frames-det 得到**顶点外接框**）。
- 单帧 points 几何 → `bboxes_by_task`，但**必须同时修 `_yolo_det_line` 的读法**：单帧 bbox 几何是扁平的
  `{type, frame_index, x, y, w, h}`（`_jsonb_types.py:411-425`），而 `VideoPolygonGeometry` 是 `{type, frame_index, points, holes}`
  （`:428-457`）**无 x/y/w/h** → 现行 `build_yolo_frame_det_labels:154` 直接把 geometry 当 bbox 传给 `_yolo_det_line:117-122`，
  `.get("x", 0)` 全取 0 → **导出全 0 空框**。修法：单帧分支比照 track 分支走一次 `points → points_to_bbox_norm` 降级。

**PR1 交付后**：所有 bbox-only 格式对全部 4 种 points 几何给出正确外接框，v0.21.20 的宣称**才真正成立**。
补 `test_export_packaging.py` 集成测试（喂 `video_track_polygon` + `video_polygon` 进 `_build_video_export_zip`）堵住回归。

### 2 · PR2 新增 seg 导出格式（`Added`）

bbox-only 容器装不下多边形，故新增视频 seg 目标。**建议 `yolo-frames-seg`**（而非视频 COCO）：

- 与既有 `yolo-frames-det` 同构（逐帧 txt、同一采样网格 / `frame_start_number` / 文件名约定，`export_packaging.py:1209`），
  增量最小；图片侧已有 `yolo-seg`（`YOLO_TARGETS:278`）可对齐行格式。
- 视频 COCO 需要新建 images/annotations/categories 三段结构 + 帧号↔image_id 映射，体量远大于本版本，
  且视频侧无既有 COCO 消费者。**若后续有需求再立项。**

加入 `VIDEO_EXPORT_FORMATS`（`export_packaging.py:69`）+ `_validate_export_targets`（`projects.py:1193`）。

### 3 · seg 序列化公共函数由本版本首建

现状是**两套平行实现、零复用**：

| 函数 | 位置 | 坐标 | 形状 |
|---|---|---|---|
| `_coco_segmentation` | `export.py:204-220` | **像素** | flat list（COCO 风格），只取外环、holes 未还原（`:207` 注释） |
| `_seg_rings_norm` | `export_packaging.py:303-316` | **归一化** | 嵌套 ring 列表（YOLO 风格） |

（AABB 计算也各一份：`export.py:_aabb_from_rings:154-167` vs `export_video.py:points_to_bbox_norm:55-66`。）

视频 seg 走 YOLO 风格 → **复用 `_seg_rings_norm`**，把它从 `export_packaging.py` 提为共享 helper，
供图片 `yolo-seg` 与视频 `yolo-frames-seg` 共用。**不新写第三份。** 轨迹几何先经
`resolved_track_frames` 解析到帧再序列化，与单帧共用同一序列化器。

### 4 · 帧维度归属沿用现状

单帧几何按 `geometry["frame_index"]` 映射到采样网格（`export_video.py:146-152`，网格外静默丢弃 `:150`）；
轨迹经 `resolved_track_frames` 展开后逐帧映射（`:161-168`）。**本版本不改采样语义。**

## 实现分阶段（PR）

- **PR1 · 修白名单 + 单帧 points 降级（`Fixed`）**：放宽 `export_packaging.py:1117-1121` / `export.py:477/523` 类型判别；
  单帧 points 几何补 `points_to_bbox_norm` 降级（否则全 0 空框）；补打包层集成测试。
  **交付物**：4 种 points 几何在 MOT / KITTI / yolo-frames-det / video_json 中导出为正确外接框。
- **PR2 · `yolo-frames-seg`（`Added`）**：`_seg_rings_norm` 提为共享 helper；新增格式 + 注册 + 校验；
  单帧与轨迹共用序列化器。
- **验证**（每 PR）：① 含 polygon/polyline（单帧 + 轨迹）的视频项目导出，下游可读；② **bbox 导出零回归**
  （MOT/YOLO/KITTI 逐格式比对）；③ 空几何 / 混合几何（bbox + polygon + track）项目导出不崩；
  ④ 采样网格外的帧仍静默丢弃、行为不变；⑤ `aap_json` 透传行为不变。CHANGELOG（`Fixed` + `Added`）+ 版本 bump。

## 不在范围

- **`video_keypoint` / `video_rotated_bbox` 导出**——inert schema，前端零产出，无数据可导（见盘点表）。待 v0.21.22 恢复后立项。
- **视频 COCO 格式**（COCO-seg video）——决策 2 已论证增量过大且无消费者。
- **真·栅格 mask 导出 / DAVIS packed-PNG**——v0.21.20 PR5，独立立项（`export_video.py` 无任何占位）。
- **图片侧 `_coco_segmentation` 与 `_seg_rings_norm` 的合并**——两者坐标域与形状均不同，合并是独立重构，
  本版本只提取 `_seg_rings_norm` 供复用，不动 COCO 路径。
- **改采样网格语义**。

## 风险

- **白名单放宽波及既有格式**：`video_json` / MOT / KITTI 突然多出此前被丢弃的行，下游若假设「只有 bbox」会受影响。
  但这正是修复目的（标注了却导不出是更大的 bug）；**须在 CHANGELOG `Fixed` 中明写行为变化**。
- **单帧 points 走 `bboxes_by_task` 的隐藏地雷**：不补降级就是**全 0 空框**（比丢弃更坏——下游拿到看似合法的空标注）。
  PR1 必须有针对 `video_polygon` 的 `_yolo_det_line` 单测。
- **零集成测试的历史包袱**：`test_export_packaging.py` 对 points 几何 0 命中，白名单 bug 才潜伏至今。
  PR1 补的集成测试是本版本最有价值的产出之一。
- **下游格式兼容**：`yolo-frames-seg` 行格式须与图片侧 `yolo-seg`（`_yolo_target_lines:343-348`）严格一致，
  否则训练脚本读不了。对齐现有已验证格式，不自创。
- **`holes` 丢失**：`_seg_rings_norm` 只取外环（与图片侧 `yolo-seg` 现状一致）。`VideoPolygonGeometry.holes`
  （`:435`）会被静默丢弃——**与图片侧行为一致，不是本版本引入的回归**，但应在文档注明。
