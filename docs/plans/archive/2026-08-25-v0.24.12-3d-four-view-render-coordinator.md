# v0.24.12 · 3D 四视图统一渲染与调度

> Status: implemented / functional verification complete; full performance sample pending
>
> Implementation authorization: yes
>
> Version: v0.24.12
>
> Baseline: `c13820b8`
>
> Architecture decision: [`ADR-0070`](../../adr/archive/0070-single-context-pointcloud-four-view-rendering.md)

## 1. 目标

把点云主透视视图与 Top / Side / Front 三正交视图收口到一个 Three.js renderer、一个图形
context 和一个渲染调度器。主视图停止永久 RAF；只有相机阻尼、点云或标注状态、三视图布局和精修状态
实际变化时才提交受影响的 pass。

本版解决的是渲染所有权重复，而不是取消多相机投影。四台相机在状态共同变化时仍需要四次 render pass，
但不再重复创建 renderer、GPU device、点云 attribute 上传、相机纹理 owner 和独立 fallback 熔断器。

## 2. 当前事实

- `PointCloudScene` 挂载一块主 canvas，并通过永久 `requestAnimationFrame` 每帧更新 OrbitControls、主 Scene
  和方向辅助器；静止后仍持续提交。
- `TriViewPanel` 另外创建 `TriViewRenderer` 和第二块 canvas。CPU 侧虽然引用同一个
  `BufferGeometry`，不同 context 仍会分别上传 GPU 资源。
- 三视图 renderer 独立处理 backend、device lost、viewport 原点、DPR、颜色 attribute 观察和 dispose；
  主视图与三视图因此可能显示不同实际 backend，并有两套状态恢复路径。
- 三视图浮窗受主点云 viewport bounds 约束，始终位于主 canvas 覆盖区域内，可以使用同一 canvas 的
  viewport / scissor 绘制。

## 3. 范围

### 3.1 单 renderer 四视图

- `PointCloudScene` 继续拥有唯一的 `PointCloudRenderer`、canvas、backend 状态与 device-lost 回调。
- 新增 `PointCloudTriViewPass`，只拥有正交相机、裁剪材质、点对象和三视图状态；它接收已有 renderer
  执行 render，不创建、销毁 renderer 或 canvas。
- 主、正交点对象引用同一个 `BufferGeometry`。两者允许使用不同材质以分别保持透视点径和正交像素点径；
  同一 context 内共享 attribute GPU buffer。
- `TriViewPanel` 只保留三行 DOM overlay、标题、坐标轴 glyph 与拖拽数学，将三行的 client rect、选中 PSR、
  冻结取景、zoom、点大小和可见状态下发给 `PointCloudScene`。
- 主 canvas 先绘制主 Scene，再在三视图内容区域清色/深度并按 scissor 绘制 Top / Side / Front；所有状态
  在结束后恢复到完整主 viewport。

### 3.2 事件驱动调度

- 用单个合帧 scheduler 替换永久 RAF，并区分 `main`、`tri-layout`、`tri-content` 脏标记。
- OrbitControls 的 pointer / wheel/change 事件启动主视图更新；启用 damping 时只在 `controls.update()`
  仍产生变化期间续帧，稳定后停止。
- TransformControls、加载/清空点云、颜色、点大小、网格、方向辅助器、框、参考框、邻帧点云、resize、
  视角动作和三视图状态都显式 invalidate。
- 同一个动画帧内的多次状态写入只产生一次提交；隐藏或折叠的三视图不提交正交 pass。
- 三视图产生可见变化时，同一 RAF 必须先重画主 Scene 再绘制 scissor pass；这是为了兼容 WebGPU 及其 WebGL2 fallback 延迟 clear 可能清空整个 swapchain 的语义。
- DOM rect 对 0.75 CSS px 内的重复测量视为同一布局；选中对象引用刷新不再触发布局重测。

### 3.3 诊断与回退

- Dev 环境在主 viewport 暴露 renderer 数、总提交数、主 pass 数、三视图 pass 数和最近提交时间，供 E2E
  与基准读取。
- backend badge 只显示唯一 renderer 的实际 backend；删除三视图独立状态和独立 circuit。
- renderer 初始化失败或 device lost 仍按 ADR-0068 重建 Legacy `PointCloudScene`，三视图随同一个 owner
  一起恢复。

## 4. 非范围

- 不移除 WebGPU 实验标记，不默认启用实验 renderer，也不删除 Legacy 路径。
- 不实现 WebXR multiview、自定义多相机 instancing、compute culling 或 GPU depth pass。
- 不引入 RenderTarget atlas；当前浮窗在主 canvas 范围内，直接 scissor 少一次纹理与合成 pass。
- 不改变三视图交互、坐标轴语义、缩放记忆、框体 mutation、相机投影、点云格式或后端 API。
- 不在本版实现 3D Quality、空间 tiling、点云 LOD 或持久化人工 2D 成员。

## 5. 数据流

```text
React / OrbitControls / TransformControls / point-cloud resources
                         │ invalidate(reason)
                         ▼
              PointCloudScene scheduler
                         │ one RAF
                         ▼
               one renderer / context
                 ├─ main Scene + perspective camera
                 ├─ axis gizmo viewport
                 └─ PointCloudTriViewPass
                      ├─ top scissor + orthographic camera
                      ├─ side scissor + orthographic camera
                      └─ front scissor + orthographic camera
```

不存在后端、数据库、公开 API、配置字段或用户偏好的新增实体。

## 6. 实施切片

### Slice A · 事件驱动主视图

1. 在 `PointCloudScene` 增加合帧 invalidate / render 调度和 Dev 计数器。
2. 把每个可见状态 mutation 接入 invalidate；OrbitControls 阻尼仅在真实变化时续帧。
3. 单元测试 scheduler 的合帧、稳定停机、dispose 取消和状态变化唤醒。

该切片独立可发布：即使不继续迁移三视图，主视图空闲提交也会归零。

### Slice B · 单 context 三视图 pass

1. 将 `TriViewRenderer` 的相机、裁剪、点径和三次 scissor render 提炼为
   `PointCloudTriViewPass`，移除 renderer factory、canvas、RAF、attribute watcher 和独立 circuit。
2. `PointCloudScene` 注册/更新/注销三视图 pass，并在同一调度帧内组合主 Scene、方向辅助器和三正交视图。
3. `TriViewPanel` 测量 row 的 client rect 并转成 render state；浮窗移动、resize、侧栏变化、折叠和展开都
   触发布局 invalidate。
4. 删除 `triRendererStatus`、第二 backend 文案与第二 canvas 生命周期。

该切片独立可发布：只改变 renderer 所有权，不改变标注数据或交互合同，代码回滚不需要数据迁移。

### Slice C · 守护、文档与浏览器验收

1. 更新点云 smoke / edit E2E，断言唯一 renderer canvas、idle 提交停止、三视图坐标与框实时同步。
2. 扩展 `benchmark-pointcloud-renderer.mjs`，记录 renderer owner、idle submit、主/三视图 pass、首次展开、
   rAF gap 和 GPU RSS plateau。
3. 更新 ADR、开发参考、用户文档、ROADMAP 与 `CHANGELOG.md`。
4. 用 nuScenes mini scene-0061 在真实浏览器依次验证切帧、选框、三视图展开/折叠、拖边/角、三轴旋转、
   三视图独立缩放、浮窗移动/resize、主视图 orbit 与相机上色。

## 10. 风险与回滚

- **浮窗与 canvas 坐标漂移**：统一使用 row client rect 减主 canvas client rect 的纯函数，并覆盖 DPR、
  WebGL 左下原点与 WebGPU 左上原点。浮窗移动时主视图与三视图一起 invalidate，先恢复旧区域再画新区域。
- **主 Scene 状态污染正交 pass**：每个 pass 明确保存并恢复 viewport、scissor、autoClear、裁剪和点径；
  正交 Scene 只包含点云，不渲染主框、网格、标签或 gizmo。
- **事件驱动漏刷新**：所有 mutation 先由测试覆盖再移除永久 RAF；Dev 计数器和 E2E 同时验证“该醒时醒、
  该停时停”。
- **性能反而回退**：任一 backend 超过 10% 回退门或出现内容丢失，不发布 Slice B；保留已独立通过的
  Slice A，恢复第二 renderer 代码不涉及数据回滚。
- **未来跨窗口三视图**：本计划假设三视图继续位于主 canvas 覆盖区；若以后 portal 到独立窗口，另立
  RenderTarget atlas / compositor 决策，不让本版预埋未使用的抽象。

## 11. 验证结果

- 调度器、三视图 pass 与时间轴回归单测通过；缩放三视图时会在同一 RAF 内先恢复主 Scene，
  0.5 CSS px 布局抖动不再重复唤醒渲染。
- 点云 smoke / edit 全量 E2E 共 16 条通过，包括唯一 canvas、三视图缩放、轨迹拆分/合并、
  跨帧视角恢复与空闲停机。
- 真实 Chrome 中 Top 从 100% 缩放到 112% 后，主 pass 计数从 3 增至 4，主点云保持可见；
  随后空闲 2.5 秒提交增量为 0，页面错误为 0。
- 缩短基准在 Legacy / 真实 WebGPU 下都确认 renderer owner 为 1、空闲提交增量为 0、运行时
  错误为 0；精修首开分别为 49.1 ms / 61.7 ms。该运行只含 1 个冷帧和 1 个相邻帧，
  不作为正式 p95 或显存 plateau 晋级证据；完整 39 帧三轮压力门仍保留。
