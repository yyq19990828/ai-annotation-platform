# 工作台右边栏四项优化：采纳属性污染 BUG 修复 + 属性审阅采纳键退役 + 分组折叠 + 讨论区完全收起

> 实施时按约定重命名为 `docs/plans/2026-07-01-vX.Y.Z-workbench-right-panel-tweaks.md`（版本号以实际发布为准）。

## Context

工作台右边栏（标注详情侧栏）四项优化，其中第 1 项是**正确性 BUG**，优先修：

1. **BUG：带属性的 AI 待审标注点"采纳"会连带污染所有人工标注的属性。**
   根因已定位（双因叠加）：
   - 后端路由 `apps/api/app/api/v1/tasks/predictions.py:174` 在 accept 后 `return await svc.list_by_task(task_id)` —— 返回**整题全部标注**而非本次新建的标注。
   - 前端 `apps/web/src/pages/Workbench/stages/image/useImageAnnotationActions.ts:660-673` 把这份全量列表当成"刚新建的标注"，对**每一条**（含所有既有人工标注）把 AI 候选属性 `carry` 合并后逐条 `PATCH /annotations/{id}`。守卫 `Object.keys(carry).length > 0` 解释了为何只有"带属性的候选"才复现。
   - 该 carry 循环本身已完全冗余：后端 `apps/api/app/services/annotation.py:305-325` 从 v0.14.9 起就把 shape 富属性透传进新建标注，v0.18.3 起 `attribute_overrides` 也原子落库。前端注释（"后端仅写 _shape_index"）是过时的。
   - **派生隐患**：三处采纳调用点（`useImageAnnotationActions.ts:662`、`:879`、`:968`）都把全量 id 记入 undo 历史 `createdAnnotationIds` → **撤销一次采纳会误删整题所有标注**（`state/useAnnotationHistory.ts:68-73`）。
2. 属性审阅区（AI 候选属性 edit-before-accept 面板）里的"采纳"按钮退役——与列表行/画布上的采纳入口重复。**用户已确认**：保留编辑能力，改为行内采纳时自动带上审阅改动。
3. "AI 待审" / "人工" 两个分组支持展开/收起，**服务端持久**（用户已确认）。
4. 评论/历史/Issue 区（DiscussionPanel）支持完全收起，复用属性区 `attrPanelCollapsed` 的持久化范式。

### 探讨修订（2026-07-01 · 三 Explore agent 事实核查 + 用户拍板）

计划里对代码现状的假设**全部属实**（后端路由 :174 return list_by_task、service 循环只返回最后一条、富属性透传 + `attribute_overrides` 原子落库、carry 循环 + 三处 push 全量 id、`attrPanelCollapsed` 四步管道范式、`WorkbenchLayout.tsx:183-189` `useElementStyle` v0.20.20 修 B-56 的注释均实锤）。发现 4 处需补正：

- **[补]** 改动 1 后端测试范围遗漏 —— 除 `test_accept_attribute_overrides.py`（走 HTTP 断言响应体，改后语义等价可不改）外，还有 `test_annotation_class_name_validation.py`（5 处）与 `test_annotation_attribute_provenance.py`（4 处）直接调 `svc.accept_prediction(...)` 拿单 `Annotation` 断言，service 返回类型一改必红；共 9 处要改成 `anns = ...; ann = anns[0]`。
- **[改]** service 签名定 `list[Annotation] | None`（None 保留 not-found 语义 → 路由 404；空 list 不作独立语义）。
- **[改]** 前端 `useAcceptPrediction` 路径 `apps/web/src/hooks/usePredictions.ts`（原计划写作 `src/api/`，实际不在那）。
- **[新加]** 改动 1.5：undo 侧顺手加一道 `parent_prediction_id` 防御过滤（用户拍板）。后端契约改后 `createdAnnotationIds` 已只含新建（正常路径下这道过滤是 no-op），但能防未来别处再往数组塞脏 id。见 §改动 1.5。
- **[改]** 改动 3 "人工" 段 gate 位置：原计划描述 rows 构造 :952-971 只有 header push；"人工" 段成员行实际在 :1010-1028 的 bucket-loop `for (const bucket of bucketed) { … }` 里 emit（GroupCard 树），gate 那处循环而非 header 附近。
- **[改]** 改动 4 讨论区收起可**复用现成 `discussionDetached` 分支**样式 —— `WorkbenchLayout.tsx:214-258` 已有 detached 时上段自动 `flex-1` + 无 bottom `ResizeHandle` 的分支，只需把二分改成 `discussionDetached || discussionCollapsed` 三态即可，不用新造。

其余（属性审阅按钮退役后编辑生命周期、画布贴框采纳不带 overrides 等）沿用原计划。

## 改动 1：修采纳属性污染 BUG（后端契约 + 前端删冗余循环）

**后端**
- `apps/api/app/services/annotation.py` `accept_prediction`（:192-380）：签名改 `-> list[Annotation] | None`；循环里 append 每条新建 annotation，末尾 `return anns`。`None` 保留原有 not-found 语义（prediction 找不到 :207-213 / shape_index 越界 :280-286）。单 shape 场景返回 `[ann]`（一元列表）。
- `apps/api/app/api/v1/tasks/predictions.py` `accept_prediction` 路由（:165-174）：接住 service 返回值；`None` → 404；成功 → **只返回本次新建的标注列表**（`response_model=list[AnnotationOut]` 不变，变的是内容语义）。删掉 `return await svc.list_by_task(task_id)`。
- 后端测试改动清单（原计划遗漏 9 处 service 直调断言，一并列齐）：
  - `apps/api/tests/test_accept_attribute_overrides.py:83-86`、`:101-106`：走 HTTP 断言响应体、目前用 `[a for a in ... if a["source"] == "prediction_based"][0]` 过滤取。改后新建全是 `prediction_based`，语义等价可保留；建议加一条"响应长度 = 新建 shape 数"断言。
  - `apps/api/tests/test_annotation_class_name_validation.py`（:189、:222、:255、:288、:319，5 处）：`ann = svc.accept_prediction(...)` → `anns = svc.accept_prediction(...); ann = anns[0]`；后续 `ann.class_name` 等断言不变。
  - `apps/api/tests/test_annotation_attribute_provenance.py`（:89、:128、:160、:184，4 处）：同上模式，改成 `anns[0]`。
- openapi snapshot 由 pre-commit 钩子自动再生，不手动跑 dump-openapi.py。`response_model` 未变，schema 层无实质 diff。

**前端**
- `useImageAnnotationActions.ts:663-673`：整段 carry 循环删除（属性已由后端原子落库）；`pickCarryAttributes`（:122-133）随之成孤儿，删除前 `rg -n "pickCarryAttributes" apps/web/src` 全仓确认仅此一处引用（core 假设：只有 :660 一处使用）。
- 三处 `history.push(... createdAnnotationIds: created.map(a => a.id))`（:661-662、:876-880、:963-968）**无需改代码**——后端只返回新建标注后语义自动纠正；核对即可。
- `apps/web/src/hooks/usePredictions.ts` `useAcceptPrediction`（:34） 的 `onSuccess`（:59-61）invalidate 保持不变（annotations 列表靠 invalidate 刷新，响应体不用于渲染）。

## 改动 1.5：undo 侧 `parent_prediction_id` 防御过滤（用户拍板深修）

后端契约改后，`createdAnnotationIds` 已经只含新建 id（正常路径下这道过滤是 no-op）。但为防未来别处再往数组塞脏 id（或历史栈里遗留旧 session 数据在 5min TTL 内被重放），在 undo 分支加一道校验。

文件：`apps/web/src/pages/Workbench/state/useAnnotationHistory.ts`

- `HistoryHandlers` 接口（:79-91）加可选 handler：
  ```ts
  /** v0.20.22 · accept undo 过滤：只删 parent_prediction_id === predictionId 的 annotation，
   *  防未来别处误把全量 id 塞进 createdAnnotationIds（原因：后端曾返回整题全量）。 */
  getAnnotation?: (annotationId: string) => AnnotationResponse | null | undefined;
  ```
- `applyLeaf` 里 `acceptPrediction` undo 分支（:68-76）改：
  ```ts
  if (direction === "undo") {
    for (const id of cmd.createdAnnotationIds) {
      const ann = h.getAnnotation?.(id);
      // 若 handler 未注入或读不到（离线/cache miss），fallback 到无过滤直删，保持旧行为不 regress。
      if (ann && ann.parent_prediction_id !== cmd.predictionId) continue;
      try { await h.deleteAnnotation(id); } catch { /* ignore */ }
    }
  }
  ```
- 调用方（工作台闭包内实例化 `useAnnotationHistory` 处）注入 `getAnnotation`：从 react-query cache 读 annotations（`qc.getQueryData<Annotation[]>(["annotations", taskId])?.find(a => a.id === id)`）。找注入点：搜 `useAnnotationHistory(` 调用，把 handler 同其他 4 个（create/delete/update/removeLocalCreate）一起挂上。
- **单测**：新增用例 `history 里 createdAnnotationIds 混入非本 prediction 的 id → undo 只删匹配的`（mock `getAnnotation` 返回不同 `parent_prediction_id`）。

## 改动 3 + 4：分组折叠（服务端持久）与讨论区完全收起（共用偏好管道）

三个新持久化字段一次加齐，完全照搬 `attrPanelCollapsed` 范式：

**偏好管道（每个字段同样四步）**

**改动 3 UI：分组头可折叠**（`AIInspectorPanel.tsx`）
- rows 构造两处独立 gate（原计划描述偏简，两段成员行 emit 位置**不在**同一处）：
  - **AI 段**：header push 在 :952-971 之内，紧邻 `filteredAiBoxes.forEach(...)` push 成员 —— `aiSectionCollapsed` 时跳过 `forEach`。
  - **人工段**：header push 在 :952-971，但成员行实际由 :1010-1028 的 `for (const bucket of bucketed) { … bucket.boxes.forEach(emitBoxWithChildren) }` emit（GroupCard 树）—— `manualSectionCollapsed` 时跳过整个 bucket 循环（也就跳过 `userGroup` row 的 push），header 与计数保留。

**改动 4 UI：讨论区完全收起**
- `apps/web/src/pages/Workbench/shell/DiscussionPanel.tsx`：增加 `collapsed` / `onToggleCollapsed` props（受控优先、缺省回落内部 state，同 `AIInspectorPanel.tsx:150-152` 的写法）；tablist 行（:73-99）左端加 chevron 收起按钮（复用现有 :88-98 分离按钮的 button 样式）；收起时不渲染 tabpanel 内容区（:100-122 整段 gate），仅剩 tab 头一条；点 chevron 展开（点 tab 不展开——避免和 tab 切换混淆）。
- `apps/web/src/pages/Workbench/shell/WorkbenchLayout.tsx` :214-258：**复用现成 `discussionDetached` 分支的样式** —— 现在已经有 `discussionDetached ? "relative flex min-h-0 flex-1 flex-col ..."` 分支自动切 `flex-1` 吃满 + `!discussionDetached` gate 掉 bottom `ResizeHandle`（:240-247）。改成三态：把 `discussionDetached` 替换为 `discussionDetached || discussionCollapsed`（上段样式选择、bottom handle gate 各一处）；讨论区容器 `!discussionDetached &&` gate 保留（分离时整个 DiscussionPanel 不渲染）+ 收起时仍渲染（仅 tab 头一条）。
- 交互组合：detached 状态下整个 `DiscussionPanel` 不渲染，collapse chev 无需额外 gate（自然不显示）；`discussionCollapsed` 只在 embedded 状态下有意义。
- 注意保留 v0.20.20 的 `useElementStyle` 注入方式（:183-189 注释详述 B-56 根因：上段 div 是条件渲染，收起再展开会 remount，`useRef+useEffect` 依赖未变不重跑 → CSS 变量丢失 → 高度回退默认）—— **不能回到 `useRef+useEffect`**。
