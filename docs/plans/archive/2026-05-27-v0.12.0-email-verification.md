# v0.12.0 · 邮箱验证（开放注册角色提升前置 · P2）

> 后端 + 前端 + DB migration · 依赖：无硬依赖（SMTP 底座已存在，复用 password-reset token 范式）

## 背景

ROADMAP §A「登录 / 注册 / 认证 · 开放注册二阶段剩余」与优先级表 P2 行长期挂着「邮箱验证」。当前实现：

- **完全没有邮箱验证**：`User`（`apps/api/app/db/models/user.py`）无 `email_verified_at`；开放注册 `POST /auth/register-open`（`apps/api/app/api/v1/auth.py`）与邀请注册（`invitations.py`）创建用户时**直接 `is_active=True`**，签发 JWT 即可登录，无任何验证 gate。
- 开放注册默认角色 `VIEWER`（零权限），且 `allow_open_registration` 默认 `False`，所以当前**未到必须做的触发点**——这条做的前提是「开放注册默认角色调高」。本版把能力补齐 + 加开关，默认不强制，触发时一键启用。

**底座已就绪，不是从零**：

- 邮件发送：`apps/api/app/services/email.py` 已有 `send_test_email()` + 完整 SMTP 链路（stdlib `smtplib`，SSL / STARTTLS），SMTP 配置存 SystemSettings（`smtp_host/port/user/password/from`）+ env fallback，`POST /system/test-smtp` 已验证连通。
- token 范式：已有 `forgot-password` / `reset-password` 端点 + `PasswordResetToken` 表（一次性 token + 过期）。邮箱验证照此克隆即可，**不引入新依赖、不新增设计模式**。

## 目标

补齐邮箱验证全链路，但**默认不改变现有注册体验**（开关关闭时行为与今天完全一致），开关打开后：注册 → 验证前不可登录 → 邮件链接验证 → 激活。`super_admin` 创建 / 邀请的用户视为已验证，不受影响。

## 已定决策

1. **gate 字段**：用**独立 `email_verified_at: datetime | None`**，登录时校验它。`is_active` 含义保持「停用/注销」单一语义，不让一个字段背两个意思（见 ROADMAP 决策底线「状态字段：不要一字段多义」）。
2. **邀请注册不验证**：邀请 token 本身已是身份证明（管理员定向发到该邮箱），邀请注册直接 `email_verified_at = now()`。只有开放注册走验证流。
3. **开关按环境派生默认值**：生产默认开、dev/staging 默认关（见下「配置」）。存量用户迁移时一律回填 `email_verified_at = created_at`（不追溯惩罚老用户）。

## 后端改动

### 1. 数据模型 + migration
- `User` 加 `email_verified_at: Mapped[datetime | None]`（nullable）。
- 新表 `EmailVerificationToken`（克隆 `PasswordResetToken` 结构）：`id / user_id(FK) / token(unique, index) / expires_at / used_at / created_at`。
- alembic migration（接 `0087` 之后）：建表 + 加列 + **存量回填** `email_verified_at = created_at`（避免老用户被锁）。

### 2. 配置（按环境派生默认值）
- `apps/api/app/config.py` 已有 `environment: Literal["development","staging","production"]`，沿用其「production 收紧」范式（如 cors / sentry）。
- 加 `require_email_verification: bool | None = None`（env：`REQUIRE_EMAIL_VERIFICATION`）。
  - **未显式设置（None）** → 按环境派生：`production` → `True`，`development` / `staging` → `False`。dev 因此**默认不需要配任何东西**。
  - **显式设置** → 以 env 为准（可在 staging 提前打开联调，或生产临时关闭兜底）。
  - 实现：用一个 `@property`（如 `email_verification_required`）封装「None → 按 environment 派生；非 None → 原值」，业务代码只读这个 property，不直接读裸字段，避免各处重复派生逻辑。
- `.env.example` 加 `REQUIRE_EMAIL_VERIFICATION=`（留空 + 注释说明「留空时生产默认开、dev 默认关」），跑 `pnpm docs:gen-env-vars`（CLAUDE.md §5）。

### 3. 端点（`apps/api/app/api/v1/auth.py`）
- `POST /auth/send-verification-email`：对当前/指定未验证用户生成 token、调 `email.py` 发信（限流：复用现有 rate-limit 机制，防刷）。
- `POST /auth/verify-email`：消费 token（校验未过期 / 未使用）→ 置 `email_verified_at = now()`、`used_at`。
- 改 `register-open`：`email_verification_required` 为真时 `email_verified_at=None` + 注册后自动发信；为假时 `email_verified_at=now()`（现状，dev 默认走这条）。
- 改 `login`：`email_verification_required` 为真且 `email_verified_at is None` → 拒绝，返回**专门的错误码**（前端据此显示「未验证 + 重发」入口，而非笼统 401）。
- 邀请注册（`invitations.py`）：创建时 `email_verified_at=now()`。

### 4. 邮件
- `email.py` 加 `send_verification_email(to, token)`：复用现有 SMTP 配置读取 + 发送函数，新增一个验证链接模板（前端 verify 落地页 URL + token query）。

## 前端改动

- **RegisterPage**（`apps/web/src/pages/Register/RegisterPage.tsx`）：开放注册成功且需验证时，跳「验证邮件已发送，请查收」提示态（替代当前直接进站），带「重发」按钮（调 `send-verification-email`，带倒计时防刷）。
- **verify 落地页**（新路由 `/verify-email?token=`）：进入即调 `POST /auth/verify-email`，成功 → 提示并引导登录；token 失效/过期 → 错误态 + 重发入口。
- **LoginPage**（`apps/web/src/pages/Login/LoginPage.tsx`）：识别后端「未验证」错误码 → 显示「邮箱未验证」+「重发验证邮件」入口（不要混进通用错误 toast）。
- 文案中文硬编码（与现状一致，i18n 是另一条 ROADMAP 线，本版不引入）。

## 验证

- 后端：`uv run pytest`（记忆：后端命令走 `uv run`）覆盖
  - **环境派生默认值**：env 未设时 `environment=production` → `email_verification_required` 为真、`development`/`staging` → 为假；env 显式设置时以 env 为准（覆盖派生）。
  - 关闭（dev 默认）：`register-open` 后 `email_verified_at` 非空、可直接登录（回归现状）。
  - 打开（生产默认）：注册后 `email_verified_at` 为空、登录被拒（专用错误码）；verify-email 消费 token 后可登录；token 过期/重复使用被拒。
  - 邀请注册：恒 `email_verified_at` 非空。
  - migration 存量回填：老用户 `email_verified_at = created_at`。
- 前端：`pnpm --filter web typecheck` + `lint`（含 `lint:css-tokens`：verify 落地页 / 提示态新 CSS 只用 `tokens.css` 既有 `--color-*`，无 fallback、无 hardcode）+ dark mode 走查。
- 单测（vitest + MSW）：注册后提示态、login 未验证错误分支、verify 成功/失败落地态、重发倒计时。
- 手测：开关打开 → 注册 → 收信（dev 用 `test-smtp` 同一 SMTP）→ 点链接验证 → 登录成功；未验证直接登录被挡 + 重发可用。

## 回退

生产临时兜底：env 显式设 `REQUIRE_EMAIL_VERIFICATION=false` 即关闭整条验证流（行为回到现状），无需回滚 migration（新列 nullable、新表不影响旧路径）。前端新增页面/分支在开关关闭时不触发。

## 备注 / 不做

- **不做 OAuth2 / 社交登录**（独立 P2 条，单独版本）。
- **不引入 i18n**（文案硬编码与现状一致）。
- **2FA / TOTP** 是另一条线，本版不碰。
- SMTP 邮件 digest（Bug 反馈 P2）与本版**共用 `email.py` 底座**，但聚类/digest 逻辑不在本版范围。
