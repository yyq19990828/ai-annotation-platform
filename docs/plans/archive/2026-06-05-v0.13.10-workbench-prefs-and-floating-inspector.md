# v0.13.10 · 工作台偏好跨端持久化 + 3D 浮层避让侧栏 + 标注详情/三视图可分离浮窗

> 计划日期 2026-06-05 · 范围：工作台 layout 偏好接入 `user.preferences.workbench`（跨设备生效）；3D 点云台浮层让位右侧栏；右侧「标注详情」面板支持"分离成可拖拽浮窗"；3D 三视图浮层升级为可拖动 + 可 resize + 位置/尺寸/折叠态持久化（同窗口浮窗形态 A）。

## 1. 背景与目标

来自用户工作台体验讨论（2026-06-05），合并成一个版本是因为三件事**共享一份后端 schema 改动**（`WorkbenchPreferences` 加字段），分散到三个版本会反复改 schema、反复改默认值。

代码基线核实结论（必看，决定了改动量）：

- **后端持久化基础设施 100% 就位**：`apps/api/app/db/models/user.py:60` 的 `User.preferences: JSONB` + `apps/api/app/api/v1/me.py:115-133` 的 `GET/PATCH /me/preferences`（已做按顶层子树合并）+ 前端 `apps/web/src/api/auth.ts:15-71` 的 `WorkbenchPreferences` schema 与 `updatePreferences()`，全都已用于现有 `smoothImage / cssImageFilter / controlPointsSize / snapToGrid / longTaskSampleRate` 等渲染偏好。**本版本只是往同一个子树里加字段**，零新机制。
- **leftWidth / rightWidth 已 localStorage 持久化**（`useWorkbenchState.ts:139-160`），但只在单台机器生效；`leftOpen / rightOpen`（同文件 137-138）是裸 `useState`，刷新即丢。本版本把这 4 个字段统一搬到 `preferences.workbench`，**保留 localStorage 作为登录前 / 离线降级**。
- **3D 浮层重叠**：`TriViewPanel`、`FloatingCameraPanel` 在 `.viewportWrap`（grid 中心列）内 `position: absolute`，硬编码 `right: 12px`（`ThreeDWorkbench.module.css:41-46`），完全不感知右栏宽度。当前截图是"视觉拥挤未真重叠"，但用户把右栏拖宽就会真重叠。`WorkbenchLayout.tsx:86` 已经在用 CSS var 注入 `--right-split-top-height` 的手法，复用同一手法注入 `--right-sidebar-width` 即可。
- **AIInspectorPanel detach 可行性**：`useWorkbenchState` 是单 React hook（不是全局 store），但 `AIInspectorPanel` 已经是受控组件（props 透传），把它包一层 `FloatingPanelShell`（`position: fixed` + 自写 drag handler）即可在同窗口内"分离"，**state 完全不用动**。`package.json` 无任何拖拽库，自写一个 80 行 hook 即可，不引依赖。

### 成功判据

1. 改 leftOpen / rightOpen / leftWidth / rightWidth → 立即写入 `user.preferences.workbench` → 换台设备 / 重登仍生效；离线 / 未登录态降级到 localStorage。
2. 3D 台拖动右侧栏 `ResizeHandle` 改变 `inspector.width` → 三视图浮层和右侧 anchor 相机预览的 `right` 偏移**同步变化**，不被遮挡；右栏 collapse 时浮层贴最右边。**同时**：顶部 anchor 相机预览（前/后摄）的 `top` 偏移避让顶部工具条高度，工具条按钮换行变两行时相机自动下移。
3. 右栏标注详情面板顶部菜单出现「分离」按钮 → 面板从 grid 槽位脱离变成可拖拽浮窗（带顶栏 + 关闭/合并回侧栏按钮）；浮窗位置/尺寸持久化到 `preferences.workbench.floatingInspector`；合并回侧栏后浮窗清空。
4. 3D 三视图浮层（`TriViewPanel`）顶栏拖动改变位置、右下角拖动 resize；位置/尺寸/折叠态持久化到 `preferences.workbench.triViewFloat`，跨设备一致；窗口 resize 后浮窗自动 clamp 到可视区域内，不丢。
5. `pnpm lint` / `pnpm test` / `pnpm lint:css-tokens` 通过；后端单测覆盖 `WorkbenchPreferences` 新字段的合并与默认值。

### 非目标（明确不做）

- **真·独立 window**（双屏标注、`window.open` + BroadcastChannel）：成本明显高且 `useWorkbenchState` 需重构成全局 store，等真实双屏诉求出现再上。本版本只做同窗口浮层。
- 浮窗的 z-order 管理、多浮窗（同时分离左栏 + 右栏）：v0.13.10 只支持右栏 `AIInspectorPanel` 分离，左栏 `TaskQueuePanel` 留作后续版本。
- **相机预览浮层**（`FloatingCameraPanel`）的拖动 / resize：v0.13.10 只做"避让右栏"的 CSS calc 修复，不做拖动。原因：相机预览有 N 个（按朝向 anchor 分组），全部加拖动语义复杂度高于收益，留作后续按需求驱动。
- 三视图浮层的「合并回侧栏」语义：三视图本来就不属于侧栏，没有"原始槽位"可回，永远是浮窗形态，本版本不引入 detach/merge 概念，只做位置/尺寸/折叠态持久化。

## 3. 后端 schema 改动

`WorkbenchPreferences` 当前只装"渲染偏好"，本版本加一个 `layout` 子结构装"布局偏好"，与渲染偏好平行（隔离两类语义，未来加更多布局字段不污染渲染分支）：

```python
class WorkbenchLayoutPreferences(BaseModel):
    left_open: bool | None = None
    right_open: bool | None = None
    left_width: int | None = None      # 200..560
    right_width: int | None = None     # 220..600
    floating_inspector: FloatingInspectorState | None = None

class FloatingInspectorState(BaseModel):
    detached: bool = False
    x: int | None = None               # 浮窗左上角 viewport 像素
    y: int | None = None
    w: int | None = None               # 200..720
    h: int | None = None               # 240..900

class TriViewFloatState(BaseModel):
    """3D 三视图浮层永远是浮窗形态(非 detach/merge), 只持久化位置/尺寸/折叠。"""
    collapsed: bool = False
    x: int | None = None               # 默认右下角 (由前端按 viewport 算)
    y: int | None = None
    w: int | None = None               # 200..480, 默认 240
    h: int | None = None               # 240..720, 默认 440

class WorkbenchLayoutPreferences(BaseModel):
    # 字段定义(完整版, 替换上文)
    left_open: bool | None = None
    right_open: bool | None = None
    left_width: int | None = None
    right_width: int | None = None
    floating_inspector: FloatingInspectorState | None = None
    tri_view_float: TriViewFloatState | None = None

class WorkbenchPreferences(BaseModel):
    # ...已有字段保持不变...
    layout: WorkbenchLayoutPreferences | None = None
```

合并策略 **不变**（仍是顶层子树覆盖式合并）：前端永远整体 PATCH `{ workbench: { ...全量 } }`。若担心 `layout` 嵌套覆盖丢字段，前端拼 PATCH payload 时 spread 当前 `workbench` 全量再覆盖（既有 `useWorkbenchConfig` 已经是这套模式，照抄）。

> **不做** 字段级 deep-merge：后端复杂度 / 边界情形（null 表示删 vs. 不变）远比"前端整体 PATCH"高，得不偿失。

后端单测重点：先 PATCH `{ workbench: { smoothImage: false } }` 再 PATCH `{ workbench: { layout: {...} } }`，验证 `smoothImage` 不被冲掉（——其实当前合并是顶层覆盖，**会被冲掉**；这就是为什么"前端整体 PATCH"是契约约束）。这条契约在 schema 注释和 `useWorkbenchConfig` 函数注释里都要写清楚。

## 4. 前端 hook 改动

`useWorkbenchConfig` 当前签名：

```ts
function useWorkbenchConfig(): {
  config: WorkbenchPreferences;
  setSmoothImage: (v: boolean) => void;
  // ...
}
```

扩展：

```ts
function useWorkbenchConfig(): {
  config: WorkbenchPreferences;
  layout: WorkbenchLayoutPreferences;       // 解构出来便于消费方
  setLayout: (patch: Partial<WorkbenchLayoutPreferences>) => void; // debounce 300ms 写回
  // ...原有字段保持
}
```

`setLayout` 内部：
1. 同步更新 React state（UI 立即响应）。
2. 同步写 localStorage（fallback / 离线 / 未登录降级）。
3. debounce 300ms 调 `authApi.updatePreferences({ workbench: { ...config, layout: { ...layout, ...patch } } })`。
4. 失败静默 warn，不阻断 UI（保留 localStorage 兜底）。

`useWorkbenchState` 里的 `leftOpen / rightOpen / leftWidth / rightWidth` 初始值改为：

```ts
const { layout, setLayout } = useWorkbenchConfig();
const [leftOpen, setLeftOpenRaw] = useState<boolean>(layout.leftOpen ?? true);
// useEffect 同步回去：setLayout({ leftOpen })
```

> **不要**把 `useWorkbenchState` 改成读 `useWorkbenchConfig` 的派生值——会让"用户改宽度"和"远端 fetch 到偏好"互相覆盖。本地状态权威 + debounce 单向写回，是与既有 `useWorkbenchConfig` 一致的范式。

## 5. 3D 浮层避让侧栏 + 避让顶部工具条

两类避让同源同方案：**让浮层的偏移 = 邻接面板的"占位"通过 CSS var 注入**，浮层用 `calc(var + 12px)` 自适应。

### 5.1 注入两个 CSS var

`WorkbenchLayout.tsx:86` 既有手法：

```tsx
splitTopRef.current?.style.setProperty("--right-split-top-height", `${splitTopHeight}px`);
```

照抄两份：

```tsx
// 右栏宽度(§5.2 浮层 right 用)
const viewportSlotRef = useRef<HTMLDivElement>(null);
useLayoutEffect(() => {
  const px = inspector.open ? inspector.width : 0;
  viewportSlotRef.current?.style.setProperty("--right-sidebar-width", `${px}px`);
}, [inspector.open, inspector.width]);

// 顶部工具条高度(§5.3 浮层 top 用): 用 ResizeObserver 因为工具条高度可能换行变化
const controlsRef = useRef<HTMLDivElement>(null);
useLayoutEffect(() => {
  const el = controlsRef.current;
  if (!el) return;
  const ro = new ResizeObserver(([entry]) => {
    const h = Math.round(entry.contentRect.height);
    viewportSlotRef.current?.style.setProperty("--top-toolbar-height", `${h}px`);
  });
  ro.observe(el);
  return () => ro.disconnect();
}, []);
```

> 工具条高度**必须用 ResizeObserver**，不能像右栏一样靠 React state 驱动——按钮组在窄屏可能 flex-wrap 成两行，靠 state 抓不到这个变化（state 只跟 inspector.width）。右栏宽度本身就是 state，所以两种手法各取所长，不强行统一。

注入位置：`controlsRef` 挂在 `ThreeDWorkbench.tsx:863` 的 `.controls` 容器（注意它在 ThreeDWorkbench，不在 WorkbenchLayout，所以 §5.1 这段实际写在 `ThreeDWorkbench.tsx`，CSS var 也只在 3D 台生效——image/video 台没顶部 controls 就不会注入，正好不打架）。`viewportSlotRef` 同理改成挂 `ThreeDWorkbench` 的 `.viewportWrap`（不挂 `WorkbenchLayout`），右栏宽度通过现有 props 一路传进 `ThreeDWorkbench`（已经有 `inspector` 信息可读，详见步骤 1–4 接好的 `useWorkbenchConfig().layout`）。

### 5.2 浮层 right 避让侧栏

`ThreeDWorkbench.module.css`：

```css
.triFloat,
.triFloatTab,
.camAnchorRight,
.camAnchorTopRight,
.camAnchorBottomRight {
  right: calc(var(--right-sidebar-width, 0px) + 12px);  /* 原: right: 12px */
}
```

### 5.3 浮层 top 避让工具条

```css
.camAnchorTop {
  top: calc(var(--top-toolbar-height, 0px) + 12px);     /* 原: top: 12px */
}
.camAnchorTopLeft,
.camAnchorTopRight {
  top: calc(var(--top-toolbar-height, 0px) + 12px);     /* 原: top: 64px(死值) */
}
```

> **删硬编码 64px**：原来的 `top: 64px` 是当时估算的工具条高度。改成 var + 12px gap 之后，工具条多高 / 换行 / 加按钮，相机预览都自动避让，不再需要每次工具条改了就回来调 64。

### 5.4 边界

| 情形 | 行为 |
|---|---|
| `rightOpen=false`（整侧栏隐藏） | `--right-sidebar-width=0`，浮层贴最右 12px |
| AIInspectorPanel 分离成浮窗（§6） | 也视为 `rightOpen=false` 等价：grid 中央列变全宽，3D 浮层贴最右 12px |
| 工具条按钮组换行变两行 | ResizeObserver 触发 var 更新，所有顶部相机预览同步下移 |
| 非 3D 工作台 | CSS var 不注入（observer 没挂），image/video 工作台 viewport 没引用这俩 var，无副作用 |
| 工具条与相机预览同时存在但都很大、viewport 太小 | 不处理（YAGNI），用户可折叠相机预览或缩起工具条按钮组 |

## 6. AIInspectorPanel 分离浮窗

### 6.1 `useDragMove` hook（新）

```ts
/** v0.13.10 · 浮窗拖动 hook。pointer-down 在 handle 上 → 监听 window pointermove/up,
 *  按下时记录鼠标-浮窗左上角偏移, move 时算出新 x/y 并 clamp 到 viewport 内(留 24px 边距防拖丢)。
 *  返回 { handleProps, isDragging }。不依赖 react-rnd / react-draggable, 与既有 ResizeHandle 风格一致。 */
export function useDragMove(opts: {
  position: { x: number; y: number };
  size: { w: number; h: number };
  onChange: (pos: { x: number; y: number }) => void;
}): { handleProps: HTMLAttributes<HTMLDivElement>; isDragging: boolean };
```

实现要点：
- 用 `setPointerCapture` 避免快速拖动鼠标跑出元素丢事件。
- clamp：`x ∈ [24, window.innerWidth - 24]`，`y ∈ [24, window.innerHeight - h - 24]`（防止顶栏拖到屏幕外抓不回来）。
- 窗口 resize → 自动 re-clamp 一次，否则换分辨率后浮窗可能跑到屏外。

单测：mock window.innerWidth/Height，验证拖动后位置正确 + clamp 边界生效。

### 6.2 `FloatingPanelShell`（新）

```tsx
<FloatingPanelShell
  title="标注详情"
  position={floatingInspector}              // { x, y, w, h } from preferences
  onPositionChange={(p) => setLayout({ floatingInspector: { ...floatingInspector, ...p } })}
  onMergeBack={() => setLayout({ floatingInspector: { ...floatingInspector, detached: false } })}
  minSize={{ w: 280, h: 320 }}
  maxSize={{ w: 720, h: 900 }}
>
  {children}
</FloatingPanelShell>
```

- 顶栏：title + 「合并回侧栏」按钮 + 「关闭」按钮（=合并回侧栏 + rightOpen=false）。
- 拖动区域：顶栏（cursor: move）。
- resize：右下角小三角，复用 `useDragMove` 同款 hook 思路（或直接复用 `ResizeHandle` 升级版）。**v0.13.10 只支持右下角 resize，不做四边 / 八方向**——够用即可，避免过度设计。
- 样式：`position: fixed`，圆角 + shadow（用 tokens.css 既有 `--color-surface-elevated` / `--shadow-lg` token，**禁止** 写 fallback / 硬编码色，CSS-tokens lint 会拦）。

```tsx
const detached = layout.floatingInspector?.detached;

## 7. 三视图浮层升级（复用 FloatingPanelShell）

const { layout, setLayout } = useWorkbenchConfig();
const tri = layout.triViewFloat ?? {};
const defaultPos = useTriViewDefaultPos();   // 按 viewport 右下角算出来的 fallback

{triSelected && !tri.collapsed && (
  <FloatingPanelShell
    title="三视图精修"
    position={{
      x: tri.x ?? defaultPos.x,
      y: tri.y ?? defaultPos.y,
      w: tri.w ?? 240,
      h: tri.h ?? 440,
    }}
    onPositionChange={(p) => setLayout({ triViewFloat: { ...tri, ...p } })}
    onCollapse={() => setLayout({ triViewFloat: { ...tri, collapsed: true } })}
    variant="no-merge"                       // 隐藏"合并回侧栏"按钮(三视图没有原始槽位)
    minSize={{ w: 200, h: 240 }}
    maxSize={{ w: 480, h: 720 }}
  >
    <TriViewPanel ... />
  </FloatingPanelShell>
)}
{triSelected && tri.collapsed && (
  <button
    className={styles.triFloatTab}
    onClick={() => setLayout({ triViewFloat: { ...tri, collapsed: false } })}
  >三视图</button>
)}
```

### CSS 改动

`.triFloat` 现在的 `position/right/bottom/width/height/z-index` **全部交给 `FloatingPanelShell`** 控制，本类只留视觉样式：

```css
/* v0.13.7 → v0.13.10 · 三视图浮层视觉样式; 位置/尺寸由 FloatingPanelShell 控制。 */
.triFloat {
  display: flex;
  flex-direction: column;
  border-radius: var(--radius-md);
  border: 1px solid var(--color-border);
  background: var(--color-bg-elev);
  box-shadow: var(--shadow-sm);
  overflow: hidden;
}
```

> 严格说 `FloatingPanelShell` 已经提供 border/bg/shadow，`.triFloat` 可以彻底不需要。**保留**它是为了让 `TriViewPanel` 内部已有的 `flex-direction: column` 排版照常工作。如果 `FloatingPanelShell` 的内容区已经是 flex column，则可彻底删 `.triFloat` 类。实施时实测一下。

`.triFloatHeader` 删除（标题栏由 `FloatingPanelShell` 顶栏接管）。`.triFloatTab`（折叠后的小标签）**保留并继续硬编码 `right/bottom`**，因为折叠态不需要拖动，固定贴右下角合理；它的 `right` 同样改成 `calc(var(--right-sidebar-width, 0px) + 12px)` 避让侧栏。

### `FloatingPanelShell` 的 `variant` 与 `onCollapse` 扩展

§6.2 的 `FloatingPanelShell` 增强：

```tsx
interface FloatingPanelShellProps {
  title: string;
  position: { x: number; y: number; w: number; h: number };
  onPositionChange: (p: Partial<{ x: number; y: number; w: number; h: number }>) => void;
  onMergeBack?: () => void;                          // 给 AIInspectorPanel
  onCollapse?: () => void;                           // 给三视图(折叠成小标签)
  variant?: "default" | "no-merge";                  // no-merge: 隐藏"合并回侧栏"按钮
  minSize: { w: number; h: number };
  maxSize: { w: number; h: number };
  children: React.ReactNode;
}
```

顶栏右侧按钮组按 props 决定：`onMergeBack` 存在且 `variant !== 'no-merge'` → 渲染「合并回侧栏」；`onCollapse` 存在 → 渲染「折叠」（仅三视图用）。

### 默认位置（首次使用 / 无持久化值）

`useTriViewDefaultPos` hook：

```ts
function useTriViewDefaultPos() {
  return useMemo(() => ({
    x: Math.max(24, window.innerWidth - 240 - 12 - getRightSidebarWidth()),
    y: Math.max(24, window.innerHeight - 440 - 12),
  }), []);
}
```

> `getRightSidebarWidth()` 读 `useWorkbenchConfig().layout.rightWidth ?? 280`（右栏 collapse 时为 0）。这样首次显示位置和 v0.13.9 的"贴右下角，且避让右栏"行为完全一致，用户无感升级。

### 边界

| 情形 | 行为 |
|---|---|
| 用户切换主题 / 缩放浏览器 → `window.innerWidth` 变小 | `useDragMove` 的 resize 监听器自动 clamp 浮窗回可视区 |
| 持久化值 `tri.x` 在屏幕外（多屏切单屏） | `FloatingPanelShell` mount 时 clamp 一次 + 写回 setLayout |
| 三视图与 AIInspectorPanel 浮窗位置重叠 | 不自动避让，用户自行拖开；本版本不引入浮窗 z-order/碰撞检测（YAGNI） |
| 折叠后 `.triFloatTab` 与"分离的 AIInspectorPanel"重叠 | 同上，用户自行调整 |
