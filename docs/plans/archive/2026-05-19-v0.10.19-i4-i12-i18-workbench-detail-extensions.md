# ROADMAP §C.7 I4 + I12 + I18 一次性收口

> 版本目标：v0.10.19（或下一切片）单 epic 落地三项工作台扩展。
> 命名约定：用户回答按"右栏固定 + group_id 新增字段 + AnnotationFeedback 统一表 + 三项作单一 epic"四条决策推进。

---

## Context（为什么做、为什么一次做）

ROADMAP §C.7 三项「标注详情扩展」长期挂在 P2 但没有触发条件,现在合并是因为三者**共享同一片 UI 表面**(右栏标注详情区 + Konva overlay 层),分别开三个 PR 会反复触碰 `AIInspectorPanel.tsx` / `ImageStage.tsx` / `Annotation` 表 schema 三处热点,churn 大于收益。

驱动信号:
- **I4 延伸需求**:用户实际反馈"评论/历史想常驻"——当前 `CommentsPanel` 嵌在 `AIInspectorPanel` 里,**未选中标注时整个面板隐藏**,任务级讨论无落点,reviewer 想"对整张图打条评论"必须先选一个框。
- **I12**:多框批量编辑 UX 缺失,标注员要给 30 个"人"框统一加 `occluded=true` 时只能逐个改。
- **I18**:reviewer 想在图像空白处指着"这片区域漏标了"打 issue,现在只能在 reject_reason 里写文字描述坐标,信号丢失。

落地后,reviewer 端体验从"逐框点开 → 写评论 → 关闭"升级为"打开任务 → 评论/历史/issue 始终在视野 → 框选 N 个直接 Ctrl+G 成组批改"。

## 三项共享设计前提

**右栏布局重构(I4 是触发点,I12/I18 复用)**:
- 当前 `WorkbenchLayout` 右栏只有 `AIInspectorPanel` 单个容器(随 `selectedAnnotationId` 显示/隐藏)。
- 重构为**两段固定结构**:
  - 上段「检查器」(`AIInspectorPanel` 瘦身,只保留 BoxList / AttributeForm / videoTrackPanel)。
  - 下段「讨论」(新组件 `DiscussionPanel`,常驻;内含 Tabs: 评论 / 历史 / Issue;按当前 `selectedAnnotationId` 切换"标注级"与"任务级"上下文)。
- 上下段比例由用户拖拽 + 持久化到 `localStorage` (复用现有 `ResizeHandle.tsx`)。

## I12 · Object Group(分组 + 批量编辑)

### 后端
- **Alembic migration**:`annotations` 表新增
  - `group_id: BigInteger NULLABLE`(同 task 内自增,设计为 nullable int 而非 UUID 因为分组语义是"同框互相引用",数值更轻量;走 `tasks.next_group_seq` 维护,见下)
  - `tasks.next_group_seq: Integer DEFAULT 0`(每个 task 一个独立序号空间;创建分组时 `UPDATE tasks SET next_group_seq = next_group_seq + 1 RETURNING next_group_seq`)
  - 索引: `ix_annotations_task_group(task_id, group_id) WHERE group_id IS NOT NULL`
- **新建 `apps/api/app/api/v1/annotations.py`**(独立 router,当前散在 `tasks.py`):
  - `POST /annotations/bulk-update` —— body `{ ids: UUID[], patch: { class_name?, attributes?, is_locked?, is_hidden?, is_occluded?, z_order?, group_id?: int | null } }`
  - `POST /annotations/group` —— body `{ ids: UUID[], task_id: UUID }`,返回新 group_id;复用 `next_group_seq`
  - `POST /annotations/ungroup` —— body `{ ids: UUID[] }`(把 group_id 置 null;若该 group 仅剩 1 个成员,该成员也自动 ungroup)
  - 权限:沿用 `assert_can_edit_annotations` 现有守卫;批量操作单事务回滚。
  - audit:`audit.bulk_annotation_edit_detail()` 复用 v0.7.3 bulk batch detail 模式。
- **不引入 parent_id 关系迁移** —— `parent_annotation_id`(车牌属于车)保持现状,与 `group_id`(平等成员)正交。导出 COCO 时:
  - `parent_annotation_id` → COCO `parent` 字段(已有逻辑)
  - `group_id` → COCO `attributes.__group_id` 命名空间(避免与客户自定义 attribute 冲突)

### 前端
- **状态管理**:`useWorkbenchState` 已有 `selectedAnnotationIds`(多选已具备 Shift+点击 / Ctrl+A);新增 hooks:
  - `useAnnotationGroup(taskId)` —— React Query mutation:`group` / `ungroup` / `bulkUpdate`
- **Konva 渲染**:`ImageStageShapes.tsx` 给同 group_id 的形状外圈渲染**第二层虚线边框**(group color = `hashColor(group_id)`);hover 同组任一框时整组高亮。
- **快捷键**:`apps/web/src/pages/Workbench/state/useWorkbenchHotkeys.ts`
  - `Ctrl+G` → group(选中数 < 2 时 toast 提示)
  - `Ctrl+Shift+G` → ungroup
  - 与现有 `Ctrl+A` / `Delete` / `B` / `V` 不冲突(已 grep 验证)
  - `?` 帮助卡片同步加两行
- **侧栏分组卡片**:`AIInspectorPanel` 的 `BoxList` 渲染时,把同 group_id 的标注**折叠为可展开 group 卡片**(标题:`组 #${group_id} · ${count} 个标注`);点击 group 卡片头部选中整组。
- **批量编辑 UI**:多选状态下 `AttributeForm` 顶部显示 banner「N 个标注被选中,修改将应用到全部」;表单 submit 走 `bulk-update`。

## I18 · AnnotationFeedback 统一表(取经合集 §2.2 落地)

### 数据层(新表,不动旧表)
- **新建 `annotation_feedbacks` 表**(走取经合集 §2.2 设计 + 平台命名规范):
  ```python
  class AnnotationFeedback:
      id: UUID
      kind: str  # 'issue' | 'comment' | 'reject' | 'bug'  (Literal enum)
      anchor_type: str  # 'project' | 'task' | 'annotation' | 'pixel'
      project_id: UUID  # 索引,所有 kind 必填
      task_id: UUID | None  # anchor_type ∈ {task, annotation, pixel} 时必填
      annotation_id: UUID | None  # anchor_type='annotation' 时必填
      anchor_position: JSONB | None  # {x: float, y: float, frame?: int} for pixel
      status: str  # 'open' | 'resolved' | 'wont_fix' (default 'open')
      severity: str | None  # 'info' | 'warn' | 'blocker'
      title: str | None  # bug/issue 用
      body: Text  # 主要内容
      author_id: UUID
      created_at / updated_at
      attachments: JSONB  # 复用 AnnotationComment.attachments 形态
      thread_parent_id: UUID | None  # 自引用,实现子评论链
  ```
- **索引**:
  - `ix_feedback_project_kind_status(project_id, kind, status)`
  - `ix_feedback_task_kind(task_id, kind) WHERE task_id IS NOT NULL`
  - `ix_feedback_annotation(annotation_id) WHERE annotation_id IS NOT NULL`

### 迁移策略(关键:旧表不动)
- **保留** `bug_reports` / `annotation_comments` / `tasks.reject_reason` 三处现表,**不做数据迁移**(避免一次性合表破窗;按 §2.2"早做比晚做便宜"是指**新表先立**,旧表数据仍在原地查)。
- **新建 PG view `v_annotation_feedback_unified`**:UNION ALL 上述三表 + 新表,字段对齐到统一 schema。前端通过新统一 API `GET /feedbacks?project_id=&kind=&anchor_type=&status=` 查询。
- **后续清理(不在本 epic)**:旧表 model 标 `# DEPRECATED, write 走 annotation_feedbacks`,新写入双写一个版本观察后,下一切片单方向切换。

### 后端 API
- 新建 `apps/api/app/api/v1/annotation_feedbacks.py`:
  - `GET /feedbacks?project_id=&task_id=&annotation_id=&kind=&status=&cursor=&limit=`(统一 keyset 分页)
  - `POST /feedbacks` —— 创建 feedback(包括 pixel issue)
  - `PATCH /feedbacks/{id}` —— 改 status / body / severity / 解 resolve
  - `DELETE /feedbacks/{id}` —— 软删(`is_active=false`,与现 comment 一致)
  - `POST /feedbacks/{id}/replies` —— 子评论(`thread_parent_id` 链)
- **新建 service** `apps/api/app/services/feedback.py`:聚合 view 读 + 新表写。

### 前端
- **IssueLayer**(Konva 层,叠在 `ImageStage` 现有 shape 层之上):
  - 新建 `apps/web/src/pages/Workbench/stage/image/IssueLayer.tsx`
  - 渲染所有 `anchor_type='pixel'` 的 feedback 为图钉图标(`<KonvaCircle>` + Icon "flag");status 配色:open=橙、resolved=绿、wont_fix=灰。
  - hover 图钉显示 tooltip 摘要;点击图钉切换 `DiscussionPanel` 到 Issue tab + 高亮对应 feedback。
- **Issue 创建入口**:`ToolDock.tsx` 加按钮 `Pin`(快捷键 `I`)——按下进入 issue 模式,Konva 单击落点弹 `IssueCreateModal` 输入标题 + 严重度,提交后创建 feedback `kind=issue / anchor_type=pixel`。
- **DiscussionPanel Issue tab**(I4 的 Tabs 已预留位):列表 + 按 status 过滤 + 单击定位到 IssueLayer 对应图钉(`Konva.Stage.to({x, y, scale})`)。
- **截图复用**:Issue 创建时自动调用 `utils/bugReportCapture.ts`(html2canvas-pro)截当前 viewport 入 `attachments`(可选)。
