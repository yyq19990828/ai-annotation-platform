# v0.18.5 — M5 · 多阶段编排配置硬化（选择器化 + 校验前置）

> 状态：**待实施 plan**（不开干）。创建于 2026-06-23。
>
> 定位：路径 B 前端 UX 硬化。M2 的 `StageCard`（`apps/web/src/pages/AIPreAnnotate/components/StageCard.tsx`）把 `parent_class_filter` / `write.keys` 做成**逗号分隔自由文本框**，打错字 → 静默过滤为空 / 静默键不匹配，是当前最容易让用户「配了没反应」的坑。本期把这些字段**选择器化**，并把校验从「跑了才 422」前移到配置期，消灭一类静默误配。纯前端为主（后端校验已就绪）。

## 1. 目标 / 非目标

**目标**
1. **`parent_class_filter` → 类别多选**：用项目类别（`project.classes` / `classes_config`）做多选，而非文本框。
2. **`write.keys` → 属性键多选**：用项目 `attribute_schema` 字段键（或下游 backend 自报的 `output_attribute_schema`）做多选。
3. **键冲突配置期预警**：多张并行卡声明写同一键时，前端即时标红提示（不等后端 422），并提供「末位覆盖」开关对应 `on_key_conflict=last_wins`。
4. **下游 backend 能力门控**：StageCard 下游 backend 选择器只列「会返回属性」的后端（自报 `output_attribute_schema` 或 `output_attribute_types`），对纯检测器给警示（吃 crop 只会重新检测、属性恒空）。
5. **单 backend 兜底 + 拓扑可读性**：项目只绑 1 个 backend 时 StageCard 提示「需先绑第二个 backend」；卡片用缩进/括号分组直观呈现「源 → 一组并行子」（不上节点图）。

**非目标**
- 不上节点图 / React Flow（路径 B 决议不变）。
- 不动后端校验（`PipelineStage` 校验 + `on_key_conflict` 已在 v0.18.2 就绪）。
- 不改共享 `PreannotateConfigForm` / `usePreannotateConfig`（红线：阶段编排只在容器/卡层）。

## 2. 详细设计

### 2.1 类别多选（parent_class_filter）

- 数据源：项目类别。`ProjectDetailPanel` 已查 `project`（`classes_config`）；把项目类别集传给 `StageCard`。
- 组件：复用现有类别选择交互（参考 `ClassWhitelistRow.tsx` 的多选样式），替换 StageCard 里的 `classFilter` 文本框。
- 语义不变：选中集合即 `parent_class_filter`（空=全部父框）。展示用类别中文/alias，提交用原类名（与检测器输出 `class_name` 对齐）。
- 边界：检测器实际输出类别可能与项目类别集不完全一致；多选列项目类别即可，附一行说明「按检测框类名匹配」。

### 2.2 属性键多选（write.keys）

- 数据源优先级：① 下游 backend 自报 `output_attribute_schema` 的 key（最准，backend 实际会写的键）；② 回落项目 `attribute_schema` 字段 key。两者经 capabilities / 项目查询已可得。
- 组件：多选 chips，替换 `writeKeys` 文本框。
- 空选 = 接收下游返回的全部键（与现状一致）。

### 2.3 键冲突配置期预警

- `ProjectDetailPanel` 已持各下游卡的派生 payload（`downstreamPayloads`）。计算所有卡 `write.keys` 的交集冲突 → 冲突时把涉事卡的该键 chip 标红 + 顶部提示。
- 提供「键冲突时末位覆盖」开关 → 请求带 `on_key_conflict: "last_wins"`（后端已支持），否则默认 `reject`（运行前就拦，不再白跑）。
- `canRun` 在 reject 模式且存在冲突时禁用运行 + tooltip 说明。

### 2.4 下游 backend 能力门控

- `StageCard` 的 backend 选择器：用 capabilities 过滤出「自报输出属性」的 backend / model；纯检测器仍可选但加 ⚠ 标注「该后端不产属性，下游富集可能为空」。
- 实现：复用 `usePreannotateConfig` 已拉的 `setupQ` / capabilities，读 `output_attribute_schema` 存在性。门控在 StageCard 容器层判断，不改共享 hook。

### 2.5 单 backend 兜底 + 拓扑分组

- StageCard 默认下游 backend 现取「首个 != 源」；项目只绑 1 个时为 null → 渲染提示卡「需先在项目设置绑定第二个 backend 才能加分类阶段」，禁用配置。
- 视觉：源阶段卡与下游卡之间加一条「↓ 对每个检测框裁 ROL」的连接说明 + 并行兄弟用同一左括号分组（纯 CSS，沿用 `stageTwoBlock` 描边风格），让扇出结构一眼可读。

## 3. 实施步骤（每步带 verify）

1. 类别多选 → verify：StageCard 父框类别从文本框改多选，选项=项目类别，提交 payload `parent_class_filter` 正确；类别路由行为不变。
2. 属性键多选 → verify：write.keys 从文本框改多选，选项来自 backend 自报 schema；空选=全键。
3. 键冲突预警 + last_wins 开关 → verify：两卡选同键 → 顶部红字 + chip 标红 + reject 模式 canRun 禁用；开 last_wins → 放行。
4. 能力门控 → verify：下游选择器对纯检测器加 ⚠；自报属性的 backend 正常。
5. 单 backend 兜底 + 拓扑分组 → verify：单 backend 项目加阶段时出提示卡；多卡渲染为并行分组。
6. 前端校验：`pnpm lint`（含 css-token）、tsc、`ProjectDetailPanel.test.tsx` 回归；新增 StageCard 选择器交互测试。
7. 版本收尾：bump 四处 + `uv lock` + openapi 快照（前端为主，后端无 schema 变更则快照不变）；`curl /health` 验证 0.18.5。

## 4. 验收标准

- 非工程师管理员配 `parent_class_filter` / `write.keys` 全程点选、不手敲，杜绝拼写误配。
- 两卡写同键在配置期即被拦/警示，不再跑完才 422。
- 下游 backend 选择器对「不产属性」的后端有明确警示。
- 单 backend 项目加阶段有清晰引导，不再静默不可用。

## 5. 风险 / 开放问题

- **检测器类名 ↔ 项目类别集不一致**：多选列项目类别，但检测器可能输出项目未配的类名 → 该框不被任何阶段命中（降级）。文案需说明「按检测框类名匹配」，避免误以为漏配。
- **共享组件耦合红线**：能力门控 / 选择器都在 StageCard（容器层）做，**勿渗进 `usePreannotateConfig`**，否则工作台 AI 面板被动继承。Review 重点。
- **backend 自报 schema 缺失**：未补 `output_attribute_schema` 的下游 backend，write.keys 回落项目 schema，仍可用但选项可能不完全匹配；属可接受降级。
