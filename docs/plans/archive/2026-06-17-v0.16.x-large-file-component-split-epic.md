# v0.16.x · 巨石文件拆分 Epic(降低单文件代码量)

> 规划日期 2026-06-17 · 范围:把三个体量与维护风险最高的源文件,按其**已经存在的内部职责边界**拆成多个文件/hook/router,降低单文件代码量、缩短认知半径。
>
> **这是一次纯结构重构,不改任何行为、不改 API、不改数据结构。** 红线见 §2。
>
> **触发来源**:2026-06-17 用 `cloc --by-file`(排除第三方 `vendor/` 与测试)对全仓做单文件体量盘点,确认下列三个文件远超同类、且内部职责可清晰切分。

## 1. 为什么是这三个(实测依据)

`cloc` 排除 `vendor/`(SAM3 / grounded-sam-2 第三方)与 `tests/` 后,自有代码单文件 SLOC Top 榜:

| 排名 | 文件 | SLOC(cloc) | 物理行 | 拆分信号 |
|---|---|---|---|---|
| 1 | `web/.../stages/three-d/ThreeDWorkbench.tsx` | **2661** | 2946 | 23×`useState` / 35×`useEffect` / **43×`useCallback`** — 典型 God Component,一个组件扛点云+相机+PSR 编辑+框选+点掩膜+浮面板 |
| 2 | `web/.../state/useWorkbenchShellModel.tsx` | **2362** | 2605 | 21×`useState` / 32×`useEffect` / **47×`useCallback`**,返回巨型对象 — 单 hook 扛整个工作台 shell 状态 |
| 3 | `api/app/api/v1/tasks.py` | **2271** | 2695 | **43 个 HTTP 端点**挤在一个 router(任务 CRUD / 视频流 / 标注 / 预测 / 生命周期 / 审核 / 锁) |

> 第 4 名 `dashboard.py`(1634)、第 5 名 `ImageStage.tsx`(1450)等本 epic **暂不纳入**——它们偏长但内聚,拆分属优化而非必需。先解决前三的高维护风险,后续视收益再议(§6)。

**不动的大文件**:`vendor/**` 第三方(2700+ 行那些)非本仓维护范围;`python-sdk/.../tui/app.py`(1323)TUI 框架天然集中,拆收益有限。

## 2. 重构红线(三条,违反即视为本次重构失败)

1. **行为零变化**:这是搬运,不是改写。移动后的代码逐行等价于移动前,**不顺手"改进"**(不重命名、不调顺序、不补 error handling、不优化算法)。对应 CLAUDE.md §3 外科手术原则。
2. **测试先绿、后绿、逐版本绿**:每个子版本开工前先跑全套测试存档为绿基线;拆完必须同一套测试仍全绿,**不新增/不删除/不修改断言**(除非纯粹是 import 路径迁移)。对应 CLAUDE.md §4。
3. **每个子版本独立可发、独立可回滚**:三个目标互不依赖,各自一个 commit/PR,任一单独 revert 不影响其余两个。

> 说明:本 epic **只做物理拆分**(把代码块挪到新文件并用 import 接回),不做"顺便重设计 state 形状/数据流"这类语义重构——那会同时引入行为风险且无法用"测试不变"来守护。若拆的过程中发现明显设计问题,**记下来另开 issue**,不在本 epic 处理。

### v0.16.10 — 拆 `useWorkbenchShellModel.tsx`(按领域抽子 hook)

**现状**:单 hook 内聚了至少 7 条独立关注线,返回一个巨型对象。已有同级 `useWorkbench*.ts`(`useWorkbenchHotkeys` / `useWorkbenchConfig` / `useWorkbenchAnnotationActions`)作为**拆分范式样板**——按同一形态继续切。

**实测关注线 → 目标子 hook**:

| 抽出子 hook(`state/` 下) | 承载状态/逻辑 | 当前行段参考 |
|---|---|---|
| `useBackendRouting.ts` | `batchBackendId` / `interactiveBackendId` / routing 并集 / 常驻 session 手动标记 | 303–460 |
| `useAiConfigPanel.ts` | `preCfg` 共享配置区 / `handleRunAi` / `buildArgs` / AI 面板 backend 选择 | 1180–1624, 2506+ |
| `useAiOverlayLayout.ts` | `aiPopover*` / `aiDrawer*` 位置尺寸 + localStorage 持久化 | 462–493 |
| `usePredictionPropagation.ts` | 预测缓存失效 / 跨帧 propagate / 插值对话框 | 584–1107 |
| `useIssuePins.ts` | `issueCreate*` / `issuePin*` / 图钉聚焦联动 discussion | 839–950, 2333 |
| `useStageViewport.ts` | `stageGeom` / `fitTick` / `winWidth` / 窗口适应 | 458–493, 1800–1987 |

**做法**:`useWorkbenchShellModel` **保留为顶层编排 hook**,内部改为调用上述子 hook 并把它们的返回**原样拼进**最终返回对象——对外 API(返回对象的字段)**一字不改**,消费方(`WorkbenchShell` 等)零改动。这是降低单文件行数、不动数据流的最稳路径。

**风险点**:子 hook 间有共享依赖(如 `selectedAnnotation` / `currentTask` / mutation)。抽取时这些作为**参数传入**子 hook,不在子 hook 内重新 `useQuery`(否则改变请求次数=行为变化,违反红线 1)。

**验证**:无现成组件测试是已知缺口(见画布统一 epic §决策 C),故本子版本**主要靠类型 + 手动冒烟**:`pnpm build` 类型零错、`pnpm lint`(含 `check-css-tokens`)、手动走查工作台核心流(选标注/跑 AI/跨帧传播/issue 图钉)。**拆前先截一份"返回对象字段清单"**(`Object.keys`)做前后比对,确保字段集不变。

## 4. 统一验证口径

每个子版本 PR 必须满足:

1. `uv run pytest`(后端目标)/ `pnpm build` 类型检查 + `pnpm lint`(前端目标)全绿。
2. **行为不变证据**:后端=OpenAPI 快照零 diff;前端=hook 返回字段集/组件 props 前后一致(附 `Object.keys` 对比或类型签名 diff)。
3. 单文件 SLOC 实测下降:拆完对目标文件再跑一次 `cloc <file>`,在 PR 描述里贴"拆前 N → 拆后 M + 新增 k 个子文件各 x 行"。
4. 重构不进 CHANGELOG 的常规 bug 修复豁免**不适用**——这是结构变更,但属内部重构、对用户无感:按 memory `feedback_changelog_bugfix` 精神,**可不进 CHANGELOG,但同步受影响的 docs**(若 `docs-site/dev/concepts/` 有引用这些文件路径/结构的图,需更新)。

## 5. 顺序与风险

```
v0.16.9  tasks.py 拆 router      → 风险低,机械,先做立信心 + 验证 OpenAPI 守护有效
v0.16.10 useWorkbenchShellModel  → 风险中,子 hook 范式已有样板,靠类型+冒烟
v0.16.11 ThreeDWorkbench         → 风险高,体量最大、测试最薄,最后做
```

- **不并行**:三者虽互不依赖,但均触碰工作台热路径,串行做便于每步隔离回归、定位问题。
- **若某步拆到一半发现职责其实纠缠**(无法在不改行为前提下干净切分):停下,记入 issue,该子版本**缩小范围或跳过**,绝不为"拆干净"而引入行为变化。
