## 背景

v0.9.3 打底的 API Key 是「phase 1 基础设施」:CRUD + bcrypt + prefix + scopes(**仅记录不强制**) + last_used + 软删除,可用于生产认证,但三处明显未闭环:

1. `scopes` 存了但路由层从不校验([ApiKeysPanel.tsx](../../apps/web/src/components/users/ApiKeysPanel.tsx) 里都写着「v0.9.3 phase 1 仅记录 scope,未在路由层强制拦截」)。
2. 无 `expires_at`,所有 key 永不过期,`resolve_token()` 无过期校验。
3. 只能撤销重建,不能 rotate / 改名 / 改 scope。

本版把这三点闭环,并加一个 `full-access` 通配 scope(运维/集成场景一键全权),前端创建界面重做。

## 红线

1. **不破坏现有认证路径**:JWT/cookie/密码登录的 principal 一律视为 full-access,**不受 scope 拦截**;scope 仅约束 `ak_` api_key principal。绝不能让带 scope 的拦截误伤 WebUI 自身的会话请求。
2. **撤销/过期即时生效**:`resolve_token()` 必须在认证入口处校验 `revoked_at` 与 `expires_at`,不依赖缓存。
3. **明文仍只返回一次**:rotate 同样遵守——返回新明文一次,旧明文立即失效。

## 范围 A · 过期时间 `expires_at`

- **迁移 0050**:`api_keys` 加列 `expires_at TIMESTAMPTZ NULL`(null = 永不过期)。
- **模型** [api_key.py](../../apps/api/app/db/models/api_key.py):加 `expires_at: Mapped[datetime | None]`。
- **认证校验** [api_key_service.py](../../apps/api/app/services/api_key_service.py) `resolve_token()`:命中 hash 后,`if key.expires_at and key.expires_at < now(): return None`(与 `revoked_at` 同等对待)。
- **创建入参** [schemas/api_key.py](../../apps/api/app/schemas/api_key.py):`ApiKeyCreate` 加可选 `expires_at` 或 `expires_in_days`(二选一,倾向 `expires_in_days: int | None`,后端换算为绝对时间,避免客户端时钟漂移)。
- **SDK 模型** [models.py](../../packages/python-sdk/src/ai_annotation/models.py):`ApiKey` 加 `expires_at: datetime | None`。

## 范围 B · Scope 真正强制(仅已定义 scope 的写路由)

现有 scope 枚举(前端 [ApiKeysPanel.tsx](../../apps/web/src/components/users/ApiKeysPanel.tsx)):
`annotations:read` · `annotations:write` · `predictions:read` · `datasets:read`。

- **principal 透传** [deps.py](../../apps/api/app/deps.py) `get_current_user()`:走 api_key 路径命中时,把 `key.scopes` 存进 `request.state.api_key_scopes`(JWT 路径不设置该 state → 表示 full-access principal)。
- **依赖工厂** `require_scopes(*needed: str)`(放 `deps.py`):
  - 读 `request.state.api_key_scopes`;未设置(JWT/密码登录) → 放行。
  - 含 `"*"`(full-access) → 放行。
  - `needed` 全部 ⊆ scopes → 放行;否则 `403 insufficient_scope`(WWW-Authenticate 带 scope 提示)。
- **挂载点(本版仅这些,已定义 scope)**:
  | scope | 挂到哪些写路由(示例,实际以路由清单为准) |
  |---|---|
  | `annotations:write` | 创建/更新/删除标注 |
  | `datasets:read` | 数据集读端点(给只读 key 用) |
  | `predictions:read` | 预测读端点 |
  - 注:`annotations:read` 是读 scope,本版给对应读端点挂上即可;**其余未定义 scope 的路由一律不挂**,行为不变。
- **明确不做**:不新造 scope、不给项目管理/导出/ML backend 等未定义 scope 的路由挂拦截。

## 范围 C · 轮换 / 编辑端点

- **`POST /me/api-keys/{id}/rotate`** [api_keys.py](../../apps/api/app/api/v1/api_keys.py):
  - 服务层 `rotate_key(db, user_id, key_id)`:校验归属 + 未撤销;重新 `generate_token()`,更新 `key_hash`/`key_prefix`,保留 `id`/`name`/`scopes`/`expires_at`,清空 `last_used_at`;返回 `(entity, plaintext)`。
  - 响应同 create:`ApiKeyCreated`(含一次性 plaintext)。旧明文立即失效。
- **`PATCH /me/api-keys/{id}`**:
  - 服务层 `update_key(db, user_id, key_id, name?, scopes?, expires_at?)`:部分更新,不动 hash。
  - 入参 schema `ApiKeyUpdate`(全可选)。
- **SDK** [client.py](../../packages/python-sdk/src/ai_annotation/client.py) `ApiKeys`:加 `rotate(key_id)` / `update(key_id, *, name=None, scopes=None, expires_at=None)`;`_http.py` `USED_ENDPOINTS` 补两条。

## 范围 D · `full-access` 通配 scope

- 约定 scope 字符串 `"*"` = 全权。`require_scopes` 见范围 B(含 `"*"` 直接放行)。
- 后端不需新字段,纯靠 scopes 数组里有没有 `"*"`。
- 前端见范围 E(创建表单加「完全访问」选项,选中即 `scopes=["*"]` 并禁用细分项)。

## 范围 E · 前端创建界面美化

[ApiKeysPanel.tsx](../../apps/web/src/components/users/ApiKeysPanel.tsx) 创建表单重做:

- **权限区**:细分 scope 多选 checkbox **+ 顶部一项「完全访问 (full-access)」开关**。选「完全访问」→ 提交 `scopes=["*"]`,细分项禁用置灰;反之走多选。
- **有效期区**:下拉(30 天 / 90 天 / 永不过期 / 自定义日期),映射到 `expires_in_days`(永不 = null,自定义 = 算天数或直接传 `expires_at`)。
- **文案**:删除「v0.9.3 phase 1 仅记录 scope,未在路由层强制拦截」提示,改为 scope 真实生效的说明(并提示「未勾选完全访问的 key 只能访问所选范围」)。
- **列表**:加「有效期」列(显示到期日 / 「永不」/ 「已过期」灰显徽标);操作列加「轮换」(走 SecretReveal 展示新明文)与「编辑」(改名/改 scope/改有效期)。
- API 客户端 [apiKeys.ts](../../apps/web/src/api/apiKeys.ts) + hooks [useApiKeys.ts](../../apps/web/src/hooks/useApiKeys.ts):加 `rotate` / `update`,成功后 invalidate 列表缓存。
