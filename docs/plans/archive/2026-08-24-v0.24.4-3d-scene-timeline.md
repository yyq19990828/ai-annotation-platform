> Approved on: 2026-08-24

## 1. 结论

本版本交付一个只读、窗口化、虚拟化的 3D Scene 时间轴。它常驻点云工作台底部，解释当前帧、缺失帧、每帧 3D 标注密度和当前选中 `track_id` 的跨帧存在情况，并复用工作台已有保存保护切换任务。

本版本不引入异步作业、QC、候选确认或时间轴编辑。当前仓库没有统一的跨帧作业摘要合同，把这些状态并入同一响应会迫使时间轴发明另一套任务模型。它们继续由独立计划设计。

## 2. 当前基线与转定稿结论

- `Scene + DatasetItem.frame_index` 已是跨 task 帧序真值；3D task 通过 `TaskDatasetItemLink(role=primary_lidar)` 关联主帧。
- `Annotation.track_id` 已是跨帧对象身份；没有 `track_id` 的孤立标注只贡献帧密度。
- 邻帧端点最多返回 20 帧且需要展开整个 scene 映射，不适合作为 1 万帧时间轴摘要。
- 工作台已有 `navigateToCrossFrameTask`，它会执行未保存保护和现有 task 可见性检查；时间轴不建立第二套导航状态机。
- 当前 nuScenes mini E2E seed 已从本地缓存读取脚本下载的数据，但两个点云 task 未挂到同一 Scene，也没有稳定 `track_id`。本版本只补齐这些关系，不把数据文件搬入仓库。
- 3D 工作台已经完成视角生命周期与高频选框性能修复。时间轴使用独立的低频窗口状态，不进入 Three.js 渲染循环，也不监听对象拖拽帧事件。

## 3. 用户可见范围

### 3.1 时间轴内容

1. 紧凑标题栏：scene 名、当前帧、总有效帧数、折叠按钮。
2. 帧密度轨道：窗口内每个逻辑 frame index 的活跃 `box_3d` 与 `point_mask_3d` 数量。
3. 当前对象轨道：仅当选中标注存在 `track_id` 时展示该对象在窗口内出现的位置。
4. 帧状态：`available` 可导航、`unavailable` 无权访问、`missing` 没有主 task。
5. 当前帧使用品牌色语义标记；缺失帧和不可访问帧使用中性色，不泄露不可见 task id 或计数。

### 3.2 交互

- 点击可用帧调用现有跨帧导航。目标帧有同 `track_id` 标注时，在任务切换和标注加载完成后恢复该对象选择。
- 横向滚动只改变观察窗口，不改变当前 task；窗口变化触发可取消的区间请求。
- 当前 task 变化后把当前帧滚入视区；高频滚动期间不使用布局动画。
- 时间轴可折叠。无 Scene、缺少 `frame_index` 或 Scene 只有一个有效帧时完全隐藏。
- 帧按钮具备键盘焦点、`aria-label`、`aria-current` 和 disabled 语义。

### 3.3 明确非范围

- 不在时间轴拖动对象边界、创建关键帧、插值、传播、接受候选或改变 task 状态。
- 不显示异步 job、质检问题、预测候选计数、revision 或任意自定义轨道。
- 不一次性返回整个 Scene 的 annotation 明细，不为每帧逐条请求 annotations。
- 不修改数据库结构、依赖、环境变量或长期 feature flag。

## 4. 视觉与布局合同

视觉命题是“工作台底部的紧凑测量带”。时间轴与 3D 视口 flush 相接，使用语义化 `bg-card`、`border-border`、`text-foreground`、`text-muted-foreground` 和品牌色 token，不使用装饰卡片、阴影、渐变或裸颜色。

- 默认展开高度不超过 120 px，折叠态只保留约 32 px 标题栏。
- 单帧 cell 宽 40 px，保证鼠标和键盘命中；密度条按当前响应窗口最大值归一化。
- 不使用 motion。滚动、选帧和 track 切换都是高频生产交互，反馈依靠状态样式和现有按钮 press 行为。
- 只使用 Tailwind 语义类，不新增 CSS module 或样式依赖。

## 5. 冻结 API 合同

新增任务锚定端点：

```http
GET /api/v1/tasks/{task_id}/scene-timeline
  ?start_frame=0
  &end_frame=79
  &track_id=optional
```

`start_frame` 与 `end_frame` 是包含端点，必须为非负整数，`end_frame >= start_frame`，单次最多 200 帧。端点先按现有任务权限校验中心 task，再对窗口内 task 批量执行同口径可见性过滤。

响应固定为摘要版本 1：

```json
{
  "summary_version": 1,
  "scene_id": "uuid-or-null",
  "scene_name": "scene-or-null",
  "current_frame_index": 12,
  "scene_start_frame": 0,
  "scene_end_frame": 9999,
  "populated_frame_count": 9984,
  "window_start_frame": 0,
  "window_end_frame": 79,
  "frames": [
    {
      "frame_index": 12,
      "state": "available",
      "task_id": "uuid",
      "task_status": "in_progress",
      "annotation_count": 4,
      "selected_track": {
        "annotation_id": "uuid",
        "source": "manual",
        "class_name": "car"
      }
    }
  ]
}
```

合同细节：

- `frames` 显式覆盖请求闭区间内每个逻辑 frame index，前端不从数组空洞猜测权限或缺失状态。
- `missing` 表示该 index 没有主 task；`unavailable` 表示存在 task 但当前用户不可见。两者 `task_id=null`、`annotation_count=0`、`selected_track=null`。
- `available` 只聚合活跃、未取消的 `box_3d` 与 `point_mask_3d`。`track_id` 过滤只影响 `selected_track`，不影响总数。
- Scene 不存在或当前 `frame_index` 缺失时返回同一 Schema 的空态，所有 scene/frame 边界为 null、`populated_frame_count=0`、`frames=[]`。
- Scene 边界只统计带 `frame_index` 的主帧索引。多模态相机 item 不重复增加 `populated_frame_count`。

## 6. 查询与权限实现

```text
GET task scene-timeline
        │
        ├─ current task visibility
        ├─ resolve primary item → Scene / current frame
        ├─ aggregate Scene min / max / distinct frame count
        └─ query only requested frame window
                    │
                    ├─ direct DatasetItem task mapping
                    ├─ primary_lidar link mapping
                    ├─ batch-visible task id set
                    └─ annotation count + selected track occurrence
                                      │
                                      ▼
React Query cache → virtualized 40 px cells → guarded task navigation
```

实现使用固定数量的窗口批量查询，不在 Python 循环内发 SQL。直接 task 关联优先，`primary_lidar` link 只补缺。不可见 task 在进入 annotation 聚合前剔除。

## 7. 前端虚拟化与缓存

- `SceneTimeline` 保留总宽度 spacer，只渲染视区与左右各 12 个 overscan cell。
- 10,000 帧按 40 px 计算总宽 400,000 px，在 Chromium 安全滚动范围内；DOM 节点数只与 viewport 宽度相关。
- 请求窗口从虚拟范围扩展并限制在 Scene 边界内，每次最多 200 帧。React Query key 包含摘要版本、task、区间和 `track_id`，request signal 负责取消旧窗口。
- 不保留旧窗口占位数据，避免快速滚动时把旧帧状态画到新位置。
- annotation 创建、更新、删除、传播和插值成功后失效 `scene-timeline` 查询。

如果后续 Scene 大到 40 px 总宽接近浏览器最大滚动尺寸，再单独引入分级缩放或 Canvas 概览。本版本 1 万帧目标不需要提前增加该复杂度。

## 9. 实施切片与验收门

1. 区间摘要 API：API 测试覆盖普通、缺失、不可见、无 Scene、非法区间和 10,000 帧窗口边界。
2. 虚拟时间轴：纯函数证明 10,000 帧只生成视区加 overscan；组件测试覆盖空态、折叠、状态、轨迹和点击导航。
3. 导航接线：StageHost 测试证明 prop 传递；目标任务加载后恢复同轨迹标注选择。
4. nuScenes mini fixture：两个真实缓存点云帧属于同一 Scene，同一车辆使用稳定 `track_id`。
5. Chromium 验收：真实 seed 中时间轴可见、点击切帧、同轨迹恢复选择、折叠展开不影响视口，控制台无错误且没有逐帧 annotation 请求。

## 11. 回滚

移除只读端点、query hook、底部时间轴与 seed Scene 关系即可。该功能不写 annotation、不迁移数据，也不改变 task 状态，因此不需要数据回滚。若前端出现布局回归，可先断开 `ThreeDWorkbench` 的时间轴渲染，后端端点保留不会影响旧客户端。

## 12. Outcome

已按冻结合同完成实施，无范围偏差：

- 新增 task 锚定的 Scene 区间摘要 API，单次闭区间不超过 200 帧，权限、缺帧和选中轨迹均在固定数量的批量查询中解决。
- 工作台底部交付 40 px cell、12 个 overscan 的横向虚拟时间轴，完成帧密度、当前帧、轨迹存在性、折叠和受保护导航。
- nuScenes mini seed 直接使用用户缓存中的两个真实 `LIDAR_TOP` 帧，同属 `scene-0061` 并共享稳定 `track_id`；数据没有进入仓库。
- API 新增的 7 个专项测试及相关 Scene/邻帧回归通过；Web 全量 353 个测试文件、2,950 个用例通过，typecheck 和颜色 token 检查通过。
- 点云 Playwright E2E 通过。独立 Chromium 实测确认数据源为 `nuscenes_mini`，跨帧后选中轨迹恢复，折叠展开稳定，时间轴与点云视口无重叠，单次请求最大 80 帧，annotation 只读取进入过的 2 个 task，控制台无错误。
