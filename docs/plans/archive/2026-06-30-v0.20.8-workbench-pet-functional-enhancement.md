# v0.20.8 · 工作台桌宠功能增强：轻量状态代理

状态：已发版 · 2026-07-01

## 背景

v0.20.6 已有实验性工作台桌宠，v0.20.7 计划把默认外观从史莱姆式小精灵收敛为像素化小人，
并铺好轻量皮肤扩展基座。本版在外观稳定后继续增强“功能语义”：让桌宠成为工作台里的低干扰状态代理。

现有边界仍然成立：

- 桌宠是工作台 UI 层，不是独立聊天助手。
- 桌宠可以表达状态和提示，但不能替代 AI 面板。
- 桌宠不进入 `/ai-pre` 编排语义。
- 桌宠不触碰标注数据，不挂 mutation，不自动修正标注。

## 产品判断

功能增强的重点不是“让桌宠更会说话”，而是把工作台里已经存在、但分散在不同面板的状态，
用一个小而稳定的视觉锚点表达出来。

优先级应按“对当前标注动作是否有帮助”排序：

1. 当前选中对象状态。
2. 当前工具 / 当前题状态。
3. AI 当前题推理和候选状态。
4. 保存 / 离线 / 审核这类工作流状态。
5. 低频陪伴文案。

## 目标

1. 桌宠能根据当前工作台上下文显示更准确的状态，而不是只有 idle / holding / happy / celebrate。
2. 增加多选、AI 运行、候选待处理、警告、离线 / 保存中、审核等轻量状态。
3. 气泡内容从随机闲聊优先，调整为“上下文短提示优先，闲聊兜底”。
4. 保持纯前端派生，不新增后端字段、表、接口或标注 mutation。
5. 保持低干扰：状态提示短、少、可关闭，尊重 `prefers-reduced-motion`。

## 状态设计

在现有 `PetMood` 基础上扩展为两层：

- `mood`：控制外观姿态和动效。
- `message`：控制气泡或举牌文案。

建议 mood 集合：

| mood | 触发来源 | 表现 |
|---|---|---|
| `idle` | 无强上下文 | 站立 / 眨眼 |
| `holding` | 选中信息卡折叠 | 举牌显示选中标题 |
| `selected` | 有选中且信息卡展开 | 注视选中对象，弱提示 |
| `multiSelected` | 多选 | 举牌或手势显示数量 |
| `aiRunning` | 当前题 AI 正在运行 | 专注 / 思考姿态 |
| `candidateReady` | 有 AI 候选待采纳 / 审阅 | 轻提示，不抢 AI 面板 |
| `warning` | 仅 UI 派生的明显问题 | 提醒姿态 |
| `offline` | 离线队列 / 保存受阻 | 等待姿态 |
| `review` | 审核 / 评论上下文 | 检查姿态 |
| `happy` | 手工新增标注 +1 | 短暂开心 |
| `celebrate` | 里程碑 | 短暂庆祝 |
| `idleTalk` | 久坐 | 低频闲聊 |

优先级：

`celebrate / happy` > `offline` > `warning` > `aiRunning` > `candidateReady` > `holding` > `multiSelected` > `selected` > `review` > `idleTalk` > `idle`

## 实现方案

### WS1 · 桌宠上下文输入

把 `WorkbenchPetProps` 从当前的少量字段扩展为稳定上下文对象：

- `selection`
  - `count`
  - `title`
  - `collapsed`
  - `sourceKind`：manual / prediction / interpolated / legacy 等已有前端派生信息
- `ai`
  - `running`
  - `candidateCount`
  - `backendOnline`
- `workflow`
  - `saving`
  - `offlineQueueCount`
  - `readOnly`
  - `reviewMode`
- `quality`
  - `warningCount`
  - `primaryWarning`
- `counts`
  - `annotationCount`

这些字段全部从 `useWorkbenchShellModel` 现有状态派生，不新增 API。

### WS2 · 状态机重构

- 将状态机调整为 `usePetState`,返回 `{ mood, message, priority }`。
- 保留现有“标注数 +1 / 里程碑”逻辑，避免行为退化。
- 久坐闲聊降级为最低优先级；只在无选中、无 AI、无警告、无离线状态时出现。
- 增加稳定防抖：
  - AI 运行状态至少展示 800ms，避免一闪而过。
  - warning 状态不循环刷屏，同一 warning 文案一段时间内只提示一次。
  - offline / saving 状态变化不应导致布局抖动。

### WS3 · 选中与多选增强

- 单选折叠：继续举牌显示类别 / 标题，点击展开完整信息卡。
- 单选展开：信息卡保持桌宠驮卡形态，只露出桌宠下半身；桌宠不再重复显示完整标题，只弱提示来源：
  - AI 候选：`候选待确认`
  - 人工标注：`已选中`
  - 视频插值：`插值帧`
- 多选：显示 `已选 N 个`，点击仍打开 / 聚焦选中信息卡，不新增批量操作入口。

### WS4 · AI 当前题状态

只接工作台当前题 AI 面板语义：

- 当前题 AI 运行中：`aiRunning`
- 有候选待处理：`candidateReady`
- backend 不在线：仅在用户打开 AI 面板或尝试运行后提示，不常驻制造焦虑。

不做：

- 不展示 `/ai-pre` 批量任务状态。
- 不提供“运行项目编排”按钮。
- 不把 prompt、参数、模型选择塞进桌宠。

### WS5 · 质量提示

首版只做前端已有信息能稳定判断的提示：

- 必填属性缺失。
- 当前选中对象来自 AI 候选且尚未采纳。
- 多选里混入锁定 / 隐藏对象。
- 视频当前帧选中对象来自插值或 prediction keyframe。

暂不做需要新算法的检查：

- 高 IoU 重叠。
- 框过小 / 面积异常阈值。
- 跨帧轨迹断点自动诊断。
- 点云 / 图像投影一致性判断。

这些后续可以做，但不塞进本版。

### WS6 · 设置与安静模式

在现有 `common.petEnabled` 之外，暂不新增持久化字段。先把行为做保守：

- 默认只对关键状态出气泡。
- 久坐闲聊间隔继续较长。
- `prefers-reduced-motion` 下只保留静态姿态和必要文本。

如果试用反馈仍嫌吵，再追加 `common.petQuietMode`；本版不先加配置复杂度。

## 测试

- `usePetState` 单测：
  - transient 优先级高于普通状态。
  - offline / warning / aiRunning / holding 优先级正确。
  - 久坐闲聊不会覆盖上下文状态。
  - 标注数 +1 / 里程碑行为不退化。
- `WorkbenchPet` 单测：
  - 多选显示 `已选 N 个`。
  - holding 点击仍触发 `onExpand`。
  - AI running / candidate ready 渲染正确文案。
  - disabled 时 `WorkbenchLayout` 仍回退纯文字折叠小条。
- 工程检查：
  - `pnpm typecheck`
  - `pnpm lint:css-tokens`
  - `pnpm vitest run src/pages/Workbench`

## 验收

- 有选中对象时，桌宠能区分单选、多选、AI 候选、插值 / prediction 等来源提示。
- 当前题 AI 运行时，桌宠进入专注状态；候选出现后给短提示，但不抢 AI 面板。
- 保存 / 离线 / 只读 / 审核上下文能显示低干扰状态。
- 无重要上下文时，桌宠回到安静 idle；久坐闲聊不会覆盖工作状态。
- 所有功能仍是纯前端派生，不新增后端契约。

## 不在范围

- 不做聊天输入框。
- 不接 LLM。
- 不自动修标注或自动采纳候选。
- 不新增后端 API / migration。
- 不显示 `/ai-pre` 批量任务状态。
- 不做皮肤切换 UI；皮肤扩展基座由 v0.20.7 覆盖。
- 不做复杂质量算法或跨帧诊断。
