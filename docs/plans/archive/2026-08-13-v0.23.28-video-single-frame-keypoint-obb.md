## 1. 路线审计结论

当前视频路线不是整体未开工，而是主工作台已可用、四个长视频闭环仍未完成：

| 路线阶段                 | 当前状态 | 已有能力                                                                   | 仍缺能力                                                       |
| ------------------------ | -------- | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Phase 1 视频导入与帧服务 | 基本完成 | 导入、元数据、抽帧、缓存、manifest、Apple Silicon Chrome strict 资格       | Windows Edge、macOS Safari 的 1080p / 4K 资格数据              |
| Phase 2 视频 Track 工具  | 完成     | bbox / polygon / polyline / mask 轨迹创建、编辑、关键帧与 outside          | 无本版阻塞项                                                   |
| Phase 3 Tracker          | 部分完成 | 窗口拆分、上一窗口末帧几何续种、多实例边界关联                             | 后端可恢复的 context / session，失败重试后的同一上下文续追     |
| Phase 4 导出             | 部分完成 | 项目 / 批次级视频导出、紧凑轨迹、逐帧展开及现有格式策略                    | task / segment / frame range 选择、范围裁剪和跨 segment 聚合   |
| Phase 5 长视频协同       | 地基完成 | 固定连续 segment、领取、心跳、释放；tracker / mask 部分操作有 segment gate | overlap 区间、通用标注写入门、工作台切段与占用提示、重叠区协同 |
| Phase 6 Track 质量指标   | 未开始   | 仅有缺关键帧、重复关键帧、track identity 不一致等结构检查                  | overlap IAA、MOTA、IDF1、HOTA 的计算、存储、展示与失败诊断     |

因此下一版不把 segment 导出、协同、tracker context 和质量指标打成一个大版本。它们分别改变导出合同、
并发写入、ML backend 协议和异步评估链路，无法用一个小而可回滚的改动安全交付。

## 2. Delivered

让视频项目在当前帧创建和编辑两种已有后端 Geometry：

- `video_rotated_bbox`：拖拽创建、选中、移动、局部轴缩放、顶部旋转手柄调整角度；
- `video_keypoint`：按类别骨骼顺序落点、跳过、标记遮挡、拖动已有节点；
- 两种几何均使用独立工具单位、类别、属性、历史记录、离线队列和只读门；
- AAP JSON 与 Video JSON 精确保留两种几何，其他不支持的训练格式在 preflight 中明确报告跳过，
  不静默丢数据；
- 补齐定向单元测试、内置浏览器实页验收、用户文档、开发文档、路线图与 `CHANGELOG.md`。

完成标准：用户启用对应工具单位后，能在视频当前帧创建、编辑、撤销、刷新恢复并导出 exact Geometry；
切换到其他帧时标注不可见，回到原帧后状态不漂移。

## 3. Not building

- 不做 rotated bbox track、keypoint track、插值或 tracker 推理；
- 不做 segment / frame range 导出、overlap 协同、跨窗 tracker context 或 Track 质量指标；
- 不新增数据库迁移、API 路由、Geometry schema 版本、前端依赖或后端依赖；
- 不新增视频 YOLO-OBB、COCO Keypoints 等训练格式；
- 不重构 ImageStage / VideoStage 为统一大抽象；仅复用现有图像端数学函数与交互语义；
- 不迁移历史数据。现有 `video_rotated_bbox` 继续原样可读，`video_keypoint` 也无需数据转换。

## 4. Approach

### 4.1 工具单位与工具入口

- `rotated-box` 归属 `rotated_bbox`，`keypoint` 归属 `keypoint`；两者不挂到 `bbox`。
- 两个工具单位的 `dataTypes` 增加 `video`，视频侧只登记 `video_modes.box`，不展示 track 变体。
- `VideoTool` 增加 `rotated-box` 与 `keypoint`，集中映射到各自单位的 `box` 变体。
- 工具栏复用图像侧图标和说明；快捷键固定为 `W`（OBB）和 `F`（Keypoint），当前视频快捷键无冲突。
- Keypoint 单位未配置节点时，工具置灰并提示先配置骨骼，不允许进入无法完成的绘制态。

### 4.2 OBB 创建与编辑

- 创建沿用图像端 `RotatedBboxTool`：先拖出角度为 `0` 的矩形，再进入选中态。
- 持久化合同保持现有 `frame_index + cx + cy + w + h + angle`；坐标归一化，角度统一到
  `[0, 360)`。
- 绘制复用现有 OBB 四角计算；命中使用旋转多边形，不用 AABB 冒充真实命中区域。
- 选中后显示八个局部轴 resize handle 和一个顶部 rotation handle；resize 复用
  `applyRotatedResize()`，旋转沿中心计算指针角度。
- 移动、缩放和旋转只更新当前 Annotation 的同一帧 Geometry，通过现有更新、撤销 / 重做、离线队列和
  `readOnly` 门提交，不新增专用保存通道。

### 4.3 Keypoint 创建与编辑

- 创建沿用图像端 `KeypointTool` 和类别级 `keypoint_schema` 顺序：左键落可见点，`Alt + 左键` 落遮挡点，
  右键跳过并记录 `v=0`。
- `points[]` 长度始终与 schema 节点数一致，点结构固定为 `{x, y, v}`；坐标归一化。
- 绘制复用 schema 的节点颜色和 edges；`v=0` 不画节点 / 连线，`v=1` 使用遮挡样式，`v=2` 使用正常样式。
- 选择标注后允许拖动 `v>0` 的单个节点；`Alt + 点击节点` 在 `v=1` 与 `v=2` 之间切换。
- 不在本版增加节点插入、删除或骨骼编辑；schema 仍由项目工具单位配置入口维护。

### 4.4 帧语义与选择

- 两种几何只在 `geometry.frame_index === currentFrame` 时进入 frame view、渲染、命中和侧栏当前帧集合。
- 创建时写入当前帧索引；移动、resize、rotate 或节点编辑不得改变 `frame_index`。
- 类别切换、重命名、属性、删除和详情指标复用现有 Annotation 侧栏与上下文菜单。
- OBB 指标显示中心、宽高和角度；Keypoint 指标显示已标注 / 遮挡 / 跳过节点数。

### 4.5 导出与导入安全

- AAP JSON 继续通过 Geometry union 原样导出 / 导入；补齐无 `tool_unit_id` 文件的 fallback：
  `video_rotated_bbox → rotated_bbox`、`video_keypoint → keypoint`。
- Video JSON 为两种几何增加 lossless 分支：OBB 保留 `cx/cy/w/h/angle`，Keypoint 保留完整
  `points[{x,y,v}]`，不把 OBB 降级为零角度 bbox，也不把 Keypoint 当作 polygon 点对。
- 现有 bbox / segmentation frame packaging 白名单不直接扩成全局“视频几何白名单”；按导出目标分别声明支持，
  避免 MOT、KITTI、YOLO-frame 等格式误收后静默转换。
- 不支持的目标由现有 preflight 返回明确 warning / loss 项；导出作业结果与 preflight 使用同一支持矩阵。

## 5. Key decisions

1. **复用已有 schema，不升版本。** 两种后端 Geometry 已在 union 中，新增迁移或第二套 payload 都是重复建设。
2. **按几何独立工具单位。** 采用当前 `rotated_bbox` / `keypoint` 绑定模型，旧 schema 注释中“Keypoint 挂 bbox”
   的表述随实现纠正，不恢复旧草案的错误归属。
3. **每种几何随交互一起补导出安全。** 不先开放创建、再留一个会静默漏导出的窗口。
4. **只共享稳定数学与语义。** 优先复用 `RotatedBboxTool`、`KeypointTool`、OBB resize 和 keypoint 颜色逻辑；
   如果图像组件 props 与视频状态耦合，则写薄视频 shape，不为两个工具抽象整个 Stage。
5. **长视频能力拆版。** 后续优先顺序为范围导出 → overlap 协同 → tracker context → Track 指标；
   本草案不为这些未来版本预建接口。

## 7. 可独立合并的实施顺序

### Phase A：视频单帧 OBB 闭环

- 开放 `rotated_bbox` 视频工具单位和 `W` 工具；
- 完成创建、渲染、真实命中、移动、局部轴 resize 与 rotation handle；
- 同一改动补 AAP / Video JSON exact round-trip 和其他格式 preflight loss；
- 更新 OBB、工具单位、视频工作台与导出文档。

验收：在任意非首帧创建 OBB，旋转跨过 `0°`、按局部轴缩放、撤销 / 重做、刷新后数值稳定；切帧不串帧；
AAP JSON 和 Video JSON 回读后的 `frame_index/cx/cy/w/h/angle` exact。

### Phase B：视频单帧 Keypoint 闭环

- 开放 `keypoint` 视频工具单位和 `F` 工具；
- 完成按 schema 落点、跳过、遮挡、骨骼渲染与节点编辑；
- 同一改动补 AAP / Video JSON exact round-trip 和其他格式 preflight loss；
- 更新 Keypoint、工具单位、视频工作台与导出文档，并收口路线状态。

验收：带 edges 的 schema 能完整落点；`v=0/1/2` 渲染、编辑、撤销 / 重做和刷新结果一致；切帧不串帧；
AAP JSON 和 Video JSON 回读后的节点顺序、坐标和 visibility exact。

两阶段均可单独回滚；Phase A 不依赖 Keypoint，Phase B 只复用已经存在的通用视频单帧提交链路。

## 9. 风险与回滚

- 最大风险是旋转坐标系与视频缩放 / pan 组合后的指针换算。只保留一个 stage → image 坐标入口，并用
  `0°/90°/359°` 与缩放后拖动覆盖回归。
- Keypoint 风险是 schema 变更后历史实例节点数不一致。本版沿用图片端当前规则：历史 Geometry 原样可读，
  新建使用当前 schema；不在读取时补点或截断。
- 无数据库迁移。回滚前端工具不会破坏已写入数据；后端 union、AAP JSON 和 Video JSON 仍能保存这些 Geometry。
- 如果图像端工具无法在不引入 Stage 大重构的前提下直接复用，则退回两个薄视频交互实现；不扩大重构范围。
