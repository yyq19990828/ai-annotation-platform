# v0.20.13 · 二次推理参数控制（单框推理阈值 / 参数与批量对齐）

状态：**已落地（v0.20.13）**。v0.20.11 的**能力补齐**——单框二次推理原只用模型默认参数，现补上阈值等控制。
**依赖 v0.20.11**（增强 `SecondaryInferenceBar`）。

## 背景

批量预标 / 交互工具栏都能让用户调模型参数（阈值等，`SchemaForm` 按 `model.params` JSON Schema 渲染），
但 v0.20.11 的 `SecondaryInferenceBar` **只发模型默认**——`buildSecondaryInferencePayload` 里 `params`
恒为空，用户无法为单框推理调 `score_threshold` / `box_threshold` 等。与批量的 parity gap。

## 现状（已核实）

- `SecondaryInferenceRequest.params`（`schemas/annotation.py`）已透传到 `_build_predict_context`，
  后端已支持——**只差前端给值**。
- `MLModelCapability.params`（`{type, properties}` JSON Schema）已在能力数据里，`SchemaForm`
  （`apps/web/src/pages/Workbench/components/SchemaForm.tsx`）已是批量 / 交互两处的参数渲染单一事实源。
- `default_thresholds` / `params.properties.*.default` 提供默认值。

## 工作项

### WS1 · 参数面板

- 选中一个能力后（或每个能力按钮展开），用 `SchemaForm` 按该 `model.params` 渲染参数控件，
  初值取 `params.properties.*.default` / `default_thresholds`。
- 参数状态存组件内（单框一次性推理，不必持久化；如需可后续接用户偏好，本版不做）。
- `buildSecondaryInferencePayload` 增参：把用户调过的 `params` 带进请求。

### WS2 · 交互形态

- 保持 `SecondaryInferenceBar` 紧凑：默认收起，点能力旁「参数」小图标展开 `SchemaForm`，
  避免一次性铺开多能力的参数把浮块撑爆。
- 无参数（`params.properties` 空）的能力不显示参数入口。

## 风险

- 参数键透传要落到 `_build_predict_context` 的正确路径（文本扁平 / v2 结构化 / 老扁平三态，
  见 [[project_interactive_candidate_coords]] 同源的 wire 差异）——后端已处理，前端只需原样带 `params`。
- 不同能力 params schema 不同，`SchemaForm` 已按 schema 渲染，无需特判。

## 验收

- 选属性分类能力 → 展开参数 → 调 `score_threshold` → 跑 → 后端收到该值（context.params 透传）。
- 无 params 的能力不显示参数入口。
- 与批量 `SchemaForm` 同组件、同渲染，无分叉。

## 依赖 / 不在范围

- **依赖 v0.20.11**；`SchemaForm` 复用批量 / 交互现成组件。
- 不做：参数持久化（用户偏好）、多能力并排参数对比。
