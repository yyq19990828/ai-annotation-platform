## 2. 迁移规约

**完全沿用 v0.17.4 计划 §2 的迁移规约**(颜色 token 映射、彩色文字暗色配对、门禁硬规则、禁 style 属性 + useElementStyle、UA 漏样基线、复用 ui/ 组件、只换表现、测试)。样板:`pages/Admin/SystemHealthPage.tsx`、`pages/Admin/AdminPeoplePage.tsx`、`pages/Dashboard/DashboardPage.tsx`、`components/ui/Modal.tsx`。

补充本版要点:
- **tw-scope**:Shell 各持久区域(Sidebar / TopBar / SidebarDrawer)是 AppShell 直接渲染的独立根 —— **各自根加 tw-scope**。Review 路由级页面(ReviewPage)根加 tw-scope;其内部子件(ReviewSidebar/MiniPanel/Workbench chrome)在 ReviewPage 的 tw-scope 内则不加。
- **Popover/Portal 浮层**(NotificationsPopover / JobsBell 下拉 / PreannotateJobsBadge 浮层):若自绘 `createPortal` 到 body,浮层根需 tw-scope;若已用 `ui/DropdownMenu`/`ui/Tooltip`/`ui/Modal` 则继承其 scope,不加。先逐个确认。
- **侧边激活态**:用设计规范彩色点缀(如 emerald 软底 / brand 软底 + 左边 active 条),保持原激活语义。
- **Shell 是高可见高风险**:UA 漏样在顶栏按钮 / 侧栏 nav 最扎眼,UA-safe 基线务必全;迁完**每个 Shell 件都要暗色 + 亮色肉眼回归**。
- `RejectReasonModal` 走 `ui/Modal`(已挂 tw-scope),弹窗内容不加 tw-scope。

## 3. 风险点

- **Sidebar / TopBar 持久全局**:迁移期它们与未迁页面共存于同一 DOM 树。各自 tw-scope 互不干扰(局部 reset),安全。但要确保 nav 激活态 / 折叠态 / 抽屉态(移动端 SidebarDrawer)逻辑零改动。
- **JobsBell / NotificationsPopover 数据密集 + 实时**(socket 驱动):只换皮,不动 socket/轮询/状态逻辑;未读红点 / 徽标计数走语义色(rose 点 / brand 计数)。
- **ReviewPage(296)** 最大,审核队列 + 操作栏;`ReviewWorkbench` 是审核画布 chrome(工具条/信息栏),画布本体不动。
- 逐文件确认无跨文件共享 module.css(v0.17.4 踩过 capability/Rendering 两次共享坑)。
