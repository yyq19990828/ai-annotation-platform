## 1. 背景与问题

平台**导出**支持 `yolo-det / yolo-obb / yolo-seg`(projects.py:789),但**导入**只支持 `aap_json / coco`([predictions.py:265](../../apps/api/app/api/v1/predictions.py#L265) `pattern="^(aap_json|coco)$"`)——导出/导入不对称,YOLO 数据导得出导不回。

YOLO 与 COCO/AAP 的组织形式差异(决定实现难点)：

| | 文件形态 | 类别 | 坐标 | 图像尺寸 |
|---|---|---|---|---|
| COCO/AAP | 单个 JSON 总文件 | 文件内自带名 | 文件内自带 | COCO 自带 width/height |
| **YOLO** | **每图一个 `.txt`** + `classes.txt`/`data.yaml` | `.txt` 只有**类别索引** | 归一化,无尺寸 | **无,需外部** |

## 2. 关键设计决策

### 2.1 图像尺寸:走 DatasetItem 真值,不要用户填
后端已有 `DatasetItem.width/height`([dataset.py:59-60](../../apps/api/app/db/models/dataset.py#L59)),导出端已在用([export.py:478](../../apps/api/app/services/export.py#L478));兜底有 PIL 探测([storage.py:277](../../apps/api/app/services/storage.py#L277))。
→ YOLO 导入**直接按匹配到的 task 取 DatasetItem 尺寸**,无需 `image_size_hint`,比 COCO 体验更好(YOLO 框归一化坐标其实不需要尺寸,但 obb/seg 转内部几何、以及与 task 像素一致性校验时用得上)。

### 2.2 上传形态:zip 包(含 labels/ + 类别文件)
YOLO 天然是一堆 `.txt`。比起多文件多选,**接受一个 zip**(内含 `*.txt` + `classes.txt` 或 `data.yaml`)更贴合 YOLO 习惯,也避免类别文件漏选。导入端点新增 `format=yolo`,接受 zip。

### 2.3 task 匹配:按文件名 stem(去扩展名)
YOLO `.txt` 名是 `001.txt`,对应图像 `001.jpg`。现有 `resolve_task`([task_matcher.py](../../apps/api/app/services/task_matcher.py))按**完整 file_path(含扩展名)**匹配,YOLO 需**按 stem(去扩展名)+ 相对目录**匹配——这是**新匹配模式**,需在 task_matcher 增一条 "stem 匹配"分支(或导入侧把 txt stem 映射到候选图像扩展名集合再匹配)。**注意同 stem 跨目录/跨扩展名歧义**,沿用现有"带子目录才精确匹配"的防误匹配策略。

### 2.4 行格式解析
- `yolo-det`:`cls cx cy w h`(归一化)→ **bbox**。
- `yolo-obb`:`cls x1 y1 x2 y2 x3 y3 x4 y4`(归一化四角)→ **rotated_bbox**(由四角反算 cx,cy,w,h,angle)或退化 **polygon**;与导出 obb 对称,需确认导出端 obb 的角点顺序约定。
- `yolo-seg`:`cls x1 y1 x2 y2 ...`(归一化多边形)→ **polygon**。
- 类别索引 → 名字:按 `classes.txt`/`data.yaml` 顺序(索引=行号);再按名字映射到项目类别(命中不到 → errors[] 累计)。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| stem 匹配跨目录/跨扩展名歧义 | 沿用"带子目录才精确匹配" + stem 命中多条时进 errors[] 不猜 |
| obb 四角顺序与导出端不一致 | 实现前先核对导出 obb 角点约定,round-trip 单测锁定 |
| zip 结构千差万别(labels/ 子目录、data.yaml 缺失) | 宽松解析 + 清晰 errors[];类别文件缺失则要求用户提供或回退项目类别顺序 |
