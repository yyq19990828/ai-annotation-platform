## 2. 版本目标

v0.23.30 交付一个默认关闭、可独立回滚的长视频协同闭环：

1. 相邻 segment 拥有明确的重叠工作区，标注结果按 segment 隔离保存。
2. SAM2 与 SAM3 interactive tracker 在能力允许时复用后端 session，而不是每个 window 重新初始化。
3. 相邻 segment 提交后自动生成 Track 质量报告，审核员完成边界身份对账。
4. 只有边界报告全部有效并已接受时，才生成无重复的 canonical 全视频轨迹和全任务导出。

成功标准：两名项目成员能同时处理同一个视频 Task 的相邻 segment，互不覆盖数据；审核员能从边界指标跳到具体帧并完成轨迹身份确认；通过审核的结果可以稳定聚合为一份全视频导出。

## 3. 明确不做

- 不迁移或自动拆分已有视频 Annotation；协同模式只允许在没有有效 Annotation、没有运行中 tracker job 的视频项目启用。
- 不引入 OT、CRDT、实时光标或 Presence；segment lease 已足以隔离写入。
- 不重做已完成的单帧 keypoint、rotated-box 和旋转手柄。
- 不把单帧 keypoint / rotated-box 混入 TrackEval；它们只参与 segment 归属和 canonical 导出。
- 不在第一版为 polyline 发明面积 IoU；Track 质量报告将其标记为不支持。
- 不新增通用工作流引擎、事件总线或“以后可能用到”的 tracker 抽象。
- 不让未对账或已过期的边界结果静默进入全任务导出。

## 4. 架构决策

ADR-0066 已记录以下四项决定及其后果。

### D1. Segment fragment 是协同模式下的写入真相

- `VideoSegment.start_frame / end_frame` 继续表示互不重叠的 core range，避免破坏现有范围导出语义。
- `Annotation` 新增可空的 `video_segment_id` 外键。协同项目的视频 Annotation 必填；旧项目保持 `NULL`，继续使用单人全轨模式。
- 每个 segment 保存自己的 track fragment。相邻 fragment 可以指向同一真实目标，但不会共享一行 Annotation。
- canonical 全轨是 accepted boundary decisions 之上的派生读模型，不再写回一条新的“完整轨迹”作为第二份真相。

### D2. Overlap 是相邻 core range 的对称扩展

项目新增 `video_collaboration` JSON 配置：

- `enabled`：默认 `false`。
- `overlap_frames`：源视频帧数，满足 `0 <= overlap_frames < segment_size_frames`。

设右侧 core 的首帧为 `B`、总 overlap 为 `O`，两侧共同工作区为：

`[B - floor(O / 2), B + ceil(O / 2) - 1]`

两侧得到完全相同、总长度为 `O` 的 overlap。`work_start_frame / work_end_frame` 由 core range、相邻边界和视频长度实时派生，不重复落库。

质量计算只使用 `overlap ∩ 项目全局采样网格` 的源帧；启用协同后，只要项目已有 Annotation，就禁止修改 `video_sampling` 和 overlap 配置，防止比较集合漂移。

### D3. Tracker context 使用显式、不透明的后端 session

- ML backend capability 增加 `tracker_context_mode: none | session` 与 `max_context_frames`。
- 首窗创建 session，后续窗只传 opaque token；token 绑定模型、视频、方向、对象集合和 job，不能跨 job 或跨后端复用。
- API runner 仍保留现有“上一窗末几何续种”作为不支持 session 的兼容路径。
- backend 重启、token 丢失或路由实例变化时，job 明确失败为 `tracker_context_lost`；不得静默降级后继续产出语义不同的结果。

### D4. TrackEval 只负责标准指标，平台负责业务对账

- HOTA、CLEAR/MOTA、Identity/IDF1 使用官方 [TrackEval](https://github.com/JonathonLuiten/TrackEval) 算法。
- 不直接依赖浮动的 Git master。按固定 commit `12c8791b303e0a0b50f753af204249e622d0281a` vendor 最小 metric 模块、MIT LICENSE 与 provenance 说明，只做 NumPy 2 的弃用别名兼容修补。
- 新增运行时依赖仅限 TrackEval 实际需要且 API 尚未具备的 `scipy>=1.14,<2`。
- 轨迹候选关系、审核决策、章节聚合和错误定位属于平台业务，不修改标准指标定义。

这与 CVAT 的实践一致：连续视频通过 overlap 形成相邻 segment，每个 segment 仍由独立 Job 保存结果，而不是多人共享同一条标注记录。参考 [CVAT 创建任务文档](https://docs.cvat.ai/docs/manual/basics/create-annotation-task/) 与 [CVAT segment/job 源码](https://github.com/cvat-ai/cvat/blob/develop/cvat/apps/engine/task.py)。

## 5. 数据模型与迁移

### 5.1 Project

新增 `video_collaboration` JSONB，并以严格 Pydantic schema 读写，未知字段直接拒绝。

启用校验：

- 项目 schema 只能包含视频单帧或视频轨迹工具。
- 项目内没有有效 Annotation。
- 项目内没有 queued / running tracker job。
- `overlap_frames` 小于实际 segment size，且 overlap 中至少有一个全局采样帧。

旧项目、旧 API 响应和未配置项目的行为不变。

### 5.2 Annotation

新增：

- `video_segment_id UUID NULL REFERENCES video_segments(id)`。
- 活跃 Annotation 的 `(task_id, video_segment_id, track_id)` 查询索引。

不新增 canonical track 表，也不改写原始 `track_id`。accepted report 中的 `same_track` 边构成图；读取或导出时用并查集计算连通分量，并以分量内字典序最小的原始 `track_id` 作为稳定 canonical ID。

### 5.3 Track 质量

新增两张窄表：

`video_track_quality_runs`

- task、左右 segment、AsyncJob、状态。
- 左右输入 revision digest、采样帧集合摘要。
- HOTA、IDF1、双向 MOTA、检测与关联计数。
- 候选 track pairs、审核决策、accepted_by / accepted_at、stale_at。

`video_track_quality_issues`

- run、左右 fragment / Annotation 标识。
- `false_positive`、`false_negative`、`id_switch`、`fragmentation`、`geometry_mismatch`、`unsupported_geometry`。
- 连续 `frame_start / frame_end` 与局部指标。

章节不复制进 issue。查询时用当前 chapter range 与错误帧范围求交，避免章节编辑制造陈旧副本。

## 6. Segment 生命周期、权限与锁

### 6.1 工作流

沿用现有 `open → assigned → locked → completed`，不增加状态枚举：

- claim：将 segment 分配给当前标注员并取得 lease。
- heartbeat：只续当前 segment lease。
- release：释放 lease，但保留 assignee。
- submit：校验 segment 数据后设为 `completed`，释放 lease，并记录输入 revision。
- reopen / unassign：仅 reviewer、project manager 或 admin 可执行；用于返工或回收长期占用的分段。

所有 segment 完成后，Task 自动进入现有 review 状态。相邻 segment 的质量 run 可提前在“两侧均完成”时启动；review approve 必须再校验所有边界 report 都是 accepted 且未 stale。

### 6.2 多人可见性

协同模式下，项目 annotator 成员可以看到并进入该视频 Task，不再受 batch 单一 annotator 的可见性限制；非项目成员仍不可见。batch 继续负责 Task 的总体状态、review 与统计，不再代表 segment 的实际负责人。

segment list 是任务内的最小分配界面，不新增独立排班系统。用户显式选择并 claim segment；不能再用当前播放帧推断 active segment，因为 overlap 中一个帧同时属于两侧。

### 6.3 锁策略

- 协同模式关闭前端整 Task `useTaskLock` 的自动获取与 heartbeat。
- 所有视频标注写入统一经过 `assert_video_annotation_write_scope`：项目权限、active segment、assignee、有效 lease、frame range 一次校验。
- 通用 create / update / delete、bulk、AI accept、mask mutate/convert、tracker accept 都调用同一校验，不在各调用方复制规则。
- review accept、reopen 与 task transition 使用数据库行锁解决并发，不依赖浏览器长连接锁。

## 7. Segment-scoped Annotation 契约

### 7.1 读取

协同模式的 `GET /tasks/{task_id}/annotations` 必须带 `video_segment_id`，只返回该 segment 的 fragment。审核 overlap 使用质量报告 API 获取两侧只读快照，不通过通用列表越权读取其他 segment。

### 7.2 写入

- create 明确携带 `video_segment_id`；update / delete 从目标 Annotation 反查 segment。
- 单帧 annotation 的 `frame_index` 必须位于 work range。
- track geometry 的所有 keyframe 和 outside marker 必须位于 work range。
- parent / child annotation 必须属于同一 segment。
- tracker job 的 range 必须完全落在 active segment work range 内。
- segment `completed` 后不可写；先由 reviewer reopen。

`track_id` 继续同时存在于一等列和 geometry JSON，并沿用 ADR-0045 的一致性校验。

## 8. Tracker context 协议与资源生命周期

### 8.1 协议

共享预测请求增加可选 `tracker_context`：

| 字段                                | 含义                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------- |
| `action`                            | `start`、`continue` 或 `close`。                                       |
| `token`                             | continue / close 时必填的不透明 token。                                |
| `job_id`                            | session 绑定的 tracker job。                                           |
| `span_start_frame / span_end_frame` | 本次 context span 的完整范围；现有 window range 仍表示本次要返回的帧。 |
| `direction`                         | forward 或 backward；双向任务各建一个 session。                        |

共享 `PredictionResult` 补齐现有 API client 已能读取的 `meta`，backend 在其中返回 token 和实际 context capability。token 不落数据库、不写日志，只存在 worker 进程内存。

### 8.2 后端实现边界

- SAM2 使用官方 predictor 的持久 `inference_state`；官方实现本来就把条件帧、memory、对象映射和已跟踪帧保存在 state 中，见 [SAM2VideoPredictor 源码](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_video_predictor.py)。
- SAM3 interactive 保持 PVS inference state；文本 multiplex tracker 继续使用当前逐窗重检测逻辑，本版本不伪装成有状态续追。
- start 时一次性加载完整 context span，并启用已有的 CPU offload；同一 span 内的 window 只推进同一个 state。反向任务同样先加载完整 span，再按 reverse 顺序传播。
- model pool 增加最小的 reservation 能力：session 存活期间阻止对应 predictor 被 LRU 驱逐，每次 continue 仍通过原有 per-entry lock 串行使用。
- start / continue 刷新 idle time；close、cancel、失败和 TTL 清理都释放 reservation 与临时视频状态。
- `VIDEO_TRACKER_MAX_CONTEXT_FRAMES` 与 `SAM3_PVS_MAX_CONTEXT_FRAMES` 是硬件校准项；backend 公开最终生效值。超过上限时 runner 分成多个 context span，只在 span 边界使用现有几何续种，并在 job 结果标明降级边界。
- 只有 context 上限大于单窗上限且资源验收通过时，backend 才声明 session capability；否则继续声明 `none`。

### 8.3 Runner 行为

1. 已声明 session capability：首窗 start，后续窗 continue，finally close。
2. 未声明 capability：保持现有逐窗 seed continuation。
3. session 丢失：当前 job 失败；用户重试时从整个 job 起点重跑，避免一份结果混用两种状态语义。
4. 仍固定同一后端 instance route lease；session token 不能替代现有路由约束。

## 9. Track 质量计算与边界对账

### 9.1 输入快照

相邻 segment 都完成后，worker 对同一 overlap 建立不可变输入摘要：Annotation id、revision / updated_at、geometry digest、label、tool、track_id 和采样帧列表。任一输入之后变化，run 立即标为 stale，禁止 accept 和 task approve。

### 9.2 几何与帧

- bbox：现有 bbox resolver + IoU。
- polygon / mask：现有帧解析与 pycocotools raster IoU。
- polyline：输出 `unsupported_geometry`，不进入汇总分母。
- 单帧工具：不进入 Track 指标。
- 只比较相同 label、tool 和 geometry family；不做跨类别猜测。
- 每个采样帧按 outside 规则解析可见实例，构造 TrackEval 所需的 ID 与 similarity matrix。

### 9.3 指标

- HOTA：官方 `0.05 ... 0.95` alpha 均值。
- IDF1：固定 IoU threshold `0.5`。
- MOTA：固定 IoU threshold `0.5`；因为 overlap 两侧都不是 ground truth，分别报告 left-as-reference 和 right-as-reference，UI 不展示一个伪装成无方向的单值。
- 同时输出 DetA、AssA、IDSW、FP、FN 和有效帧数，便于解释汇总值。
- 两侧都为空时 run 自动标记为 `empty_overlap` 并视为已解决；只有一侧为空时正常产生 FP / FN issue。

### 9.4 轨迹身份建议

平台使用与 IDF1 相同的逐帧 IoU `0.5` 匹配计数，给所有至少匹配过一帧的左右 track pair 生成候选；全局 Hungarian 一对一结果默认建议 `same_track`，其余默认 `different_track`。

审核员可以修改建议，也可以从同类别、同 geometry family 的未匹配 fragment 中手动补一条 pair；但一个 canonical 连通分量内不得出现同一 segment、同一帧上两个同时可见的 fragment。这条服务端约束防止把两个真实对象合并成一个 track。accepted decisions 保存为 report 的无向 pair 集合，原始 Annotation 不被改写。

接受 report 时还要校验整张已接受图：任何 `different_track` 边的两个端点都不能因其他 `same_track` 边落入同一连通分量。发生矛盾时拒绝本次接受并返回冲突 pair，不做自动改判。

### 9.5 报告与定位

质量面板提供：

- 边界级 HOTA / IDF1 / 双向 MOTA。
- 按 track、segment 与 chapter 汇总。
- FP、FN、ID switch、fragmentation 等连续错误帧范围。
- 点击 issue 后跳到源帧，并并排高亮两侧 fragment。
- 接受建议、修改单个 pair、reopen 对应 segment。

## 10. Canonical 读取与导出

canonical projection 复用现有 `clip_video_geometry`：

1. 每个 fragment 先裁回自己的 core range，去除 overlap 双份数据。
2. 读取所有 accepted、未 stale 的 `same_track` 边，并查集生成 canonical track component。
3. 按 canonical ID、label、tool、geometry family 合并排序后的 keyframe / outside。
4. core ranges 本身互不重叠，因此同一源帧只能由一个 fragment 写入；出现冲突即视为数据错误，不做 last-write-wins。

导出门禁：

- 全 Task / 全项目导出：涉及的全部 boundary report 必须 accepted 且未 stale。
- 跨越边界的 frame range 导出：该范围涉及的 boundary 必须已接受。
- 只落在单一 core range 的 segment / frame range 导出：允许直接使用该 segment fragment，不等待无关边界。
- 门禁失败返回结构化 `video_boundary_unreconciled`，列出 boundary 与 run 状态。

## 11. 前端工作台

最小 UI 改动：

- 顶栏增加 active segment 选择器，显示 assignee、状态、lease 倒计时与 overlap 范围。
- claim 成功后才允许编辑；切换 segment 时释放旧 lease，并停止其 heartbeat。
- 播放、seek、tracker range 和新建标注限制在 active segment work range；core 外的 overlap 区域使用半透明边界带标记。
- annotation query key 加入 segment id，切换时不复用上一 segment cache。
- reviewer 模式增加 Track 质量侧栏；点击 issue 复用现有 seek / selection 能力。
- 不加入实时在线头像、聊天、光标同步或整段视频 miniature map。

## 13. 实施顺序

### Phase A — Fragment 基础与写入门禁

- ADR、Project 配置、Annotation 外键与迁移。
- work range 纯函数及 segment response。
- 统一写入 scope 校验；补齐所有 mutation caller。
- 协同配置仍不可在 UI 启用。

验收：旧任务行为与查询计划不变；API 测试证明跨 segment、无 lease、completed segment 的所有写入路径都会失败。

### Phase B — Tracker session（可独立上线）

- shared protocol meta / capability / context。
- model pool reservation、SAM2 与 SAM3 interactive session。
- runner start / continue / close、context span 与降级标记。

验收：同一 span 内只初始化一次 state；取消、超时、backend 重启和双向任务都释放资源；无 capability backend 回归行为不变。

### Phase C — Track 质量与 canonical projection

- vendor 固定版本 TrackEval metric 子集和 LICENSE。
- quality run / issue、worker、stale digest、pair decisions。
- canonical projection 与 export 门禁。

验收：用固定合成序列校验 perfect、FP、FN、ID switch、fragmentation；结果与 TrackEval 官方期望一致；未接受边界不能跨界导出。

### Phase D — 协同 UI 与正式启用

- Task 可见性例外、active segment selector、lease 控制。
- overlap 边界带、质量侧栏、seek 与 pair review。
- segment submit / reopen 与 Task review 状态衔接。
- 文档、CHANGELOG 与路线图状态更新。

验收：两个独立浏览器用户并行处理相邻 segment，无法覆盖对方数据；reviewer 完成边界接受后可批准并导出 canonical 全轨。

## 14. 验证矩阵

### 后端

- 迁移 upgrade / downgrade；旧 Annotation 的 `video_segment_id=NULL` 路径。
- overlap 奇数、偶数、首尾裁剪、短视频与 sampling grid。
- claim 冲突、lease 到期、submit 后写入、reopen、并发 accept。
- create / update / delete / bulk / AI accept / mask / tracker 的统一 scope 覆盖。
- digest stale、重复 job singleflight、失败重试、empty overlap。
- bbox、polygon、mask 的 perfect / shift / missing / identity switch 数据集。
- canonical DSU、core clipping、跨界导出门禁。
- session token 绑定、错误 token、backend restart、TTL、cancel、双向 context。

### 前端

- active segment 显式选择；overlap 内不按 frame 错选 segment。
- lease heartbeat / release、只读状态、倒计时和失锁恢复。
- query cache 按 segment 隔离。
- tracker range 不越 work range。
- issue 跳帧、两侧高亮、pair decision 与 stale 提示。
- 两用户端到端并行场景。

### 性能与资源

- 10 个 tracker windows 的 session 与现状基线比较：初始化次数、耗时、GPU / CPU 峰值。
- backend context 帧数上限内资源必须受控；超限 span 切换必须在结果中可见。
- 典型 overlap 上 Track quality worker 的耗时和 issue 数量；分页响应不得携带全量帧明细。

## 16. 风险与回滚

| 风险                               | 控制                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------- |
| 旧 Annotation 无法安全自动拆分     | 只允许空项目启用，旧模式零迁移。                                          |
| Task 锁与 segment 锁双重冲突       | 协同模式明确禁用 Task 长锁，写入统一走 segment scope。                    |
| 后端 session 占住模型导致 LRU 失效 | reservation、TTL、hard cap、finally close；超过 context 上限显式分 span。 |
| MOTA 把一侧误当真值                | 同时报告两个方向，并在 UI 标成一致性指标。                                |
| overlap 接受后输入又变化           | revision digest 立即标 stale，审批和导出双门禁。                          |
| canonical 聚合产生重复真相         | 只做派生 projection，不新建完整轨迹 Annotation。                          |
| TrackEval 上游或 NumPy 兼容漂移    | 固定 commit、最小 vendor、保留 LICENSE 和黄金序列测试。                   |

回滚按能力开关进行：关闭 `video_collaboration.enabled` 可阻止新项目进入协同模式；旧项目与 legacy `video_segment_id=NULL` 路径不受影响。已产生 fragment 的项目不得直接切回 legacy，只能完成对账或由管理员导出后新建项目，避免静默合并数据。
