## 目标

comment 切单源完成、对账长期 drift=0 后，drop `annotation_comments`，并把过渡脚手架正式收编。

> refined-C 下收尾比原计划轻得多：**只 drop 一张表**（`annotation_comments`）。`bug_reports` / `tasks` 保持权威、不 drop。

## 步骤

1. **drop `annotation_comments`**：comment 已单源进 `annotation_feedbacks`，旧表只读保留一个版本后 drop。
2. **`v_annotation_feedback_unified` view 转正**：从"过渡对账视图"升格为**永久统一读表面**——UNION `annotation_feedbacks`（comment/issue）+ `bug_reports`（bug）+ `tasks`（reject）。view 里原本 UNION `annotation_comments` 的分支删除（comment 现在来自 `annotation_feedbacks`）。LLM 聚类去重（§B）/ Webhook fan-out（§2.1）/ 全局反馈检索都查这张 view。
3. **退役 v0.11.0 对账 cron**：comment 切完后已无任何双写，cron 失去对象，删除（`FEEDBACK_RECONCILE_DRIFT` audit action 视情况保留）。
4. **更新 ADR-0027 Status**：标注三段完成 + refined-C 范围修正（见 v0.11.8 Addendum）。
5. **文档同步**：grep 全部 `*.md` 确认无 `annotation_comments` 表名残留引用。

## 不需要做的（refined-C 红利）

- **不**改 CLAUDE.md 顶部 `bug_reports` psql 查询段——`bug_reports` 表保留，查询照常有效。
- **不** drop `bug_reports` / `BugComment` / `tasks.reject_reason`。
- **不**处理 `project_id IS NULL` bug、bug status 值域无损映射等原切单源难题（根本不迁 bug）。

## 验证

- 全反馈链路 e2e（comment / issue / reject / bug）走 view 无回归。
- comment 读写全部命中 `annotation_feedbacks`；`annotation_comments` 已无引用、已 drop。
- `pnpm docs:dev` 文档站无死链。

## 回退

⚠️ **drop `annotation_comments` 不可逆。** 前置硬条件：v0.11.10 停双写后对账连续多日 drift=0、旧表只读保留至少一个版本、drop 前全库备份。
