# v0.10.13 · Annotation Guide（CVAT-style 项目级 Markdown 指引 + asset）

> **状态**：✅ 已落地（2026-05-18，参见 CHANGELOG.md v0.10.13）。
> 拆自原合并计划文件 `roadmap-md-annotation-guide-iridescent-cerf.md`；E2（ProjectTemplate 表 + 模板库 UI）见 [`2026-05-18-v0.10.14-project-template-library.md`](./2026-05-18-v0.10.14-project-template-library.md)。

## Context

ROADMAP §A 列出的 P2 待办，参考 CVAT `Project.annotation_guide`。当前项目无任何"指引"载体，新人靠口口相传，导致标注一致性差、reject 率高。决策：项目设置加 Markdown 指引 section + 工作台左栏可折叠浮层。技术 ROI 不高但对标注一致性提升显著。

用户额外确认（2026-05-18）：

- guide_assets 走**新建** `POST /projects/{id}/guide-assets/upload-init`（不污染 dataset items）。
- 工作台浮层放**左侧栏顶部可折叠 panel**，首次自动展开 + localStorage 标记。
- annotation_guide **不进** `_CLONEABLE_PROJECT_FIELDS`：Wizard 给独立 checkbox「同时复制标注指引」（默认勾选、可取消）。
- MarkdownEditor 用 **CodeMirror 6**：原生 markdown syntax highlight + 图片拖拽。size-limit 阈值需相应调整。

体量预估 ~1.5-2d；与 E2 拆为两个独立版本：E1（v0.10.13）+ E2（v0.10.14），E1 落地后先收集客户对 guide 的写法 / 图片量 / 跨项目复用诉求反馈，再决定 v0.10.14 中"模板是否携带 guide"。

## E1.1 数据模型 + Migration

**新增字段**（`apps/api/app/db/models/project.py`）：

```python
# v0.10.13 · CVAT-style annotation guide. Markdown body + asset key list.
annotation_guide: Mapped[str | None] = mapped_column(Text, nullable=True)
guide_assets: Mapped[list] = mapped_column(
    JSONB, nullable=False, server_default="[]", default=list
)
```

- `annotation_guide`：Markdown 原文，nullable（空 = 未配置指引）；不设 length 上限，单行 TEXT。若担心爆炸，PR review 时再加 `CHECK length() < 1MB`。
- `guide_assets`：list of `{key: str, original_name: str, content_type: str, size: int, uploaded_at: ISO8601}`，记录已上传的图片资源（前端编辑器拖入 → 上传 → 自动 append 到该数组 + 把 Markdown 里的 `<img src=...>` 替换成签名 URL）。

**Migration**：`apps/api/alembic/versions/0067_project_annotation_guide.py`

- `op.add_column("projects", sa.Column("annotation_guide", sa.Text(), nullable=True))`
- `op.add_column("projects", sa.Column("guide_assets", sa.dialects.postgresql.JSONB, nullable=False, server_default="[]"))`
- downgrade 反向 drop。

## E1.2 Pydantic Schema

**`apps/api/app/schemas/project.py`**：

- `ProjectUpdate`：加 `annotation_guide: str | None = None`、`guide_assets: list[dict] | None = None`（与现有 `rendering_config` 同 pattern）。
- `ProjectOut`：加 `annotation_guide: str | None = None`、`guide_assets: list[dict] = []`。
- `ProjectCreate`：**暂不加 annotation_guide 字段**（创建项目时通常没指引，留 ProjectUpdate 走）；加 `copy_annotation_guide: bool = False` flag。

**`_CLONEABLE_PROJECT_FIELDS`**（`apps/api/app/api/v1/projects.py:388`）：

- **不**把 `annotation_guide` / `guide_assets` 加进白名单（已确认）。理由：guide 通常项目专属，复制后容易遗忘修改导致信息错位。
- 实现方式：当 `source_project_id` + `copy_annotation_guide=True` 同时给定时，把 `annotation_guide` + `guide_assets` 一并从源项目 deepcopy 进新项目；**guide_assets 复用原 storage key**（不重新上传），新项目和源项目共享存储对象——这意味着源项目删除资源时新项目也会失效，UX 上在 wizard checkbox 文案标注「(图片资源与源项目共享)」提示用户。如果客户反馈要求"独立资源"，下期再加 worker 异步拷贝 storage 对象。
- 单独给 `copy_annotation_guide` 但无 `source_project_id` → 400（请求体错误）。
- Wizard checkbox 默认**勾选**、可取消；ProjectCreateWizard 在选择源项目后才显示该 checkbox。

## E1.3 后端 API

**`apps/api/app/api/v1/projects.py`**：

- 现有 `PATCH /projects/{id}` 已经接 `ProjectUpdate.model_dump(exclude_unset=True)` 写库，**guide 更新无需新端点**，前端 PATCH 即可。

**新增端点：guide assets 上传**（新建 `apps/api/app/api/v1/guide_assets.py` 路由 module）：

```
POST /projects/{project_id}/guide-assets/upload-init
  body: { filename: str, content_type: str, size: int }
  resp: { upload_url: str, key: str, expires_in: int }

POST /projects/{project_id}/guide-assets/upload-complete
  body: { key, original_name, content_type }
  resp: { key, original_name, content_type, size, uploaded_at }
  // 校验 MinIO/S3 上 key 已写入（HEAD object），将 entry append 到 projects.guide_assets

DELETE /projects/{project_id}/guide-assets?key=<key>
  // 删 storage object + 从 guide_assets 数组移除

GET /projects/{project_id}/guide-assets/sign-url?key=<key>
  resp: { url: str, expires_in: int }
  // 签发短期 GET 预签名 URL（与 dataset items 一样）
```

**校验**：

- 路径前缀强制 `projects/{project_id}/guide/{uuid}-{filename}`，防越权写入。
- 权限：require `project_owner` 或 `super_admin`（与 ProjectSettings 入口对齐）。
- content_type 白名单：`image/png | image/jpeg | image/webp | image/gif | image/svg+xml`，单文件 ≤ 5MB（dev 阶段拍脑袋，正式上线按客户反馈调）。
- 复用 `apps/api/app/services/storage.py` 现有 MinIO client（参考 `datasets.py:131-163`）。

**不做**：

- 不做异步压缩 / 缩略图（首版 SAR 不必要，KISS）。
- 不做 GC（删 guide_markdown 时不主动清理 orphan assets；UI 给一个"清理未引用资源"按钮，留到客户反馈触发）。

**新增**：`apps/web/src/pages/Projects/sections/AnnotationGuideSection.tsx`

UI 结构（参照 `RenderingConfigSection` / `GeneralSection` 的 form pattern）：

```
┌─ 「📖 标注指引」section ────────────────────────────┐

│   ↑ CodeMirror 6 + 拖拽 / 粘贴图片自动调           │

└────────────────────────────────────────────────────┘
```

**MarkdownEditor 子组件**：

- 采用 **CodeMirror 6**（已确认）。依赖：`@codemirror/state` / `@codemirror/view` / `@codemirror/lang-markdown` / `@codemirror/commands` / `@codemirror/language` / `codemirror`，合计 ~180-220KB gzipped。
- 配置：markdown language pack + 行号 + 自动换行 + 拖拽 / 粘贴图片监听（`EditorView.domEventHandlers({ drop, paste })`），命中文件 → 调 `useGuideAssets.uploadAsset()` → 把 `![alt](guide-asset:KEY)` 文本插入到光标位置（用 `EditorView.dispatch` 派发 `changes`）。
- 工具栏：粗体 / 斜体 / 标题 / 列表 / 链接 / 图片 / 代码块；按钮通过 `EditorView.dispatch` 派发 transaction 实现插入。
- size-limit 调整：`apps/web/scripts/check-bundle-size.mjs` 阈值需 +250KB（CodeMirror 仅在 ProjectSettings 路由加载，做 dynamic import 避免污染 dashboard 首屏 bundle）。
- 预览组件新建 `GuideMarkdownView`（react-markdown + remark-gfm），渲染 `<img src="guide-asset:KEY">` 时通过 `resolveAssetUrl` 钩子换签名 URL。

**ProjectSettingsPage.tsx 接入**：

- `SectionKey` 加 `"annotation-guide"`，`SECTIONS` 数组追加 `{ key: "annotation-guide", label: "标注指引", icon: "book" }`（Icon 系统加 `book` = `BookOpen`）。
- `VALID_SECTIONS` 同步追加。
- 在 sections 渲染块加 `{section === "annotation-guide" && <AnnotationGuideSection project={project} />}`。

**hooks**：

- 新建 `apps/web/src/hooks/useGuideAssets.ts`：暴露 `uploadAsset(file) → Promise<{src, alt}>`、`deleteAsset(key)`、`signAsset(key)`（带内存缓存 + 60s 安全垫重签）。
- 复用 `useUpdateProject` 写 annotation_guide 字段。

## E1.5 前端 — 工作台左侧栏「📖 指引」浮层

**位置**：`apps/web/src/pages/Workbench/shell/WorkbenchShell.tsx`（约 1136 行，已 M6 归档），通过 `WorkbenchLayout` 加可选 `guidePanel` prop，浮层绝对定位在左上角。

**触发**：

- 默认折叠。
- 首次进入工作台（localStorage `wb:guide-seen:{projectId}` 不存在）且 `project.annotation_guide` 非空 → 自动展开 + 写 localStorage 标记。
- 用户手动折叠后写 `wb:guide-collapsed:{projectId}=1`，后续保持折叠。
- 项目无 guide（`annotation_guide` 为空 / null）→ panel 完全不渲染（不要露空状态）。

**实现**：

- 新建 `apps/web/src/pages/Workbench/sidebar/GuidePanel.tsx`：复用 `GuideMarkdownView` 渲染 `project.annotation_guide`，绑 `signAsset` 钩子。
- `WorkbenchLayout` 加可选 `guidePanel?: ComponentProps<typeof GuidePanel>` prop。
- WorkbenchShell 透传 `currentProject.annotation_guide` + `projectId`。
- localStorage key 命名遵循现有约定 `wb:guide-seen:{projectId}` / `wb:guide-collapsed:{projectId}`。

**不做**：

- 不做工作台内编辑（owner 想改就回 ProjectSettings；避免工作台 UI 复杂化）。
- 不做"我已读"按钮（首次自动展开 + 用户手动折叠就够了）。
