# v0.23.6 · 共享 RLE 内容层与图片原生 Mask Schema

> Status: Completed（实现与验证完成，生产创建默认关闭）· Epic Phase 2
>
> 父 Epic：[图像 / 视频栅格 Mask 能力统一](../2026-07-21-raster-mask-workbench-unification-epic.md)
>
> 硬前置：[v0.23.5 Mask 编辑可靠性与安全地基](2026-07-21-v0.23.5-mask-reliability-security-foundation.md)

## 1. 目标

- 将视频已验证的内容寻址 RLE 从专用实现收口为图片 / 视频共享栅格内容层。
- 新增图片 `RasterMaskGeometry`，不内联像素、不增加 blob 列。
- 建立静态图片 Mask 内容 API、强类型、鉴权、生命周期和可移植 AAP 闭环。
- 补图片 COCO RLE 导入 / 导出，结束“预测导入只看 bbox”的 Mask 缺口。
- 本版后端先具备安全 read / write；图片工作台生产创建入口留 v0.23.7 开启。

## 2. 冻结合同

以 ADR-0052 Accepted 内容为准，草案形态：

```json
{
  "type": "raster_mask",
  "mask": {
    "encoding": "coco_rle_ref",
    "size": [1080, 1920],
    "object_key": "raster-masks/sha256/ab/cd/<digest>.json",
    "sha256": "<64 hex>",
    "runs": 4096,
    "bytes": 16384
  }
}
```

- 只允许图片 DatasetItem；视频继续 `video_track_mask`。
- 二值 instance mask；soft / semantic / panoptic 不进入本 geometry。
- 图片尺寸必须匹配 DatasetItem metadata；缺尺寸拒绝，不从客户端反推。
- 空 RLE codec 合法，但 API 创建可见图片 annotation 时拒绝空前景。
- Annotation `version` 继续承担乐观锁；引用提交失败的对象由 grace-period GC 回收。

## 3. 后端切片

### P0 · 共享 validator 与 reference walker

- 抽取图片 / 视频共用 `CocoRleMaskRef`、canonical object 与 digest validator。
- task-context 层分别验证图片媒体类型 / 尺寸和视频 frame / 尺寸。
- create、patch、DB-read、prediction accept、AAP dry-run / import、export、GC reference walk 全部识别新 geometry。
- 禁止新增一份图片专用对象键、bucket 或 codec。

### P1 · API

- 复用 `POST /tasks/{task_id}/mask-content`，按 v0.23.5 权限与配额合同上传。
- 新增 `GET /annotations/{annotation_id}/mask-content` 服务静态图片。
- 保留视频带 frame 的 GET；共享鉴权、digest、size、runs、bytes 和 corrupt-object 错误映射。
- 实现 ETag 与 `If-None-Match → 304`，避免重复下载相同内容。
- OpenAPI 为新 geometry 和静态 GET 生成强类型，禁止 `response_model=None`。

### P2 · AAP portable round-trip

- AAP envelope 复用 `mask_objects`，加入 `raster_mask` reference 收集和去重。
- 导入先校验 envelope 引用完整、digest 一致、尺寸匹配，再在目标环境写不可变对象。
- dry-run 不写对象；真正 import 失败不能留下已挂载 annotation。
- 旧 AAP reader 继续读取旧 geometry；新 reader 对未知新 geometry 给稳定兼容错误。

### P3 · COCO 图片 Mask

- 导出 `raster_mask` 为标准 RLE segmentation；bbox / area 从像素计算。
- ADR / consumer fixture 冻结 `iscrowd` 语义，不能凭实现方便固定错误值。
- 导入 polygon segmentation 与 RLE segmentation；RLE 创建 `raster_mask`，不只读取 bbox。
- compressed / uncompressed RLE 的支持范围由 pycocotools fixture 固定；不支持形式给逐 annotation 错误报告。
- YOLO Seg 本版不做隐式最大外环降级。

### P4 · Feature flag 与部署

- 分离 `raster_mask_read_enabled` 与 `raster_mask_create_enabled`。
- 先部署后端 reader / OpenAPI，再部署前端 reader；本版默认 create flag 关闭。
- 记录数据库中新 geometry 计数和对象错误指标，为 v0.23.7 灰度提供观测。

## 4. 非目标

- 不实现图片 canvas renderer、alpha picking 或工具栏创建。
- 不改变现有图片 Mask 提交路径。
- 不导入 Label Studio、DAVIS、MOTS 或 class-map。
- 不扩大 4096 上限，不实现 tile / sparse。
- 不修改视频 keyframe / hold 语义。

## 5. 测试与验收

- Python / TypeScript / pycocotools 用非正方形、hole、多组件 fixture 逐像素一致。
- GET 覆盖权限、ETag / 304、404、对象损坏、类型错误、尺寸错误和跨项目访问。
- AAP `export → import → GET` 跨环境逐像素一致，相同对象去重。
- COCO import / export 覆盖 polygon、RLE、hole、单像素、空与非法 counts。
- GC 覆盖共享引用、替换、删除、事务失败、grace period 与并发读取。
- OpenAPI export / codegen / drift 全绿，旧 video Mask 测试零变化。

## 6. 文档与退出门

- 更新 ADR-0048，说明内容层已共享但视频轨迹决策不变。
- 更新 API schema boundary、annotation module、AAP 和 COCO 格式文档。
- CHANGELOG 按 Added / Changed / Security 记录。
- v0.23.7 进入条件：read flag 在开发栈开启，API / AAP / COCO round-trip 全绿，且 corrupted object 监控可见。

## 7. Outcome

- 图片 `raster_mask`、共享 `coco_rle_ref` validator / reference walker、静态内容 GET、ETag / 304、任务级授权和原子版本锁已落地；read 默认开启，create 默认关闭。
- AAP JSON 已实现图片 / 视频 Mask 对象去重、校验、先落盘后关联与 dry-run 不写入；COCO 图片导入按 RLE → polygon → bbox 选择，导出从真实像素计算 segmentation、bbox 与 area。
- 原生图片像素 renderer 上线前，Web 工作台以只读占位识别 `raster_mask`，并在移动、缩放、复制、剪贴板和普通 bbox 操作入口失败关闭。
- OpenAPI 快照、生成客户端、ADR-0048 / ADR-0052、API / 用户 / 开发文档、环境变量参考与 CHANGELOG 已同步。
- 验证证据：后端完整 Pytest 套件收集 2839 项并通过，栅格 Mask 定向回归 104 项通过；前端全量 Vitest 287 文件 / 2336 项通过；Ruff、TypeScript、ESLint、CSS token、OpenAPI drift、文档规则和 VitePress 生产构建通过。
- 生产创建仍由 `RASTER_MASK_CREATE_ENABLED=false` 阻断；corrupted object 监控可见性继续作为 v0.23.7 灰度前置，不在本阶段提前放量。
