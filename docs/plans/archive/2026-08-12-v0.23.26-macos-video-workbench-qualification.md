## 1. 目标

在 Apple Silicon MacBook 上补完 Linux 服务器不能完成的客户端验证，并把验证入口固化为可重复执行的
strict benchmark，而不是保存一次性的人工结论。

本版完成时必须能证明：

- 原生有头 Chrome 的 WebCodecs workload 实际选择 `VideoToolboxVideoDecoder`，且平台 decoder 标记为
  `true`；
- H.264 baseline、B-frame、GOP boundary、VFR、flag off 与故障 fallback 的确定性 E2E 通过；
- 1080p/30、1080p/60、4K/30 三档素材可由隔离测试栈自动生成，无需手填 task URL；
- 三档 strict benchmark 覆盖 cold/warm seek、5,000 次稳定操作、从 frame 0 开始的 60 秒真实播放、
  资源 plateau 与 fallback rate；
- 报告不能把静态 GPU capability、隐藏原生 `<video>` 的 decoder，或页面 `requestAnimationFrame`
  误当成 WebCodecs 硬解与连续播放证据；
- `ROADMAP.md`、视频专项路线、开发文档与 `CHANGELOG.md` 只记录实际通过的范围，未安装的浏览器保持
  `not tested`。

## 2. 已确认现状

- WebCodecs 默认已开启；flag-off E2E 仍通过删除 localStorage key 表达关闭，因此退回默认开启并失败。
- 当前 strict runner 依赖 CDP `videoDecoding[]` 非空；macOS Chrome 即使实际使用 VideoToolbox，该数组也
  可能为空，不能作为实际 decoder 身份证据。
- Chromium Media domain 会为 WebCodecs player 发出 `LOAD url=WebCodecs::VideoDecoder`，并发布
  `kVideoDecoderName` 与 `kIsPlatformVideoDecoder`；这可与同页隐藏原生 `<video>` 条目区分。
- 现有 benchmark 已定义三档矩阵和阈值，但要求外部提供三个 task URL。
- 现有 test-only seed 只生成 160×120 短素材和 chunk 0；直接扩大分辨率/时长会在 60 帧后落入 pending
  chunk，并误依赖未运行的 Celery worker。
- 当前 60 秒播放观测只统计页面 animation frame；若从稳定性测试后的任意位置开始，素材可能提前结束，
  仍被误判为通过。

## 3. 范围与非目标

### 3.1 本版范围

- 修正 flag-off helper，并保留默认开启的独立断言；
- 在现有 precise-frame runner 内采集、归一化和判定 macOS decoder 证据；
- 扩展现有 test-only seed endpoint，增加固定的三档 benchmark fixture；
- 为 runner 增加显式 `--seed`，自动准备登录态、task URL 和 finally cleanup；
- 让 60 秒播放从 frame 0 开始，并验证媒体时间实际前进且未提前结束；
- 在当前 MacBook 上执行真实 headed Chrome E2E 与 strict benchmark；
- 同步测试、运行手册、路线图和 Unreleased changelog。

### 3.2 非目标

- 不改变 WebCodecs 默认值，不新增 decoder、Worker、生产 API 或第三方依赖；
- 不建立通用视频素材管理或 benchmark 服务；
- 不把 `video_decode=enabled`、CDP profile、AppleAVD 支持列表或 stderr 文本当作实际命中证据；
- 不用数千张 4K PNG 生成长素材；
- 不在缺少 Edge 的机器上宣称 Edge 通过；Safari 只记录现状，不冒充 Chromium WebCodecs strict 结果；
- 不在本次实现中切正式版本号；发版时再按仓库版本同步规则处理。

## 4. 实现决策

### 4.1 flag 合同

`video.experimental.webcodecs` 的测试 helper 使用显式值表达意图：

- 开启写入 `"1"`；
- 关闭写入 `"0"`；
- key 缺失专门验证 production 默认开启。

不通过改回默认关闭来让旧测试通过。

### 4.2 macOS decoder 证据

runner 在 workload page 导航前开启 CDP Media domain，按 `playerId` 收集
`Media.playerEventsAdded` 与 `Media.playerPropertiesChanged`：

1. 仅匹配含 `LOAD url=WebCodecs::VideoDecoder` 的 player；
2. 匹配 player 必须发布 `kVideoDecoderName=VideoToolboxVideoDecoder`；
3. 同一 player 必须发布 `kIsPlatformVideoDecoder=true`；
4. workload 自身仍必须满足 `source=webcodecs`、`state=ready`、fallback 为 0；
5. 报告只保存归一化结果，不保存原始事件流或媒体 URL。

Apple Silicon 的 macOS strict 行只有上述动态证据成立才可完成。CDP Media 不可用、session detach、无匹配
player、属性缺失、decoder 名称不符或 platform 为 false 均 fail closed 为 `inconclusive`。Intel macOS 的
VideoToolbox H.264 路径可能允许软件 fallback，本版不把相同信号升级为硬解资格通过。

现有 SystemInfo GPU capability 继续作为环境诊断；macOS 不再因为空 `videoDecoding[]` 在 workload 前被
拒绝，其他平台既有规则不放宽。

### 4.3 三档测试素材

复用仅在 development + E2E seed 下注册的
`POST /api/v1/__test/seed/video-webcodecs`，新增固定 fixture：

| fixture    | 编码目标                 | 最小时长 |
| ---------- | ------------------------ | -------- |
| `1080p-30` | H.264 1920×1080 / 30 fps | 61 s     |
| `1080p-60` | H.264 1920×1080 / 60 fps | 61 s     |
| `4k-30`    | H.264 3840×2160 / 30 fps | 61 s     |

使用 FFmpeg `lavfi` 直接生成受控码率素材，GOP 固定，并按 production 的 60 帧 chunk size 切分。每个
chunk 复用现有 sample probe 与 decoder config 提取逻辑，直接写为 ready `VideoChunk`。benchmark
fixture 不返回逐帧像素 expectation；像素正确性继续由现有短小确定性 H.264 E2E 覆盖，长素材只负责
分辨率、帧率、播放和资源资格。

素材和 chunk 保持现有 `e2e/video/webcodecs/` 对象前缀，沿用现有 cleanup；FFmpeg 失败或超时必须给出
明确 prerequisite error，不能静默降级为低分辨率。

### 4.4 自动 seed 与连续播放真实性

`run-video-bench.mjs --scenario precise-frame --seed` 只在三个 task URL 全部未提供时启用：

1. reset 隔离 E2E 数据；
2. 依次创建三档 task；
3. 使用现有 test login API 获取 token；
4. 以内存 `storageState` 注入登录态并构造三个 annotation URL；
5. benchmark 结束或失败后在 `finally` cleanup。

若只提供部分 URL，继续报错，禁止 seed 与外部素材混跑；不写临时 auth-state 文件。

每行 precise-on 连续播放前先 seek frame 0。结果除页面渲染帧外，还必须记录 video `currentTime`
增量、`ended` 和实际观测时长；60 秒内未持续前进或提前 ended 都不能通过。

## 6. 实施顺序与验收

### 步骤 1：修正开关合同

- 改 flag helper；
- 默认缺失与显式关闭分别测试。

验收：flag-off 零 precise request，默认开启路径仍进入 WebCodecs。

### 步骤 2：动态 decoder 证据

- 接入 CDP Media probe；
- 增加纯分类测试，至少覆盖：空静态 profile + WebCodecs VideoToolbox 通过、只有原生 `<video>` 不通过、
  FFmpeg/false/缺属性/无事件不通过。

验收：Apple Silicon strict 报告包含已验证的 VideoToolbox 证据；移除任一必要事件后测试 fail closed。

### 步骤 3：自动素材与真实播放

- 增加三种固定 fixture、ready chunks 和 route 测试；
- 增加 `--seed` 生命周期；
- 从 frame 0 验证 60 秒媒体时间。

验收：空 task URL 环境可一条命令完成三档准备、测量和清理；部分 URL 明确拒绝。

### 步骤 4：MacBook 实机门与文档收口

至少执行：

```bash
pnpm exec vitest run scripts/video-bench/precise-frame-runner.test.mjs
cd apps/api && uv run pytest -p no:cacheprovider tests/test_seed_router.py
PLAYWRIGHT_CHROMIUM_CHANNEL=chrome PLAYWRIGHT_REQUIRE_WEBCODECS=1 \
  pnpm exec playwright test e2e/tests/video-webcodecs-precise-frame.spec.ts \
  --project=chromium --headed --reporter=line
pnpm video:bench -- --scenario precise-frame --seed --strict --headed
```

最终报告逐档列出：browser/OS/CPU/GPU、decoder 证据、cold/warm p95、blocking/long task、5,000 次操作、
60 秒媒体时间、plateau、active decoder、live frame 与 fallback rate。任何必需项缺失时结论为
`inconclusive`，不能人工改为通过。

## 7. 回滚与清理

- 无数据迁移、生产 schema 或生产 API 变化；代码回滚即可恢复旧行为。
- 自动 seed 的数据库行和 MinIO 对象必须由 `finally` cleanup 删除；失败后可重复调用现有 cleanup endpoint。
- 测试产生的 JSON/Markdown 报告和 trace 保持临时 artifact，不提交大体积视频。
- 若 Chrome Media domain 后续改变事件结构，strict 应保持 fail closed，并更新 probe 分类测试后再恢复资格。

## 8. 下版边界

本版只收口 MacBook Chrome 与可重复 benchmark。完成后，视频工作台下一版优先级再在以下独立产品能力中
选择，不与本次资格修复混写：外部视频预测导入、segment/frame-range 聚合导出、长视频 overlap/tracker
上下文、Track 质量指标、单帧 keypoint 与 rotated-box 绘制。浏览器兼容矩阵按可获得的 Edge/Safari
环境另开资格任务。

## 9. Outcome

2026-08-12 在 Apple Silicon M4、macOS、系统 Chrome 151 有头模式完成：

- WebCodecs 精确帧 E2E 9/9 通过，覆盖默认开启、显式关闭、baseline、B-frame、GOP boundary、VFR、
  pending、unsupported 与 malformed fallback；
- 三档 `--seed --strict --headed` benchmark 全部 `completed`，静态 `videoDecoding[]` 为空时仍由实际
  WebCodecs player 证明 `VideoToolboxVideoDecoder` 与 platform decoder；
- 1080p/30、1080p/60、4K/30 均完成 5,080 次采样操作、60 秒真实媒体时间、零 fallback、零播放期精确帧
  请求、单 active decoder、零 live frame / ledger growth；
- 4K/30 的 warm same-chunk p95 为 105.66 ms，其余 warm p95 均低于 49 ms；三档无 Long Task；
- benchmark 最终报告位于 `test-results/video-bench/2026-08-12T11-11-43-549Z/manifest.json`。

实现过程中定位并修复了预取缓存命中后 demux effect 清空可见时序的根因；回归测试先失败后通过。自动
fixture、登录态和 cleanup 均复用 test-only seed 路径，没有新增生产 API、依赖或数据迁移。

Windows Edge 与 macOS Safari 未在本机安装，仍为 `not tested`。下一版已收敛为
[AAP JSON 外部视频预测导入](2026-08-12-v0.23.27-external-video-prediction-import.md)。
