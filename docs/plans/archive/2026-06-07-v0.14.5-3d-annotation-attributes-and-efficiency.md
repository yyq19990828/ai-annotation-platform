# v0.14.5 · 3D 标注属性 + 标注效率(纯前端,零后端 / 零迁移)

> 规划日期 2026-06-07 · 范围:补齐点云 3D 工作台至今缺失的三块「标注完整性 + 效率」能力 ——
> **(1) 3D 框属性编辑面板**(遮挡 / 截断 / 自定义 schema)、**(2) 多选 + 批量操作**、**(3) undo/redo + 复制/粘贴/duplicate**。
> 全部落在 `apps/web/src/pages/Workbench/stages/three-d/` 与既有壳层接缝内,**不动后端、不加表 / 列 / 端点、不做数据迁移**。
>
> **定位铁律**:v0.14.5 = 纯前端切片。属性走**早已存在**的 `tool_bindings` 属性 schema 机制(后端 `_jsonb_types.py` 早支持)与既有 `useUpdateAnnotation` 的 `attributes` 字段;不触碰任何后端契约。
>
> **收尾线边界(本版只写第一版,不越界)**:
> - **v0.14.5(本文)= 3D 标注属性 + 效率**(纯前端)。
> - v0.14.6 = 6 相机实测体验 + 性能(相机面板拖动 / 窄屏 / worker 化 / 分割工具深化)——**不在本版**。
> - v0.14.7 = 点云导出标准格式(KITTI / nuScenes)——**不在本版**。

> **本轮开源平台调研补充**:xtreme1 / SUSTechPOINTS 的下一层优势是 object-centric track workflow(trackId / split / merge / finalize / 同步类别属性)。本版不引入 track schema,但属性面板、多选批量、undo/redo、复制粘贴是后续 object/track 面板的前置生产力地基。真正的跨帧 object workflow 继续放到 v0.15 线。

## 1. 背景与目标

### 1.1 为什么要做

v0.13.x ~ v0.14.4 把点云 3D 工作台的**几何标注链路**建得相当完整:放置 / 选中 / PSR 数值面板 / gizmo / 三视图精修(v0.13.5)/ 自动贴合(v0.13.8)/ 跨帧 propagate(v0.14.1)/ scene 连续调度。但**标注的「完整性」与「批量效率」**仍有三处明显空缺,直接拖慢实测标注吞吐:

| 编号 | 空缺 | 现状(代码位置) |
|---|---|---|
| **G1** | **3D 框无属性** | 选中框的右上编辑面板(`ThreeDWorkbench.tsx:1404-1527`)**只有 PSR 数值 + 类别下拉 + 锁定 + 贴合**,没有任何属性字段。调研 `docs/research/14-point-cloud-image-fusion.md` §14.5「关键难点 3:遮挡与截断 —— 物体仅在部分模态可见,需 `visible / occluded / truncated` 属性字段」点名这是联合标注的硬需求。`tool_bindings["lidar_box_3d"]` 已能配 `classes + 属性 schema`(`apps/api/app/schemas/_jsonb_types.py:269` 附近),但 3D 台从不渲染它。`AttributeForm.tsx`(`shell/` 下,2D / video 都在用)**已存在但未被 3D 引入**。 |
| **G2** | **无多选 / 批量** | `onSelectBox` 接口在 `ThreeDWorkbench.tsx:68` **早已预留** `opts?: { shift?: boolean }`,壳层 `useWorkbenchShellModel.tsx:1106-1114` 的 `handleSelectBox` 也**早已**据 `opts.shift` 调 `s.toggleSelected(id)`(多选基础设施 `selectedIds` 在 `useWorkbenchState.ts:138/305` 全链路就绪)。**唯独 3D 的两处选中调用没传 shift**(`ThreeDWorkbench.tsx:977` 主视图拾取、`CameraProjectionView.tsx:221` 投影命中),导致 3D 永远单选 → 无法批量删除 / 批量改类。 |
| **G3** | **无 undo/redo / 无 copy/paste** | 3D 台**完全没有** history 栈(`grep useAnnotationHistory` 在 `ThreeDWorkbench.tsx` 零命中),误删 / 误改一个框只能手动重建;也没有复制 / 粘贴 / duplicate —— 标同型号连续目标时每个都要从零放置 + 调尺寸。2D / video 早有 `useAnnotationHistory`(`state/useAnnotationHistory.ts`)与 `useClipboard`(`state/useClipboard.ts`),但后者的偏移 / clamp 逻辑是 **2D 几何专用**,不能直接复用到 box_3d。 |

**共同根因**:3D 台从「几何能放准」走到了「几何能放准」,但**属性、批量、可逆操作**这三块「标注生产力地基」一直没补。本版把它们一次补齐,且全部复用既有接缝(`AttributeForm` / `selectedIds` 多选链 / `useUpdateAnnotation` 乐观更新),不引入新后端面。

### 1.2 设计决策(立项拍板)

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | **属性面板复用** | **直接接 `shell/AttributeForm.tsx`,不为 3D 另写表单** | 该组件已支持 text / number / boolean / select / multiselect / range + `applies_to` + `visible_if` + 必填校验 + 防抖,2D / video 共用;3D 只需把 `tool_bindings["lidar_box_3d"]` 的属性 schema + 选中框 `class_name` / `attributes` 喂进去,`onChange` 走既有 `updateAnnotation.mutate({ payload: { attributes } })`。 |
| D2 | **occluded / truncated 语义对齐 video** | **属性即普通 schema 字段,不做特例硬编码** | video 的 `occluded` 是写进 keyframe / track `attributes` 的普通字段(`useVideoAnnotationActions.ts` 的 `handleUpdateTrackAttributes`);3D 同样把 occluded / truncated / visible 作为 `tool_bindings` 配的 boolean / select 字段渲染,**语义与 video 对齐(写 annotation.attributes 顶层)**,不在 3D 代码里硬写这三个名字。文档给出推荐 schema 片段供项目配置者参考。 |
| D3 | **多选 = 接通既有 shift 链,不新建状态** | **只在 3D 两处选中调用补传 `{ shift: e.shiftKey }`** | 壳层 `selectedIds` / `toggleSelected` / `handleSelectBox(opts.shift)` 全就绪,3D 是唯一没接的消费者。**零新增 state**,改面最小。批量删除 / 批量改类复用壳层已有的 `selectedIds`。 |
| D4 | **history 栈复用既有 hook,基于乐观更新** | **3D 台内 `useThreeDHistory`,内部复用 `useAnnotationHistory`** | `useAnnotationHistory` 的 `Command` 联合类型(create / delete / update)与其 `applyLeaf` 已能表达 3D 的放置 / 删除 / PSR / 改类 / 改属性(全是 create/delete/update),**直接复用该 hook**,只需在 3D 台提供 `HistoryHandlers`(create / delete / update 三个 Promise 化的 mutation 封装)。不另造命令模型。 |
| D5 | **copy/paste/duplicate 本地实现** | **3D 专用纯函数 `box3dClipboard.ts`(粘贴偏移在世界系)** | `useClipboard` 是 2D 像素几何专用,不可复用;3D 复制 = 序列化选中框的 `geometry(PSR)+ class_name + attributes`,粘贴 = center 加一个固定世界偏移(默认 +X/+Y 各 2m,避免叠在原框上)后 create。duplicate = 原地复制 + 偏移。逻辑纯函数化便于单测。 |

### 1.5 成功判据

1. **属性面板**:`tool_bindings["lidar_box_3d"]` 配了属性 schema 的项目,选中一个 box_3d → 右上面板出现「属性」区,可改 occluded(boolean)/ truncated / visible(select);改动经防抖 PATCH 落到 `annotation.attributes`;刷新后保留。无 schema 配置时不渲染属性区(与 `AttributeForm` 既有「visible.length===0 返回 null」一致)。
2. **多选**:Shift+Click 第二个框 → 两框同时高亮(`selectedIds.length===2`);Delete 删除全部选中;类别下拉改类作用于全部选中;点空白处清空多选回单选。
3. **undo/redo**:放置 / 删除 / 改 PSR / 改类 / 改属性后 Ctrl+Z 撤销、Ctrl+Y 重做,框状态正确回滚;切 task 清栈(复用 `useAnnotationHistory` 既有 sessionStorage 行为)。
4. **copy/paste/duplicate**:选中框 Ctrl+C → Ctrl+V 在偏移位置生成同类同属性的新框并自动选中;Ctrl+D 等价「就地复制 + 偏移」;新框入 history(可 undo)。
5. **快捷键不冲突**:Ctrl+Z/Y/C/V/D 不误触既有 V/B/P/W/E/R/Q/Shift+方向/Delete;焦点在 `INPUT`/`TEXTAREA`/`contentEditable`(PSR 数值框 / 属性输入框)时全部快捷键跳过(沿用 `ThreeDWorkbench.tsx:546/610/766/784` 的判定模式)。
6. **回归红线**:既有单选 / PSR 面板 / gizmo / 三视图(v0.13.5)/ 贴合(v0.13.8)/ 跨帧 propagate(v0.14.1)全部不破;2D / video 的 `AttributeForm`、`useAnnotationHistory`、`useClipboard` 行为不变(本版只新增 3D 消费者,不改这些共享件的公共行为)。
7. `pnpm lint`(含 `check-css-tokens`)/ `pnpm --filter @anno/web test` 全绿;真实 nuScenes-mini(本机已存)手测:配一份带 occluded/truncated schema 的 lidar 项目 → 端到端走属性 / 多选批量 / undo / copy。

## 3. 各模块设计要点

### 3.1 G1 · 3D 属性面板(接 `AttributeForm`)

**解析 schema(纯函数,`box3dAttributes.ts`)**:
```ts
// 从 project.tool_bindings 取 box_3d 工具单位的属性 schema(与 boxClasses 同一来源)。
export function box3dAttributeSchema(
  toolBindings: ProjectToolBindings | undefined,
): AttributeSchema | undefined {
  const binding = toolBindings?.["lidar_box_3d"];
  if (!binding?.enabled) return undefined;
  return binding.attribute_schema;   // 既有 tool_bindings 结构,字段名以后端 schema 为准
}
```
> ⚠️ 实现时先核对 `apps/api/app/schemas/_jsonb_types.py:269` 附近 `tool_bindings` 的实际字段名(`attribute_schema` / `attributes` / `schema`),以及前端 `@/api/projects` 生成类型里的对应字段,**不臆造字段名**;`boxClasses` 已从 `toolBindings?.["lidar_box_3d"].classes` 取(`ThreeDWorkbench.tsx:302`),属性 schema 同一 binding 下取即可。

**面板接线(`ThreeDWorkbench.tsx` 编辑面板内,PSR 区下方)**:
```tsx
{schema && selectedBox && (
  <AttributeForm
    schema={schema}
    className={selectedClass ?? ""}
    attributes={selectedAnn?.attributes}
    readOnly={!selectedEditable}
    onChange={(next) => handleChangeAttributes(next)}  // 走 history + updateAnnotation
    hideHeading={false}
  />
)}
```
- `handleChangeAttributes(next)`:`updateAnnotation.mutate({ annotationId: selectedId, payload: { attributes: next } })`,并 `history.push({ kind:"update", annotationId, before:{attributes:old}, after:{attributes:next} })`。复用 `AttributeForm` 自带 400ms 防抖 → 不必再加防抖。
- `selectedEditable` 为假(只读 / 锁定)时 `readOnly` 传真,字段全 disabled,与 PSR 面板一致。
- 无 schema / 当前 class 下无可见字段 → `AttributeForm` 自身返回 `null`(`AttributeForm.tsx:132`),面板不显示属性区,零额外判断。
- **occluded/truncated/visible**:不在代码里硬编码,由项目在 `tool_bindings["lidar_box_3d"]` 配置(boolean 的 occluded/truncated、select 的 visibility)。文档给推荐 schema:

    { "key": "occluded",  "label": "遮挡", "type": "boolean", "hotkey": "o" },

  ]}

### 3.3 G3 · history(复用 `useAnnotationHistory`)

**`useThreeDHistory.ts`(薄封装)**:把 3D 的三个 mutation 包成 `HistoryHandlers` 要求的 Promise:
```ts
const handlers: HistoryHandlers = {
  createAnnotation: (p) => new Promise((res, rej) =>
    createAnnotation.mutate(p, { onSuccess: res, onError: rej })),
  deleteAnnotation: (id) => new Promise((res, rej) =>
    deleteAnnotation.mutate(id, { onSuccess: res, onError: rej })),
  updateAnnotation: (id, payload) => new Promise((res, rej) =>
    updateAnnotation.mutate({ annotationId: id, payload }, { onSuccess: res, onError: rej })),
};
const history = useAnnotationHistory(taskId, handlers);
```
- `useAnnotationHistory` 的 `Command` 已覆盖 create / delete / update,3D 的全部操作都落这三类:

  | 3D 操作 | 落点 command |
  |---|---|
  | 放置框(`handlePlace`) | `{ kind:"create", annotationId, payload }`(onSuccess 用真 id) |
  | 删除(单 / 批量) | `{ kind:"delete", annotation }` / `pushBatch` |
  | PSR 编辑(数值面板 / gizmo / 三视图松手 / 贴合 / 归零) | `{ kind:"update", before:{geometry}, after:{geometry} }` |
  | 改类 | `{ kind:"update", before:{class_name}, after:{class_name} }` |
  | 改属性 | `{ kind:"update", before:{attributes}, after:{attributes} }` |

- **PATCH 节流与 history 的配合**:PSR 走 250ms 防抖(`schedulePatch`)/ gizmo 拖拽 / 三视图拖拽**松手才 push**(避免拖拽中途每帧入栈)。`before` 取这次编辑**开始前**的 geometry(选中 / 拖拽起始时缓存一份 `editBaselineRef`,松手 push 时用它当 before、当前值当 after)。
- 切 task 清栈、sessionStorage 5min TTL 全由 `useAnnotationHistory` 既有逻辑承担,3D 不重复实现。

**快捷键 effect**(新增,与既有判定模式一致):
```ts
useEffect(() => {
  const onKey = (e: KeyboardEvent) => {
    if (!(e.ctrlKey || e.metaKey)) return;          // 只接管 Ctrl/Cmd 组合
    const t = e.target as HTMLElement | null;
    if (t && (t.tagName === "INPUT" || t.tagName === "TEXTAREA" || t.isContentEditable)) return;
    const k = e.key.toLowerCase();
    if (k === "z" && !e.shiftKey) { e.preventDefault(); void history.undo(); }
    else if (k === "y" || (k === "z" && e.shiftKey)) { e.preventDefault(); void history.redo(); }
    else if (k === "c") { e.preventDefault(); copySelected(); }
    else if (k === "v") { e.preventDefault(); void pasteClipboard(); }
    else if (k === "d") { e.preventDefault(); void duplicateSelected(); }
  };
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, [history, copySelected, pasteClipboard, duplicateSelected]);
```
> **不冲突核对**:既有 3D 快捷键均为**无修饰键**(V/B/P/W/E/R/Q/Delete)或 Shift+方向;Q 的 effect 已显式 `if (e.ctrlKey||e.metaKey) return`(`:764`)。本版只接管 `Ctrl/Cmd + z/y/c/v/d`,与裸键零重叠。焦点在输入框统一跳过。

## 6. 风险与依赖

- **`tool_bindings` 字段名不确定**(最需先核对):属性 schema 的确切键名以 `apps/api/app/schemas/_jsonb_types.py:269` 附近 + 前端生成类型为准,**A1 第一步先 grep 核对再写 `box3dAttributes.ts`**,不臆造。若 3D 的 box_3d 属性 schema 在后端**当前未暴露**到 `tool_bindings.lidar_box_3d`(只暴露了 classes),则属性面板需依赖项目侧能配该 schema —— 若发现后端结构不支持,**立即上报**(因为补后端会破「纯前端铁律」,需改版次定位,不在本版自行扩后端)。
- **history `before` 基线时机**:PSR / gizmo / 三视图拖拽是连续编辑,`before` 必须取「这次编辑开始前」而非每次 PATCH 前(否则 undo 只回退一帧)。对策:选中 / 拖拽起始时缓存 `editBaselineRef`,松手 push 用它当 before;单测在 A3 覆盖「连续改三次 PSR → 一次 undo 回到初值」。
- **乐观更新与 history 一致性**:`useAnnotationHistory.applyLeaf` 的 create-undo 对 `tmp_` id 走本地删除分支(`:34`)。3D 走真实 mutation(非离线 tmp),create 成功后才 push 真 id,与该分支兼容;但需确认 3D 不经离线队列(`useClipboard`/video 那套 offlineQueue 不接入 3D),保持 history 直连后端,避免 id 漂移路径。
- **多选高亮渲染**:`PointCloudScene` 若仅支持单 `selectedId` 高亮,需小改接 `selectedIds`;这是渲染高亮,不碰几何 / PSR,风险低,但要确认 gizmo 只在「单选且可编辑」时挂(多选不挂 gizmo,沿用 `:537` 的 `selectedId && selectedEditable`)。
- **快捷键全局监听叠加**:本版新增一个 `keydown` effect;3D 台已有多个全局 `keydown`(W/E/R、Shift+方向、Q、Delete、B/V/P)。新 effect 只接管 Ctrl/Cmd 组合,与裸键无交集,但需确保 `preventDefault` 不吞掉浏览器在输入框内的 Ctrl+Z(已由「焦点在输入框跳过」保证)。
- **依赖**:无新后端依赖;前端依赖既有 `AttributeForm` / `useAnnotationHistory` / `selectedIds` 多选链 —— 均已稳定。
