# v0.12.0 · 建任务异步化 + 未归类池规模化（deferred-river）

> 路线图：[大数据集规模化加固](./2026-06-02-large-dataset-scale-hardening-roadmap.md) 的第二版（B4/B5）。
> 主题：把「关联 dataset → 建 task」从同步 HTTP 单事务搬进 Celery 并给进度反馈；同时补「未归类任务池（batch_id=NULL）」在大数据集下的浏览与分包规模化。
> **风险中（Celery 任务 + 前端进度 + 行为变化），挂触发条件**：单次 link 的 dataset > ~3 万 items，或真实用户反馈导入卡顿 / 超时。

## 背景

- **B4**：`link_project`（`services/dataset.py:536-598`）与 append 路径 `create_tasks_for_items`（`:600-691`）都在**同步 HTTP 请求的单个事务**里 `insert(Task), rows` 一次性建全部 task。bulk insert 治好了万级（~2s），但：
  - 十万级单条 INSERT 十万行 ≈ 5~15s，触发网关超时（30~60s）。
  - 单个大事务长时间持锁（`display_seq_tasks` nextval、tasks 写锁），阻塞并发。
  - 失败无断点，整批回滚重来。
- **B5**：v0.7.3 后新 dataset 的 task 直接 `batch_id=NULL`（`dataset.py:566-583`），而 `get_next_task` 是 `INNER JOIN TaskBatch`（`scheduler.py:108`）+ `status in (active, annotating)`——**未分包 task 永不被派发**。十万级 dataset 导入后：
  - 工作流必须先 split 才流动（UX 悬崖：导入完工作台仍空）。
  - 未归类池本身的浏览（BatchesSection 顶部横带）与 split 大表性能（回写 batch_id + recalc counters）未做规模化。

## 范围（做什么）

### B4 建任务异步化（复用现有 `async_jobs` 基建，迁移 0091 仅加 job kind 若需要）
- 新建 Celery 任务 `app/workers/task_creation.py::build_tasks_for_link`：
  - 入参 `(dataset_id, project_id)`；**分块**建 task（每块 5k：`nextval(generate_series(1,5k))` + `insert(Task)`），每块独立提交。
  - 进度写 `async_jobs`（已有表，参考 export worker 模式）：`processed / total`。
  - 幂等：以 `(project_id, dataset_item_id)` 去重（复用 `create_tasks_for_items` 已有的 existing_pairs 逻辑 `dataset.py:636-642`），支持断点重跑。
- `link_project` 改为：建 `ProjectDataset` link + 入队 Celery + 返回 `async_job_id`；**小 dataset（< 阈值，如 2000）走同步快路径**（保留即时体验，避免给小项目引入异步延迟）。
- `create_tasks_for_items`（upload/zip/scan 追加路径）同样分块化（同一 worker）。
- `project.total_tasks` 改由 worker 分块累加（避免同步路径一次性写）。

### B5 未归类池规模化（前端 + 少量后端）
- **未归类池浏览**：BatchesSection 顶部「未归类任务」入口改用 `list_tasks?batch_id=__none__`（或新增 `unbatched=true` 查询）走 cursor 分页 + 虚拟滚动（复用 v0.11.30 的索引 `ix_tasks_batch_unlabeled`，对 `batch_id IS NULL` 需补部分索引 `WHERE batch_id IS NULL`）。
- **split 大表性能**：`BatchService.split`（`services/batch.py`）回写 batch_id 改**分块 UPDATE**（避免一次 UPDATE 十万行长事务）；超阈值时同样走 Celery + async_job 进度。
- **UX 悬崖兜底**：dataset link 完成（worker done）后，前端在 BatchesSection 顶部横带明确提示「N 条未归类任务尚未进入工作流，去分包」，并给「一键全量建包」快捷入口（把未归类一次 split 成单个 active batch）。

### 前端进度反馈
- ImportDatasetWizard / 数据集关联流程：link 返回 `async_job_id` → 轮询 / WS 订阅 `async_jobs` 进度条（复用导出已有的进度 UI 组件）。
- 关联按钮态：建任务中 → disabled + 进度；完成 → 跳转/提示。

## 不做（明确排除）
- 不改 task_batch schema 语义（B5 只补浏览 + split 规模化 + 兜底提示）。
- 不自动给新 dataset 建默认包（维持 v0.7.3 决策，仅加「一键全量建包」让用户主动触发）。
- 不做 split 的智能分批（按难度/类别自动切）——仍是 random/metadata/id_range 三策略。
- 不碰导出（B6 属 v0.12.1）。

## 风险
- **同步 → 异步是行为变化**：调用方（前端 + 任何脚本/测试）不能再假设 link 返回即 task 就绪。需全量 grep `link_project` 调用点改为等 async_job。小 dataset 快路径降低面，但仍要覆盖。
- **幂等与并发**：同一 dataset 重复入队 / link 与 append 并发，靠 existing_pairs 去重兜底；需测「重复入队不双建」。
- **进度一致性**：worker 分块累加 `project.total_tasks` 与 batch 计数物化（`batch_summary`）的最终一致窗口——需确认看板读时容忍 in-flight。
- **未归类部分索引**：`WHERE batch_id IS NULL` 与 v0.11.30 的 `WHERE is_labeled=false` 可能要合成 `(project_id) WHERE batch_id IS NULL`，以 EXPLAIN 定夺。

## 验证
- 种子脚本扩展：支持「一个未 link 的 10 万 dataset」用例。
- **link 计时**：10 万 items link → 不再走 HTTP 超时；worker 分块完成总耗时记录；HTTP 立即返回 `async_job_id`（< 200ms）。
- **断点重跑**：worker 中途 kill → 重跑不双建（`(project_id, dataset_item_id)` 唯一性对拍）。
- **未归类浏览**：10 万未归类池列表首屏 + 滚动流畅（虚拟滚动），EXPLAIN 命中部分索引。
- **split 大表**：10 万未归类一键全量建包 → 分块 UPDATE 无长事务告警；split 后 `get_next_task` 立即能派发。
- `uv run pytest`（dataset / batch / workers）；`uvx ruff check`；`pnpm lint` + e2e（导入→建任务→分包→取下一题闭环）。
