# v0.11.20 · Grafana ML Backend / GPU 可视化面板

> Epic 切片 2/3 · 见 [observability epic](2026-05-27-v0.11.19-21-ml-backend-observability-epic.md)
> 依赖：[v0.11.19](2026-05-27-v0.11.19-ml-metrics-naming-and-http-sd.md)（指标已统一裸名 + `service` label，显存 gauge 已补，Prometheus 已抓到） · 用户可见：是

## 目标

在 Grafana 新增一个 ML backend / GPU dashboard，把 v0.11.19 接入的时序指标可视化，按 `service` 把多个 backend 在同一面板对比，补上 PerfHud 没有的「历史趋势」。

## 任务

### A. 新增 dashboard JSON

文件：`infra/grafana/dashboards/ml-backends.json`（**provisioning 已配置自动加载该目录所有 `*.json`**，见 `infra/grafana/provisioning/dashboards/default.yaml`，**无需改 provisioning**）。

- 数据源：复用已 provisioned 的 Prometheus（`infra/grafana/provisioning/datasources/prometheus.yaml`）。
- 模板变量 `$service`：`label_values(gpu_utilization_percent, service)`，`multi: true` + `includeAll: true`，默认 All。所有 panel 查询带 `{service=~"$service"}`，legend 按 `{{service}}`。

### B. 面板分组（row）

| Row | Panel | PromQL（要点） | 类型 |
|---|---|---|---|
| 概览 | Backend 在线 | `up{job="ml-backends", service=~"$service"}` | stat（0/1 红绿） |
| GPU | 显存占用 | `gpu_memory_used_mb / gpu_memory_total_mb * 100` | timeseries（%，0–100） |
| GPU | 显存 used/total | `gpu_memory_used_mb`、`gpu_memory_total_mb` | timeseries（MB） |
| GPU | 利用率 | `gpu_utilization_percent{service=~"$service"}` | timeseries |
| GPU | 温度 / 功耗 | `gpu_temperature_celsius` / `gpu_power_watts` | timeseries（双 Y 或两 panel） |
| 推理 | 延迟 P50/P95 | `histogram_quantile(0.95, sum by(le,service)(rate(inference_latency_seconds_bucket[5m])))`（P50 同理 0.5） | timeseries |
| 推理 | QPS | `sum by(service)(rate(inference_latency_seconds_count[5m]))` | timeseries |
| Cache | 命中率 | `rate(embedding_cache_hits_total[5m]) / (rate(embedding_cache_hits_total[5m]) + rate(embedding_cache_misses_total[5m]))` | timeseries（0–1） |
| Cache | 缓存条数 | `embedding_cache_size` | timeseries |
| 容器 | CPU / 内存 | `container_cpu_percent` / `container_memory_percent` | timeseries |

> grounded-sam2 专属的 `video_tracker_*`（帧数 Counter / 延迟 Histogram）可单列一个折叠 row，`service="grounded-sam2"` 时才有数据，sam3 留空——属正常。

## 验证

1. `docker compose --profile monitoring --profile gpu --profile gpu-sam3 up -d`（+ host API + 两 backend 注册）。
2. Grafana（`http://localhost:3001`）→ dashboard `ML Backends` 自动出现。
3. 触发几次预标/分割产生推理流量；面板中两个 backend **在同一 panel 双线**呈现；`$service` 切到单个 backend 时其余线消失。
4. 显存、利用率、温度、P95 延迟、cache 命中率均有数据；`video_tracker_*` row 仅 grounded-sam2 有值。

## 风险 / 决策点

- **histogram bucket 边界**：P95 精度取决于 v0.11.19 里 `inference_latency_seconds` 的 bucket 设置；若默认 bucket 不覆盖实际延迟区间（ML 推理常 0.5–10s），P95 会贴边失真。动手时核对 bucket，必要时在 v0.11.19 补合适 bucket（回溯一句到 epic）。
- **dashboard JSON 维护**：手写 JSON 易错，建议在本地 Grafana 拖好后 Export model 落盘，再清掉 `id`/`__inputs`/固定 datasource uid（改成 `${DS_PROMETHEUS}` 模板）以适配 provisioning。
- **空数据观感**：backend 未起时 panel 全空。stat panel「Backend 在线」放最上方，先让运维一眼看出"是没数据还是没部署"。
