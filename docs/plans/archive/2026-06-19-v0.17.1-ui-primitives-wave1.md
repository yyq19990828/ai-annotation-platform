## 1. 目标与范围

**不在本版**:删 `components/ui/` 目录、调用点 import 重指到 `@/components/shadcn/*`、Modal/Toast/交互原语 —— 全部归 v0.17.2。

## 2. 核心策略决策(对 Epic 的细化 / 偏离)

Epic 阶段 1 原设想:codemod 把 ~200 处调用点的 import 重指到 shadcn,并重命名 props / 把 `<Icon name="x">` 改写成直接 lucide 具名组件。**实测后改为更低风险的「就地适配器改写」**:

> **就地把旧 wrapper 的内部从 `module.css` 改写为 shadcn 的 `*Variants`(CVA),保留原有 prop API 与 import 路径 → 调用点零改动;视觉立即抬升;删 4 个 module.css。** import 重指 + 删 `ui/` 留到 v0.17.2「删 ui/」时统一 codemod。

**为什么这样更优(基于实测数据)**:

1. **零调用点 churn**:Button 105 / Badge 55 / Card 36 全是直接路径 import(`@/components/ui/Button`),且各组件 prop API 各异(variant 名不同、Card 无 padding)。改写内部 = 0 个 JSX 改动;repoint import = 200+ 文件改动。把「视觉改动(需肉眼回归)」与「机械 import 搬迁(数量大但每文件 trivial)」拆到两个版本,各自风险可控。
2. **Card 布局陷阱**:shadcn `<Card>` root 自带 `flex flex-col gap-6 py-6 shadow-sm`,而旧 `Card` **无 padding**(仅 `bg + border + radius`)。直接换成 shadcn Card 会在 36 处注入额外间距 → 布局破坏。适配器渲染 `rounded-xl border bg-card` 的 div 即 1:1。
3. **Icon 已是 lucide**:`Icon.module.css` 仅 `flex-shrink:0`。无需 codemod 142 处 `<Icon name>`→直接 lucide;只把 `styles.icon` 换成 `shrink-0`、删 module.css,API 与路径不变。
4. **`style` prop + eslint**:eslint 禁**所有** `style` JSX 属性(`JSXAttribute[name.name='style']`),`useElementStyle`(命令式 ref 注入)是唯一逃生口。适配器渲染**原生 `<button>/<span>/<div>`**(保留 `forwardRef` + `useElementStyle`),而非 shadcn 的无-ref 函数组件,从而:① 调用点传 `style` 继续可用;② 不触 eslint;③ 复用 shadcn 的 `buttonVariants`/`badgeVariants` 取 class。

**取舍代价**:旧 wrapper 暂时变成「shadcn 适配层」而非被删除;v0.17.2 仍需一次 import-repoint codemod 才能删 `ui/`。但那次 codemod 是纯 import 字符串替换(可脚本化、可 typecheck 兜底),远比本版混入 JSX 改写安全。

## 3. 组件映射

### 3.1 Button(`variant` / `size` → shadcn `buttonVariants`)

旧 API:`variant: default|primary|ghost|ai|danger`、`size: sm|md`。

| 旧 variant | 旧视觉(module.css) | → 新映射 | 备注 |
|---|---|---|---|
| `default` | 浮起底 + 边框 + 主文字 + 阴影 | `buttonVariants({variant:"outline"})` | 1:1 最接近 |
| `primary` | **蓝**底白字(`--color-accent`) | `buttonVariants({variant:"default"})` | **有意改色**:新 CTA = Geist 实心黑/反白(设计 §2.1)。全站主按钮由蓝转黑白,是重设计的一部分。 |
| `ghost` | 透明 | `buttonVariants({variant:"ghost"})` | 1:1 |
| `ai` | violet 软底 + violet 字 | `outline` 基 + `border-violet-500/30 bg-violet-500/10 text-violet-600 dark:text-violet-400 hover:bg-violet-500/15` | shadcn 无 ai;用设计 §2.2 violet 点缀 |
| `danger` | 浮起底 + 红描边 + 红字(**软**) | `outline` 基 + `border-rose-500/30 text-rose-600 dark:text-rose-400 hover:bg-rose-500/10` | 保持「软描边红」观感,不用 shadcn 的实心 `destructive` |

| 旧 size | → shadcn size |
|---|---|
| `md`(默认) | `default`(h-9) |
| `sm` | `sm`(h-8) |

实现:`cn(buttonVariants({ variant: mappedVariant, size: mappedSize }), extraClassName, className)`,渲染 `<button ref={styleRef} {...props}>`。

### 3.2 Badge(`variant` → 设计 §2.2/§2.3 语义色 className)

旧 API:`variant: default|success|warning|danger|accent|ai|outline`、`dot?`。

| 旧 variant | → 新 className(柔底 /10 + 暗色提亮) |
|---|---|
| `default` | `bg-muted text-muted-foreground` |
| `success` | `bg-emerald-500/10 text-emerald-600 dark:text-emerald-400` |
| `warning` | `bg-amber-500/10 text-amber-600 dark:text-amber-400` |
| `danger` | `bg-rose-500/10 text-rose-600 dark:text-rose-400` |
| `accent` | `bg-sky-500/10 text-sky-600 dark:text-sky-400` |
| `ai` | `bg-violet-500/10 text-violet-600 dark:text-violet-400` |
| `outline` | `border-border text-foreground`(即 `badgeVariants({variant:"outline"})`) |

基类用 `badgeVariants({variant:"outline"})` 去掉默认描边/底后叠加,或直接拼 `cn("inline-flex w-fit shrink-0 items-center gap-1 rounded-full px-2 py-0.5 text-xs font-medium", variantCls, className)`。`dot` → 前置 `<span className="size-1.5 rounded-full bg-current opacity-90" />`(对齐旧 6px dot)。渲染 `<span ref={styleRef}>`。

### 3.3 Card

旧:`{ children, style?, onClick? }`,渲染 `div.card`(`bg-elev + 1px border + radius-lg`,**无 padding**)。
新:`<div ref={styleRef} onClick className={cn("rounded-xl border border-border bg-card", className)}>`。保留无-padding 语义;`rounded-xl` 对齐设计「卡片 12px」。新增可选 `className` 透传(旧无,但加上无害、便于个别调用收紧)。

### 3.4 Icon

保留 `<Icon name size stroke style className />` API 与 ICON_MAP 不变。仅:① `styles.icon`(`flex-shrink:0`)→ `cn("shrink-0", className)`;② 删 `import styles`;③ 删 `Icon.module.css`。`useElementStyle` 保留(`style` 透传)。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 主按钮全站蓝→黑白,视觉跳变大 | **有意为之**(重设计 + 设计 §2.1)。截图 diff 人工确认是「预期变化」而非 bug;若用户要保留蓝,改 `--sc-primary` 即可全局回退。 |
| `useElementStyle` + shadcn class 在原生元素上的 hover/focus 表现 | 用 shadcn `buttonVariants` 全量 class(含 `focus-visible:ring`),原生 `<button>` 行为与 shadcn 一致;抽查键盘 focus 环。 |
| Badge `dot` 尺寸/对齐回退 | `size-1.5`(6px)对齐旧 dot;gap 用基类 `gap-1`。 |
| tw-tokens 门禁报新 className 暗色配对 warning | 本版新增的语义 className 一律带 `dark:` 提亮(§3.2 已含),warning 应为 0。 |
| 旧 CSS 删除后 tokens.css 仍有 `--color-ai-soft` 等悬空定义 | 不处理(tokens.css 整体退役在 v0.17.7);check-css-tokens 只查引用不查未用定义,不报错。 |
| **⚠ UA 默认样式漏出(实战踩坑)** | 适配器渲染**原生 `<button>`**,而迁移期**未启用全局 preflight**(只在 `.tw-scope` 内重置),老页面(非 tw-scope)消费时:① ghost 按钮漏出浏览器 UA 灰底 `rgb(107,107,107)` + 2px outset 边;② outline 按钮边框色退回 `currentColor`(深)而非发丝灰。shadcn 的 `buttonVariants` 默认**假设有 preflight 兜底**。**修复**:Button 适配器加 preflight 等价基线 `appearance-none border-0 border-border bg-transparent`,各 variant 用 twMerge 覆盖。**对后续 wave 的启示**:任何渲染带 UA chrome 的原生元素(`button/input/select/textarea`)的适配器,在非 tw-scope 场景都需自带这层基线;到 v0.17.7 全局 preflight 后此基线变冗余但无害。Badge(`span`)/Card(`div`)/Icon(`svg`)无 UA chrome,不受影响。 |
