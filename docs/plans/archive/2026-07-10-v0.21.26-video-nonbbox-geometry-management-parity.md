# v0.21.26 · 视频非矩形几何「管理层」补齐(选中卡 / 右键 / 边栏 / 删除 / 工具反馈)

状态:**计划(2026-07-10)**。v0.21.20–v0.21.23 把视频**渲染层**从 bbox-only 扩到了多边形 / 折线 / 旋转框及其
track 变体(能画、能选、能命中、能拖顶点改形),但**管理层**(选中信息卡 / 右键菜单 / 右栏轨迹清单 / 删除分派 /
部分光标·预览反馈)**只补了「画」没补「管」**,仍硬编码 `video_bbox` + `video_track_bbox`。后果是**「画得出、选得中,
一旦要看信息 / 用菜单 / 用边栏 / 删除,全部落到空白或 no-op」**。本计划做**纯前端**的管理层补齐,不动 schema / 后端 /
插值(那些属 v0.21.20 epic 主体)。

**定位澄清(为什么是「缺口」而非「某 epic 没干完」)**:本计划补的是**两个 epic 之间都没立任务的范围缺口**——
- [v0.21.20 多几何 track](2026-07-05-v0.21.20-multi-geometry-track.md) 的分期 PR1–PR5 全是 schema / 渲染 / 插值 /
  回填 / 导出(§83-94),**无一条**是选中卡 / 右键 / 边栏 / 删除;它是「故意跨多版本、非单版本可完结」的 epic(§113),
  渲染/绘制/导出主线大体已落地,仅 PR5「真·mask 栅格 track + DAVIS 导出」明确未做(与本计划无关)。
- [v0.21.21 视频单帧工具 epic](2026-07-07-video-single-frame-tools-epic.md) 全文对选中卡 / 右键 / 边栏 / 删除**零提及**,
  范围是「几何渲染器 + 工具绘制交互」,红线是坐标归一化 / `frame_index` / bbox 零回归。

两个 epic 都只规划了「画 / 渲染 / 插值 / 导出」,又都守「bbox 零回归」红线,于是那套 bbox-only 的**管理层 UI 被漏在缝里**
——这就是「能画不能管」的来源。真·keyframe 级点集轨迹编辑(顶点对应 / 参数化插值)仍归 v0.21.20 epic,本计划**不碰**;
AI 工具(exemplar / magic-box)反馈缺失关联 [v0.21.25 多目标追踪 epic](2026-07-07-v0.21.25-video-multi-target-tracking-epic.md)。

## 一、总根因:两个「类型闸门」卡住了全部非矩形几何

| 闸门 | 位置 | 只放行 |
|---|---|---|
| `isVideoBbox` | `stage/videoStageGeometry.ts:49` | `video_bbox` |
| `isVideoTrack` | `stage/videoStageGeometry.ts:86` | `video_track_bbox` |

已存在但**在管理层几乎无人引用**的守卫就在同一文件:`isVideoPolygon(:54)` / `isVideoPolyline(:61)` /
`isVideoRotatedBbox(:68)` / `isVideoPolygonTrack(:91)` / `isVideoPolylineTrack(:98)`。渲染层(`videoFrameViews.ts:171-208`)
已在用它们全类型建 entry;管理层没跟上。

受影响几何(共 5 类被冷落):单帧 `video_polygon` / `video_polyline` / `video_rotated_bbox`,轨迹
`video_track_polygon` / `video_track_polyline`。

## 二、现状缺口(带证据,对应用户四诉求)

### 缺口 1 · 悬浮信息卡:非矩形几何选中后正文渲染 null(用户诉求②)
「悬浮信息栏」= `SelectedAnnotationCard`(可拖拽浮动信息卡,**由选中触发**,非真 hover——视频所有 Konva 层
`listening=false`,无标注级 hover 命中)。
- 分派 `state/useWorkbenchShellModel.tsx:2192-2265`:**只有 `video_bbox` 有专属卡**(`VideoFrameBoxCardContent`,
  `:2193-2208`);其余全掉进 `else → renderVideoTrackSidebar("current","card")`(`:2261-2265`)。
- `stage/VideoTrackSidebar.tsx:456-457` card 视图 `if (!selectedTrack) return null`;而 `selectedTrack`(`:169-172`)
  源自 `videoTracks = annotations.filter(isVideoTrack)`(`:164`,仅 bbox 轨迹)。
- ⇒ 单帧多边形/折线/OBB **及** 多边形/折线轨迹选中后:**卡片有标题(类别名)、正文为空**。
- 排除项:头顶**类别小标签**正常(`videoFrameViews.ts:174-189` + `VideoKonvaOverlayLayer.tsx:56-77` 全类型覆盖)。

### 缺口 2 · 右键菜单:非矩形几何返回空 `[]`,且仍会弹出空菜单(诉求③④)
- `stage/videoContextMenuItems.ts:61` 仅 `isVideoBbox` 分支给「改类别 / 删除」;`:105`
  `if (… || !isVideoTrack(selectedAnnotation)) return []` ⇒ 非 bbox 轨迹**直接空菜单**。
- `stage/VideoKonvaStage.tsx:722-731`:命中后**无条件** `contextMenu.openAt(...)`,而 `contextMenuItems`(`:687`)对
  多边形为 `[]` ⇒ 右键点多边形**弹出一个空菜单**,加剧「删不掉」的困惑。

### 缺口 3 · 右栏轨迹清单 + handler 守卫(诉求③)
- 清单数据源 `stage/VideoTrackSidebar.tsx:164` `filter(isVideoTrack)` ⇒ 多边形/折线轨迹**不出现在清单**(→ 无行内
  显隐/锁/改类/删除/改色、无法多选批量)。
- 即便接上清单,`stages/video/useVideoAnnotationActions.ts` **6 处**硬守卫会静默早退:
  `:371-375`(批量改类 filter bbox)、`:414-416`(批量删除 filter bbox,空则 return = 静默 no-op)、
  `:447-455`(改类快捷 handleVideoSetSelectedClass 仅 bbox 返回 true)、`:457-461`(转独立框)、
  `:580-581`(帧属性)、`:590-596`(复制后续 propagate)。
- 独立 bug:每行「更多操作 ⋮」是**死按钮**——`stage/VideoTrackPanel.tsx:488-496` 唯一 handler 是
  `onClick={(e)=>e.stopPropagation()}`(图片端同款 `stage/BoxListItem.tsx:400-408`)。**bbox 行也中招**,是唯一严格
  「按钮显示了、点了纯没反应」的项。
- 交互门控:批量工具条被 `trackFilter==="current"` 门控(`VideoTrackPanel.tsx:239-315`),「全部」tab 多选只给提示
  ⇒ 易被误判为失效(**属刻意设计,本计划仅补文案/入口提示,不改门控**)。

### 缺口 4 · 删除:唯一全类型可用入口只有键盘 Delete;三条 UI 入口 bbox-only;且轨迹语义相反(诉求④)
- 底层 `state/useWorkbenchAnnotationActions.ts:488-509` `handleDeleteBox` **类型无关**按 id 删(正确),偏差全在入口分派。
- 键盘 `state/useWorkbenchHotkeys.ts:413-424`:关键帧级删除 `if (selected?.geometry.type === "video_track_bbox")`
  **只特判 bbox 轨迹** ⇒ 同按 Delete:**bbox 轨迹删当前关键帧,多边形/折线轨迹删整条**(语义相反)。
- bbox 轨迹本身:`stage/VideoKonvaStage.tsx:671-685` `canDeleteSelectedTrackKeyframe` 需
  `keyframes.length>1` 且当前帧有关键帧,否则 `deleteSelectedTrackKeyframe` `return false`(静默 no-op),hotkey 调用后
  立即 return,**不回退整条删** ⇒「选中轨迹按 Delete 有时没反应」。
- 右键 / 边栏 / 浮卡三条 UI 入口对单帧多边形/折线/OBB 与多边形/折线轨迹**全部无删除项**(缺口 1/2/3 的并发结果)。

### 缺口 5 · 工具交互反馈缺失(诉求①,「接线偏差」实为反馈层,非落库失效)
11 个工具逐一走通:**无工具静默失效**,均能产出正确几何 / 触发预测。偏差集中在反馈:
- `stage/VideoKonvaStage.tsx:887` `samProbeTool` 只列 smart-point/smart-box,**漏 exemplar / magic-box** ⇒ 这俩**无十字
  光标**;而真正决定行为的 `videoKonvaInteraction.ts:53` `isSamProbeTool` 含全部 4 个(两处谓词不一致)。
- `stage/VideoKonvaStage.tsx:610-615` `preview` 只对 `drag.mode==="bbox"` 画框,exemplar 的 `mode==="exemplar"` 落
  `null` ⇒ **exemplar 拖框全程无橡皮筋预览**(叠加无光标 ⇒ exemplar 体感最像「工具坏了」)。
- `stage/VideoKonvaStage.tsx:924`(容器 `onDoubleClick={fitViewport}`)与 `:947`(Stage `onDblClick={commitPointsDraft}`)
  ⇒ **双击闭合多边形/折线时画布同时被 fit**(视口跳变)。
- `stage/videoKonvaInteraction.ts:310-315`:`onSelect(null)` 排在 `if(!creationEnabled) return` 之后 ⇒
  **select 工具点空白不取消选中**(存疑,可能与 sticky-track 模型有意保留,见开放问题)。

  (本计划**不改**,列为已知项 / 后续)。

## 三、设计决策

1. **新增「轨迹几何联合」判定 + 解析 helper**(集中在 `stage/videoStageGeometry.ts`),避免各处散拼 `||`:
   - `isAnyVideoTrack(ann)` = `isVideoTrack || isVideoPolygonTrack || isVideoPolylineTrack`;
   - `isAnyVideoSingleFrame(ann)` = `isVideoBbox || isVideoPolygon || isVideoPolyline || isVideoRotatedBbox`;
   - 各处 `filter/find(isVideoTrack)` 逐一评估替换为联合判定(**保留 bbox 专属路径**,见风险)。
2. **选中信息卡:补「点集几何卡」**。新增一个轻量 `VideoPointsGeometryCardContent`(仿 `VideoFrameBoxCardContent`),
   用 `boundsOfPoints` / 顶点数 / 帧号等指标替代 `geometry.bbox`,提供**改类别 / 删除 / 属性**最小操作集;单帧
   polygon/polyline/OBB 走它。**兜底**:`useWorkbenchShellModel.tsx:2261` fall-through 对仍未覆盖类型改渲染
   `SelectionCardPlaceholder`(对齐图片端 `:2280`),**杜绝空卡**。
3. **右键菜单:补非矩形分支**。`videoContextMenuItems.ts` 为单帧点集几何给「改类别 / 删除」;为点集轨迹给「改类别 /
   删除整条轨迹 / 显隐 / 锁定」子集;并在 `VideoKonvaStage.tsx:722` **命中后菜单项为空则不 openAt**(消灭空菜单)。
4. **删除语义统一(分层)**:
   - **P0**:三条 UI 入口(右键 / 边栏 / 浮卡)对**所有类型**都提供删除,单帧删整个、轨迹删整条(consistent baseline)。
   - **P1**:键盘 Delete 对点集轨迹与 bbox 轨迹**语义对齐**(有 keyframe-level 编辑能力后删当前关键帧);在能力落地前,
     点集轨迹 Delete = 删整条,但**右键/浮卡同步呈现同一语义**,不再「入口间打架」。
   - bbox 轨迹的 Delete no-op 回退:`canDeleteSelectedTrackKeyframe` 不满足时,让 hotkey **回退到整条删**(或至少给 toast)。
5. **工具反馈修补**(小、独立、低风险):`samProbeTool → isSamProbeTool(videoTool)`;`preview` 对 `mode==="exemplar"`
   也画框;绘制工具下禁用容器 `onDoubleClick`(或 commit 分支 `stopPropagation`);死按钮「⋮」**移除或接真实
   `DropdownMenu`**。
6. **不做**(明确划界):schema / 后端 / 插值改动;点集轨迹的完整 keyframe 表 & 参数化插值(归 v0.21.20 epic);
   多边形真实多边形命中(外接盒命中保留)。

## 六、风险与开放问题

- **R1 · `selectedTrack` 放宽的连锁**:`VideoTrackSidebar` 的 `selectedTrack` 一旦纳入点集轨迹,`VideoTrackCardContent`
  与 `useVideoTrackActions` 深度假设 `keyframe.bbox`(关键帧表 / nearestTrackBbox / 标记消失遮挡)。**缓解**:P0 不让
  点集轨迹复用完整 track 卡,而是走**精简点集轨迹卡**(改类 / 删整条 / 显隐 / 锁),完整 keyframe 表留 v0.21.20 epic。
- **R2 · 删除语义变更**:把点集轨迹 Delete 从「删整条」改向「删关键帧」需 keyframe 级编辑能力,尚不完整;P1 先保证
  **三入口语义一致**,真·keyframe 删除随 epic 落地。需产品确认过渡期语义。
- **R3 · 命中精度**:外接盒命中在密集多边形场景会误选;本计划不改,列为后续(真实多边形 point-in-polygon 命中)。
- **开放问题 O1**:select 点空白**是否应取消选中**?当前有意保留(sticky-track 续画模型)。需确认——若确认保留则
  2.3 不改,仅加注释说明。
- **开放问题 O2**:单帧点集几何卡要不要展示「转轨迹」等进阶操作,还是仅最小集?P0 先最小集。
