## 1. 决策摘要

v0.24.2 只交付一条完整切片：**把现有 3D 框精修过程变得更快、更稳、可恢复**。范围固定为：

1. 非绘制状态双击 3D 框，主视口聚焦该对象。
2. 三正交视图支持按对象、按视图记忆缩放。
3. 同一 scene 切帧时保持主视图相机状态；跨 scene 仍遵守现有默认视角与持久化偏好。
4. 提供“框体精修 / 传感器融合 / 点级分割”三套 3D 面板布局预设，一次点击恢复。

本计划**替代父 Epic 原第 7 节的“4D Scene 时间轴与质检摘要”作为 v0.24.2 的权威范围**。原因不是时间轴价值下降，而是当前版本已经是 0.24.1，原 Epic 为 v0.24.1 安排的可信导出也没有随该编号落地，旧的连续编号和依赖关系已经失效。继续把导出、时间轴、质检和交互精修塞进同一版本，会再次形成不可独立验收的大包。

推荐顺序遵循调研报告的“切片一”：先修复每个对象都会重复发生的聚焦、缩放、相机与布局摩擦，再分别为持续创建、场景时间轴、3D 质检和可信导出建立独立草案。

## 2. 当前基线与差距

| 主题        | 当前实现                                                                                                             | 本版差距                                       | 调研依据                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------ |
| 主视口聚焦  | `handleViewportDoubleClick` 只在 point-mask 多边形模式下结束绘制；`PointCloudScene` 只有整帧 `resetView` / `bevView` | 没有对象级 fit，也没有双击手势冲突合同         | CVAT 双击 cuboid 聚焦                |
| 三视图取景  | `frameOrtho` 每次按当前框尺寸和固定 margin 自动取景，WebGL 与 2D overlay 共享同一投影                                | 用户不能缩放，也无法回到某个对象上次的精修尺度 | CVAT per-object orthographic zoom    |
| 相机连续性  | 每次 `loadPcd` 都先 `frameView`；只有开启“持久化 3D 视角”时才在加载后恢复账号偏好                                    | 默认设置下，同 scene 切帧仍会重置相机          | CVAT 切换视图不无故重置透视相机      |
| 3D 面板布局 | 三视图和相机面板可自由拖动、折叠并持久化；只有“重置相机布局”                                                         | 自由布局缺少稳定起点，混乱后不能按任务一键复原 | Supervisely 自由布局 + CVAT 稳定骨架 |

当前已有 `TransformControls` 屏幕尺寸自适应、三视图实时联动、相机投影编辑和用户布局持久化。本版在这些边界上补行为，不重写 Three.js 场景、gizmo、标注 mutation 或工作台壳层。

## 3. 目标与非目标

### 3.1 目标

- 用户能从任意透视角双击一个可见 cuboid，在不改变观察方向的前提下把对象放到适合精修的画面尺度。
- 用户在 Top / Side / Front 中缩放某个对象后，切换对象再返回时恢复各自尺度。
- 用户在同一 scene 的帧之间往返时，`position`、`target`、`up` 和 orbit / BEV 模式保持连续。
- 用户从任意拖乱、折叠状态恢复到三种标准 3D 面板布局中的任意一种，最多一次点击。
- 除双击命中对象会显式收敛为该对象单选外，缩放、切帧连续性和布局预设只影响视图与布局状态，不改变 `Annotation.geometry`、当前工具、当前帧或未保存编辑。

### 3.2 明确不做

- 不实现持续建框、Space 确认循环或连续 Auto Cuboid；它属于后续“场景工作流”独立草案。
- 不实现 scene 时间轴、frame-summary API、轨迹缺口摘要或 3D 质检规则。
- 不把原 v0.24.1 的 KITTI / nuScenes / COCO 可信导出范围并入本版。
- 不在每次从标注列表单击选中时自动移动主相机；聚焦必须是用户明确的双击动作。
- 不持久化每对象三视图缩放，不新增账号偏好字段、数据库字段或服务端实体。
- 不改变 3D 几何、坐标系、投影、自动拟合、undo / redo 和 annotation API。
- 不增加新快捷键体系；键盘只是已可见交互的等价入口。

## 4. 交互合同

### 4.1 双击对象聚焦

触发条件固定为：

- 当前 3D 工具是“选择”；
- 没有框选、point-mask 绘制或 gizmo 拖拽正在进行；
- 双击位置命中一个当前可见的 `box_3d`。

满足条件时，第二次点击完成后执行两步：先把命中对象变为单选，再聚焦该对象。若原来是多选，聚焦动作明确收敛为命中的一个对象。锁定标注和只读任务仍允许聚焦，因为该动作不改数据。双击空白不清空选择、不复位相机，也不显示无意义提示。

聚焦只改变相机的目标点和到目标的距离：

- `target` 变为框中心；
- 保留当前相机到旧 target 的观察方向、`up` 和 orbit / BEV 模式；
- 使用框尺寸的包围球、透视相机纵向 FOV 与 viewport aspect，取水平 / 垂直两个约束中更远的安全距离；
- 取景额外保留 20% 边距，并同步 near / far，避免大车、细杆和桌面小物体被裁切；far 不得低于整帧鲁棒取景的安全范围，保证用户再次拉远时不会丢失场景点云；
- 当前相机方向退化为零向量时，才回退到工作台既有默认观察方向。

手势优先级固定为：point-mask 多边形双击结束 > 其他绘制状态忽略聚焦 > 选择状态命中框后聚焦。不得用延迟单击的方式改写现有选择手感，也不得让双击多提交 annotation 请求。

显式聚焦属于相机操作：若用户开启“持久化 3D 视角”，聚焦后的状态继续通过现有偏好保存；未开启时只在当前工作台会话和同 scene 切帧间保留。

### 4.2 三视图对象级缩放

缩放记忆键为 `annotationId + top|side|front`，生命周期限定为当前 `ThreeDWorkbench` 挂载周期：

- 首次查看对象的三个视图均为 `1.00x`；
- 每个离散档位乘或除 `1.12`，范围限制为 `0.50x` 至 `8.00x`；
- 鼠标滚轮与触控板小 delta 先归一化并累计，跨过一个阈值才移动一档，避免触控板一次手势跳多档；
- 键盘聚焦到某个正交视图后，`+` / `=` 放大，`-` 缩小，`0` 恢复该对象该视图默认值；
- caption 同步显示整数百分比，例如 `Top · 112%`，让当前尺度可见；
- 拖边、拖角或旋转期间忽略滚轮缩放，避免一次手势同时改几何和视图。

Top、Side、Front 分别记忆，不强制联动。对象尺寸被编辑后保持缩放倍数，基础取景仍以新的框尺寸计算。选中其他对象再返回时恢复三个倍数；折叠 / 展开三视图也不能丢失。离开 3D 工作台后清空，刷新或换设备回到默认值。

`TriViewRenderer` 的正交相机与 `TriOrthoView` 的 2D overlay 必须消费同一个缩放值，保证点、框线、handle 和米到像素换算始终重合。不得只缩放 canvas CSS 或只改其中一层。

### 4.3 主相机状态连续性

相机连续性分三层处理：

| 场景                                 | 应用规则                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| 同一 task 内面板折叠、拖动、预设切换 | 相机 `position / target / up / mode` 逐值不变；viewport aspect 可随尺寸更新        |
| 同一 `scene_id` 切换 point-cloud 帧  | 加载前保存运行时 view state，点云完成加载后恢复；不受 `persistCameraView` 开关影响 |
| 首次进入或切到不同 scene             | 开启持久化时应用账号级 `pointcloudCamera`；关闭时使用新点云的 `frameView`          |

连续性 key 使用 manifest 的 `scene_id`。没有 scene 的单帧点云以 `taskId` 作为 key，因此不会把一个无关任务的运行时视角带到另一个任务。相同 scene 内即使 PCD URL 改变，也保持视角；`resetView` 和“俯视”仍是显式相机动作，不受此规则拦截。

运行时 view state 只接受九个有限数值和合法 mode。恢复失败时保留该帧已经生成的默认视角，不抛出阻断错误。点云加载、默认 `frameView` 和程序化恢复期间暂停相机偏好写回；恢复完成后才重新接收真实用户操作，避免保存回调循环、默认视角抢写或重复用户偏好 PATCH。

### 4.4 三套 3D 面板布局预设

主视口左上控件区新增一组可直接点击的布局命令：

| 预设       | 三视图                             | 2D 相机面板                                                      | 保持不变                             |
| ---------- | ---------------------------------- | ---------------------------------------------------------------- | ------------------------------------ |
| 框体精修   | 展开，位置和尺寸恢复为响应式默认值 | 当前相机 role 全部折叠并回默认锚点                               | 左右业务边栏、主相机、选择、工具、帧 |
| 传感器融合 | 折叠并回默认锚点                   | 清除自定义位置与折叠记录，恢复默认贴边；窄屏继续服从既有自动折叠 | 同上                                 |
| 点级分割   | 折叠并回默认锚点                   | 当前相机 role 全部折叠并回默认锚点                               | 同上；尤其不自动切换到 P 工具        |

预设只写现有 `layout.triViewFloat` 与 `layout.cameraPanels`。三视图的 `x / y / w / h` 设回 `null`，继续由现有响应式 resolver 决定位置和尺寸；相机 role 来自当前 manifest，不创建虚构 role。左右边栏和 PSR 浮窗不纳入预设，避免 3D 操作意外改动全模态共享布局。

应用预设后，用户仍可自由拖动、缩放或折叠，现有账号级布局持久化继续工作。再次点击任一预设就是一次恢复命令，不需要额外保存“当前预设”字段，也不引入“预设 / 自定义”双状态同步问题。

## 5. 状态与数据边界

```text
主视口双击
  -> ThreeDWorkbench 手势守卫
  -> PointCloudScene.pickBox
  -> 共享选中态 + PointCloudScene.focusBox
  -> 现有 view-change 持久化（仅在用户已开启时）

selected annotation id
  -> ThreeDWorkbench 会话级 zoom map
  -> TriViewPanel
  -> TriViewRenderer 正交相机
  -> TriOrthoView overlay / handle

布局预设按钮
  -> ThreeDWorkbench.helpers 纯函数
  -> 现有 WorkbenchLayoutPatch
  -> triViewFloat + cameraPanels

point-cloud URL + scene continuity key
  -> usePointCloudScene 保存运行时 view
  -> PointCloudScene.loadPcd
  -> 同 scene 恢复 / 新 scene 默认或账号偏好
```

| 状态                      | 保存位置                          | 生命周期               | 服务端变化               |
| ------------------------- | --------------------------------- | ---------------------- | ------------------------ |
| 每对象三视图缩放          | `ThreeDWorkbench` 内存 Map        | 当前 3D 工作台挂载周期 | 无                       |
| 同 scene 运行时相机       | `usePointCloudScene` ref          | 当前 3D 工作台挂载周期 | 无                       |
| 三视图与相机面板布局      | 既有 `WorkbenchLayoutPreferences` | 沿用账号级持久化       | 只写既有字段             |
| annotation / task / scene | 既有查询与 mutation               | 不变                   | 无新请求、无 schema 变化 |

本版实体增量为 0；数据库表、迁移、API、OpenAPI schema、环境变量、依赖和长期 feature flag 增量均为 0。没有外部服务、账号、密钥或 CLI 前置条件。

## 6. 实施阶段

四个阶段按顺序实施，每个阶段都必须独立可合并、可回滚，不允许等最后一批再补测试。

### Phase 1 · 对象聚焦

1. 新增纯相机取景数学，覆盖 aspect、FOV、安全边距、退化方向和 near / far 边界。
2. 给 `PointCloudScene` 增加按 box id 聚焦的命令，直接读取已有 box group 的中心和尺寸。
3. 在 `ThreeDWorkbench` 中按工具状态仲裁双击，保持 point-mask 多边形完成语义。
4. 补纯函数单测和真实 WebGL E2E，确认双击只选中 / 聚焦，不产生 annotation 写请求。

独立验收：选择状态双击框后相机 target 等于框中心、观察方向和 mode 不变；双击空白与 point-mask 绘制不触发聚焦。

### Phase 2 · 三视图缩放记忆

1. 扩展 `frameOrtho` 的统一缩放口径，默认参数保持当前行为。
2. 让 renderer 与 overlay 同时消费 `zoomByView`，caption 显示百分比。
3. 在 `ThreeDWorkbench` 持有按 annotation id 的会话级 Map，面板折叠后仍保留。
4. 接入 wheel、触控板与键盘等价操作，几何拖拽期间屏蔽缩放。
5. 补两个对象往返、三视图独立、折叠往返和触控板小 delta 的 E2E。

独立验收：切换 20 次对象后回到原对象，三个视图都回到之前的离散档位，WebGL 点和 overlay 框仍重合。

### Phase 3 · 同 scene 相机连续

1. 给 `usePointCloudScene` 传入明确的 continuity key，并区分首载、同 key 重载和换 key。
2. 同 key 加载前捕获运行时 view，加载完成后恢复；换 key 延续现有账号偏好 / 默认视角分支。
3. 用 mock scene 的 hook 单测固定调用顺序，再用两帧 lidar seed 做真实切帧回归。
4. 加布局变化不改 view state 的守护，防止预设阶段引入相机回归。

独立验收：关闭“持久化 3D 视角”时，在同 scene 两帧间往返 20 次，四个相机字段误差不超过 `1e-6`；切到不同 scene 会按默认规则重新取景。

### Phase 4 · 布局预设、文档与发布门

1. 用纯函数生成三套 `WorkbenchLayoutPatch`，只包含 `triViewFloat` 和 `cameraPanels`。
2. 在现有控件浮条加入三个可见按钮和清晰 tooltip，提供 aria-label 与 active press feedback。
3. 在 1,366 × 768 和 1,920 × 1,080 下测试相机数量 0 / 1 / 2 / 6、右栏开 / 关和三视图选中 / 未选中。
4. 更新 3D 框与点云视图用户文档，并在 `CHANGELOG.md` 的 `Unreleased / Changed` 记录用户可见变化。

独立验收：从任意自定义位置到三套标准布局均为一次点击；切换前后的 task、selected ids、tool、annotation 数量和主相机状态一致。

| 角色     | 可编辑标注员、只读 reviewer、锁定 box             |

| 选中     | 无选中、单选、多选、切换两个尺度差异明显的框      |
| 相机模式 | orbit、BEV、持久化开、持久化关                    |
| scene    | 同 scene 两帧往返、不同 scene、无 scene 单帧 task |
| 输入     | 鼠标滚轮、触控板小 delta、键盘 `+ / - / 0`        |
| 视口     | 1,366 × 768、1,920 × 1,080                        |
| 相机面板 | 0、1、2、6 个 role；默认、拖动、折叠              |

### 8.3 发布阻断条件

- point-mask 多边形双击同时触发了对象聚焦或多一条 annotation 写请求。
- 聚焦改变了 orbit / BEV mode、观察方向或框几何。
- 正交视图点云与 overlay 在任意 zoom 档位出现可见错位。
- 同 scene 切帧仍在持久化关闭时重置，或不同 scene 错误继承运行时视角。
- 布局预设改变了左右边栏、选中态、当前工具、当前帧、主相机或 annotation 数量。
- 任一目标视口遮住保存、提交、退出工具或主导航入口。
- 新增任意 API、数据库、偏好 schema、依赖、环境变量或长期 flag。

## 9. 成功指标

功能验收使用固定的 20 个 cuboid 样本，尺寸至少覆盖相差 10 倍的物体：

1. 连续双击聚焦 20 个对象，不需要额外旋转、平移或滚轮把对象重新找回画面。
2. 20 次对象切换后返回原对象，三个正交视图缩放误差均为 0 个离散档位；允许的上限是 1 档，仅用于不同输入设备的 E2E 事件归一化。
3. 同 scene 两帧往返 20 次，`position / target / up / mode` 保持；布局预设切换不改变这四项。
4. 从随机拖动、缩放和折叠后的布局恢复到任一预设只需一次点击。
5. 同一数据集实施前后各做 3 轮、每轮精修 20 个框的人工计时，记录中位耗时和额外相机操作数到本计划 Outcome；功能发布门不伪造一个尚无基线的百分比承诺。

## 10. 风险与化解

| 风险                                               | 化解                                                                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 浏览器双击会先发两个 click，导致选择和聚焦次序竞态 | 保持即时 click 选择；dblclick 只读取最终命中并执行幂等单选 + 聚焦，不引入延迟定时器    |
| 对细长或旋转框取景过紧、near plane 裁切            | 使用尺寸包围球和水平 / 垂直 FOV 的严格距离，加固定比例安全边距并同步 near / far        |
| 触控板高频 wheel 让缩放跳动                        | deltaMode 归一化、方向累计、离散档位和上下限；拖几何时禁用                             |
| 每对象 zoom Map 随访问对象增长                     | 只存 3 个有限数字，生命周期限当前工作台；不进入全局 store 或服务端                     |
| 同 scene 识别错误，把视角带到无关数据              | 只以 manifest `scene_id` 连续；无 scene 时退化为 task key；换 key 走既有首载规则       |
| 预设覆盖用户自定义位置引发意外                     | 预设是显式按钮，只覆盖两棵 3D 面板状态；自由拖动后继续持久化，且任一预设可再次一键恢复 |
| 顶部控件继续变宽                                   | 三个按钮采用现有紧凑控件与 flex-wrap，在两档目标视口做遮挡门禁；不新增常驻大面板       |

最脆弱的产品假设是：近期 3D 用户在“找到对象并把它调准”上花费的时间高于“在长 scene 中找到异常帧”。实施后的现场计时若连续 5 次会话都显示帧定位占主动操作时间超过 40%，则下一份计划优先做只读 scene 时间轴；本版已经完成的交互精修仍保持独立，不临时把时间轴并入。

## 11. 回滚

本版不迁移数据，回滚只撤销前端行为：

- 移除双击聚焦接线和 `focusBox`，主视口恢复单击选择与整帧 reset。
- 去掉 zoom factor 参数和会话 Map，`frameOrtho` 默认值恢复现有固定 margin 取景。
- 去掉 continuity key 分支，`loadPcd` 恢复当前首载行为。
- 移除三套预设按钮；已经写入的 `triViewFloat` / `cameraPanels` 仍是合法旧字段，无需清理。

回滚不能触碰 annotation、scene、用户其他偏好或删除既有布局。若只是一项交互出现问题，按 Phase 独立回滚，不整版撤回无关改进。
