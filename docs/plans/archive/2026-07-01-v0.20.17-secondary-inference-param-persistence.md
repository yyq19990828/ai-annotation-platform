# v0.20.17 · 二次推理:模型变体可选 + 参数持久化

状态：**已落地（v0.20.17）**。两件相关的「二次推理控件」增强合到一版（都作用于 `SecondaryInferenceBar`
的运行前配置、都可复用用户级偏好范式），并顺带修复了悬浮面板宽度不自适应致标签逐字竖排的问题
（两条浮顶面板 `FIELD_LABEL_CLASS` + 标题 + `VariantSelector` 轴标题补 `whitespace-nowrap`）：

1. **模型变体可选**（本版新增能力）——当前几何能力的 `model_variants` **恒取 `default_variants`，用户根本
   没法选权重档位**（series/size 等）；补一个和交互条同款的紧凑变体下拉。
2. **参数持久化**（补 v0.20.13 列为「不做」的偏好）——参数面板调过的值下次记住，不必每次重调。

**依赖 v0.20.13**（`SecondaryInferenceBar` 参数面板）、复用 `VariantSelector` / `useAiToolParamPrefs` 范式。

## 背景

### 变体不可选（新问题，用户反馈）

`buildSecondaryInferencePayload`（`useSecondaryInference.ts:170-172`）对几何能力写死
`model_variants: cap.writeTarget === "geometry" ? (m.default_variants ?? {}) : null`——
二次推理**只能跑 backend 自报的默认权重档位**。而交互条早已给用户 series/size 多轴选择
（`InteractiveToolBar.tsx:266` 的 `<VariantSelector compact>`）。同一批权重、同一套协议，
二次推理却锁死默认，体验不一致：想用大权重复核选中框的车牌、想用小权重快跑，都做不到。

### 参数不持久（v0.20.13 遗留）

v0.20.13 的参数面板（⚙ + `SchemaForm`）参数是**组件内 state**：切框、重挂载即丢，用户每次都从模型
默认重调阈值。高频用同一能力时很烦。

## 关键抓手（已核实，直接复用）

- **变体选择器现成**：`@/components/ml/VariantSelector` 的 `compact` 模式就是交互条内联横排裸下拉
  （`InteractiveToolBar.tsx:266-274`），吃 `supportedVariants` / `variantCombinations` / `defaults` / `value` /
  `onChange`，联动约束（variant_combinations）已内建。二次条直接照搬这套 props。
  - 数据源：选中能力的 `model.supported_variants` / `model.variant_combinations` / `model.default_variants`
    （`MLModelCapability`，`ml-backends.ts:70/75/82`）。无变体轴时 `VariantSelector` 自身返回 null，不渲染。
- **用户级偏好服务端范式** `useAiToolParamPrefs.ts`：存 `User.preferences.ai.*`，debounce 保存，多账户隔离。
  v0.18.31 已把交互后端选择等从 localStorage 迁到服务端（`useInteractiveBackendPref.ts`）——二次推理的
  参数**和变体选择**走同一路子，不要再引 localStorage。
- 读取优先级链现成：**用户偏好 → 模型默认**（参数走 `deriveDefaults`；变体走 `default_variants` → recommended
  → 第一项，即 `VariantSelector` 内建 fallback）。

## 工作项

### WS1 · 变体下拉接入 Bar

- `SecondaryInferenceBar` 对**几何能力**（`writeTarget === "geometry"` 且选中能力有 `supported_variants`）
  在能力下拉右侧挂 `<VariantSelector compact>`，props 取自选中能力的 model。属性能力无变体轴 → 不渲染。
- 组件内维护 `variantByKey`（按 `backendId:modelId` 分桶的 `Record<string, Record<string,unknown>>`），
  初值 = 用户偏好（WS3）→ `default_variants`。
- `buildSecondaryInferencePayload(cap, params?, variants?)` 增第三参：几何能力的 `model_variants` 优先取
  传入 `variants`（用户所选），空则回落 `default_variants ?? {}`；属性能力仍 `null`。改签名 + 现有测试补一例
  「传 variants → payload.model_variants 用它」。

### WS2 · 偏好读写 hook

- 新增 `useSecondaryParamPrefs`（或扩展 `useAiToolParamPrefs`）：读写
  `User.preferences.ai.secondary_by_model`，**按 `backendId:modelId` 分桶**，一个桶同时存该 model 的
  `params` 与 `variants` 两组 KV。debounce 保存，复用现有 preferences API。
- 后端 `User.preferences` 是自由 JSONB，加子键即可，**无需 alembic**。

### WS3 · Bar 接入偏好

- `paramsByKey` / `variantByKey` 初值链：**用户偏好（本 hook）→ 模型默认**。
- 用户在参数面板 / 变体下拉改动 → 除更新组件 state 外，debounce 写回偏好（按 `backendId:modelId`）。
- 「恢复默认」小动作（可选）：一键清该 model 偏好、回落模型默认。

## 风险

- **分桶粒度**：必须按 `backendId:modelId`（非仅 backend），否则同 backend 下检测/分类多 model 的
  参数/变体互相覆盖。与 `useAiToolParamPrefs` 的 backend 粒度并存、互不干扰（不同子键）。
- **变体与项目级 default_variants 的关系**：项目可能已在 `project.default_variants[backend_id]` 配了默认
  （交互条那套优先级）。二次推理的用户偏好定位为「用户在二次条里的临时/常用选择」，缺省回落到
  `model.default_variants`；是否叠加项目级默认，首版**不叠**（避免两套优先级纠缠），仅用户偏好 → 模型默认，
  后续如需对齐交互条再议。
- 偏好 schema 随模型 schema 变化：存自由 KV，模型换 params/variants 时旧键无害忽略，无需迁移。
- 保存失败静默降级（仍用组件内 state），不阻断推理。

## 验收

- 选中几何能力且该 model 有变体轴 → 能力下拉旁出现变体下拉；切档位 → 运行 → payload.model_variants 用所选。
- 属性能力 / 无变体轴的几何能力 → 不出现变体下拉。
- 调某能力的 `score_threshold` 或变体档位 → 跑 → 切走再回来 / 刷新 → 该能力参数 + 变体保留上次值。
- 不同 model 的参数/变体互不串；换设备登录同账户 → 一致（服务端存储）。

## 依赖 / 不在范围

- **依赖 v0.20.13**；复用 `VariantSelector`（compact）与 `useAiToolParamPrefs` 的 `User.preferences` 范式。
- 不做：项目级/团队级共享预设（用户级足够）、参数版本历史、二次推理变体叠加项目级 default_variants（见风险）。
