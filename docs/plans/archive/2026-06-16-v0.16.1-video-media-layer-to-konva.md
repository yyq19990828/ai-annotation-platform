## 1. 背景与目标

### 1.1 本版边界

视频迁 Konva 分四层叠加,本版只做**最底下一层 + 视口**,因为它最独立、可单独用「底图截图 diff」验收,且决定后面所有层的坐标/transform 基准:

- 视频帧上屏:`<video>`(`VideoMediaLayer.tsx:16`)+ 暂停 bitmap(`VideoBitmapLayer.tsx` / `useVideoBitmapCache.ts:53-220`)+ WebCodecs 精确帧(`useVideoChunkDecoder.ts:126-150`,实验)→ 统一进 `Konva.Image`。
- 视口变换:CSS `transform: scale translate`(`VideoStage.tsx:20` VideoStageSurface)→ Konva Stage `scaleX/Y/x/y`(抄 `ImageStage.tsx:950-957`)。
- 坐标:归一化 `[0,1]×[0,1/aspect]` + SVG CTM(`videoStageCoordinates.ts:47-71`)→ 像素空间 + Konva 逆变换(抄图片 `toImg()`),视频固有宽高当 `imgW/imgH`。

### 1.2 flag 并行策略

- 新增 dev flag(沿用 `experiment` 粘性范式,参考 `useVideoChunkDecoder` 的 `WEBCODECS_FLAG_STORAGE_KEY` localStorage 模式):`experiment.videoKonva`。
- `WorkbenchStageHost.tsx:390-429` 的 video 分支按 flag 渲染旧 `VideoStage`(默认)或新 `VideoKonvaStage`(opt-in)。
- 本版新栈只有底图层可用、标注/交互尚缺,**仅供开发态视觉对照**,不作生产默认。

### 1.3 成功判据

1. flag 开 → 新栈显示视频底图,播放/逐帧/暂停精确帧与旧栈**逐帧像素一致**(Playwright 截图 diff,容差内)。
2. 缩放(滚轮 + FloatingDock 按钮)、平移、fit-to-canvas、双击复位行为与旧栈一致;复用 v0.16.0 公共 viewport 原语。
3. flag 关 → 完全走旧栈,零行为变化(回退保证)。
4. 播放态帧率符合 v0.16.0 spike 设定阈值(A1 路径);暂停态走 bitmap 缓存不重绘。
5. `pnpm test` 全绿(含本版新增的媒体层 konva-mock 测试 + 坐标换算纯函数测试)。

## 3. 设计要点

### 3.1 `Konva.Image` 的帧源(按 spike 结论)

- **A1(帧合成,推荐路径)+ 分层**:视频底图独占一个 `media-bg` Konva Layer(独立 canvas),`Konva.Image` 的 `image` 指向**隐藏的 `<video>` 元素**(仍负责解码,不再是显示面);`Konva.Animation` 在 `isPlaybackActive` 时每帧只 `mediaLayer.batchDraw()` blit 当前帧——**标注层(v0.16.2 起)在另一 Layer,播放时静止不重绘**;暂停时停动画、把 `useVideoBitmapCache` 的精确 `ImageBitmap` 设为 image source 画一次。
- 暂停态(标注主力场景)**不进重绘循环**,沿用 bitmap 缓存;播放态也只重绘视频层不动标注层——这是 perf 的两手关键规避(v0.16.0 spike 已据此验证)。
- **A2(降级,若 spike 不达标)**:`<video>` 仍 DOM 显示,Konva Stage 透明叠加;此时本版要把 Konva Stage transform 与 `<video>` CSS transform 双向同步(ADR 已记契约)。两条路在 `VideoKonvaMediaLayer` 内分支,由 flag/常量切。

### 3.2 坐标:像素空间替代 CTM

- 视频固有宽高 `videoIntrinsicW/H`(从 `<video>.videoWidth/Height` 或 manifest)当作 `imgW/imgH`,标注归一化坐标 `× imgW/H` 得像素坐标(与图片 `b.x*imgW` 同构,`ImageStageShapes.tsx:241`)。
- 屏幕↔世界用 Konva Stage 的 `getRelativePointerPosition()` / 逆变换,替代 `clientToSvgWithDom`/`clientToSvgWithRect` 两套 fallback(`videoStageCoordinates.ts:10,31`)。
- 存储仍归一化,**数据零迁移**(epic 红线①)。

### 3.3 视口复用 v0.16.0 公共件

- `fit.ts(vpSize, {w:imgW,h:imgH})`、`zoom.ts(cursor, delta, stepFactor, [0.2,8])`、`scaleCancel.ts` 直接调,行为与图片对齐。
- 删除 VideoStageSurface 的 CSS transform 路径(仅在新栈内;旧栈保留)。

### 3.4 不动的东西

- 解码链路(`useVideoChunkDecoder`/`useChunkSamples`/`videoChunkDemux`)、bitmap 缓存 LRU、播放控制/时间轴/Minimap/PlaybackOverlay——全是 Stage 兄弟 DOM 或纯逻辑,本版不碰。

## 5. 已知风险 / 未尽事项

- **A1 播放重绘抖动**:若实际数据比 spike 重,降级 A2;flag 让两栈共存,不阻塞。
- **WebCodecs 实验路径 × Konva**:精确帧 VideoFrame → Konva.Image 需确认 `createImageBitmap(VideoFrame)` 或直接作 image source 的兼容;实验 flag 叠加实验 flag,文档写清组合矩阵。
- **高 DPR 屏**:Konva 的 `pixelRatio` 与视频固有分辨率换算要核对,避免底图模糊或过采样;对照图片 stage 的 DPR 处理。
- **截图 diff flaky**:视频帧解码时序导致抓帧不稳;基线固定到「暂停指定帧」而非播放中抓帧。

## 6. 验证策略

- **纯函数测**:`videoKonvaCoordinates` 归一化↔像素往返、clamp 边界;viewport 复用件已在 v0.16.0 测过。
- **konva-mock 组件测**:媒体层在 mock 下断言 `Konva.Image` 收到正确 image source / 尺寸 props;播放/暂停切换断言重绘开关。
- **Playwright 对照**:同一视频同一帧,新旧栈截图 diff;缩放到 2×/fit 后再 diff。
- **回退测**:flag 关确认走旧 `VideoStage`,旧测试全绿。
