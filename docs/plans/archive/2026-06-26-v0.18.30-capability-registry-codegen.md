## 0. 动机 / 缺口(源码核对)

后端 registry 是 SSOT(`capability_registry.py`),但前端把它**手抄了好几份**,后端改了不同步 → label 不一致 / 新增值前端不认:

| 前端手抄 | 位置 | 应同源于 |
|---|---|---|
| task→中文 label(模型市场) | `ModelMarket/capability/labels.ts:47 taskLabel`(+ `infraLabel`/`modalityLabel`/`geometryLabel`) | `TaskSpec.label` 等 |
| task→中文 label(**第二份**,工作台) | `Workbench/shell/InteractiveToolBar.tsx:84 modelTaskLabel` | 同上 |
| prompt 受控词表(交互线) | `useBackendRouting.ts:17 INTERACTIVE_PROMPTS` | `PROMPTS.interactive_route`(v0.18.29) |
| prompt 受控词表(fallback) | `useMLCapabilities.ts:21 FALLBACK_PROMPTS` | `PROMPTS.requires_input` |
| 工具→prompt 判定 | `useWorkbenchShellModel.helpers.ts:128 promptOfTool` | 同上 |

`labels.ts` 与 `modelTaskLabel` 是**两份独立的 task→label 中文映射**,后端 `TaskSpec.label` 是第三份真值。

## 1. 目标 / 非目标

**目标**
- 后端导出 `capability-registry.snapshot.json`(提交进 git),**镜像 `openapi.snapshot.json` 链路**(导出脚本 + pre-commit 重导 + CI `--check` 防漂移)。
- 前端从 snapshot codegen 出 `capabilityVocab.gen.ts`(值数组 `as const` + union 类型 + 元数据 record + prompt 派生集合 + label 辅助)。
- 全量迁移上表 5 处手抄到生成物。
- `GET /v1/ml-capabilities/protocol` 顺带对外暴露 `prompts`(协议增强,前端运行时消费方与 codegen 同源)。

**非目标**
- 不改 registry 数据(PROMPTS 表已在 v0.18.29 加;本版只搭管道 + 迁移消费方)。
- 不动 OpenAPI codegen(这是**第二条独立管道**,复用模式、不复用配置)。
- 生成物 `capabilityVocab.gen.ts` 不进 git(gitignore,同 `src/api/generated/`)。
- 不做运行时拉 `/protocol` 替换静态常量(codegen 出静态值即可;`/protocol` 暴露 prompts 仅供已有运行时消费方/契约对齐)。

## 3. 设计与改动

### 3.1 后端

1. **`ProtocolCapabilitiesResponse` 加 `prompts`**(`schemas/ml_capabilities.py`):新增 `ProtocolPromptItem(id, label, summary, requires_input: bool, interactive_route: bool)`;响应加 `prompts: list[ProtocolPromptItem]`。
2. **`_build_payload()`**(`api/v1/ml_capabilities.py:42`)补 `prompts=[ProtocolPromptItem(...) for p in PROMPTS]`(PROMPTS = v0.18.29 新增的受控表)。`GET /protocol` 自动随之暴露 prompts。
3. **`scripts/export_capability_registry.py`**(镜像 `export_openapi.py`):import `_build_payload`,`payload.model_dump(mode="json")` → `json.dumps(..., indent=2, sort_keys=True, ensure_ascii=False)` 写 `apps/api/capability-registry.snapshot.json`;`--check` 模式比对不一致即非零退出。**不依赖 DB/app 启动**(registry 是纯模块常量,比 openapi 导出更轻——无需 `app.openapi()` 全量构建,直接调 `_build_payload`)。

### 3.2 前端 codegen

4. **`apps/web/scripts/gen-capability-vocab.mjs`**:读 `../api/capability-registry.snapshot.json` → 字符串模板生成 `src/api/generated/capabilityVocab.gen.ts`,内容:
   ```ts
   // AUTO-GENERATED from apps/api/capability-registry.snapshot.json — do not edit.
   export const TASK_IDS = ["detection","obb",...] as const;
   export type TaskId = (typeof TASK_IDS)[number];
   export const TASKS: Record<TaskId, { label: string; summary: string;
     defaultGeometry: string[]; defaultModalities: string[] }> = { detection: {...}, ... };
   // infra / modality / geometry 同构
   export const PROMPT_IDS = [...] as const;
   export type PromptId = (typeof PROMPT_IDS)[number];
   export const INTERACTIVE_ROUTE_PROMPT_IDS = [...] as const; // p.interactive_route
   export const REQUIRES_INPUT_PROMPT_IDS = [...] as const;    // p.requires_input
   // label 辅助(带 unknown fallback,复刻 labels.ts 现有语义)
   export function taskLabel(id: string): string { return (TASKS as any)[id]?.label ?? id; }
   ```
   输出后跑 prettier(复用 `openapi-ts` 的 `format: "prettier"` 思路,或脚本内 `prettier --write`)。
5. **串接 `pnpm codegen`**(`apps/web/package.json`):`"codegen": "openapi-ts && node scripts/gen-capability-vocab.mjs"`。
6. **`codegen-if-changed.mjs`**:`generated` 目标除 `types.gen.ts` 外加查 `capabilityVocab.gen.ts`;`snapshot` mtime 比较加 `capability-registry.snapshot.json`(任一新于产物即重跑)。

### 3.3 消费方迁移(全量,机械)

7. **三份 task→label map 的处理(裁定)**:实测前端有**三份措辞各异的 UI 定制 label**——`labels.ts`(ModelMarket 短称: 检测/分割/分类)、`InteractiveToolBar.MODEL_TASK_LABELS`(工作台: 旋转框检测/文字识别/视频追踪)、后端 registry(全称: 目标检测/实例分割)。**label 是各 UI 上下文的展示文案, 非漂移真值, 不统一其值**(强统一会改多处 UI 文案 = regression)。codegen 的价值落在**用生成的 `TaskId` 类型收紧这些 map 的 key**(`Record<TaskId, string>` 替 `Record<string, string>`): 后端新增 task 时这两处 TS 报错提示补全、且 key 不会拼错 id。各 map 的 label 值原样保留, UI 零变化。
8. **prompt 三处(核心, 无 UI 风险)**:`useBackendRouting.ts:17 INTERACTIVE_PROMPTS`、`useMLCapabilities.ts:21 FALLBACK_PROMPTS`、`promptOfTool` + `TOOL_REGISTRY` prompt 判定,全部 import 生成物 `INTERACTIVE_ROUTE_PROMPT_IDS`/`REQUIRES_INPUT_PROMPT_IDS`/`PROMPT_IDS`,删本地副本(**承接 epic §B-前端**,epic 原 v0.18.30 契约测试方案作废)。这是消除「后端上 scribble 前端不认」静默失败的核心。

## 4. 防漂移(三道闸)

- **pre-commit**`regen-capability-registry-snapshot`:改 `capability_registry.py`/`schemas/ml_capabilities.py` 时自动重导 + `git add`(提交即修复,同 `regen-openapi-snapshot`)。
- **CI**`test_capability_registry_contract.py`:`export --check`,snapshot 与当前 registry 序列化不一致即红灯(防作者忘了重导)。
- **前端生成物 gitignore + prebuild 自动生成**:`capabilityVocab.gen.ts` 永远跟 snapshot,无需前端契约测试(snapshot 即真值,机器生成无法写错)——这正是 codegen 比「手抄 + 契约测试」更强之处。

## 5. 测试 / 验收

- 后端:`export --check` 在 registry 改动后失败、重导后通过;snapshot 含 `prompts` 段;`GET /protocol` 返回 `prompts`。
- 前端:删 `src/api/generated` → `pnpm codegen` 重生成 `capabilityVocab.gen.ts`;消费方编译通过;模型市场 + 工作台 task/infra/geometry 中文 label 渲染**不变**(回归)。
- **漂移演练**:registry 加一个 task 但不重导 → CI `--check` 红;重导提交 → 前端 build 自动出现新 label,无需手改任何前端文件。

## 6. 风险

- **label 是 UI 定制、非真值(已实测裁定)**:前端三份 task→label map 措辞各异(ModelMarket 短称「检测/分割/分类」/ 工作台「旋转框检测/文字识别/视频追踪」/ 后端全称「目标检测/实例分割」), 确为有意 UI 定制。裁定: codegen **不统一 label 值**(避免改 UI 文案), 只用生成的 `TaskId` 类型约束各 map 的 key(防新增 task 漏配 / id 拼错)。codegen 真正消除的漂移是 **prompt 逻辑集合**(interactive_route / requires_input)与 **ID / 结构元数据**, 非展示文案。
- **本地开发时序**:改 `capability_registry.py` 后若没重导 snapshot,`codegen-if-changed` 靠 mtime 不会触发前端更新 → 本地看到旧值。**pre-commit 是关键防线**;DEV 文档要提示「改 registry 后跑 export 或依赖 pre-commit」。
- **两条 codegen 的认知成本**:`DEV.md` / `docs-site/dev` 标明两条管道(openapi 类型 + registry 词表)各自职责与触发,避免后人混淆。
- **`ensure_ascii=False` + 排序稳定性**:导出 JSON 用 `sort_keys=True` + 固定缩进,保证 snapshot diff 稳定(同 `export_openapi.py`)。

## 9. 实施记录 / scope 调整（v0.18.30 落地）

实施中两处依实测裁定收窄,记录于此:

- **label map 不加类型约束(3b 降级)**:原计划用生成的 `TaskId`/`InfraId` 收紧三份 label map 的 key。实测 `labels.ts` 的 `INFRA_LABELS` 含 `unknown`、`MODALITY_LABELS` 含 `text`/`point_cloud`——均为受控词表**之外**的运行时兜底/预留值(`unknown` 由 `_normalize_infra` 产出; `text`/`point_cloud` 是 registry 注释标注的预留语义)。`Record<InfraId,…>` 严格约束会因这些额外 key 报错且缺 `lidar`。只有两份 task→label map 的 key 正好等于受控集合, 但单独约束 task 一类会引入 `string` index `Record<TaskId>` 的 `as` cast 噪音且三类不一致。故本版 **label map 保持现状(UI 定制文案)**, codegen 已提供 `TASKS`/`PROMPTS` 等数据供未来按需消费。
- **`FALLBACK_PROMPTS` 保留**:`useMLCapabilities.ts` 的 `FALLBACK_PROMPTS = [point, interactive_box, text]` 是「老 backend 缺 `supported_prompts` 时的业务兜底默认」, 非受控词表子集(不对应任何 registry 派生集合), 不迁移。

**本版实际交付**:snapshot 导出脚本 + 前端 codegen 管道 + 三道防漂移闸(pre-commit / CI contract / prebuild) + `GET /protocol` 暴露 prompts + `useBackendRouting.INTERACTIVE_PROMPTS` 贯通生成物(真漂移源)。核心目标(管道基建 + prompt 受控词表贯通)达成。
