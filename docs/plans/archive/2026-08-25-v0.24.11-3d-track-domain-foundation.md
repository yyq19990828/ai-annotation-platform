## 1. 推荐结论

推荐建立 Scene 级 Track 聚合、存在区间与可逆命令日志，再交付轨迹终结。当前 `Annotation.track_id` 继续作为通用成员身份键和旧客户端查询合同；新增领域层负责轨迹级类别、属性、revision、多个存在区间与修复操作。

该方案改动数据库、所有 3D Track 写路径、Scene 时间轴、跨帧任务中心、导出和测试，不是小版本补丁。它能避免终结、缺席、恢复、拆分、合并、3D Quality 和多模态对象分别推导轨迹状态。

## 2. 当前事实

- ADR-0045 把 `Annotation.track_id` 定为跨几何类型的身份权威键，但没有 Track 表、轨迹级 revision 或存在区间。
- 3D Scene 的一条轨迹由多个 task 下的 Annotation 聚合。类别、首末帧、成员数和冲突每次查询时临时计算。
- split/merge 已有候选、预览、snapshot token、权限复核、确定锁序和原子改写，可以作为统一命令合同的原型。
- `Annotation.source` 表达来源，不足以区分人工关键帧、系统派生帧和无法判断角色的存量帧。
- `AnnotationOperation` 当前是 Task 级 Mask/转换操作账本，kind 与 lineage relation 有严格枚举。把 Scene Track 命令硬塞进去会扭曲其作用域。
- Scene 时间轴、可信 LiDAR 导出和 Data Manager 已依赖活跃 Annotation；引入存在区间时必须同步更新，不能只改工作台 UI。

## 3. 领域不变量

### 3.1 身份与作用域

- 一条 3D Scene Track 必须属于一个 project 和一个 Scene。
- `track_id` 在新 3D Scene Track 中稳定且唯一；Annotation 的 `scene_track_id` 与 `track_id` 必须指向同一 Track。
- Track 类别是轨迹级真值。成员类别漂移属于非法状态，迁移 verifier 报告但不猜测修复。
- 图片单帧 Annotation 与现有 compact video track 暂不要求创建 Scene Track。

### 3.2 存在区间

- 区间为闭区间，按 frame 排序，同一 Track 内不得重叠或首尾相邻。
- 一条 Track 可有多个区间，支持缺席后恢复。
- `retired_at` 表示整个身份被逻辑删除，不等于某个时间点开始缺席。
- 活跃 3D Annotation 必须落在一个存在区间内；不在区间内的成员必须停用或拒绝写入。

### 3.3 时间角色

- `keyframe`：用户明确创建、修改或确认的时间锚点。
- `derived`：插值、传播、跟踪或其它可重算结果。
- `sample`：导入或历史数据无法可靠判断关键帧语义的兼容成员。
- source 与 temporal role 相互独立。接受模型候选后可以是 `source=prediction_based` 且 `temporal_role=keyframe`。

### 3.4 命令与撤销

- 所有命令先预览，再携带 Track、interval、Annotation version 快照执行。
- 操作必须有幂等键、完整 before/after 摘要和 inverse payload。
- 只有相关 Track 在目标操作后没有新 revision 时才允许撤销。
- 撤销本身也是新 operation，不删除历史操作记录。

## 4. 推荐 Schema

### 4.1 `scene_tracks`

建议字段：

```text
id UUID PK
project_id UUID FK
scene_id UUID FK
track_id VARCHAR(64)
class_name VARCHAR(100)
presence_mode inferred | explicit
attributes JSONB
attributes_meta JSONB
revision INTEGER
created_by UUID NULL
retired_at TIMESTAMPTZ NULL
created_at / updated_at
```

约束与索引：

- `UNIQUE(project_id, scene_id, track_id)`。
- `presence_mode=inferred` 表示保守成员包络；命令或无损区间导入后切换为 `explicit`，缺席帧不得被普通传播静默扩展。
- `revision >= 1`。
- project 必须与 Scene 所属 Dataset/项目关系一致，由 service 与迁移 verifier 检查。
- `(scene_id, class_name, track_id)` 索引服务时间轴、候选和质量查询。

### 4.2 `scene_track_intervals`

建议字段：

```text
id UUID PK
scene_track_id UUID FK
start_frame INTEGER
end_frame INTEGER NULL
source VARCHAR(30)
version INTEGER
created_by UUID NULL
operation_id UUID NULL
created_at / updated_at
```

约束：

- `start_frame >= 0`，`end_frame IS NULL OR end_frame >= start_frame`。
- 固定长度 Scene 不接受超过末帧的区间。
- PostgreSQL exclusion constraint 或同等级事务锁保证区间不重叠；service 再合并相邻区间。
- 每次区间变化递增 Track revision。

### 4.3 `annotations.temporal_role`

新增非空列，允许 `keyframe / derived / sample`。回填规则必须保守：

- `source=interpolated` 回填 `derived`。
- 其它历史记录回填 `sample`，不能因 `source=manual` 自动认定为关键帧。
- 新人工创建或几何修改写 `keyframe`。
- 插值、传播、跨帧 job 写 `derived`；用户显式确认后转为 `keyframe`。

### 4.4 `annotations.scene_track_id`

新增 nullable UUID 外键，`ON DELETE SET NULL`：

- 3D Scene 中具有 `track_id` 的 `box_3d` 成员必须同时关联一个 SceneTrack。
- 图片、compact video track 和尚未通过迁移 verifier 的异常历史链保持 NULL。
- `track_id` 继续冗余用于旧客户端、导入导出和跨版本查询；service 和诊断器验证外键所指 Track 的外部键、project、scene 与 class 全部一致。
- 新 3D 成员先解析或创建 SceneTrack，再写 Annotation，不能在提交后异步补外键。

### 4.5 `scene_track_operations`

建议字段：

```text
id UUID PK
scene_id UUID FK
actor_id UUID
kind VARCHAR(30)
idempotency_key VARCHAR(128)
request_digest VARCHAR(64)
snapshot_token VARCHAR(64)
source_revisions JSONB
result_revisions JSONB
before_state JSONB
after_state JSONB
inverse_payload JSONB
status committed | reverted
reverted_by_operation_id UUID NULL
created_at / completed_at
```

第一组 kind：`split / merge / mark_absent / resume / terminate / revert`。外键和 JSONB 只保存可重建、可审计的数据，不存点云或完整 geometry blob；逐帧 Annotation 的前后版本由现有历史与明确 ID 列表关联。

## 5. 权威关系

```text
SceneTrack
  ├─ class / track attributes / revision
  ├─ PresenceInterval [0..N]
  └─ Annotation member [0..N] via scene_track_id
       ├─ track_id / geometry / source / temporal_role / version
       └─ task -> dataset item -> scene frame

TrackCommand
  ├─ preview(snapshot)
  ├─ lock Track + intervals + annotations
  ├─ validate current revisions
  ├─ mutate intervals / member state / identity
  └─ operation journal + audit
```

- Track 是身份、类别、区间和轨迹级属性的权威来源。
- Annotation 是某帧几何、来源、成员属性和版本的权威来源。
- 区间决定对象是否存在；Annotation 缺口不自动等于缺席。
- `scene_track_id` 是新 3D Scene 成员关系的权威外键；`track_id` 继续冗余在 Annotation 上，保证现有查询与导出兼容。双写 verifier 阻止漂移进入发布。

## 6. 回填与迁移

### 6.1 预检

迁移前以 `(project_id, scene_id, track_id)` 扫描所有活跃 `box_3d`：

- 无 Scene、跨 Scene、重复 frame、类别漂移、非法 `track_id` 单独报告。
- 无异常链才创建 Scene Track；异常链保持旧路径，不阻塞数据库迁移，但新命令不可用。
- 报告包含稳定 code、计数和有限样例，不输出 geometry。

### 6.2 回填

- 每条合法历史链创建一个 Scene Track。
- 存在区间先使用 `[min(member_frame), max(member_frame)]` 的 `legacy_envelope`。历史成员缺口继续表示“范围内缺标或未物化”，不能自动解释为缺席。
- Annotation temporal role 按第 4.3 节保守回填。
- 回填写入 `scene_track_id` 与 temporal role，不修改 geometry、track_id、source、is_active 或 version。

### 6.3 双写阶段

以下路径必须一起覆盖：

- Annotation 创建、更新、删除与恢复。
- 单条和批量传播、区间插值。
- 3D 跨帧任务结果接受。
- split/merge。
- 导入、AI 接受和任何能生成 `box_3d + track_id` 的内部路径。

诊断端点按 Scene 返回 Track 与旧 Annotation 聚合的差异。双写门未清零前，不能让生命周期命令进入普通用户界面。

## 7. 用户命令语义

### 7.1 标记缺席

- 用户选择缺席起点，并可选恢复帧。
- 操作缩短或拆分存在区间，区间内 derived 成员停用。
- 区间内存在 keyframe 或 sample 时，预览列出冲突；第一版要求显式确认保留为隐藏历史，不静默删除。

### 7.2 恢复

- 在缺席区间内指定恢复帧，创建新存在区间。
- 当前帧必须有 keyframe，或用户同时从相邻 geometry 创建一个新 keyframe。
- 恢复同一 Track 与创建新 Track 是两个动作，UI 不根据帧间隔猜测。

### 7.3 终止

- 终止关闭包含当前帧的最后一个存在区间，不创建后续区间。
- 未来既有成员按 temporal role 分组预览；执行后停用并记录精确 inverse。
- 终止不重写 `track_id`，不删除 Track，不影响历史成员。

### 7.4 拆分与合并

- 保留现有 survivor、类别一致、无同帧冲突和成员上限语义。
- 拆分同时切分区间、迁移成员并创建新 Track。
- 合并同时合并区间；重叠或相邻区间按成员冲突和存在规则验证。
- 原 API 可兼容一版，内部转到统一 command service。

### 7.5 撤销

- UI 默认只提供最近一次相关 Track 操作的撤销。
- 任一受影响 Track、interval 或 Annotation 在操作后变化，撤销返回 stale，并显示需人工修复的原因。
- 撤销 split/merge 恢复原身份和区间；撤销缺席/终止恢复原成员 active 状态与区间。

## 8. API 草案

```http
GET  /api/v1/tasks/{task_id}/scene-tracks/{track_id}
POST /api/v1/tasks/{task_id}/scene-track-commands/preview
POST /api/v1/tasks/{task_id}/scene-track-commands/execute
POST /api/v1/tasks/{task_id}/scene-track-commands/{operation_id}/revert
GET  /api/v1/tasks/{task_id}/scene-track-commands?track_id=...
GET  /api/v1/tasks/{task_id}/scene-track-diagnostics
```

详情响应包含 Track revision、类别、轨迹级属性、存在区间、按 temporal role/source 汇总的成员、异常 code 和允许命令。默认不返回所有 geometry，点击区间后再用现有 Annotation API 按帧窗口加载。

## 9. 前端

Scene 时间轴：

- 色带只表示存在区间，成员密度和 keyframe 另用标记。
- 缺席区间为空，Track 恢复后出现第二段色带。
- keyframe、derived 和 sample 使用不同 marker，不用颜色同时承担来源与角色。

跨帧任务中心：

- “轨迹修正”升级为“轨迹生命周期”。
- 详情先展示区间、关键帧、来源和异常，再展示可用命令。
- 每个命令复用同一个 Preview 结构：范围变化、成员影响、锁定或权限冲突、撤销条件。
- 成功后刷新 Track detail、Annotation、Scene 时间轴和候选；刷新失败时保留 operation id 供恢复查询。

## 10. 质量与多模态接口

- 3D Quality Issue 保存 `scene_track_id + track_revision`，断点规则以存在区间为范围，不把明确缺席报成漏标。
- 时序跳变只比较同一存在区间内的相邻可信成员。
- 未来相机人工 2D member 关联 Scene Track，并独立保存 sensor context 与 revision。
- Quality 只能建议 `scene-track-command`，首版仍需用户预览与确认。

## 11. 实施切片

### M1：ADR、Schema、回填与 verifier

交付 Track、interval、temporal role、operation 表与迁移；生产路径保持旧读，先证明回填无损。

### M2：双写、详情 API 与影子读

覆盖所有 3D Track 写路径，时间轴在诊断开关下读取新模型并与旧聚合对账。

### M3：统一 split/merge 命令

把已发布能力迁入 command journal，保持 API 兼容并增加精确撤销。

### M4：缺席、恢复与终止

交付完整用户流程、成员停用与 inverse，普通用户界面切换到新 Track read model。

### M5：下游、浏览器和发布门

统一 Data Manager、导出、质量 locator、文档和 nuScenes mini E2E；关闭旧聚合诊断差异后才允许发版。

五个切片属于同一候选版本，但每个切片单独可迁移、可测试、可回滚：M1 只增加影子模型，M2 只增加双写诊断，M3 保持旧 API 兼容，M4 才开放新用户命令，M5 关闭发布门。M1/M2 没有通过时不得开发 M4 的普通用户入口。

## 12. 验收矩阵

### 数据与迁移

- 空数据库、合法链、单帧链、跨帧缺口、类别漂移、重复帧、跨 Scene 污染。
- 迁移前后 Annotation 数、geometry hash、track_id、source、active 与 version 一致。
- downgrade 只在尚无新 Track command 时允许；已有新领域数据后采用前滚修复，不丢审计。

### 性质测试

随机生成 `mark_absent/resume/terminate/split/merge/revert` 序列，持续验证：

- 区间有序、不重叠、不相邻。
- 活跃成员都在一个区间内。
- Track 类别与成员类别一致。
- revision 单调递增。
- 成功 revert 恢复执行前的成员身份、active 状态和区间。

### 权限与并发

- Scene 内任一成员 task 不可见、不可编辑或 annotation 锁定时，整次命令拒绝。
- preview 后新增成员、修改 geometry、调整区间或执行第二个命令，旧 snapshot stale。
- 相反顺序的 merge、terminate 与传播并发只能有一个成功，不形成 phantom member。
- 长 Scene 超出事务预算时明确拒绝或转异步，不能静默截断。

### 前端与浏览器

- nuScenes mini 构造出现、暂时缺席、恢复、终止、撤销、拆分与合并完整流程。
- 刷新页面后区间、marker、成员计数和最近操作一致。
- 终止预览清楚区分 keyframe、derived、sample 和不可修改成员。
- 操作成功但刷新失败时可按 operation id 恢复结果，不重复执行。
- 全流程无 console error、无永久 loading、无旧帧几何闪回。

## 14. 回滚

- M1/M2 阶段可关闭新读路径，停止双写并保留 Track 表，不删除已回填数据。
- 普通用户命令上线后，回滚只隐藏入口并恢复旧读；已提交 operation 与 interval 保留只读。
- 不允许通过删除新表回滚已经执行的缺席、终止、拆分或合并。需要用 operation revert 或前滚修复恢复真值。

## 15. 转定稿专项检查

- 新 ADR 与 ADR-0045 的关系必须写清：`track_id` 仍是成员身份键，Scene Track 新增轨迹级权威状态。
- 重新扫描所有 `Annotation.track_id` 写入点，不能依赖本草案的文件快照。
- 核对 `AnnotationOperation`、AuditLog 和 Annotation History，决定 journal 复用哪些基础函数，避免复制安全合同。
- 在 dev nuScenes mini 上统计最长 Track、成员数、缺口和类别漂移，确认同步事务上限。
- 先证明 Data Manager、可信导出和 Scene 时间轴遵守存在区间，再开放终止操作。
- 实施中若当前源码与本文合同冲突，先更新 ADR 和本计划，再继续写代码，不能静默缩小范围。
