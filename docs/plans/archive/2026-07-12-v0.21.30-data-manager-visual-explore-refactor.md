## 1. 背景与现状痛点

data-manager 目前是一个**结构完整、但"数据库表格"气质偏重**的界面:

- 三个 lens(任务 / 对象 / 轨迹)顶部 Tab 切换;左 210px 视图侧栏 + 右主区,**固定两栏、不可拖拽**。
- 任务 lens 用**原生 `<table>` + offset 翻页**(PAGE_SIZE 50);对象/轨迹 lens 用 **react-virtual 虚拟滚动 + cursor 无限加载**(PAGE_SIZE 100)——两套实现。
- 首屏只有 5 格 KPI strip,**完整的图表 + 聚合分布藏在右侧"统计"抽屉**里。
- 筛选靠 chip + popover **逐条编辑**;图表是**只读**的。
- **整个界面看不到一张图 / 一帧画面 / 一个框**——对标注平台是最反直觉的缺口。
- `ProjectDataManagerPage`(任务 lens)与 `EntityDataManagerLens`(对象/轨迹 lens)**各自实现了一遍**视图栏 / header / 保存逻辑,骨架高度重复。

三个方向的核心命题:
- 🅰 让"看得见数据"——缩略图网格 / 画廊 + 对象裁图。
- 🅱 让"分析可操作"——图表可点即筛,分析从抽屉搬到台前。
- 🅳 让"改一处生效"——抽公共骨架、统一表格、可折叠侧栏。

---

## 2. 目标与非目标

### 目标
1. data-manager 至少一个 lens 提供**缩略图/画廊视图模式**,让用户不进工作台就能肉眼扫数据质量。
2. 图表柱子**可点击 → 加一条筛选**,分析与查询形成闭环。
3. 完整聚合分析**可在首屏展开**(不必开抽屉)。
4. 三个 lens 共享**一套公共骨架**,任务表格与对象/轨迹表格统一为**同一套虚拟表格**。
5. 全程遵守项目前端色彩规范(shadcn 语义类 / `--sc-*`,dark 模式成对),URL 即状态、深链不破。

### 非目标
- 批量动作 / 工作流(另立 epic)。
- 点云 BEV 真缩略图渲染(本轮纯点云用占位图,不新建渲染管线)。
- 修改后端聚合口径 / 新增分析指标(除 🅱 里明确的 confidence filter 字段可选项)。

## 3. 关键可行性结论(探查已固化,避免重复踩坑)

### 🅰 媒体 / 缩略图
| 模态 | 能否拿到可展示缩略图 | 端点 / 字段 | 后端改动 |
|---|---|---|---|
| 图像 | ✅ 直接可用 | `DataManagerTask.thumbnail_url` + `blurhash`(基类 `TaskResponse` 已有字段) | 见 A0 待确认项 |
| 视频帧 | ✅ 首帧 poster | 同上(导入时已生成 poster→thumbnail) | 见 A0 |
| 点云+多相机 / scene | ⚠️ 相机参考图降级 | `GET /tasks/{id}/point-cloud/manifest` → `cameras[].image_url`(相机图 item 自带缩略图) | 建议 manifest 透出相机 `thumbnail_url` |
| 纯点云 / 无相机 lidar | ❌ 无 2D 预览 | 无 | 降级图标占位 |
| 对象裁图(bbox 小图) | ⚠️ 几何可拿,无现成 crop 端点 | 几何:`GET /tasks/{id}/annotations`→`geometry`;原图:`file_url` | 前端 canvas 裁可零后端起步;批量/mask/旋转框建议新增 crop 端点(复用 `workers/roi.py`) |

- 基建齐备:后端缩略图 = 256px WEBP q80 + blurhash 4×3;预签名 URL 默认 1h、对齐 10 分钟网格(可命中浏览器缓存、批量加载友好)。
- 前端可复用:`apps/web/src/components/Thumbnail.tsx`(blurhash 占位 + lazy + error 回落)、`BatchCardGrid.tsx`(缩略图网格样板)。

### 🅱 图表 → 筛选映射
- 图表数据项已携带**原始筛选 key**:`DataManagerCharts.tsx:57-69` 的 `rows()` 产出 `{ key, name, value }`,`key` 是未本地化的枚举/ID。**点柱子拿 filter value 在数据层已具备,无需改数据结构。**
- recharts `^3.8.1` 的 `<Bar>` 支持 `onClick`,回调可取 datum(含 `key`)。
- summary/facets 各分布都是 `Record<stableKey, count>`,key = 状态枚举 / source / class_name / tool_unit_id / annotation_type / model_version。

**逐维度"能否点选筛选"结论:**

| 图表维度 | 筛选 field | 操作符 | 可点选 |
|---|---|---|---|
| 任务状态 | `task.status` | `eq` | ✅ |
| 标注/对象/轨迹来源 | `annotation.source` | `eq`(注意 `operators[0]` 是 `exists`,必须显式 `op:"eq"`) | ✅ |
| 标注/对象类别 | `annotation.class_name` | `eq` | ✅ |
| 几何类型 | `annotation.annotation_type` | `eq` | ✅ |
| 工具单位 | `annotation.tool_unit_id` | `eq` | ✅(当前未画成图) |
| 待审模型版本 | `prediction.model_version` | `eq`(`"未标记"` = null 占位,不可点) | ✅ |
| **待审置信度桶** | 无 confidence filter 字段 | — | ❌ 图表可看不可点 |
| **轨迹质量异常** | 无 filter 字段(仅计数列) | — | ❌ 图表可看不可点 |
| kind_metrics 模态标量 | — | — | ❌ 非分布 |

- 状态注入入口:
  - 任务 lens:`ProjectDataManagerPage.tsx:568` `toggleQuickRule({field, op, value})`——**最贴合**,value 为 string。
  - 对象/轨迹 lens:仿 `EntityDataManagerLens.tsx:777` `onAdd`,但显式 `op:"eq"` + `value: key`(此 lens value 为原生类型)。
- 首屏搬迁约束:整页 `overflow-hidden`,表格靠 `flex-1 min-h-0` 吃剩余高度独立滚动;新分析面板**必须 `shrink-0`**,默认折叠或自带 `max-height + overflow-auto`,否则展开会把表格挤塌。数据流已就绪(summary 随 filterJson 重算、facets 随 filter 重查),点柱子→改 filter→查询刷新→图表自更新,闭环天然成立。

### 🅳 布局重复点
- 两处各写一遍:视图侧栏 + header(标题/统计/刷新/保存)+ 保存/切换视图的 Dialog/AlertDialog 逻辑。
- 表格双实现:任务 = 原生 table(`ProjectDataManagerPage.tsx:823`);对象/轨迹 = 虚拟网格(`EntityDataManagerLens.module.css` + `useVirtualizer`)。

## 4. 方向 🅱：可点的分析(建议最先做——纯前端、低风险、体验立竿见影)

### B0 · 图表视觉重做(美化基线)— ✅ 已实现 v0.21.30
> 触发源:2026-07-12 评审当前 `DataManagerCharts.tsx` 三列横条的观感问题。全部改动集中在 `DataManagerCharts.tsx` 一个文件,与 B1 交叉筛选同一块地。
> **落地状态**:已完成并通过图表单测(2/2)、`typecheck`、`lint:css-tokens`。下列全部要点已实现;B1 交叉筛选(onClick→filter)尚未接线,留待下一步。

- **布局(已定:方案 B 两列)**:`grid gap-4 lg:grid-cols-3` → `lg:grid-cols-2`。三列过挤;单列(一图一行)最宽敞但任务 lens 5 图纵向过长,故取两列折衷。
- **图表方向保持横条**:recharts `layout="vertical"` 即横向柱,**不改竖条**——类别排行用横条,中文/长名(如 `__unknown`)可水平直读;竖条只能斜排/截断。
- **单值不撑满**:给 `<Bar maxBarSize={22}>` 限制柱条厚度,单值分布(如"标注来源=人工")不再在垂直方向被撑满成大色块(截图绿块根因),且四张图统一保持横条风格(实测中占比条方案与其它图风格不一致,已弃用)。
- **hover / 点击不刺眼**:`<Tooltip cursor={false}>` 关闭悬浮时横跨整行的浅灰高亮块(recharts 默认硬编码浅灰,深色下呈白块);`<BarChart accessibilityLayer={false}>` 关闭 recharts 给 svg 加的 `tabindex`,消除点击后触发的全局蓝色焦点描边(无障碍已由 `role="img"` + aria-label 承担)。
- **空图折叠**:无数据的图(如"待审模型版本/置信度")不再占满 `h-40` 一整格,折叠成一行紧凑提示,把垂直空间还给有内容的图。
- **配色去装饰、编码含义**:删除 `series[index % series.length]` 的按图序号轮换(颜色不承载信息、制造噪音)。排行类维度(来源 / 类别 / 模型版本 / 几何类型)统一**单一量级色**;有语义的维度(任务状态)用**固定语义色板**,并与列表 Badge 同色(待标注=蓝 / 标注中=琥珀 / 待审=紫 / 已完成=绿 / 已退回=红),让表格与图表颜色语言一致。
- **数值直标 + 去网格**:柱尾加 `LabelList` 直标数值,随即删掉 `XAxis` 刻度与竖向 `CartesianGrid`,坐标轴/网格退到背景;柱条 `maxBarSize ≤ 24`,圆角只在数据末端(`radius=[0,4,4,0]`)。
- **保留**:Tooltip、`useTheme` 主题联动、`--sc-*` 取色、`role="img"` + aria-label 无障碍文本、Skeleton 加载态。
- **verify**:两列不挤;单来源项目"标注来源"显示占比条而非色块;空图仅一行;任务状态色与列表 Badge 一致;删除竖网格后柱尾数值可读;dark 模式下横条与数值均清晰。

> 通用图表规范(全局适用,非 data-manager 专属):以项目自带 `dataviz` skill 为准——颜色编码含义不按序轮换、永远单 Y 轴、状态色保留不作普通系列、文字用文字色、先选形态(单值→数字/meter、KPI→stat tiles)、细柱+直标+退隐网格。新建任何图表前先读该 skill。

## 7. 依赖关系与建议执行顺序

```
🅱-B0 图表美化  ─┐ (纯前端, 同 DataManagerCharts.tsx, 与 B1 合并做)  ← 最先做
🅱-B1 图表可点  ─┤ (纯前端, 半天~1天, 高价值, 无依赖)      ← 验证模式
🅱-B2 首屏分析  ─┤ (纯前端, 有布局约束)
🅱-B3 KPI 下钻  ─┘
        │
🅳-C1 公共 Shell ── (地基, 让后续改动只改一处)               ← 第二步
        │
🅳-C3 视图模式容器 ── 依赖 C1 ──┐
        │                      ├─ 🅰-A1 图像/视频网格 (依赖 A0 确认)  ← 第三步
🅰-A0 后端字段确认 ────────────┘
        │
🅰-A2 点云降级 / 🅰-A3 对象裁图 ── 独立, 可后置                ← 第四步
🅳-C2 统一虚拟表格 ── 较重, 可最后收敛(或与 C1 合并)
```

**推荐顺序与理由**:
1. **先 🅱(B0→B1→B2→B3)**:纯前端、零后端、风险最低。B0 图表美化 + B1 交叉筛选同在 `DataManagerCharts.tsx`,合并落地;交叉筛选是体验质变,先做能快速验证方向、拿到反馈。
2. **再 🅳-C1**:趁 🅱 改动不大时把公共骨架抽出来,后面 A/B 的每次改动只改一处。
3. **然后 🅰-A0→C3→A1**:确认后端字段 → 搭视图模式容器 → 上图像/视频网格(体验第二个质变)。
4. **最后 A2/A3/C2**:点云降级、对象裁图、任务表格虚拟化收尾。

> 权衡:C1(动地基)有回归风险,故放在 🅱 之后而非最前——先用低风险改动确认整体方向,再动骨架。若团队更看重"一次性把地基打好",可把 C1 提到最前,但需以现有测试为回归网并补齐 Shell 的测试。

## 8. 风险与开放问题

- **A0 后端字段**:若 `tasks/query` 未 populate 缩略图,A1 会多一个后端小改动(低成本,但要排期)。**先确认再排 A1。**
- **置信度桶不可点选**:🅱 里这是已知限制。若要让它可点,需后端新增 `annotation.confidence` / `prediction.confidence` 的 filter field(支持 `gte/lt/between`)——列为**可选增强**,不阻塞 B1。
- **对象裁图成本**:批量网格若走前端 canvas 裁,每对象要载整张原图(同 task 多对象可共享原图);mask/旋转框裁剪 roi.py 不支持。建议 A3 先只做"对象详情单图",批量网格视需求再上后端 crop 端点。
- **C1/C2 回归面大**:三 lens 共骨架 + 表格迁移,务必以 `ProjectDataManagerPage.test.tsx` / `DataManagerCharts.test.tsx` / `DataManagerFilterBar.test.tsx` / `dataManagerUrlState.test.ts` 为回归基线,改动前后都跑。
- **色彩规范**:所有新 UI 走 shadcn 语义类 / `--sc-*`,状态色成对 `dark:`;提交前 `pnpm lint:css-tokens`。
- **缩略图 URL 过期**:presigned 1h,长挂页面靠 react-query staleTime 重查刷新(参考现有 `usePointCloudManifest` 的 staleTime 处理)。
