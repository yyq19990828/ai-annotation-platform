# v0.15.17 · 临帧框叠加产品化(门控收紧 + 对象级↔场景级 + 批量端点 + 降级常驻可见)

> 规划日期 2026-06-12 · 范围:v0.15.1 交付了「邻帧框 overlay + ego 对齐」,但落地后暴露 4 个产品化缺口——叠加在哪暴露(门控)、显示多少(对象级 vs 场景级)、什么代价(K 条并发请求 + client 过滤)、可不可信(降级只有一次性 toast)。本版只打磨**已有的框叠加**(ReferenceBox),不引入新数据模型;邻帧**点云**叠加是另一条线,见 [`2026-06-12-v0.15.18-neighbor-pointcloud-overlay.md`](2026-06-12-v0.15.18-neighbor-pointcloud-overlay.md)。
>
> **前置依赖(硬)**:v0.15.1(`useNeighborAnnotations` / `useSceneTrajectory` / `egoAlign.ts` / `CrossFrameOverlayToggle`)、v0.15.6(`workbench.common.crossFrameOverlayK` 已收编进 preferences)。与点云叠加(v0.15.18)正交,可先发。

### 1.2 本版四件事

| 点 | 能力 | 替代了什么 |
|---|---|---|
| **A. 门控收紧** | 统一「scene 数据才暴露叠加」的判定,复核 video 侧同款组件是否在非 scene 场景误露出 | 隐性的「task 级 scene_id 凑合用」 |
| **B. 对象级↔场景级** | 新增 `crossFrameOverlayScope` 设置:`selected`(现状,选中对象才叠)/ `all`(不选对象也叠邻帧全部框) | 「想看整体时序必须先随便选一个对象」 |
| **C. 批量端点** | 后端一次返回 K 帧邻帧标注(可选 group_id 服务端过滤),替代 `2K` 条并发 + client 过滤 | K=7 时 14 条往返 + 拉全量再丢弃 |
| **D. 降级常驻可见** | overlay 开启且该 scene 无 ego pose 时,在叠加控件旁显示**常驻 badge**「无 ego 轨迹·未对齐」 | 一次性 toast 划过即忘 |

### 1.3 不在本版本

- **邻帧点云叠加**:见 v0.15.18,本版只动框(ReferenceBox)。
- **审核侧按 source/scope 批量操作**:overlay 是只读参考,不落库,无审核动作。
- **overlay 框的可编辑/可点选**:邻帧框仍是只读参考,不允许在当前帧直接拖邻帧框(那是 propagate 的职责,v0.15.1 已有)。
- **跨 batch / 跨 dataset 邻帧**:邻帧反查仍走 v0.14.x 既有 scene/neighbors 路径,不扩展。

### 1.4 成功判据

1. **默认零回归**:`crossFrameOverlayScope` 默认 `selected`,不改设置的用户行为与 v0.15.1 byte 级一致(选中对象 → 叠该 group 邻帧框;不选 → 空)。
2. **门控**:非 scene 数据(`manifest.scene_id == null`)任何 stage(点云 / 视频)都不暴露叠加控件;复核结论写进文档(scene_id 是否足够,还是需 ALSO gate project.scene_mode)。
3. **场景级**:`scope=all` 时,**不选任何对象**也显示当前 K 邻帧的全部框(经 ego 对齐);此时若选中某对象,该对象 group 的邻帧框高亮、其余弱化。
4. **批量端点**:`scope=selected` 走带 group_id 的服务端过滤(payload 只含该 group);`scope=all` 走不带 group_id 的整批返回;前端从 `2K` 条并发降为 **1 条**请求。后端有单测(返回帧数 = 区间内邻帧数、group_id 过滤正确、非 scene task 422/空)。
5. **降级可见**:无 ego pose 的 scene 开 overlay → 控件旁常驻 badge 点亮;有 pose 时不显示。badge 与既有一次性 toast 不重复打扰(toast 可保留或并入 badge,实施时定)。
6. `uv run pytest -q` / `pnpm test` / `pnpm lint` 全绿;真实 nuScenes scene-0061 端到端:`scope=all` 不选对象即见整帧邻帧框,切 `selected` 回到单 group。

## 3. 各模块设计要点

### 3.1 门控收紧(点 A)

- **结论先行**:`manifest.scene_id` 是**正确语义门**——「该 task 的数据属于一个 scene、存在前后帧」才是邻帧叠加的前提;`Project.scene_mode` 是**项目调度声明**(by_scene 分包 / 连续调度),不是 overlay 的必要条件。一个 scene_mode=false 的项目若导入了 scene 数据,叠加仍应可用。**因此保持 scene_id 门控,不强加 scene_mode。**
- **要修的**:复核 video 侧 stage 是否复用 `CrossFrameOverlayToggle` 且在非 scene 视频(`manifest.scene_id == null`)误露出;若是,补同等门控。把门控判定收敛到一处(避免点云/视频两处各写一份漂移)。

### 3.2 对象级↔场景级(点 B)

- 新增 preferences 字段 `workbench.common.crossFrameOverlayScope: "selected" | "all"`,默认 `"selected"`(= 现状)。放在 `common` 组(与 `crossFrameOverlayK` 同组,video/点云共享)。
- `scope=selected`:维持现状(`selectedGroupId` 驱动,缺选则空)。
- `scope=all`:`useNeighborAnnotations` 的 `enabled` 不再要求 `selectedGroupId != null`;`referenceBoxes` 构建遍历邻帧**全部**框;若同时选中某对象,该对象 group 的邻帧框走高亮样式,其余走弱化样式(复用既有 ReferenceBox 样式分级,不新增渲染管线)。
- UI:`CrossFrameOverlayToggle` 旁加一个紧凑的 scope 切换(对象/全部),仅在 `overlayK>0` 时可用。

### 3.3 批量邻帧标注端点(点 C)

- 新端点 `GET /scenes/{scene_id}/neighbor-annotations?task_id={center}&k={k}&group_id={optional}`:
  - 服务端按 scene + center task 的 frame_index 反查 ±k 帧的 task(复用既有 neighbors 反查),一次性查这些 task 的标注。
  - `group_id` 给定 → 服务端过滤(`scope=selected`,payload 最小);省略 → 返回区间全部框(`scope=all`)。
  - 返回按 `task_id` / `frame_index` 分组,前端直接喂 referenceBoxes 构建,**省掉 `2K` 条并发与 client 过滤**。
  - 几何/坐标不变:仍是各帧 ego 系 PSR,ego 对齐照旧在前端 `egoAlign.ts` 做(端点不掺和坐标变换,职责单一)。
- 上限:`scope=all` 单次返回有帧内框数软上限(超出在响应里标记 `truncated`,前端提示「邻帧框过多,仅显示前 N」),避免极端场景拖垮渲染——呼应点 4a 的「不静默截断」。

### 3.4 降级常驻可见(点 D)

- overlay 开启(`overlayK>0`)且 `useSceneTrajectory` 对当前 scene 取不到 pose(或邻帧缺 pose)时,在 `CrossFrameOverlayToggle` 旁渲染常驻 badge:「无 ego 轨迹 · 邻帧框未对齐」(warning 色)。
- 与既有一次性 toast(propagate 路径的 `warnNoMotionCompensation`)解耦:toast 管「跨帧 propagate 动作」的反馈,badge 管「overlay 显示态」的常驻可信度信号。两者文案对齐,不互相覆盖。
- badge 用 `tokens.css` 既有 warning 语义色,不新造颜色(遵守 CLAUDE.md §6)。

## 5. 已知风险 / 未尽事项

- **`scope=all` 的渲染压力**:K=7 × 每帧数十框 → 数百只读框。先用既有 ReferenceBox 弱化样式 + 帧内软上限兜底;若仍卡,降采样邻帧框(按距离/类别)留后,不在本版过度设计。
- **批量端点与既有 `getAnnotations` 缓存一致性**:overlay 走新端点拿邻帧框,当前帧仍走 `getAnnotations`;两者数据源不同,刷新时机需对齐(端点结果纳入 react-query 失效链)。
- **门控收敛后的回归**:把两处门控收敛到一处时,务必保证点云侧现状(`manifest.scene_id`)行为不变,仅修 video 侧误露出(若存在)。
- **scope 切换与 K 的交互**:`scope=all` + 大 K 体验差,UI 可在 all 模式下限制可选 K(如最大 5),实施时按真实数据手感定。

## 6. 验证策略

- **端点单测**(最重):造一个 3 帧 mini scene,断言 `neighbor-annotations` 返回帧数 = ±k 命中数、带 group_id 时只回该 group、非 scene task 返回空/422。
- **前端**:`scope=selected` 既有用例不破;新增 `scope=all` 用例(不选对象 → referenceBoxes 非空、选对象 → 该 group 高亮)。
- **真实数据**:scene-0061,`scope=all` 不选对象即见整帧邻帧框;无 pose 的 SUSTech scene 开 overlay → badge 点亮且框不对齐(不报错)。
- **回归红线**:默认设置下 v0.15.1 行为 byte 级不变;`point_mask_3d` 等不可叠类型仍不进 overlay。
