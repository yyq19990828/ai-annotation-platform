## 背景与动机

视频工作台想「对当前帧跑图像 backend（det/seg/分类）做单题预标」，但**送不进 backend**：

- **当前帧像素可取 ✅**：`useVideoBitmapCache`（`pages/Workbench/stage/useVideoBitmapCache.ts`）把帧解成
  `ImageBitmap` 缓存（键 `taskId:frameIndex`，`createImageBitmap(<video>)` 抓帧，`activeBitmap` 暴露当前帧）。
- **但供图路径全在服务端 ❌**：所有 predict 路径（`predict_test` / `interactive_annotating` / worker 批量）
  都用 `_resolve_task_url(task)`（`api/v1/ml_backends.py:48`）从 task 派生图 URL，client 只传 `task_id`。
  视频 task 的 `file_path` 是**整段 mp4**，图像 backend 取不到帧。

**故本版新开一条「client 供图帧」predict 路**——非复用图像交互 AI。**供图路径 = 帧上传（通用）**，
不走 `data:` 捷径（gsam2/sam3 不认 data URI，「要做就做通用全量」）。

- 新端点：`POST /projects/{project_id}/ml-backends/{backend_id}/predict-frame`，挂在

## 风险

- **画布跨域污染 → `<video crossOrigin="anonymous">`（已修，含部署依赖）**：视频 `<video>` 加载的是
  跨域 MinIO presigned URL；`createImageBitmap(video)` 画到 canvas 后 canvas 被污染，导出 JPEG 抛
  `SecurityError`。修法：给 `<video>` 加 `crossOrigin="anonymous"`（storage 对 presigned GET 返回
  ACAO）。**部署依赖**：需对象存储对 web 源返回 CORS 头——MinIO 默认放行（dev 已验证
  `access-control-allow-origin` 正确回显），但若生产改用**未配 CORS 的 S3**，`crossOrigin` 会让**整个
  视频加载失败**（不止 AI 抓帧）。上生产前须确认 S3/MinIO bucket CORS 允许 web 源。
- **backend 需吃到「单帧图」而非 mp4**：WS1 传的是 client 供的帧 JPEG URL，backend 当普通图片
  predict，无需 frame 定位——避开视频抽帧。核对各 backend 对单图 http URL 的 predict 契约。
- **归一坐标系**：交互浮层/候选归一 0-1，入库百分比 0-100（见 memory `interactive_candidate_coords`）。
  WS1 落 `video_bbox` 时须与既有 `video_bbox` 入库口径一致，别飞出画布。
- **候选与 track 无关**：单帧 `VideoBbox` 无跨帧 id，与 v0.21.2 track_id 统一正交，不产 track_id。

## 验收

- 视频工作台选一帧 → AI popover「运行当前题」→ 图像 backend 返回候选，渲染为当前帧的框。
- 采纳候选 → 落成 `VideoBboxGeometry`（`frame_index` = 当前帧），工作台正确渲染、切帧后只在该帧显示。
- 图像项目行为不回归（`isVideoTask=false` 时仍走原 task 级 `triggerPreannotation`）。
- 端到端跑通一个真实 backend（yolo 或 gsam2）。

## 不在范围

- 整段视频逐帧批量（那是 v0.21.7 Phase 4 执行单位 epic）。
- 编排画布 / 输入节点 / 执行单位（v0.21.5 Phase 2）。
- tracking 接编排（v0.21.6 Phase 3）。
- 交互式 SAM2/SAM3 video tracker（`VideoTrackerJobsPanel`）原样不动。
