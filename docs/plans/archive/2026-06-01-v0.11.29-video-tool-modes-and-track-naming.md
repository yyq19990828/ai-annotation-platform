# v0.11.29 · 视频工具：单帧/轨迹独立开关 + 几何 type 命名规范化

- **日期**：2026-06-01
- **类型**：新功能 + 重构（含**存量数据迁移**：`geometry.type` / `annotation_type` 值 `video_track` → `video_track_bbox`）
- **背景**：视频工作台现有「矩形框」(`box`) 与「轨迹矩形框」(`track`) 两个工具，但它们：
  1. **共用同一个 `tool_unit_id = "bbox"`**，项目设置里只有一个 `enabled` 开关，一开两个工具全出现，无法只放开其中一个。
  2. 在数据层用 `annotation_type` / `geometry.type` 区分：单帧框 = `video_bbox`、轨迹框 = `video_track`。`video_track` 这个值里**没有几何信息**（因为目前轨迹只有矩形一种），未来接入「轨迹多边形」时命名会冲突且不齐。
- **根因**：`annotation_type` 把「几何」与「时序」两个正交维度耦合进了一个值。规范结构应是 `video_[track_]<几何>`，时序作为可选中缀。
- **目标**：
  1. **A 阶段**：把轨迹矩形的 type 值 `video_track` → `video_track_bbox`，单帧 `video_bbox` 已符合 `video_<几何>` 形态、**不动**。为未来 `video_polygon` / `video_track_polygon` 留位。
  2. **B 阶段**：在 `bbox` 工具单位上加一组视频专用子开关 `video_modes: {box, track}`，实现两个工具独立开关。**类别 / 属性绑定仍只有一套**（`tool_bindings["bbox"]`），零重复 —— 这是与需求方确认的关键取舍：单帧框与轨迹框几何一致，只是轨迹多了时序性，分两套配置会重复。
  3. **B 阶段（工具栏改造）**：视频工具栏加 `hand` 视图工具兜底（恒显示、左键平移、ESC 回归），并把 `VIDEO_TOOLS` 按「单帧 / 轨迹 / 视图」分组 + divider，呼应 `video_[track_]<几何>` 模型，为未来多边形/轨迹多边形预留扩展位。

## 设计定稿（已与需求方确认）

1. **复用 `bbox` 工具单位，不拆新 tool_unit**。子开关字段名采用 `{box, track}`，与前端 `VideoTool = "box" | "track"` 枚举对齐。
2. **`video_modes` 默认/缺省 = 两个都开**：老项目 binding 无 `video_modes`（`None`）时，前端视为 `box` 与 `track` 均可用，向后兼容，无需为存量项目写数据迁移。
3. **几何 type 命名只迁 `video_track` → `video_track_bbox`**，`video_bbox` 保持不变。
4. 类别 / 属性 / keypoint 绑定结构不变，仍挂在 `tool_bindings["bbox"]` 一套。

## ⚠️ 易错点（实施前必读）

- **绝不误伤「轨迹」领域操作名 / AI 任务名**：以下 `video_track*` 是**时序维度的通用领域概念**（跨几何，未来多边形轨迹也复用），与几何 type 数据值无关，**全部保持原样**：
  - `video_tracker_job` / `video_tracker_jobs` 表、model、schema、service（AI 自动追踪任务）
  - API endpoint：`propagate_video_track`、`compose_video_tracks`、`convert_video_track_to_bboxes`（`apps/api/app/api/v1/tasks.py:710,962,1041`）
  - operation 字符串 `f"video_track.{data.operation}"`（`tasks.py:1012`）
  - service 文件 `services/video_tracks.py`、`services/video_tracker_runner.py`、`services/video_tracker_adapters.py` 的**文件名与函数名**
  - 前端文件名 `VideoTrackPanel.tsx` / `VideoTrackSidebar` / `useVideoAnnotationActions` 等**不改名**
  - **本次只改 `"video_track"` 这个字符串字面量（几何 type 值 / `annotation_type` 值）**，不改任何标识符/文件名/endpoint。
- **判断逻辑里的 `== "video_track"` / `!= "video_track"` 是数据值比较，要改**；但它所在的函数名（如 `propagate_video_track`）不改。逐处甄别。
- **前端 `Geometry` 类型是 codegen 派生**：必须先改后端 `_jsonb_types.py` 的 Literal 再跑 codegen，`VideoTrackGeometry.type` 自动变 `"video_track_bbox"`。**不手改** `api/generated/types.gen.ts`。
- **大量测试 fixture 用了字面量 `"video_track"`**：A 阶段会牵动 ~10 个前端 test 文件 + 后端测试，需同步替换值。

## B 阶段 · `video_modes` 子开关（单帧/轨迹独立开关）

### B1. 后端 schema（`_jsonb_types.py` · `ToolBinding` 约 248-268）
- 新增可选字段：
  ```python
  class VideoModesConfig(BaseModel):
      model_config = ConfigDict(extra="forbid")
      box: bool = True    # 单帧矩形框 (video_bbox)
      track: bool = True  # 轨迹矩形框 (video_track_bbox)

  class ToolBinding(BaseModel):
      enabled: bool = False
      classes: list[ToolClassEntry] = []
      attribute_schema: AttributeSchema = {}
      keypoint_schema: KeypointSchema | None = None
      # v0.11.29 · 仅视频项目的 bbox 单位消费：控制「单帧框 / 轨迹框」是否各自可用。
      # None = 两者均可用（向后兼容老项目）。
      video_modes: VideoModesConfig | None = None
  ```
- 仅作为 UI 工具过滤；后端**不强制校验** annotation 是否符合 modes（保持简单，避免阻断存量/AI 写入）。如需校验另议。

### B2. codegen
- 后端改完跑前端 codegen → `GenToolBinding` 自动带 `video_modes`。**不手改**生成文件。

### B3. 项目设置 UI（`pages/Projects/sections/`）
- 在 `bbox` 工具单位 tab（`ToolUnitTabs.tsx` / 相关 section）下，**仅当项目数据类型为 `video`** 时渲染两个 checkbox：「单帧矩形框」「轨迹矩形框」，读写 `tool_bindings["bbox"].video_modes.{box,track}`。
- 状态读写经 `useProjectToolBindings.ts`（含自动保存链路，参照基本信息/标注指引现有自动保存）。
- 缺省（`video_modes == null`）UI 默认两个勾选。

### B4. 视频工具栏改造（`ToolDock.tsx` + `VideoStage.tsx` + hotkeys）

> 现状摸底：视频栏走 `ToolDock` 的独立分支（**92-124**），只渲染 `box`/`track` 两个平铺按钮，**无任何视图工具**；平移走右键拖拽 / letterbox（`VideoStage.tsx:1232,1599,1604`，`drag.kind="pan"`，右键 `evt.button===2`）；`VideoTool = "box" | "track"`（`useWorkbenchState.ts:27`），无中立态；ESC 在视频模式 = `cancel`（`hotkeys.ts:304,337`），不切工具。

**B4a · 加 `hand` 视图工具（第一层兜底 + 中立态）**
- `VideoTool` 扩为 `"box" | "track" | "hand"`（`useWorkbenchState.ts:27`；默认值 `"box"` 不变）。
- `VIDEO_TOOLS`（`ToolDock.tsx:61-64`）新增 `hand` 项（`icon: "hand"`, `label: "视图"`, `desc: "拖拽平移画布"`），并给每项加 `group` 字段（见 B4c）。
- `VideoStage.tsx` 左键逻辑：`videoTool === "hand"` 时，`handleStagePointerDown`（**1236** 一带）走 `kind:"pan"` 而非 `kind:"draw"`（与右键平移共用 pan 分支），即 hand 下左键平移、不绘制。
- **恒显示、不受 `video_modes` 过滤**（与图片栏 hand 一致）—— 这是空栏兜底：即便 `box`/`track` 都关，hand 仍在，工具栏不空。

**B4b · `video_modes` 过滤（独立开关落地）**
- 把 `tool_bindings["bbox"].video_modes` 透传到 `ToolDock`（数据流：`project.tool_bindings["bbox"].video_modes` → workbench model → `ToolDock` prop）。
- 仅过滤 `box` / `track`：`video_modes == null` → 两者都显示（兼容）；否则按 `video_modes.box` / `video_modes.track` 决定。**`hand` 不参与过滤**。
- 复核模式（`reviewMode`）逻辑不变。

**B4c · 分组 + divider（第三层，为未来几何预留）**
- `VIDEO_TOOLS` 每项加 `group: "static" | "track" | "view"`：
  - `static`：`box`（未来 `polygon`…）
  - `track`：`track`（未来 `track-polygon`…）
  - `view`：`hand`
- 视频分支复用图片分支的 divider 渲染（`ToolDock.tsx:147` 的 `prevGroup !== curGroup` 机制），组间插 `styles.divider`。当前呈现：`矩形框 | divider | 轨迹 | divider | 视图`。

**B4d · ESC 回归 hand**
- 视频模式 ESC：在现有 `cancel`（取消当前绘制）基础上，把 `videoTool` 切回 `"hand"`（改 `useWorkbenchHotkeys.ts:568` 一带的 `cancel` 派发，或在 video 分支的 cancel 后追加 `setVideoTool("hand")`）。
- hand 的主 hotkey：复用图片栏习惯（如 `H`），数字副键沿用 `Alt+digit` 体系（`box`=1 / `track`=2 / `hand`=3 或保持 4，实施时与图片栏对齐取一致值）。

## 风险与取舍

- **命名迁移面广但都是字面量替换**：`"video_track"` 散布 ~15 处后端 + 数处前端 + ~10 测试文件，最大风险是**漏改一处导致读/写 type 不一致**或**误改了 `video_tracker_*` 标识符**。靠步骤 3 的两条 grep 兜底。
- **为什么不留兼容分支（读时同时认 `video_track` 与 `video_track_bbox`）**：本地一次性迁移 + 硬切更干净，避免长期残留兼容代码。线上若已有存量轨迹，迁移前先核对条数。
- **复用 bbox 单位的代价**：`video_modes` 是塞进通用 `ToolBinding` 的视频特例字段（image/lidar 不消费）。可接受 —— 换来类别/属性零重复，符合需求方判断。未来若真要「轨迹多边形」独立类别体系，再评估是否拆 tool_unit。
- **工作量**：B 阶段 ~半天（schema + 2 处 UI），A 阶段 ~半天（字面量替换 + 迁移 + 测试）。耦合不紧，B 可独立先合；A 建议单 PR 内顺序实施，不拆并行 worktree（迁移与测试需统一验证）。
