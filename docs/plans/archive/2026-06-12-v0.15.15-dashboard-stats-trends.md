## 背景

v0.15.12 给 TUI 引入了 `Sparkline` 滚动曲线，但只用在「单 backend GPU 实时」一个场景。后端其实有大量**带时间序列的统计端点**——`/projects/stats` 给 12 周的总量/完成/AI 率/待审序列，`/dashboard/*` 给标注员/审核员/全员绩效（含 4 周趋势、sparkline_7d、p50/p95、first_pass_yield、rejected_rate）——这些天然适合把 v0.15.12 的曲线能力**从「单设备实时」推广到「项目生产趋势 + 团队绩效」**，让 TUI 在 SSH 下也能看「这个项目这两个月走势如何、谁的产出/质量异常」。

本版把这类只读统计补进 SDK，并在 TUI 加一个**只读**看板，严守红线 3：是「监控/观测」，不是复刻 web 仪表盘的交互。

## 红线（沿用 SDK/TUI 既有三条）

1. **TUI 只消费 `Client` 公开 API**，不碰 `_http`。
2. TUI 限定在 `[tui]` extra，可整体删除。
3. **只读观测，不复刻 web 仪表盘**：只画趋势 + 关键标量，不做 web 那套筛选/下钻交互；绩效视图是「SSH 下看团队产出」的只读列表。

## 数据可行性（待落地前核对 OpenAPI）

| 端点 | 用途 | 用于 TUI 的关键字段（待核对） | 角色 |
|---|---|---|---|
| `GET /projects/stats` | 可见项目聚合 | `total_data` `completed` `ai_rate` `pending_review` + `*_series`（各 12 周） | 已认证 |
| `GET /dashboard/admin/people` | 全员绩效卡片 | `user_id` `name` `role` `main_metric` `throughput_score` `quality_score` `rejected_rate` `sparkline_7d` `alerts` | admin |
| `GET /dashboard/me/performance` | 自助绩效对标 | `throughput` `quality_score` `trend_throughput[4w]` `team_trend_throughput[4w]` `p50/p95_duration_ms` `first_pass_yield` `rejected_rate` | annotator+ |
| `GET /dashboard/annotator` / `/reviewer` / `/admin` | 角色仪表盘 | 视角色而定（daily_counts / approval_rate / pending_review_count 等） | 对应角色 |

> **核对点**：`*_series` 的长度与点序、`sparkline_7d` 的数组结构、各 dashboard 端点的角色门控，均以源码为准。模型只声明要画的字段，其余 `extra="allow"`。

## 范围 A · SDK 模型 + 命名空间

**`models.py` 新增**（精简：只声明 TUI/CLI 要用的字段 + 序列，其余 `extra="allow"`）：

- `ProjectStats`：标量 `total_data` / `completed` / `ai_rate` / `pending_review` + 序列 `total_data_series` / `completed_series` / `ai_rate_series` / `pending_review_series`（`list[float]`）。
- `PersonStat`：`user_id` / `name` / `role` / `throughput_score` / `quality_score` / `rejected_rate` / `sparkline_7d`（list）/ `main_metric` / `alerts`（list）。
- `MyPerformance`：`throughput` / `quality_score` / `trend_throughput` / `team_trend_throughput` / `p50_duration_ms` / `p95_duration_ms` / `first_pass_yield` / `rejected_rate`。
- 其余 dashboard（admin/reviewer/annotator）字段密度高且角色各异 → **返回宽松 `_AAPModel`（`extra="allow"`）**，只在 CLI/TUI 取需要的字段，不为每个端点写满模型。

**`client.py` 新增**：

- `Projects.stats() -> ProjectStats`（挂到现有 `Projects` 命名空间）。
- `class Dashboard`：`admin()` / `reviewer()` / `annotator()` / `people() -> list[PersonStat]` / `me_performance() -> MyPerformance`。
- `Client.__init__` 注册 `self.dashboard`；`__init__.py` 导出新模型。
- 403 经 0.15.14 的 `PermissionError` 语义统一处理。

## 范围 B · CLI

- `aap stats [--json]`：打印项目聚合标量 + 用文本 sparkline（unicode 块字符，CLI 无 Textual）渲染 4 条 12 周序列。
- `aap dashboard [--role admin|reviewer|annotator] [--json]`：默认按 `me()` 角色取对应仪表盘；`people` 子命令 `aap dashboard people [--json]` 打印全员绩效表（admin）。
- 归 `PANEL_MONITOR`。

## 范围 C · TUI 看板 + 绩效

- **顶层新增「📊 看板」tab**（第 5 个主 tab）：
  - 顶部一行关键标量（total/completed/AI 率/待审）。
  - 4 条 `Sparkline`（复用 v0.15.12 的 widget + CSS），分别画 `total_data_series` / `completed_series` / `ai_rate_series` / `pending_review_series`，每条带中文标签与当前值。
  - 数据源 `client.projects.stats()`，放 thread worker；刷新走 `r`（与其它 tab 一致），**不做高频轮询**（统计是周级数据，无需实时）。
- **「🏆 绩效」视图（admin-gated）**：
  - 用 0.15.14 的 `self._role` 判定——非 admin 角色**不挂载**该 tab（而非挂载后 403）。
  - `DataTable` 全员绩效：列 `姓名 / 角色 / 产出分 / 质量分 / 退回率 / 7日趋势`，`sparkline_7d` 用紧凑 sparkline 或迷你块字符；`alerts` 非空的行着色提示。
  - 行下钻 → `DetailScreen` 展示该成员关键指标（不引入 web 的多维下钻）。
- **「我的绩效」**（任意角色）：可在「看板」tab 内附 `me_performance()` 的自助对标（个人 vs 团队 4 周均线两条 Sparkline）；若与全员绩效信息重叠则二选一，避免臃肿。

## 不在本版范围

- web 仪表盘的交互式筛选（时间范围/项目切换/钻取）→ 红线 3，不复刻。
- 任何写操作。

## 风险与取舍

- **定位漂移（最大风险）**：看板/绩效极易长成「半个 web」。守住：只读、只画趋势 + 关键标量、不做筛选下钻；绩效是「SSH 下看团队产出」的运维向只读视图。范围超出即拆到独立版本。
- **模型不为每个 dashboard 写满**：admin/reviewer/annotator 字段密度高且角色各异，故只为「要画的」（projects.stats 序列、people 列表、me_performance）写精简模型，其余 `extra="allow"` 取用，控制维护面。
- **角色门控**：绩效 tab 以 0.15.14 的 `me()` 角色**前置不挂载**，而非挂载后吃 403——前提是 0.15.14 已落地；若单独发本版，则退化为「挂载 + 403 局部提示」。
- **序列结构未知**：`*_series` / `sparkline_7d` 的点序与长度需核对；渲染前对空/短序列做兜底（Sparkline 传空 list 不崩）。
