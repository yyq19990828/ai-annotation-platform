# v0.20.16 · 二次推理上下文条改版（借鉴交互悬浮面板）

状态：**已落地（v0.20.16）**。用户反馈原条「丑的不行」——10+ 能力平铺成一大坨重色实心按钮、跨 3 行、
散落 ⚙。改成借鉴 `InteractiveToolBar` 悬浮面板的结构化单行。**依赖 v0.20.11–13**（增强其入口）。

## 问题

`SecondaryInferenceBar` 把项目所有 crop-capable 能力（跨 backend，可达 10+）平铺成一排 `variant="default"`
实心按钮，能力多时换 3 行、占满画布顶部宽度，⚙ 参数按钮散在每个能力旁——视觉噪音大、重、乱。

## 方案（借鉴 InteractiveToolBar）

复用交互悬浮面板的视觉语言与布局范式：

- **同款卡片**：`flex-col gap-1 rounded-md border border-border bg-card px-3 py-1.5 shadow-md`。
- **能力收成一个按 task 分组的 `<select>`**（`<optgroup>` 按 检测/分割/关键点/OCR… 分组，同模型选择器），
  取代平铺按钮——从"一大坨"缩成一个下拉。
- **结构化单行**：`标题（✦ 二次推理·「类」框）· DIVIDER · 能力[下拉] 落点提示 ⚙ ⚠补字段 · DIVIDER · [运行]`，
  用 `FIELD_LABEL_CLASS` / `SELECT_CLASS` / `DIVIDER` 与交互条一致。
- **选中项驱动**：⚙ 参数、⚠ 补字段、运行都作用于下拉当前选中的能力（此前每能力各一套按钮）。
  参数面板（`SchemaForm`）在有可调参数且展开时挂在卡片下方。

## 交互变化

- 原：点某个能力按钮 = 直接跑。新：下拉选能力 → 点「运行」跑（多一次点击，但 10+ 能力下拉远比平铺清爽，
  与交互条"选模型→交互"的心智一致）。
- ⚙ / ⚠ 收敛为选中项的单一入口，不再逐能力散落。

## 验收

- 有能力 → 渲染分组下拉 + 运行按钮；无能力 / readOnly → 不渲染。
- 选几何能力 → 运行 → 新增子框 toast；选属性能力缺字段 → ⚠ 补全 CTA + 运行后 warning toast。
- 选中项有可调参数 → ⚙ 显示、展开参数面板；无参数 → 无 ⚙。
- 视觉与 `InteractiveToolBar` 一致（同卡片 / 分隔线 / 字号 / 下拉样式）。

## 依赖 / 不在范围

- **依赖 v0.20.11–13**；复用 InteractiveToolBar 的样式常量范式（本版就地定义同款常量，未强抽共享模块）。
- 不做：能力按选中框类别过滤（→ v0.20.18，下拉已缓解杂乱，降级为软置顶）、参数持久化（→ v0.20.17）。
