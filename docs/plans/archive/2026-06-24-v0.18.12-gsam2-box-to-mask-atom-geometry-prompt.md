# v0.18.12 — gsam2 box→mask 批量分割原子 + 阶段间 geometry prompt 传递(方案B)

> 状态:**草稿 / 讨论中**。本文件先立骨架,细节随后续讨论补全。
> 关联:[[2026-06-23-v0.18.1-staged-preannotate-mvp]]、[[2026-06-23-v0.18.2-staged-preannotate-roi-routing]]、onnxtools 原子化(v0.18.9)

## 1. 背景与决策

0.18.x 的跨 ml-backend 编排,最小可编排单元是 backend `/setup.models[]` 里的**单个 model**。
onnxtools 在 v0.18.9 确立了"把内部复合管线拆成 public 原子 model + internal 整体 model"的模式
(`detect` / `classify` / 一锅端)。

gsam2 已天然暴露 4 个 model(`detection` / `segmentation` / `interactive-seg` / `tracker`),
但唯一**缺**的可编排原子是:**SAM2 的"框→mask"作为非交互、public 的批量下游 model**。
今天 SAM2-from-box 只以 `interactive-seg`(`is_interactive=true`)形态存在,只能在工作台手动调用,
无法被多阶段编排当作下游 stage 消费上游检测框。

**已拍板:**
- ✅ 做 gsam2 的 **box→mask 批量分割原子**(public、非交互、下游可编排)。
- ✅ 数据传递走 **方案 B**:阶段间传递上游 **geometry prompt**(原图坐标的 bbox/point),
  而非仅传裁好的 crop 图。协议③ + `PipelineStage` 做相应扩展。
- ❌ 暂不做:embedding-as-atom(不透明 tensor,跨 backend 无价值)、detect→track 视频编排(卡在视频编排尚不存在,另立)。

**目标管线(端到端验收场景):** 任意检测器(YOLO / onnxtools-detect / gsam2-detection)产出 bbox
→ 下游 gsam2 `box→mask` 原子消费这些框 → 输出 polygon,merge 回原预测 / 新建预测(按 stage `write` 配置)。

## 2. 改动面(分层)

### 2.1 协议层(方案B 核心,载荷形态 = 1a)
- ml-backend-protocol:新增"下游 stage 以 geometry prompt 为输入"的约定,**协议 v2.1 → v2.2**(纯加法)。
  - **载荷形态 = 1a 全图 + 原图坐标框列表**:下游 stage 收**全图 presigned URL**(复用 stage0 同一 URL)
    + 该图的 **N 个父框(原图归一化坐标)列表**,而非逐 crop。
  - `/predict` 输入支持**单图多框**:一条输入项携带全图 file_path + `prompts:[{box, parent_box_idx}…]`,
    backend `set_image` 一次、循环 N 框跑轻量 decoder(共享 embedding)。
  - **crop/geometry 判别器复用现有 `supported_prompts`**,不新增字段:
    `[none]` → crop 模式(现状,onnxtools 逐 crop);含 `bbox` 且非交互 → geometry 模式(box-seg,全图+框列表)。
  - 老 backend(均为 none/crop)行为不变。文档:`docs-site/dev/reference/ml-backend-protocol.md`。
- **形态决策依据**:SAM2 encoder 成本由 `set_image` 次数决定(与裁多小无关),1a 一图一次 encode、
  N 框共享,较 1b 逐 crop 的 N 次 encode 是数量级优势;且 1a 无需坐标回映、mask 质量更好(全图上下文)、
  省掉 crop 上传、命中 embedding cache(键 `sha1(url|sam_variant)`)。详见 §6 决策记录。

### 2.2 gsam2 backend
- `/setup` 新增一个 public model:**`grounded-sam2-box-seg`**,
  `task=segmentation`、`is_interactive=false`、`supported_prompts=[bbox]`(**只做 bbox,point 暂缓**)、
  `supported_geometric_outputs=[polygon]`。
- `predict()` 按 `model_id` 路由,推理**复用 `predict_bbox()`**(`predictor.py:161-175`)+ mask→polygon 簇
  (`_masks_to_results`)。**内核零新增推理**;主要新增 = setup 一条 + 路由一行 + **单图多框入口**
  (一次 `set_image`、循环框列表)。
- 不复用 `interactive-seg`(它 `is_interactive=true`,工作台手动工具,与批量下游原子是两个上下文);
  共享底层 `predict_bbox` 但作为两个 model 暴露。
- 复合 `segmentation` model 保留不动(向后兼容,单步 text→mask 仍可用)。

### 2.3 平台编排层(apps/api)
- `_run_task_pipeline`(`tasks.py:550-720`):按下游 model 的 `supported_prompts` 选投递方式。
  geometry 模式下**不裁 crop、不上传 crop**,而是把全图 presigned URL + 上游 Prediction 的归一化框列表
  (按图聚合)投给下游 backend。
- **结果回写**:下游每框输出按 `parent_box_idx` merge 回对应父框(复用现有按 `box_idx` 回写思路);
  polygon 已是原图坐标,**无需坐标回映**。
- merge/write 复用现有 `enriched_by_stage` / `PredictionMeta.extra` 机制。

### 2.4 前端编排 UI
- `StageCard` / `usePreannotateConfig`:box→seg 原子作为 public model 自动出现在下游选择器
  (visibility 过滤已就绪,无需特判)。
- 下游 input 模式(crop vs geometry)**按 model `supported_prompts` 自动决定,不暴露给用户选**。

## 4. 预标 UI:gsam2 文本路径改 task-first + 输出集去重

> 此节可**独立于原子件先行**(纯前端,wire 不破坏),作为把"backend+开关"心智推向"backend+可选 model"的铺垫。
> `box-seg` 原子落地后能直接作为新选项/下游 stage 接入,不必为它返工 UI。

### 4.1 现状与症状
gsam2 走 `isTextPath`(`usePreannotateConfig.ts:171`),配置模型和几何路径(YOLO)不是一套:
- 无 model 选择,只有**底部一个 `输出形态` toggle**(框/掩膜/全部);
- variant 取**顶层 union**(`:168-183`),sam+dino 两组**永远全显**(框其实不用 SAM);
- 下发 `output_mode` 而**不发 model_id**(`buildArgs:429-435`)。

根因:gsam2 被当成"一个 backend + 一个 output_mode 开关",而非"backend + 若干可选 model"。
因此输出形态只能放最后、sam_variant 白显、params 无 model 可挂只能堆底部。

### 4.2 目标形态(task-first + 输出集互不重叠)
backend 已声明 `detection`(text→box,仅 DINO)与 `segmentation`(text→box→mask,DINO+SAM)两个 model。
把"输出形态"提升为**该路径的 task/model 选择器**,置于 prompt 之后、参数之前;**两条 task 输出集去重**:

| Task | 输出 | variant | output 子开关 |
|---|---|---|---|
| **文本检测 (DINO)** | 只出框 | 仅 dino | 无 |
| **文本分割 (DINO+SAM)** | 掩膜 / 全部(框+掩膜) | sam+dino | 留 {掩膜, 全部} |

- **关键去重**:分割 task 的输出值从 `{框, 掩膜, 全部}` → **删掉"框"** → `{掩膜, 全部}`。
  因为 backend `predict_text(output="box")` 只跑 DINO、跳过 SAM(`predictor.py:197-298`),
  "分割@框" 与 "检测" 产出完全等价,属冗余。
- **"全部"保留合理**:`output="both"` 是同一次 SAM 推理同时吐框+掩膜的真复合产物,非纯框路径,不算重叠。
- **结构即隐藏**:框只活在无 sam 轴的"检测" task 下,选检测自然看不到 SAM 参数——
  无需写"按 output_mode 条件隐藏 sam_variant"的特殊逻辑。

### 4.3 实现要点(前端为主,wire 不破坏)
- variant/params **跟随选中 task**:用 `capabilitiesQ.data.models` 里**每个 model 真实声明的 `supported_variants`**
  派生(检测→dino;分割→sam+dino),取代 `:168-183` 的顶层 union 兜底(顺手修掉该历史 workaround)。
- params 视觉上挂在 task 选择器下方。
- **wire 不全废 output_mode**:检测 task 不带 output(或恒 box);分割 task 仍用 output_mode 区分 {mask, both}。
  output_mode 从"3 值后端开关"退化为"分割内部 2 值子选项",后端零改动,影响面最小。
- 文本路径是否改发 `model_id`(真·彻底 task-first)**暂不做**,留待 `box-seg` 原子需要时再统一收。

### 4.4 验证
- gsam2 项目配置面板:顶部出现"检测 / 分割"task 选择;选检测时无 SAM 参数、只 dino;选分割时 sam+dino + {掩膜,全部}。
- 分割下拉**不再出现"框"**;批跑产出与改造前一致(检测出框、分割出掩膜/全部)。

## 7. 协议显式 composition 维度(原子 vs 内部编排)

### 7.1 动机
模型市场的 model 目录把**原子**(一次推理)和**内部编排**(一个 model 内部串多原子、一次 predict 一气呵成)
平铺为平级条目,`task` 只描述输出形态、与"原子/复合"正交。今天唯一的部分信号是 `visibility=internal`,
但它**语义被重载**(本意"编排不可选"被 onnxtools 顺手当"内部复合"用)且**跨 backend 不一致**
(onnxtools 一锅端标了 internal;gsam2 的 segmentation/tracker 复合却是 public,完全没标)。
→ "是原子还是内部编排"目前只能靠读 display_name + 经验,非机器可读。

### 7.2 字段设计(协议 v2.2,纯加法)
- `/setup.models[]` 每条新增可选字段 **`composition`**,取值 `"atom"` | `"composite"`。
  - `atom`:单次推理 / 单原子(detection、interactive-seg、onnxtools detect/classify、box-seg)。
  - `composite`:一个 model 内部编排多个原子(gsam2 segmentation/tracker、onnxtools 一锅端)。
- **向后兼容**:字段可选,缺省 = `"atom"`(绝大多数 model 是原子;现存复合都在我们自管的 backend,本版显式标注)。
- **与 `visibility` 解耦**:两轴独立——
  - `composition` = 原子/复合(描述性);
  - `visibility` = 编排下游选择器是否可选(行为性,回归单义)。
  - 例:onnxtools 一锅端 = `composition=composite` + `visibility=internal`(复合且编排不可选);
    gsam2 segmentation = `composition=composite` + `visibility=public`(复合但单步仍可选)。
- `ml_capabilities._normalize_model` 透传 composition(缺省 atom);`capabilities` 接口带出。

### 7.3 本版各 backend 标注
- **gsam2**:detection=atom、segmentation=composite、interactive-seg=atom、tracker=composite、**box-seg=atom**。
- **onnxtools**:vehicle-attr=composite、vehicle-detect=atom、vehicle-attr-classify=atom。
- **yolo**:各 task model=atom。

### 7.4 消费(本版最小行为,不过度改造)
- **模型市场**:model 卡片加徽标「原子」/「内置流程」(读 composition)。
- **编排下游选择器**:行为不变(仍按 visibility 过滤),仅在 UI 上对 composite 项加标识。
  "编排时优先推原子 / 折叠复合" 等更主动的策略**本版不做**,留作后续。
- `visibility` 的过滤逻辑保持现状(onnxtools internal 仍被滤),只是文档上澄清其单一语义。

### 7.5 验证
- gsam2/onnxtools/yolo `/setup` 各 model 带正确 composition;`capabilities` 透出。
- 模型市场出现「原子 / 内置流程」徽标且与上表一致。
- 老 backend(echo 等不声明)→ capabilities 回落 atom,无报错、无 UI 异常。
