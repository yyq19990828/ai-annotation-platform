## 目标:给 `/me/performance` 与 `/admin/people` detail 补 3 个质量归因维度

1. **Reject 原因细分(per-person)**:本人被驳回任务按 `reject_reason_type`(漏标/多标/类别错/位置错)分布 → 指导针对性反馈。
2. **类别覆盖 / 分布**:本人标注按 `class_name` 的 top-N 占比 → 检测偏科/盲区(§4.1 点名)。
3. **首过率 first-pass yield**:一次通过(无 reopen)/ 提交总数 → 比 reopen 率更标准的质量 KPI。

## 后端(`apps/api/app/api/v1/dashboard.py`)

新增 3 个共享 helper(both `/me/performance` 与 `/admin/people/{user_id}` 调用,避免重复):

- `_reject_reason_breakdown(db, uid, start)` → `[{reason_type, count, pct}]`:`Task.assignee_id==uid AND reject_reason_type IS NOT NULL AND submitted_at>=start`,group by reason。
- `_class_distribution(db, uid, start, limit=10)` → `[{class_name, count, pct}]`:`Annotation.user_id==uid AND is_active AND created_at>=start`,group by class_name,top N。
- `_first_pass_yield(db, uid, start)` → `float | None`:`count(reopened_count==0) / count(*)` over `Task.assignee_id==uid AND submitted_at>=start`。无样本→None。

Schema 扩展(均**追加字段**,向后兼容):
- `MyPerformance` += `reject_reason_breakdown` / `class_distribution` / `first_pass_yield`。
- `AdminPersonDetail` += 同三字段。

> 编辑已上线的 `admin_person_detail` 仅**追加返回字段**(不改既有计算)→ 低回归风险;旧前端忽略未知字段。
