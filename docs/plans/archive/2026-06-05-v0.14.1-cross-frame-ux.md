## 1. 背景与目标

### 1.1 v0.14.0 之后还缺什么

v0.14.0 立了"scene + frame_index + neighbors API"的地基,但只让前端**透出**字段到调试面板,**没有给用户任何跨帧能力**。具体缺:

1. **跨帧 propagate**:目前一辆车连续 8 帧出现,annotator 要在每帧从零画一个 3D 框,**8 次重复工作**。研究里 SUSTechPOINTS / xtreme1 都让这一步变成"画第 1 帧,Shift+→ 一键推到下 1 帧、调一下位置、再 Shift+→"——估算节省 60-80% 重复工作。
2. **邻帧参考叠加**:画框时看不到"上一帧这辆车在哪",纯靠记忆判断时序连续性。三视图组件已经在用 `selectedGroupId` 高亮同帧成员(`ThreeDWorkbench.tsx:893`),但**只在当前帧内**,跨帧那一半完全没做。
3. **task 调度不知道 scene 边界**(v0.14.0 §5.3 留的口子):annotator 标完 T-5 提交,系统按 uncertainty / uniform 给个完全不相关的 T-127——跨帧 propagate 的"下一帧"语义在调度层断了,annotator 体验是"我刚标的奔驰跑哪了"。
4. **2D / 视频跨帧 UX 缺位**:图像序列 / 多段视频在 v0.14.0 已经有 scene + frame_index,但前端工作台同样没消费;同一个 hook + UX 应该跨数据类型共用。

### 1.2 目标:三种数据形态共用一套跨帧 UX

按 v0.14.0 §1.2 的存法分类,本期目标 UX 覆盖:

| 存法 | 跨帧 UX 行为 | 本期支持? |
|---|---|---|
| **A. 整段 mp4 一个 task** | task 内 propagate(已有,`video_tracker_runner`)+ 邻帧 overlay(本期新) | ✅ 整合 |
| **B. 抽帧图像序列** | 跨 task `Shift+→` propagate + 邻帧 overlay | ✅ |
| **C. 多段 mp4 拼成长录像** | 段级跨 task `Shift+→` propagate + 邻帧 overlay(段内沿用 A) | ✅(段级) |
| **3D 点云逐帧** | 跨 task `Shift+→` propagate + 邻帧参考框(3D 主视图 + 三视图) | ✅ 重点 |

**关键设计观察**:UX 抽象是"跨 frame_index 的同 group_id 复制",**与几何类型(box_3d / box_2d / polygon)正交**。本期一套 hook + 一份操作语义,跨 3D / 2D 都能用,不重复发明。

### 1.3 不在本版本

- **跨帧自动插值**(从第 1 帧、第 10 帧两个关键帧,自动算中间 8 帧的位置):留 v0.15+,需要 propagate UX 先跑一段时间反馈;SUSTechPOINTS `trajectory.py interpolate` 的等价物,**值得做但属于"高阶 propagate"**。
- **跨帧 Kalman 预测**(根据前 N 帧速度,预测下一帧 PSR):同上,留 v0.15+。
- **多目标批量 propagate**(全选 5 个框一键推到下一帧):本期只做"选中 1 个"。批量留 v0.14.x+。
- **跨 group_id 编辑**(在邻帧叠加层直接拖一个参考框 → 升级成当前帧的实框):邻帧 overlay 本期**只读**,不可拾取,不可拖。
- **跨场景 propagate**(case C 段内末帧 → 段间首帧的"无感"接续):v0.14.0 §5.4 已经说留 v0.15+;本期 `Shift+→` 在 scene 末帧报"已到 scene 末帧"提示。
- **点云分割 (`PointMaskGeometry`) 的跨帧 propagate**:本期只覆盖 `box_3d` / `box_2d` / `polygon_2d`;分割跨帧涉及 point_indices 在不同帧点云上的语义(decimate stride 变化导致 indices 失效),不简单复制 → 留 v0.15+。
- **跨帧 UX 在 case A (单段 mp4) 内的内部 propagate**:已由 `video_tracker_runner` 解决,本期不重做,只对接它到统一 hook 接口让前端调用方式一致(§3.6)。

### 1.4 成功判据

1. **3D 工作台跨帧 propagate**:打开 SUSTech demo / nuScenes 任一帧 task(假设有 ≥ 2 帧的 scene),选中某 box_3d → 按 `Shift+→` → 前端调 v0.14.0 `GET /tasks/{id}/neighbors?k=1` 拿到 next_task_id → POST `/annotations` 到 next_task(复制 PSR + group_id + class + attributes,**convention_at_create 取目标 task 当前 axis_convention**)→ 跳到 next_task 工作台 → 新建的框已选中,annotator 可立刻微调。若 next 为空(末帧),报 toast"已是该 scene 最后一帧",不跳走。
2. **三视图 + 主视图邻帧叠加**:打开任一 3D task → 在调试面板可切换"邻帧叠加 K"(0/1/3/5,默认 0)→ K>0 时 `useNeighborAnnotations` hook 批量拉前 K 个 + 后 K 个 task 的同 group_id annotations → 在 3D 主视图 / 三视图渲染半透明、不可拾取、与主框同色但描边暗 50% 的参考框。切换主框选择 → overlay 跟随 `selectedGroupId` 重算。
3. **2D 跨帧 propagate(case B)**:在抽帧图像序列 dataset(可用现有任何 jpg 序列项目演示)中按 `Shift+→` propagate 选中的 box_2d / polygon_2d → 行为镜像 3D 端,共享 group_id、跨 task、scene 边界正确处理。
4. **视频段级跨帧(case C)**:多段 mp4 dataset 中按 `Shift+→` propagate 选中的 box_2d → 段级跨 task;段内 `Shift+→` 沿用现有 `video_tracker_runner` 路径(详 §3.6)。
5. **task 调度 scene 优先**(v0.14.0 §5.3 挂入点正式启用):project 配置加 `prefer_same_scene_continuation: bool = False`(默认 OFF,既有项目零回归)→ 显式打开后,`get_next_task` 在 sequence 策略下优先返回"用户上一个提交的 task 的同 scene 下一帧"(若可见、未锁、未由 user 标过);找不到再回退到既有策略。**不**强制独占 scene(避免和 batch 体系冲突)。
6. **scene 末帧 / 首帧边界 UX**:首帧按 `Shift+←` → toast "已是该 scene 首帧";末帧按 `Shift+→` → toast "已是该 scene 末帧";**绝不**误跳到上 / 下一个 scene 首 / 末帧。
7. **测试覆盖**:
   - 前端单测:`useFrameNeighbors`、`useNeighborAnnotations`、`Shift+→` 键盘行为、scene 边界 toast、邻帧 overlay 渲染(用 mock manifest + neighbors 数据)。
   - 后端集成:`prefer_same_scene_continuation=True` 的 `get_next_task` 优先级测试;现有 sampling 策略零回归。
   - 端到端手工:SUSTech / nuScenes(若 v0.14.2 已落)各跑一遍 §1.4 判据 1-6。
8. `pnpm lint` / `pnpm test` / `uv run pytest -q` 全绿。

## 3. 各模块设计要点

### 3.1 `useFrameNeighbors` hook(共用 3D / 2D / 视频段)

```ts
// useFrameNeighbors.ts
type NeighborInfo = { task_id: string; frame_index: number };
type NeighborsData = {
  scene_id: string;
  scene_name: string;
  frame_index: number;
  scene_total_frames: number;
  prev: NeighborInfo[];     // 最近者排第一(cur-1 在 index 0)
  next: NeighborInfo[];
};

export function useFrameNeighbors(taskId: string | null, k: number = 1) {
  // 1. 若 task manifest 没 scene_id(历史未 backfill 数据)→ return { neighbors: null, ... }
  // 2. 否则 SWR/react-query 调 v0.14.0 端点 GET /tasks/{taskId}/neighbors?k={k}
  // 3. 透传后端 NeighborsResponse;手动 mutate 接口暴露给 propagate 完成后触发刷新(可选)
  // 4. 缓存键带 taskId + k,task 切换时自动重新拉
  return { data: NeighborsData | null, isLoading, error, refresh };
}
```

**关键**:hook 不知道几何类型,纯调 v0.14.0 端点;3D / 2D / 视频 workbench 共用同一份。

### 3.2 `useNeighborAnnotations` hook(邻帧框叠加用)

export function useNeighborAnnotations(

  nextTaskIds: string[],

  // 1. 把 prev + next task_ids 去重合并,批量 GET /annotations?task_id__in=...&group_id={selectedGroupId}

`PointCloudScene.setReferenceBoxes(boxes: ReferenceBox[])`:

### 3.3 `Shift+→` / `Shift+←` 键盘行为

挂在 `ThreeDWorkbench.tsx` 的 keydown 监听上,与现有快捷键体系共存(避免与 Shift + 视图切换等冲突,详查 `keyMap.ts`):

```ts
async function handleShiftArrow(direction: 'next' | 'prev') {
  const selected = annotationStore.selected;
  if (!selected || selected.geometry.type !== 'box_3d') {
    toast.info('请先选中一个 3D 框'); return;
  }
  const neighbors = await refresh();  // 强刷一次,避免缓存陈旧
  const target = direction === 'next' ? neighbors?.next[0] : neighbors?.prev[0];
  if (!target) {
    toast.info(direction === 'next' ? '已是该 scene 最后一帧' : '已是该 scene 首帧');
    return;
  }
  // 调后端 propagate(详 §3.4)
  const newAnnotation = await api.annotations.propagateToTask({
    source_id: selected.id, target_task_id: target.task_id,
  });
  // 跳目标 task(类似 next-task 流程,但直接 navigate,不走 scheduler)
  navigate(`/workbench/${target.task_id}?selectAnnotation=${newAnnotation.id}`);
}
```

**关键 UX 决定**:
- 跳过去**自动选中**新建框,annotator 不用再点
- 跳过去之前的当前 task **自动 release lock**(沿用现有切 task 流程的 release 逻辑)
- **不**前置确认:propagate 不是破坏性操作,新框是 group_id 共享,annotator 调坏了可以 revert;每帧都弹确认会拖死效率

### 3.4 `POST /annotations/{id}/propagate-to-task/{target_task_id}` 端点

请求(`PropagateRequest`):
```json
{ "override_psr": null }  // 留扩展位,本期前端总是 null = 完全复制源 PSR
```

响应(`PropagateResponse`):
```json
{ "annotation": <新建 annotation,含 id / geometry / group_id / ...> }
```

服务实现(`services/annotation.py`):
```python
async def propagate(db, *, source_annotation_id, target_task_id, user_id) -> Annotation:
    # 1. 拿源 annotation,断言 type 在 ['box_3d', 'box_2d', 'polygon_2d']
    # 2. 拿目标 task,断言:
    #    - 同 project_id(跨项目 propagate 拒)
    #    - 用户对该 task 有 write 权(共用既有 annotation 权限)
    # 3. 复制 payload:
    #    - geometry / class / attributes:直接深拷贝
    #    - group_id:若源 annotation 无 group_id,先给源分配一个(走 group_id_seq),再复用
    #    - convention_at_create:取目标 task 的 axis_convention(不是源的!)—— 这是 v0.13.11 安全网的关键
    #    - PSR 数学:**PSR 是 ISO 系坐标,目标 task 加载侧会按目标 dataset.axis_convention 反应用旋转**,
    #              所以源 PSR 原值复制即可,convention_at_create 写目标 dataset 的 convention 让 banner 不误报
    # 4. 创建新 annotation 行,user_id 为当前用户,is_active=True
    # 5. 返回新 annotation
```

**坐标系正确性论证**(关键不能错):
- v0.13.11 已经把"PSR 在数据库内永远是 ISO 系"的契约打通
- 跨帧 propagate 只是把 ISO 系 PSR 字节复制到下一帧——下一帧渲染时同样按目标 dataset 的 convention 反应用旋转,结果就是"同样的世界坐标位置"
- 若源帧和目标帧的 dataset.axis_convention **不同**(罕见,但理论可能,如同一 project 跨多 dataset 而 dataset 各自声明)→ propagate 仍然复制 ISO 系 PSR,渲染对齐正确;`convention_at_create` 写目标 convention,后续切换不报误警

### 3.5 邻帧 overlay 切换 UI

### 3.6 case C 段内 propagate 接 `video_tracker_runner`

多段视频 dataset 内,**段间** propagate 走本期新 `/annotations/propagate-to-task`(因为段是不同 task)。**段内** propagate 沿用既有 `video_tracker_runner`(因为段内同 task,frame_index 在 VideoFrameIndex 表)。

前端 `VideoSegmentWorkbench` 的 `Shift+→` 行为:
1. 当前位置是段内 frame K(K < 段末)→ 调 video_tracker_runner 路径 propagate 到 frame K+1
2. 当前位置是段末 frame → 调本期新端点 propagate 到下一段 task 的 frame 0
3. 当前位置是 scene 末段末帧 → toast "已是该 scene 最后一帧"

→ **同一个 `Shift+→` UX,内部分流到两套后端**,annotator 无感。本期前端 wire 完两套,后端不动 `video_tracker_runner`。

### 3.7 `prefer_same_scene_continuation` 调度行为

`Project` 加列(默认 False,既有项目零回归);项目设置面板加 toggle("启用 scene 连续标注模式")。

`scheduler.get_next_task` 修改(在既有策略前置 1 步):

if project.prefer_same_scene_continuation:

        if next_in_scene:

**关键边界**:
- 不强制独占 scene(annotator A 标了 frame 5,frame 6 仍可分配给 B);只是"如果同一个人继续要 task,优先连续"
- 30 分钟窗口是"用户连续工作 session"的粗糙估计,**不**写死;走 project 配置 `scene_continuation_window_min`(默认 30)
- 用户跨 batch 工作时:此优先只在同 batch 内适用(避免跨 batch 抢任务,沿用既有 batch 边界)
- 用户没有 recent_submitted 或其 scene_id 为 NULL → 直接走既有策略,行为等价于关闭

**回归保护**:`prefer_same_scene_continuation=False`(默认)时,**整段代码不进入**,既有 unit / integration test 全部应该零变化。这是 §1.4 判据 7 的硬测试。

## 5. 已知风险 / 未尽事项 → 后续 plan

### 5.1 跨帧自动插值 / Kalman(留 v0.15+)

本期只做"单帧 propagate":选一个框,推到下一帧,annotator 自己调位置。SUSTechPOINTS `trajectory.py` 还有"在 N 帧间线性插值"和"基于速度的 Kalman 预测";那是"高阶 propagate",效率提升另一档,但**复杂度上一档**(需要选两个关键帧定义起止;插值中间帧的 group_id / class 同步;Kalman 状态怎么持久化)。留 v0.15+ 单独立项。

### 5.2 跨场景段内段间无感(case C,v0.14.0 §5.4 沿用)

段末按 `Shift+→` 跳下一段时,目前体验是"切到下一段 task"。理想体验是"无感连续,只是 mp4 换了"。这需要两个 frame_index 命名空间(VideoFrameIndex / dataset_items.frame_index)在 UX 层面统一,涉及 PlaybackController 改造,留 v0.15+。

### 5.3 多 annotator 同 scene 协作语义

`prefer_same_scene_continuation=True` 时,**仍允许**多 annotator 同 scene 标不同帧。但有些场景下用户希望"我标了 scene-0061 第 1-10 帧,剩下都让我标完"——这种"软独占"涉及锁 / 分配 / 进度展示,本期不做。留 v0.14.x+(取决于用户反馈)。

### 5.4 PointMask 跨帧 propagate

`PointMaskGeometry { point_indices }` 跨帧复制无意义(目标帧的 point_indices 是另一片点云),本期跳过。研究里 SUSTechPOINTS 也没有 mask 跨帧;若未来真要做,需要"3D 物体边界 → 目标帧重新选点"的语义,基本是重做。留 v0.15+。

### 5.5 大 K 的 overlay 性能

本期 K 上限 5,前端不虚拟化。若用户反馈想看 ±20 帧,需要前端 LOD + 后端 k 上限放宽,留 v0.15+。

### 5.6 跨 dataset propagate

本期严格"同 project 同 scene"才能 propagate。理论上跨 dataset(同 project 多 dataset)、跨 scene(同 dataset 多 scene)的 propagate **语义上不成立**(根本就不是同一段录像),所以本期端点直接 422 拒绝。docs 说清楚。
