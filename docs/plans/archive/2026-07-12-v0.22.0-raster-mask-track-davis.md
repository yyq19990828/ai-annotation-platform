# v0.22.0 · 真·栅格 mask track + DAVIS

状态：**已实施（2026-07-13）**。Phase A 已用真实 SAM fixtures 完成可复现基准并冻结 `coco_rle_ref`；Phase B–E 已按
ADR-0048 落地 schema / API、视频 mask 渲染编辑、SAM2 / SAM3 原始 mask candidate、AAP JSON 无损迁移、COCO RLE 与
DAVIS packed-PNG 导出。本切片保持独立，没有与 `v0.21.x` 小修混合。

上游索引：[多几何 track 剩余切片](2026-07-12-multi-geometry-track-remaining-slices.md)。

## 目标

- 新增真正保存逐像素二值掩膜的 `video_track_mask`，不再把 mask 矢量化为 polygon；
- 支持当前帧 mask track 的读取、渲染、创建、笔刷 / 橡皮编辑、关键帧管理与撤销重做；
- grounded-SAM2、SAM3 multiplex、SAM3 PVS 能返回原始 mask candidate，接受后落同一 mask track；
- 导出标准 DAVIS palette PNG 序列；
- 对 payload 体积、解码缓存、对象数、overlap 与非法 RLE 设置明确上界，不把风险留给 PostgreSQL / 浏览器 OOM。

## 固定边界

- 保留独立 `VideoTrackMaskGeometry`，不重构现有三种 track schema；
- mask 归 `region` tool unit，与 polygon 共享类别 / 属性；
- 不新增单帧 `video_mask` geometry：视频 mask 笔刷只创建 / 编辑 mask track keyframe；
- 不做 optical-flow / morphing；相邻关键帧用 nearest hold，距离相同时取较早帧，outside 优先；
- server-side convert / split / merge / join 继续不支持 mask；
- Phase A 真实样本已证明长视频内联会超过 geometry 上界；正式合同使用内容寻址 `coco_rle_ref`，RLE 对象独立存储。

## 本次修订冻结的执行规则

- `v0.21.33` 的 `coco-frames-seg` 已在当前代码交付；Phase E3 不再是条件工作，而是本版必做的兼容扩展；
- `MaskBuffer.data` 是 row-major，COCO RLE 是 column-major；所有 codec 测试必须用非正方形 fixture，禁止直接顺序遍历 backing
  array 假装兼容；
- Pydantic 只校验 RLE 自洽、run 数和 geometry 序列化字节；mask 尺寸与源视频 metadata 一致性在 annotation / import /
  tracker accept 的 service 边界校验，因为 schema 层拿不到 `DatasetItem`；
- mask hold 是独立 resolver 语义，不改 bbox / polygon / polyline 的插值 resolver；outside 优先，前后关键帧均可参与 nearest，
  等距取较早帧，首尾之外保持最近关键帧；
- 图片工作台继续 `mask -> polygon`；视频 mask editor 单独接线，不能把图片 editor 加两个方法后就视为完成；
- DAVIS object id 在整个 sequence 内稳定，且 255 保留为 void，因此限制是**每个 sequence 的唯一可导出 mask track 总数不超过
  254**，不是只检查单帧
  可见数；
- DAVIS overlap 按 `z_order` 升序写入（较高值后写并获胜），相同 `z_order` 按 track number 升序写入（较大编号获胜）；
- DAVIS 的 0-based 五位帧名不能复用当前 manifest 的全局 `frame_start_number` / 固定六位输出；manifest 改为逐输出目录携带
  `start_number` 与 `padding`，并保留旧 manifest reader 兼容。

## Phase A 候选 geometry 合同

```json
{
  "type": "video_track_mask",
  "track_id": "track-uuid",
  "semantic_label": null,
  "keyframes": [
    {
      "frame_index": 12,
      "mask": {
        "encoding": "coco_rle",
        "size": [1080, 1920],
        "counts": [0, 10, 4, 20]
      },
      "source": "manual",
      "occluded": false,
      "attributes": null
    }
  ],
  "outside": []
}
```

`counts` 首项表示 column-major 扫描下的背景 run，与 COCO uncompressed RLE 对齐。此处是 benchmark 输入合同，不代表已经决定
最终把 `counts` 内联进 annotation JSONB。schema 校验：正尺寸、非负整数 counts、`sum(counts) == height * width`、frame 唯一、
outside 合法、单 mask run 数上界、整条 geometry bytes 上界。

冻结的细节语义：width / height / counts 全部是 strict integer（bool、float、数字字符串均拒绝）；keyframes 按 frame_index 严格
递增且最多 3000 个；outside 要求 `from <= to`，写入时还要落在视频 frame_count 内。空 mask（`counts=[height*width]`）合法、
可无损往返，但视为不可见，渲染 / picking / 导出均跳过；它不隐式改写 outside。resolved keyframe 继承所选关键帧的 source /
occluded / attributes，只把 resolved frame_index 改成当前帧。

Phase A 已选择对象存储，`keyframes[].mask` 使用不可变内容寻址引用：

```json
{
  "encoding": "coco_rle_ref",
  "size": [1080, 1920],
  "object_key": "raster-masks/sha256/ab/cd/<digest>.json",
  "sha256": "<64 hex>",
  "runs": 4096,
  "bytes": 16384
}
```

引用只指向 COCO uncompressed RLE JSON；API 读路径通过受鉴权的 mask content endpoint 返回内容，不把永久 bucket URL 写进
geometry。写入采用“先上传 immutable object，再提交 annotation / staged_result 引用”；事务失败留下的未引用对象由按引用扫描 +
grace period 的 GC 清理。删除 / 替换 annotation 不同步删对象，避免回滚和共享内容寻址引用竞态。

## Phase A · 合同、基准与架构闸

### A1 · RLE codec 与 golden fixtures

- Python / TypeScript 各自实现小型纯函数 encode / decode；
- Python backend codec 放在 `apps/_shared/mask_utils` 供 grounded-SAM2 / SAM3 共用；API 保留一个无第三方依赖的薄适配层并与共享
  fixture 做字节级契约测试，避免为了一个几十行 codec 改写 API Docker build context；TypeScript codec 放在 workbench shared geometry；
- Python / TypeScript 共享同一 JSON fixture，覆盖：空 mask、整图 mask、首像素为前景、奇偶 run、单像素、非正方形、棋盘格、
  非整数 / 负数 run、非法总长、尺寸乘积溢出；
- round-trip 必须逐像素相同，并固定 column-major 顺序；
- codec 不依赖 `pycocotools`，但可用它在测试中交叉验证标准兼容性。

### A2 · 体积与性能基准

- 输入使用仓库现有真实 SAM mask fixtures（nearest resize 到 720p / 1080p / 4K）以及 rectangle / ellipse / checkerboard /
  seeded 50% noise；不能只用易压缩矩形；
- 30 / 300 / 3000 帧 × 1 / 10 / 50 目标用实测单帧分布投影总量，至少对 30 帧 × 10 目标做真实序列化与 gzip，避免只看
  算术估计；
- 记录单 keyframe runs / RLE JSON bytes、单 geometry JSON bytes、staged candidate JSON bytes、API gzip bytes、Python / Node
  decode p50/p95，以及前端 row-major buffer 占用；结果写入 `docs/research/16-raster-mask-rle-benchmark.md`；
- Phase A 候选服务端预算：单 mask `runs <= 1_000_000`、单 annotation geometry JSON `<= 8 MiB`、单 tracker staged payload
  JSON `<= 64 MiB`、单 mask 最大 `4096 x 4096`；最终常量必须由报告 Outcome 冻结，422 文案逐项测试；
- inline 通过条件：真实 SAM fixture 的 1080p p95 profile 在 3000 帧 × 1 目标投影下不超过 8 MiB，且 300 帧 × 10 目标
  staged payload 不超过 64 MiB；任一失败即选择 `coco_rle_ref`，补齐 immutable object、鉴权读取、引用生命周期与 GC 设计后再进入
  Phase B；
- 性能条件：1080p 单 mask Node decode p95 `<= 16 ms`，4K `<= 50 ms`；失败时优化 codec / worker 解码，不能靠放宽内存上限通过。

### A3 · ADR / 合同冻结

- 新增 ADR-0048，记录 inline RLE 与对象存储取舍、JSONB 全量重写成本、candidate 双份占用和最终选择；说明它只扩展视频持久化
  mask，不推翻 ADR-0013 / ADR-0022 的图片 `mask -> polygon` 决策；
- 明确视频分辨率变更不支持，keyframe mask size 必须与源视频 metadata 一致；
- 明确 API / AAP / Video JSON 是否内联 RLE，不能各格式自创表示。
- benchmark 脚本固定随机 seed，输出 raw JSON（含 git SHA、Python / Node / OS / CPU、warmup 次数、样本次数、compact UTF-8
  bytes 定义）和 Markdown 报告；极端 3000 × 50 组合只做投影与 preflight，不物化 TB 级数组。

Phase A 是硬前置；没有基准与 ADR，不进入 Phase B。

### Phase A Outcome（2026-07-13）

- 共享 fixture 与 Python / TypeScript codec 已落地，API 与 Web 各 12 个 golden / invalid cases 通过；
- 真实 SAM 1080p p95 单帧 RLE JSON = 3,727 bytes；3000 帧单轨投影 = 11,431,900 bytes，超过 8 MiB gate；
- 实际 30 帧 × 10 目标 staged JSON = 1,144,550 bytes，300 帧 × 10 目标投影未超过 64 MiB；
- Node decode 1080p / 4K p95 均低于 16 / 50 ms gate；codec 性能通过，inline JSONB 体积不通过；
- 最终选择 `coco_rle_ref`，冻结单 mask 4096 × 4096、1,000,000 runs、4 MiB canonical object、8 MiB geometry、
  64 MiB staged payload；生命周期与事务见 ADR-0048，原始数据见 `docs/research/data/16-raster-mask-rle-benchmark.json`。

## Phase B · schema、服务层与无损读路径

- 增 `VideoTrackMaskKeyframe` / `VideoTrackMaskGeometry`，加入 Pydantic discriminated union；
- 建一个复用的 geometry / mask validator，接入 create、patch、prediction accept、AAP import / dry-run、tracker stage / accept 和 DB-read
  强类型测试；AAP 上传在 `json.loads` 前做原始字节上限，不能让 import 绕过 RLE / geometry 限制；
- task-context validator 在以上写路径核对 video metadata 的 width / height / frame_count；
- 更新 OpenAPI snapshot、docs API、前端 codegen 与手写 UI union；
- 扩 `isAnyVideoTrack`、compact track identity、Data Manager entity/filter、retired tool-unit 归位、annotation import 派生；
- `video_tracks.py` 增 mask resolver：outside 优先、nearest hold、tie 取 earlier、首尾之外 hold；`clean_keyframe` 保留 mask payload；
- Video JSON 给 export-only track record 写显式 `geometry_type`（不存在 Video JSON importer，不声称 round-trip）；AAP schema minor bump
  `1.2 -> 1.3`，原生 geometry 做 export -> import round-trip，并把 `video_track_mask` 派生到 region；二者都覆盖 inline / ref
  最终合同，旧 bbox / polygon / polyline 零变化；
- 导出 / 查询中所有显式三类型 allowlist 增 mask，bbox-only 格式明确按 RLE AABB 降级或显式跳过，由各格式合同决定，
  不输出全 0 空框。

导出合同固定如下：

| target | mask track 行为 |
|---|---|
| AAP JSON / Video JSON | 保留最终 RLE payload / reference；Video JSON 带 `geometry_type` |
| MOT / KITTI / `yolo-frames-det` | 由非空 RLE 计算 AABB；空 mask 跳过 |
| `yolo-frames-seg` | 跳过，不为导出临时矢量化 |
| `coco-frames-seg` | 输出标准 COCO RLE，`iscrowd=1` |
| DAVIS | 解码后写 palette PNG |

## Phase C · 前端渲染、选择与编辑

### C1 · MaskBuffer 复用

- `MaskBuffer` 增 `fromRle` / `toRle`；
- `useMaskEditor` 增 `initFromRle` / `commitToRle`，保留现有 brush、erase、dirty-rect 与 radius；
- 图片侧现有“mask → polygon”提交行为不变，视频侧显式走 RLE commit。
- 贯通 `shell model -> stage host -> VideoWorkbench -> VideoKonvaStage` 的视频 editor 生命周期；尺寸取视频 metadata，选中 / resolved
  mask 变化时重新初始化，提交走独立 mask track create / keyframe update payload builder；
- undo / redo 冻结为**每次 pointer stroke 一步**，另保留 annotation commit 级历史；视频进入 mask 编辑态后 `B/E` 归 brush / erase，
  退出编辑态恢复既有视频 bbox / exemplar 快捷键。

### C2 · 视频 render / cache / picking

- 当前帧只解码可见 mask；committed cache key 用 annotation id + version + resolved keyframe frame，staged key 用 job id +
  instance id + frame + staged revision；
- 切 task、annotation version 变化或 cache eviction 时调用 `ImageBitmap.close()`；
- Konva 透明叠加使用类别色和选中态，不为每次 React render 重建全尺寸 ImageData；
- picking 必须 alpha-aware，不能复用 polygon/polyline 的 bounding-rect hit；
- staged candidate 与已接受 annotation 共用 renderer，避免 preview / accept 视觉漂移。
- 新增独立 `VideoMaskView` / mask layer，不把 RLE 塞进 vector `points` / `geom`；主选择和 context-menu 都经同一 alpha-aware
  `videoStagePicking` 分支。

### C3 · 创建与关键帧编辑

- 视频工具栏增加 mask track 工具，仅在 video + `region.video_modes.track` 可用；
- 在无选中 mask track 时提交创建单关键帧 track；选中时编辑当前 resolved mask 并物化 / 替换 manual keyframe；
- 选中卡 / roster / timeline 支持关键帧、outside / occluded、显隐、锁定、改类、删除和 undo / redo；
- compose、convert 等不支持操作隐藏或显示准确禁用原因。
- timeline 把 mask 关键帧之间标为 held / between-keyframes，不复用 interpolated 文案；首版不画 mask center path preview。

## Phase D · tracker 原始 mask candidate

- capability controlled vocabulary 加 `mask`；tracker model 的 `supported_geometric_outputs` 声明真实集合；
- `TrackerContext.output_geometry` 扩 `mask`；grounded-SAM2 / SAM3 直接把 bool mask 编成合同 RLE，不先转 polygon；
- runner coercion / persist、多实例建轨、staged preview、accept / discard 全部按 geometry kind dispatch；
- 前端 preview 改为 typed geometry union，移除只接收 bbox 的过滤；mask candidate 与 committed annotation 走 C2 同一 view / cache /
  picking adapter；
- 继续只持久化项目采样网格帧，manual keyframe 保护、低置信 outside、跨窗 identity 不变；
- candidate 总 bytes 超上限时 job 明确失败并给诊断，不保存半截 staged JSONB；
- runner 在 append result 和发布 WebSocket 事件前逐 mask 校验并滚动累计 encoded bytes；一旦超限原子失败、
  `staged_result=NULL`，返回稳定 error code / detail，不先把全量结果堆进内存再事后检查；
- RLE AABB helper 接入 seed 提取、跨窗 continuation、multiplex IoU、manual keyframe 保护与新实例建轨，禁止未知 mask 退化为零框；
- 三个 tracker 都必须支持，避免同一 UI 选不同模型后 geometry 类型悄悄变化。

## Phase E · DAVIS packed-PNG

### E1 · target 与目录

- 新增 video-only `davis` target；
- 每个 sequence 输出：
  - `JPEGImages/Full-Resolution/{sequence}/{frame:05d}.jpg`，由 manifest / `fetch_frames.py` 生成；
  - `Annotations/Full-Resolution/{sequence}/{frame:05d}.png`，由 exporter 生成 palette-mode PNG；
  - `ImageSets/2017/val.txt`，导出包固定作为待评估数据集，不在实现中猜测 split。
- manifest 的每个 frame output spec 自带 `dir / start_number / padding / extension`；旧字符串 `frame_output_dirs` 继续可读。
  DAVIS spec 用 `0 / 5 / jpg`，YOLO / COCO 继续既有编号，允许同一 ZIP 多 target 并存。

### E2 · object id 与重叠

- background=0，255 保留为 DAVIS void、不分配；只对 mask track 按 `derive_track_number` 的同款排序确定性映射到 1..254；
- 每个 sequence 的唯一可导出 mask track 超过 254 明确失败，不取模、不复用 palette id；
- outside 不写，occluded 仍写；
- overlap 按 annotation `z_order`、再 track number 确定覆盖顺序，并在包内 README 明示；
- 文件名是 0-based 连续采样帧号，与 `fetch_frames.py` 输出严格对齐。
- palette 固定为 256 × RGB（768 bytes）；sequence name 走现有 sanitize 规则并在碰撞时显式失败；`val.txt` 按 sequence 排序，
  一行一个名字且以换行结尾；`is_hidden` 是 UI 状态，不影响导出。

### E3 · COCO 扩展

[`v0.21.33`](2026-07-12-v0.21.33-coco-frames-seg.md) 已实施；本版必须让既有 `coco-frames-seg` 读取 mask track 并输出
COCO RLE segmentation，`iscrowd=1`（compressed / uncompressed RLE 均按 COCO crowd mask 读取），并继续用 pycocotools
`annToMask()` 做真实 consumer 验证。

## 验收矩阵

- RLE：Python / TypeScript / pycocotools 交叉 round-trip 像素一致；非法 counts / size / bytes 明确 422；
- 渲染：1080p / 4K 当前帧切换无持续内存增长，cache eviction 确实释放 bitmap；
- 编辑：创建、brush、erase、编辑 hold 帧物化 keyframe、outside、undo / redo、刷新重载数据一致；
- AI：三种 tracker 均完成 `mask → candidate → accept`，多目标不串 id，accept 前 annotation 零污染；
- 导出：DAVIS PNG mode / palette / pixel id / overlap / outside / occluded / >255 / frame numbering 有 golden tests；
- 下游：用真实 DAVIS consumer 读取一次，不只检查 ZIP 文件名。
- 体积：报告给出真实 SAM fixture 分位数和组合投影；Outcome 明确 inline / ref 选择与冻结上限，超限 API 返回稳定 422；

## Outcome（2026-07-13）

  grace period 与单轮上限的清理任务回收；
- 后端新增 `video_track_mask` 强类型、task-context 校验、上传 / 鉴权读取端点、nearest-hold resolver、AAP JSON 1.3
  `mask_objects` 往返、Video JSON / bbox-only / COCO / DAVIS 分派，以及 tracker stage / accept 原子性；

  共用同一内容解码、缓存、alpha 渲染和 picking 路径；
