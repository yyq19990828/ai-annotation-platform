# v0.18.10 — 工作台 AI 语义收口 / 项目主后端 / 视频选择工具与平移退役

> 状态：**已实施**。创建于 2026-06-24。
>
> 定位：0.18.x 已经开放跨 ML Backend 多阶段编排后，本版做一次产品语义收口：明确「编排」归 `/ai-pre`，工作台 AI 悬浮面板只承载当前题 AI 执行与候选审阅；同时把「默认 ML Backend」改成更准确的「项目主后端」语义。另同步把视频工作台从早期工具模式退回到更自然的画布交互：保留显式选择工具，并退役可见的平移工具。
>
> 明确延后：GSAM2 这类 backend 内部自带编排链路的长期拆分 / 优化方向，本版只记录为后续议题，不做改造。

## 1. 背景判断

### 1.1 工作台 AI 悬浮面板的语义需要变窄

0.18.x 之后，平台已经有两条 AI 路径：

- `/ai-pre`：项目级 / 批量级多阶段编排。这里允许用户显式选择每个阶段的 backend、model、ROI 路由、写回字段，是跨 ML Backend 编排的主入口。
- 工作台 AI 悬浮面板：标注过程中对**当前题 / 当前画面**运行 AI，查看候选框、编辑候选属性、采纳或忽略。

因此工作台悬浮面板不应继续被理解成「选择一个默认 backend 后执行所有 AI 能力」或「轻量 pipeline 编辑器」。它的语义应收窄为：

1. 当前题的一次性 AI 执行入口。
2. AI 候选结果的局部审阅入口。
3. 当前会话的 backend/model/参数快捷选择入口。

它不承载阶段编排、跨 backend 拓扑编辑、批量运行态解释。

### 1.2 「默认 ML Backend」仍有必要，但名称不准确

当前项目级 `ml_backend_id` 仍然有实际价值：

- 新建预标注配置时提供初始选择。
- 工作台当前题 AI 执行没有用户显式选择时提供 fallback。
- 交互式点选 / 框选模型路由在没有更具体偏好时可用作优先 backend。
- 项目团队可以表达「这个项目主要依赖哪个 backend」。

但在跨 backend 编排开放后，叫「默认 ML Backend」容易产生误解：用户可能以为它会覆盖多阶段 pipeline，或认为一个项目只能绑定一个 AI 后端。更准确的产品语义是「项目主后端」：

- 它是项目级的默认偏好 / 初始选择 / fallback。
- 它不是 pipeline 的唯一 backend。
- 在 `/ai-pre` 中，每个 stage 显式选择的 backend/model 才是编排运行的权威来源。

本版只改 UI 文案与说明语义，不改数据库字段、不做 API 迁移。

### 1.3 视频工具栏应对齐图像工作台的自然交互

视频工作台早期把工具模式拆成 `box / track / hand`，其中 `hand` 是为没有中性态时提供「不创建标注也能拖动画布」的 fallback。现在图像工作台已经优化到更自然的画布交互：选择、拖动、缩放、平移不应都变成显式工具按钮。

本版对视频工作台采用同一方向：

- 保留显式「选择」工具，作为不创建标注的中立态。
- 退役可见的「平移 / hand」工具按钮。
- 保留明确的创建工具：矩形框、轨迹。
- 选择工具下点击 / 拖动 / resize 已有标注；创建工具下也优先命中已有标注。
- 平移走右键拖拽 / Space+拖拽 / 触控板滚动等视图手势，而不是工具栏模式。

## 2. 目标 / 非目标

**目标**

1. **工作台 AI 悬浮面板语义收口**：把标题、分组、按钮文案从泛化的「预标注 / backend 默认选择」调整为「当前题 AI / 候选审阅」。保持轻量，不引入 pipeline 编辑。
2. **默认后端改为项目主后端语义**：保留 `project.ml_backend_id` 和现有 API 形态，前端标签、按钮、说明文案统一改成「项目主后端 / 主后端」，并解释它是初始选择与 fallback。
3. **跨 backend 编排边界清晰**：`/ai-pre` 继续是多阶段编排入口；工作台只消费当前选择，不展示 stage 拓扑。
4. **视频工作台工具收口**：视频 ToolDock 展示「选择 / 矩形框 / 轨迹」，退役「平移 / hand」工具；`hand` 模式从类型、热键、文档中退场。
5. **视频默认交互补齐**：选择工具下空白左键不创建；已有标注的选择 / 移动 / resize 优先于创建；空白区域拖拽只在当前创建工具为 `B` / `T` 时创建；右键拖拽与 Space+拖拽可平移视图。
6. **文档与测试同步**：用户文档、开发概念文档、快捷键说明与测试用例更新到新语义。

**非目标**

- 不处理 GSAM2 / grounded-sam2 内部级联与平台级编排的长期拆分问题。
- 不改 ML Backend protocol，不新增 backend API 字段。
- 不改 `projects.ml_backend_id` 数据库字段名，不做迁移。
- 不把工作台 AI 悬浮面板做成 React Flow / stage editor。
- 不移除视频矩形框和轨迹创建能力。
- 不重做视频标注数据模型、track 命名、插值、关键帧策略。

## 3. 产品语义设计

### 3.1 工作台 AI 悬浮面板

悬浮面板的第一层信息应回答三个问题：

1. 这次对哪道题 / 哪个画面运行 AI？
2. 本次使用哪个 backend/model/参数？
3. 候选结果如何审阅、采纳、忽略？

建议文案方向：

| 现有倾向 | 新语义 |
|---|---|
| `AI 预标注` / `开始预标` | `当前题 AI` / `运行当前题` |
| `默认 ML Backend` | `本次 backend` 或 `项目主后端` |
| `置信度阈值` | 保持，但放在「候选筛选」分组 |
| `采纳全部` | 保持，但明确只对当前题候选生效 |

面板结构建议：

1. **本次运行**：backend、model、基础参数、运行按钮。
2. **候选筛选**：阈值、候选数量、批量采纳 / 忽略。
3. **候选审阅**：当前选中 AI 候选的属性、置信度、来源、可编辑字段、采纳。
4. **轻量状态**：运行中 / 失败 / 无候选，不展示 pipeline stage 统计。

实现约束：

- `AIPredictionPopover` 可以增加 `usage="workbench"` 这类上下文 prop 来收口文案，但不要把 `/ai-pre` 的 stage 语义塞进共享表单。
- `useWorkbenchShellModel` 中当前题 AI 执行仍复用现有单题 preannotate 调用路径，只调整呈现语义。
- 候选属性审阅继续留在工作台，因为它是标注决策的一部分，不属于批量编排配置。

### 3.2 `/ai-pre` 与工作台的边界

`/ai-pre`：

- 配置多阶段 pipeline。
- 每个 stage 显式选择 backend/model。
- 展示运行态、阶段统计、ROI 路由、写回字段。
- 是跨 ML Backend 编排唯一的产品主入口。

工作台：

- 运行当前题 AI。
- 展示当前候选。
- 支持当前候选的属性修正与采纳。
- 可切换本次使用 backend/model，但这只是本次运行设置，不是 stage 编排。

验收时要特别检查：工作台 UI 不出现「阶段」「pipeline」「下游」「ROI 路由」等容易让用户以为能在这里编排的概念。

### 3.3 项目主后端

产品命名统一调整：

| 位置 | 现有文案 | 新文案 |
|---|---|---|
| 项目设置 / ML Backends 区 | `默认 ML Backend` | `项目主后端` |
| backend 行按钮 | `设为默认` | `设为主后端` |
| backend badge | `默认` | `主后端` |
| selector option suffix | `（默认）` | `（项目主后端）` 或 `（主）` |
| 空值说明 | `未设默认` | `未设项目主后端` |

说明语义统一为：

> 项目主后端用于新建配置和工作台 AI 的初始选择 / fallback；多阶段预标注中，每个阶段显式选择的 backend/model 仍然独立生效。

实现约束：

- 本版不改 `ml_backend_id` 字段名，避免 API、OpenAPI、DB migration、生成客户端大范围联动。
- 代码内部变量可暂时保留 `projectMlBackendId` / `ml_backend_id`，但用户可见文案不要再叫「默认 ML Backend」。
- 若改注释，只改与本版 touched 代码直接相关的注释，不做无关重命名。

## 4. 视频工作台工具设计

### 4.1 术语约定

本版中的「选择工具与平移工具退役」按以下方式落地：

- **选择工具**：保留 / 新增独立按钮，`VideoTool = "select"`，用于不创建标注的中立态。
- **平移工具**：移除可见 `hand` 工具按钮与热键模式。
- **选择行为**：选择工具下点击已有框 / 轨迹即可选择；拖动已有形状即可移动；拖动 handles 即可 resize。创建工具下也先命中已有标注，再处理空白创建。
- **平移行为**：使用右键拖拽、Space+左键拖拽、触控板 / 滚轮视图操作，不需要切换工具。

这能避免视频工具栏出现「选择、矩形框、轨迹、平移」四个模式；用户需要停止创建时回到选择工具，需要看图时用右键 / Space 手势平移。

### 4.2 工具栏

视频 ToolDock 展示三个标注工具：

1. `选择`：用于点选、移动、resize 已有视频标注，不在空白处创建新框。
2. `矩形框`：用于创建单帧 `video_bbox`。
3. `轨迹`：用于创建 / 追加 `video_track`。

不展示：

- `平移`
- `hand`

当项目配置禁用了某个视频模式时，对应创建工具继续隐藏。若两个创建模式都禁用，ToolDock 仍显示选择工具，画布仍可选择已有标注、平移、缩放；不再用 `hand` 作为空工具 fallback。

### 4.3 交互优先级

视频画布 pointer 行为按优先级处理：

1. 正在 resize / drag 已有标注：继续编辑已有标注。
2. pointer 命中已有标注：点击选择，拖动移动，不创建新标注。
3. 右键拖拽或 Space+左键拖拽：平移视图。
4. 当前工具是 `select`：空白区域左键不创建。
5. 空白区域左键拖拽：按当前创建工具创建 `box` 或 `track`。
6. `Esc`：取消当前绘制 / 清选择 / 退出 pending 状态，最后回到 `select`，但不切换到 `hand`。

这个优先级是本版的关键：即使当前创建工具是 `box` 或 `track`，点击已有标注也应优先选择，而不是误创建。

### 4.4 热键

保留：

- `V`：选择工具。
- `B`：矩形框创建工具。
- `T`：轨迹创建工具。
- `Esc`：取消当前操作 / 清选择。
- 现有缩放、播放、帧跳转热键。

移除或改文档：

- `Alt+3`：不再选择视频 hand 工具，改为选择工具备用键。
- 文档中的 `V / B / T` 应分别对应选择、矩形框、轨迹；平移说明迁到视图手势。

Space+拖拽如果图像工作台已有状态，应复用同一 `spacePan` 状态传入视频 stage；不要为视频另造一套全局按键状态。

## 6. 验收标准

- 工作台 AI 悬浮面板语义清楚：它是当前题 AI 执行与候选审阅入口，不像 pipeline 编辑器。
- `/ai-pre` 仍是唯一跨 ML Backend 多阶段编排入口。
- 用户可见位置不再把项目级 backend 叫「默认 ML Backend」，统一为「项目主后端 / 主后端」。
- 项目主后端仍能作为工作台和配置表单的初始选择 / fallback；多阶段 pipeline 的 stage backend 选择不受影响。
- 视频 ToolDock 不再出现「平移」按钮，保留「选择」按钮。
- 视频已有标注的选择、移动、resize 在选择工具下明确可用；矩形框和轨迹创建能力不回归。
- 视频右键拖拽、Space+拖拽、滚轮 / 触控板视图操作可用。
- 文档与快捷键说明同步，没有残留的视频 `V=平移` 指引。
- 本版没有 GSAM2 内部编排拆分、backend protocol 变更、DB migration。

## 7. 风险 / 开放问题

- **字段名与产品名短期不一致**：代码和 API 仍是 `ml_backend_id`，UI 改叫「项目主后端」。这是本版有意控制范围；后续如果要重命名字段，应单独开 schema migration plan。
- **无创建工具项目的工具栏**：如果项目禁用 box 和 track，视频 ToolDock 仍保留选择工具。验收时要确认画布仍能选择、平移、缩放已有标注，并且空态不误导。
- **Space+拖拽状态贯通**：如果当前 `spacePan` 只服务图像 stage，视频需要接入同一状态。不要另建重复的 document keydown 监听。
- **文案过度解释**：UI 里避免大段说明。核心解释放文档；产品界面使用短标签、tooltip、空态即可。
- **GSAM2 误入本版范围**：不要借文案收口去拆 backend 内部 pipeline。最多在文档中说明平台编排与 backend 内部能力可以并存。

## 9. 后续议题

GSAM2 / grounded-sam2 这类 backend 内部自带编排链路，长期可以再开独立 plan 讨论：

- 哪些内部 pipeline 应保留为 backend 的高阶能力。
- 哪些能力应拆成平台可编排的原子 model。
- 平台如何在 model capability 中表达「原子模型」与「复合 pipeline」。
- UI 如何避免把 backend 内部链路和平台 stage 链路混成一件事。

本版只先把用户最容易混淆的两个入口收口：工作台当前题 AI 与项目主后端。
