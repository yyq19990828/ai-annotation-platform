# v0.16.4 · 切换 Konva 为默认 + 观察期(不删旧栈)

> 规划日期 2026-06-16 · 范围:画布栈统一 epic 的**切换版(可逆)**。把 `experiment.videoKonva` 默认打开,让视频工作台默认走 Konva 新栈;但**旧 SVG 栈与 flag 全部保留**,生产出问题可秒级关 flag 回退。本版只切默认 + 观察,**不删任何代码**——删栈是下一个独立 release v0.16.5。Epic 见 [`2026-06-16-v0.16.x-canvas-unification-epic.md`](2026-06-16-v0.16.x-canvas-unification-epic.md)。
>
> **前置依赖(硬)**:v0.16.3 功能对等检查单**全勾** + Playwright 新旧栈截图 diff 无回归。不过则本版不发。

## 1. 背景与目标

### 1.1 为什么切默认与删栈必须拆成两发

删整套旧 SVG 视频栈**不可逆**。若同一版里既默认开 Konva、又删旧代码,一旦生产冒出 staging/Playwright 没覆盖的环境相关问题(GPU 驱动 / 浏览器怪癖 / 高 DPR / 特定视频编码),将**无快速退路**,只能紧急 hotfix。Canvas 渲染的长尾问题只有**真实用户暴露**才暴露得出来。

所以本版(v0.16.4)只做"默认开 + 留退路 + 观察",删栈留给 v0.16.5——这是经典 expand/contract 迁移纪律,多留一版死代码的成本是零头,换来一个秒级逃生舱。

### 1.2 本版动作

1. `experiment.videoKonva` 默认值 → **ON**(旧栈 + flag 代码原样保留)。
2. 加**埋点/日志**:记录每次会话实际走哪条栈、是否发生过 flag 回退,作为观察期的客观信号。
3. 进入观察期:一个完整发布周期 / 足量真实用户用量。

### 1.3 切换闸门(先决条件)

- v0.16.3 §6 功能对等检查单逐项通过。
- Playwright 图片 + 视频冒烟 + 截图基线全绿,新旧栈 diff 在容差内。
- dev/staging 已用 flag 实测无阻塞性问题。
- 闸门任一不过 → 本版不发,问题回 v0.16.1/.2/.3 修。

### 1.4 放行 v0.16.5 的门槛(观察期出口)

- 观察期内**无人触发 flag 回退**(或回退均可归因于已修复的个案)。
- 无视频渲染相关回归上报。
- 满足后才进入 v0.16.5(删栈,不可逆)。

### 1.5 成功判据

1. 默认状态下视频工作台走 Konva 新栈;全流程(画框/关键帧/传播/播放/缩放/视觉设置)正常。
2. 关 flag → 秒级回退旧 SVG 栈,行为与切换前完全一致(逃生舱可用)。
3. 埋点能区分栈来源与回退事件。
4. `pnpm test` / Playwright / `pnpm lint` / `uv run pytest -q` 全绿(本版无删除,主要是默认值翻转 + 埋点)。

## 3. 设计要点

### 3.1 默认开 ≠ 强制

- flag 仍是 `experiment` 粘性项(localStorage 按 userId 分桶,与 WebCodecs 同范式),用户/环境可单独关。
- 可选:支持 env/项目级强制旧栈,给运维一个不依赖前端 localStorage 的总开关(若运维场景需要)。

### 3.2 埋点要能回答"该不该删栈"

- 维度:会话数走 konva vs svg、主动关 flag 次数、异常自动降级次数(若实现了"Konva 初始化失败回退 SVG"的兜底)。
- 这些数据是 v0.16.5 删栈的**客观放行依据**,不靠主观感觉。

### 3.3 本版不碰文档措辞

- 「视频 SVG / 双栈」的概念文档清理留到 v0.16.5(删栈后系统才真的单栈),避免本版文档与"旧栈仍在"的事实矛盾。

## 4. 实施顺序

```
P0 闸门:确认 v0.16.3 对等检查单全勾 + diff 无回归(不过则停)
P1 默认值翻转 + 埋点
P2 回退演练:手工关 flag 确认秒级回旧栈
P3 发布 + 进入观察期(挂监控)
P4 观察期出口评审:无回退/无回归 → 放行 v0.16.5
```

## 5. 已知风险 / 未尽事项

- **环境相关 canvas 问题**:本版的全部意义就是用"留 flag + 观察"兜住这类问题;逃生舱必须真的可用(P2 演练)。
- **埋点不足导致放行依据薄弱**:埋点要在发布前就位,否则观察期是"盲观察"。
- **观察期多长**:建议至少覆盖一个完整发布周期 + 足量真实视频标注会话;具体由埋点数据(回退率趋稳为零)定,不拍脑袋。
- **flag 默认开后旧栈无人测**:旧栈进入"仅回退用"状态,其测试仍保留到 v0.16.5,期间不主动维护。

## 6. 验证策略

- **回退演练**:关 flag → 旧栈 → 旧 SVG 测试全绿,行为零变化。
- **埋点验证**:构造 konva/svg/回退三种情形,确认上报正确。
- **全量回归**:test / e2e / lint / pytest。
