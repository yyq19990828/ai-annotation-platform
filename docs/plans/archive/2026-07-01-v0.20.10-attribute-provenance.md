# v0.20.10 · 属性级溯源（per-key origin sidecar）

状态：**已落地**（v0.20.10）。四问探讨 Q1 的核心 gap 之一。是 Q1b（v0.20.11 选中框二次推理）的**前置**——
二次推理写回的 AI 属性靠它标记来源。

> **落地说明**：调查确认 pipeline provenance 是 **stage 级、非 per-key**（`PredictionMeta.extra.pipeline`
> 有 `stages[].write_keys` / `ml_backend_id` / `model_id` + `enriched_attr_keys`）。per-key 来源通过
> **前缀反推**得到（enriched key = `f"{label}_{k}" if label else k`，与 `tasks.py:_run_task_pipeline`
> 一致）。**`confidence` 数据里不存在，未编造**（meta 只写 origin + model_ref）。meta 采「只存
> origin=ai 条目，human 隐式」的最小设计。

## 背景

「选中框做二次推理」的典型产物是**混合体**：人手画的几何框 + AI 二次推理填的属性（OCR 文本 /
分类属性）。此时整框级的 `source` 字段说不清「这个 `color` 字段到底是人填的还是 AI 填的」。要在
画布上区分 AI 属性与人工属性，需要**属性级（per-key）溯源**。

## 现状（已核实）

- `annotation.attributes` 是裸 `dict[key, value]`（`_jsonb_types.py:649`
  `AnnotationAttributes = dict[str, ...]`），**无 per-key origin/model/confidence**。
- 整框级溯源已有：`annotation.source`（manual/prediction/interpolated/...）、`confidence`、
  `parent_prediction_id`——但都是**整框粒度**，覆盖不了「人画框 + AI 填属性」。
- **prediction 层已有属性溯源**：`PredictionMeta.extra.pipeline` 记录「属性来自哪个 stage /
  backend / model」（batch pipeline 二次推理的产物）。但 prediction 转 annotation（accept）时，
  属性写进 `attributes` JSONB，**per-key 来源在这一步散失**。

## 目标

给 annotation 的每个属性 key 补一层来源标记（origin/model/confidence），让「AI 填的属性」在数据和
UI 上都可区分；把 prediction 已有的 per-key 溯源在转 annotation 时**保留**而非重造。

## 工作项

### WS1 · 数据模型

- annotation 新增 **`attributes_meta` JSONB 独立列**（不塞进 `attributes` 内，避免污染值空间）。
  **实际落地形状**（只存 `origin=ai` 的键，human 隐式；`confidence` 数据里没有故省略）：
  ```jsonc
  {
    "<attr_key>": {
      "origin": "ai",
      "model_ref": { "backend_id": "...", "model_id": "..." }
    }
  }
  ```
- alembic 迁移 `0111`（加列，`NOT NULL`，`server_default '{}'`）。
- **向后兼容**：存量行 `{}` → 读作全 `human`，无需回填。

### WS2 · 写入与维护

- **accept-prediction 转 annotation**（`annotation.py:130-275`）：从 `PredictionMeta.extra.pipeline`
  提取 per-key 来源，写入 `attributes_meta`（origin=ai + model_ref + confidence）。
- **人工改属性**：`update` / `bulk-update` 属性时，把被改 key 的 `origin` 置 `human`（人工覆盖即
  「认领」）。
- **键同步**（正确性红线）：删除某属性 key 时同步删 `attributes_meta` 对应项；`attributes_meta`
  不得残留已不存在的 key。

### WS3 · API + 前端

- `AnnotationOut` 带 `attributes_meta`（`types.gen.ts` 随 OpenAPI 再生）。
- 前端：属性面板里，`origin=ai` 的属性值旁一枚极轻 chip（如小 ✦），hover 显 model + confidence；
  人工改该属性后 chip 消失 / 转「已确认」。轻量、不改属性编辑主流程。

## 风险

- **key 同步**是唯一正确性红线：属性增删必须联动 meta，否则 meta 里出现幽灵 key 或漏标。
- 不要做成「影子副本」：只存 per-key 元数据，不复制属性值本身；「AI 曾建议过 X 但被人改成 Y」的
  历史对比走已有 audit_log / annotation history，不进本列。

## 验收

- 跑一次 batch pipeline 二次推理（检测→分类写属性）→ accept → annotation 的 `attributes_meta`
  里对应 key 标 `origin=ai` + model_ref。
- 人工在画布改该属性 → chip 消失、meta 转 `human`。
- 删该属性 → meta 对应项一并消失。

## 依赖 / 不在范围

- 无前置依赖。**是 v0.20.11（Q1b）的前置**（二次推理 AI 属性靠它标记）。
- 不做：属性值历史版本对比（走 audit）、跨框属性来源统计报表。
