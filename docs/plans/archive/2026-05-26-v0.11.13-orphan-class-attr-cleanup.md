# v0.11.13 · 删除类别/属性的孤儿数据治理

> 讨论结论落地。涉及三件事:**删除确认弹窗**、**工作台隐藏 + 运维清理端点**、**导出兜底跳过孤儿**。

## 背景:删除是非破坏的,孤儿是"算出来的"

类别/属性定义存在 `projects.tool_bindings`(JSONB);标注存的是裸 `class_name`(字符串)和 `attributes`(JSONB),**与定义之间无外键、无稳定 ID**。

- 在项目设置删类别/属性,只是把它从 `tool_bindings` 移走,**标注数据原样不动**。
- "是不是孤儿"不是标注上的状态位,而是**每次拿 `class_name` / 属性 key 去当前 `tool_bindings` 实时比对**算出来的。
- 因此**删除完全可逆**:加回同名类别/同 key 属性,标注立即恢复(颜色、属性面板全回来),与从未删过无法区分。

由此确立语义分层:

| 操作 | 可逆性 | 谁能做 |
|---|---|---|
| 前端删类别/属性 | ✅ 可逆(加回同名即恢复) | 项目 owner |
| 运维 cleanup | ❌ 不可逆(标注软删 / 孤儿属性键被抹) | owner / superadmin |

**删除 ≠ 数据没了;cleanup 才是扣扳机。** 弹窗文案应弱化恐吓、强调"可恢复",真正的破坏点是 cleanup。

> 注:"换成稳定 ID"经讨论**不排期**(rename 已有原子端点解决唯一痛点,改造是全平台级、且会破坏"删了又加回自动复活"这个友好行为)。

## 现状(调研已确认)

- 删除走 `PATCH /projects/{id}` 改 `tool_bindings`,无确认、无受影响计数、无任何校验。
  - `apps/web/.../sections/ClassEditor.tsx`(删除 = `value.filter(...)`)
  - `apps/web/.../sections/AttributeSchemaEditor.tsx`(同)
- 工作台:孤儿类别**照常显示**(`colors.ts` 走 hash 派生稳定色,不报错),无"已删除"标记,**无任何按类别筛选/隐藏开关**(只有按帧、按来源)。孤儿属性**天然不显示**(`AttributeForm.tsx` 遍历 `schema.fields` 渲染)。
- 导出:孤儿标注/属性**都会被导出**且各格式不一致——COCO `category_id` 降级 0、YOLO 行号 0(与真 0 类撞车)、VOC/AAP 原样写;`attributes` 里的孤儿 key 各格式都原样写,导致导出文件 schema 与 data 自相矛盾。
  - `apps/api/app/services/export.py`(加载在 `_load_data`,各格式 `export_coco/yolo/voc/aap_json`)
  - `apps/api/app/services/project.py`(`derive_classes_list` / `derive_attribute_schema`)

## 步骤

### A. 删除确认弹窗 + 受影响计数(第 1 件)

1. **后端用量统计端点**(新):`GET /projects/{id}/class-usage`
   - 返回 `{ classes: {name: count}, attributes: {key: count} }`。
   - 实现:`SELECT class_name, count(*) ... WHERE project_id=? AND is_active GROUP BY class_name`;属性侧用 `jsonb_object_keys(attributes)` 聚合或在 service 层遍历统计。
   - 权限:project owner(复用 `require_project_owner`)。
2. **前端**:`ClassEditor` / `AttributeSchemaEditor` 删除按钮改为**点击时拉一次用量**再弹确认框。
   - 文案(弱恐吓):"类别 **X** 已被 **N** 条标注使用。删除后这些标注将变为孤儿——**暂不影响标注数据,加回同名类别即可恢复**;工作台可隐藏孤儿标注,如需彻底清除请运维执行清理。"
   - N=0 时仍弹确认但提示"无标注引用,可放心删除"。

### B. 工作台隐藏 + 运维清理端点(第 2 件)

3. **前端隐藏开关**:作为**全局视图开关**放进 Topbar 右侧齿轮 ⚙ 菜单。
   - 挂载点:`Topbar.tsx:108` 的 `overflowItems`(目前为空数组,注释"现仅承载主题切换",正好扩展);开关项语义"隐藏孤儿标注"。
   - 选这里而非 `AIInspectorPanel`:它是影响**画布 + 列表**的全局开关,不归属"人工 / AI 待审"任一区块;且 topbar 菜单不依赖有无 AI 框、是否视频任务,任何任务都能稳定访问。
   - 生效面:列表走 `filteredUserBoxes` 过滤链(`useWorkbenchShellModel.tsx`),画布 stage 同步隐藏孤儿框;判定 = `class_name` 不在当前 `classesConfig` 的 key 集合内。
   - 孤儿类别在列表行(`BoxListItem.tsx`)加 ⚠ 标记,让用户能区分(开关关闭时也可见标记)。
4. **后端清理端点**(新):`POST /projects/{id}/cleanup-orphans`
   - 权限:owner / superadmin。
   - 支持 `dry_run`(默认 true):返回 `{ orphan_annotations: N, orphan_attribute_keys: {key: count} }` 预览,**不写库**。
   - `dry_run=false` 执行:
     - **孤儿标注**:`class_name` 不在当前派生类别列表 → **软删 `is_active=false`**(与现有标注删除一致,可审计可恢复)。
     - **孤儿属性(决策 B)**:对 `class_name` 仍有效但 `attributes` 含 schema 外 key 的标注,**物理摘除这些 key**(直接改 JSONB;单 key 无软删概念)。
   - 二者正交、同端点内分别统计与执行。

### C. 导出兜底(第 3 件)

5. **`export.py` 加载后过滤**:`class_name` 不在当前派生类别列表的标注**直接跳过**,不进任何格式。
   - 全局生效:即使运维尚未 cleanup,导出层已不再泄漏孤儿标注(与"软删"在导出端表现一致——现有导出已跳过 `is_active=false`)。
   - 孤儿属性 key:导出前按当前 `attribute_schema` 收敛 `attributes`(只保留 schema 内的 key),消除导出文件 schema/data 不一致。

## 验证

- 后端:`cd apps/api && uv run pytest`(新增——用量统计计数正确;cleanup dry_run 不写库且数字与真删一致;软删后标注 `is_active=false`;孤儿属性 key 被摘除而有效 key 保留)。
- 导出:构造一条孤儿类别标注 + 一条带孤儿属性 key 的有效标注,导出 COCO/YOLO/VOC/AAP,断言孤儿标注不出现、孤儿 key 不出现、schema 与 data 一致。
- 前端可逆性手测:删类别→工作台开"隐藏孤儿"标注消失→加回同名→标注复活、属性面板恢复。
- 删除弹窗显示正确的 N(含 N=0 分支)。

## 回退

- A/B 的新端点是增量,删之即回退;前端开关/弹窗为纯 UI 增量。
- C 的导出过滤是行为变更但无损(孤儿本就是不该出现的数据);如需临时恢复旧行为,移除过滤分支即可。
- cleanup 的**软删可逆**(`is_active=true` 即恢复);但**孤儿属性 key 的物理摘除不可逆**——这是决策 B 的已知代价,故 cleanup 强制 dry_run 预览 + 高权限门槛。

- 决策 B(清理顺带做属性收敛)已确认:否则"class 有效但属性 key 已删"的标注其孤儿 key 永久留存并继续污染导出。
- 不做稳定 ID 改造(见背景)。触发再评估的条件:跨项目复用类别本体 / 需审计区分"删了又加回" / 类别需挂结构化 ontology 元数据。
