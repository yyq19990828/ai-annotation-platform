# v0.14.8 · Data Manager 保存视图 + 受控过滤 DSL + 只读运营面

> 规划日期 2026-06-07 · 范围:借鉴 Label Studio Data Manager,给项目任务运营补一层**保存视图(saved views)** 与**受控 filter DSL**。本版只做只读视图、过滤、排序、列显隐与计数列,不做筛选结果批量写操作。批量导出/重跑预标/指派/分包留后续。
>
> 触发来源:开源平台对标第 2 点。Label Studio 的强项不在专业点云/视频标注内核,而在通用数据运营面:Data Manager views、filter、统计列、批量动作。本平台当前有 batch、search、review/feedback,但缺项目内可保存的任务视图。

## 1. 背景

当前项目管理员常见问题:

- 想看「有预测但未采纳」的任务。
- 想看「有未解决 feedback / reject」的任务。
- 想看「某个 model_version 低置信度预测」的任务。
- 想把这些筛选保存成固定入口,每天回来继续处理。

现在这些能力分散在 batch、review、dashboard、search 中,没有一个项目级 Data Manager 面板承载。

## 2. 目标

### A. Saved Views

新增项目内保存视图:

```text
ProjectTaskView
  id
  project_id
  name
  owner_id
  visibility: private | project
  filter_json
  sort_json
  columns_json
  created_at / updated_at
```

首版仅支持:

- 创建 / 更新 / 删除 view。
- 复制 view。
- 默认 view:全部任务、待标注、待审核、有未解决反馈、有预测候选。
- 视图可 project 共享,但只有 owner/project_admin 可编辑共享视图。

### B. Filter DSL

受控 DSL,不开放任意 SQL:

```json
{
  "op": "and",
  "rules": [
    {"field": "task.status", "op": "in", "value": ["pending", "review"]},
    {"field": "feedback.unresolved_count", "op": "gt", "value": 0},
    {"field": "prediction.model_version", "op": "eq", "value": "sam3-v1"},
    {"field": "annotation.class_name", "op": "in", "value": ["car", "person"]}
  ]
}
```

首版字段白名单:

| 族 | 字段 |
|---|---|
| task | status、assignee、reviewer、batch_id、scene_id、frame_index、created_at、updated_at |
| dataset | dataset_id、file_type、metadata key 的少量白名单 |
| annotation | annotation_count、class_name exists/in |
| prediction | prediction_count、model_version、avg_confidence、source |
| feedback | unresolved_count、kind、severity |
| scene | scene_name、frame_index range |

### C. 任务表列

项目任务表新增可选列:

- annotation_count
- prediction_count
- avg_prediction_confidence
- unresolved_feedback_count
- model_versions
- scene_name / frame_index
- last_activity_at

## 3. 非目标

- 不做筛选结果批量写操作。
- 不做 `select all across pages except excluded`。
- 不做任意 JSONB key 查询。
- 不做跨项目全局 Data Manager。
- 不替代现有 batch;view 是运营视角,batch 是流程/分包实体。

## 4. 后端设计

### 4.1 模型与迁移

新增表 `project_task_views`:

- `project_id` FK CASCADE
- `owner_id` FK SET NULL
- `visibility`
- `filter_json`, `sort_json`, `columns_json`
- `(project_id, name, owner_id)` 可重复规则需谨慎:private view 只约束 owner 内唯一,project view 约束 project 内唯一。

### 4.2 查询服务

新增 `services/task_views.py`:

- `validate_filter(filter_json)`:字段、操作符、值类型校验。
- `compile_filter(filter_json)`:编译到 SQLAlchemy 条件。
- `list_tasks_for_view(project_id, view_id, page, page_size)`:返回任务 + 计数列。

**边界**:

- 动态字段一律走白名单;未知字段 422。
- metadata 查询首版只允许已索引/已声明 key,避免 JSONB 全表扫。
- 计数列用 subquery / CTE,不要在 Python 里 N+1 聚合。

### 4.3 API

```text
GET    /projects/{id}/task-views
POST   /projects/{id}/task-views
GET    /projects/{id}/task-views/{view_id}
PATCH  /projects/{id}/task-views/{view_id}
DELETE /projects/{id}/task-views/{view_id}

POST   /projects/{id}/tasks/query
GET    /projects/{id}/task-views/{view_id}/tasks
```

`POST /tasks/query` 支持临时 filter,用于前端未保存状态。

## 5. 前端设计

新增或改造项目任务页:

- 左侧 view tabs/list。
- 顶部 filter builder。
- 可保存当前 filter/sort/columns。
- 表格列可显示/隐藏。
- 每个 view 显示 task count。

首版 filter builder 可以简单:

- 字段 dropdown
- op dropdown
- value input
- and-only + 少量 group 支持

不要做复杂可视化规则树,先保证 query 能表达核心运营场景。

## 6. 测试与验证

后端:

- filter validator 拒未知字段 / 错误类型 / 不允许的 op。
- `unresolved_feedback_count > 0` 查询命中正确 task。
- `prediction.model_version = X` 查询命中正确 task。
- project_admin 只能访问自己项目 view。
- private/project visibility 权限正确。

前端:

- 创建/保存/切换 view。
- filter builder 生成稳定 JSON。
- 列显隐持久化。
- 默认 views 渲染。

手工:

- 一个 scene project 中按 scene/frame_index 过滤。
- 一个 AI 预标项目中按 model_version 和 low confidence 过滤。
- 一个 review 项目中按 unresolved feedback 过滤。

## 7. 后续版本

本版只读。后续可在同一地基上追加:

- `v0.14.x`:筛选结果批量导出。
- `v0.14.x`:筛选结果重跑预标 / 清理预测。
- `v0.15+`:active learning queue,把 saved view 作为训练/重标队列入口。

## 8. 风险

- **查询性能**:filter DSL 一旦支持太多 JSONB 动态字段,会拖垮任务表。首版必须白名单 + explain。
- **权限绕过**:view 是 project-scoped,所有 query 必须先套 project visibility,不能只过滤 view id。
- **批量动作膨胀**:本版明确不做写操作,避免审计和权限范围过大。
- **与 batch 混淆**:UI 文案要强调 view 是视图,batch 是流程单元。
