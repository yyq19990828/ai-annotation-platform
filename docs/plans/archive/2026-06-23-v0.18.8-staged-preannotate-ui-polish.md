# v0.18.8 — M8 · 多阶段编排 UI 美化 / 设计打磨

> 状态：**待实施 plan**（不开干）。创建于 2026-06-23。建议在 v0.18.5（选择器化）/ v0.18.6（运行态实时化）**之后**启动——那两版会重排 `StageCard` 与运行态结构，先落功能再美化，避免重复打磨。
>
> 定位：路径 B 的前端**视觉 / 交互打磨**。M1–M6 的多阶段 UI 是**功能优先**搭的：`StageCard`（`apps/web/src/pages/AIPreAnnotate/components/StageCard.tsx`）是「左描边块 + 朴素文本框」(`stageTwoBlock` / `textInput`)，运行态是「纯文本统计行」(`stageStatRow`)，**既没用上现成原语**（`ProgressBar` / `RadialProgress` / `StatCard` / `Badge` / `Tooltip`），也**没有「流水线」视觉隐喻**。本期对标 [`docs-site/dev/reference/design-system.md`](../../docs-site/dev/reference/design-system.md) 与 v0.17.x shadcn 体系，把这套界面提到与全站一致的设计水准。

## 1. 目标 / 非目标

**目标**
1. **流水线视觉隐喻**：把扁平阶段列表重排为「源（检测）→ 连接线 → 一组并行子（分类扇出）」的可读结构——源卡 + 下游卡用统一 `Card` 卡面、共享左轨/括号呈现扇出，连接处显「对每个检测框裁 ROI」内置语义。不上节点图（决议不变），靠卡片分组 + 轨线表达。
2. **StageCard 卡面升级**：用 `Card` 原语替换裸描边块；卡头含**阶段角色徽标 + 图标 + 角色色**（检测 / 分类 / OCR 各异）+ 折叠/展开；字段分组、输入控件统一对齐设计系统（不再裸 `textInput`）。
3. **运行态可视化升级**：逐阶段统计从纯文本行升为 **`ProgressBar` / `RadialProgress` 进度 + 色编状态 `Badge`（pending/running/done/failed）+ `StatCard` 风格计数**（检出 / 成功 / 失败），running 态加轻动效。
4. **候选属性审阅打磨（工作台）**：`AIInspectorPanel` 的「属性审阅」区——改动字段高亮 + 「恢复预测值」+ 「采纳（含改动）」按钮层级化 + 置信度展示 + 更顺滑的折叠。
5. **状态与微交互补全**：加/删卡过渡、hover/focus 态、空态（未加阶段→友好引导）、加载骨架、禁用态清晰化。
6. **暗色 + token 审计**：所有新表面走语义 token + 暗色配对，过 `check-tw-tokens`；圆角 / 间距 / 字号对齐 scale。

**非目标**
- 不上节点图 / React Flow（路径 B 决议）。
- 不加新功能 / 不改编排语义、校验、请求体（纯视觉 + 交互层）。
- 不改共享 `PreannotateConfigForm` / `usePreannotateConfig` 的逻辑（红线）；仅做与其视觉一致的对齐。

## 2. 详细设计

### 2.1 流水线视觉隐喻（ProjectDetailPanel）

- 源阶段配置区 → 一条「↓ 对每个检测框裁 ROI」连接说明 → 下游卡组。
- 并行兄弟用**共享左轨 + 顶部「并行」标**呈现「同源扇出」，区别于「再串一阶段」（本期仍单层，但视觉为未来留位）。
- 仍是卡片列表，非画布；轨线/分组纯 CSS（沿用并升级 `stageTwoBlock` 描边为成体系的 rail）。

### 2.2 StageCard 卡面（核心美化）

- 外层 `Card`；卡头 = `Icon`（检测/分类/OCR 角色图标）+ 角色 `Badge` + 「阶段 N」+ 折叠钮 + 删除钮。
- 角色色：检测 / 分类 / OCR 各一语义 accent（取自 design-system Semantic Color，避免裸色）。
- 字段区分组：模型配置（复用 `PreannotateConfigForm`）/ 路由（父框类别）/ ROI（pad）/ 写回（属性键）四组，每组小标题 + 紧凑布局；输入控件统一用设计系统输入样式（替换裸 `textInput`）。
- 折叠态只显「角色徽标 + backend/model 摘要 + 写回键 chips」，省空间。

### 2.3 运行态可视化（ProjectDetailPanel + StageCard）

- 每张卡右上角状态 `Badge`：pending（灰）/ running（蓝 + 脉冲）/ done（绿）/ failed（红）。
- 卡内嵌一条 `ProgressBar`（该阶段 ok/targeted 比例）或小号 `RadialProgress`；并行兄弟各一条。
- 计数用 `StatCard` 风格小块：检出 N · 成功 M · 失败 K（失败>0 才红）。
- 数据来源同 v0.18.6（WS 实时 + 终态回落），本期只升表现层。

### 2.4 候选属性审阅打磨（AIInspectorPanel）

- 「属性审阅」区：被改字段加高亮边/点；提供「恢复预测值」小钮（清 `editedAiBoxAttrs`）。
- 「采纳（含改动）」按钮主次分明（primary），旁置「忽略」次级；顶部显候选置信度 + 来源 backend chip。
- 折叠/展开过渡顺滑；空属性候选不显审阅区（现状保持）。

### 2.5 状态 / 微交互 / 暗色

- 加卡：列表插入轻过渡；删卡：淡出。
- 空态：未加任何下游阶段时，「+ 加第二阶段」按钮区给一句引导文案 + 示意（检测→分类）。
- 加载：能力目录 / backend 拉取中显骨架而非空白。
- 全量 token / 暗色审计：新增 className 无裸色、语义色暗色配对齐全，`pnpm lint:css-tokens` 通过；圆角用 `--sc-radius`，间距/字号对齐 scale。

## 3. 实施步骤（每步带 verify）

1. StageCard 卡面升级（Card + 角色徽标 + 分组 + 折叠） → verify：视觉对齐设计系统，折叠态摘要正确，功能不回归（payload 不变）。
2. 流水线分组 / 连接线（ProjectDetailPanel） → verify：源→并行子结构一眼可读；多兄弟分组正确。
3. 运行态升级（ProgressBar/RadialProgress/Badge/StatCard） → verify：跑批时各卡进度/状态/计数可视化（接 v0.18.6 数据）。
4. 候选审阅打磨（AIInspectorPanel） → verify：改动高亮 + 恢复预测值 + 按钮层级；采纳行为不回归（`AIInspectorPanel.test.tsx` 绿）。
5. 状态/微交互/空态/骨架 → verify：加删卡过渡、空态引导、加载骨架。
6. 暗色 + token 审计 → verify：`pnpm lint`（含 `check-tw-tokens`）、tsc、相关 `*.test.tsx` 全绿；明暗两态人工走查。
7. 版本收尾：bump 四处 + `uv lock` + openapi 快照（纯前端则快照不变）；`curl /health` 验证 0.18.8。可选录 GIF 入文档（参考 `project_gif_recording_inventory`）。

## 4. 验收标准

- 多阶段编排界面视觉水准与 v0.17.x shadcn 全站一致，不再是「功能优先的表单堆」。
- 「检测 → 并行分类扇出」结构一眼可读（无连线 UI、非节点图）。
- 运行态以进度条 / 状态徽标 / 计数块呈现，而非纯文本行。
- 候选属性审阅的改动态、采纳层级清晰。
- 明暗两态一致，`check-tw-tokens` 通过，无视觉回归 / 功能回归。

## 5. 风险 / 开放问题

- **与 v0.18.5/6 的改动重叠**：本版打磨的就是那两版重排后的 `StageCard` / 运行态结构，**必须排在其后**，否则重复返工。
- **共享组件红线**：卡面美化勿渗进 `PreannotateConfigForm` 内部逻辑；仅做容器/卡层的视觉包裹与样式对齐。
- **过度设计**：美化以「对齐设计系统 + 用好现成原语」为度，不引入花哨动效 / 自定义图表；RadialProgress 等用现成，不新造。
- **可用设计技能**：可借 `design-taste-frontend` / `frontend-design` skill 提案配色与布局，但产出须落到设计系统 token，不引入一次性裸样式。
