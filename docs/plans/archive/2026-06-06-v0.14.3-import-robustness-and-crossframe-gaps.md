### 1.3 成功判据

1. **R1**:`group_frames` 接受一份可选的「角色 pattern 配置」(默认值 = 现有 `lidar`/`camera`/`calib`,零行为变化);传入 `lidar_point_cloud` / `camera_image` 等别名能正确分帧。新增单测覆盖默认 + 别名两路。`scene_inference.ROLE_DIR_NAMES` 与之共用同一份配置源,不再各写一套。
2. **R2**:`import_nuscenes_scene.py` 加 `--frame {sensor,ego}`(默认 `ego`)。`ego`:逐点乘 `T_ego_from_lidar` 落 ego 系、外参改 `cam_from_ego`、`axis_convention=iso_8855`;`sensor`:保留 v0.14.2 的 apollo 行为。`ego` 模式下对真实 scene-0061 跑 `sniff` 命中 `iso_8855`、BEV 车头朝上(肉眼)。lite 测试覆盖两模式 axis_convention 落值正确。
3. **R3**:`Shift+→`/`Alt+→` 目标 task 不在当前已加载 task 列表时,能正确加载并跳转选中(而非静默失败)。前端单测:模拟 neighbors 指向「未加载分页里的 task」→ 断言触发了对应加载 + selectTask。
4. **R4**:`SniffAxisConventionResponse` 增 `per_camera[]`(每相机的 best + score + role)与 `agreement`(一致占比),**向后兼容**(新增可选字段)。前端 `AxisConventionPicker` 在分歧时给一行提示。
5. **R5**:overlay 档位可在设置里自定义最大 K(或加 7/10 档),`useFrameNeighbors(k)` 的 `k ∈ [1,20]` 后端约束不变。
6. **R6**:向导上传伪多 scene zip 顶层用了保留角色名 / 超体积时,响应 `scene_inference_notes` / 错误信息明确指出原因(链 import-formats.md)。
7. `pnpm lint` / `pnpm test` / `uv run pytest -q` 全绿;真实 nuScenes-mini(本机已存)端到端复跑通过。

## 3. 各模块设计要点

### 3.1 R1 · 角色 pattern 单一真值(`role_patterns.py`)

新建一处定义,`group_frames` 与 `scene_inference` 共用:

```python
# role_patterns.py(示意)
@dataclass(frozen=True)
class RolePatterns:
    lidar: tuple[str, ...] = ("lidar", "lidar_point_cloud", "velodyne", "points")
    camera: tuple[str, ...] = ("camera", "image", "cam")
    calib: tuple[str, ...] = ("calib", "calibration")

DEFAULT_ROLE_PATTERNS = RolePatterns()
```

- `group_frames(items, patterns=DEFAULT_ROLE_PATTERNS)`:`_last_index` 改为「parts 命中 patterns.lidar 任一」;camera/calib 同理。**默认值含现有三个 magic word,零行为变化**(回归靠现有 `test_pointcloud_import.py` 守)。
- `scene_inference.ROLE_DIR_NAMES` 改为 `set(patterns.lidar + patterns.camera + patterns.calib + ("video","images","videos"))`。
- **不**做「每 dataset 自定义 pattern」的持久化(过度设计);只把 magic word 收口到一处、加几个常见同义词。xtreme1 风格(带数字后缀 `camera_image_0`)用前缀匹配(`p.startswith(pat)`)兜住。
- 风险:前缀匹配可能误命中(如目录名 `images_raw`)。用「精确相等 OR 以 `pat + 分隔符` 开头」收紧,避免 `imagesXXX` 误命中。

### 3.2 R2 · nuScenes ego-frame 变换(`--frame ego`,默认)

v0.14.2 的 `_compute_lidar_to_cam_extrinsic` + raw 点上传是 `sensor` 模式。新增 `ego` 模式:

- **点变换**:读 LIDAR_TOP 的 `calibrated_sensor`(sensor→ego)得 `T_ego_from_lidar`;`.pcd.bin` 每点 `p_ego = R·p + t`,写 ego 系点云。BEV 即 ISO 车头朝上,`axis_convention=iso_8855`。
- **外参**:相机外参从 `cam_from_lidar` 改 `cam_from_ego`(链里去掉尾部 `@ T_ego_from_lidar`,见 v0.14.2 脚本注释的推导)。投影仍正确(点与外参同在 ego 系)。
- **默认 `ego`**:更正确、与 v0.15.0 ego 地基自洽;`sensor`(apollo)保留给「想要原始传感器系点」的人。
- **幂等冲突**:同一 dataset 不能混 `sensor`/`ego`(axis_convention 不同)。脚本检测 dataset 已存在且 axis_convention 与本次 `--frame` 不符 → 报错拒绝(不静默覆盖)。
- lite 测试:fake 数据下断言 `ego` 模式 dataset.axis_convention=="iso_8855"、点被变换(给非单位 `T_ego_from_lidar`,断言输出点 ≠ 输入点);`sensor` 模式 =="apollo"。

### 3.3 R3 · 跨帧 propagate 跨 batch 导航

`crossFrameTarget.resolveCrossFrameTarget` 现返回 `{kind:"ok"|"no-scene"|"boundary"}`,`ok` 后 `selectTask(targetTaskId)`。问题:`selectTask` 只在 `tasks`(当前 batch 已加载分页)里有效。

- **诊断分支**:`selectTask` 前判断 `targetTaskId` 是否在已加载 `tasks` 里。
  - 在 → 现行为(直接选)。
  - 不在但 `hasNextPage` → 触发 `fetchNextPage` 直到目标出现或翻完(neighbors 已给 frame_index,可估算方向);出现则选。
  - 跨 batch(目标在别的 batch)→ 用 neighbors 返回的 `task_id` 直接 `updateUrl({ taskId })` 走「按 taskId 直接打开」路径(不依赖 batch 列表),并 `pendingCrossFrameSelectRef` 落选中。
- **最小实现**:优先支持「直接按 taskId 打开任意 task」——因为 neighbors 已给确定的 `task_id`,工作台本就支持 `?task=<id>` 直开,不必非得在 batch 列表里。把 `selectTask` 在「目标不在列表」时退化为「URL 直开 + 重新拉该 task 详情」即可,跨 batch 也覆盖。
- 单测:`useWorkbenchShellModel` 的 propagate 逻辑抽出可测函数,模拟「目标不在 tasks 列表」→ 断言走 URL 直开分支。

### 3.4 R4 · sniffer 跨相机一致性透出(向后兼容)

`AxisSnifferService.sniff_dataset` 已逐相机评估(v0.14.2 的 `evaluated`)。扩展返回:

- `per_camera: [{camera_role, best, score}]`(每个有效相机一行,按 score 降序)。
- `agreement: float`(= best 与最终一致的相机占比)。
- `SniffAxisConventionResponse` 增这两个**可选**字段(`None` 默认),老前端忽略不破。
- `AxisConventionPicker`:`agreement < 1` 时显示「N/M 个相机一致,侧/后相机可能误导,已优先正前相机」一行灰字提示。
- **不改** best 选择逻辑(v0.14.2 已正确),只是把过程透出。

### 3.5 R5 · overlay K 自定义 / R6 · ZIP 提示

- R5:`CrossFrameOverlayToggle` 档位从写死 `[0,1,3,5]` 改为可含 `7`、或在 3D 设置里存一个 `maxOverlayK`(localStorage),`useFrameNeighbors` 的 `k` 仍受后端 `[1,20]` 约束。最小化:加 `7` 档即可,K>7 收益递减。
- R6:`upload_zip` 末尾 scene_inference 的 `ValueError`(顶层角色名冲突 / >100 scene)与体积 413 的 detail 文案细化,明确「顶层目录别用 lidar/camera/calib/image/video 当 scene 名;多 scene 请走转换脚本」,链 import-formats.md。
