## 1. 结论

本版恢复 `nuscenes` 导出，但只接受来源确实为 nuScenes、且具备真实 scene、log、map、sample、
sample_data、传感器标定、逐传感器 ego pose 与原始媒体引用的完整 Scene。其它 LiDAR 来源、历史未回填
数据或局部 Scene 导出必须在创建 AsyncJob 前拒绝，不生成固定 token、零时间、单位位姿、空 map 或
伪造 log。

导出使用官方十三张核心 JSON 表：`attribute`、`calibrated_sensor`、`category`、`ego_pose`、
`instance`、`log`、`map`、`sample`、`sample_annotation`、`sample_data`、`scene`、`sensor`、
`visibility`。原始点云、相机图和 map 不重复塞进 ZIP，改用精确保留原相对路径的预签名 manifest
回源；下载后可按 `v1.0-aap` 初始化 nuScenes devkit。

## 2. 范围

- nuScenes 导入脚本保留原始 log / map / sensor / calibrated_sensor / sample_data / ego_pose 元数据，
  同时保存未转换的 `.pcd.bin` 与真实 map 资产；幂等重跑回填历史 Scene。
- 预检逐 Scene 验证来源、完整帧集合、连续 frame index、时间戳、ego pose、原始媒体、map/log、
  传感器合同与相机标定未漂移。
- 确定性 token、sample / sample_data / annotation prev-next、instance 首尾与引用完整性。
- 平台 ego/ISO `box_3d` 转换为全局 translation / quaternion；`size` 映射为 nuScenes 的
  `[width, length, height]`，框内点数从当前 PCD 精确计算。
- 项目与批次预检、后台 ZIP、前端选择入口、用户/开发/API 文档和版本源同步。

## 3. 非范围

- 不导出 sweep、radar、lidarseg、panoptic、预测结果或多相机 COCO。
- 不声明兼容官方 detection / tracking benchmark；本版只保证官方 devkit 的 load / query
  合同，类别 ontology 和官方 split 映射留待后续版本。
- 不为非 nuScenes 数据合成 log、map、location、vehicle 或原始传感器标定。
- 不把当前平台 PCD 冒充 nuScenes `.pcd.bin`；导出只引用导入时保留的原始五通道文件。
- 不允许只导出 Scene 的部分帧；批次切断 Scene 时返回稳定预检问题。
- 单次范围不超过 1000 帧和 30000 个有效 3D 框，单帧 PCD 不超过 256 MiB、总 PCD 不超过 4 GiB，精确框内点测试不超过 1 亿次；更大范围的流式导出留待后续版本。
- 不引入 `nuscenes-devkit` 运行时依赖；将它作为 test extra 中的官方兼容性 oracle，
  同时用仓库内验证器冻结字段、外键和链合同。

## 4. 数据流

```text
nuScenes source tables + raw media
            │ import / idempotent backfill
            ▼
Scene.source_metadata + DatasetItem.metadata + SceneFramePose + raw object keys
            │ strict project/batch preflight
            ▼
Frozen LidarFrameExportCtx ──► deterministic serializer ──► 13 JSON tables
            │                                      │
            └──────────────► exact media manifest ─┘
                                                   │ fetch_nuscenes_media.py
                                                   ▼
                                      devkit-readable v1.0-aap tree
```

## 5. 实施与验收

1. **来源保全**：扩展 importer 与 lite fixture；验证新导入和幂等重跑均回填原始点云、map 与元数据。
2. **严格预检**：项目 / 批次覆盖来源缺失、Scene 不完整、pose / timestamp 缺失、媒体缺失和标定漂移。
3. **纯序列化器**：固定两 Scene、每 Scene 三帧、跨帧轨迹、旋转 ego pose 与无 track 单帧对象 golden。
4. **ZIP 与回源**：十三张表、`media_manifest.json`、下载脚本、README 与引用验证器全部通过；
   回源测试资产后可用官方 `NuScenes(version="v1.0-aap", dataroot=...)` 初始化并查询核心引用。
5. **前端与文档**：启用 nuScenes 选项；失败时展示逐帧问题，成功时允许入队。
6. **发布收口**：合并现有 `Unreleased` 修复，更新四处版本源、lock、OpenAPI、CHANGELOG 并跑全量门禁。

## 6. 回滚

若引用完整性或 devkit 兼容门失败，只重新禁用 `nuscenes` 前端选项并恢复预检拒绝；已回填的来源元数据与
原始资产保留，不修改 Annotation、SceneTrack 或现有 KITTI / Point Mask 导出。Dataset 删除后仍保留
`_nuscenes/source` 资产，避免已签发导出包在链接有效期内无法回源；可证明无引用的延迟 GC 不在本版范围内。

最脆弱的假设是：目标项目的 nuScenes Scene 可以通过导入源重跑获得真实 map/log 与原始 `.pcd.bin`。
若源数据已丢失，严格预检会保持拒绝，不能用平台现有 PCD 或默认地图绕过。

## 7. 实施结果

- importer 已冻结并幂等回填原始 scene、log、map、sample、sample_data、sensor、calibrated_sensor、
  ego_pose 与媒体指纹；新数据集使用 Dataset UUID 隔离对象前缀，来源漂移会在任何对象写入前拒绝。
- 项目与批次预检会在创建 AsyncJob 前拒绝非 ego 来源、部分 Scene、断裂引用、位姿/时间漂移、
  标定漂移、媒体大小/SHA-256 不一致或超过 1000 帧 / 30000 个有效 3D 框的范围；后台构建前再次执行同一合同。
- 导出生成确定性的十三张核心表、精确点数、全局框、跨帧 instance 链、原路径媒体清单、回源脚本
  和说明文档；缓存键已覆盖 Task 范围、Scene、位姿、传感器条目和来源指纹。
- 前端入口、用户/开发/API 文档、Roadmap、CHANGELOG、四处版本源、lock 与 OpenAPI 快照已同步。
- 官方 `nuscenes-devkit` 集成用例已物化两 Scene、六 sample 的导出树，完成 `NuScenes` 初始化、
  核心引用查询和原始 LiDAR 文件读取；该结论不扩展为官方 detection/tracking benchmark 兼容声明。

验证结果：定向后端 45 项通过；全量 API 3395 项通过、9 项跳过；Web 3050 项通过；lint、
typecheck、OpenAPI 合同和文档站构建均通过。
