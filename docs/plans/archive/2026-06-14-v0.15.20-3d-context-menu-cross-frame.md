## 1. 背景与核心疑惑

### 1.1 用户的两个疑惑(本版要正面回答)

> ①「这个**目标帧**会让用户疑惑——和 task 名、图片名都没有任何关联。」
> ② 批量延续「放在**左上角视角组件**里面不合适……3D 工作台的选中右键菜单还没实现,看看能不能联动。」

**症结判断**:这两点是同一个病的两个症状——

- **位置错配**:`CrossFrameInterpolateBar` 和「重置视角 / 俯视 / 重置相机布局」并排塞在同一个左上角浮条里,把「我**怎么看**场景」(视角控制)和「我**对标注做什么**」(延续/插值)两类语义混为一谈。
- **坐标错配**:「目标帧」是一个**系统内部坐标**(`frame_index` 整数),却要用户拿它去指代一个他实际上靠**画面内容 / task** 来认知的对象。用户既不知道"当前是第几帧",也不知道要填的数字对应哪个 task / 哪张图;填错了还可能撞上 `±20` 反查范围限制被直接拒。

「对标注的操作」应当跟着标注对象走 → 进右键菜单;「指定哪一帧」应当让用户**看着内容选**,而非填坐标。

### 1.2 现状(已读源码)

**批量延续 / 目标帧 UI**:
- `CrossFrameInterpolateBar` 挂在视角浮条 `.controls`(`ThreeDWorkbench.tsx:2106-2119`,CSS `top:12px left:12px`),与视角按钮并排。
- 「目标帧」是 `<input type="number">`(`CrossFrameInterpolateBar.tsx:100-108`),变量 `targetFrameRaw`/`targetFrame`,值为 `frame_index`(0 ~ `scene_total_frames-1`),超 `±20` 邻帧反查范围报错"请先跳到更近的帧分段操作"。
- 三个回调实现在壳层:`crossFramePropagateBatch`(`useWorkbenchShellModel.tsx:973`)、`crossFramePropagateToTask`(`:1029`)、`crossFrameInterpolate`(`:1072`)。
- 快捷键:单框延续 `Shift+→/←`、批量延续 `Ctrl+Shift+→/←`(`ThreeDWorkbench.tsx:920-949`,`hotkeys.ts:104-105`)。

**3D 右键菜单**:目前**完全没有**。仅有一个全局 `contextmenu` 监听用于拖拽中取消预览(`ThreeDWorkbench.tsx:1540-1552`),viewport `div` 上**没有** `onContextMenu`,可直接挂载无冲突。

**2D 工作台已有可复用基建**:
- `apps/web/src/components/ui/ContextMenu.tsx`(Portal + Esc/外点关闭 + 自动翻转,`z-index:60`)。
- `DropdownItem` 接口(`components/ui/DropdownMenu.tsx:15-32`):支持 `label / icon / kbd(快捷键徽章) / active / divider / disabled / onSelect`。
- `useCanvasContextMenu`(菜单开合 + 坐标 state)。
- 菜单项构建范本 `imageStageContextMenu.ts`(`buildImageContextMenuItems:66-175`)与集成范本 `stage/ImageStage.tsx`。

**3D 已有右栏标注列表面板(关键更正)**:
- `AIInspectorPanel` 在 `WorkbenchLayout.tsx:156`(嵌入)/`:225`(浮窗)渲染,`WorkbenchLayout` 是**所有 stage 共享的布局层**,右栏显隐由 `rightShouldRenderEmbeddedPanel` 控制、**不按 stage 区分** → 3D 同样有此列表面板。
- 列表行**已带对象操作**:`AIInspectorPanel.tsx:961-963` 已接 `onDeleteUserBox` / `onChangeUserBoxClass` / `onToggleUserBoxFlag(id, "is_locked" | "is_hidden")`(删除/改类别/锁定/**隐藏**全有),走壳层回调、stage 无关。
- inspector props 由壳层 `useWorkbenchShellModel.tsx:2255` 无条件供给(不因 3D 消失);列表不按 `geometry_type` 过滤 → `box_3d` 照常进列表。

**两套操作入口(本版只新增第②套)**:
| 入口 | 现状 | 说明 |
|---|---|---|
| ① 右栏列表行 | ✅ 已有 | 删除/改类别/锁定/隐藏,走壳层 `onDeleteUserBox`/`onChangeUserBoxClass`/`onToggleUserBoxFlag` |
| ② 画布就地右键 | ❌ **缺** | 本版要补;**复用①同源的壳层回调**,不新写逻辑 |

**画布交互/快捷键的内部回调(供右键即时项复用)**:`handleDeleteSelected`(`ThreeDWorkbench.tsx:1084`)、`handleChangeClass`(`:1094`,支持批量)、`handleToggleLock`(`:1229`)、`copySelected`(`:1409`)、`pasteClipboard`(`:1416`);**复制/粘贴是画布专属**(列表行没有),右键走这两个。隐藏在画布内无独立 handle,但壳层 `handlePatchShapeFlag(id,"is_hidden",v)` 早有且列表在用 → 右键**复用壳层回调即可,无需新写**。`is_locked`/`is_hidden` 是 annotation 字段(`types/index.ts:401-402`),2D/3D 共用模型,PATCH 走既有 `update` mutation。z-order 移顶/底 3D 无、本版也不做。

**选中机制**:`pickBox(clientX, clientY)`(`PointCloudScene.ts:886-899`,Raycaster 命中返回 `boxId`);选中态 `selectedId` / `selectedIds` 由壳层管理(`ThreeDWorkbench.tsx:104-106`),`onSelectBox(id, {shift})` 写入。

**邻帧缩略图数据源(Layer 2 用)**:
- 点云**无** BEV 预渲染缩略图;`dataset_item.thumbnail_url` 是给图像/视频帧的,点云帧没有。
- 但每帧关联的**相机图**现成:当前帧经 `GET /tasks/{id}/point-cloud/manifest` 的 `manifest.cameras[].image_url` 取得(`ThreeDWorkbench.tsx:1611-1627`)。
- 邻帧相机图可取,但需"逐帧拉 manifest"——`neighbors` 只返回 `{task_id, frame_index}`(`schemas/scene.py:39-56`),不含图;前端 `useNeighborPointClouds.ts` 已经在做"neighbors → 逐帧拉 manifest"这个模式,filmstrip 可复用。

### 1.3 做什么 / 不做什么

**做**:
- 3D viewport 挂 `onContextMenu`,按 `pickBox` 命中与否**分流**:命中框 → 框操作菜单;空白 → 帧级(批量)菜单。
- 新建 `threeDContextMenu.ts` 构建菜单项(对标 `imageStageContextMenu.ts`),复用 `ContextMenu` + `useCanvasContextMenu`。
- 通用操作(删除/改类别/锁定/隐藏)右键项**复用与右栏列表同源的壳层回调**(`onDeleteUserBox`/`onChangeUserBoxClass`/`onToggleUserBoxFlag`),复制/粘贴复用画布 `copySelected`/`pasteClipboard`;**无需新写隐藏回调**。
- 即时延续也进菜单(延续到上/下一帧、批量延续上/下一帧),菜单项带 `kbd` 徽章教学快捷键。
- 「延续到指定帧 / 插值填充」点击后弹**二级帧选择 popover**:
  - **Layer 1**:回显「当前第 X/N 帧」、目标帧回显「→ 第 Y/N 帧」、「+5 / +10 / 到末帧」语义步进、数字精确兜底。
  - **Layer 2**:横向**相机图缩略图条**(±5 帧),点选/hover 预览设为目标帧。
- **移除** `CrossFrameInterpolateBar`,左上角浮条只留视角控制。

**不做**(明确边界):
- **z-order「移到顶层/底层」不搬进 3D**:3D 空间无 2D 那种图层遮挡语义,z-order 对点云框无意义。
- **不动右栏标注列表面板**:`AIInspectorPanel` 本就 stage 无关地对 3D 渲染、已带行级操作;本版只新增**画布就地右键**这一入口,不改列表面板本身(无需新建)。
- **不改延续/插值后端**:`propagate-to-task` / `propagate-batch` / `interpolate-range` 端点与 service 逻辑不动。
- **暂不新增后端 batch 缩略图端点**:Layer 2 先走"逐帧拉 manifest + React Query 缓存";仅当 C 阶段实测请求数/延迟不可接受,才评估 `GET /tasks/{id}/neighbors-manifest?k=`(本版不做)。
- 快捷键集合不变(`Shift+→/←`、`Ctrl+Shift+→/←` 保留),本版不给"隐藏"分配新快捷键。

### 1.4 成功判据

1. **右键分流正确**:右键命中某框 → 先选中该框 → 弹「框操作」菜单;右键空白 → 弹「帧级(批量)」菜单。
2. **现有操作零回退**:删除 / 改类别 / 锁定 / 复制 / 粘贴 / 单框延续(上下) / 批量延续(上下)全部可从右键菜单完成,且原快捷键行为不变;菜单项右侧 `kbd` 徽章与实际快捷键一致。
3. **隐藏/显示经右键可用**:复用与右栏列表同源的壳层 flag 回调,右键「隐藏」→ `is_hidden=true` 即时不渲染、右栏列表同步;再右键「显示」恢复。
4. **目标帧不再是裸数字**:打开帧选择 popover 能看到「当前第 X/N 帧」;选目标帧时有「+5/+10/到末帧」步进与相机图缩略图条;选中即回显「→ 第 Y/N 帧」;数字输入仅作精确兜底。不再能选出超 `±20` 反查范围的帧(步进/缩略图天然受限)。
5. **旧浮条移除**:`CrossFrameInterpolateBar` 从视角浮条消失,浮条只剩视角控制;延续/插值功能经右键菜单完整可达,无功能缺失。
6. **降级**:非 scene task(`manifest.scene_id == null`)右键菜单**不出现**延续/插值/帧级项(与现有 gating 一致);通用操作(删除/改类别等)正常。
7. `pnpm test`(含新增菜单项构建 / 帧选择纯函数单测)、`pnpm lint`(含 `check-css-tokens`)全绿。

## 3. 各模块设计要点

### 3.1 右键触发与命中分流(ThreeDWorkbench)

- viewport `div` 加 `onContextMenu={handleContextMenu}`,`e.preventDefault()` 后用 `sceneRef.current?.pickBox(e.clientX, e.clientY)` 判定:
  - **命中 boxId**:若未选中则先 `onSelectBox(boxId)`,记录 `contextTargetId = boxId`,`contextMenu.openAt(x, y)` → 走「框操作」菜单。
  - **未命中(null)**:`contextTargetId = null` → 走「帧级(批量)」菜单。
- 与既有"拖拽中右键取消预览"(`:1540-1552`)的关系:仅在**非拖拽态**才弹菜单;拖拽进行中右键仍走 `cancel()`。用拖拽状态 flag 区分,避免两者打架。
- 复用 2D 的 `useCanvasContextMenu`(开合/坐标);`<ContextMenu>` 的 `z-index:60` 高于浮条,正常覆盖。

### 3.2 菜单项构建(threeDContextMenu.ts,对标 imageStageContextMenu.ts)

两套菜单项,由 `contextTargetId` 是否为空决定渲染哪套:

```
命中框(contextTargetId != null)          空白(contextTargetId == null)
┌──────────────────────────┐            ┌──────────────────────────────┐
│ 延续到下一帧      Shift+→ │            │ 批量延续到下一帧 Ctrl+Shift+→ │
│ 延续到上一帧      Shift+← │            │ 批量延续到上一帧 Ctrl+Shift+← │
│ 延续到指定帧…             │            │ 批量延续到指定帧…             │
│ 向后插值填充…             │            └──────────────────────────────┘
│ ──────────               │
│ 改类别                    │   ← 复用 handleChangeClass
│ 隐藏 / 显示               │   ← 新 handleToggleHidden(按 is_hidden 切 label/icon)
│ 锁定 / 解锁               │   ← 复用 handleToggleLock(按 is_locked 切 label/icon)
│ 复制              Ctrl+C  │   ← 复用 copySelected
│ 粘贴              Ctrl+V  │   ← 复用 pasteClipboard
│ ──────────               │
│ 删除                 Del  │   ← 复用 handleDeleteSelected
└──────────────────────────┘
```

- 即时项(上/下一帧、批量上/下)直接 `onSelect` 调对应回调,无需输入,带 `kbd` 徽章。
- 「延续到指定帧… / 向后插值填充… / 批量延续到指定帧…」`onSelect` 打开 **FramePicker**(§3.4),不在菜单内放输入框。
- gating:`manifest.scene_id == null` 时,延续/插值/帧级项整体不构建(与现有 `CrossFrameInterpolateBar` 的 scene 门控一致);通用操作不受影响。
- 锁定态框的删除/改类别按现有语义(若 2D 对 locked 框有禁用约定,3D 对齐)。

### 3.3 通用操作右键项 · 复用列表同源回调(零新逻辑)

- 删除/改类别/锁定/隐藏右键项的 `onSelect` **直接调与右栏列表同源的壳层回调**:`onDeleteUserBox` / `onChangeUserBoxClass` / `onToggleUserBoxFlag(id, "is_locked"|"is_hidden")`。这些回调列表行(`AIInspectorPanel.tsx:961-963`)已在用、stage 无关 → 右键与列表行为天然一致,**无需新写 `handleToggleHidden`**(壳层 `handlePatchShapeFlag` 已处理 `is_hidden`,渲染侧 `:709` 已读)。
- 复制/粘贴列表行没有,右键走画布内部 `copySelected`(`:1409`)/`pasteClipboard`(`:1416`)。
- **接线前提**:壳层 inspector 回调目前经 `WorkbenchStageHost` 未透传给 3D stage(2D 才传)。实施时择一:(a)把这几个回调透传进 `ThreeDWorkbench`(与列表同源,推荐);(b)右键直接调画布内部 `handleDeleteSelected`/`handleChangeClass`/`handleToggleLock`,隐藏仍走壳层 flag。优先 (a) 以保证右键与右栏列表完全一致。
- 多选场景:若 `selectedIds.length > 1` 且右键的是其中一员,延续/改类别/删除等按现有"批量"语义作用于整组(与 `handleChangeClass` 已支持批量一致);否则只作用当前 `contextTargetId`。

### 3.4 帧选择 popover · Layer 1(FramePicker)

打开时机:菜单点「延续到指定帧 / 插值填充 / 批量延续到指定帧」。一个轻量 popover(定位在鼠标点附近,复用 ContextMenu 的翻转避溢出思路),内含:

- **当前帧回显**:「当前 第 X / N 帧」(`X=neighbors.frame_index`,`N=scene_total_frames`,数据现成)。
- **语义步进按钮**:`+5` / `+10` / `到末帧`(`prev` 侧对应 `-5/-10/到首帧`)。点击即把目标帧设为对应值并钳到 `[0, N-1]` ∩ `±20` 反查范围,天然不越界。
- **目标帧回显**:选定后显示「→ 第 Y / N 帧」;若能从 manifest/neighbors 低成本拿到 task/图片标识则附带(加分项,拿不到不阻塞)。
- **数字精确兜底**:保留一个 `number` input 作高级精确控制,范围/校验沿用现有 `CrossFrameInterpolateBar` 逻辑(迁移而非重写)。
- **动作**:popover 底部给「延续到此帧」/「插值填充到此帧」按钮,分别调 `crossFramePropagateToTask` / `crossFrameInterpolate`(经 neighbors 反查把 frame → target_task_id)。两动作**共用同一选择器**。

> Layer 1 不依赖任何新数据,纯前端用既有 `neighbors`(frame_index / scene_total_frames)即可,低风险先落地。

### 3.5 相机图缩略图条 · Layer 2(useNeighborFrameThumbs + FramePicker)

- 在 FramePicker 顶部加一条横向 filmstrip:展示当前帧 ±5 帧的**相机图缩略图**,当前帧高亮,点缩略图即设为目标帧,hover 放大预览。
- 取图:`useNeighborFrameThumbs(taskId, k=5)` → 复用 `useNeighborPointClouds` 的"neighbors → 逐帧 `point-cloud/manifest`"模式,取每帧 `manifest.cameras[0].image_url`,React Query 缓存(`staleTime` 复用 manifest 既有配置)。
- 性能:±5 ≈ 最多 10 个 manifest 请求,首屏并发、命中缓存后近乎免费;`<img>` 用 `max-width` 缩小显示,不额外渲染点云。仅当实测请求数/延迟不可接受才评估后端 batch 端点(本版不做,见 §1.3)。
- 缺图降级:某邻帧无相机图 → 该格显示占位(帧号),不阻塞其余;整 scene 无相机图 → filmstrip 隐藏,回落到 Layer 1 的步进+回显。
- 样式:缩略图边框/高亮色取 `tokens.css` 既有语义色,**不硬编码颜色**(CLAUDE.md §6);如需新语义色先在 `tokens.css` 补 light+dark。

### 3.6 移除旧浮条(收尾)

- 从 `.controls` 浮条删除 `<CrossFrameInterpolateBar>` 挂载,删除组件文件及其 CSS;浮条只剩「重置视角 / 俯视 / 重置相机布局 / 点选模式」。
- `crossFramePropagateBatch / crossFramePropagateToTask / crossFrameInterpolate` 三个壳层回调**保留**(改由右键菜单 + FramePicker 调用),不动其实现。
