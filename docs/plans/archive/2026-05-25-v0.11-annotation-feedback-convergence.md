## 核心约束：统一表**不持有**旧表的 kind 专属字段

切单源真正难的原因。`annotation_feedbacks` 是 4 源公共并集，每张旧表都有独有列/子资源：

| 旧表 | 统一表没有的专属字段 / 子资源 |
|---|---|
| `bug_reports` | `display_id`、`route`、`user_role`、`duplicate_of_id`、诊断上下文（`browser_ua`/`viewport`/`recent_api_calls`/`recent_console_errors`/`screenshot_url`）、`resolution`、`fixed_in_version`、`assigned_to_id`、`triaged_at`/`fixed_at`、`reopen_count`/`last_reopened_at`；子表 `BugComment`；status 值域 `open/triaged/fixed/duplicate/wontfix`（≠ 统一表 `open/resolved/wont_fix`） |
| `annotation_comments` | `is_resolved`（布尔，非 status）、`mentions`、`canvas_drawing`、`anchor`（≠ `anchor_position`） |
| `tasks.reject_reason` | `reject_reason_type`（4 类枚举）；reject 是 **task 状态机字段**，非独立行 |

**v0.11.8 ADR 决策（refined-C，已认同）解开了这个约束**：不强行物理合并 4 类。`v_annotation_feedback_unified` view 已是免费的统一读表面，故——
- **comment + issue** 单源进 `annotation_feedbacks`（comment 是唯一需真迁的旧表）；
- **bug 留 `bug_reports`、reject 留 `tasks`**（权威源不动），统一读走 view。

→ bug 的 15 字段 / `BugComment` / `display_id` / `project_id IS NULL`、reject 的 task 状态机耦合**全部不再是迁移对象**，第三段从"大迁移"降级成"一次 comment 迁移 + 撤两个 mirror"。

## 成功判据（§2.2 收敛完成的定义，refined-C 口径）

1. 无双写：comment/issue 单源写 `annotation_feedbacks`；bug/reject 单源写 `bug_reports`/`tasks`；任何 kind 不再两处写。
2. 统一读表面唯一：`v_annotation_feedback_unified` view 永久 UNION 4 源，LLM 聚类去重 / Webhook fan-out / 全局检索都查它。
3. 前端 comment/issue/history 走统一 DiscussionPanel；bug/reject 保留各自专用入口（BugReportDrawer / 审核流）。
4. `annotation_comments` drop；`bug_reports` / `tasks` 保持权威不动。
5. 新增**标注类**反馈类型零成本（落 `annotation_feedbacks`）；新增跨源消费（LLM/webhook）零成本（落 view）。
