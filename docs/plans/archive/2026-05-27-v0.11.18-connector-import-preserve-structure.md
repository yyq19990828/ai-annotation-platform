# v0.11.18 · 连接器导入保留源目录结构 + 路径名自动命名数据集

- 日期：2026-05-27
- 关联：v0.11.14~16 连接器导入 epic（`2026-05-26-v0.11.14-16-dataset-import-connectors-epic.md`）的增量优化
- 状态：已实施（前后端 + 单测 + 文档，CHANGELOG [0.11.18]）

## 1. 背景与动机

当前从存储连接器（S3/SFTP）导入数据集时存在两个不便：

1. **目录被拍平**：`ingest_one()` 用 `_safe_basename(relpath)` 只取文件名，源里的
   `a/img.jpg`、`b/img.jpg` 进来后都变成 `{dataset}/img.jpg`，子目录结构丢失，同名文件还要加
   `-1/-2` 后缀。
2. **数据集名要手填**：选了连接器的某个路径后，还得另外想一个数据集名。

用户的真实诉求：**选连接器的某个路径（如 `dataset-A`）→ 直接拿路径末段当数据集名（可改）→
导入后数据集内部目录结构与源一致**。这样「源文件夹 = 数据集」，文件夹内部结构 = 数据集内部结构；
后续源里新增 `c/` 时，对同一数据集再导一次即可（内容哈希去重自动跳过 `a/`、`b/`）。

### 关键根因

- `app/services/dataset.py:282` —— `source_name = _safe_basename(relpath)`，砍掉目录。
- `obj.relpath`（来自 `S3CompatibleSource._rel_from_key`）是**相对连接器根 base_prefix** 的，
  会带上 `source_path` 那一段。若原样保留会**多嵌套一级**（`{dataset}/dataset-A/a/img.jpg`）。
  正确做法是剥掉 `source_path` 前缀，只保留 source_path **内部**的子路径。

## 2. 设计决策（已与需求方确认）

1. 这套行为只作用于**连接器导入**这条路；本地多文件、ZIP 两条路不动。
2. `source_path` 末段自动作为数据集名，**可重命名**；路径为空则回退连接器名或留空。
3. **保留目录结构 = 连接器导入的默认行为**，不加「保留子目录」勾选框（避免多余配置）。
4. 前端向导 **Step1 / Step2 对调**：先「选择来源」，再「基本信息」，让自动命名顺其自然。

## 3. 影响面分析（`file_name`/`file_path` 含 `/` 之后）

> `file_name`: `img.jpg` → `a/img.jpg`；`file_path`: `{name}/img.jpg` → `{name}/a/img.jpg`

| 组件 | 文件:行 | 结论 |
|---|---|---|
| 关联项目 / 建任务 / 分包 | `dataset.py:657-658`、`task.py` | ✅ 无影响，仅存值，无唯一约束 |
| 当前导出（live） | `export_packaging.py:189/358/370` + `relative_path_from_file_path()` | ✅ 无影响，本就用 file_path 算相对路径 |
| 缩略图 / 视频元数据 | `media.py:549`（UUID key）、`:596`（`Path.suffix`） | ✅ 无影响 |
| 前端展示 | `DatasetsPage.tsx:259`、`AnnotatePage.tsx:60` | ✅ 无影响，纯文本 + truncate |
| 去重 `_unique_file_name` | `dataset.py:410/414`（`os.path.splitext`） | ✅ 无影响，正确保留目录 |
| **旧 ExportService YOLO** | `export.py:675-676` | ⚠️ `labels/{base}.txt` 会按子目录嵌套 |
| **旧 ExportService VOC** | `export.py:735-737` | ⚠️ `Annotations/{xml}.xml` 会按子目录嵌套 |
| **导入端 `_safe_basename`** | `dataset.py:282` | ❗必改，否则结构仍被砍 |
| **`scan_s3_bucket`** | `dataset.py:516` | ❗必改，当前只传叶子名 |

旧 `ExportService` 仍被 `batches.py:884`、`projects.py:950` 调用（非主路径）。其 YOLO/VOC 让标签
进子目录其实**与图片层级一致、属合理行为**，倾向「跟随结构」不改；若担心下载方期望扁平，再用
`os.path.basename()` 兜平（有同名碰撞风险）。本计划默认**不改旧导出**，仅在验收时确认可接受。

## 4. 实施方案

### 4.1 后端

**A. `ingest_one` 支持目标相对路径（`app/services/dataset.py`）**

- 新增可选参 `dest_relpath: str | None = None`。
  - 给定时：清洗后（`normalize_relpath`，挡 `..`/前导 `/`）用作 `file_name`，
    `storage_key = f"{ds.name}/{dest_rel}"`。
  - 不给时：维持现有 `_safe_basename(relpath)` 行为（`scan` 旧调用、其它调用零影响）。
- `_unique_file_name` 沿用（`splitext` 对带 `/` 路径行为正确）。
- 内容哈希去重逻辑不变（这正是「补 c/ 时跳过已有」的机制）。

**B. 导入 worker 计算 source 相对子路径（`app/workers/dataset_import.py`）**

- 对每个 `obj`：`dest_rel = strip_source_prefix(obj.relpath, source_path)`，传入
  `ingest_one(..., dest_relpath=dest_rel)`。
- `strip_source_prefix`：`src = normalize_relpath(source_path)`；若 `relpath` 以 `src + "/"`
  开头则去掉该前缀，否则原样（source_path 为空 → 整体保留；单文件 → basename）。
- 注意 `relpath` 是 base_prefix 相对、`source_path` 是用户输入；base_prefix 非空且用户输入已含
  base 的边界情况，实现时以 adapter 暴露的 listing prefix 或 `_rel_from_key` 对齐后再 strip，
  并以单测覆盖。

**C. `scan_s3_bucket` / `scan_and_import` 保留相对路径（`app/services/dataset.py:498-520`）**

- 列举对象时把相对数据集前缀的**完整子路径**作为 `dest_relpath` 传入，而非 `key.rsplit('/')[-1]`。

### 4.2 前端（`apps/web/src/components/datasets/ImportDatasetWizard.tsx`）

1. **Step1/Step2 对调**：`STEP_LABELS`、`stepNums`、`step` 初值、`goNextOrSubmit`、`Footer`
   的 prev/next 与校验时机相应调整；`skipCreate`（追加到已有数据集）仍只显示「来源」步。
2. **连接器选完路径自动命名**：`onSetSourcePath` 时，若用户尚未手改过名字，将
   `name` 设为 `sourcePath` 末段（`split('/').filter(Boolean).pop()`）；空路径回退连接器名。
   用一个 `nameTouched` 标志区分「自动填」与「用户手改」。
3. **校验时机**：名字非空校验从「Step1 进 Step2 的 gate」挪到**提交前**（`ensureDataset` 前）。
4. files / zip 模式不享受自动命名（无文件夹来源），仍手填，逻辑不变。

- 「数据集记住来源 + 一键重新同步」（之前讨论过，已被需求方降级，不做）。

- 本地多文件 / ZIP 的文件夹选择与层级保留 —— 不做。
- 旧 `ExportService` YOLO/VOC 的扁平化改造 —— 默认不改，验收时确认行为可接受。
