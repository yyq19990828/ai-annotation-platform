# v0.12.5 · 成员绩效 CSV 导出 + 项目维度下钻(A2)

> 轨道 A 第二刀。路线见 [annotator-performance-deepening](2026-06-03-annotator-performance-deepening.md) §A2。

## 范围澄清(动手前的实情校正)

计划 §A2 原设想「点 reject 数/类别 → 复用现有 tasks 查询 + query param 跳过滤列表」。落地核查发现该假设过乐观:

- `GET /api/v1/tasks` **`project_id` 必填**,只支持 `status` / `assignee_id` / `batch_id` 过滤,**无** `reject_reason_type`、**无** `class_name`。
- ReviewPage 也只认 `project` / `batch`,且只看 `status=review`。
- 而绩效 detail 的 reject 细分 / 类别覆盖是**跨项目聚合**,落不到「单项目 + 单过滤」的现有列表。

所以 reject/类别下钻需给工作台 tasks 查询新加过滤(触碰 B-16 可见性 + cursor 分页)+ 解决跨项目落点,已非快赢零风险。而 A3(v0.12.6)本就要把这些聚合做成项目级,届时下钻落点天然顺。

**本版定档(2026-06-03 拍板「项目维度下钻」)**:

1. **CSV 导出**(完整):干净、复用 `audit_logs`/`users` 既有 csv 范式 + 直接复用 `admin_people_list` 聚合,零重复。
2. **项目维度下钻**(快赢):detail 抽屉「项目分布」每行 → 链接到该项目 review 队列按本人 assignee 过滤(复用后端**已有** `assignee_id` 过滤 + ReviewPage 加一个 `assignee` query param)。
3. **reject/类别下钻延后并入 A3**(v0.12.6),与项目级聚合改造同切,避免半成品 + 单项目/跨项目落点矛盾。

## 实现

### 后端(`apps/api/app/api/v1/dashboard.py`)
- 新增 `GET /admin/people/export`(super_admin):接收与 `admin_people_list` 同参(role/project/period/sort/q),**直接调用** `admin_people_list(...)` 取 `AdminPeopleList`,再 `csv.DictWriter` 输出。
  - Excel UTF-8 BOM(`﻿`)防中文乱码,对齐 `users.py` 导出。
  - 列:`user_id,name,email,role,status,project_count,main_metric,main_metric_label,weekly_compare_pct,throughput_score,quality_score,activity_score,rejected_rate`。
  - **路由顺序**:必须定义在 `/admin/people/{user_id}` **之前**,否则 `export` 被当 `user_id` 命中详情端点。
  - 新增 import:`csv`、`io`、`StreamingResponse`。

### 前端
- `api/dashboard.ts`:`exportPeople(params)` —— fetch + Bearer + blob 下载,镜像 `usersApi.exportUsers`。
- `pages/Admin/AdminPeoplePage.tsx`:
  - 头部加「导出 CSV」按钮(带当前筛选 role/period/sort/q),失败 toast。
  - `PersonDrawer` 加 `useNavigate`;「项目分布」行改为可点 → `navigate('/review?project=<pid>&assignee=<userId>')` 并关抽屉。
- `pages/Review/ReviewPage.tsx`:读 `assignee` query param → 注入 `taskListParams.assignee_id`。
