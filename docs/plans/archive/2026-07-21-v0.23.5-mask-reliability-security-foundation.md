# v0.23.5 · Mask 编辑可靠性与安全地基

> Status: Completed（退出门已满足）· Epic Phase 1
>
> 父 Epic：[图像 / 视频栅格 Mask 能力统一](../2026-07-21-raster-mask-workbench-unification-epic.md)
>
> 关联决策：[ADR-0052 共享栅格 Mask 与图片 geometry 合同](../../adr/0052-shared-raster-mask-and-image-geometry.md)（本版 Accepted）。
>
> 本版不新增生产 geometry 类型；先让现有图片 polygon 中转和视频 RLE 路径可靠、可诊断、可继续演进。

## 0. 基线校准（vs 原稿三处事实修正）

经代码核验（基线 commit `b71cd2c6`），原稿以下措辞与现状不符，本版纠正：

1. **"无限制 zlib 解压" → 实际不存在 mask 解压路径。** 当前 mask 内容以未压缩 canonical JSON 存储（`apps/api/app/services/raster_mask_storage.py:canonical_rle_bytes`）。本版**新增 gzip 传输 + bounded decompress**（按已确认决定），属 net-new 代码；同时修复真正的无界读取（见 §2 修正项）。
2. **真正的无界读取**在 `apps/api/app/api/v1/ml_backends.py` 的 `predict_frame` / `interactive_annotating_frame`（`await frame.read()` 无 Content-Length 上限）与 mask-content 上传缺 quota。
3. **对象存储 I/O 当前同步阻塞 async loop**：`store_coco_rle` / `load_coco_rle` 在 `async` 调用点直接调用 boto3 sync `put_object` / `get_object`，违反 §2 P3 "对象存储 I/O 不阻塞 async event loop"，本版用 `asyncio.to_thread` 包裹修复。

## 1. 目标

- 消除切题 / 切帧 / 异步加载覆盖未提交笔迹的风险。
- 统一图片 / 视频 Mask 会话状态、stroke undo / redo 和保存失败恢复。
- 关闭锁定、只读、Delete、Enter 与并发提交绕过路径。
- 修复后端解压、帧上传、tracker accept 和 staged 生命周期风险。
- 正确渲染既有 polygon holes / multi_polygon，禁止精修时静默丢环。
- 输出并接受 ADR-0052，为 v0.23.6 的共享 RLE schema 冻结边界。

## 2. 范围

### P0 · 可复现测试先行

- 为视频“加载中落笔后被迟到 GET 覆盖”写集成测试。
- 为图片保存失败后 Buffer 被清空、图片 stroke undo 未接线写测试。
- 为图片 / 视频锁定后 `M → pointer → Enter` 绕过写测试。
- 为视频 Delete 当前 Mask 时误删整轨、context-menu 缺失写测试。
- 为重复 Enter / 双击确认并发上传写测试。
- 为 gzip bounded decompress（zip bomb / 超比 / 超输出）、超大交互帧上传和双 tracker job 并发 accept 同源 annotation 写后端测试。

### P1 · 编辑会话状态机

统一 `idle / loading / ready / dirty / saving / error`：

- `sessionId + generation` 隔离旧请求；task、frame、selection、annotation version 构成 session key。
- loading / saving 禁止 pointer 写入；旧 GET、404 和 mutation 回包不能初始化新 session。
- task / frame / tool / route 离开 dirty 会话时显示“保存 / 丢弃 / 继续编辑”。
- 保存使用单飞 Promise；成功后才清 Buffer，失败保留 history、label、refine lineage 并可 retry。
- 图片 `ImageStage` 接入 `beginStroke / endStroke`，与视频共享 undo / redo 快捷键和工具栏状态。
- Escape 只取消当前 Mask session，不误撤销 annotation history。

### P2 · 权限与操作语义

- 抽取 `canEditMask`，供 toolbar、hotkey、pointer、context-menu、commit 共用。
- 同时检查 task readOnly、annotation / track lock、当前 assignment / segment lock 和 editor state。
- Enter 必须满足 `ready|dirty` 的真实提交条件；无变化不物化 held keyframe。
- Delete 删除图片对象或视频当前关键帧；整轨删除仅走 `Ctrl/⌘+Delete` 或确认动作。
- 图片 prediction refine 使用服务端 decision / lineage；刷新后原候选不复活。
- 单个视频 Mask load 失败只标记该对象，保留其它 records，并提供重试和诊断。

### P3 · 后端安全与并发

- **gzip 传输 + bounded decompress（net-new）**：新增 `apps/api/app/utils/raster_mask_gzip.py`，流式 `zlib.decompressobj`，超任一上限（`MAX_COMPRESSED=8 MiB` / `MAX_UNCOMPRESSED=4 MiB` / `MAX_EXPANSION_RATIO=20`）立即 `raise ValueError`；引用保持 `encoding: "coco_rle_ref"`，对象存储偏好由 `storage_encoding: "identity" | "gzip"` 表示，gzip 对象使用 `.json.gz` key；HTTP 上传压缩仅由 `Content-Encoding: gzip` 表示。SHA-256 仍对未压缩 canonical bytes 计算；前端 `maskRle.ts` 在浏览器支持且满足同一边界时压缩上传，否则回退普通 JSON；下载由服务端解压后返回统一 `coco_rle` JSON（详见 ADR-0052 D6）。
- **交互帧上传 size cap（修复真正的无界读取）**：`predict_frame` / `interactive_annotating_frame` 读 `Content-Length`（> `MAX_FRAME_UPLOAD_BYTES=32 MiB` → 413），用 `await frame.read(chunk)` 流式累计超限即 413；解码后校验宽高 ≤ 4096、总像素 ≤ 16M、格式 ∈ {JPEG, PNG}。
- **tracker accept 并发 → 409**：同事务 `with_for_update` 锁 job 与源 Annotation，校验 `annotation.version` 与 job 发起时记录的 `expected_source_version`（写入 `job.prompt`）、任务状态、assignment 与 segment lock；不等 → `TrackerJobStateConflict`（409），不得 last-writer-wins。
- **accept / discard 后清除或归档 staged 引用**：GC 只保留未终结或仍在宽限期的 job 对象。
- **mask-content upload 增任务权限与 orphan 配额**：`upload_task_mask_content` 补 annotation `is_locked` 检查与 per-task orphan quota（`MAX_ORPHAN_MASK_OBJECTS_PER_TASK=256`）。
- **对象存储 I/O 不阻塞 async event loop（修复现状）**：`store_coco_rle` / `load_coco_rle` 改 `async def`，boto3 sync `put_object` / `get_object` / `delete_object` 调用点用 `await asyncio.to_thread(...)` 包裹（覆盖 `raster_mask_storage.py`、`ml_backends.py:upload_crop_bytes`、`cleanup.py` GC）。

### P4 · Polygon 正确性止血

- `ImageStageShapes` 使用 even-odd fill 渲染 `holes` 与全部 `multi_polygon` 外环。
- selection、bbox、viewport fit、面积和 COCO helper 消费完整几何。
- 现有 Mask refine 若不能无损保存，入口禁用并说明原因；不再静默取最大环。
- 保存失败或版本冲突不丢稿；用户刷新前可复制诊断信息。

### P5 · ADR-0052

新增 `docs/adr/0052-shared-raster-mask-and-image-geometry.md`（本版 Accepted），至少冻结：

- 类型名 `raster_mask`（图片单对象）；视频沿用 `video_track_mask`，不新增单帧 `video_mask`。
- 共享 `coco_rle_ref` schema、泛化图片静态 GET API（`GET /annotations/{id}/mask-content/{frame}`）和 task-context validator。
- polygon ↔ Mask 显式无损 / 有损转换报告、空 Mask 语义、source / parent lineage 字段和独立 read / create feature flag。
- 4096 上限沿用（dims ≤ 4096，pixels ≤ 16M，runs ≤ 1M，canonical ≤ 4 MiB）；tile / sparse 触发条件留 v0.23.10。
- JSONB 加法扩展部署顺序（后端 reader → 前端 renderer → 创建开关）、forward-fix 回滚限制。
- gzip 分层契约（正文 `coco_rle`、引用 `coco_rle_ref`、HTTP `Content-Encoding`、对象 `storage_encoding`）、`.json.gz` key、bounded decompress 常量与未压缩 canonical SHA-256。
- 编辑会话状态机语义（`idle → loading → ready → dirty → saving → error`、sessionId + generation 隔离、单飞保存、`canEditMask` 门）。

## 3. 非目标

- 不创建 `raster_mask` annotation。
- 不改变图片 Mask 默认提交仍转 polygon 的现状，除非只是阻止有损提交。
- 不实现高级笔刷、AI 原生 Mask、格式导入或大图 tile。
- 不重构视频 nearest-hold、Tracker 算法或项目 tool binding。

## 4. 验收

- 图片、视频离开 dirty session 必须经过 guard；旧请求无法覆盖当前 Buffer。
- 保存失败后继续画、undo、redo、retry 均可用，最终只产生一次 mutation。
- 锁定对象经所有 UI / 快捷键路径不可修改。
- 视频 Delete 当前关键帧不删除整轨；整轨删除有明确动作与确认。
- gzip bomb（bounded decompress）、超大帧上传和并发 accept fixture 被前置拒绝（413 / 400 / 409）。
- holes / multi_polygon 渲染与 COCO 输出不再只取主外环。
- ADR-0052 Accepted，v0.23.6 所需合同无开放阻断项。
