# v0.21.18 · useWorkbenchConfig 接入共享 preferences query（首屏冗余 GET 收敛尾项）

状态：**计划（2026-07-07）**。§C.1 项 ① 的**遗留后续**——v0.21.17 已把 `ai.*` 四个偏好 hook 收敛到共享
react-query（`useUserPreferences()`），但明确排除了 `useWorkbenchConfig`（`workbench` 子树，独立 layout 持久化
管道）。它才是首屏 `GET /auth/me/preferences` 冗余的**真正大头**：首屏被 3~4 个实例各自裸 fetch 一次。本计划把它也
接入同一份共享 query。**纯前端**，不改后端 / schema，无 alembic。

**范围裁定（2026-07-07 与用户对齐）**：
- **只做项 ①**（本计划）。
- **项 ②**（PipelineGraphCanvas 每 tick 无谓 `setNodes` re-render）**跳过**——ROADMAP 已反复判低收益高回归，
  拓扑稳定时 react-flow 已 shallow-eq 吸收大部分开销，验证成本却不低。见「不在范围」。
- 刷新语义：**接受共享 query 的 5min staleTime**（不做 `refetchOnMount:'always'`）——工作台偏好几乎都是本人本
  设备改，跨设备即时性要求低；换首屏零冗余 GET。

## 动机（现状，带证据）

`ai.*` 四 hook 已共享 `useQuery({queryKey:["me","preferences",userId], queryFn:authApi.getPreferences,
enabled:!!userId, staleTime:5*60*1000})`（`apps/web/src/pages/Workbench/state/useUserPreferences.ts`），浏览器实测
同 key 去重后仅 fire 1 次。**但** `useWorkbenchConfig`（`apps/web/src/pages/Workbench/state/useWorkbenchConfig.ts`）
完全不走 react-query：

- **读路径是裸 fetch**：`useEffect([userId])` 里 `authApi.getPreferences()` → `mergeUser(res.workbench, userId)`
  → `setUserConfig`（`useWorkbenchConfig.ts:617-639`）。读 `.workbench` 子树，不碰 `ai.*`。
- **首屏 3~4 个实例各拉一次**（模块级 `broadcastConfig` 只同步内存态，不合并网络请求）：

  | 挂载点 | file:line |
  |---|---|
  | `useWorkbenchState()`（shell 主状态，无条件） | `Workbench/state/useWorkbenchState.ts:112` |
  | `ImageStage`（图片首屏） | `Workbench/stage/ImageStage.tsx:448` |
  | `ImageWorkbench`（图片首屏） | `Workbench/stages/image/ImageWorkbench.tsx:210` |
  | `WorkbenchSettingsDrawer`（`WorkbenchLayout.tsx:370` 无条件渲染，hook 恒挂载） | `Workbench/shell/WorkbenchSettingsDrawer.tsx:55` |
  | `VideoWorkbench`（视频首屏，替代前两项） | `Workbench/stages/video/VideoWorkbench.tsx:126` |

  → 图片项目首屏 **3~4 次**并发相同 `GET /auth/me/preferences`（StrictMode dev 放大即 ROADMAP 实测 6 次）。
- **写完不 invalidate 共享 query**：`update`（`:641-671`）/ `setLayout`（`:701-715`）/ `setFields`（`:718-732`）/
  防抖 flush（`:674-699`）/ 卸载 flush（`:603-615`）全都只 `setUserConfig` + `broadcastConfig` + `writeLocalLayout`，
  从不碰 `["me","preferences",userId]`。两套管道当前互不感知缓存。

**API**（`apps/web/src/api/auth.ts`）：`getPreferences()` GET `/auth/me/preferences`；
`updatePreferences(payload)` PATCH（后端按顶层子树 `exclude_unset` 合并，可只提交 `{workbench:...}`）。
**关键事实**：PATCH **返回整份 `UserPreferences`**——可直接回灌缓存，无需重拉。

## 定稿决策

- **读 → 复用 `useUserPreferences()`。** 删 `:617-639` 裸 fetch effect，改从共享 query 的 `prefs?.workbench` 经
  `mergeUser` 同步进本地 `userConfig`（与四个 ai hook 完全对称，消掉 3~4 次并发 GET）。首帧仍用初始 state
  （`:577-579` 的 `user?.preferences?.workbench` + `preferLocalLayout`）防 layout 闪。
- **写 → `setQueryData` 整份回灌，不 invalidate。** `update`/防抖 flush/卸载 flush 成功拿到 PATCH 返回的整份
  `UserPreferences` 后，`queryClient.setQueryData(userPreferencesQueryKey(userId), resp)`。整份返回值无子键覆盖风险
  （区别于 ai hook 的子键浅替换必须走 invalidate），且省一次 GET。切账号由 query key 带 `userId` 自然隔离。
- **保留不动**：① `broadcastConfig` 内存广播（抽屉↔画布乐观预览即时性，query 缓存不够即时）；② `mergeLayout` /
  `readLocalLayout` / `writeLocalLayout` 的**本地 layout 优先**管道（共享 query 返回的 `workbench.layout` 仍须走
  `mergeLayout` 本地优先合并，不能被远端整片覆盖——这是主要副作用面）；③ 防抖 flush + 卸载 flush 语义。
- **刷新语义 → 沿用 5min staleTime**，不加 `refetchOnMount`。跨设备改偏好最长延迟 5min，可接受。

## 实现分阶段

- **WS1 · 读接入共享 query**：`useWorkbenchConfig` 引入 `useUserPreferences()` + `useQueryClient`；删裸 fetch
  `useEffect([userId])`；新增监听 `prefs?.workbench` 变化 → `mergeUser` → `setUserConfig`（保留 `broadcastConfig`）。
- **WS2 · 写回回灌**：`update` / 防抖 flush / 卸载 flush 成功后 `setQueryData(key, resp)` 整份回灌。
- **WS3 · 验证**：网络面板确认图片/视频工作台首屏 `/me/preferences` 从 3~4 次降到 **1 次**（与 ai hook 共享）；
  改设置抽屉里通用/图片/视频/点云/布局各类字段 → 画布实时预览生效（broadcast）、PATCH 落库、重进工作台保持；
  **layout 本地优先回归重点**：浮窗位置/折叠等 localStorage 双写值不被远端覆盖、跨设备不串；跨用户切换不脏写。
- **WS4 · 版本**：CHANGELOG（`### Changed` 归「首屏 preferences 请求收敛」）+ 版本源同步 bump（§10）。

## 风险

- **layout 本地优先被远端覆盖（主风险）**：`workbench.layout` 有 localStorage 优先逻辑（`preferLocalLayout` /
  `mergeLayout`）。接入共享 query 后，query data 变化触发的 `setUserConfig` 必须仍走 `mergeLayout` 本地优先，
  不能拿远端 `workbench.layout` 整片盖掉本地。WS3 必须专项回归浮窗坐标/折叠态。
- **多实例本地态 vs 共享缓存一致性**：3~4 实例仍各自维护 `setUserConfig` 本地态（乐观 + broadcast）。共享 query
  只负责初始/refetch 同步与写后回灌；要确保 `setQueryData` 回灌后各实例经 query 订阅拿到同一份，不与 broadcast
  打架（broadcast 走内存即时、query 走回灌兜底，二者应指向同一 resp）。
- **切账号 / pending flush**：query key 带 `userId` 隔离拉取，但防抖 pending 在 key 切换/登出时仍须 flush 或丢弃
  （现有卸载 flush `:603-615` 等价保留），否则跨用户脏写。
- **收益量级诚实**：省 2~3 个**已并发**（非串行阻塞）的 GET，属「随手」级；价值在首屏该端点压到 1 次 + 统一
  preferences 数据源，不是性能瓶颈修复。
