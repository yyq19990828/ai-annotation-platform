# v0.11.26 · 视频工作台时间轴外观/布局优化

日期：2026-05-29
范围：`apps/web/src/pages/Workbench/stage/VideoPlaybackOverlay`（CSS 为主，不动 JSX 结构）

## 背景

视频底部播放浮层（`VideoPlaybackOverlay`）的时间轴存在两个用户实测痛点：

1. **进度条圆点（playhead thumb）过大遮挡信息**
   `tokens.css:185-211` 的 thumb 为 16×16px 圆点，居中盖在 4px 轨道上，左右覆盖 ±8px。
   而同轨道上的关键帧圆点仅 7px、grid 刻度 1px、loop 高 4px、书签/issue 三角 8px，
   16px 圆点会压住相邻关键帧与刻度，干扰读取。

2. **进度条宽度随帧数位数 / loop 状态变短**
   `VideoPlaybackOverlay.module.css:1-10` 的 grid 为
   `grid-template-columns: auto minmax(180px, 1fr) auto`，总宽固定 `min(820px, 100%-28px)`。
   第 3 列 `.status`（`white-space: nowrap`，`auto` 宽度）内容一变宽就吃掉中间 `1fr` 进度条：
   - 帧数 个位→百位，`F x/y` 变长（`tabular-nums` 只保证同位数对齐，跨位数总宽仍变）→ 进度条变短；
   - 出现 `Loop a-b` 标签 + `清除` 按钮时状态列骤宽 → 进度条进一步被挤压。

   > 注：先前调研报告称"Loop 与进度条布局完全分离、不挤压"，经核实有误——
   > 三者同处一个固定宽度的 grid 行，第 3 列变宽必然挤压第 2 列。

## 目标 / 成功标准

- P0-1：playhead 不再遮挡相邻关键帧/刻度，仍能清晰指示当前位置且可拖动。
- P0-2：进度条宽度恒定，不随帧数位数或 loop 标签出现而变化。
- 不破坏现有交互（seek / shift 拖拽建 loop / 键盘步进 / hover 预览）与所有 `data-testid` 测试。
- 改动尽量局限在 CSS，不改 JSX 结构（保 testid 与单测稳定）。

## 方案

### P0-1 · Playhead 竖线化（`apps/web/src/styles/tokens.css`）

把 thumb 从 16px 圆点改为细竖条 playhead（覆盖 webkit + moz 双实现）：

- `width: 3px`（默认），`height: 16px`（贯穿轨道高度，做位置指示线），`border-radius: 2px`；
- `margin-top` 保持 -6px（相对 4px track 垂直居中，竖条上下贯穿 input）；
- 保留 `background: var(--color-accent)`，白边收细为 `1px`，阴影保留作对比；
- hover/active 时加宽便于抓取：`.video-timeline-range:hover::-webkit-slider-thumb`（及 active、moz 对应）→ `width: 5px`。

竖条仅占 3px 宽，不再压住 7px 关键帧与 grid 刻度；点击轨道任意处仍触发 seek（已有 `onPointerDownCapture`），抓取需求弱化。

### P0-2 · 状态行下移，进度条独占一行（`VideoPlaybackOverlay.module.css`，纯 CSS）

当前 JSX 子元素顺序：`controls` → `timelineShell` → `status`（三个直接子节点）。
改为两行 grid，进度条与控件同行、状态独占第二行横跨整宽：

```css
.overlay {
  grid-template-columns: auto 1fr;   /* 控件 | 进度条 */
  grid-template-rows: auto auto;     /* 行1: 控件+进度条; 行2: 状态 */
  row-gap: 4px;
  /* column gap 仍 12px，total width 不变 */
}
.controls     { grid-column: 1; grid-row: 1; }
.timelineShell{ grid-column: 2; grid-row: 1; }
.status       { grid-column: 1 / -1; grid-row: 2; justify-content: flex-start; }
```

效果：进度条宽度 = 总宽 − 控件宽（恒定），状态文本（含 loop/帧数）随便变都不影响进度条。
overlay 高度增加约一行（~16px + row-gap），位于视频底部，可接受。

> JSX 完全不动，仅靠 `grid-column/grid-row` 重排，testid 与单测不受影响。

## 风险

- 竖条过细在浅色帧上可能对比不足 → 靠白边 + 阴影兜底，手测确认。
- overlay 增高可能与视频底部其他叠层重叠 → 手测确认 z-index/位置。
- 颜色全部走 `tokens.css` 既有 token，无新增 token，遵守第 6 节色彩规则。
