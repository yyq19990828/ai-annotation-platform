# v0.11.27 · 图片遮挡：内置状态位 → 属性联动

- **日期**：2026-05-30
- **类型**：重构 + 新功能（含 **breaking change**：删除 `annotations.is_occluded` 列）
- **背景**：图片工作台的「标记遮挡」内置状态位 `is_occluded` 当前只影响前端视觉（虚线+半透），**不进任何图片导出**，且占用 `BoxListItem` 状态位按钮一格。本地库 93 条标注仅 1 条使用，几无价值。
- **目标**：删除内置 `is_occluded`，把「遮挡」语义收敛为普通的属性 schema 字段，并让被标记的 boolean 属性继续驱动「虚线+半透」视觉；属性天然进导出，一举解决「没用 / 占格子 / 出不去导出」三个问题。

## 设计定稿（已与需求方确认）

1. **彻底删除内置 `is_occluded`**（UI 三入口 + DB 字段 + 迁移）。`is_hidden` / `is_locked` / `z_order` 三个状态位**保留不动**。
2. **属性 schema 的 boolean 字段新增可选标记 `style_occluded`**：勾选后，该属性值为 `true` 时，画布上对应标注框渲染为**虚线 + 0.5 半透**（沿用现有 `ImageStageShapes` 视觉，不限定属性 key 名）。
3. **切换方式**：属性自带的**数字键 hotkey（1-9）** + 属性表单勾选。**字母 O 键废弃，不保留、不扩展。**
4. **红利**：遮挡成为普通属性 → 自动进 COCO `annotations[].attributes` / YOLO `attribute_schema.json`，无需改导出层。

## ⚠️ 易错点（实施前必读）

- **视频遮挡是另一套，绝不触碰**：`BoxListItem.tsx:65,68`（视频轨迹 `keyframe.occluded` 计数）、`hotkeys.ts:78,263`（Q 键 `videoToggleOccluded`）、`VideoStage.tsx` 全部、`services/export_video.py`、`services/video_tracks.py` 等保持原样。本次只动**图片侧 `is_occluded`**。
- **`ImageStageShapes.tsx` 的 `occluded` prop 保留**：它的虚线 + `opacity 0.5` 渲染逻辑在 B 阶段复用，只是取值来源从 `is_occluded` 改为属性计算值。
- **前端 `AttributeField` 是 codegen 派生**（`api/projects.ts:24 = GenAttributeField`）：必须先改后端 `_jsonb_types.py` 再跑 codegen，**不可手改**前端生成类型。后端 `AttributeField` 为 `extra="forbid"`，前后端不同步会导致校验失败。

## B 阶段 · 新增 `style_occluded` 属性联动

### B1. 后端 schema（`_jsonb_types.py`）
- `AttributeField`（`50-69`）新增：
  ```python
  # v0.11.27 · true 表示「该 boolean 属性=true 时，画布框渲染为虚线+半透（遮挡样式）」。
  # 仅图片任务 boolean 字段消费；不影响导出（属性值照常进 attributes）。
  style_occluded: bool | None = None
  ```
- `AttributeSchema._check_unique`（`86-106`）追加校验：`style_occluded` 仅当 `type == "boolean"` 允许，否则 `raise ValueError`（仿现有 hotkey 校验）。

### B2. codegen
- 后端改完运行前端 codegen（生成 `api/generated/types.gen.ts`），`GenAttributeField` 自动带 `style_occluded`。**不手改生成文件。**

### B3. 属性编辑器（`AttributeSchemaEditor.tsx`）
- 在 `f.type === "boolean"` 时新增一个 checkbox 块（位置：紧随 `102-105` 必填 checkbox 之后）：
  ```tsx
  {f.type === "boolean" && (
    <label className={styles.checkboxLabel}>
      <input type="checkbox" checked={!!f.style_occluded}
        onChange={(e) => setField(i, { style_occluded: e.target.checked })} />
      该属性为真时，框渲染为虚线+半透（遮挡样式）
    </label>
  )}
  ```

### B4. 渲染联动（关节）
1. **`transforms.ts`**：
   - `Annotation` 渲染对象去掉 `is_occluded`，改用计算字段 `occluded?: boolean`（同步改 `types/index.ts:336-347`）。
   - `annotationToBox(a, occludedKeys?: Set<string>)` 计算：
     ```ts
     occluded: occludedKeys
       ? [...occludedKeys].some((k) => a.attributes?.[k] === true)
       : false,
     ```
   - 默认不传 `occludedKeys` 时 `occluded=false`（兼容 `transforms.test.ts` 现有调用）。
2. **提取 `occludedKeys` 的 helper**（放 `transforms.ts`）：
   ```ts
   export const collectOccludedKeys = (fields: AttributeField[]): Set<string> =>
     new Set(fields.filter((f) => f.type === "boolean" && f.style_occluded).map((f) => f.key));
   ```
3. **调用点传入**：
   - `useWorkbenchShellModel.tsx:484-489`：`userBoxes` 的 `.map(annotationToBox)` → `.map((a) => annotationToBox(a, occludedKeys))`，`occludedKeys` 由 `collectOccludedKeys(toolView.attributeSchema.fields)` memo 化。
   - `ReviewWorkbench.tsx:78`：同样改造（复核界面需一致显示）。
   - ⚠️ 确认 `toolView.attributeSchema` 是否覆盖全部工具单位；若按单位隔离，则对各单位 schema 取 `occludedKeys` **并集**（key 唯一，attributes 无该 key 则不触发，不会误伤）。
4. **`ImageStage.tsx:938,978,1068,1112`**：`occluded={!!b.is_occluded}` → `occluded={!!b.occluded}`。
5. **`ImageStageShapes.tsx`**：`occluded` prop 与虚线/半透逻辑保持不变。

## 风险与取舍

- **体验变化**：遮挡从「开箱即用的 O 键」变为「项目需在 schema 配置才有」。符合需求方判断，但需在 CHANGELOG / 用户文档周知。
- **breaking**：删列不可逆（downgrade 仅重建空列，原值不恢复）。线上若已有存量遮挡数据需评估，本地仅 1 条可忽略。
- **工作量**：删除 ~20 文件 + 联动 ~6 文件 + codegen + 迁移 + 测试，约半天–1 天；耦合紧，单 PR 内顺序实施，不拆并行 worktree。
