# v0.18.3 — M3 · 编排界面产品化 + 审阅侧衔接

> 状态：**待实施 plan**（不开干）。创建于 2026-06-23。
>
> 定位：路径 B（[ROADMAP](../../ROADMAP/2026-06-23-staged-preannotation-pipeline-roadmap.md)）收尾里程碑。M1/M2 把后端通路与编排语义打通；本期把 `/ai-pre` 升级成**完整的线性阶段卡列表 UI**（增删排序、逐阶段进度条、批量成功率可视化），并补**审阅侧**衔接（工作台候选属性审阅 + 分步采纳）。同时评估转正后端基建（正式表字段、`chord` 并行）。**编排界面形态 = 线性阶段卡，不上节点图**（ROADMAP §4 决议，本期落地完整版）。

## 1. 目标 / 非目标

**目标**
1. **完整阶段卡列表 UI**（`ProjectDetailPanel`）：可增删、排序、串接下一阶段、并行添加同级阶段；点开卡 = 该阶段配置表单（复用 `PreannotateConfigForm`）。
2. **运行态可视化**：逐阶段进度条 + 批量成功率统计（如「检测 1240 框，颜色 1198/失败 42」），并行兄弟各一条（消费 M2 §2.6 数据）。
3. **审阅侧触点 1（B 泛化）**：工作台候选 `AiBox` 渲染**任意 select/multiselect 属性**；accept 支持「先看属性预测 → 改 → 再 commit」分步采纳（非一步全采纳）。
4. **`write=new_shape`**：下游产独立几何（detect→二次 seg 等），新建 `Prediction` 行 + `parent_prediction_id` 关联。
5. **后端基建转正评估**：按 M1/M2 实测价值决定是否把 `stage_index`/`parent_prediction_id` 从 `PredictionMeta.extra` 提为正式列；是否把并行兄弟拆 Celery `chord`。
6. **（视实测）一键采纳整条 pipeline 输出**：ROADMAP §7.4，按数据质量决定是否值得。

**非目标**
- 不上节点图 / React Flow（ROADMAP §4「重审节点图边界」：无深度≥3 扇出 / 运行时动态分支 / 循环 / 用户自助任意拓扑，节点图即过度设计）。
- 不做工作台触点 2「选中框交互式跑属性模型」（ROADMAP §5 表列 v0.18.3+ enrich，本期可选靠后，非上线前置）。
- 不动协议（均已 v2.x，无需升版）。

## 2. 详细设计

### 2.1 完整线性阶段卡列表（ROADMAP §4 界面形态）

- `ProjectDetailPanel` 从 M1/M2 的「最小可加阶段」升为**可增删排序的阶段卡列表容器**：
  - 卡操作：删除、上下排序（源阶段约束：下游 `parent_stage` 必须指向更靠前的源）、「串接下一阶段」、「并行添加同级阶段」。
  - 卡内 = 复用 `PreannotateConfigForm`（点开展开），**配置面板即卡片本身**，无画布+独立 inspector 双区。
  - 数据流为内置约定（上游每框→下游 ROI、下游结果→写回属性），**不暴露连线/字段映射 UI**；用户只配「父框类别过滤」+「写回属性键」（ROADMAP §4 关键交互）。
- **红线（贯穿，ROADMAP §5）**：阶段编排逻辑只在 `ProjectDetailPanel` 容器层；**`PreannotateConfigForm`/`usePreannotateConfig` 不被改成 pipeline 感知**，工作台 `AIInspectorPanel` 不继承阶段卡。

### 2.2 运行态可视化

- 消费 M2 §2.6 的逐阶段 `stats`：每张卡显状态徽标（pending/running/done/failed）+ 统计计数；并行兄弟各一条进度。
- 批量域呈现「批统计」而非单次执行追踪（ROADMAP §4：比节点图绿框更适合批量标注）。

### 2.3 审阅侧触点 1 — 候选属性审阅 + 分步采纳（ROADMAP §5）

- **背景**：v0.18.0 已给候选属性**只读最小预览**（缺口 A）。B 把它从「只显示 OCR 文本」**泛化为任意 select/multiselect 属性都能在候选上渲染 + 审阅**。
- `BoxListItem` / `AIInspectorPanel`：候选行渲染 `AiBox.attributes`（车型/颜色等任意 select 属性，显示中文 label）。
- accept 流程：从「几何一步全采纳」改为「**先呈现属性预测 → 可改任意 select 值 → 再 commit**」分步；复用 `AttributeForm`（已支持 select/multiselect 编辑）。
- **红线**：面板**不 host 阶段卡列表**（扇出/类别路由对单框一次交互无意义，只在批量有意义，ROADMAP §5）。

### 2.4 `write=new_shape`（ROADMAP §3.3）

- 下游产独立几何时（少见，如 detect→二次 seg），不 merge 进父框，而**新建 `Prediction` 行**，`parent_prediction_id` 指向上游框。
- 需要 §2.5 的正式列 `parent_prediction_id` 支撑（或继续 `PredictionMeta.extra` 过渡，视 §2.5 决定）。

### 2.5 后端基建转正评估（ROADMAP §6 M3）

- **正式表字段**：依 M1/M2 实测「按 `extra` 查阶段元信息」是否够用，决定是否给 `predictions` 加 `stage_index: int|None` / `parent_prediction_id: uuid|None` 正式列（含 alembic 迁移）。`new_shape`（§2.4）是主要推动力。
- **`chord` 并行**：同父并行兄弟无交叉依赖，是 `group`/`chord` 天然并行单元（ROADMAP §7.1）。按规模 / 耗时实测决定是否把 M2 的「顺序跑兄弟」拆为 `chord`。
- 两项均**按需转正**，不为对称而做（CLAUDE.md §2）。

### 2.6 （视实测）一键采纳整条 pipeline（ROADMAP §7.4）

- 若 M1/M2 实测属性预测质量稳定，提供「一键采纳整条 pipeline 输出」批量入口；否则维持逐框 accept。决策点放本期末，按数据说话。

## 3. 实施步骤（每步带 verify）

1. 完整阶段卡列表 UI（增删/排序/串接/并行） → verify：能可视化搭出 detect→(color‖vehicle_type) 拓扑，配置随卡片增删正确同步进 `pipeline_stages`。
2. 运行态可视化 → verify：跑多阶段批，逐阶段进度条 + 成功率统计实时更新，并行兄弟各一条。
3. 候选属性审阅 + 分步采纳 → verify：工作台候选框显示 select 属性中文 label，可改后再采纳，入库为改后值。
4. `write=new_shape` → verify：配 detect→seg 下游，产独立几何行且 `parent_prediction_id` 关联上游框。
5. 后端基建转正（按评估结论选做） → verify：若加正式列，alembic 迁移 + 查询走新列通过；若拆 `chord`，并行兄弟耗时下降且结果一致。
6. （视实测）一键采纳 → verify：批量采纳整条 pipeline 输出，框 + 属性全部入库。
7. 版本收尾（CLAUDE.md §10）：bump 四处 + `uv lock` + openapi 快照；若加列另跑迁移；`curl localhost:8000/health` 验证 0.18.3。
8. 文档收口：`docs-site/user-guide/`（AI 预标注多阶段编排用法）+ `docs-site/dev/concepts/`（编排架构）+ CHANGELOG；ROADMAP B 完成项按 feedback「ROADMAP 完成项删除」清理。

## 4. 验收标准

- 非工程师管理员能在 `/ai-pre` 用卡片列表搭出「检测→并行多分类」拓扑并跑批，全程不接触连线/映射 UI。
- 运行态逐阶段进度 + 成功率清晰可见。
- 工作台候选框的 select 属性可审阅、可改、分步采纳后正确入库。
- `write=new_shape` 下游几何与父框正确关联。
- 节点图未被引入（验证 ROADMAP §4 边界仍成立）。

## 5. 风险 / 开放问题

- **共享组件耦合**（ROADMAP §5 红线，本期最易踩）：阶段卡列表与工作台共用 `PreannotateConfigForm`，必须容器持实例、不改组件本身。Review 重点盯这条。
- **正式列 vs `extra`**：过早加列违反 CLAUDE.md §2；过晚则 `new_shape` 关联查询低效。以 §2.4 是否实装为决断锚。
- **一键采纳的质量门槛**：模型抖动下批量采纳风险高，§2.6 决策必须有实测数据支撑，不可拍脑袋上。
- **节点图诱惑**：实现完整阶段卡时易滑向「干脆上 React Flow」；守住 ROADMAP §4 边界，出现深度≥3/动态分支/循环再评估。
