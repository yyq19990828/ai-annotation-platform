## 1. 结论

本版在现有 `box_3d` 创建链路外增加一个显式、可见、可退出的持续 armed 会话，不增加第二套 cuboid 创建器。用户按一次 `B` 后，可连续使用主视口点击默认框、主视口拖框自动拟合；放大相机后开启一次种框，也可连续通过相机矩形和视锥拟合创建。类别、当前创建方式与现有拟合参数在成功后保持，每个对象仍独立走现有 annotation mutation 和 3D history。

本版不绑定 `Space`。当前三条创建路径都在 pointer-up 直接形成完整可提交几何，没有“等待完成”的中间步骤；新增 `Space` 要么无效，要么会引入重复提交语义。`V` 和 `Esc` 是持续会话的唯一键盘退出合同。

## 2. 当前仓库审计

审计基线为 `62f6469a`，四处版本源和运行时健康检查均为 `0.24.2`，数据库迁移 head 为 `0155_audit_bi_daily_mv.py`。本版不改变 API、OpenAPI schema、数据库表、迁移、依赖、环境变量或账号级偏好。

当前创建路径：

| 路径         | 当前入口                          | 当前提交                        | 当前缺口                                     |
| ------------ | --------------------------------- | ------------------------------- | -------------------------------------------- |
| 主视口点击   | `ThreeDWorkbench.handlePlace`     | 默认尺寸 `box_3d`               | 调用 mutation 后立即切回选择工具             |
| 主视口拖框   | `ThreeDWorkbench.handleBoxSelect` | `psrFromPoints` 自动拟合        | 调用 mutation 后立即切回选择工具；空选区静默 |
| 放大相机种框 | `ThreeDWorkbench.handleSeedBox`   | 视锥选点、`fitYaw`、`fitBottom` | 每次成功后关闭种框模式；保存期间仍可再次拖框 |

已有能力继续作为真值：

- `activeClass` 由工作台壳层持有，切换类别后天然保持，不新增粘性类别设置。
- `threeDTool` 已由工作台壳层持有；`box` 可直接表达主视口 armed 状态，不扩展公开工具类型。
- `useCreateAnnotation` 已有乐观写入和失败回滚；本版只在组件层统一每次创建的 busy、成功选择、history 和错误反馈。
- `useThreeDHistory` 已把每次 create 作为独立记录；持续会话不引入批量撤销实体。
- 切 task 已强制回到选择工具；本版补齐只读、类别不可用和迟到响应的同类安全边界。

草案判断：持续创建方向仍成立；`Space` 合同不再成立；相机保存期输入闸和“只在进入 armed 时清选择”是当前源码审计新增的必要范围。

## 3. 用户与交互合同

目标用户是在同一帧内连续标注多个同类车辆、行人或障碍物的 3D 标注员。

### 3.1 主视口

1. 按 `B` 或点击「连续建框」进入 armed；进入时清除旧选择一次。
2. 状态条持续展示当前类别、可用手势和 `V/Esc` 退出提示。
3. 单击创建默认尺寸框；拖框对屏幕矩形内点云运行现有 `psrFromPoints` 自动拟合。
4. 成功后新框保持选中，工具仍 armed；下一次 pointer 可以直接创建下一个对象。
5. 框内无点或无法找到放置位置时不创建半成品，状态条显示可恢复原因，工具仍 armed。
6. annotation 保存期间禁止开始下一次 pointer，不排队、不并发、不重复 POST。

### 3.2 放大相机

1. 点击一次「种框」进入相机 armed；按钮展示当前类别和下一次动作。
2. 拖矩形继续使用现有视锥选点、最近簇、yaw 与 bottom 拟合；点不足时继续使用现有明确提示的默认框降级。
3. 成功后相机种框保持 armed，新框保持选中，可继续拖下一个矩形。
4. 保存期间相机 canvas 禁止开始下一次种框，并显示保存状态。
5. `V/Esc` 退出相机种框；关闭放大相机仍按现有合同复位相机种框状态。

### 3.3 安全退出

- `V/Esc`、切 task、进入只读、`lidar_box_3d` 类别变为不可用时退出创建态并清理本地错误提示。
- task 切换使旧请求回调失效；迟到成功不得在新 task 选中旧 annotation，也不得污染新 task history。
- 用户在保存期间主动退出时不取消已经发送的服务器请求，但响应只能更新原 task 数据，不能重新激活工具。
- 一次撤销只删除最近一个成功创建的对象；刷新后数据与单次创建路径一致。

## 4. 状态与数据流

```text
Workbench shell
  activeClass + threeDTool
          │
          ├──────────────► ToolDock: active / armed 入口
          │
          ▼
ThreeDWorkbench
  armed / drawing / saving / recoverable error
          │
          ├─ 主视口 click ─────► 默认 PSR ───────┐
          ├─ 主视口 drag ──────► psrFromPoints ──┤
          └─ CameraProjectionView drag ─► 视锥拟合 ┤
                                                 ▼
                                      单一 submitBoxCreation
                                                 │
                         useCreateAnnotation + useThreeDHistory
                                                 │
                             成功选中新框并恢复 armed
```

组件间不新增反向状态同步：`CameraProjectionView` 只接收保存期阻断信号并上报矩形，创建会话仍由 `ThreeDWorkbench` 单点持有。

## 6. 可独立合并切片

### Slice A：主视口持续创建

- 抽取单一 `submitBoxCreation`，统一 busy、success、error、history 与 task revision。
- 主视口点击和拖框成功后保持 `box` 工具；只在首次进入 armed 时清旧选择。
- 状态条展示 armed、saving、recoverable error。
- 独立验收：连续两次创建只激活一次 `B`，产生两个 POST、两个可逐次撤销的 history entry，`V/Esc` 后点击不再创建。

该切片单独发布时已经可用，回滚只需恢复成功后 `select` 和旧状态条文案。

### Slice B：相机连续种框

- 相机种框成功后保持 `seedMode`。
- 保存期间阻止新的相机 pointer，按钮表达当前类别与保存/失败状态。
- 复用 Slice A 的单一提交与 revision，不建立第二套 mutation 管线。
- 独立验收：一次激活后连续两次相机拖框产生两个串行 POST；保存期额外拖动不产生第三个请求；关闭、`V/Esc` 均退出。

该切片可在 Slice A 后独立合并；回滚只恢复相机种框成功后关闭模式，不影响主视口持续创建。

## 8. 验收标准

1. 同一类别连续创建 20 个对象只激活一次工具；工具激活次数相对旧路径下降至少 90%。
2. 点击、拖框和相机种框的每次成功创建都恰好产生一个 annotation POST 和一个独立 history entry。
3. 保存期间的新 pointer 被拒绝，不产生并发创建队列或重复对象。
4. 空框、放置失败和请求失败均保留 armed，显示可恢复原因，不改变已有选择和 history。
5. 成功后新框保持选中；进入 armed 时旧选择只清理一次，不会因成功选择而再次清空。
6. `V/Esc`、切 task、只读和类别撤销均在一个事件周期内退出；迟到响应不污染新 task。
7. 本版实体增量为 0；API、schema、迁移、依赖、环境变量和持久偏好增量均为 0。

## 9. 风险、假设与回滚

最脆弱假设是当前真实工作负载以同类目标密集建框为主。如果真实任务以零散跨类对象为主，持续模式仍保持显式且可退出，但效率收益会低于预期；这不会改变数据合同，也可直接恢复单次创建。

主要风险是用户误以为已回到选择态而误建。工具坞 active 状态、状态条 armed 文案、相机按钮三处共同表达当前动作，不增加动画。高频键盘与 pointer 操作保持零动效，避免视觉反馈被感知为延迟。

回滚不触碰数据：恢复三个成功路径的单次退出、删除 busy/错误状态和相机阻断 prop 即可。已经创建的 annotation 与 history 都是普通合法记录，无迁移和清理任务。

外部依赖、账号、密钥和第三方 CLI 增量均为 0。

## 10. Outcome

实施已按本计划收口：

- 主视口点击、主视口拖框自动拟合和放大相机种框已共用一条串行提交链；成功后保持 armed 和新框选中，失败可直接重试。
- 状态条和相机按钮显示当前类别、保存、错误与退出方式；保存期拒绝新 pointer，viewport 内控件不再因事件冒泡误创建。
- 切 task 会使旧请求回调失效，迟到成功不会选中旧框或写入新 task history；类别切换、`V/Esc`、只读和类别不可用的安全边界均由同一会话状态守卫。
- 隔离点云 E2E 项目使用本机 seed 缓存中的 nuScenes mini `LIDAR_TOP`，并提供 `car` / `pedestrian` 两个框类别；不将数据集搬入仓库。
- 定向几何单测 45 条通过；全量前端 351 个测试文件、2943 条测试通过；最终 Chromium 点云矩阵 18 条通过，其中一次 `B` 连续创建 20 个框并逐个撤销/重做。
- Python / Web lint、Tailwind token 检查、格式、TypeScript 类型检查、Web 生产构建、文档构建和 `git diff --check` 全部通过。API、schema、数据库迁移、依赖、环境变量和持久偏好增量均为 0。
