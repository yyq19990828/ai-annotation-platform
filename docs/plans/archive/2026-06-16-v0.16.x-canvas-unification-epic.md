# v0.16.x · 画布栈统一 Epic(视频渲染栈 SVG+DOM → Konva)

> 规划日期 2026-06-16 · 范围:正式上线前,把视频工作台的渲染栈从「`<video>` + `<canvas>` 位图 + 多层 SVG + DOM 文字」统一到 **Konva**,与图片工作台同栈。目标是消除「图片 Konva / 视频 SVG」双栈带来的**视觉参数永久双份维护、坐标模型分裂、能力实现两遍**的长期税。
>
> **决策来源**:2026-06-16 讨论,用户在评估 SVG vs Konva 双栈优劣后拍板:**上线前统一到 Konva**。
>
> **与 v0.15.x 的关系**:v0.15.27(标注视觉样式设置)仍按双栈交付——它建的「共享视觉规格模块 `annotationVisual.ts`」在本 epic 完成后,**双 draw 路径塌缩为单路径**,是本 epic 的直接受益项与清理对象(见 §6)。

## 0. 为什么是 Konva 而不是 SVG(决策记录,进 ADR)

- 二者都能扛(CVAT 全 SVG、Label Studio 全 Konva);痛点不在选型,在**本仓库混用导致默认值漂移 + 双份实现**。
- 选 Konva 的决定性理由:**图片侧已是 Konva(ADR-0004,5 Layer)且无法离开**——它有多边形数百顶点、SAM 掩膜(像素级 `getImageData`)、重度顶点拖拽,这些 SVG 做不了。**视频形状稀疏、可以迁就图片**;反向(把图片迁到 SVG)不可能。所以统一方向只能是 Konva。
- 代价(已知,接受):视频失去 SVG 的三个白送项——CSS 主题/暗色直接管文字、`non-scaling-stroke` 恒定线宽、DOM 文字的字体/i18n/断行。迁移后这三项都要在 Konva 里**手动等价实现**(scale 抵消线宽、Konva Text、tokens 值经 JS 注入)。图片侧早已这么做,有现成范式可抄。

## 2. 三个核心架构抉择(本 epic 的脊柱)

### 决策 A — 视频像素怎么进 Konva 【需 v0.16.0 性能 spike 闸门】

| 方案 | 做法 | 优 | 劣 |
|---|---|---|---|
| **A1 帧合成进 Konva(推荐)** | `Konva.Image` 以隐藏 `<video>` 为 source,**视频单独一层** `batchDraw`;播放时 `Konva.Animation`/rAF 逐帧重绘视频层,**标注层静止不重绘**;暂停时贴 bitmap 缓存 | **真·单栈单坐标单 transform**,根治漂移;标注与底图同一命中模型 | 播放时视频层整帧重绘有成本,4K@60 需实测 |
| **A2 透明 Konva 盖在 `<video>` 上** | `<video>` 仍是 DOM,Konva Stage 透明只画标注 | 不重绘视频像素,perf 稳 | **没真正统一**:仍两个 transform 要同步(正是要消灭的漂移源),坐标双轨 |

**明确推荐:A1 + 分层(video 层 / 标注层各自 canvas)**。理由:本 epic 全部价值在「单栈」,A2 等于没迁。A1 的两个缓解几乎让 perf 风险归零:① **分层**——播放时只有视频层 `batchDraw`,标注层(数百形状)静止不动;② **暂停态走 bitmap 缓存不进重绘循环**——精修标注都在暂停态,逐帧重绘只发生在"播放观看"时,不伤精修体验。**v0.16.0 spike 在分层前提下量化**(1080p@30 视频单层单帧 < ~8ms 即过;4K@60 仅上限参考)。仅当分层后 A1 仍不达标才降级 A2,届时把「双 transform 同步契约」写成 ADR 里有测试守护的一等不变量(非临时补丁)。

### 决策 B — 坐标模型统一到「像素空间 + Konva transform」

- 采图片范式:存储仍是归一化(数据零迁移),**渲染边界**用视频固有宽高换算成像素(等价图片的 `imgW/imgH`),Konva Stage 负责 scale/pan。
- 废弃视频的 SVG CTM 转换(`videoStageCoordinates.ts`),改用图片的 `toImg()` 同款逆变换。
- 收益:scale 抵消、fit-to-canvas、滚轮缩放逻辑与图片**同一套**,可抽公共。

### 决策 C — 先建 Konva 测试基建(v0.16.0 硬前置)

视频现有强 RTL 覆盖(`VideoStage.test.tsx` 查 SVG DOM)会**整片失效**;图片侧目前**零组件测试**(`vitest.setup.ts` 无 react-konva mock)。迁移前必须立起测试策略,否则迁完无法验证回归。三选一 → **推荐混合**:

1. 纯逻辑测试照旧(picking/resize/geometry,已栈无关)。
2. **react-konva mock**:把 `Stage/Layer/Rect/...` mock 成带 `data-testid` 的 DOM stand-in,让组件交互测试沿用 RTL `fireEvent`(改造量可控,保住现有断言风格)。
3. **Playwright 冒烟**:真浏览器跑 1-2 条端到端(画框/选中/播放),守住 canvas 真渲染。

此基建**图片侧同样受益**(补上它缺失的组件测试)。

## 4. 全程红线

1. **数据零迁移**:标注存储仍归一化坐标,只改渲染边界换算。
2. **flag 双栈并行**:全程保留 SVG VideoStage 作回退,逐版用 flag 对照验收,**观察期通过前不删旧栈**(v0.16.5 才删,v0.16.4 仅切默认)。

4. **像素级对照验收**:每层迁移用「同帧同标注,新旧栈截图 diff」守回归(Playwright 截图)。

## 5. 风险登记

| 风险 | 级别 | 缓解 |
|---|---|---|
| A1 帧合成 perf 不达标(高分辨率/高帧率) | 高 | 分层(视频层单独 batchDraw,标注层静止)+ 暂停态走 bitmap 缓存,两手缓解;v0.16.0 spike 在分层前提下量化;仍不达标才降级 A2(ADR 记契约) |
| 删栈不可逆,生产回归无退路 | 高 | v0.16.4 切默认与 v0.16.5 删栈拆两个 release,中间观察期;门槛=真实使用无人触发回退;旧栈+flag 全程保留到 v0.16.5 |
| 测试整片失效、迁移无回归网 | 高 | v0.16.0 先立测试基建(决策 C),再动渲染 |
| 视频特有交互(关键帧拖拽/track 传播热区)在 Konva 命中模型下行为漂移 | 中 | picking/resize 纯函数复用;Konva 命中只换事件源,几何判定不变 |
| Konva Text 无自动断行,长标签换行/截断回归 | 中 | 抄图片 Label 现成处理;`annotationVisual.ts` 统一文本组装 |
| 暗色/类别色填充在亮底视频帧对比度不足 | 中 | 沿用 v0.15.27 §5 的对比度自检;必要时极淡暗罩 |
| Minimap/PlaybackOverlay 等 DOM 浮层与 Konva 集成接缝 | 低 | 这些是 Stage 兄弟节点,非 Layer,基本不动 |

## 6. 与 v0.15.27 的衔接

- v0.15.27 先交付双栈共享视觉规格 `annotationVisual.ts`(默认值单一来源 + `settings→绘制值`纯函数),Konva 与 SVG/DOM 两条 draw 路径都消费它。
- 本 epic v0.16.5 完成后,SVG/DOM 路径消失,`annotationVisual.ts` 的双路径塌缩为单 Konva 路径——**双份维护税正式归零**,这是统一的终点收益。
- 因此 v0.15.27 的「双份实现」是过渡形态,不是浪费:它先把参数/默认值收口(立即可用),v0.16.x 再把渲染栈收口(彻底)。

**排期决策(2026-06-16 用户拍板)**:**先发 v0.15.27 再做 v0.16.x**。视频侧视觉设置在 v0.15.27 先按 SVG/DOM 实现一遍(过渡期短、设置即时可用),v0.16.2 迁 Konva 时这套消费点随渲染层一并改写;`annotationVisual.ts` 纯函数(默认值 + `settings→值`映射)跨栈不变、不浪费,只换最后的 draw 调用。代价是视频侧 draw 代码写两遍,已接受。
