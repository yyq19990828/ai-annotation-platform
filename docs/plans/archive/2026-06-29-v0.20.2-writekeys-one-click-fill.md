# v0.20.2 · 属性键对账升级为「一键补全」

状态：草案（draft）。把 v0.19.2 WS1 的 `write.keys × output_attribute_schema` **对账警告**
从「只提示」升级为「一键修复」。小到中量级，纯前端为主。

## 背景

v0.19.2 WS1 在编排 StageCard 加了对账警告：选的写回属性键若不在所选 model 自报的
`output_attribute_schema` 内 → 非阻断提示「该模型可能不产出此键」。但**只提示、不给出路**——用户看到警告
仍得自己去项目设置补属性，再回编排重选。v0.19.2 计划已把「属性自动映射」显式列为「另议」。

平台其实已有「从 backend 导入属性」（`ImportAttributesFromBackendDialog`，把 backend 自报 schema 一键导成
项目 attribute_schema）。把它和对账警告**接起来**，就能闭环「发现缺口 → 一键补」。

## 目标

对账警告旁给一个 CTA：「一键用该模型 schema 补全缺失属性键」，复用既有属性导入链路，把
model 自报但项目缺的属性字段补进项目，补完警告自动消失。

## 工作项

### WS1 · 对账警告加 CTA（前端）

- `StageCard.tsx`（v0.19.2 已渲染 `unknownWriteKeys` 警告）—— 警告里加按钮「补全这些属性键」。
- 点击 → 取该 model `output_attribute_schema` 中 `unknownWriteKeys` 对应的字段定义，调既有属性导入
  逻辑（`ImportAttributesFromBackendDialog` 的核心 mutation，抽成可复用 hook）写进项目 attribute_schema。
- 补全成功 → 刷新项目 capabilities → `unknownWriteKeys` 收敛为空 → 警告消失（已是派生态，自动）。

### WS2 · 复用 / 抽取导入链路

- 把 `ImportAttributesFromBackendDialog` 里「schema 字段 → 项目 attribute_schema 写入」的部分抽成
  `useImportBackendAttributes()` hook（dialog 与 StageCard CTA 共用），避免逻辑两份。
- 与 v0.20.1 协同：若 v0.20.1 已落 `semantic_role`，补全时一并写入角色（text/language/orientation）。

## 风险

低到中（纯前端 + 复用既有 mutation）：
- 写项目属性 schema 是有副作用操作，CTA 须给确认（避免误点改了项目配置）。
- 键命名空间：StageCard 有「子物体命名前缀」（label → `hat_color`），补全时补的是**原始键**还是带前缀键需对齐
  （建议补原始键到项目 schema，前缀仅在写回时加，与 worker 行为一致）。

## 验收

- 选一个项目没有的属性键 → 出对账警告 + 「补全」按钮 → 点击确认后项目多出该属性字段、警告消失。
- 取消确认 → 项目 schema 不变。
- 补全的字段（v0.20.1 落地后）带正确 `semantic_role`。

## 排期与依赖

- 依赖 v0.19.2 WS1（对账警告，已落）。
- 与 v0.20.1 同窗口（都动属性导入链路 + StageCard 属性区）——建议紧邻或合并。
- 与 v0.20.0 协同：RapidOCR 的 `output_attribute_schema` 是最自然的「一键补全」试验场。

## 不在范围

- 全自动映射（不经用户确认直接改项目 schema）：保持「一键 + 确认」，不做静默自动映射。
