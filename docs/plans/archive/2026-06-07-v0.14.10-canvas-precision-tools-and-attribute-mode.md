# v0.14.10 · 画布精细交互 + 模型市场前端重构

> 规划日期 2026-06-07 · 本版含**两条独立线**:
> - **第一线(Part A)· 画布精细交互**:借鉴 CVAT 的 snap / join / slice / attribute mode,补齐图片/视频单帧工作台在密集 polygon / mask / 属性补录场景下的效率工具。只做前端工具和既有 annotation 更新,不改几何存储 schema。
> - **第二线(Part B)· 模型市场前端重构**:承接 v0.14.9 能力声明协议 v2,把 `/model-market` 从三块堆叠面板重构为「能力目录 / 运行时观测 / 注册管理」分段视图,能力目录加列表态/分组/搜索,运行时观测独立并去 SAM/DINO 化(展示泛化)。详见文末 Part B。

## 1. 背景

本平台已具备 bbox、polygon、multi_polygon、rotated_bbox、polyline、keypoint、mask brush 等基础能力。但密集标注场景还有几个高频痛点:

- polygon 边界相邻时,手工贴边容易漏缝/重叠。
- 多个 polygon/mask 需要合并或切开。
- 大量对象只需要补属性,反复选框再找属性面板效率低。
- 已有右键菜单和快捷键,但缺几何专用精细操作。

CVAT 可借鉴的是 snap-to-contour / snap-to-point、slice/join、attribute annotation mode。不要照搬其 imperative canvas runtime,只取工具语义。

## 2. 目标

### A. Snap 工具

支持:

- snap-to-point:拖 polygon 顶点时吸附到附近已有顶点。
- snap-to-edge/contour:绘制 polygon 时吸附到已有 polygon 边。
- 可配置像素阈值,默认 8px。
- 按住 Alt 临时禁用 snap。

作用范围:

- image polygon / multi_polygon 外环。
- video_bbox 不参与。
- mask brush 不参与首版。

### B. Join / Slice

Join:

- 选中两个同类 polygon / multi_polygon。
- 合并为一个 multi_polygon 或 polygon union。
- 保留 class / attributes;若不同 class,要求用户选择目标 class。

Slice:

- 选中 polygon。
- 画一条切割 polyline。
- 生成两个 polygon;attributes 复制。

### C. Attribute Annotation Mode

属性补录模式:

- 左侧/顶部显示当前属性字段。
- 点击对象后直接循环设置该属性值。
- 快捷键数字选择属性值。
- 支持“下一个未填该属性的对象”。

首版目标:

- boolean / select / multiselect。
- bbox / polygon / rotated_bbox。
- 不覆盖 text/number/range。

## 3. 非目标

- 不改 annotation geometry schema。
- 不引入新的 polygon boolean 库;优先复用现有 `polygon-clipping`。
- 不做 mask RLE 独立几何。
- 不做 3D point_mask 编辑;它由 v0.14.6 覆盖。
- 不做任意复杂拓扑修复;失败时明确提示用户手动处理。

### 4.1 Snap

新增纯函数:

```text
snapPointToCandidates(point, candidates, thresholdPx)
snapPointToSegments(point, segments, thresholdPx)
buildSnapIndex(annotations, viewportTransform)
```

前端接入:

- polygon draw move。
- polygon vertex drag。
- 显示 snap indicator。

性能:

- 首版可用简单空间网格,不引入 R-tree。
- 只索引当前 viewport 可见 annotation。

### 4.2 Join

流程:

1. 用户多选两个或多个 polygon(复用现有 `selectedIds` 多选,无需新增选区机制)。
2. 右键(`imageStageContextMenu.ts`)或选区动作栏(`ImageSelectionActions.tsx`,加在 `onChangeClass`/`onDelete` 旁)点 Join。
3. 用 `polygon-clipping.union` 合并(依赖已装;`stage/iou.ts`、`shared/geometry/maskToPolygon.ts` 有现成用法可抄)。
4. 生成新 geometry(可为 `multi_polygon`),删除旧 annotation 或标记旧 annotation inactive。
5. 经 `useAnnotationHistory` 作为**单条** command 推入(参考 `videoTrackCommands.ts` 命令模式),可整体 undo。

决策:

- 如果 class 不同,弹确认选择 class。
- attributes 只有完全相同才保留;不同则清空或让用户选择一个来源。首版建议“选择来源 annotation”。

### 4.3 Slice

流程:

1. 用户选中 polygon。
2. 进入 slice mode:**实现为一个 `CanvasTool`**(`stage/tools/SliceTool.ts`,在 `tools/index.ts` 注册),复用 `PolylineTool` 的画线基建(`ToolPointerContext` → `DrawingState`)。
3. 画一条 polyline 穿过 polygon。
4. 前端计算切割结果(`polygon-clipping` difference / 半平面分割,落 `shared/geometry/polygonOps.ts`)。
5. 两个新 annotation 替换原 annotation,经 `useAnnotationHistory` 作单条 command(同 Join)。

风险:

- polygon boolean 的切割比 union 更复杂。若实现成本过高,可先做 Join + Polygon Crop,Slice 顺延(不阻塞 Join / Attribute Mode 上线)。

### 4.4 Attribute Mode

新增模式状态:

```text
attributeMode:
  enabled
  toolUnitId
  fieldKey
  currentValue
```

交互(快捷键全部经 `state/hotkeys.ts` SoT 注册,**实现前先核 `state/hotkeyUsage.ts` 数字键占用避免冲突**,并重生成 `hotkeys.generated.md`):

- 点击对象 = 更新该对象 attributes[fieldKey]。
- `[` / `]` 切换字段。
- 数字键选择枚举值。
- `N` 跳下一个未填字段对象。
- 输入框焦点下不触发(沿用现有 hotkeys 焦点守卫)。

与现有 `shell/AttributeForm.tsx` 关系:

- AttributeForm 是单对象编辑。
- Attribute Mode 是批量补录路径。
- 两者写同一个 `annotation.attributes`(经 `useAnnotationHistory`,attribute mode 每次写也入 history,可 undo)。
- mode 状态挂在 `useWorkbenchState.ts`(与 `selectedIds` 同源,见 §4.0)。

## 7. 风险

- **几何算法失败**:boolean ops 对自交 polygon 敏感。失败时不应写坏数据,返回可读错误。
- **undo 语义**:join/slice 是多 annotation delete/create,必须作为一个 history command。
- **快捷键冲突**:Attribute mode 数字键可能和现有工具冲突,必须接入 hotkeys SoT。
- **性能**:snap index 在大量 polygon 下可能重;首版按 viewport 可见对象构建。

## 8. 与其他版本关系

- v0.14.6 覆盖 3D point_mask 的套索/加减点;本版覆盖 2D polygon/mask 精细操作。
- v0.14.8 Data Manager 的 saved views 可筛出“缺属性”任务;本版 attribute mode 负责高效补录。
- 不影响 v0.15 3D 时序计划。

# Part B · 模型市场前端重构(能力目录 / 运行时观测独立 / 列表态)

> 与 Part A 完全独立,可单独排期/单独提交。承接 v0.14.9「能力声明协议 v2」(已落地 `CapabilityCatalogPanel`、`/capabilities` 端点、grounded-sam2/sam3/mock-v2 三 backend 适配)。本线**纯平台侧**,不实现任何 YOLO/ONNX backend 本体(沿用 v0.14.9 §9 边界)。

## B1. 背景

`/model-market` 当前是三块全宽 Card **纵向堆叠**,三套互不跳转的主键视角:

| 面板 | 主键 | 数据源 | 职责 |
|---|---|---|---|
| `ObserveBackendsPanel` | 容器 URL(env `ML_BACKEND_OBSERVE_URLS`) | `observe()` | 在线/延迟/GPU/池/warm 试启动 |
| `CapabilityCatalogPanel`(v0.14.9 新) | model 条目 | `overview()` + 每 backend `capabilities()` | 能力静态展示 + 多轴 chip 过滤 |
| `RegisteredBackendsTab` | 项目→backend | `overview()` | 注册 CRUD + 健康/卸载/预热 + 变体 |

三个核心问题:

1. **运行时可观测性劈成两半且重复**:`ObserveBackendsPanel`(env URL 视角)与 `RegisteredBackendsTab` 状态列(`RegisteredBackendsTab.tsx` L271–291 渲染 gpu_info / cache hit / model_version,L296–336 又有 health/unload/reload 行操作)。一个「既在 env 又被注册」的容器,运行时信息在两处各显示一次。
2. **observe 子系统是 grounded-sam2 专用件**:`admin_ml_integrations.py` 的 `VariantCatalog`(L304)只有 `sam_variant`/`dino_variant` 两轴;`_extract_variant_catalog`(L334)只认这两个 key 的 enum;前端 `ObserveBackendsPanel.tsx` L156–173 写死两个 select、L130 拼 `${sam}/${dino}`。v2 协议引入的通用 `supported_variants`(YOLO `series`×`size` 等多轴)在 observe 路径**一律返回 None** → 所有非 SAM 容器显示「该容器不暴露变体目录」。
3. **扁平卡片网格不抗规模**:`CapabilityCatalogPanel` 是 `auto-fill minmax(300px)` 扁平网格,无分组/排序/搜索(只有 chip facet)。未来企划的 ONNX 聚合 backend(N 模型)+ YOLO 官仓 backend(全 series×size)会让它炸成几十张卡。

## B2. 目标

- **P1 布局收口**:`ModelMarketPage` 引入分段控制 `[能力目录 | 运行时观测 | 注册管理]`,顶部加 StatCard 总览条(已连/总 backend、使用项目数、模型条目数)。

- **P3-Gen-展示**:observe 去 SAM/DINO 化,变体目录改读通用 `supported_variants` 多轴结构,前端按轴数动态渲染 select;grounded-sam2/sam3 旧 sam/dino 向后兼容。
- **P3-Gen-动作(占位)**:warm/smoke 的通用变体动作只定义请求形状,不实现;对未声明通用 warm 的容器,「试启动」按钮 disabled + tooltip。

## B4. 设计

### B4.1 页面 IA(P1 + P3-IA)

`ModelMarketPage.tsx`:

- 顶部 StatCard 总览条:ML Backend 已连/总数、使用项目数、模型条目数(从 `overview()` + 各 `capabilities()` 派生;模型条目数依赖 capability 查询 settle,未 settle 时显示「探测中」占位)。
- 分段控制三视图(自实现 tab,参考 `pages/Projects/sections/ToolUnitTabs.tsx`,UI 层无共享 primitive),**tab 状态用 `?tab=catalog|runtime|registry` query param 驱动**(可深链;`ModelMarketPage` 已用 `useSearchParams`,现有 `?tab=failed → /ai-pre/jobs` redirect 保留):
  - **能力目录** → `CapabilityCatalogPanel`(model-centric,见 B4.2)。
  - **运行时观测** → 新 `RuntimeObservePanel`(见下)。
  - **注册管理** → `RegisteredBackendsTab` 瘦身:保留项目分组 + 注册/编辑/删除 + 跳项目设置;**移除运行时指标列(gpu/cache/model_version)与 health/unload/reload 行操作、移除展开的 `VariantPanel` warm 面**(全部迁到运行时面)。
- 三面板共用 `["admin","ml-integrations","overview"]` query key(React Query 自动去重,勿新增重复请求)。

**`RuntimeObservePanel` 的 keying(关键修正)**:`observe()` 返回的 `ObserveTarget` **不带 backend_id**,只按 `url.rstrip("/")` 标 `registered`,且**一个 URL 可被多个项目注册**(`admin_ml_integrations.py` L420 `reg_by_url` 是 set)。lifecycle 动作(unload/reload/health)走项目级 hooks `useMLBackend{Unload,Reload,Health}(projectId)`,**必须有 project_id + backend_id**。因此**不能**按 URL 去重驱动 lifecycle。正确结构:

- **以已注册 backend 为主键**:遍历 `overview().projects[].backends[]`(自带 project_id + backend_id → 完整 lifecycle + `VariantPanel` warm)。
- **env-only 容器**(observe URL 未匹配任何注册 URL):作为「未注册容器」单列展示,仅 `observe/smoke-test`(URL-based,无项目级动作)。
- **已注册容器的实时指标**:按 `url.rstrip("/")` 把 `observe()` 的 `ObserveTarget` join 到注册 backend;命中用 observe 实时值(在线/延迟/GPU/池),未命中(URL 不在 env)回落 `health_meta` 快照。
- 同一 URL 被 N 个项目注册 → 在已注册列表里按 (project, backend) 各出现一次(lifecycle 本就是项目级);join 的 observe 实时指标为共享容器同值。
- **可选后端增强(降低 join 脆弱性)**:`ObserveTarget` 增加 `registered_backends: list[{project_id, backend_id, label}]`,免去前端 URL 归一化边界;列为 P3-IA 的可选项,不阻塞首版(首版可纯前端按 URL join)。

跨视图弱关联:能力卡 →「在运行时观测查看来源容器」,按 backendId 切 `?tab=runtime` + 高亮。首版只做这一单向;运行时卡 → 能力目录的反向顺延。

## B7. 风险

- IA 重组触及三组件:复用同一 query key,勿引入重复请求或 N+1 拉取。
- **共享容器歧义**:一个观测 URL 可被多个项目注册;运行时面以 (project, backend) 为主键展示,observe 实时指标按 URL join 为共享同值,勿用 URL 当唯一主键驱动 lifecycle。
- observe 契约改动需双写/回落,**不得破坏** grounded-sam2/sam3 现网 sam/dino warm 与显示。
- 列表态大数据量:分组折叠 + 阈值兜底,避免几十张卡/行一次性挂载。
- CSS token 红线:列表态/分段/分组新样式只用 `tokens.css`,过 `check-css-tokens`。
- 跨 tab 关联:env-only 容器无 backendId,只能按 URL 匹配;匹配不到时优雅降级(不报错)。
