# v0.12.6 · 成员绩效项目级范围(A3)+ reject/类别下钻

> 轨道 A 第三刀(已知风险项,单独切版隔离回归)。路线见 [annotator-performance-deepening](2026-06-03-annotator-performance-deepening.md) §A3。

## 目标
1. **项目级范围(A3 核心)**:`/admin/people` 系列聚合按项目切分,而非"`project` 仅过滤返回哪些用户、数字仍全局"(研究档 §6 避坑)。放行 project_admin 看自有项目绩效。
2. **reject/类别维度下钻**(A2 顺延):tasks 端点支持按 reject 原因 / 类别过滤,详情抽屉项目模式下可下钻。

## 实现

### 后端(`apps/api/app/api/v1/dashboard.py`)
- 新增 `_resolve_people_scope(db, current_user, project)`:统一解析项目范围 + RBAC。
  - super_admin:`project` 可选(给定则校验存在),返回 pid 或 None(全局)。
  - project_admin:`project` **必填**且必须是其 owner 项目(`assert_project_visible`,越权 404、缺省 403)。
- 两端点角色门 `require_roles(SUPER_ADMIN, PROJECT_ADMIN)`;`admin_person_detail` 新增 `project` 参数。
- **每个聚合**加项目过滤片段(`*ann_proj`/`*task_proj`/`*event_proj`):
  - list:ann 吞吐 / rev 吞吐 / 上周·本周 / reopen / sparkline / active_minutes。
  - detail:throughput / 4 周趋势(产能+质量) / 项目分布 / 耗时直方图 / 周环比。
  - 3 个 v0.12.4 helper(`_reject_reason_breakdown`/`_class_distribution`/`_first_pass_yield`)加可选 `project_id`。
- **不切分**:timeline(审计流,无可靠 project 维度)、project_count(成员所属项目数)。
- export 端点放行 project_admin(委托 `admin_people_list` 强制范围)。

### 后端(`apps/api/app/api/v1/tasks.py`)
- `GET /tasks` 新增 `reject_reason_type`(`Task.reject_reason_type ==`)与 `class_name`(`exists(annotation WHERE task_id & class_name & is_active)`)过滤。

### 前端
- `permissions.ts`:project_admin 加 `admin-people` 页面权限。
- `Sidebar.tsx`:`admin-people` 入口去掉 `isSuperAdmin` 硬门,由 `canAccessPage` 过滤(analytics/health 仍超管专属)。
- `useDashboard.ts`:`useAdminPeople` 加 `enabled`;`useAdminPersonDetail` 加 `project`。`dashboard.ts` getAdminPersonDetail 加 project。
- `tasks.ts`:`TaskListParams` + `listByProject` 加 `reject_reason_type`/`class_name`。
- `AdminPeoplePage.tsx`:
  - 项目下拉(super_admin 含「全部项目」,project_admin 锁自有项目 + 自动选第一个,未选不发请求避免 403)。
  - project 传入 list / export / 详情抽屉。
  - 详情抽屉项目模式下 reject 原因 / 类别行可点 → `DrillTaskList` 内联展开该项目内本人匹配任务(只读 display_id + 状态)。
