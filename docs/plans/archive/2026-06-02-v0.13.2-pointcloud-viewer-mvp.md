# v0.13.2 · 前端点云查看器 MVP(只读)

> Epic:[点云 + 图像联合标注工作台](./2026-06-02-v0.13.x-point-cloud-workbench-epic.md) 第三切片。
> 主题:引入 **Three.js**(裸 + React 薄封装),在工作台渲染**点云 + 相机视图**,**只读(可看不可标)**。
> 依赖:v0.13.1(scene 导入 + link + 标定)。
> 调研对应:research §14.10.4(双栈架构 / 裸 Three.js 决策)、§14.8.4(前端是工作量大头)。

## 背景

后端两切片已能把 scene 导入为「task + 多文件 link + 标定」。本切片首次让用户**看见**点云:打开一个 lidar 任务,3D 渲染主点云,旁边列出各相机图像。先只读,3D 框标注(v0.13.3)与投影联动(v0.13.4)分开做,避免一次吞太多。

### 已就位的接缝(勘探确认)
- **分流点**:`useWorkbenchShellModel.tsx:272` 已有 `stageKind = type_key === "lidar" ? "3d" : ...`;`WorkbenchStageHost.tsx` 的 `"3d"` 分支当前是占位符 `ThreeDWorkbenchPlaceholder` —— **本切片把它替换成真 `ThreeDWorkbench`**。
- **点云文件已可取**:v0.13.1 令 `task.dataset_item_id` = 主点云、`task.file_path` = lidar `.pcd`,故 `task.file_url`(tasks.py:1979 presign)**已直出点云 URL**,前端无需新接口即可加载主点云。
- **缺口**:相机图 URL + 各相机标定没有 API 暴露(`TaskDatasetItemLink` 仅 service 层)。

### 点云格式(夹具实测)
`.pcd` v0.7 **binary**,`FIELDS x y z _ intensity _ timestamp _ ring _`(含 `_` padding 字段),单帧 ~6.7 万点。loader 需正确跳过 padding、读 xyz(+ 可选 intensity 上色)。

## 范围(做什么)

### 0.13.2-1 点云 manifest API(后端,小)
- 新增 `GET /tasks/{id}/point-cloud/manifest` →
  ```
  { point_cloud_url, point_cloud_format: "pcd",
    cameras: [{ name, role, image_url, calibration: SensorCalibration | null }] }
  ```
- 实现:`get_linked_items(task)` 取 link → 主点云 presign(或复用 task.file_url)、各 camera item presign + 读 `metadata_["calibration"]`。仿 video manifest endpoint(tasks.py:326 一带)风格,返回 `expires_in`。
- 非 lidar task 调用 → 404 / 409(明确报错)。

### 0.13.2-2 引入 Three.js(裸 + 薄封装)
- `apps/web/package.json` 加 `three` + `@types/three`(**不引 react-three-fiber**,epic 决策:命令式编辑器更顺)。
- `vite.config.ts` `manualChunks` 加 `"vendor-three": ["three"]`;**3D 模块整体 lazy import**(`React.lazy` / 动态 `import("three")`),只有打开 lidar 任务才加载 three(~600KB 不进主 bundle、不拖累 2D 工作台)。

### 0.13.2-3 前端 3D 模块(独立目录,双栈隔离)
`src/pages/Workbench/stages/three-d/`(与 Konva `stage/` 平行,**不污染**现有 2D):
- **薄封装**:`PointCloudScene.ts`(命令式)—— 管 `WebGLRenderer` / `PerspectiveCamera` / `Scene` / `OrbitControls`,挂载到 React ref 容器,负责 resize / dispose 生命周期。
- **加载点云**:`loadPcd(url)` 用 Three.js `PCDLoader`(或自写 binary 解析兜底 padding/intensity);转 `THREE.Points` + `PointsMaterial`。
- **`ThreeDWorkbench.tsx`**:React 组件,`useTaskPointCloudManifest(taskId)` 拉 manifest → 渲染 `<PointCloudViewport>`(3D 画布)+ 相机图面板(只读缩略/可放大)。
- **交互(只读)**:OrbitControls(旋转/平移/缩放)、点大小调节、上色切换(高度 / intensity)、reset view、点数/帧信息条。
- **性能地基**:大点云**抽稀 / LOD**(超过阈值如 50 万点按步长降采样渲染),`log()` 提示已抽稀;为 v0.13.3+ 规模化留钩子。**别等卡了再补**(epic 风险条)。

### 0.13.2-4 接线
- `WorkbenchStageHost` 的 `"3d"` 分支:`ThreeDWorkbenchPlaceholder` → `<Suspense>` 包 lazy `ThreeDWorkbench`。
- `useWorkbenchShellModel` 输出加 `3d` layout 分组(taskId + manifest hook),仿 image/video 分组。
- 新 SDK:`tasksApi.getPointCloudManifest(taskId)` + React Query hook `useTaskPointCloudManifest`(codegen 出类型后接)。

## 不做(明确排除)
- 不做 3D 框标注 / 任何写操作(v0.13.3)。
- 不做标定驱动的 3D→2D 投影 / 联动高亮(v0.13.4);相机图只**平铺展示**,不画投影框。
- 不做点云语义分割 / point_mask。
- 不动现有 Konva 2D / 视频工作台。
- 不做多帧序列播放(单帧 task 维度)。

## 风险
- **PCD binary + padding/intensity**:`PCDLoader` 对 `_` padding 字段兼容性需实测;不行则自写 binary 解析(按 FIELDS/SIZE/TYPE 偏移读 xyz)。先用夹具 `000970.pcd` 验证。
- **bundle 体积**:three ~600KB;必须 lazy + 独立 chunk,确保 2D 工作台首屏不退化(验证 `pnpm build` chunk 分布)。
- **WebGL 资源泄漏**:切任务 / 卸载要 `dispose()` geometry/material/renderer,否则多次进出 OOM。生命周期在薄封装里收口。
- **大点云**:百万点需抽稀;本切片先做降采样,真正 LOD/分块加载随规模化深化。
- **dev 环境点云数据**:需把夹具 scene 真导入 pcwb 栈(MinIO + DB)才能在浏览器看到;验证前先用导入管线灌一个 lidar 项目。

## 验证(成功标准)
- **后端**:`GET /tasks/{id}/point-cloud/manifest` 返回正确 point_cloud_url + cameras(URL 可下载、calibration 与导入一致);非 lidar task 报错。`uv run pytest` 新增端点测试。
- **前端**:把夹具 scene 导入 pcwb 栈 → 浏览器打开该 lidar 任务 → 点云渲染、OrbitControls 可转、相机图列出;切任务无 WebGL 泄漏(console 无 context lost / 内存稳定)。用 chrome-devtools MCP 实测截图。
- `pnpm --filter web typecheck` / `pnpm lint` / `pnpm --filter web build`(确认 vendor-three 独立 chunk、主 bundle 不含 three)。
- 现有 2D / 视频工作台回归无影响(分流隔离)。
