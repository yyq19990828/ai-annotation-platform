## 2. 与组件迁移的不同:页面是「叶子」,改写 JSX 而非保 API

页面不被别处 import → **没有「调用点零改动」约束**,直接改写页面自身 JSX + 退役其 module.css。范式:

1. **根节点挂 `tw-scope`**:迁移期无全局 preflight,页面用 Tailwind 工具类需 `.tw-scope` 局部 reset(box-sizing / margin / border 基线)。每个迁好的页面根 `className="tw-scope ..."`(同 `/dashboard-next` PoC)。
2. **JSX 用 Tailwind + `ui/` 组件**:布局/间距/排版用 Tailwind;按钮/输入/卡片/徽标/头像等用已迁好的 `@/components/ui/*`(它们自带 UA 基线,可在/不在 tw-scope 都正确)。
3. **颜色走设计规范**:中性 `--sc-*`(bg-background/card、text-foreground/muted-foreground、border-border),语义彩色走 §2.2 调色板 + 暗色配对;**严禁裸色/任意色值**(tw-tokens 门禁)。
4. **退役 module.css**:逐页删除;`grep` 确认无残留 import。
5. **更新测试**:页面 test 若按 module class 断言(`styles.x` / `_class_hash`),改用语义查询(role/text/label)或新 className;行为断言不变。
6. **`DashboardPage` 提为正式**(epic 阶段 3):把 `/dashboard-next`(`DashboardPageNext.tsx`)的范式落为正式 `DashboardPage`,删旧实现;路由 `/dashboard` 指向新版,移除临时 `/dashboard-next`(或保留 alias 一版)。**单独 commit,重点验**。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| **UA 漏样**(反复踩) | 页面里任何裸 `<input>/<button>/<select>/<textarea>` 必须显式 `appearance-none border-0/border bg-transparent`;优先用已迁 `ui/` 组件(自带基线)。每页 light/dark 截图核对边框/底色。 |
| `.tw-scope` 与页面内未迁子组件共存 | tw-scope 只加在页面根;若页面仍引用某未迁子组件(自带 module.css),其样式不受 tw-scope reset 破坏(scope reset 只设 box-sizing/border-width:0,子组件 css 显式覆盖)。逐页核对。 |
| 页面 test 按 module class 断言 | 改语义查询(role/text/label);行为断言不变。逐页跑该页 test。 |
| `DashboardPage` 提 Next 改路由 | 单独 commit;确认 `/dashboard` 指新版、删 `/dashboard-next` 不破坏书签(可留 alias 一版);跑 DashboardPage.test。 |
| 大页面一次性改动大 | 按 §3 分 4 组、逐页提交,可回退。 |
| 截图基线变化 | 视觉重设计本就改观;Playwright 截图 diff 人工确认是「预期重设计」而非 bug。 |
