Phase 2 的独立落地。**地基版**——把「源 = 合成第 0 号 root 阶段」的五套特判收敛成 graph 内一条
携带 `source:{}` 的普通输入节点，并解除对 video 项目的编排早退。v0.21.6（tracker 接编排）依赖本版。

## 背景与动机

源目前是「画布/payload 层合成的第 0 号 root 阶段」，散落 5 个文件靠
`ROOT_SID` / `kind==="source"` / `isSource` / `stage:0` / `deriveSourceShape` 五套特判维系：

- 真值模型 `stagesGraph: {sid, parentSid}[]` **不含源**；源边靠 `parentSid==="root"` 隐式表达，
  源节点在 `ProjectDetailPanel` / `GlobalPipelineLibraryPage` 里**手工合成**。
- `deriveSourceShape`（`utils/pipelineGraph.ts:193`）是 v0.21.1 WS0 的**过渡产物**——从 model 反推源
  类型/产物标签，本版退役。
- 「video 项目进不了编排」的真正位置 = `ProjectDetailPanel.tsx:657` 的
  `if (dataType==="video") return <VideoPreannotateGuide>` 早退（**不是列表过滤**）。

**终态（ROADMAP 方向 B/C，Option B 统一画布）**：源收敛成 graph 内 `parentSid=null` 且携带
`source:{kind:"dataset", data_type, execution_unit}` 的普通 entry；画布不再 special-case 源 vs 阶段；
同一编排器按 `project.data_type` 派生（**不新建视频专属编排 surface**）。

**最小原则**：本期只做「输入节点 + video 输入 + 执行单位=video 单分支」跑通，不预建 frame/scene
分支 UI（那是 v0.21.7）。

## 风险

- **改已发布 v0.21.0 编排**：payload 结构变更须向后兼容旧持久化 `project_pipelines`（stage0=源）——
  反序列化时把旧 `stages[0]`（无 source 字段）识别为输入节点，避免砸存量模板。
- **五套特判散在 5 文件**：改一处漏一处易致画布渲染错乱；WS2-7 需一起改、测试兜底。
- **默认值=现状红线**：image 项目现有编排行为零回归（输入节点 data_type=image/execution_unit 缺省
  等价旧「源阶段」）。

## 验收

- image 项目编排：输入节点作首节点渲染，下游 stage 行为与 v0.21.0 一致（零回归）。
- video 项目能进编排（不再早退 VideoGuide），输入节点显示 `data_type=video` + `execution_unit=video` 徽标。
- 旧持久化 `project_pipelines` 模板能正确加载（stage0→输入节点）。
- `deriveSourceShape` 无引用；画布无 `SourceNode`/`StageNode` 二分。
