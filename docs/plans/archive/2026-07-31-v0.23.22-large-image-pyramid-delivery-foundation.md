## 1. 本版目的

本版建立超大图 tile 的服务端派生资产与访问合同，但不改 `ImageStage` 的生产渲染。

当前 thumbnail worker 会：

```text
MinIO Body.read()
  → Python bytes 持有整对象
  → Pillow Image.open(...).convert("RGB")
  → resize/encode
```

这条链路适合普通 thumbnail，不适合作为 50MP–250MP 金字塔 generator。大图生成必须：

- 流式下载到有界临时文件；
- 使用按 region/sequential 处理的 generator；
- 对 decoded pixels、tile count、derived bytes、临时磁盘、wall time 和并发设置硬上限；
- 在临时 generation 完整成功后原子发布 manifest/DB ready；
- 失败时不留下“DB ready、对象缺失”或半个 pyramid；
- 私有对象存储中不把数千个 presigned URL 塞入 Task 列表。

v0.23.22 完成后，客户端能够获得一个稳定、鉴权、有 generation fence 的 pyramid manifest 和
可见 tile URL，但 v0.23.23 才开始让 Konva 消费它。

## 2. 冻结决策

### D1. 专用状态模型，不把完整 manifest 塞入 JSONB

资产身份与 generation 分两层：

```text
image_pyramid_assets
  id UUID
  dataset_item_id UUID nullable
  task_id UUID nullable
  profile_version string
  active_generation integer nullable
  building_generation integer nullable
  created_at / updated_at

image_pyramid_generations
  asset_id UUID
  generation integer
  source_fingerprint string
  status pending | building | ready | failed
  width / height
  tile_size
  overlap
  max_level
  format
  normalization_version
  manifest_key
  overview_key
  tile_count
  retained_bytes
  error_code
  attempts
  last_accessed_at
  created_at / updated_at
```

合同：

- asset 的 `dataset_item_id` 与 `task_id` 恰有一个非空；
- DatasetItem 来源的多个 Task 共用同一 asset；legacy direct Task 使用 task-scoped asset；
- asset 以 `(owner, profile_version)` 唯一，generation 以 `(asset_id, generation)` 唯一；
- `active_generation` 只指向已完整验证的 ready generation；
- `building_generation`/partial unique constraint 保证一个 asset 同时最多一个 pending/building；
- profile/normalization 重建且 source fingerprint 不变时，manifest endpoint 继续提供旧 active，
  新 generation 只在发布事务中原子替换 active pointer；
- source 对象被替换且 fingerprint 变化时，旧 ready 只能保留作回收/审计，不能继续作为当前图片
  active 内容返回；客户端使用新源的 overview/thumbnail + processing 状态，避免把旧像素与新标注坐标叠加；
- failed building generation 不清空仍匹配当前 source fingerprint 的旧 active；
- `error_code` 为低基数稳定 code，不持久化任意 decoder stderr。

### D2. 平台自有 manifest v1

采用轻量、自描述、immutable 的 manifest：

```json
{
  "schema": "aap-image-pyramid/v1",
  "generation": 3,
  "sourceFingerprint": "sha256:...",
  "normalizationVersion": "v1",
  "width": 16385,
  "height": 12289,
  "tileSize": 512,
  "overlap": 1,
  "format": "webp",
  "levels": [
    {
      "level": 0,
      "scaleFactor": 1,
      "width": 16385,
      "height": 12289,
      "columns": 33,
      "rows": 25
    },
    {
      "level": 1,
      "scaleFactor": 2,
      "width": 8193,
      "height": 6145,
      "columns": 17,
      "rows": 13
    }
  ],
  "overview": {
    "width": 512,
    "height": 384,
    "contentDigest": "sha256:..."
  }
}
```

实际 manifest 可把 levels 由小到大排序，但 schema 与客户端必须只依赖显式 `scaleFactor`，不得依赖
数组顺序猜测。

manifest 不包含：

- object storage key；
- 全量 tile URL；
- bucket/endpoint；
- 用户/项目标识；
- adapter/GPU 信息。

### D3. 512 core + 1px overlap

- logical core tile 为 512×512；
- 存储 tile 可含 1px overlap；
- manifest/URL 坐标 `(level, x, y)` 指 logical core；
- edge tile 的 full-resolution source rect 由整数公式显式推导；
- overlap 只用于采样接缝，客户端必须 crop，不能把 overlap 计入 world geometry；
- 背景 tile 与 Mask tile 恰好同为 512 只是坐标便利，不共享内容或 key。

### D4. pyvips binding 作为生产生成器

M0 保留以下比较：

- `libvips` CLI；
- `pyvips.Image.dzsave()`；
- 现有 Pillow 仅作为小 fixture correctness oracle，不作为大图 production candidate。

选择标准：

- peak RSS；
- wall time；
- temp disk；
- output bytes/tile count；
- JPEG/PNG/alpha/gray/ICC/EXIF correctness；
- Debian/production image 安装体积与 arm64/x86_64 可用性；
- 取消、超时与进程 crash 后可清理性。

实现冻结：

- production path 使用 `pyvips.Image.dzsave()`，依赖镜像内 `libvips-tools`；
- binding 便于同一进程内读取 header、执行 EXIF autorotate、颜色规范化并获取精确输出元数据；
- CLI 保留为 spike/故障隔离对照，不作为本版运行路径；
- Pillow 仅处理小 fixture、header probe 与 correctness oracle，不允许成为 eligible 大图的生产兜底；
- pyvips/libvips 不可用时返回稳定 `generator_unavailable`，不得回退到 `Body.read()` + Pillow。

### D5. 私有存储使用批量签发

API：

```text
GET  /api/v1/tasks/{task_id}/image-pyramid
POST /api/v1/tasks/{task_id}/image-pyramid/asset-urls
POST /api/v1/tasks/{task_id}/image-pyramid/retry
```

- manifest endpoint 做现有 Task 可见性鉴权，返回 status envelope；ready 时包含 immutable manifest
  和短期 `overview.url/expires_at`，但 object storage key/签名 URL 不写入 manifest object；
- `asset-urls` body 最多 128 个 discriminated item：
  `overview(generation)` 或 `tile(generation, level, x, y)`，供 overview/tile 同步刷新；
- 服务端验证 generation、level、grid bounds 与 asset owner，再签发；
- 返回统一 `expires_at`，客户端可批次刷新；
- 禁止前端提交/拼接任意 object key；
- retry 只允许对 failed/stale 资产，具备幂等与频率限制；
- manifest 使用 `ETag`、`Cache-Control: private`；
- tile 对象 immutable，可在 presigned response 上使用长缓存语义。

单 tile authenticated redirect 可作为调试/兼容端点，但生产 scheduler 不应为每个 tile 多一次 API
round trip。

### D6. 派生资产与源同寿命

首版不让 `image-pyramids/` 进入 30 天 lifecycle：

- source 删除/替换时清理对应 owner 的 generation；
- failed/incomplete staging prefix 有短 TTL 或显式 GC；
- ready row 指向的 generation 不被 bucket lifecycle 单独删除；
- orphan scanner 对 DB row 与 object prefix 做双向对账；
- 如未来改成可过期缓存，必须同时交付请求时自愈/惰性重建，不能单改 lifecycle。

## 3. Full-resolution 坐标与规范化

### 3.1 坐标合同

pyramid `width/height` 必须与工作台使用的 full-resolution logical image dimensions 一致。

必须覆盖：

- 非 2 次幂；
- width/height 不能被 512 整除；
- 1×N/N×1 edge；
- scale factor 逐级 ceil/floor；
- overlap crop；
- EXIF orientation 1/3/6/8；
- ICC → sRGB；
- grayscale 与 alpha。

### 3.2 EXIF/历史数据

不得在已有标注任务上静默改变坐标：

1. M0 记录浏览器 `naturalWidth/Height`、DatasetItem width/height、Pillow、libvips 对每个 EXIF fixture
   的结果。
2. 冻结 `normalization_version`：是否 autorotate、何时 strip metadata、如何得出 logical dimensions。
3. 新入库图片在任务/标注创建前写入规范化尺寸。
4. 已有 annotation 的 owner 若数据库尺寸与生成结果不一致，资产状态为 stable failed/ineligible，
   客户端继续原路径，需迁移时另立显式工具。
5. 不允许只旋转 pixels 而保留旧 dimensions/annotations。

### 3.3 编码策略

M0 比较：

- opaque photo：高质量 WebP 与 JPEG；
- alpha/line art：lossless WebP 与 PNG；
- overview：WebP；
- 色彩：统一 sRGB，manifest 记录 normalization version；
- 不默认引入 AVIF/JXL，避免生成耗时与浏览器矩阵扩大。

最终策略需以缺陷标注视觉 golden、文件大小和生成成本决定。若 lossy tile 与源图差异超过计划阈值，
对该格式/项目使用 lossless，不以带宽收益牺牲可见缺陷。

## 4. Eligibility 与状态

冻结阈值：

```text
pixels < 16,777,216
  → not required，现有整图

16,777,216 <= pixels < 50,000,000
  → optional candidate，可后台生成但客户端默认仍可整图

pixels >= 50,000,000
  → required，自动生成；客户端不得自动整图 decode
```

硬上限：

- maximum decoded pixels：300,000,000；
- maximum width/height：32,768；
- maximum tile count：20,000；
- maximum derived bytes：8 GiB；
- maximum temp disk：12 GiB；
- maximum source compressed bytes：8 GiB；
- maximum duration：1,800 秒；
- generation lease：2,100 秒；
- asset URL expiry：900 秒；
- retry cooldown：300 秒。

超过 hard limit 返回稳定 `unsupported_dimensions`/`resource_limit`，不重试风暴。

状态机：

```text
missing → pending → building → ready
                    └→ failed

ready + profile drift、source 相同 → active(old) + pending(generation + 1)
ready + source replacement → inactive(old) + pending(generation + 1)
failed + explicit/eligible retry → pending(same or next generation by policy)
```

- 一个 owner 同 profile 同时最多一个 building；
- Worker crash/timeout 后 lease 到期可重领；
- ready 发布点是“tiles + overview + manifest 全部验证成功，在同一 DB transaction 中将 generation
  标记 ready 并原子切换 asset.active_generation”；
- 同 source 的 profile rebuild 失败时旧 active 继续服务；source replacement 时旧 generation
  不再服务，但可保留到新 generation 发布/回收窗口结束后再 GC。

## 5. 生成流程

```text
load owner/source fingerprint
  → acquire DB row/lease
  → stream MinIO object to bounded temp file
  → probe header/dimensions/format
  → eligibility + decompression/resource admission
  → generate into unique staging directory
  → verify tile grid/digests/count/edge dimensions
  → upload staging prefix
  → upload immutable manifest last
  → DB transaction status=ready
  → asynchronously GC previous/stale generation
```

要求：

- 不使用 `Body.read()` 聚合整个 source；
- media pyramid queue 初始每 worker 并发 1；
- subprocess 有 process group、timeout、stderr cap 与 kill；
- 临时路径使用安全的 task-specific directory；
- 文件名/manifest 不接受源文件名拼接；
- upload 支持流式/分块；
- generation 可重复执行而不发布重复 active row；
- 任何失败将 DB 置 stable failed、释放 lease、安排 staging cleanup。

## 6. API 与 Task 输出

Task 列表/详情只增加轻量 summary：

```json
{
  "image_pyramid": {
    "status": "ready",
    "generation": 3,
    "width": 16385,
    "height": 12289,
    "tile_size": 512,
    "format": "webp",
    "required": true
  }
}
```

不放 full manifest 或 tile URLs，避免任务队列响应膨胀。

Manifest endpoint：

- `ready` 返回 active generation 的完整 v1 + 短期 overview URL envelope；同 source rebuild
  进行中时另外返回 building generation/status，但不切断 active；
- `pending/building` 返回 status、retry_after_ms、overview/thumbnail available；
- `failed` 返回 stable code、retryable、required；
- gate off/not eligible 返回 `not_available`，小图客户端继续现路径；
- 每次 successful read 更新 `last_accessed_at` 应做采样/异步，避免热点写。

Asset URL batch：

- overview/tile discriminated items 去重并保持请求顺序；
- 超限 422；
- stale generation 409，返回 active generation；
- asset not ready 409；
- 无权限 403；
- 对象缺失不得仍返回 signed URL，应把资产标记 inconsistent 并触发自愈/告警；
- URL expiry 至少覆盖正常 fetch/decode 窗口。

## 7. 数据迁移与回填

- migration 只建表/索引/check，不同步扫描或生成；
- 新图片 upload/thumbnail 流程在尺寸已知后 enqueue eligible pyramid；
- 旧 DatasetItem 提供管理命令按 cursor 扫描并 enqueue；
- legacy direct Task 单独处理，避免同 file_path 重复 Task 无界生成；
- backfill 可 dry-run，输出 eligible/skipped/unsupported 数量；
- source fingerprint 缺失时可流式计算一次并写回，不以路径作为内容 identity；
- 回填 gate 默认关闭，运维显式启动，队列与并发独立。

## 8. 安全与资源门

### 8.1 输入

- header 与实际 decode dimensions 一致；
- decompression bomb 按 decoded pixels 拒绝；
- 多页 TIFF/GIF 拒绝进入 raster pyramid v1；
- SVG/PDF 不进入 raster pyramid v1；
- corrupt/truncated source stable failed；
- 路径、symlink、archive traversal 不适用/不得引入；
- libvips loader allowlist 与系统 codec 版本可追踪。

### 8.2 访问

- 所有 manifest/overview/tile URL 签发复用 Task/Project 权限；
- 坐标和 generation 严格验证；
- 返回内容类型与 manifest format 一致；
- CORS 仅按现有前端 origin；
- access log 不记录完整 presigned query；
- rate limit 防 tile coordinate enumeration/重签风暴；
- 不把 storage host/key 暴露进持久客户端状态。

### 8.3 资源

- 独立 Celery route/queue；
- 单 job wall timeout；
- download/generated/upload bytes 指标；
- temp disk reservation；
- per-worker concurrency 1 起步；
- generation lease 与重复消息幂等；
- cleanup 自身有 batch/timeout 上限。

## 11. 验收门

### Correctness

- 每级 level dimensions、columns/rows 与 tile source rect golden exact；
- edge/overlap 没有丢/重采 logical pixel；
- EXIF/ICC/alpha fixture 与冻结 normalization 一致；
- existing annotation owner 不发生 dimensions drift；
- manifest digest/grid 与实际 objects 一致；
- duplicate/timeout/crash 不发布半成品。

### 性能/资源

- 50MP/200MP 生成不将整个源对象读入 Python bytes；
- peak RSS、temp disk、wall time 均低于 M0 冻结门；
- 同 worker concurrency=1 时连续 20 个 job 资源回到 plateau；
- derived bytes/tile count 在 hard limits 内；
- Task list 不因 pyramid 增加 O(tile count) payload。

### 访问/故障

- unauthorized 无 manifest/overview/tile URL；
- invalid coordinate/generation 不签发；
- expired batch 可刷新；
- stale generation 不能进入 active client cache；
- source/object missing 有稳定状态与自愈/告警；
- retry/backfill 无重复 active generation。

## 12. Rollout 与回滚

- `IMAGE_PYRAMID_AUTO_GENERATE=false` 关闭自动 enqueue；
- manifest/API 可先部署，不被 v0.23.23 客户端选择；
- generator 镜像/依赖回滚不影响 source/Task/annotation；
- ready assets 保持可读，除非明确禁用 API；
- schema 可保留，生成状态不影响普通 Task；
- 禁止以删除 ready objects 作为紧急回滚。
