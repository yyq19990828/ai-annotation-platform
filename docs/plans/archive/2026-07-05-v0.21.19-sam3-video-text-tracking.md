状态：**计划（2026-07-05，修订 2026-07-07：纠正 sam3 视频权重认知 + 补 sam2_video 扩充评估）**。把视频追踪对话框里
**纯占位的 `sam3_video` 选项**接成真能力——文本/exemplar 驱动的视频目标追踪。**跨前后端 epic 级**（前端 text UI +
协议 text 字段贯通 + 能力协商建模 + **ML backend 新建 video predictor**），非纯前端、非单版本可完结；本计划定「协议贯通 +

## 动机（现状：sam3_video 选项存在但纯占位，带证据）

调研结论先行：**`sam3_video` 已在前端下拉与后端 adapter 注册表里占了槽位，但走的是和 `sam2_video` 完全相同的
seed-bbox 传播链——没有 text 输入、没有 text 协议字段、sam3-backend 侧完全没有 video 实现。**

### 现状 1 · 前端选项占位、无 text 框
`apps/web/src/pages/Workbench/stage/VideoTrackerPropagateDialog.tsx`：`TRACKER_MODEL_OPTIONS:34-38` 含
`sam3_video`（`:37`，note 同 sam2「需项目绑定 ML backend」）；模型下拉 `:290-306` 全渲染。但提交 payload
（`handleSubmit:202-208`）只有 `from_frame/to_frame/model_key/direction/sam_variant`——**无任何 text 字段**；
SAM 尺寸 `SAM_VARIANTS:41-47` 选的是 tiny/small/base_plus/large 尺寸，不是 text。

### 现状 2 · 后端协议无 text，job 链路 bbox-only
- POST `.../tracks/{annotation_id}:propagate`（`apps/api/app/api/v1/tasks/video.py:638`）→ `create_tracker_job`。
- 请求 schema `VideoTrackerPropagateRequest`（`schemas/video_tracker_job.py:14-28`）：`prompt: dict`（自由 JSONB，
  `:20`，只校验是 object）+ `sam_variant`——**协议无 text 字段**（可塞进自由 `prompt` 但无人写/读）。
- `create_tracker_job`（`services/video_tracker_job_service.py:140-190`）落库时只把 `sam_variant` 合进
  `payload.prompt`（`:168-171`），不注入 text/exemplar。
- 能力协商 `capability_registry.py:278-298` `TaskSpec(id="tracker")` 只声明「`/setup.supported_trackers` +
  `/predict` 返回带 instance_id 的 bbox 序列」；**sam2 vs sam3 在 API 侧零差异**，text/exemplar 协商在 tracker
  链路完全未建模（text/exemplar 只在图片 `interactive_seg` 链路存在）。

### 现状 3 · sam3-backend 无 video 实现（最大缺口）+ 视频权重认知纠正
`apps/api/app/services/video_tracker_adapters.py:159-163`：`sam3_video → MLBackendVideoTrackerAdapter("sam3_video")`
（`:162`，与 sam2 共用同一 adapter 类），context（`:107-120`）里也没有 text/exemplar 字段。而实际 backend：
- **`sam2_video` 有完整实现**：`apps/grounded-sam2-backend/`（`/setup` 声明 `supported_trackers:["sam2_video"]`，
  `_run_video_tracker`（`main.py:1057-1108`）+ `SAM2VideoTracker.propagate`（`video_predictor.py:98`）+ 独立显存池
  `video_pool.py`）。
- **`sam3_video` 完全没有 backend 实现**：`apps/sam3-backend/` 是**纯图片** backend（`main.py` 只 image predict，
  `type ∈ {point,interactive_box,text,exemplar}`），无 `video_predictor.py`、无 `video_tracker`/`supported_trackers`。

**⚠️ 关键认知纠正（修订新增）——sam3 的视频能力不是图像模型的延伸，而是独立的视频权重 sam3.1_multiplex：**
- 仓库里 `sam3.pt`（3.0）与 `sam3.1_multiplex.pt`（3.1）**不是同一图像模型的两个版本，而是两种不同模态的模型**：
  `facebook/sam3 → sam3.pt` 是**图像**模型（PCS + inst 交互），`facebook/sam3.1 → sam3.1_multiplex.pt` 是**视频**模型
  （Object Multiplex 多目标追踪）。见 `sam3-backend/scripts/download_checkpoints.py:46-53`（两套 repo+权重）、
  `predictor.py:83-85`（`MODEL_VARIANT="sam3"`，注释「当前加载 sam3.pt (3.0)…sam3.1_multiplex 是视频模型」）。
- **「3.1 被临时屏蔽」的真实含义**：图像 `/predict` **故意不加载** 3.1 视频权重——`predictor.py:120-124` docstring +
  `download_checkpoints.py:14-19` 说明：3.1 的 inst 权重命名（`tracker.model.*`/`interactive_convs`）与 vendored 图像-inst
  结构（`inst_interactive_predictor.model.*`/`sam2_convs+convs.3`）**对不上 → 强载会静默加载随机权重 → 噪声 mask**。
  是**架构不兼容**，不是显存或能力回退。下载侧软屏蔽：`SAM3_DOWNLOAD_VIDEO` 默认关（`download_checkpoints.py:81,108-128`）。
- **结论**：sam3_video 的 backend 实现应**加载 sam3.1_multiplex 走视频路径**（vendor `model_builder.py:937`
  `build_sam3_multiplex_video_model`），而非从图像 sam3.pt 延伸。sam3 图像侧继续用 3.0 sam3.pt，视频侧用 3.1 multiplex，
  **两者并存、各占一份显存，不是二选一**。

### 坐标红线
视频存储/交互统一**归一化 [0,1]**（`videoKonvaCoordinates.ts:6-8` 「epic 红线①」）；tracker 回填
`video_tracker_runner.py:61-67` `_normalize_bbox` + `:159-164` 写归一化 bbox。新链路须沿用。

## 定稿决策（拟）

- **切片边界**：本版本落「**协议 text 贯通 + 前端 text UI + 能力协商区分**」三层——让平台**能表达并下发**
  text-driven 追踪请求、前端条件式显示 text 框、能力协商区分「seed-bbox tracker（sam2）」vs「text-driven tracker
  （sam3 需 text/exemplar）」。**backend 实现（新建 sam3 video predictor + 显存池）是 gating 依赖，单列 PR/子计划**，
  在无 backend 前前端按能力协商**灰置** sam3_video（不做假占位可点）。
- **视频权重选型 → 只做 sam3.1_multiplex，不做 3.0 视频路径可选（修订新增，有明确默认答案）：**
  - 视频侧 backend 加载 `build_sam3_multiplex_video_model`（vendor `model_builder.py:937`）+ `sam3.1_multiplex.pt`。
  - **不引入「3.0/3.1 视频双可选」**。理由三条：① 官方 `RELEASE_SAM3p1.md:16-22`——3.1 视频侧相对 3.0 全面持平或更优
    （Object Multiplex 128 目标 ~7x 加速、VOS 6/7 benchmark 提升、MOSEv2 +2.0），**无回退**；② sam3-backend 现为单槽单变体
    （`main.py:189-214` `cap=1`、`main.py:408` `model_variant` `readOnly`、`main.py:225-226` 非法变体直接 422），做双可选
    要新增多变体加载 + 显存调度整套；③ 单卡已有图像 sam3.pt ~5.8GB 常驻，再叠视频 multiplex ~3.2GB，放不下同时三份，
    3.0 逐目标视频路径相对 3.1 无能力收益，保留只为 A/B 对比不值当。**若未来确需 A/B（对照 `README.md:251` v0.10.2
    AB 工具），单列后续版本，不进本切片。**
  - **多目标张力标注**：sam3.1 multiplex **天然多目标**，而当前 tracker 链路是单 annotation 单 track
    （runner 按单 annotation_id 传播）。首切片按「单目标每次一 track」消费 multiplex 输出（只取目标 track），
    多目标批量是后续能力，不在本版本。
- **协议 → `VideoTrackerPropagateRequest` 显式加 `text` / `exemplars` 字段**（而非塞进自由 `prompt`），
  `create_tracker_job` 写进 payload、`MLBackendVideoTrackerAdapter` context（`:107-120`）透传。exemplar bbox 沿用
  归一化，复用 sam3 图片侧 `Exemplar` schema 形状（`sam3-backend/schemas.py:49-65`）。
- **能力协商 → tracker TaskSpec 增「text-driven」维度。** `capability_registry.py:278-298` /
  `ml_capabilities.py`（tracker 判定 `:94/:179`）区分两类 tracker，`/setup` 声明 `supported_trackers` 时带
  text 需求标志；前端据此在 `modelKey==="sam3_video"` 时**必显** text 框、无绑定 sam3 backend 时灰置。
- **前端 → text 输入 UI + payload 扩字段。** `VideoTrackerPropagateDialog` 在 sam3_video 下渲染 text 框（+可选
  exemplar 框，复用图片交互 exemplar 手势另议），`handleSubmit`（`:202-208`）加 text；`VideoTrackerPropagatePayload`
  （`@/api/videoTracker`）扩字段。
- **跨窗 seeding 语义差异**：runner 跨窗靠上一窗 bbox 续追（`runner.py:275-317`）；text-driven 是**每窗按 text 重
  检测**而非 bbox 续追——runner 需按 tracker 类型分派 seeding 策略（本切片先定协议与前端，seeding 策略随 backend PR）。

## sam2_video 能否同步扩充（回应关注点，评估 + 归属，不进本切片）

调研结论：**vendor `SAM2VideoPredictor` 的能力远超平台当前暴露，扩充是「接线级」——不改模型，只在 wrapper 加参数 +
`/setup` 扩声明。** 平台现状是 SAM2.1（4 尺寸）**单目标、bbox-seed、单向、窗内 ≤300 帧**传播，输出逐帧 bbox +
**二值 confidence（`video_predictor.py:169` 写死 0.0/1.0）** + outside 标志。vendor 已原生支持但被平台丢弃/未接线：

| vendor 已原生支持 | 平台现状（`grounded-sam2-backend/`） | 归属建议 |
|---|---|---|
| **mask 输出**（`propagate_in_video` 本就 yield 原分辨率 mask logits） | 丢弃 mask 只算外接 bbox（`video_predictor.py:_mask_to_bbox_norm`） | → **v0.21.20 multi-geometry**（与其强耦合） |
| **point seed（正负点）、box+point 混合 refine** | 只传 box（`add_new_points_or_box` 仅 box 分支） | 可独立小改进，不阻塞本计划 |
| **mask seed**（`add_new_mask`） | 完全未接线 | 与 v0.21.20 协同 |
| **多目标**（obj_id 任意，propagate 返回 `[num_obj,…]`） | 硬编码 `_OBJ_ID=1`、只取 obj[0]（`video_predictor.py:62,254`） | 需 track 链路支持多目标，较重，后续 |
| **真实 confidence**（模型有 IoU/object score） | 写死 0.0/1.0 | 可独立小改进 |
| 原生长视频（`init_state` 直接吃整段） | 平台自切 ≤300 帧窗规避显存 | 长程 memory 优化，后续 |

**决策：不把这些塞进本 text-driven 计划（避免 scope 蔓延）。** mask 输出归 v0.21.20；point-seed/真实 confidence 可各自
拆独立小改进版本；多目标与 sam3.1 multiplex 的多目标能力共享同一「tracker 链路多目标化」的下游依赖，一并作后续 epic。

  text/exemplars；`create_tracker_job` 写 payload；adapter context 透传；tracker TaskSpec 建模 text-driven 维度；

- **PR2 · 前端 text UI + 能力灰置**：sam3_video 下显 text 框、payload 扩字段；无绑定 sam3 video backend 时按能力
  协商灰置（复用 v0.18.x 能力接线：backend 未声明 `supported_trackers:["sam3_video"]` 即不可选）。
- **PR3 ·（gating 依赖，单列）sam3.1_multiplex video backend 实现**：在 sam3-backend 新建 `video_predictor.py` +
  独立显存池（参考 grounded-sam2 `video_pool.py`）+ `/predict` 的 `type=="video_tracker"` text-seeding 分支 + `/setup`
  声明 `supported_trackers:["sam3_video"]`。**加载 `build_sam3_multiplex_video_model` + `sam3.1_multiplex.pt`**
  （非图像 sam3.pt），前置：打开 `SAM3_DOWNLOAD_VIDEO=1` + 接受 `facebook/sam3.1` gated license
  （`download_checkpoints.py:35-37,111-128`）。**显存**：图像 sam3.pt ~5.8GB 已常驻，叠视频 multiplex ~3.2GB+ 运行时激活，
  单卡紧张——需独立显存池 + idle 让渡（复用 `main.py:230-243` idle 卸载）。**镜像 COPY 需 rebuild 才生效**
  （见 CLAUDE.md §8；GPU 显存/权重需实测）。
- **PR4 · seeding 策略 + 回填**：runner 按 tracker 类型分派（text 每窗重检测 vs bbox 续追）；`apply_tracker_results`
  兼容 text-driven 输出；multiplex 多目标输出首切片按单目标消费（只取目标 track）。
- **验证 + 版本**：E2E ① 绑 sam3 video backend 项目 → sam3_video 可选、显 text 框、跑出候选；② 未绑 → 灰置；
  ③ sam2_video seed-bbox 链零回归；④ 归一化坐标正确。CHANGELOG（Added）+ 版本 bump（后端能力 = minor 语义）。

## 不在范围

- **多几何 track（polygon/polyline/mask）**：见 [v0.21.20](2026-07-05-v0.21.20-multi-geometry-track.md)。**但注意 AB
  耦合**：sam3/sam2 内部本是 mask 模型，text→mask 是自然产物，当前两链都在 bbox 边界丢 mask
  （`video_predictor.py:164`、`runner.py:159`）；本计划先只取 bbox 候选，mask 保留与 v0.21.20 协同。
- **sam2_video 接线级扩充（mask 输出 / point-seed / 多目标 / 真实 confidence）**：见上「sam2_video 能否同步扩充」节，
  按归属拆到 v0.21.20 或独立小改进版本，不进本 text-driven 切片。
- **sam3 视频 3.0/3.1 双可选（A/B 对比）**：本切片只做 3.1_multiplex；双可选需多变体加载+显存调度，无能力收益，
  若确需 A/B 单列后续版本。
- **图片侧 sam3 text/exemplar 交互**：已存在（`interactive_seg` 链），不动。
- **exemplar 视频侧手势 UI**：exemplar 框在视频时间维的采集手势较重，本切片先支持 text，exemplar 协议留位、UI 另议。

## 风险

- **协议契约两端耦合**：adapter context（`:107-120`）与 grounded-sam2 `_run_video_tracker`（`main.py:1057`）是隐式
  契约；sam3 复用同 context 但 seed 换 text，runner 跨窗 seeding 语义变（text 重检测 vs bbox 续追），须分派。
- **backend 是重头新建 + 显存现实**：sam3-backend 现无任何 video 代码 + 无 video 显存池；PR3 是本计划真正的工作量与
  GPU 依赖风险。**单卡需同时容纳图像 sam3.pt(~5.8GB) + 视频 sam3.1_multiplex(~3.2GB)**，是硬约束，可能需 idle 让渡
  或分卡部署；权重走 gated license + 冷启动成本（图像重载参照 `main.py:154` ~8-12s 量级）。前端/协议先行、backend
  gating 是为让平台侧不阻塞。
- **runner 强 bbox 假设**：`apply_tracker_results`（`runner.py:128-186`）全程 `_normalize_bbox`+`video_track_bbox`；
  text 若产 mask/polygon 会被降级（与 v0.21.20 强耦合）。
- **multiplex 多目标 vs 单 track 链路错配**：sam3.1 multiplex 天然多目标，而 runner/落库是单 annotation 单 track；
  首切片按单目标消费（只取目标 track）会浪费 multiplex 的多目标优势，多目标批量是后续「tracker 链路多目标化」依赖。
- **能力灰置精确性**：按 `supported_trackers` 含 `sam3_video` 才放开，避免未绑 backend 项目误开 text 框却跑不动
  （对照 v0.21.14 的「默认换真实 + 隐藏 mock」同类 gate 教训）。
