# v0.10.40 · ai-pre 变体选择 + 变体富元数据 UI

> **来源**：已归档 epic [ML Backend 能力协商 + AI 预标注模态化重设计](../../ROADMAP/archive/2026-05-22-ml-backend-modality-and-ai-preannotate-redesign.md) 的延伸；主 [ROADMAP.md](../../ROADMAP.md) §A「变体热切换后续延伸 · `/setup.supported_variants` 富元数据」(P3) + 用户实测发现的缺口。
> **性质**：前端为主 + backend `/setup` 富元数据扩展；不碰 `async_jobs` 合表，不做多模型对比。

---

## 0. 一句话目标

**让 ai-pre 预标界面能选模型变体**（当前选不了），并把变体选择器从裸 enum 下拉升级为**带显存 / 精度 / 推荐档元数据的富选择器**，工作台与 ai-pre 共用同一个组件。

---

## 1. 现状事实（已读码确认）

**核心缺口 —— ai-pre 选不了变体（用户实测确认）**：
- gsam2 backend `/setup.params` **已暴露**变体 enum：`sam_variant`(tiny/small/base_plus/large)、`dino_variant`(T/B)，含 title/description（[`apps/grounded-sam2-backend/main.py:388-401`](../../apps/grounded-sam2-backend/main.py)）。
- 但 `SchemaForm` 在 v0.10.23 **故意排除**这两个 key（[`SchemaForm/index.tsx:38-39,54,65`](../../apps/web/src/pages/Workbench/components/SchemaForm/index.tsx)），理由是"变体移到工作台 AI 面板会话级设置消费"。
- ai-pre 的 `ProjectDetailPanel` 复用 `SchemaForm` 渲染参数面板（[`ProjectDetailPanel.tsx:519`](../../apps/web/src/pages/AIPreAnnotate/components/ProjectDetailPanel.tsx)），**没有**工作台那个 AI 面板 → 变体字段被吃掉、ai-pre 永远选不到变体。预标请求 `params` 因此不带变体，后端落到 backend 默认变体。

**已经做对、不要重做的部分**：
- 多 backend 选择：`ProjectDetailPanel.tsx:486-503`，项目绑 >1 backend 时有 `<select>` 切换，默认绑定值。✅
- 工作台变体选择器：`AIInspectorPanel.tsx:429-462` 的私有 `VariantSelector`——按 `/setup.params` 的变体 enum 渲染两个裸下拉，会话级，已可用但**无富元数据**、且**未导出复用**。

**富元数据缺口（ROADMAP §A P3）**：
- 变体下拉只显示裸值（"tiny/small/base_plus/large"），无"显存占用 / 精度 / 推荐档"提示。
- backend `/setup` 当前无 `supported_variants` 富数组（只有 `params` 里的 enum + description）。

---

## 2. 决策底线（本版守住）

- 变体能力靠 backend `/setup` **自描述**，平台不手填、不硬编码变体清单（沿用能力协商底线）。
- 不为灵活性回退 DSL；富元数据走 JSONB `/setup.supported_variants` 结构化字段。
- 两套 job 模型不合表；不做多模型对比可视化（已确认非本版目标）。
- 不破坏工作台现有会话级变体语义；ai-pre 与工作台共用组件但各自持久化作用域不同（见步骤 3）。

---

## 3. 实施步骤（带验收）

### 步骤 1 · backend `/setup` 暴露 `supported_variants` 富元数据
- gsam2 + sam3 backend 的 `/setup` 响应新增 `supported_variants`：每轴一组，每个变体携带 `{ value, label, vram_gb?, tier?("fast"|"balanced"|"accurate"), recommended?:bool, note? }`。与现有 `params.sam_variant.enum` 同源（enum 仍保留，富数组是叠加，不删旧字段保兼容）。
- **verify**：`curl .../setup` 返回含 `supported_variants`，值与 `SAM2_CONFIGS`/`DINO_CONFIGS` 一致；sam3-backend（单轴/无变体）返回空或单轴不报错。

### 步骤 2 · 抽出共享富变体选择器组件
- 把 `AIInspectorPanel` 私有 `VariantSelector` 提升为共享组件（如 `apps/web/src/components/ml/VariantSelector.tsx`）：优先读 `/setup.supported_variants` 渲染富选项（label + 显存/档位/推荐徽章），无富数组时回落当前裸 enum（向后兼容老 backend）。
- 复用 `VARIANT_FIELD_KEYS`（仍是 SchemaForm 的排除真值，单一来源不变）。
- **verify**：组件单测——给富 schema 渲染徽章、给纯 enum schema 回落裸下拉、无变体字段时整段隐藏。

### 步骤 3 · ai-pre 接入变体选择器
- `ProjectDetailPanel` 在「后端推理参数」面板（`SchemaForm` 之上/旁）插入共享 `VariantSelector`，数据源 = 已拉的 `setupQ.data`。
- 变体值并入随请求透传的 `params`（与 `paramsValue` 合并，运行时 `onRun` 的 `baseArgs.params` 带上变体）。
- 持久化作用域：变体按 backend 记忆（复用 `useAiToolParamPrefs(selectedBackendId)` 的同一桶，或单列一个 variant 桶——实现时二选一，倾向同桶以免割裂）。
- **verify**：ai-pre 选 gsam2 项目 → 出现 SAM2/DINO 变体富选择器 → 选 large → 跑预标 → 后端 `PredictionJob.params` 落库含 `sam_variant=large`；切 backend 变体独立记忆。

### 步骤 4 · 工作台选择器替换为共享组件
- `AIInspectorPanel` 改用步骤 2 的共享组件，删私有 `VariantSelector`，保持会话级语义与现有 `data-testid`（`ai-variant-selector` / `ai-variant-{key}`）不破测试。
- **verify**：工作台 AI 面板变体选择行为不变（含原有 e2e/单测），新增富徽章展示；`pnpm test` 绿。

### 步骤 5 · 文档 + ROADMAP 收尾
- `CHANGELOG.md` 加 v0.10.40 条目；`docs-site/dev/reference/ml-backend-protocol.md` 补 `supported_variants` 字段规格；用户手册 ai-pre 章节补"选变体"。
- ROADMAP：删 §A「变体热切换后续延伸 · `/setup.supported_variants` 富元数据」P3 条目 + 优先级表对应行；归档 epic 不动（本项是其延伸，非三阶段内）。
- **verify**：`pnpm docs:dev` 渲染正常；协议文档与 backend 实际响应一致。

---

## 4. 不做 / 留作触发项
- 多模型对比可视化（已确认非本版目标）。
- `async_jobs` 统一表收敛（§B P3，按瓶颈触发）。
- 精细单 batch modal：方向已放弃，v0.9.7 遗留 orphan 组件（PreannotateStepper / ProjectBatchPicker / PromptComposer / OutputModeSelector / RunPanel / usePreannotateDraft）已于 v0.10.40 删除。
- 变体推荐的自动选档（按图像分辨率/显存自动挑变体）：本版只做"展示元数据 + 人工选"，不做自动决策。

---

## 5. 风险 / 注意
- backend 改 `/setup` 属镜像内代码 → 按 CLAUDE.md §8 需 rebuild backend 容器，不是 restart。
- `supported_variants` 与 `params.*_variant.enum` 双字段同源，注意别让二者漂移（backend 侧从同一 config dict 派生）。
- 工作台变体是**会话级**、ai-pre 是**按 backend 持久化偏好**，共用组件但作用域不同——组件只管渲染 + onChange，持久化交给各调用方，别把 storage 逻辑塞进共享组件。
- gsam2 双轴（sam+dino）、sam3 可能单轴或无变体——组件必须容忍 0/1/2 轴。
