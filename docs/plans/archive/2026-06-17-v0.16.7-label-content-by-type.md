# v0.16.7 · 标签内容按标注类型分段(单帧 / 轨迹 / AI)

> Created: 2026-06-17
> Status: Draft
> 依赖:v0.16.6(ADR-0041 收尾,Konva 成为图片 + 视频唯一渲染栈,视觉参数全仓同源)

## 0. 背景与动机

工作台设置里的「标签内容」是一组扁平多选 chip(`类别名 / ID / 置信度 / 属性`,存 `common.labelContent: string[]`)。两个问题:

| 现状 | 问题 |
| ---- | ---- |
| 一套扁平开关管三类语义不同的标注 | `置信度` 只对 AI 框生效(`buildLabelText` 判 `isAi`),单帧 / 轨迹框勾了**完全无效**,只能靠一行小字「置信度仅 AI 预标注框有」打补丁,UI 零体现 |
| 同一个 `ID` 开关含义跨类型漂移 | 单帧 = 分组号 `group_id`,轨迹 = 轨迹号 `track_id`,AI 还多一个 `✦模型/导入` 前缀——一个开关,三种语义 |
| 控件右对齐 + `flex-wrap` 的小药丸 | 4 个 chip 挤成 2 行(`类别名 ID` / `置信度 属性`)长短不齐,观感乱(用户原话:丑) |
| **视频轨迹标签根本不读这个设置** | `videoFrameViews.buildEntryView` **硬编码** `#轨迹号 · 类别名 · 状态`,「轨迹」这一类从未接入「标签内容」 |

不同类型的标注「可展示信息本来就不一样」。本版把「标签内容」从一维扁平开关重做成**按标注类型分段**:单帧 / 轨迹 / AI 各自一组、只列该类型真正有意义的字段,并把视频轨迹标签首次接入这套配置。顺带修掉布局观感问题。

## 1. 排查结论:画布上所有"贴标签文本"的对象(穷尽谱系)

动手前已穷尽排查画布上所有会渲染文字标签的对象,确认除「单帧 / 轨迹 / AI」外没有遗漏的"信息不一样"的类型。结论:

### 1.1 纳入分段(受 `labelContent` 控制)

| 段 | 渲染入口 | 现状显示 | 现读 labelContent | 可展示字段集 |
| --- | --- | --- | --- | --- |
| **单帧** | `ImageStageShapes.shapeLabelText`(所有几何:bbox/polygon/polyline/rotated/keypoint 整体标签),`isAi=false` | `类别名 [#id][attrs]`(score 对单帧无效) | ✅ | 类别名(恒)、`#分组号`、属性 |
| **AI** | 同上,`isAi=true`(即 `"predictionId" in box`,预测图层的框) | `✦来源 类别名 [#id][%score][attrs]` | ✅ | 类别名(恒)、`✦来源`、置信度、`#id`、属性 |
| **轨迹** | `videoFrameViews.buildEntryView` + `VideoKonvaOverlayLayer`(视频 track 当前帧框) | `#轨迹号 · 类别名 · [插值/遮挡]`(**硬编码**) | ❌ 待接入 | 类别名(恒)、`#轨迹号`、状态(插值/遮挡)、属性 |

**`isAi` 判定不改**:`"predictionId" in box`(`ImageStage.tsx:880`)。正式标注层一律 `isAi=false`(`ImageStage.tsx:1050+`),即使 `source="prediction_based"`(采纳预测后落库的正式标注,`transforms.ts:264`)也走**单帧段**;只有悬在预测图层、未采纳的框(带 `predictionId`)走 **AI 段**。边界天然干净,本版不引入新语义。

**几何形状维度无需分段**:图片侧 5 处 `shapeLabelText` 调用(box/polygon/polyline/rotated/keypoint 整体)共用同一字段集,"形状"不影响"展示哪些字段",只按 单帧/AI/轨迹 分即可。

### 1.2 刻意排除(独立 / 固定逻辑,本版不纳入)

| 对象 | 入口 | 为何排除 |
| --- | --- | --- |
| keypoint **节点名** | `ImageStageShapes.tsx`(每个关键点旁显示 `schema.nodes[i].name`) | 来自骨骼 schema,非标注字段,语义固定,始终显示 |
| 视频 **ghost 参考框**(`#号 · 类别 · 参考 F123`) | `videoFrameViews.ts:167` | 跨帧参考提示,需固定简洁,不该被用户关字段 |
| 视频 **pending draft**(画一半草稿,仅类别名) | `videoFrameViews.ts:181` | 草稿态,固定简洁 |
| **点云 3D 框** | `PointCloudScene`(setBoxes) | **当前不渲染任何标签文本**(仅线框 + 拾取网格);将来若加,再归入对应段 |
| 视频 **legacy bbox**(旧格式 `VideoBboxGeometry`) | `videoFrameViews.ts`(source=`legacy`) | 历史边缘格式;沿用轨迹段渲染,不单列 |
| Issue 图钉 / Mask 覆盖 / 点云坐标轴 | `VideoKonvaIssueLayer` / `MaskOverlayLayer` / `PointCloudScene` | 非标注字段标签(符号 / 色块 / `X·Y·Z`) |

> 轨迹的 `semantic_label`(跨任务 Re-ID)与逐帧 `attributes` 当前都不在画布展示。本版把 `attributes` 纳入轨迹段(可选),`semantic_label` 暂留 future(§6)。

## 3. 数据结构设计

### 3.1 类型(前后端对齐)

```ts
// token 全集(class 三段恒含,不入数组)
type LabelFieldToken = "id" | "score" | "attrs" | "source" | "state";

interface LabelContentByType {
  single: ("id" | "attrs")[];          // 分组号 / 属性
  track:  ("id" | "state" | "attrs")[]; // 轨迹号 / 状态(插值·遮挡) / 属性
  ai:     ("source" | "score" | "id" | "attrs")[]; // 来源前缀 / 置信度 / id / 属性
}
```

字段语义:

| token | 段 | 含义 | 渲染 |
| --- | --- | --- | --- |
| `id` | single | 分组号 `group_id` | `#3` |
| `id` | track | 轨迹号 `trackNumber` | `#5` |
| `id` | ai | 分组号 `group_id` | `#3` |
| `score` | ai | 置信度 `conf` | `95%` |
| `source` | ai | 预测来源前缀 | `✦ 模型` / `✦ 导入` |
| `state` | track | 帧来源状态 | ` · 插值` / ` · 遮挡` |
| `attrs` | 三段 | 属性字典压缩(含 OCR text 等) | `occluded text=ABC` |

### 3.2 默认值(对齐现状观感)

```ts
labelContent: {
  single: [],              // 只类别名(现状单帧 score 无效,实际只显 class)
  track:  ["id", "state"], // #轨迹号 + 状态(= 现视频硬编码)
  ai:     ["source", "score"], // ✦来源 + 置信度(= 现 AI 框观感)
}
```

### 3.3 旧数据迁移(扁平 `list` → 新对象)

老 `labelContent: string[]`(如默认 `["class","score"]`)只作用于**图片**(视频一直硬编码),所以:

- **single / ai 段**:按老扁平值分发——`id`→给 single+ai;`score`→仅 ai;`attrs`→给 single+ai;`class`→丢弃(恒显)。
- **ai 段补 `source`**:老版 `✦来源` 前缀恒显,迁移补上以保持前缀可见。
- **track 段**:**忽略老值**(老值本就不管视频),直接给默认 `["id","state"]` = 现视频观感。

例:老 `["class","score"]` → `{ single: [], track: ["id","state"], ai: ["source","score"] }`(图片 + 视频观感均不变)。

迁移逻辑前后端各实现一份(后端 `field_validator(mode="before")` 主迁,前端 `useWorkbenchConfig` sanitize 兜底,二者规则一致)。

## 5. 手测脚本

1. **老用户兼容**:用一个已存 `labelContent: ["class","score"]` 的账号登录工作台 → 图片单帧框只显类别名、AI 框显 `✦来源 + 类别名 + 置信度`、视频轨迹框显 `#号 · 类别 · 状态`,与改前一致。
2. **单帧段**:勾上 `分组号`/`属性` → 图片手工框标签实时增减对应字段;`置信度` 在单帧段不存在(UI 无此项)。
3. **AI 段**:关掉 `✦来源` → AI 框前缀消失;关 `置信度` → 百分比消失。
4. **轨迹段**:关 `状态` → 视频轨迹标签不再显示 `· 插值/· 遮挡`;关 `#轨迹号` → 编号消失;勾 `属性` → 逐帧属性出现。
5. **跨实例同步**:设置抽屉改动 → 画布实时预览;刷新后保持(后端持久化)。
6. **排除项不受影响**:keypoint 节点名、ghost「参考 F123」、pending draft、点云 3D 框 标签均不随设置变化。

## 6. 范围外(明确推后)

- **轨迹 `semantic_label`(跨任务 Re-ID)** 在画布展示 → 待 track 段有实际需求再加 token。
- **keypoint 节点名受控**(让用户开关骨骼节点名)→ 独立诉求,本版不动。
- **ghost 参考框 / pending draft 字段可配** → 参考/草稿固定简洁,无需。
- **点云 3D 框画布标签** → 当前点云框无文字标签,属另一项工作(需先决定 3D 标签渲染方案)。
- **项目级锁定 labelContent** → 当前 `labelContent` 不在 `lockable` 字段;按需后续。
