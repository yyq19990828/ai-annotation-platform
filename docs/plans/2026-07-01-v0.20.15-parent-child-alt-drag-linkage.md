# v0.20.15 · 父子标注 Alt 拖动联动

状态：草案（draft）。补 v0.20.9 列为可选后续的移动联动——拖父框时子框一起搬。
**依赖 v0.20.9**（父子模型）；建议在 v0.20.14（同胞高亮）之后，用户能先看清归属再联动搬动。

## 背景

v0.20.9 的 WS4 把「拖动父框时子框一起搬」列为可选、首版不做。父子标注实际用起来后（尤其
v0.20.11–13 二次推理批量产出子框），整体挪一个父物时子框不跟随会很别扭。

## 关键抓手 / 冲突（已核实）

- **Alt 键已被重度占用**（`ImageStageShapes.tsx`）：折线/多边形 `Alt+点击边`插顶点、关键点
  `Alt+点击`切可见性（782）、顶点交互按 `e.evt.altKey` 分流（328/627/789）。故「Alt 拖动」若也用 Alt，
  必须限定作用面为 **box 主体拖动**（非顶点/边/节点），且与上述互斥（那些都发生在 vertex/edge/node 上）。
- **需定位 box 移动 commit 落点**：图片框的整体平移落库路径（DOM `BoxRenderer` 拖动 vs Konva
  Transformer / draggable Group）在本轮探查未一处命中，**WS0 先定位**再动手（不同渲染层落点不同）。
- 联动 = 父框位移 `(dx, dy)` → 每个直接子框 geometry 施加同样 `(dx, dy)` → 批量 commit。几何是 0-1
  归一化，`dx/dy` 用归一化增量即可，子框各自 clamp 到 [0,1]。

## 工作项

### WS0 · 定位移动 commit 路径

- 找到「拖动框主体 → 更新 geometry → 落库」的现有 handler（图片任务）；确认它拿得到 `(dx, dy)` 或
  新旧 geometry。这是本版能否轻量实现的前提。

### WS1 · Alt 拖父联动子

- 拖动**父框主体**且按住 Alt 时，计算位移增量，对其直接子框应用同样增量，随父框一并 commit（一次
  批量更新，进同一撤销步）。
- 不按 Alt = 只搬父框（现状不变，向后兼容）。子框超出 [0,1] 的 clamp 策略：整体 clamp 还是各自 clamp，
  WS1 定（倾向各自 clamp，父到边界子仍跟随不越界）。

### WS2 · 反馈

- 拖动时给轻提示（如"联动 N 个子框"），或子框在拖动中显影，避免用户不确定是否生效。

## 风险

- **Alt 语义冲突**：务必限定「box 主体拖动」面，避免与顶点/关键点的 Alt 交互打架（二者作用对象不同，
  天然可分，但要在 handler 里显式 gate）。[[feedback_button_terminology]]：拖拽键位口误常见，动手前
  与用户确认最终键位（Alt 拖 vs 其他修饰键）。
- **撤销原子性**：父 + 子的位移必须进同一个 undo 步，否则撤销只回退父框、子框留在错位。
- 一层约束：子框无孙，联动只一层，实现简单。

## 验收

- 选中并 Alt 拖父框 → 子框同步位移；撤销一次 → 父子一起回到原位。
- 普通拖父框（不按 Alt）→ 只父框动，子框不动。
- 子框到画布边界 → 按定好的 clamp 策略，不越界、不丢框。

## 依赖 / 不在范围

- **依赖 v0.20.9**；建议排在 v0.20.14 后。
- 不做：缩放联动（父框 resize 时子框等比缩放——更复杂，另议）、video/3D 联动、多层。
