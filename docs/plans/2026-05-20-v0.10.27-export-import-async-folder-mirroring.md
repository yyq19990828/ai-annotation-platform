## 1. 现状定性（调研结论）

### 1.1 导出 `apps/api/app/services/export.py`

- 4 格式：COCO(`export_coco` 299-420，返回 `str`) / YOLO(`export_yolo` 422-479，返回 `bytes` ZIP) / VOC(`export_voc` 481-535，返回 `bytes` ZIP) / AAP JSON v1.1(`export_aap_json` 537-651，返回 `str`)。
- 入口：`GET /projects/{id}/export`（`api/v1/projects.py:708`）、`GET /.../batches/{bid}/export`（`api/v1/batches.py:843`）。参数 `format` / `include_attributes` / `video_frame_mode`。
- **完全同步**：`_load_data()`（93-122）分步全量加载（先全量 `Task` 按 sequence_order 排序，再独立全量 `Annotation` filter is_active），`async def` 直接在路由 `await`，拼完整 ZIP/JSON 后 `Response(content=...)` 返回。**无分页 / 无流式 / 无 Celery / 不落对象存储**。ZIP 用内存 `io.BytesIO()` + `zipfile` 全量缓存。大项目（万级 task）→ 内存暴涨 + 请求超时。
- **产物扁平化 bug**：YOLO 用 `base = t.file_name.rsplit(".",1)[0]` → `labels/{base}.txt`；VOC 同理只用 `t.file_name`。`file_name` 只存叶子名，**丢失递归目录**。不同子目录同名文件（`animals/cat/001.jpg` 与 `animals/dog/001.jpg`）→ 两者都写 `labels/001.txt`，**第二个静默覆盖第一个 = 数据丢失**。
- **硬编码尺寸 bug**：`export.py:41` `IMG_W, IMG_H = 1920, 1280`，COCO(`371-372`) / VOC(`503-504`) 用常量算像素坐标。真实尺寸其实存在 `DatasetItem.width/height`（`db/models/dataset.py:59-60`，nullable），且 `_load_dataset_items()`（141-150）已经现成加载成 `Dict[UUID, DatasetItem]`，只是导出像素坐标处没用它。

### 1.2 导入预标注 `apps/api/app/services/predictions_import.py`

- 端点 `POST /projects/{id}/predictions/import`（`api/v1/predictions.py:258-377`），支持 COCO + AAP JSON。
- 架构成熟：同步端点 + `async_jobs` 双写追踪（kind=`predictions_import`，`predictions.py:284-374`，dry_run 不记录）+ `dry_run` 全路径校验 + geometry 适配层（`internal_geometry_to_ls_shape` 46-143）复用 `PredictionService.create_from_ml_result`。lenient 容错（错误进 `errors[]` 不整批失败）。result 仅存 `{imported, skipped, error_count}`。
- 前端 `PredictionImportWizard.tsx`（三步：选格式/文件 → dry-run 预览 → 提交），`predictionsApi.import` 走 multipart；不轮询，靠 `JobsBell` 单独看后台进度。
- 缺口：仅按 `image.file_name` ↔ `task.file_path` 匹配（`task_matcher.resolve_task`，display_id 优先 + file_path fallback），**未按相对目录匹配**；同名跨目录会误匹配。

### 1.4 Celery 队列与路由（关键约束）

- 模板：`batch_predict`（`workers/tasks.py:386-411`）—— `asyncio.run(_run_batch(...))`，内部 `async_sessionmaker` + `create_job/mark_running/update_progress(每5%, tasks.py:244-252)/mark_complete(275-290)`。export worker 照此写。

- **新增 import/export 桶 + 7 天 lifecycle 只是同模式小扩展。**

### 1.6 数据模型关键事实

- `DatasetItem.file_path = key`（**完整 MinIO key，保留嵌套**，`dataset.py:53` String1000），`file_name`（String500）只存叶子名；`width/height`（Integer, nullable）。
- `tasks.file_path`（String1000，`task.py:33`）/ `file_name`（String500，`task.py:32`）/ `dataset_item_id`（FK nullable，`task.py:28-30`）→ 可 join 拿 width/height。
- **MinIO/S3 本质扁平 KV，没有真目录**；key 里的 `/` 是普通字符，"文件夹"是控制台按前缀渲染的视觉假象。**MinIO 完全能保留嵌套**（key 写成 `animals/cat/001.jpg` 即可），拍平是我们代码的选择，且两条入口不一致：
  - Web / `scan_and_import`：`file_path = key` ✅ **保留嵌套**。
  - CLI `import_images.py:111`：`storage_key = f"{folder}/{img_path.name}"` ❌ **拍平**（只取叶子名）。

## 2. 核心决策（已拍板）

1. **导出异步化（一律走异步，无同步快路径）**：转 Celery worker + `async_jobs` 追踪（kind=`export`）+ 产物落 MinIO `export` 桶 + 返回预签名下载 URL + 前端复用 `JobsBell` 轮询/进度。**不保留 task 数阈值的同步快路径**——求行为一致、无魔数。
2. **新建两个 MinIO 桶**：`import` / `export`，**7 天 lifecycle**（产物短生命周期）。桶内按 `image / video / lidar` 分层，**本期只做 image**（key 前缀 `image/`）。
3. **导出产物 = 仅 labels 镜像目录 + 按需回源脚本**（不打包图片本体）：
   - 理由：体积小、桶生命周期压力小、尊重"用户本地可能已有数据集"。
   - 布局：
     ```
     {project_display_id}_export.zip
     ├── {project_id}/{dataset_id}/labels/animals/cat/001.txt   ← 镜像 file_path 去前缀的相对路径
     ├── {project_id}/{dataset_id}/labels/animals/cat/001.attrs.json  (include_attributes 时)
     ├── classes.txt
     ├── attribute_schema.json
     ├── data.yaml                ← YOLO 训练入口，images/labels 路径已配好
     ├── images_manifest.json     ← 每张图 {相对路径, dataset_id, presigned_url(7天), expires_at}
     └── fetch_images.py          ← 跑它把图片拉成 images/<同相对路径> 平行树
     ```
   - `fetch_images.py` 读 `images_manifest.json` 的**预签名 URL**（7 天有效 = 桶生命周期，用户无需配 MinIO 密钥）；下载到 `images/` 与 `labels/` 严格平行 → 即取即训。本地已有图则不跑。**启动时校验 `expires_at` 并提示"链接将于 X 过期，尽快下载"**（解决 URL 过期临界，开放问题3 已定）。
4. **相对路径真值**：`file_path` 去掉 dataset 名前缀（`{dataset}/animals/cat/001.jpg` → `animals/cat/001.jpg`），换扩展名落 `labels/`。**绝不用 `file_name`**（丢目录 + 同名覆盖）。
5. **VOC 前端隐藏**：太少用 + 硬编码尺寸本身有 bug。后端 `export_voc` 暂留（不删，避免破坏 API 契约），仅前端 `ExportSection` 下拉摘掉选项。
6. **导入端对称**：`predictions/import`（及未来 `annotations/import`）应支持**按相对目录路径匹配** task，与导出镜像一致。
7. **连带必修**：CLI `import_images.py` 改为 `relative_to(image_dir)` 保留相对路径——否则入口拍平后库里无嵌套可镜像。Web/scan 路径已 OK 无需改。
8. **队列与 worker（已定）**：新开 **`export` 专用队列** + **新增独立 worker 服务 `celery-worker-export`**（`-Q export`）。资源隔离，导出大任务不拖累预标/媒体处理。
9. **导出缓存（本期就做，已定）**：新建 **`export_artifacts` 表** 做 cache key → 产物映射。命中复用桶内产物（探活 + 刷新预签名 URL）。
10. **batch 跨多 dataset 分层（开放问题5 已定）**：布局已按 `{project_id}/{dataset_id}/` 分层，跨多 dataset 的 batch 天然分开，**不再按 batch 细分**。

## 3. 缓存设计（`export_artifacts`）

**表结构**（alembic 迁移一支）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID PK | |
| `cache_key` | String(64), **unique index** | sha256 hex |
| `project_id` | UUID FK | |
| `batch_id` | UUID, nullable | 项目级导出为 null |
| `format` | String(20) | coco/yolo/aap_json |
| `object_key` | String(500) | `image/{project_id}/{job_id}.zip` |
| `file_count` | Integer | label 文件数 |
| `size_bytes` | BigInteger | 产物大小 |
| `expires_at` | DateTime(tz) | = 产物创建 + 7d，与桶 lifecycle 对齐 |
| `created_at` | DateTime(tz) | server_default now |

**cache_key 算法**（双字段指纹，**修删除标注 max 不变漏洞**）：
```
cache_key = sha256(
  scope_id(project_id 或 batch_id),
  format, include_attributes, video_frame_mode,
  max(annotation.updated_at WHERE is_active AND not cancelled),
  count(active annotation)        ← 删除标注会让 count 变，单 max 不变也能失效
)
```

**命中流程**（worker 入口先走）：
1. 算 cache_key → 查 `export_artifacts`（未过期行）。
2. 命中 → `storage.stat_object(export 桶, object_key)` 探活：
   - 在 → 刷新预签名下载 URL，直接 `mark_complete` 写 result，**跳过重生成**。
   - 不在（被 lifecycle 清了）→ 删该行，回退重生成。
3. 未命中 → 正常生成 → 落桶 → 写 `export_artifacts` 行。

**清理**：新增 beat 任务清 `expires_at` 过期的 `export_artifacts` 行（与桶 7d lifecycle 对齐，复用现有 cleanup 队列/模式）。
