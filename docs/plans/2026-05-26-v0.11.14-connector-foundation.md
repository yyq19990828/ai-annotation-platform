# v0.11.14 · 存储连接器基建（模型 + 加密 + 白名单 + CRUD）

> [epic 索引](2026-05-26-v0.11.14-dataset-import-connectors-epic.md) · 切片 1/3 · 依赖：无
>
> 本切片**只搭基建与连接器管理**，不含任何导入逻辑——连接器可创建、可测连通性，但还不能往数据集拉数据（导入在 v0.11.15）。

## 目标

落地"可复用、密钥加密、受白名单约束"的存储连接器，作为后续服务端拉取的安全地基。完成后：超管可配主机白名单，超管/项目管理员可创建并测试 S3/SFTP 连接器，密钥加密落库且永不回吐。

## 现状

- 凭据/加密设施：`apps/api/app/config.py` 有 `secret_key`(JWT 用)；依赖含 `python-jose[cryptography]`（`cryptography` 可用）、`boto3`、`passlib[bcrypt]`。**无 `paramiko`**。
- 系统级配置：已有 `apps/api/app/api/v1/system_settings.py`（白名单拟复用此机制，不新建表）。
- 对象存储封装：`apps/api/app/services/storage.py::StorageService`（boto3 client 模式可参考）。

## 后端改动

### 1. 依赖
- `apps/api/pyproject.toml`：新增 `paramiko>=3.4`。→ **改 deps 需 rebuild 镜像**（worker/api）。

### 2. 加密工具
- 新建 `apps/api/app/core/crypto.py`：基于 `cryptography.fernet.Fernet`，封装 `encrypt_secret(dict)->bytes` / `decrypt_secret(bytes)->dict`。
- 新 env `CONNECTOR_ENCRYPTION_KEY`（config.py 加字段，默认 None；缺失时连接器创建/解密直接报 503 并提示配置）。**独立于 `secret_key`**。
- `.env.example` 同步 + `pnpm docs:gen-env-vars`。

### 3. 数据模型 + 迁移
- 新建 `apps/api/app/db/models/storage_connection.py::StorageConnection`：
  - `id UUID`、`name str`、`kind str("s3"|"sftp")`
  - `config JSONB`（非密钥：s3 → endpoint/region/bucket/base_prefix/use_ssl；sftp → host/port/username/base_path/auth_type("password"|"key")）
  - `secret_enc LargeBinary`（Fernet 密文：s3 → {access_key,secret_key}；sftp → {password} 或 {private_key,passphrase?}）
  - `scope str("global"|"project")`、`project_id UUID?`、`created_by UUID`、`created_at/updated_at`
- alembic 迁移（**新增迁移仅需 `docker restart` worker，无需 rebuild**——但本版同时改了 deps，仍要 rebuild）。

### 4. 白名单（复用 system_settings）
- system_settings 增配置项 `connector_host_allowlist`：host/endpoint 模式列表（如 `oss-cn-hangzhou.aliyuncs.com`、`10.0.3.0/24`、`192.168.1.50`）。仅 super_admin 可写。
- 新建 `apps/api/app/services/connector_guard.py`：
  - `assert_host_allowed(host_or_endpoint)`：解析出 host → 匹配白名单模式（精确域名 / CIDR）。
  - `assert_not_ssrf(host)`：DNS 解析为 IP 后，拒绝 loopback / link-local(169.254/0.0) / 未在白名单 CIDR 内的私网；**解析后用真实 IP 复检，防 DNS rebinding**。
  - 白名单为空时：默认 deny-all（项目管理员建不了任何连接器，引导超管先配）。super_admin 自身建 global 连接器是否豁免白名单 → **本版按"超管也走白名单"实现**（最稳，避免超管误配内网）。

### 5. 连接器 service + API
- 新建 `apps/api/app/services/storage_connection.py`：CRUD + `test_connection()`（s3=list bucket 前 N；sftp=连接+listdir base_path 前 N）。所有出网前先过 `connector_guard`。
- 新建 `apps/api/app/api/v1/storage_connections.py`：
  - `POST /storage-connections` 创建（body 含明文密钥，service 内立即加密；项目管理员只能建 scope=project 且 project_id 属己，超管可建 global）
  - `GET /storage-connections` 列表（脱敏：返回 config 但**绝不返回 secret**；按 scope/project 过滤可见性）
  - `GET /storage-connections/{id}` 详情（脱敏）
  - `POST /storage-connections/{id}/test` 连通性测试（过白名单+SSRF，返回 ok/错误原因 + 样例条目数）
  - `PATCH /storage-connections/{id}`（改 name/config，密钥可选轮换）
  - `DELETE /storage-connections/{id}`
- schema 新建 `apps/api/app/schemas/storage_connection.py`：In 含密钥字段、Out **无密钥字段**。
- 注册路由到 `apps/api/app/api/v1/__init__.py`（或对应 router 聚合处）。
- 审计：连接器 create/update/delete/test 记 audit log（参考现有 action 命名）。

## 验证

- `cd apps/api && uv run pytest`：新增 service 单测——加密往返、白名单匹配（域名/CIDR 命中与未命中）、SSRF 拒绝 loopback/link-local、DNS rebinding（mock 解析返回内网 IP）被拦、密钥不出现在任何 Out schema。
- `uv run alembic upgrade head` 干净执行；模型与迁移一致。
- 手测：超管配白名单 → 项目管理员建 project 连接器（白名单外被拒、白名单内成功）→ test 通过 → list/detail 响应无密钥字段。
- openapi 快照经 pre-commit 钩子排序生成（勿手动 dump）。

## 回退

新表 + 新路由，无存量数据依赖。回退 = 删路由注册 + `alembic downgrade` + 删新文件。白名单存 system_settings，回退不影响既有配置。

## 备注

- 本版**不接入 `ImportDatasetWizard` 也不动现有 scan**，对现有导入零影响。
- "超管也走白名单"是本版的保守选择；若后续证明阻碍超管运维，再在 v0.11.15 评估给 global-scope 开有限豁免。
- `paramiko` 本版只用于 test_connection 的 listdir，真正的流式拉取在 v0.11.15。
