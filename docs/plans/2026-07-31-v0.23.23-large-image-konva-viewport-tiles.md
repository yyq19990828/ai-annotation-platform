## 0. 实施范围冻结

本版按当前 v0.23.22 API 合同直接实施，不新增服务端存储模型或 tile 路由：

- Task 的 `image_pyramid` summary 只负责是否探测；ready manifest 继续通过
  `GET /tasks/{id}/image-pyramid` 获取，tile URL 继续通过最多 128 项的
  `POST /tasks/{id}/image-pyramid/asset-urls` 批签；
- 客户端 gate 默认开启，并在 production build arg、Compose 与环境变量文档中提供独立回滚；
- LOD 使用 `devicePixelRatio`，以 `0.75..1.25` 为当前级 hysteresis 保持区间；
- decoded tile 档位固定为 32 / 64 / 128 MiB，fetch/decode 并发固定为 2 / 4 / 6；
- overview 是首屏与故障 coverage；本版不另建 Service Worker、Cache Storage、WebGL 或
  WebGPU 背景 renderer；
- required 大图的自动路径禁止请求 original。显式原图 override 只有在
  `width × height × 4` 可通过当前 decoded-byte 档位时才可出现；超过预算时保持 overview
  与明确状态，不提供危险按钮；
- v0.23.24 只接收只读 resource snapshot 与 `pausePrefetch` 接口，本版不提前合并
  Raster Mask/背景的全局预算。

## 1. 本版目的

本版把 v0.23.22 的 pyramid 接到图片/审核工作台，使 50MP 以上图片不再由一个
`HTMLImageElement` 整图下载、解码和驻留。

核心路径：

```text
Task image source summary
  → fetch immutable pyramid manifest
  → choose LOD from viewport scale × DPR
  → visible tile + one-ring overscan
  → bounded sign/fetch/decode queue
  → ImageBitmap preferred / HTMLImageElement fallback
  → decoded-byte LRU
  → ancestor coverage + full-detail Konva tile layer
```

本版不等待 WebGPU，也不请求 adapter。没有 GPU 的客户端使用完全相同的背景 tile 链路；
Raster Mask morphology 继续使用 v0.23.21 已资格的 CPU fallback。

## 2. 当前源码事实

### 2.1 主背景

`ImageStage` 当前：

- 以 `mediaKey ?? fileUrl` 稳定 presigned URL；
- 调用 `useImage(imageSourceUrl)`；
- 以 `imageWidth/imageHeight` 或 `naturalWidth/naturalHeight` 计算画布 dimensions；
- 在 `Layer(name="bg")` 中只渲染一个 `Konva.Image`。

Stage canvas 本身是 viewport 尺寸，主要风险是整图 image decode/texture，而不是创建巨型 Stage。

### 2.2 可复用地基

- `vp.scale/tx/ty + viewport size + imgW/imgH` 已生成归一化可视 bbox；
- 同一 bbox 已传给 tiled Mask editor；
- fit/focus-selection/Minimap/Issue pin/vector/Mask 都使用 full-resolution coordinate；
- `useRasterMaskRecords` 有 decoded bitmap 字节预算、queue、reservation、LRU 与
  `ImageBitmap.close()` 的现成设计原则；
- thumbnail/blurhash 已存在，可承担 initial coverage。

### 2.3 隐藏整图消费者

本版必须同时收口：

1. 邻题预取会 `new Image()` 加载前后 Task `file_url`；
2. Minimap 在无 thumbnail 时回退 `fileUrl`；
3. 评论画布 `CanvasDrawingEditor` 使用原图 URL 作为 CSS background；
4. `ReviewWorkbench` 复用 `ImageStage`，但尚无 pyramid source；
5. Discussion/Comment props 固定传 `task.file_url`；
6. 任意 screenshot/preview 路径若从背景 URL 再建 image，不能绕回整图。

评论弹窗只需要 overview 分辨率；不需要复制完整 tile runtime。

## 3. 冻结决策

### D1. 单一 ImageSource union

不在 `ImageStage` 内散落多个 boolean：

```ts
type WorkbenchImageSource =
  | {
      kind: "single";
      identity: string;
      url: string;
      width?: number;
      height?: number;
      thumbnailUrl?: string;
      blurhash?: string;
    }
  | {
      kind: "pyramid";
      identity: string;
      generation: number;
      manifest: ImagePyramidManifestV1;
      overviewUrl?: string;
      thumbnailUrl?: string;
      blurhash?: string;
      originalFallback?: {
        url: string;
        estimatedDecodedBytes: number;
        allowed: boolean;
      };
    }
  | {
      kind: "pyramid-pending" | "pyramid-failed";
      identity: string;
      width: number;
      height: number;
      overviewUrl?: string;
      thumbnailUrl?: string;
      blurhash?: string;
      retryable: boolean;
      errorCode?: string;
    };
```

`ImageStage` 只消费 resolved source；API/Task 状态解释在上层 hook。

### D2. full-resolution world 坐标不变

每个 tile node 的 world rect 来自 manifest level/tile 的 integer source coverage：

- Konva Stage 继续 `scaleX/Y=vp.scale` 与 `x/y=vp.tx/ty`；
- vector、Mask、Issue、snap、cursor、fit、focus、Minimap 不换坐标系；
- level pixel 只作为背景采样，tile node 仍占 full-resolution world rect；
- overlap 用 `crop` 去除，不扩大 world rect；
- 不用浮点累加 `previous.x + width` 定位下一 tile。

### D3. LOD 选择有 DPR 与 hysteresis

对 level scale factor `S`：

```text
device pixels per level pixel = vp.scale × S × devicePixelRatio
```

选择最粗但不会明显上采样的 level，初始目标区间例如 `0.75..1.25`，M0 以视觉和请求量冻结。

- zoom in 超过上阈值才升级细 level；
- zoom out 低于下阈值才降级；
- wheel 连续缩放期间可暂缓新 level，rAF/短 debounce 后请求；
- 不能因阈值附近微抖反复请求两级；
- DPR 变化（跨屏/浏览器 zoom）重新评估。

### D4. ancestor coverage 永不先撤

显示顺序：

```text
blurhash
  → thumbnail/overview
  → coarser ancestor tiles
  → target LOD visible tiles
```

- target tile ready 后只替换其覆盖区域；
- ancestor 仅在全部所需 child ready 且 Konva draw 完成后可 eviction；
- 单 tile 404/decode failure 保留 ancestor，不出现 checkerboard blank；
- 快速 pan 时旧 viewport tiles 可被 LRU，但旧 generation/task tile 绝不提交。

### D5. ImageBitmap 优先，HTMLImageElement 也是完整 fallback

首选：

```text
fetch signed URL → Blob → createImageBitmap → cache
```

无 `createImageBitmap` 或瞬时失败：

```text
Blob/ObjectURL → HTMLImageElement → cache
```

- 两条路径都使用相同 queue、generation fence 与 decoded byte admission；
- ImageBitmap eviction/dispose 调 `close()`；
- HTML image eviction 清空 src/revoke ObjectURL；
- 单次 bitmap failure 可降级 element，不要求刷新；
- WebGPU 状态不参与图片 decode route。

### D6. required 大图不自动回整图

- small/no-pyramid：现有 `useImage` 不变；
- optional pyramid failed：estimated decoded RGBA 在设备档位允许时可自动/明确选择 single；
- required（默认 ≥50MP）pending/building：overview + “高清切片生成中”，可继续归一化/粗略查看，
  不发原图请求；
- required failed：overview + retry/error，原图只能在显式用户动作且预算允许时加载；
- hard-limit 图片不提供危险的自动 original fallback。

## 4. 组件与职责

### 4.1 `resolveWorkbenchImageSource`

- 合并 Task file URL、thumbnail/blurhash、pyramid summary/manifest；
- 稳定 identity 使用 media identity + pyramid generation；
- presigned URL 变化不重置已加载同 generation；
- source/generation 变化递增 scope generation，取消所有旧请求；
- required 状态决定是否允许 whole-image fallback。

### 4.2 `visibleImageRect`

从 `ImageStage` 抽纯函数：

```ts
visibleImageRect(
  viewport: { width: number; height: number },
  transform: Viewport,
  image: { width: number; height: number },
  overscanScreenPx?: number,
): PixelRect | null
```

- 返回 full-resolution 半开整数 rect；
- clamp image bounds；
- 处理负 translation、fit、小图全可见、极端 zoom；
- polygon LOD、background tile 与 Mask viewport 逐步共用，避免各自 rounding。

### 4.3 `ImageTileScheduler`

职责：

- current LOD 与 ancestor coverage；
- visible/core、one-ring、directional prefetch priority；
- asset URL batch 中的 tile 签发；
- bounded fetch/decode；
- AbortController；
- generation/token fence；
- retry/backoff；
- decoded-byte reservation/LRU；
- resource snapshot；
- pause/resume prefetch（供 v0.23.24）。

不得承担：

- annotation state；
- Mask truth；
- viewport mutation；
- WebGPU initialization；
- server generator retry policy。

### 4.4 `KonvaImageTileLayer`

建议一个独立 `Layer(name="image-tiles")`：

- overview/ancestor 在下；
- target tiles 在上；
- `listening=false`；
- 只在 tile batch/state 改变时 `batchDraw()`；
- rAF 合并多个 tile ready，避免每个网络完成触发整 Stage React commit；
- visible node count 有界；
- `imageSmoothingEnabled` 继续使用 workbench config；
- root CSS filter/brightness 与 single image 一致；
- layer 不创建第二个 canvas renderer。

M1 比较 declarative React nodes 与 imperative node registry；以 correctness、清理和 commit cost 选择。

## 5. Tile key、坐标与 crop

Cache key：

```text
sourceIdentity / generation / level / tileX / tileY / format
```

不使用 signed URL，因为 URL 会过期/刷新。

每个 tile resolve 出：

- logical level core rect；
- stored overlap rect；
- full-resolution world rect；
- image crop rect；
- decoded width/height；
- expected encoded content type。

必须测试：

- `1/511/512/513`；
- `8192/8193`；
- 最右/最下 edge；
- 四角；
- non-square level；
- overlap 0/1；
- level scale factor；
- DPR 1/1.25/2；
- fractional `vp.scale/tx/ty`。

不以 overlap 掩盖坐标错误；关闭 image smoothing 的 pixel golden 也必须无 gap/duplicate logical pixel。

## 6. Queue 与 LRU

### 6.1 初始档位

由 M0 固定，建议起点：

| 档位     | decoded tile budget | fetch/decode concurrency |             overscan |
| -------- | ------------------: | -----------------------: | -------------------: |
| low      |               32MiB |                        2 |    visible only/半圈 |
| standard |               64MiB |                        4 |               1 ring |
| high     |              128MiB |                        6 | 1 ring + directional |

decoded bytes 按 `decodedWidth × decodedHeight × 4` 计费，不能按压缩 Blob bytes 或条目数。

### 6.2 Admission

- 请求/解码前 reserve；
- visible tile 可 eviction 非 pinned prefetch/远 viewport；
- 当前 coverage ancestor、visible target、正在交付 Konva 的 image pinned；
- 单 tile 超预算时保留 ancestor 并标 deferred；
- 同 key single-flight；
- URL sign、fetch、decode 分阶段 token 校验；
- cache hit 更新 LRU；
- Task 切换先 generation fence，再异步 cleanup。

### 6.3 Prefetch

优先级：

```text
visible target
  > missing ancestor coverage
  > one-ring overscan
  > pan direction next ring
  > adjacent task manifest/overview
```

- 邻题不得预取 full original；
- wheel/pan active 时只做 visible/coverage；
- idle 才做 directional/adjacent；
- `saveData`/低档位禁用 directional；
- v0.23.24 接入 Mask editing pressure 后可暂停最低优先级。

## 7. Fault/fallback 状态机

| 失败                             | 行为                                                   |
| -------------------------------- | ------------------------------------------------------ |
| manifest 403/expired             | 刷新 Task/manifest 一次；不循环                        |
| stale generation                 | 清当前 batch URL，获取 active generation，旧回包丢弃   |
| asset URL batch 403              | 刷新授权一次；保留 ancestor                            |
| tile 404/object missing          | 标记 inconsistent；有限重试；保留 ancestor；报告服务端 |
| fetch timeout/offline            | abort/backoff；保留 coverage                           |
| createImageBitmap transient fail | 同 Blob 降级 HTML image                                |
| both decode fail                 | tile error；ancestor/overview                          |
| cache budget insufficient        | deferred；不破坏 visible coverage                      |
| rapid pan/task switch            | abort；token fence；stale commit=0                     |
| pyramid pending                  | overview/blurhash + status                             |
| required pyramid failed          | overview + retry；不自动整图                           |
| no WebGPU/GPU lost               | 背景完全不受影响                                       |

## 8. 隐藏消费者收口

### 8.1 Minimap

- pyramid source 只用 thumbnail/overview；
- required 大图没有 thumbnail 时显示 blurhash/占位，不回退 full file URL；
- viewport rect 仍用 full-resolution dimensions；
- 单图路径保持现有 `thumbnail || fileUrl`。

### 8.2 邻题预取

- small/single image 可保留现有受控 prefetch；
- pyramid 只 prefetch summary/manifest/overview；
- required pending 不碰 original；
- adjacent task tile detail 不预取，除非未来数据证明收益。

### 8.3 评论画布

- 用 overview/thumbnail 作为 CSS background；
- drawing points 继续 normalized；
- 明确提示评论背景是预览质量，不影响锚点坐标；
- 不在 680px 弹窗启动完整 tile scheduler；
- preview 缺失不回原图大对象。

### 8.4 ReviewWorkbench

- 复用同一个 `WorkbenchImageSource` 与 tile scheduler；
- 不维护第二份 review-only loader；
- read-only 不改变 cache/coordinate；
- review screenshot/issue pin 与 annotation 对齐。

### 8.5 其他

- 全仓搜索 `file_url` → `new Image/useImage/backgroundImage/fileUrl fallback`；
- `ImageBackdrop.tsx` 当前若确认为无引用，记录死代码但不在本版无关删除；如被使用则纳入 source union；
- ML backend、导出、原图下载继续使用 original source，不改为 lossy tile。

## 9. 诊断

`ImageTileResourceSnapshot`：

- source kind/generation/current level；
- viewport/visible/overscan tile count；
- queued/fetching/decoding/ready/deferred/error；
- cache hits/misses/evictions；
- requested/encoded/decoded bytes；
- reserved/retained/budget bytes；
- live ImageBitmap/HTML image/ObjectURL；
- bitmap created/closed；
- abort/stale commit；
- sign batch count/refresh；
- ancestor coverage ratio/target coverage ratio；
- tile ready → draw latency；
- current pressure/prefetch paused。

snapshot 不含 presigned URL、storage key、source filename。

## 11. 验收门

### Correctness

1. tile seam 两侧的 vector、Mask overlay、brush cursor、Issue pin 与 pixel probe 无 1px 偏移。
2. 非 2 次幂/edge/overlap/DPR 下 logical coverage 无 gap/duplicate。
3. fit/focus-selection/Minimap jump 的 viewport 与 single-image oracle 相同。
4. 任务/generation 切换 stale tile commit 为 0。
5. tile failure 保留 ancestor/overview，不闪 checkerboard。
6. required 大图的自动路径不请求 original URL；只有用户显式 override 且 decoded-byte
   admission 通过时才允许受控请求，并有独立 E2E。
7. small image 继续现有 single source，网络/视觉/交互等价。

### 性能

在本地 fixture 服务、同机器两轮：

- 50MP/200MP 首个 useful coverage 不等待 full-resolution source；
- target viewport detail settle p95 低于 M0 冻结门；
- 连续 pan/zoom FPS ≥30，Long Task = 0；
- decoded bytes 不超过档位预算 + 单个在途 reservation；
- live node/bitmap/request 停止后 plateau；
- 8K 4× 局部浏览继续满足既有大画布内存/FPS 门；
- small-image first paint/pan p95 不恶化 >5%。

### Dispose

- queued/in-flight/decode = 0；
- ImageBitmap created = closed（仍显示的交付对象在 layer dispose 后关闭）；
- ObjectURL 全 revoke；
- Konva tile nodes = 0；
- retained/reserved bytes = 0；
- event/observer/timer/AbortController 无泄漏。

## Outcome

- **版本与范围：**实施从 `2ce6218a` 开始，版本源、lock、OpenAPI snapshot 与
  `CHANGELOG.md` 已同步到本版；当前变更尚未创建 release commit。没有新增服务端表、对象布局或 tile
  路由。
- **客户端合同：**上层统一解析 `single/pyramid/pyramid-pending/pyramid-failed`；LOD 使用
  `viewport scale × scaleFactor × DPR` 与 `0.75..1.25` hysteresis。调度器按 32/64/128 MiB、
  2/4/6 并发做批签、decoded-byte reservation/LRU、AbortController 和 generation fence；
  短期 URL/首次拉取失败只重新批签一次。Konva 背景使用单个批量绘制 Shape，overview/已缓存粗层级先
  覆盖，目标 tile 渐进叠加。
- **真实图片：**Linux Chromium 147 打开 123MP 与 233MP ready fixture，首屏分别稳定在 level 3
  的 12 个 tile（7,750,720 retained bytes）与 level 4 的 6 个 tile（3,666,632 retained bytes），
  两者 `errors=0`、`originalRequestCount=0`。123MP 连续缩放/往返平移后 target coverage 为 1，
  retained 为 88,413,768 / 134,217,728 bytes，`staleCommits=0`、原图请求仍为 0。
- **切题与缩放回归：**123MP、233MP 与超高图连续往返切换后均保持画面可见与 target
  coverage 1；fit 比例按新图尺寸在 9%/6% 之间正确切换，233MP 图使用滚轮或浮条从
  6% 放大后可连续缩回 6%，不会反向跳到固定 20% 下限；Minimap 与缩放浮条无重叠，
  浏览器无控制台或 tile 请求错误。
- **降级与释放：**移除 `navigator.gpu` 后可见 12/ready 12；移除 `createImageBitmap` 后使用
  12 个 HTML image + 12 个 ObjectURL、0 bitmap，离开工作台后诊断 scope 清空。调度单测覆盖迟到
  response 丢弃、bitmap close、dispose 归零和一次重签名。
- **帧节奏限定：**当前 X11 转发环境的小图 single 与 123MP tile 在同一交互脚本下的 p95 frame
  delta 都是 133.3ms，未达到绝对 30fps 门，因此本机不能给出合格 FPS 结论；tile 最终轮为
  `Long Task=0`。量化 target settle、长会话 plateau、DPR A/B，以及 macOS、Windows、Wayland
  仍明确为未资格，不从当前 Linux 结果外推。
