# v0.18.32 · YOLO backend 预标参数声明精确化（文案 + per-context 默认值校准）

> 草案（2026-06-26）。纯 **backend 侧**（`apps/yolo-backend`）改动：把六个 model 共用的一份
> `_PARAMS_SCHEMA` 拆成「按上下文校准的派生 schema」，修正文案不准与默认值未校准两处缺口。
>
> **不动协议、不动平台、不动前端**——前端 `SchemaForm` 已 schema-driven，description/default
> 改了自动生效。版本节奏沿用平台 0.18.32 编号，但实际 bump 的是 `BACKEND_VERSION`（见 §6）。

---

## 0. 背景与查证结论（先证伪初判，再定范围）

起因（2026-06-26 会话）：怀疑 YOLO 各 task 的预标参数「一刀切」——闭集四 task（detect/segment/
pose/obb）+ 开集文本检测/分割共用同一份 `_PARAMS_SCHEMA`（`main.py:320-341`、挂载点
`:427`/`:510`/`:582`），只有 exemplar 单拆 `_EXEMPLAR_PARAMS_SCHEMA`（`:348-370`/`:556`）。
初判：conf/iou/max_det 对 pose/obb 语义错配，需按 task 拆「参数集」。

**查证（ultralytics 本地源码 `third-party/onnxtools/third_party/ultralytics`）推翻了初判的一半**：

| 事实 | 证据 |
|---|---|
| 四 task 全继承 `DetectionPredictor.postprocess`，统一一条 NMS | `pose/predict.py:9 PosePredictor(DetectionPredictor)`、`obb/predict.py:12 OBBPredictor(DetectionPredictor)`、`segment/predict.py:10 SegmentationPredictor(DetectionPredictor)` |
| NMS 一处调用，conf/iou/max_det 三参全传，**obb 仅多 `rotated=True`** | `detect/predict.py:54-63`：`non_max_suppression(preds, self.args.conf, self.args.iou, ..., max_det=self.args.max_det, nc=0 if task=="detect" else len(names), rotated=self.args.task=="obb")` |
| backend 对全部 task 统一喂三参 | `predictor.py:231-233`（通用）、`:292-294`（开集文本）、`:365-367`（box-seg 下游） |

**结论：conf / iou / max_det 对四个 task 都是生效旋钮，不存在「无效参数」。** obb 的 iou 走
rotated（probiou）NMS，但阈值语义仍是「重叠抑制阈值」，旋钮有意义；pose 走标准多实例 NMS，
三参同样有效。**故不需要按 task 拆「参数集」**（参数集本就该一致）。

缺口收窄为**两类真问题**，都不涉及参数有效性：

1. **文案不精确**：`conf.description = "保留置信度高于此值的检测/分割结果…"`（`main.py:327`）
   写死「检测/分割」，却被 pose / obb / 开集六个 model 共用，挂到 pose/obb 时文案不贴切。
2. **默认值未按上下文校准**（仅闭集 conf 默认有据，其余存疑）：
   - 开集文本（detect-world / detect-yoloe / segment-yoloe）沿用闭集 `conf=0.25`（`:510` 复用同表）。
   - exemplar 注释（`main.py:343-346`）已自证「YOLOE 视觉提示相似度分天然偏保守」——**同属 YOLOE
     开集打分逻辑的文本版大概率同样偏保守**，却没像 exemplar 那样单独校准默认。
   - 附带发现：exemplar 注释自相矛盾——既写「默认 0.25 而非闭集 0.25」又写「沿用闭集 0.5」
     （`:344-346`），与实际 `_PARAMS_SCHEMA.conf.default=0.25`（`:324`）对不上。注释需厘清。

## 1. 目标 / 非目标

**目标**
- 把 `conf.description` 改为 **task 中性文案**（去掉「检测/分割」字样），让 pose/obb/开集共用不别扭。
- 给 obb 的 `iou.description` 补一句「朝向框走旋转 NMS（probiou），阈值含义相同」（可选、轻量）。
- 给**开集文本** model 一份**独立 params schema**（仅默认值/文案不同，参数集与闭集一致），
  默认 conf 取值**以实测为准**（见 §3 验证门槛），不盲改。
- 厘清 exemplar 注释里「闭集 0.5」的矛盾表述。

**非目标**
- **不拆「参数集」**：四 task 的 conf/iou/max_det 都有效，参数集保持一致（查证已证伪初判）。
- **不动协议**：`/setup` wire 不变，仍逐 model 挂 `params`；只是挂的对象从「一份共用」变「按
  上下文派生的几份」，字段结构零变化。
- **不动平台 / 前端**：`SchemaForm` schema-driven，description/default 改了自动渲染；
  `ml_capabilities` 解析与 `x-platform-role` 映射不受影响。
- **不改 pose/obb 的 max_det 默认（300）**：除非有实测证据，默认值合理性争议留作观察项，不在本版动
  （避免无据调参）。

## 2. 设计与改动（`apps/yolo-backend/main.py`）

把当前「一份 `_PARAMS_SCHEMA` 打六处」改为**小工厂派生**，共享参数集、仅覆盖 description/default：

1. **基础表中性化**：`_PARAMS_SCHEMA.conf.description` 去掉「检测/分割」→
   「保留置信度高于此值的结果。调高=更少更准，调低=更多但含噪。」（task 中性）。
2. **新增 `_build_params_schema(*, conf_default=0.25, conf_desc=None, iou_desc=None)`**：返回一份
   深拷贝，覆盖给定字段。闭集四 task 用默认（等价现状，**零回归**）。
3. **闭集四 task**（`_build_model_entry`，`:427`）：继续用基础默认（保持 0.25 不变）。
4. **obb**（`:598` 挂载）：传 `iou_desc` 注明 rotated NMS（可选；若嫌琐碎可跳过，不影响功能）。
5. **开集文本三 model**（`_build_openvocab_model_entry`，`:510`）：改挂
   `_build_params_schema(conf_default=<实测值>, conf_desc="开集文本匹配置信度…")`。
   **`<实测值>` 在 §3 验证前先占位为 0.25（= 现状，安全），实测有据再调。**
6. **exemplar**（`_EXEMPLAR_PARAMS_SCHEMA`，`:348`）：可改为 `_build_params_schema` 的
   `score_threshold` 变体复用，或保持独立——**保持独立**（它换了字段名 `score_threshold`，
   复用收益低），仅修 `:344-346` 注释矛盾。

> 实现要点：派生用深拷贝，避免六处共享可变 dict 被意外改写（当前是同一对象引用挂多处，
> 只读无碍，但派生后各自独立更安全）。

## 3. 开集默认 conf 校准——验证门槛（不盲改）

§2 第 5 条的 `<实测值>` **必须有据**，否则保持 0.25。验证方式（择一）：
- 在 GPU 可用环境对 YOLOE 文本检测/分割跑几张含小目标的图，对比 conf∈{0.1, 0.25, 0.4} 的
  召回/噪声，确认是否需下调；
- 或参考 exemplar 已落地的 0.25 经验值——若文本版打分分布与 VP 一致，直接沿用 0.25（即**不改默认**，
  本版退化为纯文案修正）。

**诚实标注**：若实测不可行或结论不显著，本版就只做「文案中性化 + 注释厘清」，默认值一律不动。
这不是缩水——查证已表明默认值改动缺乏现成证据，无据调参比不改更糟。
