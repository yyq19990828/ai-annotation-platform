## 1. 目标与成功标准

本版把已经可创建、可编辑、可传播的 instance Mask 接入可运营的质量闭环：质量问题必须可重复计算、
可定位、可审阅、可修复；格式支持必须通过真实 consumer 逐像素验证，而不是只生成看似正确的文件名或 JSON。

成功标准：

- 图片与视频 Mask 有稳定、可配置的质量指标；同一 annotation version 的重复扫描不会生成重复问题。
- 问题可跳转到 annotation、帧和像素区域；annotation version 改变后旧问题立即以 stale 语义展示，
  不能继续冒充当前真值。
- reviewer 可比较当前 Mask 与上一版本、Tracker / AI 候选、邻近关键帧，并在 overlay、boundary、XOR、
  added、removed 视图间切换。
- 现有 Tracker 的实例 / 帧窗口决定扩展到 QC region；manual keyframe、locked annotation、segment lock
  和已审阅范围默认不可覆盖。
- 批量修复先 dry-run，再按冻结指纹提交；小批原子写入，大批可恢复分片，且在保留期内可冲突安全地回滚。
- AAP、COCO、Label Studio BrushLabels、binary / indexed PNG、YOLO Seg、COCO Frames、DAVIS、
  YouTube-VOS 和 MOTS 都有明确的无损 / 有损合同与 consumer round-trip。
- 5K / 8K QC、导入和导出沿用上一版的 tile、Worker、字节预算与临时目录配额，不创建全帧 RGBA。

部署级 `RASTER_MASK_CREATE_ENABLED` 继续默认开启并只作紧急总闸。M0–M8 期间项目级
`raster_mask_native_editing_enabled` 仍是独立 opt-in；M9 发布提交正式放量：新建项目默认开启，
既有项目通过数据迁移开启，同时保留项目级 opt-out，确保需要回退的单个项目无需关闭部署总闸。

## 2. 已有基线与本版增量

| 领域 | 当前可复用能力 | 本版只补的差量 |
|---|---|---|
| Mask 真值 | `raster_mask` / `video_track_mask`、不可变 COCO RLE ref、task-aware 校验 | revision ledger、QC region ref 与 GC 保活 |
| 像素计算 | RLE area / bbox、Worker pool、tile decode / merge、组件 / hole / morphology | 确定性 QC kernel、时序指标、跨 tile union |
| 反馈 | `annotation_feedbacks` 的 issue / comment、pixel anchor、thread / resolve | QC 专用 issue 表；评论 anchor 扩展 region / boundary 描述 |
| 审阅 | task approve / reject、review claim、Mask 编辑、审计 | approve-with-warning、blocking QC、Mask compare |
| Tracker | staged candidate、revision、实例 + 帧窗口 accept / reject、manual 保护 | issue region 决定、candidate digest、跨 job reviewed-range 保护 |
| 原子变更 | `MaskMutationService` 的 scope fingerprint、version、锁、idempotency、lineage | QC repair plan、可恢复分片和 rollback ledger |
| 导出 | AAP / COCO、COCO Frames、DAVIS、落盘 ZIP、异步 job、缓存 | adapter registry、统一 preflight / loss report、新格式与 consumer |
| 导入 | AAP、COCO / YOLO prediction、数据集 ZIP 路径与大小防护 | instance Mask import plan、staged receipt、统一安全 archive reader |

现有 Tracker 的“按实例 / 帧窗口决定”不是待办，不重写；现有 DAVIS 和 COCO Frames 导出也不另起第二套。

## 3. 不变量与术语

### 3.1 真值与版本

- QC 只读 immutable RLE object；不把 preview、PNG、bbox 或 overview 当 Mask 真值。
- 所有 issue、compare、repair 和区域接受都绑定 `annotation_id + annotation_version`；候选另绑定
  `job_id + job_revision + candidate_digest`。
- 写事务的锁顺序保持 `Task → segment / content refs → Annotation → domain row`；锁后重查版本、任务状态、
  `is_locked`、reviewed range 与 receipt digest。
- region 的坐标使用归一化半开区间 `[x0, y0, x1, y1)`；精确区域使用内容寻址二值 RLE ref，bbox 只用于
  定位和预取，不能替代精确 region。

### 3.2 像素与时序语义

- 二值前景采用 8-connectivity，背景 / hole 采用 4-connectivity，避免对角接触同时把前景和背景视为连通。
- 所有面积、IoU、Dice、XOR 和 overlap 都按像素整数计算；展示时才格式化小数。
- 视频只比较真实可解释的状态：manual / prediction / held 分开标注；相同 ref 的 held→held 不制造零变化
  “模型稳定”证据；outside 与 occluded 不按普通可见帧报异常。
- sparse 标注格式中的“未标注帧”不等于 outside，也不等于 nearest hold；无法原生表达时必须出有损报告。

### 3.3 格式语义

- `lossless` 表示 import→AAP canonical RLE 或 AAP→export→官方 consumer 后逐像素、class、instance、frame
  与 track identity 全部保持；只保持像素但丢 track / sparse-frame 语义仍是 `lossy`。
- overlap winner、frame base、padding、class / instance ID 映射必须出现在 manifest 和 preflight report，
  不允许依赖 ZIP 顺序或字典遍历顺序。
- 导入执行只能使用与 dry-run 相同的 staged object digest、adapter version、mapping 和 plan digest；变化时
  返回 409，要求重新预检。

## 4. 数据合同

### 4.1 Project Mask QC 配置

`projects.mask_qc_config` 为 JSONB，空对象读取成以下 `balanced` profile；PATCH 整体校验后替换：

```json
{
  "schema_version": 1,
  "config_revision": 1,
  "enabled": true,
  "blocking": false,
  "auto_run": "on_review_submit",
  "single_frame": {
    "near_empty_pixels": 16,
    "small_component_pixels": 32,
    "small_component_ratio": 0.005,
    "small_hole_pixels": 32,
    "narrow_bridge_width": 2,
    "boundary_noise_ratio": 0.15,
    "bbox_iou_min": 0.98,
    "overlap_pixels": 1
  },
  "temporal": {
    "sample_step": 1,
    "iou_drop": 0.35,
    "centroid_shift_diagonal": 0.15,
    "area_change_ratio": 0.50,
    "component_delta": 2,
    "flicker_max_frames": 2,
    "drift_min_consecutive": 3
  },
  "severity_overrides": {}
}
```

- `blocking=false` 时所有规则只提示；为 true 时也只有 severity=`blocker` 的当前 issue 阻止 task approve。
- 自动扫描只在提交 review 时合并为一个 task scope job；每次 annotation save 不直接启动 Celery 风暴。
- 项目管理员可关闭单条规则或覆盖 severity；未知 code 拒绝保存，不能静默忽略拼写错误。
- 每次配置更新由服务端递增 `config_revision`；QC run 同时冻结 revision 与 canonical config digest。

### 4.2 Mask revision ledger

新增 `mask_annotation_revisions`：

```text
id, project_id, task_id, annotation_id, annotation_version
geometry, geometry_digest, source_kind, operation_id?, actor_id?
created_at, expires_at
UNIQUE(annotation_id, annotation_version)
```

- 任一 Raster Mask 从 version N 写到 N+1 前，在同一事务 `INSERT ... ON CONFLICT DO NOTHING` 保存 N 的
  geometry；创建时不额外复制 current，删除 / deactivate 前保存最后活跃版本。
- 只保存 geometry 引用，不复制 RLE bytes；GC 把未过期 revision 和 repair rollback ref 计入 live roots。
- 默认每 annotation 保留最近 20 个版本且至少 30 天；最新 predecessor 在新版本存在期间始终保留。
- compare 基线已过期时返回 `baseline_expired`，不退化成当前版本或 bbox。

### 4.3 指标定义

单帧 kernel 输出整数原值和派生 ratio：

- `area_pixels`、`bbox_ratio`、`component_count`、`hole_count`、最大 / 最小 component area。
- `empty_mask`、`near_empty_mask`、`touches_border`、`small_island`、`small_hole`。
- `narrow_bridge`：在配置宽度的 erosion 下导致同一前景 component 分裂的区域；region 是被移除且连接
  两侧的像素，不把普通细长目标整体误报成桥。
- `boundary_noise`：`open(close(mask, radius=1), radius=1)` 与原 Mask 的 XOR 像素除以 4-neighbor
  boundary length；报告原始 numerator / denominator。
- `derived_geometry_mismatch`：stored bbox / polygon 派生像素与 Mask AABB / RLE 的 IoU 低于阈值。
- `same_class_overlap` / `cross_class_overlap`：交集像素、IoU、containment 与精确交集 region ref。

视频按相邻有效采样点和最近 manual anchor 输出：

- IoU / Dice、质心对角线归一化位移、面积变化率、boundary XOR ratio、component / hole delta。
- `flicker` 是被可见帧夹住、长度不超过阈值的短 visible / absent run；视频首尾截断不报同一规则。
- `drift` 必须连续达到阈值，且记录 anchor frame、candidate confidence、source 与 correction lineage。
- prediction 与 held 分开聚合；outside 跳过，occluded 单列统计，不进入默认 blocker。
- 扩展共享视频 resolver，明确返回 `state=exact|held|absent|outside|occluded`、
  `resolved_from_frame`、source、confidence 与 correction lineage；`outside[].source=prediction` 是模型
  明确判空的 `absent`，`source=manual` 才是人工 `outside`。旧 resolver 对两者继续返回
  `None`，不改 geometry schema；QC 与工作台不得分别猜测 held 来源。

### 4.4 QC issue

新增 `mask_qc_runs`，保存 scope、config revision / digest、source snapshot digest、async job ID、
status、progress 与 summary；领域 run 与通用 job 一一对应，不能把长期可查询的 QC 语义只塞在 job payload。

新增 `mask_qc_issues`：

```text
id, run_id, project_id, task_id, annotation_id, annotation_version
related_annotation_ids, code, severity, status
frame_start?, frame_end?, metric, threshold
region_bbox?, region_mask_ref?, region_digest
dedupe_key, source, suggestion
resolved_by_id?, resolved_at?, created_at, updated_at
UNIQUE(project_id, dedupe_key)
```

- `status ∈ open | resolved | wont_fix | stale`；version 不匹配时 API 即使后台尚未落状态也返回
  `effective_status=stale`。
- `dedupe_key = sha256(code + annotation/version + related ids + frame range + region_digest)`；同一版本重跑
  upsert 指标与 `last_seen_run_id`，不复制 issue。
- overlap 等多对象问题按稳定排序后的最小 annotation 为 primary，全部成员放 `related_annotation_ids`。
- `region_mask_ref` 仍走 Raster Mask 内容对象合同；无精确像素区域的时序 issue 只存 bbox / frame range。
- 人工评论继续复用 `annotation_feedbacks`；`anchor_type=pixel` 的 `anchor_position` 扩展可选
  `region_bbox / region_digest / boundary_digest`，不新建平行评论系统。

### 4.5 QC job 与预算

复用 `async_jobs`，新增 kind `mask_qc`、`mask_repair`、`mask_repair_rollback`、`mask_format_import`；
导出继续使用 `export`。QC job payload 只存 scope、config digest、annotation version 摘要，不塞 RLE。

- 单 job 最多 1,000 annotations、5,000 sampled frames、200,000 tiles；超限在 enqueue 前 422。
- 图片大于 dense 门后用 512 tile + halo；components / holes 通过 tile 内 label 与边界 union 合并。
- overlap 先用 AABB sweep-line 生成 pair，再做 RLE 交集；pair 上限 100,000，超限稳定返回
  `qc_overlap_pair_budget_exceeded`。
- 每 25 annotations 或 100 frames 检查 cancel，分批提交 issue；job 失败不删除上一轮当前 issue。
- 任务 scope 同一 config / version digest single-flight；新版本完成后旧 job 结果只可写 stale issue。

## 5. API 与事务

### 5.1 QC

```text
POST  /projects/{project_id}/mask-qc/runs
GET   /projects/{project_id}/mask-qc/issues
GET   /tasks/{task_id}/mask-qc/summary
GET   /mask-qc/issues/{issue_id}
PATCH /mask-qc/issues/{issue_id}
POST  /mask-qc/issues/{issue_id}/corrections
GET   /annotations/{annotation_id}/mask-compare
```

- run scope 为 `project | task_ids | annotation_ids`，请求显式携带 `expected_versions`；缺省使用当前快照并
  把版本写进响应。
- issue 列表使用 `(severity, created_at, id)` keyset，支持 code / status / task / annotation / frame 过滤。
- compare 的 baseline 仅允许 `previous_version | tracker_candidate | ai_candidate | neighbor_keyframe`；响应返回
  两侧 immutable refs、digest、指标和 loss，不由 API 生成大 PNG。
- correction 从当前 drift / flicker issue 创建既有 video correction job，并携带 issue / anchor lineage；
  stale issue 返回 409。

### 5.2 Task 审阅

- `POST /tasks/{id}/review/approve` 增加可选 body：`expected_qc_digest`、`warning_issue_ids`、`note`。
- blocking profile 下存在当前 blocker 时返回 409 `mask_qc_blockers_present`；非 blocking profile 可空 body
  继续兼容旧客户端。
- 携带未解决 warning 完成即是“接受但记录警告”；issue ids、QC digest 和 note 写入同事务 audit，任务状态
  仍使用现有 completed，不新增伪状态。
- 评论锚点与 approve / reject 不自动 resolve QC issue；只有显式 resolve / repair 后重算可改变状态。

### 5.3 Tracker region 决定

现有 `/video-tracker-jobs/{id}/decisions` 保持实例 + 帧窗口合同，新增互斥 selector：

```json
{
  "qc_issue_id": "...",
  "decision": "accept",
  "job_revision": 4,
  "candidate_digest": "sha256:...",
  "expected_source_versions": {"annotation-id": 8}
}
```

- issue 必须属于同 task / annotation / candidate 与单帧 region，且 version、region digest 均为 current。
- accept 只应用 `region_mask_ref` 内的 candidate XOR；region 外、其它帧、其它实例逐像素不变。
- reject 只消费该 region 的 staged candidate；剩余候选继续保活，全部决定后才清 staged refs。
- 新增 `mask_review_scopes` 记录 reviewer、source job、annotation version、frame range、region digest 与 decision；
  accept scope 绑定 mutation 后的 result version，后续 job 默认保护其覆盖范围；之后再发生其它 annotation
  version 变化时旧 scope 可审计但不再当当前锁。
- 修正现有 tracker review context：task 处于 `review` 时，已 claim 的 reviewer 和项目特权 reviewer 可做决定；
  仍拒绝未认领用户和 `completed` task，不能沿用当前一概拒绝 review task 的 guard。
- manual keyframe、annotation lock、segment lock、当前 reviewed scope 的保护在行锁后重查；不提供
  `override_manual=true` 的 UI 快捷绕过，特权覆盖必须单独确认并写 audit。

### 5.4 批量修复与回滚

```text
POST /projects/{project_id}/mask-qc/repairs:dry-run
POST /projects/{project_id}/mask-qc/repairs
POST /mask-qc/repairs/{job_id}/rollback
```

- 修复种类：`delete_small_islands`、`fill_small_holes`、`resolve_same_class_overlap`、
  `rerun_local_sam`、`rerun_tracker`。
- dry-run 输出 issue / annotation、源版本、changed pixels、mutation 数、跳过原因、scope fingerprint、
  plan digest 和 15 分钟 receipt。自动修复阈值必须是当前 QC config 的子集或显式更严格。
- 每个 task 最多 100 mutations 时复用 `MaskMutationService` 原子提交；更大 scope 固定按 task + 100 mutation
  分片，每片原子、可重试、可恢复，job result 逐片记录。
- locked、reviewed、manual、版本冲突和 blocker policy 都是逐条稳定 skip code；不能把 skip 算成功。
- `mask_repair_batches` 保存 before refs、after versions、operation ids 和 7 天 rollback 到期时间；GC 在到期前
  保活 before refs。rollback 只有 current version 等于对应 after version 才执行，冲突分片整体 409。
- rerun SAM / Tracker 只产生候选，不直接覆盖 annotation；接受仍走现有候选事务。

## 6. 格式 adapter 框架

### 6.1 统一接口

新增 registry，而不是继续在 `build_export_zip` 堆格式分支：

```text
MaskFormatAdapter
  media_types
  capabilities
  preflight_import(staged_object, project, mapping) -> MaskFormatPlan
  execute_import(plan, receipt) -> per-item report
  preflight_export(project, scope, options) -> MaskFormatPlan
  write_export(plan, sink) -> artifact + report
```

`MaskFormatPlan` 固定：adapter/version、loss class、items、unknown labels、size conflicts、overlap conflicts、
ID / frame mapping、estimated objects / files / bytes、skips、warnings、plan digest。每个 item 都有
`lossless | lossy | unsupported` 与 machine-readable codes。

### 6.2 安全与资源

- 把 datasets ZIP 的路径规范化、目录项、symlink、单文件、总展开 bytes、压缩比与文件数限制抽到共享
  `safe_archive`；导入 adapter 禁止直接 `extractall`。
- staged import 只接受 object storage key + SHA-256；预检流式读取 central directory / manifest，执行复核 digest。
- 导出沿用 tempfile 落盘，不回退 `BytesIO` 整包；单 job 临时空间默认 8 GiB、单 entry 512 MiB、文件数
  200,000，可由 ops env 收紧。写入过程中持续检查实际 bytes，不只相信预估。
- success / failure / cancel 都清临时目录；artifact 继续使用 7 天生命周期与预签名 URL。
- import 每 task 原子；大包跨 task 可恢复，result 列出 committed / failed / skipped task，重试只处理未提交项。
- archive reader 还必须拒绝重复规范化路径、case-fold collision、symlink、manifest 悬空引用，以及 PNG
  magic / 位深 / 尺寸与 manifest 不一致；不能只防 `../`。
- export cache key 加入 adapter version、manifest version 与 options digest；相同 key 的 cache miss single-flight，
  避免并发重复生成和唯一键竞争。

### 6.3 损失码

至少冻结：

```text
overlap_resolved, holes_polygonized, components_split, track_identity_lost,
sparse_frames_collapsed, occlusion_lost, class_id_remapped, instance_id_remapped,
instance_id_overflow, frame_base_changed, unknown_label, image_size_mismatch,
unsupported_geometry, nonportable_media_reference
```

UI 不翻译 code 本身，只映射说明；未知 code 仍显示原值，不能吞掉。

## 7. 图片 instance Mask 格式合同

| 格式 | import / export 合同 | 逐像素 consumer |
|---|---|---|
| AAP JSON | embedded canonical RLE object，无损；ref-only artifact 继续标非备份 | AAP importer + shared golden |
| COCO instance | 接受 polygon、uncompressed counts 和 compressed RLE；Mask 导出优先 compressed RLE，`iscrowd=1`；无损像素，class 显式映射 | `pycocotools.COCO.annToMask` |
| Label Studio BrushLabels | 官方 task / result 结构，`original_width/height`、`from_name/to_name`、`value.format=rle`；LS brush RLE 与 COCO RLE 使用独立 codec，不混用 | 官方 Label Studio SDK brush decoder |
| Binary PNG per instance | `masks/<item>/<instance>.png`，8-bit L，背景 0 / 前景 255；manifest 固定 annotation / class / media path；无损 | Pillow `L` decode |
| Indexed PNG instance map | 每 item 一张 8-bit `P` PNG，0 背景、1–255 instance；manifest 固定 pixel id；超过 255 拒绝或分片，不能回绕 | Pillow palette decode |
| YOLO Seg | polygon 行；hole、多 component、1px / 2px 结构和曲线边界均有损，必须带 loss report；导入也按 polygon rasterize 后生成 Mask | 独立 YOLO parser + raster golden |

Indexed PNG 的 overlap policy 只能是 `error | z_order | larger_area | smaller_area`，preflight 默认 `error`；
非 error 时每个被覆盖实例和像素数进入报告。binary per-instance 可无损保留 overlap。

## 8. 视频 instance Mask 格式合同

| 格式 | import / export 合同 | 逐像素 consumer |
|---|---|---|
| AAP JSON | keyframe / outside / occluded / source / track id 无损 | AAP importer + shared golden |
| COCO Frames RLE | 每个展开帧像素无损；缺少 track extension 时轨迹语义有损，不能按 category 猜 track | `pycocotools.COCO.annToMask` |
| DAVIS | `Annotations/<resolution>/<sequence>/<frame>.png` indexed PNG；同一 object id 跨帧稳定，0 背景；overlap 必须先选 winner | Pillow + DAVIS loader fixture |
| YouTube-VOS 风格 | sparse annotation PNG + `meta.json` object / category / annotated frames；未标注帧需选择 `outside_gaps` 或 `nearest_hold`，两者都报告 `sparse_frames_collapsed` | 官方目录 / metadata fixture reader |
| MOTS | 每 sequence 根目录 txt；`frame id class_id height width compressed_coco_rle`；frame base、class map、track id map 显式配置 | `pycocotools.mask.decode` |
| Video JSON | 继续只导出，ref-only，`nonportable_media_reference`；不新增可移植 import 宣称 | AAP internal reader |

- DAVIS / indexed PNG 的 palette 只负责显示，pixel index 才是 identity；PNG 优化不能重排索引。
- YouTube-VOS 的 sparse gap 无法映射为现有 nearest-hold schema 而不改变语义，因此本版明确是有损导入；
  不偷偷给 `video_track_mask` 增加第三种时间插值。
- MOTS 不从 `id = class * 1000 + instance` 反推任意项目类别；class / id mapping 写入 manifest 与 report。
- COCO Frames 没有 track extension 时，每个 frame instance 独立导入并报告 `track_identity_lost`，不按 IoU 自动串轨。

## 9. 前端工作流

### 9.1 QC drawer

- 工作台右侧新增“Mask 质检”页签：severity / code / status 筛选、当前 task summary、重新扫描与 job progress。
- 点击 issue 原子完成：切 task（必要时）→ 切视频 frame → 选 annotation → fit region → 打开 compare；任一步失败
  保持 issue 选中并提供重试。
- canvas 使用现有 overlay / tile renderer 显示 issue region；不为 issue 再创建一张全图 canvas。
- stale issue 显示旧版本标记，只允许查看 / 重新扫描，不允许修复、region accept 或当 blocking 证据。

### 9.2 Mask compare

- compare controller 只持两个 immutable refs / candidate buffers，模式为 `overlay | boundary | xor | added | removed`。
- decode、XOR、boundary 和计数复用固定 Worker pool；8K 只请求 viewport tile + halo。
- 面板显示两侧版本 / 来源、area、Dice、IoU、changed pixels、frame / anchor 和 loss；缺 baseline 明示原因。
- region / boundary 评论从当前 compare 选区创建，保存 normalized bbox、region / boundary digest 与 frame。

### 9.3 修复与格式 UI

- issue 多选进入批量修复 drawer，第一屏永远是 dry-run；确认按钮显示实际对象 / 帧 / 像素 / 分片数。
- rollback 只在 receipt 未过期且版本仍匹配时显示；冲突报告可下载，不提供“强制覆盖”。
- 导入 / 导出中心统一展示 loss class、mapping、overlap policy、frame base、unknown label 与 skipped items；
  `lossy` 必须二次确认，`unsupported` 不可勾选执行。

## 12. 浏览器验收矩阵

1. 图片 donut + 三 component 扫描得到正确 hole / component，点击问题定位精确 region。
2. 跨 512 tile 的小岛 / bridge 只生成一个去重 issue，8K 页面无整图 canvas。
3. 同类 / 跨类 overlap 显示交集像素；切 XOR / added / removed 后计数一致。
4. annotation 更新后旧 issue 立即 stale，旧 job 晚到不覆盖新 version。
5. 上一版本 compare 后添加 region comment，刷新仍定位同一 digest。
6. 视频 held、outside、occluded、flicker、drift golden 只报预期问题。
7. 从 drift issue 创建 correction job，候选 lineage 带 issue / anchor。
8. Tracker region accept 后 region 外、窗口外、manual 与 reviewed range 逐像素不变。
9. 同 revision 重复 region decision 幂等；过期 revision / digest 返回 409。
10. blocking profile 阻止 approve；关闭 blocking 后“接受但记录警告”完成并可在 audit 查看。
11. 批量删小岛 / 填 hole dry-run 与实际 changed pixels 一致，locked 项逐条 skip。
12. repair rollback 成功恢复 before ref；人工新改后 rollback 冲突且不覆盖。
13. Label Studio、binary PNG、indexed PNG、COCO image 导出下载后 consumer 逐像素一致。
14. lossy YOLO、indexed overlap 和 unknown label 在执行前必须确认 / 映射。
15. COCO Frames、DAVIS、YouTube-VOS、MOTS 各完成 import→edit→export consumer 闭环。
16. 大包取消 / 配额失败后 job、通知、临时文件与重试入口状态正确。

## 14. 非目标

- 不引入 semantic / panoptic class-map、16-bit semantic PNG 或类别冲突合成；留 v0.24.0。
- 不改变 `raster_mask` / `video_track_mask` geometry schema，不新增“稀疏未知帧”插值模式。
- 不用自动 QC 默认阻止提交，不用单一 IoU 代替所有判断。
- 不做模型化 / 学习型 QC、主动学习排序或跨视频 re-identification。
- 不把 YOLO polygon、DAVIS / indexed winner 或 sparse gap 转换宣传成无损。
- 不在 region accept 中提供任意自由形状覆盖；只接受当前 QC issue 的 immutable region。
- 不重写通用 Annotation、Task review、Tracker 或 Export job 框架。

## 15. 退出条件

v0.24.0 进入前必须有直接证据证明：

- M0–M9 各有独立验证记录和独立提交，工作区无本版本遗留修改。
- 当前 issue 不重复、不使用旧版本真值；compare、repair、region accept 都有版本 / digest / 锁证据。
- manual、locked、reviewed、outside / occluded 与 held 语义在 QC 和写入路径一致。
- 16 条浏览器场景全绿，5K / 8K QC 与大包格式门通过，无持续 Worker / bitmap / temp / staged 增长。
- 计划内各格式的无损 / 有损结论与真实 consumer 一致，所有 loss / skip 均机器可读且用户可见。
- rollback roots、revision refs、QC region refs 和 staged import 在保留期内不会被 GC，过期后可观测清理。
- instance Mask 的质量与交换合同稳定，后续 semantic / panoptic 不需要修改现有 instance geometry。
