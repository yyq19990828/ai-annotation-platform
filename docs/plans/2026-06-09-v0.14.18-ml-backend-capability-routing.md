# v0.14.18 · 多 ML Backend 能力路由(交互/批量两条线分流)

> 计划日期 2026-06-09 · 范围:一个项目注册多个 ML Backend 时(`MAX_ML_BACKENDS_PER_PROJECT ≥ 2`),把工作台 AI 从"单 active 后端驱动一切"改成**按角色 + 能力路由**——交互工具(point/bbox/text/exemplar)自动路由到支持该 prompt 的交互后端,批量预标走批量后端,两条线**同时就绪**。重点解决"yolo 设为默认 → gsam2 交互功能失效",并给出**多个交互后端**的解析规则。
>
> **已落地的前置(本 plan 之前)**:
> - `MAX_ML_BACKENDS_PER_PROJECT` 上限可调到 2(`.env`),注册即 1:N 可用集合。
> - 「绑定」语义改为「设为默认」(commit `ee4529da`):`ml_backend_id` 退化为"批量默认后端 + AI 总开关",不再是"唯一可用"闸门。
> - 工作台 AI 面板已有批量 backend 选择器(commit `6bba84ae`,复用 `PreannotateConfigForm`),但当时是**单 `selectedBackendId` 驱动一切**——本期把它拆成两条线。
>
> **不依赖后端改动**:`/predict/interactive`、`/preannotate` 都已按传入 `backendId` 工作,只校验后端存在、不要求等于 `project.ml_backend_id`(`apps/api/app/api/v1/projects.py:1232`)。本期纯前端。

## 1. 背景与问题

### 1.1 现状根因

工作台工具栏的交互工具(point/bbox/text/exemplar)能否使用,由这一条 gate:

```
useMLCapabilities(projectId, backendId).isPromptSupported(promptOf(tool))
```

而 `backendId` 是**单个**后端(默认 = 项目默认后端)。当默认后端是 yolo(批量,`supported_prompts: ["none"]`)时,`isPromptSupported("point") = false` → 全部交互工具置灰 → **gsam2 明明已注册在线,却够不着**。

链路:`useMLCapabilities`(`apps/web/src/pages/Workbench/state/useMLCapabilities.ts`)→ `useWorkbenchShellModel` → `ToolDock` / `useWorkbenchHotkeys` 的 `isPromptSupported`。

### 1.2 目标

注册两个后端的真实意图是**按能力分工**:gsam2 干交互精修,yolo 干整图批量。它们应当并存、各司其职,而不是被"单 active 后端"搞成互斥。

### 1.3 关键约束(实现必须尊重)

- `useInteractiveAI`(`apps/web/src/pages/Workbench/state/useInteractiveAI.ts`)只吃**一个** `mlBackendId`,且按 `(taskId, mlBackendId, ctx)` 缓存候选、**切 backend 即清空**(line ~106)。→ 路由必须在**单次交互手势内稳定**(多点 point 会话不能中途换后端)。
- 批量几何兼容校验走 `mlCapabilities.activeModel` + `enabledToolUnits`(`useCapabilityValidation.ts`),与交互线正交。

## 2. 核心模型:从"单 active"到"角色 × 能力路由"

```
                  ┌─ 交互线 (point/bbox/exemplar) ─┐
工作台 AI ────────┤                                 ├── 各自解析到支持该能力的后端
                  └─ 批量线 (文本 prompt / 开始预标 / OCR / 版面) ─┘
```

- **交互线**:画点/框 / 拖示例框(逐手势、逐对象)→ 解析到"支持该 prompt 的交互后端"。
- **批量线**:文本 prompt「找全图」+「开始预标」→ `preCfg`,用批量选择器(= 现 `selectedBackendId`,默认 = 项目默认后端)。

> **文本 = 批量(2026-06-09 决策)**:文本 prompt「给词→全图找所有实例」本质是批量语义,**从工具栏 AI 工具摘除**,只留在批量 AI 面板。这与后端自报一致——gsam2 的 detection/segmentation(文本路径)`is_interactive: False`,只有 interactive_seg/tracker 才 `True`。因此**交互 prompt 只剩 point/bbox/exemplar**,text 不进 `resolveInteractive`。

两条线**同时就绪**:yolo 当批量默认,gsam2 自动接管交互(point/bbox)。

## 3. 能力索引

对每个已注册后端拉一次 `/setup`(`useQueries`,管理页 `MlBackendsSection.tsx` 已是同款),建索引:

```
capIndex: backendId → {
  prompts: Set<"point"|"bbox"|"exemplar">,          // 交互 prompt(text 归批量, 不在此)
  textCapable: boolean,                              // 支持文本 prompt(批量线用)
  isInteractive: boolean,
  trackers: string[],                                // supported_trackers(视频用,本期不消费)
  reachable: boolean,                                // /setup 拉取成功
}
```

`/setup` 拉取失败的后端 `reachable=false`,从候选里排除(自动降级到其它可用后端)。

## 4. 多个交互后端的解析(本期核心)

**逐 prompt 确定性解析 + 首选兜底:**

```
resolveInteractive(p):                       # p ∈ {point, bbox, exemplar}(text 已归批量)
  cands = [b for b in registered
           if capIndex[b].reachable and p in capIndex[b].prompts]
  if cands == []:                    return null     # 该工具置灰
  if projectDefault in cands:        return projectDefault   # 项目默认优先(§10 决策)
  if preferredInteractive in cands:  return preferredInteractive
  return cands[0]                                     # 兜底:按注册顺序第一个支持它的
```

- **`preferredInteractive`**:用户选定的"首选交互后端"。默认 = 项目默认后端(若它本身交互)否则第一个交互后端。**按项目持久化**(localStorage,key 形如 `wb:preferred-interactive:{projectId}`)。
- **工具栏可用性** = 并集:某 prompt 只要**任一**交互后端支持,工具就亮:
  `isPromptSupported(p) = resolveInteractive(p) != null`。
- **`sam` 的 backend** = `resolveInteractive(promptOf(s.tool))` —— 随选中工具解析。point 多点会话内 prompt 类型不变 → backend 稳定 → 候选缓存不被清(满足 §1.3)。

### 4.1 三种情形覆盖

| 场景 | 行为 |
|---|---|
| 只 1 个交互后端 | 全部交互 prompt 路由到它,**无任何新 UI**(退化 = 现状) |
| 2 个都支持 point/bbox(gsam2 + sam3) | 都路由到**首选**(默认=项目默认);出现"交互后端"选择器切首选 |
| 异构:A 只 point,B 只 bbox | point→A,bbox→B **自动分流**(首选不支持时按兜底链) |

### 4.2 选择器位置与能力作用域

- **位置**:复用 `AIToolDrawer` 现有「后端」槽位(`AIToolDrawer.tsx:142-155`,本期把 `disabled` 启用)。抽屉按当前工具上下文渲染,天然有"当前工具"语境。(对比:ToolDock 竖排图标条无文字下拉位;AI 浮窗属批量线,放交互后端会混。)
- **能力作用域(关键,防错配)**:「后端」下拉**只列支持当前工具 prompt 的后端** `cands(promptOf(activeTool))`,选中值 = `resolveInteractive(promptOf(activeTool))`(真正会跑该工具的后端)。
  - 因此**永远选不到不支持当前工具的后端**。
  - `onChange` 设 `preferredInteractive`(对当前工具必合法)。切到别的工具时若 preferred 不支持它,`resolveInteractive` 按兜底链回退,下拉显示回退后的真实后端 —— **显示与执行始终一致**。
- **出现条件**:`cands(promptOf(activeTool)).length >= 2` 才可切,否则只读显示(单候选无 UI 噪音)。

## 5. 改动点(集中在前端)

| 现在 | 改为 |
|---|---|
| `selectedBackendId` 驱动一切 | 拆成 `batchBackendId`(= 现 selectedBackendId,批量线)+ `preferredInteractiveId`(交互线) |
| `mlCapabilities = useMLCapabilities(单 backend)` | 新增 `useBackendRouting(projectId, backends, defaultId)`:产出 `capIndex` + `isPromptSupported`(并集)+ `resolveInteractive` + preferred 状态/持久化 |
| `sam = useInteractiveAI({ mlBackendId: 单 backend })` | `mlBackendId: resolveInteractive(promptOf(s.tool))` |
| point warmup 用单 backend | `resolveInteractive("point")` |
| 批量 `preCfg` 用 selectedBackendId | 用 `batchBackendId`(行为不变) |
| `AIToolDrawer` 显示单 backendName | ≥2 交互后端时渲染交互后端选择器 |

- 新增 1 个 hook(`useBackendRouting`)+ `AIToolDrawer` 一个条件选择器。
- `ToolDock` / `useWorkbenchHotkeys` 的 `isPromptSupported` 签名**不变**,只是数据源从单后端换成路由并集。
- 批量几何校验(`useCapabilityValidation`)继续挂 `batchBackendId` 的 activeModel。

## 6. 边界与边缘情况

- **视频追踪**:`supported_trackers` 是另一维,已有 `VideoTrackerPropagateDialog` 选 tracker。**本期不碰视频**,只做图像交互 + 批量;视频后端解析留后续(同法可扩展)。
- **成本统计 / 能力警告**:交互相关挂 resolved 交互后端,批量挂 `batchBackendId`。
- **后端不可达**:`reachable=false` 从候选排除,自动降级。
- **首次进入无 preferred**:按默认规则(项目默认若交互,否则第一个交互后端)。
- **项目默认后端被改 / 后端被删**:preferred 若失效自动回落默认规则。

## 7. 后端内 model 路由(gsam2 协议 2.1 · 含 #3 回归修复)

跨后端路由(§2–4)解决"选哪个后端";但 gsam2 升级到协议 2.1 后,`/setup` 返回 **4 个 task 级 model、各带不同变体子集**,于是"后端内选哪个 model"也必须按能力/任务路由,不能再 `models[0]` / 全列。

gsam2(grounded-sam2)能力表(实测 `/setup`,protocol 2.1):

| model id | task | prompts | 几何输出 | 变体 |
|---|---|---|---|---|
| grounded-sam2-detection | detection | text | bbox | dino_variant |
| grounded-sam2-segmentation | segmentation | text | polygon | sam_variant + dino_variant |
| grounded-sam2-interactive-seg | interactive_seg | point, bbox | polygon | sam_variant |
| grounded-sam2-tracker | tracker | bbox | polygon→bbox | sam_variant |

顶层另有 `supported_variants`(sam_variant + dino_variant 两组)、`supported_text_outputs: [box, mask, both]`。

### 7.1 问题 (b):文本批量只能选 DINO 变体 —— #3 回归

现状:`usePreannotateConfig.primaryModel = models.find(非 doc) ?? models[0]` = **detection**。于是批量 popover 的:
- 变体选择器 = detection.supported_variants = **仅 dino_variant**(选不了 SAM2 变体);
- `derivePanelShape(detection)` 因 geo=[bbox] → **输出形态锁 box 并隐藏**。

**根因**:gsam2 的"文本批量"是**后端级**能力——由 detection(框/dino)+ segmentation(掩膜/sam+dino)按 `output_mode` 在后端内部编排,任何单 model 都表达不全。

**修复**:文本/prompt 路径(`!isDocMode && !isGeometricBackend`)的变体与输出形态改走**顶层能力**:
- 变体来源 = 顶层 `supported_variants`(两组);variant 轴 keys 同样取顶层(保证 `buildArgs` 拆分 + warm 跟踪正确)。
- 输出形态 = 顶层 `supported_text_outputs`(box/mask/both 三选可见),不用单 model 的 `supported_geometric_outputs`。
- `primaryModel` 不再驱动文本路径的变体/形态(几何路径仍用逐 task model)。

### 7.2 问题 (a):工具栏"模型"下拉列出全部 task 宏观项

现状:`AIToolDrawer` 在 `models.length > 1` 时按 task 分组列出全部 4 个 model(检测/分割/交互式分割/视频追踪)。用 smart-point(point)时只有 interactive_seg 能跑,却把 text/bbox model 也列为可选 → 看着像"和真实权重无关的宏观项"。

**修复**:模型选择器按**当前工具的 prompt 能力过滤** —— 只列 `supported_prompts ⊇ promptOf(activeTool)` 的 model(point → 仅 interactive_seg)。过滤后通常剩 1 个,选择器自动隐藏;真正的"权重"由变体选择器(sam_variant)承担。

### 7.3 原则

| 路径 | 入口 | 选 model 依据 | 变体/形态来源 |
|---|---|---|---|
| 交互工具 (point/bbox/exemplar) | 工具栏 | 按工具 prompt 过滤(interactive_seg) | 该 model 的变体(sam_variant) |
| 文本 prompt「找全图」 | **批量面板**(从工具栏摘除) | 不绑单 model(后端编排) | **顶层** supported_variants + supported_text_outputs |
| 几何批量 (yolo) | 批量面板 | 选中的 task model(detect/seg/obb/pose) | 该 task model 的变体(series/size) |
| OCR / 版面 | 批量面板 | activeDocModel | 该 model 的变体 |

### 7.4 改动点(并入 §5)

- `usePreannotateConfig`:文本路径变体/`panelShape` 改走顶层能力;`primaryModel` 仅用于几何/doc 判定。
- `AIToolDrawer`:模型选择器按 `promptOf(tool)` 过滤 `models`(text 工具已摘除,过滤集只含 point/bbox/exemplar)。
- **工具栏移除 `text-prompt` 工具**:`SamTextPanel`(「找全图」文本输入段)从 `AIToolDrawer` 摘除,文本能力只在批量 AI 面板(popover 的 prompt 路径已具备)。`TOOL_REGISTRY` / 工具能力 gate / 快捷键去掉 text-prompt 项。

## 8. 不在本版本

- 视频追踪后端的能力路由(留后续)。
- 同一 prompt 想**同时**对比两个后端结果(只走单一 resolved,用户切 preferred)。
- 逐 prompt 各自独立 preferred(本期一个 preferred + 逐 prompt 兜底,已覆盖异构;若实战需要再升级)。
- 后端侧改动(本期纯前端)。

## 9. 实现步骤与验证

1. 写 `useBackendRouting(projectId, backends, defaultId)` → 单测:capIndex 构建、resolveInteractive 三情形、兜底链(项目默认→preferred→注册序)、reachable 降级。
2. `useWorkbenchShellModel` 拆 `batchBackendId` / `preferredInteractiveId`,接 `sam` / warmup / `isPromptSupported` 到路由。
3. `usePreannotateConfig` 文本路径变体/panelShape 改走顶层能力(修 §7.1 回归)。
4. **从工具栏摘除 `text-prompt` 工具**(TOOL_REGISTRY / gate / 快捷键 / AIToolDrawer 的 SamTextPanel),确认批量面板覆盖文本用例。
5. `AIToolDrawer` 模型选择器按工具 prompt 过滤;≥2 交互后端时加交互后端选择器 + 持久化。
6. 回归:单后端项目行为零变化(退化路径);yolo 默认 + gsam2 注册 → 交互工具(point/bbox)亮且命中 gsam2、批量「开始预标」命中 yolo、批量文本「找全图」变体两组齐全。
7. tsc / eslint / 受影响测试全绿;同步 `docs-site/user-guide/`(交互/批量分流 + 文本归批量说明)。

## 10. 决策与待讨论

已定(2026-06-09):
- **文本 = 批量**:文本 prompt 从工具栏 AI 工具摘除,只留批量 AI 面板;交互 prompt = point/bbox/exemplar(见 §2 引文、§7.4)。
- **exemplar 保留交互线**:虽输出是"找全图相似",但**输入需在画布上拖框指定示例**,是手势驱动,留工具栏交互线(与 point/bbox 同类)。
- **首选兜底规则**:`resolveInteractive` 兜底顺序 = 项目默认后端 → preferred → 注册顺序。
- **preferred 持久化粒度**:**per user × project**(多人协作各自偏好不串)。
- **`ml_backend_id`(默认)**:路由上线后进一步弱化 —— 仅保留"批量默认 + AI 总开关"语义,不再参与交互能力判定;后续视情况评估是否废弃。
- **gsam2 两个回归/暴露问题并入本期**:(b)文本批量变体走顶层(§7.1)、(a)工具栏模型按工具过滤(§7.2)。
- **交互后端选择器**:位置 = `AIToolDrawer` 现有「后端」槽位(启用);**能力作用域化** —— 只列支持当前工具 prompt 的后端,选中值 = 实际解析后端,出现条件 = 该工具有 ≥2 个候选后端(详 §4.2)。
