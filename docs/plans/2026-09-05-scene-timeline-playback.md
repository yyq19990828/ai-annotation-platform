# Scene 时间轴美化与连续播放计划

状态：已确认并实施，定向检查与浏览器实测通过。代码基线：`ac48b237`。本轮已明确将连续播放纳入范围；未分配发布版本号。

## 目标与现状

将点云画布底部的 Scene 帧格升级为紧凑、可展开的时间轴，便于连续浏览、准确定位和沿对象轨迹检查。视觉参照项目现有视频播放条的展开形态。

用户截图中的主要问题是每帧都有完整竖边框，小帧号、密度柱和轨迹标记挤在同一列；整个模块高度固定，信息层次和操作入口弱。当前代码为 32px 标题栏加 64px 帧格，含边框约 97px。本轮浏览器实测在 791px 窗口、744px 画布内容宽度下仍为 97px，说明新设计必须按画布容器宽度响应，不能只看浏览器宽度。

已有能力继续作为实现基础：当前帧定位、横向虚拟滚动、160ms 快速点选合并、下一帧预取、标注数量、任务状态数据、对象存在区间和成员角色、质检标记及跨帧任务入口。Scene 是跨 task 帧序列，摘要接口每次最多返回 200 帧，没有保证完整的 FPS 或时间戳。

## 推荐形态

采用一个底部嵌入式组件，两种显示形态。借用视频的分行轨道和紧凑控件节奏，使用工作台现有语义主题色。Scene 继续随主画布移动，不在本次新增 Dockview 面板或浮窗。

无 Scene 或不超过一帧时，保持现有不显示时间轴的行为；摘要加载失败保留重试入口，不渲染空播放器。

### 紧凑态，默认显示

- 目标高度 72px：一排播放与定位控件，一条轻量全段位置轨道。显著减少逐帧栅格，保留当前帧位置和可点击进度。
- 控件包括 Scene 名称、上一帧、播放/暂停、下一帧、帧号输入、总帧数、浏览速率、质检、跨帧任务和展开按钮。
- 当前帧使用明确游标和品牌色；总帧数和实际帧编号分别表达，例如 `F105 · 6/39`，正确支持非零起点 Scene。
- 全段位置轨道支持点击和拖动定位。拖动期间先显示候选帧号，松手才提交目标，避免每个像素都触发任务跳转。读屏和键盘可以使用原生 range 控件操作。
- 轨道仅表达全段进度和当前窗口。未加载区间不能伪装成“零标注”或“没有质检问题”。

紧凑态信息示意，符号仅说明位置，不是最终图标：

```text
scene-0061   ‹  ▶  ›   F[12] · 13/39   [2 帧/秒]     质检 3   跨帧任务   展开
起点 ────────────────●────────────────────────────────────────── 终点
```

### 展开态，按轨道检查

目标高度约 180–220px，随有效信息行数变化。各轨道共用一个帧窗口、标尺和当前帧游标；左侧标签列约 72px，轨道行高 24–28px，普通文字 12px，帧数等宽对齐。

| 轨道     | 表达与交互                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 帧标尺   | 清晰主刻度与轻量次刻度，不再给每帧画满高度的边框。悬停显示准确帧号。                                          |
| 任务状态 | 复用项目现有任务状态名称和颜色。缺失、不可访问、摘要加载中有不同纹理或文字提示。                              |
| 标注密度 | 当前窗口内每帧的 3D 标注数量，悬停显示具体数值；窗口内统一柱高基准，并注明当前窗口最大值。                    |
| 当前对象 | 选中轨迹后显示。存在区间用淡色带，已物化 keyframe/derived/sample 用不同形状区分；缺口不能自动解释为对象缺席。 |
| 质检问题 | 有问题时显示，沿用最高严重度标记和现有定位回调；同帧多个问题仍由质检面板展开。                                |
| 底部操作 | 播放与帧输入、浏览速率、缩放、定位当前帧、质检和跨帧任务。                                                    |

```text
scene-0061 · 当前对象 car #17                                      收起
帧          0         5         10        15        20        25
任务状态    ──────────────── 已处理 / 待处理 ──────────────
标注数量    ▁▂▁▃▂▂▁▂▁▃▂▁▁▂▃▁▂▂▁▂▁
当前对象        ═══●════════◆══════●══════
质检问题             !                  !
             ‹  ▶  ›   F[12] · 13/39   [2 帧/秒]   −  +  定位当前帧
```

没有选中轨迹时隐藏对象行；没有质检问题时保留质检入口，不占一条空轨道。播放时当前游标与帧号必须始终清晰，不能依赖颜色辨认。

### 自由布局与视觉约束

- 沿用 `bg-card`、`border-border`、`text-foreground`、`text-muted-foreground`、`brand` 与任务状态 tokens。只保留一层容器边界，不复制视频控件里的固定暗色玻璃、渐变和高层级遮罩。
- 容器小于 720px 时控件分成两行；小于 480px 时质检/跨帧入口使用有 Tooltip 和无障碍名称的图标。播放、帧输入、展开按钮一直可见，不被挤出画布。
- 高度不足以同时留下 240px 主视图时，暂时使用紧凑态；恢复空间后恢复用户选定的展开态，不覆盖桌面布局快照。
- 展开/收起保留焦点与当前窗口，不重建 Scene 或 renderer。切帧、游标移动和缩放不做布局动画；按下和焦点反馈沿用现有按钮。
- 展开偏好和缩放档位仅在当前工作台会话中记忆；切帧不重置，切 Scene 重置窗口。播放状态不持久化，刷新后始终暂停。
- 同一 Scene 内切 task 时保留窗口和播放意图，只重置目标帧的加载状态。现有按 taskId 清空窗口/定时器的 effect 要区分预期切帧与外部跳转；以真实返回的 sceneId 确认场景身份，不能依据占位摘要继续播放。

## 导航增强

1. **前后帧**：定位前后可访问帧，跳过摘要明确标为 missing/unavailable 的位置，轻量提示跳过数量；到边界禁用对应按钮。
2. **帧号直达**：校验实际整数帧号及 Scene 起止范围。窗口外目标通过现有接口查询 `[N,N]`，再走现有导航回调；明确缺失或不可访问时留在原帧并提示，不擅自换成邻帧。
3. **缩放**：第一轮使用 24/40/64/80px 每帧四档，默认 40px。各行同步变化，缩放以当前帧为锚点，手工横向浏览以窗口中心为锚点；提供“定位当前帧”。
4. **滚动和跟随**：播放时游标接近可见窗口边缘才向前平移，避免每帧强行居中。暂停后允许查看别处，不立刻把窗口拉回当前帧。
5. **键盘**：仅时间轴自身或帧轨道获得焦点时，Space 播放/暂停、普通左右键前后帧、Home/End 首尾定位。输入框、菜单和模态保持自身键盘行为。不得复用 3D 的 Shift+左右跨帧复制，也不覆盖画布方向键微调或 Space 平移。
6. **长 Scene**：保留虚拟化及 200 帧请求上限，缩放变化后重新测量虚拟列表。总览条允许任意位置定位；不增加万帧全量加载、伪全段密度或全段关键帧扫描。

## 连续播放行为

### 时钟与就绪

- 名称为播放/暂停，速率菜单明确显示 `1 / 2 / 4 帧/秒`，默认 2 帧/秒。这是浏览速率，不宣称采集原速或视频倍速。
- 采用串行逐帧预览：目标帧就绪后至少停留 `1000 / 速率` 毫秒，到期才导航下一帧。菜单提示这是最高浏览速率，加载较慢时实际速率降低；不堆积定时任务、不跳帧追赶，不用固定 interval 连续触发导航。
- 手动点选继续保留 160ms 合并意图；播放器共用串行导航执行路径，但不重复支付人工点选防抖。暂停优先于待发送的自动导航。
- `onNavigateFrame(true)` 仅意味着任务/URL 导航获准，不能作为帧就绪信号。由 `ThreeDWorkbench` 派生带 taskId 的 loading/ready/error：manifest 匹配当前 task、标注查询成功、目标点云 URL 与已加载 URL 相同、stats 存在、点云不在加载且无资源/renderer 错误，才进入 ready。
- 当前帧先显示已有点云直到目标点云就绪，沿用原有几何替换和渐进上色。相机上色、深度等可选资源不阻塞播放；未就绪的相机图显示该帧加载态，不能残留上一帧图像。
- 播放过程中只预取下一可访问帧，复用现有缓存上限、取消与 generation 机制；不创建新 renderer、复制 geometry 或在生产逻辑中读取开发诊断 DOM 属性。
- 连续等待目标 15 秒仍未就绪则暂停并显示可重试状态。错误恢复后不自动续播。

### 编辑与任务锁

连续播放采用只读预览，避免每帧反复申请编辑锁。这是本计划中明确包含的行为调整：

- 播放前，检查 PSR 的 250ms 待发送提交、非法但尚未提交的表单值、已在途标注保存、拖动、连续建框/选点草稿以及相机编辑模态。存在未完成操作时禁用播放并显示具体原因，不通过切帧丢弃草稿或偷偷提交非法字段。
- 播放启动后在 Shell 暂停当前 3D 浏览会话的写锁申请，复用 `useTaskLock` 的 enabled 参数，停止旧心跳并释放旧锁。已发出但迟到的获取锁响应要在仍不需要该任务锁时清理，不能释放重新恢复编辑后正在使用的同任务锁。
- 播放期间保留主视角旋转/缩放和时间轴浏览，屏蔽创建、修改、删除、传播、任务提交等写操作。现有服务端权限验证保持权威。
- 暂停后恢复当前帧的正常锁流程；获取成功前保持只读，锁冲突仍可查看。审核或其他原本只读的场景不会因暂停而取得编辑权限。
- 点击主画布/三视图的编辑区域或使用编辑快捷键时先暂停，本次操作不同时提交编辑；明确暂停并恢复就绪后再执行编辑。播放控制在 loading 状态仍允许暂停。
- 暂停会取消未发送意图和后续定时器。已提交到路由的切帧允许完成一次，完成后停在该帧，不再推进。

### 轨迹、缺帧与退出

- 播放开始时记住所跟随的 trackId。跨到没有物化成员的帧时保留跟随意图，不伪造框；后续帧有同轨迹成员时恢复该成员选择。离开 Scene 或结束这次播放会话时清理该临时意图。
- missing/unavailable 摘要只用于跳过，不请求其点云资源；需要新摘要窗口时显示等待并按最多 200 帧分段读取。真实 403、网络、解码和 renderer 错误立即暂停。
- 到末帧停止，再次播放从首个可访问帧开始。第一轮不循环、不反向自动播放。
- 页面进入后台、画布面板被隐藏、切换 Scene、任务队列外部跳转或离开工作台时暂停；回来后不自动恢复。

## 接入与改动范围

最低变更路径是复用现有摘要、缓存、导航和组件体系，补一个 Scene 专用的播放控制 hook，不建立通用媒体播放器框架。视频组件保留自身 timebase、章节、循环、AI 轨道等业务。

```text
Workbench Shell：导航保护、预览状态、任务锁和写操作边界
  ↓ 状态 / 显式导航命令
ThreeDWorkbench：当前帧资源就绪、待提交编辑、轨迹选择
  ↓ frameReady / 编辑阻塞原因 / 预览命令
SceneTimeline：紧凑/展开、可见窗口、帧定位
  └─ useScenePlayback：串行时钟、目标 taskId、暂停和错误
```

资源状态向下传递，播放和导航通过显式回调发出；不新增全局 store。手动和自动导航共用执行器，只有意图调度方式不同。

预计涉及 8–10 个生产文件，加相关测试与文档总计约 16–20 个文件：

| 文件                                                    | 计划改动                                                                    |
| ------------------------------------------------------- | --------------------------------------------------------------------------- |
| `SceneTimeline.tsx`                                     | 两态布局、分轨、播放控件、帧输入、焦点内快捷键、窗口与导航联动。            |
| `sceneTimelineVirtualization.ts`                        | 缩放档位、帧窗口上限及锚点计算；保持非零 Scene 起点正确。                   |
| 新增 `useScenePlayback.ts`                              | 有界串行播放、就绪门槛、暂停/超时/迟到响应和跟随轨迹意图。                  |
| `ThreeDWorkbench.tsx`                                   | 派生生产就绪状态、连接播放预览、覆盖编辑开始/未完成操作与成员选择。         |
| `usePsrPatchPipeline.ts`                                | 暴露待发送/在途提交状态，开始播放前不能漏掉 250ms 防抖窗口。                |
| `WorkbenchStageHost.tsx` / `useWorkbenchShellModel.tsx` | 传递 Scene 预览状态与回调，将预览接到既有锁及写操作保护。                   |
| `useTaskLock.ts`                                        | 明确预览暂停锁申请的生命周期，验证并处理迟到获取与恢复同任务锁的竞态。      |
| `timelineCoords.ts` / `VideoPlaybackOverlay.tsx`        | 复用坐标换算，将现有 `niceFrameStep` 原样提取为共享纯函数；视频行为不重写。 |

以上文件位于当前 Workbench 模块及 `apps/web/src/hooks/`。不新增后端 endpoint、数据库迁移、workspace schema、账号设置、依赖、环境变量、API key 或外部账号。总览聚合数据、章节、书签、范围循环和时间轴自由停靠不在本轮范围。

## 实施批次与验收

**批次 A：视觉与手动导航。** 实现紧凑/展开、分轨、帧输入、缩放与焦点内导航，并同步指南。此时仍可正常手动使用，无需等待播放功能，独立可合入。

**批次 B：连续播放与预览边界。** 一起接入播放控制、资源就绪、待保存保护、锁生命周期与错误暂停。不能先交付一个只按定时器切任务、未处理保存/锁的播放按钮。

最脆弱的前提是“导航成功等于可继续播放”。已由显式目标就绪门槛替代。第二个风险是快速切帧期间的编辑和锁竞态，必须用可控制的迟到响应测试验证，不能只看顺畅播放截图。

| 验收组 | 必须覆盖                                                                                                                  |
| ------ | ------------------------------------------------------------------------------------------------------------------------- |
| 视觉   | 明暗主题、0/1/39/10000 帧、无轨迹/有轨迹、有/无质检、容器 320/480/744px 与桌面 1440/1728/1920px；375px 维持现有桌面提示。 |
| 导航   | 非零起点、首尾、缺帧、不可访问、未加载目标、错误重试；缩放和手工滚动不被无故拉回，跨帧后轨道仍对齐。                      |
| 播放   | 1/2/4 帧每秒、慢请求、等待中暂停、15 秒超时、末帧、外部切任务、隐藏/恢复、旧请求晚到。始终至多一个自动导航在途。          |
| 编辑   | 播放前 PSR 防抖和保存失败、未完成绘制；播放期间零标注写入/传播/任务提交；暂停后锁未就绪不得编辑。                         |
| 锁     | 播放不逐帧获取锁或启动心跳；暂停仅恢复当前帧；旧获取晚到不留锁、不释放新会话的有效同任务锁。                              |
| 性能   | 万帧虚拟列表仍有界，摘要请求不超过 200 帧；实际播放一段 Scene 无新 renderer/geometry 副本，停止后无永久空闲渲染循环。     |
| 回归   | 三视图/相机自由布局、主视角连续性、跨帧任务与质检入口，以及视频播放条展开和键盘行为。                                     |

## 实施与验证结果

已交付紧凑/展开分轨时间轴、全段定位、实际帧号输入、四档缩放和 1/2/4 帧每秒串行只读播放。Shell 暂停任务锁并阻止写操作；点云与标注真正就绪后才推进。输入无效、待保存、绘制或编辑面板未结束时无法启动，失败重试保持暂停。

实际接入还修改了 `Topbar`、`useWorkbenchHotkeys` 和 `usePointCloudScene`：禁用提交入口，隔离时间轴与布局菜单的键盘事件，为失败点云提供原地重试。任务摘要共享 React Query 的取消信号，单个预取消费者退出不会误取消播放器等待中的相同请求。窗口外任务解析时允许短暂空任务身份，继续等待预期目标，沿用原有 15 秒期限。
