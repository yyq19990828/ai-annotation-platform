## 3. 设计要点

### 3.1 ThreeDWorkbench 的配置注入

ThreeDWorkbench 已接收壳层 props(layout 回调等);新偏好沿同通道注入 + 变更回调上抛,由壳层(useWorkbenchConfig)统一防抖 PATCH——与 v0.15.3 抽屉写路径同一条,**不在 stage 内直接发请求**。

### 3.2 旧 localStorage 键收编(一次性 seed)

```
读 preferences 字段:
  - 有值 → 用之(已 seed 过或用户在别的设备设过)
  - 无值(后端默认)且旧全局键存在 → 取旧值作为初值,立即 PATCH 写入 preferences,
    成功后 localStorage.removeItem(旧键)
```
注意「无值」与「默认值」不可区分的问题:pydantic 默认填充会让后端总是返回值。处理:seed 判定改为**前端本地标记**——`workbench.{userId}.pcd.migrated`(localStorage)不存在且旧键存在才 seed,seed 后写标记。简单、幂等、可单测。

### 3.3 PointCloudScene 的 setter 形态

网格/轴/阻尼都是场景生命周期内可变属性,加三个幂等 setter(`setGridVisible(v)` 直接 `grid.visible = v`,不增删对象),React 侧 useEffect 同步——遵循该文件既有的「场景对象常驻、属性可变」风格(如 setReferenceBoxes)。

### 3.4 双入口一致性

既有「显示」菜单里的点大小滑块/掩膜模式下拉**保留**,但改为读写同一 preferences 字段(经同一 setter),抽屉与菜单天然同步;不做第二份 state。

## 5. 已知风险 / 未尽事项

- **ThreeDWorkbench.tsx 体量大**(本版主要改动集中于此):严格只动列出的状态与初始化路径,不顺手重构(CLAUDE.md §3)。
- **seed 的竞态**:首帧 preferences 尚未 fetch 完成时进入工作台——沿用 useWorkbenchConfig 既有的「默认值先行、fetch 后覆盖」节奏,seed 放在 fetch 完成回调里,避免把默认值误写回。
- **colorize 恢复的代价**:大点云上色是显著一次性计算;粘性恢复=用户已知成本(他自己开的)。但**首帧自动触发**与手动点击路径需走同一懒加载逻辑,防止任务尚未载完点云就上色。
- **视频侧 overlayK 替换会话级 state**:确认 `useWorkbenchShellModel` 透传链(CrossFrameOverlayToggle 的 value/onChange)无其他消费者依赖「进任务重置为默认」的旧行为;若审核流依赖重置,改为仅标注模式粘性(实现时确认,PR 说明)。

## 6. 验证策略

- **单测**:seed 幂等(有旧键/无旧键/已 migrated 三态);三 setter 幂等;掩膜模式枚举回退(脏值→rect)。
- **手工端到端**(用本机 nuScenes dataset,见 temporal roadmap §6):调点大小+关网格 → 刷新保持;第二个账号登录同浏览器 → 不串台;开 colorize → 重进任务自动恢复且投影正常;视频任务调 K=5 → 刷新保持。
- **回归红线**:点掩膜三种模式框选行为、跨帧 overlay 渲染(v0.15.1 ego 对齐)不变,既有测试守。
