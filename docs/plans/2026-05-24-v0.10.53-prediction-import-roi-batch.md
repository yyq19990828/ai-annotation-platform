## 2. 设计决策

### 2.1 keypoint LS 映射（ROI-6 的岔路，本版需拍板）

内部 `KeypointGeometry` 是一组带可见性的点（`points: list[{x,y,v}]`，v∈{0,1,2} COCO 可见性），LS 标准 `keypointlabels` 是单点单区域，无「多点带可见性」标准结构——阻抗不匹配。

- **方案 A-kp（推荐，默认）**：沿用 `keypointlabels` type，用扩展 `value.points:[{x,y,v}...]` 承载点集 + 可见性。result 仍是 LS `{type,value,score}` 形状，写/读对称简单。代价：`value.points` 非 LS 原生 schema，纯 LS 工具（CVAT）读会忽略点集——但 keypoint 本就不在 COCO/VOC/YOLO 导出范围，影响可接受。
- **方案 B**：导入直接写内部格式 shape（`{type,class_name,geometry,...}`），利用 `to_internal_shape` 的 `"geometry" in s` pass-through（[prediction.py:45](../../apps/api/app/services/prediction.py)）零转换对称。代价：破坏「result 是 LS 标准」不变量，仅对 keypoint 开特例使存储不统一。

> 默认 A-kp。实现前在 PR/Step 4 启动时最终确认。

### 2.2 多 shape 的入库语义（ROI-2）

一个 `AAPPredictionEntry` 当前对应一条 Prediction（result=[单 ls_shape]，[predictions_import.py:240-270](../../apps/api/app/services/predictions_import.py)）。增 `shapes[]` 后：一个 entry → 仍是**一条** Prediction，但 `result=[ls_shape_1, ls_shape_2, ...]`（list[shape]）。前端 `predictionsToBoxes`（transforms.ts:195）本就按 `p.result.map(shape => ...)` 展开多 shape，天然支持。`score` 取 entry 级；各 shape 自带 confidence。

### 2.3 多文件的合并语义（ROI-3）

**客户端循环**：wizard 选 N 个文件 → 对每个文件调一次现有单文件端点 → 前端聚合 `imported/skipped/errors[]` 计数展示。**不改后端端点签名**（最小改动；errors[] 标注来源文件名便于定位）。dry_run 同样逐文件跑。

## 3. 实施步骤

### Step 1 — COCO `image_size_hint` 端点 + wizard 透传（ROI-1）
- 后端 [apps/api/app/api/v1/predictions.py](../../apps/api/app/api/v1/predictions.py) import 端点：`format=coco` 时新增可选 form 字段 `image_width` / `image_height`，组装成 `image_size_hint=(w,h)` 传给 `import_coco`（importer 已支持）。
- 前端 [PredictionImportWizard.tsx](../../apps/web/src/components/predictions/PredictionImportWizard.tsx)：选 COCO 时显示两个可选数字输入（默认空 = 不传，沿用 image 自带 width/height）；[predictions.ts import()](../../apps/web/src/api/predictions.ts) multipart 带上。
- **验证**：构造缺 width/height 的 COCO + 填 hint → dry_run 不再整批 skip；image 自带尺寸时 hint 不覆盖。

### Step 2 — `AAPPredictionEntry.shapes[]`（ROI-2）
- schema [apps/api/app/schemas/aap_json.py:73](../../apps/api/app/schemas/aap_json.py)：`AAPPredictionEntry` 增 `shapes: list[dict[str,Any]] | None = None`（与单 `geometry` 二选一；都给时 `shapes` 优先，`geometry` 视作单元素）。
- importer [predictions_import.py `_entry_to_ls_shape`](../../apps/api/app/services/predictions_import.py)：改造为产出 `list[ls_shape]`——遍历 `entry.shapes`（或退化为 `[entry.geometry]`），逐个走 `internal_geometry_to_ls_shape`，跳过 None 的并计 errors[]；全空则该 entry skip。`import_aap_json` 用合并后的 `result=[...]` 调一次 `create_from_ml_result`。
- **验证**：单测——一个 entry 带 3 个 shape → 一条 Prediction、result 含 3 shape；含 1 个不支持 kind → 该 shape 进 errors[]，其余 2 个正常入库；旧单 `geometry` entry 行为不回归。

### Step 3 — 多文件批量导入（ROI-3）
- 前端 [PredictionImportWizard.tsx](../../apps/web/src/components/predictions/PredictionImportWizard.tsx)：file input 加 `multiple`；逐文件顺序调用 `predictions.import()`，聚合各文件 `AAPImportResult` 为总计 + 分文件明细；errors[] 前缀文件名。
- 后端不改（沿用单文件端点）。
- **验证**：preview 选 2 个 AAP JSON → 预览汇总计数正确，errors 能区分来源文件；单文件路径不回归。

### Step 4 — keypoint 几何补齐（ROI-6，写/读双向对称）
- 按 §2.1 选定方案（默认 A-kp）。
- 写路径 [internal_geometry_to_ls_shape](../../apps/api/app/services/predictions_import.py:46)：增 `keypoint` 分支 → `{type:"keypointlabels", value:{points:[{x*100,y*100,v}...], keypointlabels:[cls]}, score}`；空点集 → None。
- 读路径 [to_internal_shape](../../apps/api/app/services/prediction.py:30)：增 `keypointlabels` + `value.points` → `keypoint` geometry；同步 `derive_tool_unit_from_ls_type` 给 keypointlabels 正确 unit，**替换 [prediction.py:15](../../apps/api/app/services/prediction.py) 注释承认的「归 bbox 占位」**（顺带修 ML backend 直出 keypointlabels 的渲染缺陷）。
- 校验坐标系：x/y *100（LS），v 不缩放（0/1/2 原样）。
- **验证**：round-trip 单测（内部 keypoint → LS → 内部，含 v∈{0,1,2} 与可见点 AABB）；导入端到端 + 工作台渲染（geometryToShape keypoint 分支 transforms.ts:87 已就绪）。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| keypoint 非标准 value.points 破坏 CVAT 兼容 | §2.1 已评估影响局限；如顾虑改方案 B |
| shapes[] 与 geometry 二选一歧义 | 明确优先级（shapes 优先）+ 单测覆盖两路；旧 fixture 全绿 |

| image_size_hint 覆盖了 image 自带尺寸 | importer 现有逻辑：image 有 width/height 时优先，hint 仅兜底（predictions_import.py:358-363）；不改该优先级 |
