## 1. 任务目标与背景

### 1.1 要做什么
把"选中标注后右键弹操作菜单"从 v0.10.33 的**视频 track 一种**，推广到：
- **图片 stage 的所有标注类型**：box / rotated-box / polygon / polyline / mask / keypoint（[Tool 类型见 useWorkbenchState.ts:9-26](../../apps/web/src/pages/Workbench/state/useWorkbenchState.ts)）；
- **视频 stage 的 `video_bbox`**（单帧框；`video_track` 已在 0.10.33 覆盖）。

即：用户用任意标注工具在图上画好形状、**选中后右键** → 在光标处弹出该标注的常用操作菜单。

### 1.2 为什么做
右键菜单是工作台缺失的平台级能力（三个 stage 的 `onContextMenu` 原本都只 `preventDefault`）。0.10.33 已补上基建并让视频 track 先吃；本版本让**图片 stage 这个主力场景**和视频单帧框也用上同一套右键入口，对齐 CVAT「选中对象右键即得完整操作面板」的心智，让标注员不依赖侧栏。

### 1.3 关键架构差异（务必先理解）
| | 视频 stage（0.10.33 已做） | 图片 stage（本版本） |
|---|---|---|
| 渲染 | SVG overlay，手动 picking | **Konva（react-konva）**，每个形状是 Konva 节点 |
| 命中判定 | `pickTopVideoEntryAt(entries, pt)`（[videoStagePicking.ts:19](../../apps/web/src/pages/Workbench/stage/videoStagePicking.ts)） | **Konva `stage.getIntersection(pointer)`** 或形状节点自身 `onContextMenu` |
| 选中 | `onSelect(id)` | 形状 `onClick`（[ImageStageShapes.tsx:104](../../apps/web/src/pages/Workbench/stage/ImageStageShapes.tsx) `e.cancelBubble=true; onClick(e)`） |
| 右键平移 | 见 0.10.33 §2 | [ImageStage.tsx:700-710](../../apps/web/src/pages/Workbench/stage/ImageStage.tsx) `onContextMenu preventDefault` + `onPointerDown` `button===2 → setDrag({kind:"pan", sx, sy})` |
| 操作 handler | `useVideoTrackActions` (`trackActions`) | **`useWorkbenchAnnotationActions`**（`handleDeleteBox` / `handlePatchShapeFlag` 等） |

## 3. 实现方案

### 3.0 设计核心：类型感知的菜单项构造器
每个 stage 写一个纯函数 `buildContextMenuItems(annotation, handlers): DropdownItem[]`，按 `annotation.geometry.type` 返回不同项。**菜单外壳与开合逻辑复用 0.10.33，本版本只新增"按类型拼 items"和"图片 stage 的命中/平移共存"**。

### 3.1 图片 stage 接入

改 [ImageStage.tsx](../../apps/web/src/pages/Workbench/stage/ImageStage.tsx)：

1. **右键拖拽 vs 轻点**（同 0.10.33 §2 判定表，阈值 5px）：
   - `onPointerDown`（[:700](../../apps/web/src/pages/Workbench/stage/ImageStage.tsx)）已 `setDrag({kind:"pan", sx, sy})` 记录起点——直接复用，**不要动 pan 逻辑**。
   - **保留 keypoint 特例**（[:707-708](../../apps/web/src/pages/Workbench/stage/ImageStage.tsx)：keypoint 工具下右键 = 跳过当前节点，不抢 pan）——菜单判定要排在该特例之后，keypoint 绘制中右键不弹菜单。
   - 在 `onContextMenu`（[:700](../../apps/web/src/pages/Workbench/stage/ImageStage.tsx)）里：`preventDefault` 始终保留；用 `drag` 的 `sx/sy` 与事件坐标比位移，≥5px 视为平移不弹；< 阈值则命中判定。
2. **命中判定**：用 Konva `stageRef.current.getIntersection({ x, y })` 拿到右键处的形状节点 → 反查 annotation id（形状节点上挂 id，或用现有 selection 映射）。**推荐用 getIntersection 在容器层集中判定**，与视频的"容器层 picking"对称；不要给每个形状散绑 `onContextMenu`（难统一 pan/tap）。
   - 若需要，给形状组件（[ImageStageShapes.tsx](../../apps/web/src/pages/Workbench/stage/ImageStageShapes.tsx)）的 Konva 节点补 `name`/`id` 属性以便反查。
3. 命中后：先 `onSelect(id)`（与左键点击一致），再 `contextMenu.openAt(clientX, clientY)`。
4. **构造 items**（按类型）：

   | 菜单项 | 适用类型 | onSelect | kbd | disabled |
   |---|---|---|---|---|
   | 改类别 | 全部 | `onChangeUserBoxClass(id)` | — | `readOnly` |
   | 锁定 / 解锁 | 全部 | `handlePatchShapeFlag(id,"is_locked",!locked)` | `L` | — |
   | 隐藏 / 显示 | 全部 | `handlePatchShapeFlag(id,"is_hidden",!hidden)` | `H` | — |
   | 标记遮挡 / 取消 | box/rotated-box/polygon | `handlePatchShapeFlag(id,"is_occluded",!occluded)` | `O` | `readOnly\|\|locked` |
   | （divider） | | | | |
   | 移到顶层 / 底层 | 全部 | `handlePatchShapeFlag(id,"z_order",...)` | — | `readOnly\|\|locked` |
   | 复制 / 粘贴 | 全部 | `useClipboard` copy/paste | `Ctrl+C`/`Ctrl+V` | — |
   | （divider） | | | | |
   | 删除 | 全部 | `handleDeleteBox(id)` | `Del` | `readOnly` |

   - 文案随当前态切换（锁/隐藏/遮挡读 annotation 的 `is_locked`/`is_hidden`/`is_occluded`）。
   - 类型差异：mask/keypoint 是否支持 occluded 视既有数据模型而定，不支持就不放该项（按 `geometry.type` 过滤）。
5. 在 ImageStage 渲染树挂 `<ContextMenu>`（与 0.10.33 视频侧同样用 portal 渲染，避免被 Konva 容器裁剪）。

### 3.2 视频 stage 新增 `video_bbox` 分支
改 [VideoStage.tsx](../../apps/web/src/pages/Workbench/stage/VideoStage.tsx) 的 root `onContextMenu`（0.10.33 已写命中判定）：
- 0.10.33 里 `if (!hit || !isVideoTrack(hit.ann)) return;` —— 放宽为也接受 `isVideoBbox`。
- `video_bbox` 的 items：改类（`onChangeUserBoxClass`）、删除（`onDelete`）、**聚合为轨迹**（若已多选多个 bbox，`onComposeTracks?.({operation:"aggregate_bboxes", ...})`，与 `VideoTrackPanel` 的"聚合 N 个框"同源）、拆/复制框（`onConvertToBboxes`，与 `VideoSelectionActions` 一致）。
- `video_track` 分支保持 0.10.33 不变。

### 3.3 不做（留位 / 边界）
- 空白处右键菜单（工具/新建）——非本版本，另议。
- 多选批量右键菜单——本版本按单选处理（右键先选中命中对象）；批量留待后续。
- polygon/polyline 的"编辑点 / 简化 / 翻转方向"等几何专属操作——CVAT 有，但本版本先不做，留待几何编辑专项。

## 4. 验收口径
1. **回归红线（两个 stage）**：右键拖拽（≥5px）平移画布行为完全不变；浏览器原生菜单始终被抑制；图片 keypoint 绘制中右键跳节点的特例不被破坏。
2. 图片 stage：选中任一类型标注后右键 → 光标处弹对应菜单；菜单操作结果与侧栏/快捷键一致（同走 `handlePatchShapeFlag` / `handleDeleteBox` / `onChangeUserBoxClass`，无重复实现）。
3. 视频 stage：右键 `video_bbox` 弹框操作菜单；`video_track` 菜单与 0.10.33 一致无回归。
4. `readOnly` 时不弹菜单或相应项禁用；锁定对象的写操作项禁用，"解锁"仍可用。
5. 菜单越界翻转、Esc / 外部点击 / 选中项关闭（复用 0.10.33 `ContextMenu`，无需重测外壳）。
6. 暗色模式配色正确（`pnpm lint:css-tokens` 通过）。

## 7. 实现注意（踩坑）
- **Konva 命中坐标**：`getIntersection` 接收的是 stage 容器内的相对坐标，注意把 `clientX/clientY` 减去容器 `getBoundingClientRect()` 偏移，并考虑当前缩放/平移变换（参考 ImageStage 既有的坐标换算工具，勿自造）。
- **形状反查 id**：给 Konva 节点设 `id`/`name` 或维护 node→annotationId 映射；优先复用 ImageStage 现有的 selection 命中逻辑（找它左键选中是怎么定位形状的，照搬）。
- **最小改动**：复用 0.10.33 的 `ContextMenu`/`useCanvasContextMenu`；图片侧只加命中/items/渲染，不重构 Konva 事件体系、不动 pan 状态机。
- **类型感知**：items 构造器以 `geometry.type` 分支；新增类型时只改这一个纯函数，便于测试与扩展。
