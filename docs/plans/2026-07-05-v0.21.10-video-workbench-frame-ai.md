# v0.21.10 · 视频工作台「当前题 AI」单帧检测能力 + 待审计数稳定

状态：**计划（2026-07-05）**。修复视频工作台「当前题 AI」面板对视频 task **基本不可用**的三处缺陷
（排查见下）。纯前端为主（一处后端行为确认），无 schema/alembic。与
[v0.21.9 视频预测审阅联动](2026-07-05-v0.21.9-video-prediction-review-linkage.md) 正交——v0.21.9 是
「AI 结果怎么看/审」，本计划是「AI 单帧推理能不能跑、待审数准不准」。

## 动机（排查已定位到根因，全部带证据）

### 断点 A · 面板模型下拉被写死只剩 tracker，没有单帧检测入口
工作台调 `usePreannotateConfig` 时**没传 `executionUnit`**（`useWorkbenchShellModel.tsx:963-966`），
hook 内 `isVideoTracking = isVideoProject && executionUnit !== "frame"`（`usePreannotateConfig.ts:206`）
→ 恒 `true` → `geometricModels`/`selectableModels` 被过滤成**只 `task === "tracker"`**
（`usePreannotateConfig.ts:207-215 / 266-287`）。视频项目在工作台里根本选不到图像检测模型。
（对比：批量页 `ProjectDetailPanel:924` 有 execution_unit 开关能切 `"frame"`，工作台面板没有。）

### 断点 B · 单帧「运行当前题」发给 tracker → 静默 0 候选
主按钮 `onRunAi` 视频指向 `handleRunVideoFrameAi`（`useWorkbenchShellModel.tsx:2651`），抓当前帧 JPEG →
`buildArgs` 发的 `task_type` 就是选中模型（=tracker，`usePreannotateConfig.ts:582-587`）→ `/predict-frame`
把单帧图喂给 tracker backend → yolo `_predict_tracker` 对这张 .jpg 跑 `model.track` 产 `video_track_bbox`
（`apps/yolo-backend/predictor.py:219,465`）→ 服务端 `to_video_bbox_result` **只收 `type=="bbox"`、
`video_track_bbox` 整条丢弃**（`prediction.py:352-355`）→ `candidate_count=0`，toast「新增 0 个候选」。
**即视频单帧 AI 现在点了等于没点。**

### 断点 C · 「待审」数抖动 100→500→100
- header 的 `{aiBoxCount} 待审`（`AIInspectorPanel.tsx:588`）= `aiBoxes.length`
  （`useWorkbenchShellModel.tsx:2647`），而 `aiBoxes` 来自 `predictionsToBoxes`（`transforms.ts:246`）
  **完全没按 `frameIndex` 过滤、也不按 id 去重**；下方候选**列表**却按当前帧过滤
  （`AIInspectorPanel.tsx:905`）。→ 两个数语义不同：header 是**全视频所有帧**候选总数，列表是当前帧。
- 叠加 offset 分页（`usePredictions.ts:5-27`：PAGE_SIZE=100、按 confidence desc、cumulative-offset 作
  pageParam）：跑完 `/predict-frame` invalidate（`useWorkbenchShellModel.tsx:1464`）后逐页重取，新预测按
  高置信度插到顶部使 offset 漂移、相邻页 shape 重叠，无去重的 `aiBoxes.length` 把重复 shape 都计入 →
  瞬时冲高（500），refetch 全完 offset 重对齐后回落（真实值）。

## 定稿决策（拟，待用户确认一处）

- **「当前题 AI」面板 = 当前帧作用域**（正名）。视频下它应做**单帧检测**（对当前帧跑 detection→
  `video_bbox` 落该帧），而非整段 tracker——tracker 是整段操作，归 Shift+T 种子追踪 / 批量页（execution_unit=
  video），不该混进「当前题」。
- **断点 A/B 修法**：工作台给 `usePreannotateConfig` 传 `executionUnit="frame"`（面板据此放开非-tracker 的
  `GEOMETRIC_TASKS` 检测模型），`buildArgs` 自然发 `task_type=detection/segmentation` → `/predict-frame` →
  `to_video_bbox_result` 正确落 `video_bbox`。**后端零改动**（单帧路径本就支持，只是之前喂错了模型类型）。
- **断点 C 修法**：① `aiBoxCount` 对视频**按当前帧过滤后再计数**，与列表口径一致；② `predictionsToBoxes`/
  `aiBoxes` 按 `id`（`pred-${p.id}-${shapeIndex}`）去重，消除重取期重复计数；③（可选，治本）`usePredictions`
  的 offset 分页改稳定游标 / 重取去重，消除 offset 漂移。①②即可让 header 稳定且与列表一致，③为深层加固。
- **面板纯做单帧检测**（用户 2026-07-05 拍板方案 a）。「当前题 AI」面板不保留整段追踪入口——追踪走
  Shift+T 种子追踪 / 批量页（execution_unit=video）。面板留一句轻指引，告诉找追踪的用户去哪跑，避免"入口
  消失"的困惑。（理由：tracker 在该面板本就静默失效，移除是修复不是减功能。）

## 关联缺陷（同根「帧作用域缺失」，一并收）

- **编排按钮「运行当前题（按项目编排）」对视频跑整段而非当前帧**：`buildPipelineRunPayload` 投
  `task_ids:[taskId]` **无 frame_index**（`useWorkbenchShellModel.helpers.ts:157-163`），与其注释「只跑当前
  一图」（`AIInspectorPanel.tsx:605`）矛盾——视频 task 变成整段 batch（execution_unit=frame 就 335 帧全跑）。
  纳入本计划：编排按钮对视频 task 也走**当前帧作用域**（复用单帧 `/predict-frame` 逐阶段，或给 payload 加
  frame_index 让后端单帧执行）；多阶段编排在单帧上的语义随 WS3 细化。

## 实现分阶段

- **WS1 · 视频单帧检测能力（断点 A/B）**：工作台透传 `executionUnit="frame"` 给 `usePreannotateConfig`；
  确认 `buildArgs` 发 detection `task_type`；E2E 验证单帧「运行当前题」在当前帧落 `video_bbox` 候选（非 0）。
  面板不留 tracker 入口（方案 a），留一句去 Shift+T / 批量页的指引。
- **WS2 · 待审计数稳定（断点 C）**：`aiBoxCount` 视频按当前帧过滤；`predictionsToBoxes`/`aiBoxes` 按 id 去重；
  视需要改分页游标。验证跑 AI 后 header 数稳定、与列表一致、不再冲高回落。
- **WS3 · 编排按钮视频帧作用域（关联缺陷）**：`buildPipelineRunPayload` 对视频 task 带当前 frame_index +
  单帧执行路径；多阶段编排单帧语义细化（首版可限单阶段检测，与 v0.21.7 首刀一致）。
- **WS4 · 验证 + 版本**：E2E 全链（单帧检测落候选 / 待审数稳 / 编排按钮不再跑整段）；CHANGELOG + 版本 bump。

## 不在范围

- 整段 tracker 的能力本身（已有，走 Shift+T / 批量页）；本计划只把它移出「当前题」单帧语义。
- 逐帧批量优化 / 采样步长（那是 v0.21.8 + Q2 的活，另议）。
- v0.21.9 的时间轴预测密度 / 轨迹候选画布渲染 / 关键帧来源可辨（正交，独立）。

## 风险

- **移除面板 tracker 入口的回归感**（方案 a 已定）：习惯从工作台面板点追踪的用户会一时找不到入口——WS1
  必须在面板留一句指引（去 Shift+T 种子追踪 / 批量页），把"入口消失"变成"入口迁移"。
- **去重口径**：`aiBoxCount` 与列表都要用**同一** frame-scope + dedup 函数，否则又对不上（v0.21.9 也要复用
  `resolveTrackAtFrame`，注意口径统一）。
- **编排单帧语义（WS3）**：多阶段编排在单帧上「上游框喂下游」的执行链，后端单帧路径 `/predict-frame` 当前
  是单模型单帧，多阶段要么限单阶段、要么需后端补单帧多阶段执行——WS3 细化时定，勿在本计划膨胀。
