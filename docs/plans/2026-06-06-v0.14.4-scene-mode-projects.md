# v0.14.4 · scene 模式项目 + scene 感知分包 + 数据集 kind 匹配(patch,加两列)

> 规划日期 2026-06-06 · 范围:把 scene 从「散落在各子系统的隐式开关」提升成**项目级一等声明**(`scene_mode`),用它当总开关驱动 scene 感知分包 / scene 连续调度 / 跨帧 UX,并在「项目↔数据集关联」处加 **kind 对称硬门**。同时补上至今缺失的 `by_scene` 分包策略与 data_type 匹配校验。Roadmap 见 [`2026-06-06-v0.15-temporal-fusion-roadmap.md`](2026-06-06-v0.15-temporal-fusion-roadmap.md)。
>
> **前置依赖**:v0.14.0(scene 模型)/ v0.14.1(scene 连续调度 `prefer_same_scene_continuation` + 跨帧 propagate)/ v0.14.2(nuScenes 脚本)/ v0.14.3(导入鲁棒性 + 跨帧跨 batch 导航 R3)均已合入。本版**在它们之上加两列 + 一个分包策略 + 一道关联校验**,不改既有契约。

## 1. 背景与目标

### 1.1 为什么要做

v0.14.0~v0.14.3 把 scene 模型、跨帧 propagate、跨 batch 导航都建起来了,但 scene 始终是**隐式**的:数据集「是不是 scene」靠派生(有没有 `Scene` 行),项目根本不知道自己是不是要做时序标注。由此带来一组互不知情的冲突(详见关联分析):

| 编号 | 冲突 | 现状(代码位置) |
|---|---|---|
| **C1** | 分包切碎 scene | `services/batch.py::_split_random` 按 `(created_at,id)` 均分/shuffle,**完全不看 `scene_id`/`frame_index`**;一个 scene 的连续帧会被切到多个 batch、派给多个人。split 策略至今只有 `["metadata","id_range","random"]`(`schemas/batch.py:145`),**`by_scene` 不存在**。 |
| **C2** | 跨帧 propagate 撞可见性墙 | scene 被拆到不同人的 batch 后,A 想把框延续到 B 的帧 → `_assert_task_editable`(annotator 可见性 `batch.annotator_id IS NULL or == self`)拒绝 → `Alt+→` 静默失败。 |
| **C3** | scene 连续调度被分包反噬 | `scheduler.py::_next_same_scene_task` 找到下一帧仍过 `_filter_assignable_task_ids`(batch 归属);分包没把 scene 留在一起时,v0.14.1 这个特性永远回退随机——和分包对着干。 |
| **C4** | 审核粒度错位 | 审核是 per-batch(`reviewing→approved`);track 漂移只有整段帧放一起才看得出。scene 跨多 batch → 跨帧一致性**无法被审**。 |
| **C5** | 数据集↔项目零匹配 | `POST /datasets/{id}/link` **无任何 kind 校验**(连 data_type 都不校验),前端 `Step5Datasets` 直接 `useDatasets()` 不带 filter;video 数据集能挂 image 项目,scene 数据集能挂普通项目。 |

**根因**:scene 不是项目的一等概念。一旦 `scene_mode` 显式声明,就能**一处声明、处处联动**,C1~C4 顺带消解,C5 的 kind 匹配也有了判据。

### 1.2 设计决策(已拍板)

| 维度 | 选择 | 含义 |
|---|---|---|
| 数据集 scene 声明 | **混合** | gating 用**派生** `has_scenes`(实时 `EXISTS(scenes)`,零漂移、不加 `scene_count` 列);另加显式 `is_temporal` 意图列**仅用于导入期校验**。 |
| 关联 gating | **对称硬门** | 项目 `(data_type, scene_mode)` ⟺ 数据集 `(data_type, has_scenes)` 两者都必须相等。前端过滤 picker + 后端 link 端点 422,API 也绕不过。 |
| scene_mode 行为 | **自动联动** | 开 scene_mode 即默认:`prefer_same_scene_continuation=true` + 分包默认 `by_scene` + 跨帧 UX 默认亮(用户仍可逐项再关)。 |

### 1.3 待定小点(本文件取默认,可改)

- **video 是否纳入 scene_mode**:本版**只对 `image` / `lidar` 开** scene_mode(video 已有抽帧 / tracker 独立路径,留后)。wizard 里 video 的 scene 开关隐藏。
- **建项目后能否翻转 scene_mode**:**一旦该项目已建 task,scene_mode 锁死不可改**(改会让已 link 数据集 kind 不一致);要改先解绑清空。无 task 时可改。
- **小 scene 是否打包进一个 batch**:本版 `by_scene` 默认 **一个 scene 一个 batch**(最干净:scene=batch=owner,审核即 scene 审核);打包多个小 scene 留后续可选项。

### 1.4 不在本版本

- ego_pose / 时间戳数据模型(留 v0.15.0,见 roadmap)。
- 跨帧自动插值 / Kalman / 批量 propagate(留 v0.15.1)。
- scene 级独占锁 / scene 级 assignment 模型 / 多人分段标同一 scene(对称硬门下 scene≈batch≈一个 owner 已拿到 90% 价值,重模型留到出现「长 scene 必须多人分段」硬需求时)。
- 对**存量** project-dataset link 的追溯校验:新规则只拦**新** link,旧 link 不动。
- `by_scene` 的「按目标体积打包多 scene」(见 1.3)。

### 1.5 成功判据

1. **scene_mode 项目**:建 image/lidar 项目时可勾选 scene 模式;勾选后该项目 `prefer_same_scene_continuation` 默认 `true`、分包默认策略 `by_scene`。已建 task 后接口拒绝翻转 scene_mode(422)。
2. **kind 对称硬门**:scene_mode 项目的数据集 picker **只列出** `data_type` 相同且 `has_scenes=true` 的数据集;普通项目只列出 `has_scenes=false` 的;`POST /datasets/{id}/link` 对 kind 不匹配返回 **422**(含 data_type 不匹配,这是第一次强制)。
3. **`by_scene` 分包**:`POST /batches/split` 支持 `strategy="by_scene"`,一个 scene 的全部帧进**同一个 batch**、**绝不跨 batch**,batch 内 task 按 `frame_index` 升序且 `sequence_order` 落帧号。对本机 `DS-NU-nu-mini-multi`(3 scene)分包得 **3 个 batch**,每 batch 帧序连续。
4. **派生 has_scenes**:`GET /datasets` 支持 `has_scenes=true|false` 过滤(实时 `EXISTS`);不加 `scene_count` 列。
5. **is_temporal 导入校验**:导入声明 `is_temporal=true` 却未建出任何 scene → 导入报错;`false`/未声明保持现状。
6. **回归红线**:既有 `random`/`metadata`/`id_range` 分包、既有未匹配 link 的存量数据、v0.14.1 scene 调度、v0.14.3 跨 batch 导航全部不破。
7. `pnpm lint` / `pnpm test` / `uv run pytest -q` 全绿;真实 nuScenes-mini(本机已存)端到端:建 scene_mode lidar 项目 → picker 只见 `DS-NU-*` → `by_scene` 分包 → 跨帧 propagate 不再撞墙。

## 3. 各模块设计要点

### 3.1 schema · 两列(单次迁移)

```python
# project.py
scene_mode: Mapped[bool] = mapped_column(Boolean, nullable=False, server_default="false", default=False)

# dataset.py
is_temporal: Mapped[bool] = mapped_column(Boolean, nullable=False, server_default="false", default=False)
```

- **不加 `dataset.scene_count`**:`has_scenes` 一律实时派生 `EXISTS(SELECT 1 FROM scenes WHERE scenes.dataset_id = datasets.id)`。数据集数量级小,EXISTS 过滤/出参派生开销可忽略,换零漂移。
- 回填:`scene_mode=false`、`is_temporal=false`(存量 dataset 即便有 scene,intent 也置 false——它只管「导入时声明」,不影响 has_scenes 派生)。
- `DatasetOut` 增**派生只读** `has_scenes: bool`(出参算,不存)。

### 3.2 D1 · scene_mode 自动联动 + 翻转锁

`services/project.py` 建项目时:

```python
if payload.scene_mode:
    payload.setdefault("prefer_same_scene_continuation", True)   # 用户没显式给才默认 True
    payload.setdefault("default_split_strategy", "by_scene")      # 见 §3.4 落点
```

- `prefer_same_scene_continuation` 是 v0.14.1 已有列,这里只是 scene_mode 时默认打开;用户在高级设置里仍可关。
- **默认分包策略**:本版不新增「项目默认 split 策略」持久列(过度),而是前端建项目后的「分包向导」**预选** `by_scene`(scene_mode 项目)。即联动落在 UX 预选 + 文档约定,而非新列。若后续要硬约束再加列。
- **翻转锁**:`PATCH project` 改 `scene_mode` 时,若 `project.total_tasks > 0` → 422「已建 task 的项目不可切换 scene 模式,请先解绑数据集」。无 task 可改(同时 kind 重算)。

### 3.3 D2 · 派生 has_scenes + is_temporal 导入校验

- `GET /datasets` 增 `has_scenes: bool | None = None` 查询参:`True` → `WHERE EXISTS(...scenes...)`;`False` → `WHERE NOT EXISTS(...)`;`None` 不过滤。与既有 `data_type` 参可叠加。
- 导入链路(nuScenes 脚本 / ZIP 向导)收尾处:若调用方声明 `is_temporal=true` 但该 dataset `scene_count==0`(本次没建出任何 scene)→ 抛 `ValueError`/422「声明为时序数据集但未识别出任何 scene,请检查目录结构」。`false`/未声明 → 现状不变。
- `is_temporal` **不参与** gating(gating 只看派生 has_scenes),它纯粹是导入期的「早失败」护栏。

### 3.4 D3 · kind 对称硬门(`project_kind.py` 单一真值)

```python
# project_kind.py(示意)
@dataclass(frozen=True)
class ProjectKind:
    data_type: str        # image / video / lidar
    scene_mode: bool

@dataclass(frozen=True)
class DatasetKind:
    data_type: str
    has_scenes: bool

def kind_matches(p: ProjectKind, d: DatasetKind) -> bool:
    return p.data_type == d.data_type and p.scene_mode == d.has_scenes
```

- `services/dataset.py::link_project` 进入建 link 前:取 project kind + dataset kind(`has_scenes` 实时查),`kind_matches` 为假 → **422**,detail 明确分两类:「data_type 不匹配(项目 image / 数据集 lidar)」或「scene 模式不匹配(scene 项目需 has_scenes 数据集)」。
- **这是第一次强制 data_type 匹配**;只拦新 link,存量 link 不追溯(§1.4)。
- 前端 `Step5Datasets`:用项目 kind 派生 picker 过滤参 `?data_type=X&has_scenes=<scene_mode>`,只列匹配项;无匹配时空态提示「没有符合该项目类型的数据集,请先导入对应数据集」。后端 422 是兜底(防直接调 API)。

### 3.5 D4 · `by_scene` 分包(本版核心补缺)

`services/batch.py` 加 `_split_by_scene(project_id, data)`,`split()` dispatcher 加分支,`schemas/batch.py` 的 `strategy` Literal 加 `"by_scene"`:

```
1. 取 splittable task(_splittable_task_ids:batch_id IS NULL or B-DEFAULT,按 created_at,id)
2. 每个 task 反查 (scene_id, frame_index)
   —— 复用 scene 服务的两路反查:task.dataset_item_id 直链 / TaskDatasetItemLink role=primary_lidar
   —— 抽成 scene.py 里可复用 helper(scheduler / neighbors / 本策略三处共用)
3. 按 scene_id 分组;scene_id 为 NULL 的 task(scene_mode 项目里理论不该有)落「无 scene」组
4. 每个 scene → 一个 TaskBatch(DRAFT):
   - name = f"{name_prefix} · {scene_name}"
   - _assign_tasks(batch.id, 该 scene 全部 task_id)
   - 写 task.sequence_order = frame_index(让 SEQUENCE 采样按帧序走)
   - recalculate_counters(batch.id)
5. annotator_id/reviewer_id 透传(可选,与现有 random 一致)
```

- **一 scene 一 batch**:scene=batch=owner,C1/C2/C4 一并解(propagate 不跨 owner、batch 审核即 scene 审核)。
- **`sequence_order=frame_index`**:配合 scene_mode 项目默认 `sampling=sequence`,「领下一个」即「下一帧」,与 v0.14.1 scene 连续调度同向。
- 「无 scene」组:本版按现有 random 行为兜底单独成 batch(或并入,给 warning),不静默丢。
- 不做「多小 scene 打包」「scene 内再切分」(§1.4)。

### 3.6 前端 wizard

- `Step1DataTypeAndTools`:`data_type ∈ {image, lidar}` 时显示「scene 模式」开关(video 隐藏);state 提到 `CreateProjectWizard` 顶层 `sceneMode`。
- `Step5Datasets`:`useDatasets({ data_type, has_scenes: sceneMode })` 过滤;卡片继续显示 `data_type`,scene 数据集加「时序 / N scene」角标;空态提示见 §3.4。
- `api/projects.ts` 的 `ProjectCreate` 带 `scene_mode`;建项目成功后进分包向导时,scene_mode 项目预选 `by_scene` 策略。

## 5. 已知风险 / 未尽事项

- **强制 data_type 匹配是行为收紧**:历史上能乱 link,本版起新 link 受限。存量违例 link 不追溯(只可能在「再次 link」时撞 422)。文档需说明。
- **一 scene 一 batch 可能产生很多小 batch**:10 scene → 10 batch。本版接受;「按体积打包小 scene」留后续。
- **scene_count==0 的「时序意图」数据集**:导入中途(scene 还没建完)`has_scenes` 暂为 false,link 会被拦;需在导入**完成后**再 link。文档提示。
- **翻转锁的边界**:无 task 时可改 scene_mode,此时若已 link 了 kind 不符的数据集,需一并校验/解绑;实现时在翻转处重算 kind,冲突则要求先解绑。
- **scene 删除使 has_scenes 翻转**:scene 仅在导入建、随 dataset CASCADE 删,正常无独立删除路径;若未来加 scene 删除端点,需考虑对已 link scene_mode 项目的影响。本版不涉及。
- ego_pose / 插值 / 批量 propagate / scene 级锁 **不在本版**(v0.15.x)。

## 6. 验证策略

- **后端单测**:
  - `test_batch_split_by_scene`:多 scene → 一 scene 一 batch、batch 内帧序升序、`sequence_order==frame_index`;无 scene task 兜底。
  - `test_dataset_link_kind_match`:4 象限矩阵(data_type 同/异 × has_scenes 同/异)断言 200/422;含「scene 项目 + 非 scene 数据集 → 422」。
  - `test_project_scene_mode`:scene_mode 建项目联动 `prefer_same_scene_continuation=true`;有 task 后 PATCH scene_mode → 422。
  - `test_datasets_list_has_scenes`:`?has_scenes=true/false` EXISTS 过滤正确。
- **前端单测**:`Step5Datasets` 按 (data_type, has_scenes) 过滤、空态。
- **真实数据**(复用本机 `~/data/nuscenes-mini` + `DS-NU-*`):
  1. 建 scene_mode lidar 项目 → Step5 picker **只见** `DS-NU-nu-scene-0061` / `DS-NU-nu-mini-multi`(均 has_scenes),不见普通 lidar/image 数据集。
  2. link `DS-NU-nu-mini-multi` → `by_scene` 分包得 3 batch,每 batch 帧连续。
  3. 同一 batch 内 `Shift+→` 跨帧 propagate 不再撞可见性墙(scene 不跨 owner)。
  4. 故意 curl link 一个 `has_scenes=false` 的数据集到 scene 项目 → 422。
- **回归红线**:`random`/`metadata`/`id_range` 分包 byte 级不变;存量 link 不被新校验影响;v0.14.1 scene 调度 / v0.14.3 跨 batch 导航测试不回退。
