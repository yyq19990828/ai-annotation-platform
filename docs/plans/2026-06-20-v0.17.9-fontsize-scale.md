# v0.17.9 · 字号标尺(734 处 text-[Npx] → 命名 scale)

> 隶属 [设计系统第二阶段 Epic](./2026-06-20-v0.17.x-design-system-phase2-epic.md)。机械但面广,严格走截图。

## 1. 目标

把全站 **734 处** `text-[Npx]` 任意字号收敛为一套命名字号 scale。本项目是紧凑 UI,主字号比 Tailwind 默认小一档(默认 `text-xs`=12 / `text-sm`=14),需自定义。

实测分布:`text-[11px]`×290 · `text-[13px]`×216 · `text-[10px]`×61 · `text-[11.5px]`×56 · `text-[12.5px]`×47 · `text-[10.5px]`×37 · `text-[13.5px]`×15 · 其余(9/15/22px…)≈10。

## 2. 命名映射(方案 A:沿用 Tailwind 名并覆盖默认值,已定 2026-06-20)

| 命名 token | px | 覆盖现值 | 备注 |
|---|---|---|---|
| `text-2xs` | 10px | 10px(61) | 徽标 / 极小辅助 |
| `text-xs` | 11px | 11px(290) | **最高频**,正文小字 |
| `text-sm` | 13px | 13px(216) | 面板标题 / 正文 |
| (特例) | 15/22px | 15(4)/22(2) | 标题,数量极少,可直接命名或列白名单 |

- **半像素值归并**(11.5/12.5/10.5/13.5,共 ~155 处):各归最近命名档,**逐档过截图**确认无可见位移;确有差异者列白名单保留任意值,不强并。
- **命名方案已定 = A**:复用 Tailwind 类名 `text-2xs/xs/sm` 并在 `@theme inline` 覆盖其默认值,降低认知成本、让全站(含 shadcn 组件)统一收紧到紧凑档。**代价**:`text-xs/sm` 不再是 Tailwind 公认的 12/14px,vendored shadcn 组件会一并跟随(见 §4 验收)。

## 3. 落地步骤

1. **定义 scale**:`shadcn.css` `@theme inline` 加 `--text-2xs/xs/sm`(= 上表 px),覆盖 Tailwind 默认 xs/sm。
2. **codemod**:`text-[11px]`→`text-xs`、`text-[13px]`→`text-sm`、`text-[10px]`→`text-2xs`;半像素按 §2 决策替换。分批跑,每批截图。
3. **门禁**:`check-tw-tokens.mjs` 加规则「禁 `text-[*px]`(白名单除外)」,防回潮(先 warning 一版)。

## 4. 验收

- `grep -rE "text-\[[0-9.]+px\]" apps/web/src` 收敛到白名单内极少数。
- 全站文字密度 / 行高 **亮暗双主题**截图与基线一致(等价替换)。
- **shadcn vendored 组件回归**(选 A 的连带面):`components/shadcn/ui/` 内用 `text-sm/xs` 的组件(按钮 / 输入 / 菜单 / 对话框等)字号随之收紧一档,逐一截图确认无破版。
- `pnpm lint && pnpm typecheck && pnpm test` 全绿。
- 完成后:Epic §2 表本行置 ✅;本 plan 补 `## Outcome`。

## Outcome

- 在 `shadcn.css` 定义紧凑字号 scale:`text-2xs=10px`、`text-xs=11px`、`text-sm=13px`,并补少量命名档 `text-3xs/micro/ui/md/stat/control-xl` 覆盖原有低频整数字号。
- 全量替换 `apps/web/src` 内 `text-[Npx]`;半像素档按计划归入最近命名档,无剩余 `text-[Npx]`。
- `check-tw-tokens.mjs` 新增任意字号 warning,提示新增调用点改用命名字号 token。
