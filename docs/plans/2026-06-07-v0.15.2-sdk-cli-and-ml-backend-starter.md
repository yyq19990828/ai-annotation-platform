# v0.15.2 · Python SDK / CLI / TUI + ML Backend Starter(降级为教程)

> 规划日期:2026-06-07 · 细化:2026-06-11 · 范围:把平台已有 OpenAPI、API key、ML Backend 协议产品化为外部集成入口。此计划承接开源平台对标第 3 点,顺延到 0.15,不挤占 0.14 的产品面 patch 线。
>
> 定位:先覆盖稳定工作流,不要一次性包全 API。SDK 是客户集成物料,不是内部前端 codegen 的替代品。
>
> 2026-06-11 细化要点:① ML Backend starter 模板判定为时过早,降级为"starter 教程 + 现有示例打磨";② 新增 TUI 面板(Textual),作为 SDK 的 extras;③ CLI 选型 Typer + Rich。

## 1. 背景

本平台已有:

- FastAPI OpenAPI。
- API key service。
- 异步 jobs。
- 数据集上传 / 导入。
- 预测导入 / 导出。
- ML Backend `/health` / `/setup` / `/predict`。

缺的是:

- 外部用户可直接安装的 Python SDK。
- CLI cookbook。
- ML Backend starter 模板。
- 版本兼容策略。

Label Studio 的 `label-studio-sdk` 和 `label-studio-ml-backend` 是强产品资产。本平台应做轻量版,但保留自身协议边界。

## 2. SDK 首版范围

包名暂定:

```text
ai-annotation-sdk
```

核心对象:

```python
from ai_annotation import Client

client = Client(base_url="...", api_key="...")
```

覆盖 8 个稳定工作流:

1. `projects.list/create/get`
2. `datasets.create/upload_files/upload_zip/link_project`
3. `tasks.list/get/next`
4. `annotations.list/create/update/delete`
5. `predictions.import_file`
6. `jobs.list/get/wait`
7. `exports.create/wait/download`
8. `api_keys.list/create/revoke`(可选,admin only)

不覆盖:

- 所有 admin 页面 API。
- 所有 dashboard/analytics API。
- 内部 workbench patch 细节。

## 3. CLI 首版范围

技术选型:**Typer + Rich**。

- Typer:类型驱动的命令定义,与 SDK 的 pydantic 模型天然衔接;原生集成 rich(自动美化 `--help` 与 traceback)。
- Rich:表格(projects/datasets list)、进度条(upload / jobs wait / export download)、spinner、语法高亮的 JSON 输出。
- 备选 Click + rich-click 不采用:Typer 即是 Click 的上层,无需两套。
- **可脚本化约束**:所有 list/get 类命令提供 `--json`,该模式下输出裸 JSON、无 rich 装饰;rich 在非 TTY(管道)下自动降级,但 `--json` 是显式契约,CI/脚本只依赖它。

命令:

```bash
aap login --url ... --api-key ...
aap projects list
aap projects create --name ... --type image|video|lidar
aap datasets create --name ...
aap datasets upload <dataset-id> ./data --zip
aap datasets link <dataset-id> <project-id>
aap predictions import <project-id> result.json --format aap_json
aap jobs wait <job-id>
aap export project <project-id> --target aap_json --out out.zip
```

配置:

- `~/.config/ai-annotation/config.toml`
- 支持 env: `AAP_BASE_URL`, `AAP_API_KEY`

## 4. TUI 面板(2026-06-11 新增)

### 4.1 选型调研结论

| 库 | 结论 | 理由 |
|---|---|---|
| **Textual** | ✅ 主选 | Python TUI 事实标准;Rich 同作者同渲染层(与 CLI 共享生态);CSS 式布局 + 现成 widget(DataTable / Tree / TabbedContent / ProgressBar / Log);自带 Pilot 测试框架;可 `textual serve` 跑在浏览器 |
| Trogon | ⚪ 不依赖 | 2 行代码把 Typer CLI 自动转成表单式 TUI,但 ~1 年未发版,且只是"填参数执行",不是面板;可作为零成本试验,不进正式依赖 |
| prompt_toolkit | ❌ | 强在 REPL/行编辑(IPython、pgcli 形态),不适合 dashboard |
| urwid | ❌ | 老牌但 API 陈旧,布局/性能弱于 Textual |
| pyTermTk / asciimatics / blessed | ❌ | 小众,widget 生态不足 |

**已知风险**:Textualize 公司已于 2026-02 解散,Textual 转为社区维护(作者继续参与),迭代速度下降。评估:项目体量大、API 已稳定、无可替代竞品,接受该风险;TUI 只是 SDK 的 extras,不绑死平台核心。

### 4.2 MVP 范围

入口:`aap tui`(随 `[tui]` extra 安装)。

面板聚焦"长时任务监控"这一 TUI 最有价值的场景:

- 项目 / 数据集列表(DataTable,选中查看详情)。
- **jobs 实时监控**:轮询 `jobs.list`,进度条 + 状态着色,完成时高亮。
- 导出任务跟踪:export 创建 → wait → 提示下载路径。
- 上传进度(datasets upload)。

不做:

- 标注内容预览 / 图片渲染。
- 任何写操作以外的 admin 功能(API key 管理等)。
- 自定义主题/配置系统。

### 4.3 架构约束

- TUI 是 SDK Client 的纯消费方:只调 SDK 公开 wrapper,不直接碰 generated client / HTTP。
- 依赖隔离:`pip install ai-annotation-sdk[tui]`;核心 SDK 保持轻依赖(httpx + pydantic),不被 textual 拖重。
- 测试用 Textual 自带 Pilot(headless 驱动 + snapshot)。

## 5. ML Backend Starter → 降级为 starter 教程(2026-06-11 修订)

**判定:独立模板目录为时过早,本版不建。** 依据:

- 协议仍在快速收敛期:v0.14.12–0.14.15 三周内 4 个版本(多模型目录、PoolStatus、default_variants、字段统一),`ml-backend-protocol.md` 近 20 天 9 次更新。模板会成为又一个追协议的维护点,且最容易被遗忘。
- 生产 backend 只有 3 个(yolo / sam3 / grounded-sam2),全部自研自维护,尚无外部接入需求验证模板的真实形态。
- "starter"角色已被现有资产覆盖:`docs-site/dev/examples/echo-ml-backend/`(63 行最小骨架)、`mock-v2-backend/`(191 行 v2 协议形态)、共享协议库 `apps/_shared/protocol_v2/`(367 行,三个生产 backend 均已依赖)。

本版改做两件事:

1. **starter 教程**:`dev/ml-backend/starter.md` 写成"从 echo 示例出发接入一个真实模型"的 tutorial,指向现有 echo/mock-v2 示例 + `aap_protocol_v2`,并把两个示例升级到最新协议版本、纳入 contract test 保活(防止示例烂掉)。
2. **样板下沉共享库(内部受益)**:三个生产 backend 各自重复的 presigned URL 下载、observability 采样(合计 ~525 行重复)择机沉淀进 `aap_protocol_v2`,这同时为未来真模板打地基。

**重启模板的触发条件**(满足其一再立项):

- 协议连续 2 个 minor 版本无 breaking change;或
- 出现第一个外部团队接入 ML Backend 的真实需求。

不做(同原计划):训练框架、模型下载器、GPU 调度。

## 7. 生成与打包策略

生成:

- 使用 OpenAPI 生成 typed client 作为底层。
- 手写薄 wrapper 提供稳定工作流。
- 生成层不作为公开 API;公开 API 是 wrapper。

打包(单包 + extras):

```text
ai-annotation-sdk         # 核心:httpx + pydantic,保持轻
ai-annotation-sdk[cli]    # + typer + rich,提供 aap 命令
ai-annotation-sdk[tui]    # + textual(隐含 [cli]),提供 aap tui
```

版本策略:

- SDK minor 跟平台 minor。
- breaking change 写 migration guide。
- 首版标记 beta。

## 9. 风险

- **过早锁死 API**:只包稳定 workflow,不要暴露内部接口。
- **OpenAPI 生成层泄漏**:用户不应直接依赖 generated client 的所有方法。
- **认证安全**:CLI config 文件权限提示。
- **Textual 维护风险**:Textualize 公司 2026-02 解散,项目转社区维护;TUI 限定为 extras、不进平台核心,必要时可整体砍掉而不影响 SDK/CLI。
- **TUI 范围蔓延**:面板只做监控类只读场景 + 少量任务触发,不复刻 web 前端。
- ~~Starter 变成框架~~ → 已通过降级为教程消除;新风险是**示例烂掉**,以 contract test 保活兜底。
