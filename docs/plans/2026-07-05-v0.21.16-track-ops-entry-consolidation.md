# v0.21.16 · 轨迹操作入口收敛（术语消歧 + 转框去重 + 多选浮卡收口）

状态：**计划（2026-07-05）**。收口视频工作台**轨迹操作入口割裂**——「拆」一词混指两种完全不同的操作、
转独立框入口 4 处重复且锁判据不一致、多选轨迹时浮卡退化为占位（操作整片换位到 roster）。**纯前端**（视频
工作台交互层），不改后端 / schema / 操作链路语义，无 alembic。

承接视频 UX 三连（v0.21.12/13/14）的延后项「组合/拆分入口收敛 + 多选浮卡退化」。**关键前提纠正**：调研发现
「拆」在 UI 上是**两种语义完全不同的操作**——`split`（转独立单帧框 `video_bbox`）与 `split_track`（在当前帧把
一条轨迹切成前后两条）。任何「收敛为单一拆分入口」若不先消歧，必然把两者错并。故术语消歧是本计划**硬前提**。

## 动机（现状，逐条带证据）

绝对路径前缀：`apps/web/src/pages/Workbench/`。浮卡=`shell/selectionCard/VideoTrackCardContent.tsx`；
右键=`stage/videoContextMenuItems.ts`；roster/批量=`stage/VideoTrackPanel.tsx`；回调注入=`stage/VideoTrackSidebar.tsx`。

### 断点 1 · 「拆」一词混指两种操作（硬前提）
- `onConvertToBboxes({operation:"split"})` = **把轨迹关键帧拆成独立单帧框（`video_bbox`）**。
- `onSplitSelectedTrack → splitSelectedTrack → onComposeTracks({operation:"split_track"})` = **在当前帧把一条轨迹
  切成前后两条轨迹**（不生成 bbox）。
两者 UI 上都叫「拆…」（浮卡按钮「拆轨迹」`VideoTrackCardContent.tsx:398-407` 是 `split_track`；下拉「拆关键帧/拆全帧」
`:305-318`、右键「拆当前帧为独立框」`videoContextMenuItems.ts:159-168`、关键帧表行「拆此关键帧为独立框」`:602-611`
全是 `split`→框）。**代价与效果天差地别，命名却不分**。

### 断点 2 · 转独立框（split→框）4 入口重复 + 锁判据不一致
| 入口 | file:line | scope | frameMode |
|---|---|---|---|
| 右键「拆当前帧为独立框」 | `videoContextMenuItems.ts:159-168` | `frame` | 当前帧 |
| 浮卡更多下拉「拆关键帧」 | `VideoTrackCardContent.tsx:305-311` | `track` | `keyframes` |
| 浮卡更多下拉「拆全帧」 | `:312-318` | `track` | `all_frames` |
| 浮卡关键帧表行「拆此关键帧为独立框」 | `:602-611` | `frame` | `kf.frame_index` |
四者 `operation` 全是 `"split"`、走同一 `onConvertToBboxes` handler，**行为一致，只是多壳**。真正重复的是**右键当前帧
与关键帧表当前行**（`frameIndex === kf.frame_index` 时完全等价）。且 **disabled 判据不一致**：右键受 track 锁约束
（`trackMutationDisabled(readOnly||selectedTrackLocked)`，`videoContextMenuItems.ts:162`），浮卡下拉/表行只看
`readOnly`、不看 `selectedTrackLocked`（`VideoTrackCardContent.tsx:288`）——同族操作在「是否受锁约束」上分歧，是真实行为缺口。

### 断点 3 · 多选轨迹浮卡退化（核心工作量）
`state/useWorkbenchShellModel.tsx:1886-1914`（`selectionCard`）：视频多选态仅当选中项**全是 `video_bbox`** 才给
批量卡（`VideoBoxBatchCardContent`，含聚合为轨迹）；否则 `:1913` **回退为 `SelectionCardPlaceholder`**「已选中 N 个」
纯占位。**结构性根因**：轨迹多选态根本**不在** `s.selectedIds` 里——`selectedTrackIds` 是 `VideoTrackSidebar.tsx:170`
的私有 `useState`（注释 `:1886-1888` 明说轨迹多选走右栏 roster、浮卡保持精简占位）。故浮卡对「多选了两条轨迹」完全
无感知。**表现**：选中 1 条轨迹 → 操作在浮卡（十余项）；选中 2 条 → 浮卡变占位、操作只能去 roster 批量条
（合并/跳连/批删，`VideoTrackPanel.tsx:274-294`）。同一交互对象、选择数从 1→2，操作面板整片换位。

### 断点 4 · 操作×入口矩阵不齐
- **跳连 join / 合并 merge 只在 roster**（`VideoTrackPanel.tsx:274-293`），单选时无从触达（需 2 选），且**无快捷键**。
- **split_track / 复制后续 / 复制粘贴关键帧只在浮卡**（无右键、无快捷键）。
- **删轨迹重复 4 入口**、改类/锁/隐重复到浮卡+右键+roster+快捷键。
- `canJoin`（`VideoTrackSidebar.tsx:195-197`）= 2 条同类且帧区间不重叠；`canMerge`（`:193`）= 2 条同类——跳连是
  合并的更严格子集（多「不重叠」前提）。v0.21.14 已补 disabled 原因 tooltip，本计划补入口归属。

## 定稿决策（拟）

- **硬前提 → 术语消歧。** 强制区分「**拆分轨迹**（split_track，切两条）」与「**转为独立框**（split→bbox）」的文案 +
  图标（如 scissors vs boxes），全站统一。这是任何收敛的前置，否则错并两种操作。
- **断点 2 → 转框入口去重 + 统一锁判据。** 退掉右键「拆当前帧为独立框」（被关键帧表行逐帧精确入口覆盖），保留
  「更多下拉」（粒度 keyframes/all_frames）+ 关键帧表行（逐帧）两个入口。转框族 disabled 统一到
  `readOnly || selectedTrackLocked`（消除右键受锁、下拉/表行不受锁的分歧）。
- **断点 3 → 多选浮卡收口（核心）。** 把轨迹多选态 `selectedTrackIds` 从 `VideoTrackSidebar` 私有 state 提升到
  shell model（或让浮卡消费 sidebar 暴露的多选态），使浮卡在「多选 ≥2 轨迹」时渲染**轨迹批量卡**（合并/跳连/批删/
  批量改类锁隐），与单选浮卡同处，消除「1→2 选操作换位」。roster 批量条保留（两处入口对等，不是二选一）。
- **断点 4 → 跳连/合并进浮卡多选态 + 补引导。** 随断点 3 的选择态统一，跳连/合并在浮卡轨迹批量卡出现（单选之外
  的统一归宿）；disabled 原因 tooltip（v0.21.14 已做）延续。快捷键是否补另议（避免 keymap 冲突）。

- **补跳连/合并快捷键**：需全量查 keymap 冲突（`hotkeys.ts`），另议；本计划先解决入口归属。

## 风险

- **术语消歧不彻底 → 错并两操作**：WS1 未先落就做入口收敛，会把 split_track 和 split→框合成一个入口（灾难）。
  故 WS1 是硬前提、先合入。
- **选择态双写回归（WS3 主风险）**：轨迹多选 `selectedTrackIds` 提升跨 `useWorkbenchShellModel` ↔ `VideoTrackSidebar`
  边界，触及「选择态单一数据源」假设；与 `selectedIds`（`:1841`）联动、roster 高亮、焦点联动（v0.21.11）易回归。
  提升时保证单一 owner、双向订阅无环。
- **浮卡与 roster 双入口一致性**：批量操作现只在 roster，进浮卡后两处必须同一 handler、同一 disabled 判据，避免
  「浮卡能点 roster 不能」的新分歧。
- **右键退项的肌肉记忆**：退掉右键「拆当前帧为独立框」可能有用户习惯依赖；关键帧表行入口需明显可达，必要时保留
  过渡期提示。
