# v0.21.12 · 轨迹画框「吞框」修复 + 粘轨迹态可视化 + 多轨迹跨网格帧续写

状态：**第一部分（吞框修复 + 粘轨迹提示）已实现并提交（WS1–2，commit `1ba4c267`）；第二部分（多轨迹跨网格帧续写，
WS5–8）已实现（2026-07-06 并入本版本）**。以前端为主（视频画布交互层）；WS8 的「续写后自动前进」开关新增一个
`WorkbenchVideoPreferences.trackContinueAutoAdvance` 偏好字段（前后端 schema 各加一个布尔，存 JSON 偏好列、**无 alembic**）。

第一部分修复视频工作台用轨迹工具画框时**「同一帧再画一个框会把上一个框吞掉」**的反直觉交互；第二部分收口一个相邻的
多轨迹摩擦：**在一个网格帧画了 N 条轨迹框，到下一网格帧只有「选中那条」能续写，其余 N-1 条既无实框也无 ghost、必须
回上一帧或右栏重新选中**。两者机制正交（第一部分管**同帧**，第二部分管**跨网格帧**），但同属「轨迹画框手感」主题，故并版。

与 [v0.21.11 审阅流水线](2026-07-05-v0.21.11-review-pipeline-frame-object-cycle.md) 正交、可并行；本计划新建出的轨迹
天然接入 0.21.11 的 `focusObject` 焦点联动与「当前帧对象环」，第二部分的 Tab 循环直接复用其 `frameObjectCycle`。

## 动机（现状：同帧重复画框静默覆盖，带证据）

### 根因链：自动选中 + 同帧 upsert 替换
用轨迹工具（`videoTool === "track"`）画框后覆盖上一个框，是**一个自动选中副作用 + 一个纯函数决策**的组合，四步触发：

1. **画完第一个框 → 自动选中该轨迹**：`create.mutate` 的 `onSuccess` 里 `s.setSelectedId(created.id)`
   （`stages/video/useVideoAnnotationActions.ts:196-210`）。此后 `selectedTrack` 立即非空
   （`stage/VideoKonvaStage.tsx:186-189`，选中的 annotation 恰为 video_track 时非空）。
2. **同帧再画第二个框 → 落入 track 分支**：松手提交时 `resolveDragCommit`
   （`stage/videoKonvaInteraction.ts:83-92`）判定——
   ```ts
   // track 工具且选中轨迹未锁:画框落到该轨迹当前帧关键帧(而非建独立框)。
   if (videoTool === "track" && selectedTrack && !lockedTrackIds.has(selectedTrack.geometry.track_id)) {
     return { type: "track", ann: selectedTrack, geom };   // ← 归属到选中轨迹, 不新建
   }
   ```
   唯一开关就是 `selectedTrack` 是否存在（且未锁）。
3. **派发走 upsertKeyframe**：`videoKonvaInteraction.ts:232-252` 的 `type:"track"` 分支
   `p.onUpdate(action.ann, upsertKeyframe(geom, frameIndex, ...))`。
4. **同帧关键帧被替换**：`upsertKeyframe`（`stage/videoStageGeometry.ts:111-131`）对**同一 `frame_index`**
   先 `filter((kf) => kf.frame_index !== frameIndex)` 删旧、再 push 新 → 第一个框那唯一关键帧被顶掉，
   无论第二个框画在哪都表现为「吞掉/覆盖」。

### 为何是「设计使然」但仍需修
`type:"track"` 分支的意图是**跨帧打点**：画帧 0 的框 → 换到帧 10 再画 → 因 `frame_index` 不同而**新增**关键帧、
形成插值，这是轨迹标注的核心价值。坏点仅在**同一帧**：同帧第二次画框几乎总是「我要标第二个物体」，而不是
「重做这一帧的关键帧」。当前逻辑把这两种意图混为一谈，且**静默**覆盖（无提示、无撤销引导）。

### 唯一的现有出口过于隐蔽
避免覆盖只能：点「新建轨迹」按钮清空选择（`stage/VideoTrackSidebar.tsx:277-280` 的 `startNewTrack` →
`onSelect(null)`），或换到别的帧再画。按钮 title 已写明机制「清除当前轨迹选择，下一次画框会新建轨迹」
（`stage/VideoTrackPanel.tsx`），但这要求用户预先理解「粘轨迹」模型——反直觉正在于此。

## 定稿决策（拟）

- **断点核心 → 同帧判定：选中轨迹在当前帧已有关键帧时，第二次画框判为「新建轨迹」而非覆盖。**
  在 `resolveDragCommit` 的 track 分支加一个条件：`selectedTrack` 在 `frameIndex` **已有关键帧** →
  跳过 `type:"track"`，落到下面的 `type:"draw"` 新建分支（`kind:"video_track_bbox"`）。语义收敛为——
  **跨帧画框延展当前轨迹（保留插值价值）；同帧画框新建物体（匹配「一个框 = 一个对象」的反射）。**
- **可选增强 → IoU 消歧「修正 vs 新建」。** 若担心「用户就是想重画修正同帧的框」被误判成新建：当新框与同帧
  旧关键帧框 **IoU ≥ 阈值（如 0.5）→ 判为替换（修正）**，位置明显不同 → 新建。默认可先不做（修正本就该
  拖拽已有框，走 `beginMove` 而非 `draw`），留作二期开关。
- **配套 → 「粘轨迹」态可视化，让延展/覆盖不再是惊吓。** 轨迹工具激活且有选中轨迹时，画布内（或轨迹分组头）
  常驻一条状态提示：`正在延展轨迹 #3 car · 换帧画框继续 / 同帧画框新建 / Esc 结束`。把隐式的「粘轨迹」模式
  升级为**显式可见**——这是本轮体感提升的关键，不只修 bug 还补心智模型。

## 定稿架构

```
videoKonvaInteraction.ts · resolveDragCommit (改判定)
  track 分支前置守卫:
    hasKeyframeAtFrame = selectedTrack.geometry.keyframes.some(kf => kf.frame_index === frameIndex)
    if (videoTool==="track" && selectedTrack && !locked && !hasKeyframeAtFrame)
        → { type:"track" }        // 该帧尚无关键帧 → 延展 (新增关键帧)
    else if (videoTool==="track" && selectedTrack && !locked && hasKeyframeAtFrame)
        → (可选) IoU≥阈值 ? { type:"track" } /*修正*/ : 落 draw /*新建*/
    else 维持原有 draw / bbox 分支

新建出的轨迹 → (0.21.11) focusObject 居中 + 进当前帧对象环

粘轨迹态提示 (新增薄组件/画布 overlay 文案)
  可见条件: videoTool==="track" && selectedTrack
  文案随 selectedTrack 当前帧是否已有关键帧切「换帧继续 / 同帧新建」措辞
```

## 实现分阶段

- **WS1 · 同帧判定（核心）**：`resolveDragCommit`（`videoKonvaInteraction.ts:83-92`）track 分支加
  `hasKeyframeAtFrame` 守卫；命中已有关键帧则落到 `type:"draw"` 新建。补单测覆盖「同帧第二画 → 新轨迹」
  「异帧第二画 → 延展关键帧」「锁定轨迹不受影响」。
- **WS2 · 粘轨迹态可视化**：轨迹工具 + 选中轨迹时渲染常驻提示（画布 overlay 或复用轨迹分组头区域）；
  文案按「当前帧是否已有该轨迹关键帧」切换；`Esc` 已有清选路径则复用，否则接 `startNewTrack`。
- **WS3 ·（可选）IoU 消歧**：新框 vs 同帧旧关键帧框算 IoU，≥阈值判修正（覆盖）、否则新建；阈值走常量，
  留配置位。默认关闭，验证 WS1 手感后再定是否开。
- **WS4 · 验证 + 版本**：E2E ① 轨迹工具同帧连画两框 → 两条独立轨迹、第一框不再消失；② 帧 0 画框、换帧 10
  再画 → 仍是同一轨迹两关键帧（插值不回归）；③ 锁定轨迹画框行为不变；④「新建轨迹」按钮与换帧旧路径不回归；
  ⑤ 粘轨迹提示在工具/选中态切换时正确显隐。CHANGELOG（Fixed + Changed）+ 版本 bump。

## 不在范围

- **改 `upsertKeyframe` 本身语义**：它在粘贴关键帧、复制到当前帧、AI 传播落帧等多条路径被复用，同帧替换在
  那些场景是正确的。本计划只在**画框提交决策处**分流，不动 `upsertKeyframe`。
- **legacy `video_bbox`（单帧框）路径**：单帧框工具不走 track 分支，行为不变。
- **0.21.11 的焦点联动 / 对象环本体**：本计划仅「衔接」（新建轨迹交给 focusObject），不实现该基建。

## 风险

- **「修正同帧框」被误判为新建**：少数用户习惯用「重画一个框」来修正同帧关键帧。缓解：修正的正道是拖拽已有框
  （move/resize handle，不触 draw）；如反馈强烈再开 WS3 的 IoU 消歧。文档/提示需明确「改框请拖，别重画」。
- **判定分支的隐式副作用**：`beginDraw`（`videoKonvaInteraction.ts:166-176`）在按下时也会按 `videoTool/selectedTrack`
  决定是否 `onSelect(null)`，与提交判定须口径一致，避免「按下清了选择、松手又当延展」的错配。
- **粘轨迹提示的视觉噪音**：常驻提示别抢画布注意力；用低对比、贴边、随状态自动隐藏（无选中轨迹即不显示）。
- **IoU 阈值可复现性**：若启用 WS3，阈值与 IoU 计算须确定性（同输入同判定），否则「有时覆盖有时新建」更困惑。

# 第二部分 · 多轨迹跨网格帧续写（WS5–8，并入本版本）

## 动机（现状：新网格帧上只有选中那条能续写）

在一个网格帧画了 N 条轨迹框后，切到下一网格帧：

1. **其余 N-1 条在新帧根本不渲染**：一条轨迹若只有「上一帧」那一个关键帧、当前帧还没有，`resolveTrackAtFrame`
   （`videoStageGeometry.ts`）需要**前+后两个**可见关键帧才能插值出框；只有前没有后 → 返回 `null` → 该轨迹在新帧
   无实框（`videoFrameViews.ts:136-140`）。
2. **能「画进去续写」的参考 ghost 只给选中那一条**：`videoFrameViews.ts:173-196` 仅为 `selectedId` 命中且未锁的
   轨迹生成 ghost。
3. 于是新帧上：选中那条有 ghost 可画 → 续写；其余 N-1 条既无实框也无 ghost = 视觉上消失，必须先选中它
   （回上一帧点其框、或右栏点选）才能把 ghost 拉回来。

**本质：ghost 被绑死在「单一选中」上 → 多轨迹续写被迫串行 + 反复切选择。**

## 定稿设计（保留「选中→画」，只补「可见 + 够得着」）

不做空间自动归属（画框自动归到最近轨迹），沿用 v0.21.12 WS1 的「画框只作用于当前选中轨迹」——只补两个缺口：

- **集合 S** = 「**恰好上一网格帧**（`gridPrev(current, step)`，见 `videoSamplingGrid.ts`）有关键帧 · 未锁定 ·
  当前帧还没画」的轨迹。严格口径、天然限流（用户确认接受「跳一格的轨迹不显示」这一取舍）。
- **多 ghost 可见**：S 全体在当前帧画 ghost（选中那条高亮、其余更淡以示「仅参考、未选中」），位置沿用
  `trackReferenceAtFrame`（默认 `off`=最近关键帧原位，不引入运动预测）。
- **Tab 并入「轨迹」类**：`buildFrameCategories`（`frameObjectCycle.ts`）的 `track` 列 = 当前帧已解析框 + S 的
  ghost，一起空间排序循环；选中 S 里的轨迹即可续，不用回上一帧或右栏。
- **点击/拖 ghost 选中**：pickables 从「entries + 单 ghost」放开成「entries + S 全体 ghost」。白捡好处——拖选中
  轨迹的 ghost 本来就走 `move → upsertKeyframe` 在当前帧落关键帧，放开可命中后「抓任意待续 ghost 挪到物体新位
  → 该轨迹直接续写」几乎零成本，与 Tab+画框两条路并存。
- **续写后自动前进**：**新增视频设置开关，默认关**；开启时，续写完一条（它离开 S）自动选中 S 里的下一条，连画不
  用手动 Tab（类似 0.21.11「采纳后自动前进」）。

## 定稿架构

```
videoFrameViews.ts · deriveVideoFrameViews (ghost 单数 → 列表)
  入参新增 samplingStep / prevGridFrame
  S = tracks.filter(有 kf@prevGridFrame && !locked && 无 kf@current)
  carryOverGhosts = S.map(trackReferenceAtFrame) ; 选中那条标 selected

VideoKonvaTracksLayer / OverlayLayer (多 ghost 渲染)
  选中 ghost = 现有高亮样式 + 标签; 其余 = 更淡虚框 + 精简标签(仅 #N)

videoKonvaInteraction.ts (pickables 放开)
  pickables = entries + carryOverGhosts   // 原为 entries + [ghost]
  点击 ghost → onSelect(track.id) ; 拖 ghost → move → upsertKeyframe(承 WS1 语义)

frameObjectCycle 消费方 (VideoKonvaStage.frameCategories)
  track 类 refs = 当前帧 track entries + carryOverGhosts   // Tab 一起转

视频设置 (workbenchSettingsFields + preferences)
  新增 continueAutoAdvance:boolean 默认 false
  续写提交后若开 → 选中 S 的下一条
```

## 实现分阶段

- **WS5 · 集合 S + 多 ghost 派生**：`deriveVideoFrameViews` 的 `ghost` 单数改列表（新增 `carryOverGhosts` 或
  统一为 `ghosts[]`）；入参加 `samplingStep`/上一网格帧；算 S；选中态标记。补单测（恰好上一网格帧命中/跳格不命中/
  锁定排除/当前帧已画排除）。
- **WS6 · Konva 多 ghost 渲染**：轨迹层/覆盖层从「单 ghost」支持「多 ghost + 标签」，选中高亮、其余淡化可辨。
- **WS7 · 交互放开 + Tab**：pickables 纳入 S ghost，点击→选中、拖→续写；`frameCategories` 的 track 类扩充 S；
  验证 Tab/Shift+Tab 在「已画 + 待续」轨迹间稳定可预期循环。
- **WS8 · 自动前进开关 + 验证**：新增视频 preference（默认关）+ 续写后前进逻辑；E2E ① 新网格帧 N 条待续全部
  可见 ghost；② Tab 循环到某条 → 画框/拖 ghost 续写、其余不受影响；③ 点击 ghost 选中；④ 开关开启后续写自动前进
  下一条、关闭则维持手动；⑤ 锁定/跳格轨迹不进 S。CHANGELOG 补 `### Added`。

## 第二部分不在范围

- **空间自动归属**（画框自动归到最近轨迹）：明确保留「选中→画」模型，不做自动归属（避免多 ghost 聚集时的判定歧义）。
- **运动预测 ghost 位**：ghost 位置沿用现状 `off`=最近关键帧原位；linear/kalman 仍是独立实验开关，不在本次默认路径。
- **宽口径「所有未完成轨迹」**：采严格「恰好上一网格帧」，跳格轨迹需回该帧或右栏找（用户确认取舍）。

## 第二部分风险

- **多 ghost 视觉噪音**：选中/非选中 ghost 必须一眼可辨，否则用户误以为「画框会落到所有 ghost」；用高亮 vs 淡化 +
  标签繁简区分。
- **严格口径的盲区**：跳一格没画的轨迹不进 S、新帧上不可见——已知取舍，需在提示/文档说明「只带上一网格帧的轨迹」。
- **Tab 混排**：轨迹类里「当前帧已画」与「待续 ghost」混在一起循环，排序须稳定（复用 `spatialSort`），否则「下一个」
  不可预期。
- **拖 ghost vs 画框的手势边界**：`beginDraw`/`beginMove` 在 pointerdown 按命中分流，S ghost 纳入命中后，须确保
  「按在 ghost 上」走 move（续写选中）而非误判 draw，与 WS1 的提交判定口径一致。
