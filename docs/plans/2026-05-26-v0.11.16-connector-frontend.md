# v0.11.16 · 连接器收口单入口（owner-scope + 数据集页 + 导入向导第三模式）

> [epic 索引](2026-05-26-v0.11.14-16-dataset-import-connectors-epic.md) · 切片 3/3 · 依赖：[v0.11.15](2026-05-26-v0.11.15-adapter-and-import-job.md)
>
> 本切片把 v0.11.14/15 的后端能力接到 UI，功能正式对用户可见。**含一处后端语义调整**（project-scope → owner-scope），因为单入口设计移除了项目上下文。

## 设计决策（本切片的前提）

1. **唯一入口 = 数据集页**。连接器的管理与使用都从 `/datasets` 进；**不在项目创建 / 项目设置里出现任何连接器入口**。
   - 理由：数据集是**全局库**（`Dataset` 无 `project_id`，经 `ProjectDataset` 挂项目），且导入是"**一次性拷入 `minio-datasets`**"而非实时引用。把"从外部连接器导入"放进项目语境会误导用户以为**项目数据源直连外部 / 数据集是外部存储的实时镜像**，与实际不符。收到全局数据集页可从产品语义上避免这个误解。
2. **连接器 scope：project → owner**。既然入口在无项目上下文的全局页，项目级连接器无法自然确定归属项目。改为按**创建者**归属：
   - 超管建 `global`（全平台可见可选）。
   - 其他有权用户（项目管理员）建 `owner`（仅自己可见、跨自己能导入的数据集复用）。
3. **主机白名单留在系统设置**（超管）。它是全局安全控制、不是"数据源入口"，不会引发上面的误解；放数据集页反而不伦不类。

> **数据迁移：最小。** v0.11.16 之前没有任何创建 project-scope 连接器的 UI，线上理论上不存在 project-scope 数据；但 DB 已有 `ck_storage_connections_scope` 约束，因此本版仍需一条极小 Alembic 迁移：把约束从 `global|project` 改为 `global|owner`，并把历史 `project` 行兼容更新为 `owner`。

## 后端改动（owner-scope 落地）

> 收敛点共三处，得益于 v0.11.15 已把可见性校验集中到 `assert_connection_usable(user, conn)`（见下方"对 v0.11.15 的要求"）。

- **模型** `db/models/storage_connection.py`：`StorageConnectionScope` 枚举 `global` / `owner`（替掉 `project`）。`project_id` 字段废弃（保留列与 FK，停止写入）。
- **service** `services/storage_connection.py`：
  - `create()`：owner-scope 不再要求 `project_id`；落 `created_by`。
  - `list_visible()`：`global` ∪ `created_by == self`（去掉 project_id 过滤分支）。
  - 可见性单点 `assert_connection_usable(user, conn)`：`global` 或 `conn.created_by == user.id` 或 super_admin。
- **API** `api/v1/storage_connections.py`：create 入参去 `project_id` 必填校验；`_assert_can_admin` / `_assert_can_view` 改走 `created_by`。
- **schema**：`StorageConnectionCreate` 去 `project_id`；`StorageScope` 改 `global|owner`。
- **测试**：改写 v0.11.14 的 `test_project_scope_requires_project_id` → owner-scope 不需 project_id 即可创建；补 `list_visible` 只见自己 + global、他人 owner 连接器不可见/不可用。
- **CHANGELOG**：本版 `### Changed` 记一条"连接器 project-scope 收敛为 owner-scope"。

## 前端改动

### 1. API + hooks
- 新建 `apps/web/src/api/storageConnections.ts`：list/create/get/test/patch/delete + `importFromConnection(datasetId, body)`。
- 新建 `apps/web/src/hooks/useStorageConnections.ts`：对应 query/mutation，create/delete 后失效列表缓存。
- `useDatasets.ts` 加 `useImportFromConnection()`（起 job，返回 job_id）。
- 进度轮询：复用现有 async_jobs hook；若无则新建 `useAsyncJob(jobId)`（轮询 `GET /async-jobs/{id}`，completed/failed/cancelled 停轮询）。

### 2. 连接器管理（**仅数据集页**，不进项目设置）
- 新建 `apps/web/src/components/connections/`：
  - `ConnectionList` / `ConnectionForm`（kind 切 s3↔sftp 表单字段；密钥字段 write-only，编辑时占位提示"留空不改"）。
  - `ConnectionTestButton`（调 test，展示 ok / 错误原因 / 样例条目数）。
- 入口归属：
  - **数据集页 `/datasets`**：加"存储连接器"管理区（或在导入向导内联"管理连接器"）。按可见性展示 `global`（只读，超管维护）+ 自己的 `owner` 连接器（可建 / 改 / 删 / 测）。
  - **超管**：系统设置页只保留"**主机白名单**"一块（连接器本身也能在数据集页管，白名单是安全控制留系统设置）。
  - **不新增**项目创建 / 项目设置页的连接器入口。

### 3. 导入向导第三模式
- `ImportDatasetWizard.tsx` Step2 加第三 tab/模式"从连接器导入"：
  - 选连接器（下拉，按可见性过滤）→ 填 `source_path` + `recursive` + 可选 `include_globs` → 提交起 job。
  - 可内联"+ 新建连接器"，建完即可选用（少跳转）。
  - Step3 改为**进度态**：轮询 job，展示 progress_pct + added/skipped/errors，完成后给"查看数据集"。
  - 文件上传 / ZIP 两种旧模式行为完全不变。

### 4. 文案 / i18n
- 按现有 i18n 机制补连接器 / 白名单 / 导入进度相关文案。

- `pnpm --filter web typecheck` + `pnpm --filter web lint`（含 `lint:css-tokens`）。
- dark mode 走查（B-32/36/38/39 教训：连接器表单、白名单表、进度条所有新 CSS）。
- 端到端手测（chrome devtools MCP 辅助看 API/console）：
  - 超管配白名单 → 在数据集页建 global S3 连接器 → test ok。
  - 项目管理员在数据集页建 owner SFTP 连接器（白名单外被拒并有清晰提示）；登出换另一项目管理员，**看不到**前者的 owner 连接器。
  - **项目设置页 / 项目创建流程里没有任何连接器入口**（回归确认）。
  - 导入向导第三模式 → 选连接器 + 路径 → 起 job → Step3 进度推进 → 完成后数据集出现新条目 + 缩略图。

  - 旧两种导入模式回归无变化。

## 回退

新增组件 + 新模式入口，旧路径不动。回退 = 移除第三模式入口 + 数据集页连接器管理入口（API 文件可留）。必要时第三模式挂 feature flag 灰度。owner-scope 后端改动若需回退，恢复 `list_visible` / scope 枚举即可（无数据依赖）。

## 可见性校验收敛（本版自理）

> v0.11.15 即将收尾、不再改动，故本版**不依赖**它预先收敛，由 v0.11.16 自己兜底。

- 落 owner-scope 时，先把 import 入口（`POST /datasets/{id}/import-from-connection`）及各处"连接器可见性 / 可用性校验"**收敛到单个 helper `assert_connection_usable(user, conn)`**，再切 project→owner。若 v0.11.15 已把判断散在 import 路由/service 多处，本版一并归拢——改动只落在 **helper + `list_visible` + create 校验**三个点，不波及 adapter / job / ingest。
