## 1. 本版目的

当前无 GPU fallback 已满足 correctness，但没有复用已完成的 packed 数据面：

```text
无 navigator.gpu / gate off / adapter null / initializing / budget failure
  → decode base RLE 为 dense Uint8 alpha
  → applyMaskMorphology()
  → dense before/after diff
  → history patches
```

而 WebGPU 成功路径已经具备：

```text
immutable packed base cache + packed dirty overrides
  → packed source words
  → square dilate
  → core XOR words
  → dense word-scatter history patches
```

v0.23.21 的第一目标是让**没有 GPU 的客户端也拥有高质量、精确、有界的 CPU 路径**。本版先
A/B 一个 Worker 内 `Uint32Array` packed square-dilate backend，并让 GPU runtime failure
可直接复用已准备好的 packed source，不再无条件回头 materialize dense alpha。

第二目标是清理 v0.23.16–v0.23.19 封版后仍留在 production surface 的漂移：

- 当前 gate 已是 `VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU !== "false"`，不再是历史计划中的
  default-off；
- production Worker protocol 仍暴露 `benchmarkXorPatchStrategy=dense-per-bit`，但
  v0.23.19 已固定 dense word-scatter；
- `2112` 单边与 64MiB 组合仍是 route 代理，provider 已能计算更精确的 prospective bytes；
- runtime error 只压成一个 `gpu-runtime-failed`，不利于判断失败发生在 prepare、write、
  encode、submit、map 还是 patch；
- WebGPU unavailable/lost 后缺少明确的 session cooldown/circuit breaker 与只重试一次合同；
- compute snapshot 还没有进入 workbench perf/bug-report 证据。

## 2. 本版成功定义

1. `square dilate` 的 packed CPU candidate 与现有 dense CPU、WebGPU、canonical oracle 在任意
   合法 ROI、image edge、非 32 对齐 origin/width、radius `1..31` 上 bit-exact。
2. candidate 通过门后，gate off、无 `navigator.gpu`、adapter null、initializing、预算不足、
   device lost 与 GPU runtime failure 的 eligible `square dilate` 都优先使用 packed CPU；
   disk/其他 operation 继续使用现有 dense CPU。
3. GPU 已成功准备 packed source 后发生 write/encode/submit/map failure，同请求直接使用该 source
   跑 packed CPU，不重新 decode RLE 为 dense alpha。
4. candidate 未通过性能/资源门时完整删除 packed CPU production route，只保留 oracle/benchmark
   证据；correctness fallback 继续是现有 dense CPU，不伪造收益。
5. 2048² 与 4K 的 packed CPU operation total p95 相对当前 dense CPU 的两轮改善率算术平均至少 35%，
   且每轮改善都不低于 25%；或在内存主门中 transient source/diff bytes 至少减少 70%、
   每轮 p95 都不恶化超过 5%。
6. packed CPU fallback 的 Long Task 为 0，Worker/session/cache/scratch 在长会话 plateau，dispose
   后归零。
7. WebGPU route 不再依赖 `2112` 魔数；统一用 operation/limits/prospective byte admission，
   仍保留 4MP crossover，除非同版本 A/B 明确修改。
8. WebGPU provider 在第一次 adapter/init/device/runtime 失败后进入 cooldown；cooldown 到期后的
   首个 eligible foreground request 只允许一次受控重试，连续第二次失败后当前 page lifecycle
   固定 CPU。新 Mask session 不打破 cooldown/circuit。
9. 生产协议不再接受 `dense-per-bit` selector；per-bit reference 移到 test/benchmark helper。
10. bug-report/perf snapshot 可得到最近有界 route、fallback reason/stage、分段延迟与应用逻辑字节，
    不采集 adapter name、device id 或高熵硬件信息。

## 5. Packed CPU 算法合同

### 5.1 输入输出

输入复用 `preparePackedRasterMaskMorphologyRoi()`：

```text
sourceWords: Uint32Array
sourceWordsPerRow
inputWidth/inputHeight
coreOffsetX/coreOffsetY
coreWidth/coreHeight
radius
```

输出与 WebGPU 完全同构：

```text
xorWords: Uint32Array
xorWordsPerRow = ceil(coreWidth / 32)
```

随后只能进入现有 dense word-scatter builder，不建立第二套 history patch 逻辑。

### 5.2 语义

- bit `1` 表示 foreground；
- image 外部永远按 `0`；
- square dilation 半径为闭区间 `[-r, +r]`；
- core 外的 halo 只读不写；
- source origin 与 core origin 可任意非 32 对齐；
- 每行尾部无效 bit 必须在 source/intermediate/output 清零；
- XOR 只比较 morphology after 与 core source center；
- zero change 返回空 patches、null bounds、0 changed pixels。

### 5.3 Candidate

至少比较：

1. **Dense baseline**：当前 separable byte-alpha morphology + dense diff；
2. **Packed direct**：逐输出 word 扫 row/shift，作为简单 correctness candidate；
3. **Packed separable CPU**：水平 word expansion intermediate + 垂直 OR；
4. **Packed cache bypass**：direct-RLE packed prepare，隔离 cache 收益。

不得预设 packed 一定更快。现有 dense square morphology 已是横纵 sliding-window，实现可能在小 radius
更有优势。最终 route 可按 ROI/radius 选择：

```text
small ROI / packed candidate no-win → dense CPU
large eligible square dilate / packed winner → packed CPU
GPU ready + WebGPU winner → WebGPU
GPU failure after packed prepare → packed CPU
```

### 5.4 Scratch 与预算

- CPU intermediate、XOR output、packed source logical bytes 与 retained base cache 全部计账；
- scratch 可 grow-only，但只在 prospective admission 通过后增长；
- budget pressure 下允许 bypass base cache 使用 exact-sized transient；
- packed candidate admission 失败时直接 dense CPU，不能先分配后宣告不足；
- dense fallback 的 alpha/after/diff 峰值也必须进入 metrics，便于 v0.23.24 联合 ledger。

当前实现把 WebGPU gate 与 `computeBudgetBytes` 混为一项：gate off 会把预算置零，低内存档位也可能
返回零。v0.23.21 必须拆成：

```text
cpuComputeBudgetBytes  = CPU packed/dense scratch、transient 与 retained cache 的准入上限
webGpuPolicy           = build gate + secure context + navigator/adapter/device 状态
gpuBufferBudgetBytes   = WebGPU source/XOR/readback buffer 的准入上限
```

- gate off、无 `navigator.gpu`、adapter null 或 GPU buffer 不可接纳不得把
  `cpuComputeBudgetBytes` 置零；
- 低内存档位使用更小但明确的 CPU hard budget，分别计算 packed 与 dense prospective bytes；
- GPU 不可接纳但 packed CPU 可接纳时走 packed CPU；
- packed 不可接纳但 dense 可接纳时走 dense；两者都不可接纳时返回稳定的 budget rejection，
  不允许 dense 路径绕过计账继续分配；
- M0 必须覆盖 gate off、no-GPU、`deviceMemory <= 2GB` 和“GPU budget 不足但 CPU budget 足够”。

## 6. 路由与熔断

### 6.1 Route 事实

route 只使用：

- operation/kernel/radius；
- input/core dimensions；
- WebGPU gate 与 secure context；
- adapter/device state；
- WebGPU supported limits；
- 分开的 CPU compute budget、GPU buffer budget 与 prospective bytes；
- provider/Worker-generation cooldown 与 page-lifecycle circuit；
- 已固定的 ROI/radius crossover。

不使用 adapter vendor/name/device id。

### 6.2 Provider 状态

建议状态：

```text
idle → warming → ready
  ├─ unavailable(cooldown)
  ├─ lost(cooldown)
  └─ closed
```

- 首次 eligible 操作触发 warmup，但当前操作立即 CPU，不等待初始化；
- adapter null/init failure 在当前 Worker generation 不重复；
- runtime failure 记录 stage，销毁 device/buffers 并进入 cooldown；
- device lost 同理；
- 新 Mask session 不自动打破 cooldown；
- 第一次失败后，只有 cooldown 到期且出现新的 eligible foreground request 时尝试一次；成功后清零
  consecutive failure count，连续第二次失败后当前 page lifecycle 固定 CPU；
- test/运维显式 reset 只能提前结束第一次失败后的普通 cooldown；不能清除 page-fixed circuit，
  后者只在完整 provider/page lifecycle 重建后恢复；
- `pagehide`/最后 session release/dispose 释放 provider；`visibilitychange` 只在长时间 background 或
  pressure 时释放，不在短暂切 tab 中抖动。

### 6.3 Failure stage

至少区分：

- `adapter-request`
- `device-request`
- `shader-compile`
- `pipeline-create`
- `buffer-create`
- `queue-write`
- `encode`
- `submit`
- `map`
- `readback-validate`
- `patch-build`

对产品 UI 仍映射为稳定低基数 reason；详细 stage 只进入本地诊断/受控 telemetry。

## 7. Production 协议清理

### 7.1 删除 benchmark selector

v0.23.19 winner 已固定 `dense-word-scatter`。本版：

- 从 production `RasterMaskMorphologyRoiRequest` 删除 `benchmarkXorPatchStrategy`；
- Worker production handler 始终调用 word-scatter；
- per-bit oracle 移到 test-only module 或 benchmark script；
- benchmark 若需 A/B，直接导入纯函数/专用 runner，不污染消息协议；
- 删除正常运行永远为 0/固定值的 candidate-specific counters。

### 7.2 口径校准

不得重写历史实测时点，但应在 v0.23.16–v0.23.19 header/ADR 附注：

- 这些版本资格时 gate 为 default-off；
- `6a782418`/ADR-0060 后 build gate 缺省为 true；
- capability、operation、ROI、budget 与 runtime fallback 仍使 WebGPU 成为可选后端；
- Linux 服务端 GPU 与浏览器客户端 WebGPU 无关。

## 11. 性能退出门

正式 runner：

- 2048²、3840×2160；
- radius `1/8/31`；
- dense/sparse/edge fixture；
- cold direct-RLE、warm packed base cache；
- `3 warmup + 10 measured`、两轮；
- CPU-only 普通 Chrome，不依赖强制 Vulkan；
- 与 WebGPU runner 分开报告。

packed candidate 进入 production 至少满足其一：

1. 主门：operation total p95 相对 dense CPU 的两轮改善率算术平均 ≥35%，且每轮改善均 ≥25%；
2. 内存门：transient source/diff bytes 降低 ≥70%，每轮 p95 均不恶化 >5%，且资源 plateau 更低。

同时必须：

- exact patch/undo/redo/save/reload；
- Long Task = 0；
- cache/scratch plateau；
- dispose 后 session/Worker/scratch/GPU owner/buffer = 0；
- 小 ROI p95 不回归 >5%，否则 route 必须保持 dense。

## 12. 回滚

- `VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU=false`：关闭 provider，CPU 路径继续。
- packed CPU 出现问题：route 回现有 dense CPU；不影响 RLE/history/protocol。
- circuit/诊断异常：关闭诊断 consumer，不改变 compute。
- 新 route 不做数据库/API migration。
- rollback 后不得恢复 production benchmark selector。

## Outcome

- **Release commit：**`f7cfeaa0`；实施与 dense 性能基线为 `ab35d73c`。
- **Winner 与 crossover：**production 选择 `packed-separable`，仅用于 input ≥ `4,194,304`
  pixels、`square dilate`、radius `1..31`；其他操作或 packed admission 失败保留 dense CPU。
  direct kernel 只保留为 pure test/benchmark oracle。
- **性能：**2048²/4K、radius `1/8/31` 两轮 12 个 production case 的端到端 p95 相对 dense
  baseline 改善 `80.1%–91.3%`，全部超过 35% 主门；direct → separable kernel 在 radius 8/31
  改善 `88.4%–96.6%`。12/12 patch、save、reload checksum exact。
- **预算：**协议拆为 `cpuComputeBudgetBytes` 与 `gpuBufferBudgetBytes`；低内存默认 CPU
  32 MiB / GPU 0，常规 64/64 MiB，高内存 128/128 MiB。CPU prospective ledger 包含 packed/dense
  transient、水平 intermediate、XOR、patch upper bound、cache 与 scratch。
- **Fallback：**gate off、无 GPU、adapter/init/budget failure 与 GPU runtime failure 都能复用
  packed source；`cpu-fallback` 不再 materialize dense alpha。GPU 成功路径在本机 RTX 3090 强制
  Vulkan 下重跑，2048²/4K p95 为 `16.2/31.7 ms`，单 owner、零 Long Task、dispose 归零。
- **Circuit：**首次失败进入 30 秒 cooldown；到期后由下一次 eligible foreground request 试一次；
  连续第二次失败后当前 page/provider lifecycle `page-fixed`。stage 覆盖 adapter、device、shader、
  pipeline、buffer、queue、encode、submit、map、readback 与 patch build。
- **诊断与死代码：**production `dense-per-bit` selector、per-bit builder 与固定零 counters 已删除。
  当前任务最近 20 次 typed compute events 可进入 BUG 报告，任务切换/dispose 清空，不含完整 task id、
  Mask 内容、adapter/driver 或浏览器原始错误。
- **证据与文档：**数据写入
  [`21-mask-packed-cpu-fallback-ab.json`](../research/data/21-mask-packed-cpu-fallback-ab.json)，并新增
  ADR-0061、更新 WebGPU 调研、标注架构、研发排障、部署运维与 CHANGELOG。
- **未验证项：**macOS/Wayland/Windows 无 flag WebGPU、Firefox/Safari、真实浏览器 device-lost 注入、
  多标签页显存压力仍未完成；本机强制 Vulkan 不外推为跨平台支持。
- **移交：**v0.23.22 只消费本版稳定的 dual-budget、compute metrics、circuit 与 packed CPU route；
  超大图 tile/pyramid 不修改本版 `morphology_roi`、history patch 或 canonical RLE 合同。
