> Status: implemented and verified

>
> Implementation authorization: 用户要求确定计划草案并直接实施
>
> Baseline: `d20846aa771d08063189b9a5378e4313aa4c3a66` (`v0.24.9`)

> Scope owner: 3D Scene 内 `box_3d` 轨迹身份修正

## 1. 结论

本版本在现有“3D 跨帧任务中心”内新增轨迹修正区，交付同一 Scene 内的轨迹拆分与合并。操作只修改
`Annotation.track_id` 和 annotation 版本，不自动修改、插值或删除 3D 几何。

拆分以当前帧为边界：当前帧及之前保留原 `track_id`，之后的成员获得一个新的 `track_id`。合并以当前
选中轨迹为显式 survivor，只允许合并同类别且活跃帧完全不重叠的第二条轨迹；任何冲突都拒绝，不覆盖已有真值。

操作采用“候选 → 预览 → 携带快照令牌执行”的同步原子事务。单次最多涉及 5000 个活跃成员，超过上限明确
拒绝，避免长 Scene 上出现无界事务。不新增表、迁移、Worker 或通用轨迹实体。

## 2. 当前事实与采用依据

- ADR-0045 已确定 `Annotation.track_id` 是跨几何类型的轨迹身份权威落点，3D 传播、插值、时间轴与导出均读取该列。
- 现有跨帧任务中心已经是 Scene 级批量动作入口，继续放在同一处能避免再增加一个浮层或导航模块。
- 视频轨迹已有拆分 / 合并产品语义，但视频把一条轨迹压在单个 geometry JSON 中；3D 是跨 task 的多行
  annotation，必须单独实现权限、锁顺序、快照和事务边界，不能直接复用视频 service。
- 0.24.8 已让传播稳定生成轨迹；0.24.9 的可信导出会消费轨迹身份。没有修正能力时，错误身份会直接进入下游包。

## 3. 用户可见语义

### 3.1 拆分

- 必须在当前帧选中一个具有 `track_id` 的活跃 `box_3d`。
- 当前帧必须是该轨迹的一个真实成员，且当前帧之后至少还有一个成员。
- 当前帧及之前保留原 `track_id`；之后全部成员获得一个新 `trk_<uuid>`。
- 为使传播快照、缓存和质量视图感知拓扑变化，该轨迹所有成员均递增 `version`。
- 任一成员被锁、不可见、不可编辑、跨出当前 Scene、类别漂移或一帧存在重复成员时，整次拆分拒绝。

### 3.2 合并

- 当前选中轨迹固定为 survivor，用户从候选列表选择第二条轨迹。
- 候选只展示当前 Scene 中同类别、帧集合不相交且当前用户可完整编辑的轨迹。
- 两条轨迹都必须每帧至多一个活跃成员；帧集合有任何交集均拒绝，不提供 overwrite。
- 第二条轨迹的成员改为 survivor `track_id`，两条轨迹所有成员均递增 `version`。
- 合并后不补 gap、不插值、不改变 source / class / attributes / geometry。

### 3.3 预览与冲突

- 预览显示类别、轨迹首末帧、成员数、将被重写的成员数和 survivor。
- 预览返回由 operation、边界、annotation id / version / task / frame / class / track 计算的
  `snapshot_token`。
- 执行请求必须回传该令牌；服务端锁行并重算，不一致返回 HTTP 409 `track_snapshot_stale`，不做部分写入。
- 单次两条轨迹合计最多 5000 个活跃成员；超限返回 HTTP 422 `track_member_limit_exceeded`。

## 4. API 合同

### 4.1 合并候选

```http
GET /api/v1/tasks/{task_id}/track-operations/candidates?track_id=trk_x&limit=20
```

响应包含当前轨迹摘要、最多 20 条可合并候选和 `truncated`。候选摘要固定包含
`track_id / class_name / member_count / first_frame / last_frame`。无权访问的 task、锁定成员、类别漂移、
重复帧或超过成员上限的轨迹不会出现在结果中。

### 4.2 预览

```http
POST /api/v1/tasks/{task_id}/track-operations/preview
```

拆分请求：

```json
{
  "operation": "split",
  "primary_track_id": "trk_primary",
  "split_after_frame": 12
}
```

合并请求：

```json
{
  "operation": "merge",
  "primary_track_id": "trk_survivor",
  "secondary_track_id": "trk_candidate"
}
```

`split_after_frame` 必须等于 URL 中 task 的 Scene frame。merge 的 survivor 永远是
`primary_track_id`，不根据首帧或创建时间隐式改变。

### 4.3 执行

```http
POST /api/v1/tasks/{task_id}/track-operations
```

请求字段与预览相同，并增加必填 `snapshot_token`。响应包含 `operation / survivor_track_id /
created_track_id / updated_member_count / primary / secondary`。拆分返回 `created_track_id`，合并返回 null。

## 5. 执行与权限边界

```text
3D 跨帧任务中心
   │ 选中当前轨迹 / 选择候选
   ▼
候选 API ──► 预览 API ──► snapshot_token
                            │ 显式确认
                            ▼
                       执行 API
                            │
             Scene / task / annotation 权限复核
                            │
             按 track_id、annotation id 确定性锁行
                            │
                  快照复核 + 原子改 track_id/version
                            │
             audit log + commit ──► 刷新 annotations / 时间轴
```

- anchor task 先执行可见性与可编辑性检查。
- 所有轨迹成员必须属于 anchor project 和同一 Scene；不存在“只改当前用户可见子集”的降级路径。
- 所有成员 task 都必须对当前用户可见且可编辑，annotation 不能锁定。
- 行锁按 annotation UUID 排序，两个 track 的操作键按字典序冻结，避免相反 survivor 请求形成不同锁顺序。
- `track_id` 由既有 `_new_track_id()` 工厂生成，不新增第二种格式。
- 审计使用 `annotation.update`，detail 记录 operation、Scene、边界、原/新 track、成员数和快照令牌摘要，
  不写几何 payload。

## 6. 明确非范围

- 不实现轨迹终结；未来已有框是删除、隐藏还是保留，需要独立冻结语义。
- 不跨 Scene / 项目合并，不合并不同类别，不覆盖同帧冲突。
- 不修改 cuboid 几何，不自动插值、补帧、删框或调用跟踪模型。
- 不建设独立 Track 表、操作日志表、撤销 journal 或后台 job。
- 不在本版实现 3D Quality 检测；本版本只提供未来 issue 可调用的人工修正原语。
- 不把 WebGPU 实验开关转正式，也不扩展 nuScenes 导出合同。

## 8. 验收测试

后端 happy path：

- 三段轨迹在中间帧后拆分，前段保留原 id、后段获得合法新 id，所有成员 version +1。
- 两条同类且帧不重叠轨迹合并，primary 保留、secondary 全部改 id，geometry 不变。
- 候选只返回同 Scene、同类、无重叠且可完整编辑的轨迹。

后端错误与边界：

- 无 track、边界不是 anchor 帧、没有尾段、同帧重叠、轨迹内重复帧、类别漂移。
- 不可见 / 不可编辑 task、锁定 annotation、跨 Scene 污染、成员超过 5000。
- 预览后任一 annotation version / membership 变化，执行返回 stale 且零写入。
- 两个相反顺序合并请求只能有一个成功，另一个 stale / not found，不形成部分结果。

前端：

- 未选轨迹时解释为什么不可拆分 / 合并；只读时不允许确认。
- 拆分预览显示边界与影响数，确认时携带 snapshot token。
- 合并候选、预览、survivor 文案正确；API 409 后提示重新预览。
- 成功后刷新 annotations、Scene 时间轴和候选，不关闭传播作业历史能力。

浏览器：

- 在 nuScenes mini Scene 选中跨帧车辆轨迹，打开跨帧任务中心，完成一次拆分预览并取消确认。
- 使用测试 seed / 网络拦截完成一次合并确认，核对请求体、刷新请求、成功提示和零 console error；不污染
  开发数据集的长期真值。

## 10. 回滚

前端移除轨迹修正区即可恢复原任务中心；传播作业不受影响。后端移除三个 track operation 端点和 service，
没有 schema / migration 回滚。已经执行的身份修正属于用户真值操作，不能在技术回滚时反向猜测恢复；审计记录
保留原 / 新 track 与成员数，若产品需要一键撤销，应另建带版本快照的 reversible journal。

## 11. 最脆弱假设

本计划假设单个 Scene 内一次身份修正不超过 5000 个成员，且工作台的协作锁能避免在执行事务的极短窗口内
并发创建同一轨迹的新成员。服务端会用快照令牌和现有行锁阻止已存在成员的并发修改；若真实长 Scene 或并发
标注证明新成员 phantom 是常态，下一步必须让所有 track 成员创建路径共同获取 Scene / track advisory lock，不能
继续扩大同步事务上限。

## 12. 实施与验收结果

- 后端已交付候选、预览和原子执行三个端点，覆盖权限复核、成员上限、行锁、快照冲突、审计与零部分写入。
- 前端已把“轨迹修正”并入 3D 跨帧任务中心，覆盖未选轨迹、只读、候选加载、预览、确认和 stale 后重预览。
- 后端轨迹、跨帧作业、Scene 时间轴和领域架构相关测试通过；前端类型、lint、组件测试、OpenAPI、文档与生产构建通过。
- Playwright 在隔离点云 seed 上通过真实 API 完成一次拆分，再从服务端候选列表选择新轨迹并合并回 survivor；请求使用真实
  `snapshot_token`，浏览器无 console 或 page error，测试结束后 seed cleanup 清理数据。
