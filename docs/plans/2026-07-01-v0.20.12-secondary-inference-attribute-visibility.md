# v0.20.12 · 二次推理属性可见性闭合 + codegen 同步 + 组件测试

状态：**已落地（v0.20.12）**。v0.20.11（选中框二次推理）的**体验收尾**——闭合「属性型产物写了库却不显示」的静默缺口。
**依赖 v0.20.11**（本版增强 `SecondaryInferenceBar` + 复用 v0.20.2 一键补全）。

> 落地记：WS0 codegen 经核实**并未漂移**（`pnpm codegen` 零 diff——`types.gen.ts` 由快照 / pre-commit
> 保持同步，先前 `grep -A25` 窗口太小误判），WS0 为验证型无改动。WS1 属性可见性闭合 + WS2 组件测试均落地。

## 背景

v0.20.11 上线后发现两个收尾缺口：

1. **属性型产物可能静默不显示**（真实体验坑）：`AttributeForm` 只渲染项目 `attribute_schema.fields`
   里的键（`(schema?.fields ?? []).filter(isVisible)`）。二次推理把 `color` / `vehicle_type` 等写进
   `annotation.attributes` + `attributes_meta`，但**若这些键不在项目 attribute_schema**，属性面板就
   不显示、也没 `✦ AI` chip——用户看着像「跑了没反应」。平台已有 v0.20.2「一键补全」机制
   （`handleFillAttribute`，`useWorkbenchShellModel.tsx:870`），但**只接在批量 / 交互工具栏的
   `capabilityWarnings` 警告条**，没接到 `SecondaryInferenceBar`。
2. **codegen 漂移**（hygiene）：v0.20.9–0.20.11 给 OpenAPI 加了 `AnnotationCreate.parent_annotation_id`、
   `AnnotationOut.attributes_meta`、`SecondaryInferenceRequest/Response`，快照已再生，但 `pnpm codegen`
   没跑 → `types.gen.ts` 滞后（前端用手维护的 `@/types` 故能跑，但生成层与快照不一致）。
3. **`SecondaryInferenceBar` 无组件测试**（只测了 `buildSecondaryInferencePayload` 纯函数）。

## 工作项

### WS0 · codegen 同步（hygiene，先做）

- 跑 `pnpm codegen`（`openapi-ts` + gen-capability-vocab），让 `types.gen.ts` 与 openapi 快照一致。
- **只提交生成结果差异**，不手改生成文件。确认 `AnnotationCreate.parent_annotation_id`、
  `attributes_meta`、`SecondaryInference*` 进 `types.gen.ts`。

### WS1 · 属性可见性闭合（核心）

- **选能力前预判**：`SecondaryInferenceBar` 里对 `write_target="attributes"` 的能力，比对其
  `output_attribute_schema` 的键与当前项目 `attribute_schema`（当前框 tool_unit）——列出**缺失键**。
- **入口补全 CTA**：能力按钮旁 / 运行后 toast 给「缺 N 个字段，一键补全」action，复用
  v0.20.2 的 `handleFillAttribute` 路径（把 `OutputAttributeSchemaItem` 转 `AttributeField`，
  转法复用 `useCapabilityValidation.ts:155` 那段），补进项目启用工具单位、confirm + 落库。
- **运行后反馈精确化**：toast 从「写回 N 项属性」升级为「写回 N 项（其中 M 项项目缺字段，去补全）」，
  避免"写了看不见"的困惑。
- 复用 v0.20.10 的 `attributes_meta` → chip：补全字段后 `AttributeForm` 自然显示该键 + `✦ AI` chip。

### WS2 · `SecondaryInferenceBar` 组件测试

- mock `useSecondaryCapabilities` + `useRunSecondaryInference` + toast，覆盖：
  - 有能力 → 渲染能力按钮；无能力 → 不渲染。
  - 点击 → 调 run + 成功 toast（属性型 / 几何型 sub 文案）。
  - 属性型缺字段 → 出现「补全」CTA。
  - readOnly / 多选 → 不渲染（渲染门由 shell 控制，组件层测 readOnly）。

## 风险

- **补全写项目配置有副作用**：沿用 v0.20.2 的 `window.confirm` 门（[[feedback_button_terminology]] 同款
  谨慎），不静默改 schema。
- 缺失键预判要按**当前框的 tool_unit** 取项目 schema，不能跨 unit 误判。

## 验收

- 项目 schema 缺 `color` 时跑属性分类 → toast 提示缺字段 + 一键补全 → 补完属性面板显示 `color` + `✦ AI` chip。
- 项目 schema 已有键 → 直接显示，无补全提示。
- `types.gen.ts` 含新字段，`pnpm typecheck` 通过。
- `SecondaryInferenceBar` 组件测试覆盖渲染 / 触发 / 补全 CTA。
