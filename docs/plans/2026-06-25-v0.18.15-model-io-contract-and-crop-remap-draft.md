# v0.18.15 — 模型 I/O 输入契约 + crop 坐标回映

> 状态：**已落地**（2026-06-25 创建，同日实现，提交 `3e158a69`）。
>
> 范围：承接 [0.18.14 受限树形流水线](./2026-06-25-v0.18.14-staged-preannotate-tree-dag-draft.md) §6.6 显式推迟的两块 plumbing。这两块是**几何 depth-3**（`person → 检测 hat → color`）真正可跑的前提，0.18.14 只交付了结构骨架与 attribute 链，本版补齐几何链。

## 落地说明（与草案的偏差）

7 个 PR 全部实现并测试通过（roi/worker/endpoint/capabilities 后端全绿；前端 1654 测试全绿）。与草案的关键偏差：

- **worker 无需链式 transform compose**（草案 §2.2.4）：每个 crop 都裁自**原图**（用回映后的父框几何在原图上重裁），其 transform 即相对原图，直接回映即可——既省掉 compose，也避免逐层 JPEG 重压误差累积，比草案方案更精确。`compose_transforms()` 仍作为已测原语保留（备未来「裁自 crop」场景）。
- **能力门控 / 投递解析落在端点而非 pydantic 校验器**（草案 §3.4）：`PipelineStage` 的 `model_validator` 无 DB 访问、拿不到 backend 能力快照，故把 `supported_inputs` 可达性门控（422）+ 投递方式烘焙（写回阶段 `input.mode`）放在 `POST /preannotate` 端点（已有 backend 归属校验处）。
- **修复 0.18.14 链路缺口**：0.18.14 端点 `norm` dict 未透传 `label` / `input` 给 worker，导致子物体属性前缀（`hat_color`）在真实端点下不生效——本版一并修。
- **FE 父子关系用「加子阶段」按钮而非父阶段下拉**（草案 §6）：在产几何的阶段卡下渲染「加子阶段」（`parentSid` 即该卡），比可重父化的下拉更简单且足以表达受限树形；`availableParentStages` 双向兼容过滤退化为「产几何 + depth<3」门控 + 端点侧 `supported_inputs` 可达性兜底。
- **`_synthesize_supported_inputs` 只依赖 `supported_prompts`**（草案 §3.1 提 task）：task 维度未用到，按「是否交互式 prompt」即可区分（非交互→含 crop）。

## 0. 为什么单列一版

0.18.14 把受限树形的 schema / 校验 / 拓扑执行 / UI 脚手架 / crop 钉死 attributes-only 都做了，但它依赖的两个 `roi.py` 原语只够 depth-2 的几何过渡（0.18.14 §6.6）：

1. `crop_inputs_from_boxes`（`roi.py:68-151`）裁完即丢弃 `(left, top, scale)`，**无法把 crop-local 几何回映到原图**——只能服务"下游回属性"。
2. `crop` / `geometry_prompts_from_boxes` 都只读 `rectanglelabels`（bbox），**不读 polygon**，且 geometry-prompt 只能表达"给定框→出几何"，不能"在 ROI 内检测新子物体"。

于是 0.18.14 用一条校验把"产几何但模型不支持 bbox prompt"的子挡在门外。本版的目标就是**解禁这条校验**：让普通检测器能在父 ROI 的 crop 上跑、并把检出几何回映回原图，从而 `person → 检测 hat → color` 真正成立。

同时把 0.18.14 §5.5 留下的"一等输入契约"协议字段一并做掉——它和坐标回映同属"让 I/O 兼容性可声明、可校验"这同一主题。

## 1. Goals / Non-Goals

### Goals

1. **crop 坐标回映**：crop 记录仿射变换 `(offset_x, offset_y, scale_x, scale_y)`，下游在 crop 上检出的几何反投影回原图坐标，作为可消费的新几何写入 `stage_outputs`。
2. **多边形几何源**：crop / geometry-prompt 原语支持以 polygon 父框为输入（取外接框裁剪 / 归一化），让 `detect → box-seg → 几何级下游` 链成立。
3. **一等模型 I/O 输入契约**：协议新增 `supported_inputs`（`full_image | crop | bbox_prompt | point_prompt`），与 `supported_prompts`（交互 prompt）解耦；模型市场展示"可接受输入"由它驱动，`availableParentStages` 做**双向**兼容过滤，`_resolve_input_mode` 由它正推。
4. 解禁 0.18.14 §6.2 的"产几何子必须支持 bbox prompt"校验，改为按 `supported_inputs` 判定可达性。
5. 链式坐标 provenance：depth-3 下每层 crop 的变换链可追溯，回映误差可观测。

### Non-Goals

- 不引入自由 workflow DAG（延续 0.18.14 的克制）。
- 不做旋转框 / 实例分割 mask 的逐像素回映（本版只做轴对齐 bbox + polygon 外接框级别的几何回映）。
- 不改 `/ai-pre` 的批量编排入口语义。

## 2. 模块 A — crop 坐标回映

### 2.1 `roi.py` 原语改造

| 改动点 | 文件 : 行号 | 内容 |
|---|---|---|
| `CropBatch` 增变换 | `roi.py:21-30` | 每个 input 额外带 `transform: {ox, oy, sx, sy}`（crop 在原图的偏移 + 缩放，供回映） |
| `crop_inputs_from_boxes` 落变换 | `roi.py:132-150` | 裁剪时把 `(left, top)` 与 `crop→模型输入` 的缩放记进 `transform`，不再裁完即弃 |
| 新增 `remap_geometry_to_image()` | `roi.py`（新） | 入参 crop-local shapes + transform，出参原图坐标 shapes；轴对齐 bbox 与 polygon 顶点都按 `(x-ox)/sx`... 反投影 |
| polygon 父框支持 | `roi.py:115`、`roi.py:194` | 几何门控放开：polygon 父框取外接框裁剪 / 归一化（mask→bbox） |

### 2.2 Worker 执行

`tasks.py:292-369` 的 crop 分支增第三态：当子 `write.target ∈ {geometry, intermediate}` 且子模型 `supported_inputs` 含 `crop`（普通检测器在 crop 上跑）时：

1. `crop_inputs_from_boxes` 裁父 ROI（带 transform）。
2. 下游检测，返回 crop-local 几何。
3. `remap_geometry_to_image()` 反投影回原图坐标，写 `stage_outputs[st.stage]`，供孙子阶段消费。
4. 链式：depth-3 时变换按层 compose（root→parent crop→child crop），`provenance_root_box_id` 串联（0.18.14 §10 已约定字段）。

### 2.3 风险

- **回映误差**：JPEG 重压 + 整数裁剪边界引入亚像素误差；逐层累积。缓解：transform 用浮点、不取整；可观测里加"回映往返误差"统计抽样。
- **嵌套画质**：0.18.14 §10 的按深度 pad + `min_crop_side_px` 守卫继续生效。

## 3. 模块 B — 一等模型 I/O 输入契约

### 3.1 协议字段

`docs-site/dev/reference/ml-backend-protocol.md`：新增 `supported_inputs: list[str]`（`full_image | crop | bbox_prompt | point_prompt`）。语义与现有字段的关系：

- 与 `supported_prompts`（point/bbox/text…，**交互式用户 prompt**）**解耦**：一个纯分类器 `supported_prompts=[]` 但 `supported_inputs=["full_image","crop"]`；一个 box-seg `supported_inputs=["bbox_prompt","full_image"]`。
- 老 backend 缺字段 → 平台按 `task` + `supported_prompts` 合成兼容默认（detect/cls→`["full_image","crop"]`；box-prompt seg→`["bbox_prompt","full_image"]`），保证零退化。

### 3.2 数据 / 类型

| 改动点 | 文件 : 行号 | 内容 |
|---|---|---|
| 能力规范化合成默认 | `apps/api/app/services/ml_capabilities.py:91-111` | `_normalize_model()` 补 `supported_inputs`，缺省按上面规则合成 |
| 后端类型 | `MLModelCapability`（`apps/web/src/api/ml-backends.ts:42-81`） | 加 `supported_inputs?: string[]` |
| 实例类型 | `CapabilityInstanceModel`（`apps/web/src/api/mlCapabilities.ts:74-103`） | 同上 |

### 3.3 消费方改造

- **模型市场卡片**（0.18.14 §5.5 已加`可接受输入`行，复用 `supported_prompts`）→ 本版改读 `supported_inputs`，语义更准（`整图 / crop / 框提示 / 点提示`）。
- **`_resolve_input_mode`**（0.18.14 §6.3，按 `write.target` 正推）→ 升级为"`write.target` 决定**产物形态**、`supported_inputs` 决定**投递方式**"二维判定，替掉启发式。
- **`availableParentStages`**（0.18.14 §5.2 仅按父 `write.target` 过滤）→ 加**子侧**过滤：子 `supported_inputs` 与父输出几何不兼容则不可选，UI 给出原因 tooltip。

### 3.4 解禁 0.18.14 的校验

0.18.14 §6.2 "子产几何 → 必须支持 bbox prompt" 替换为："子产几何 → `supported_inputs` 必须含 `bbox_prompt` 或 `crop`"。含 `crop` 的检测器走模块 A 的回映路径；含 `bbox_prompt` 的走 geometry-prompt 路径。至此 `person → 检测 hat → color` 通过校验并可跑。

## 5. 验收

- `person → 检测 hat → color`（hat 是普通检测器、在 person crop 上跑）：root 框出现 `hat_color`，hat 框坐标回映落在 person 框内，`max_depth == 3`。
- `detect → box-seg → 几何级下游`（polygon 父框）成立。
- 回映往返误差抽样 < 阈值（亚像素级）。
- 0.18.14 的全部接受 / 拒绝用例不退化；原"产几何但模型不支持 bbox prompt"422 改为"`supported_inputs` 不含 `bbox_prompt`/`crop`"才 422。
- 模型市场卡片`可接受输入`显示来自 `supported_inputs`（老 backend 显示合成默认）。

## 6. 兼容性

- 协议字段 `supported_inputs` additive，老 backend 缺省由平台合成，零退化。
- `roi.py` transform 为新增返回字段，单阶段 / depth-2 路径不读它即可保持原行为。
- 数据库无 migration（能力仍走 `health_meta` JSONB 快照）。
