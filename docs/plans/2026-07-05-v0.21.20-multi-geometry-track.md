## 两条正交轴：单帧几何 vs 轨迹几何（本计划范围澄清）

视频侧「非 bbox 几何」其实是**两条正交的轴**，工作量与难度差一个量级，必须先分清：

- **轴 A · 单帧几何**（`video_bbox` → `video_polygon`/`_polyline`/`_keypoint`/`_rotated_bbox`/`_mask`）：在**某一帧**上画一个多边形/折线/关键点/OBB/掩膜，几何 = 图片几何 + `frame_index`（照抄 `VideoBboxGeometry:408-422` 的 `type`+`frame_index`+载荷范式），**无插值、无关键帧对应、无参数化重采样**。这是较简单的一半，也是「**在视频工作台增加图片工作台所有单帧工具**」这个更大诉求的落点。
- **轴 B · 轨迹几何**（`video_track_bbox` → `video_track_polygon` 等，**本计划主体**）：跨帧、逐关键帧插值的 track。硬骨头在插值（顶点对应 + 周长/弧长参数化重采样），见缺口 2 与风险节。

**两轴共享的地基**（schema 变体、视频栈 `<Line>`/keypoint/mask 渲染、视频栈工具交互）是**同一套**；**只有插值/关键帧对应是轴 B 独占**。因此**轴 A（单帧）应先行、作为轴 B 的地基**：先把单帧几何跑通（省掉最难的插值），track 几何再在其上叠加插值层。

**注意范围差**：本计划（轴 B）只碰 polygon/polyline/mask **三种几何**；而「图片工作台所有单帧工具」（轴 A）还包含 **keypoint、rotated-box（OBB）、以及 4 个 AI 工具**（smart-point/smart-box/exemplar/magic-box）——后者需要视频侧交互式 SAM 逐帧接线，是轴 A 里独立的一大块。轴 A 的完整工作量评估另见单帧工具专项（待落盘）。

## 动机（现状：track 几何 bbox 硬编码，全链 bbox-only，带证据）

**术语纠正**：ROADMAP 原写「扩 `video_track.geometry.kind`」——实际判别字段是 **`type`** 不是 `kind`。

### 缺口 1 · schema 只有 bbox 一种
- 后端 `apps/api/app/schemas/_jsonb_types.py`：`VideoTrackGeometry:455-470`，`type: Literal["video_track_bbox"]`
  （`:462`，单值）；关键帧 `VideoTrackKeyframe:434-444` 的 `bbox: VideoTrackBbox`（`:436`，x/y/w/h `:425-431`）
  **硬编码**，无 polygon/points/mask 承载。
- 图片侧几何联合（`:616-627`）有 `PolygonGeometry:473`/`MultiPolygonGeometry:507`/`PolylineGeometry:536` 等，但
  **没有对应的 video_track_polygon/_polyline/_mask 变体**（全仓 grep 0 命中）。
- 前端：`api/generated/types.gen.ts:3856-3862` `VideoTrackGeometry`（`type?:"video_track_bbox"`）；stage 类型
  `videoStageTypes.ts:9` `VideoStageGeom={x,y,w,h}`（bbox 硬编码）；判定 `videoStageGeometry.ts:45-47` `isVideoTrack`
  = `type==="video_track_bbox"`（唯一 track 类型）。

### 缺口 2 · 插值 bbox-only、无参数化
- 前端 `videoStageGeometry.ts:133-142` `interpolate`：对 `{x,y,w,h}` 四分量线性 lerp。
- 后端 `services/video_tracks.py:92-99` `lerp_bbox`：bbox 各 key 线性插值。
两者都**假设 a/b 同结构同分量数**；顶点数可变的 polygon 无法直接套用。「按周长/长度参数化插值」**完全不存在**。

### 缺口 3 · 渲染只有 `<Rect>`
`VideoKonvaTrackShape.tsx` 全文只 `<Rect>`（`:2,:51,:64`），`geom: VideoStageGeom`（`:14`）；无 `<Line>`（polyline/
polygon）/ mask 渲染分支。

### 缺口 4 · mask 存储在图片侧也不存在（一律矢量化）
图片侧 mask 一律转 polygon/multi_polygon 存（`_jsonb_types.py:473/507`，`mask_to_multi_polygon`），**无 RLE/bitmap/
raster mask geometry**（`PointMaskGeometry:595` 是 3D 点云，非 2D 栅格）。前端 `type=="mask"` 命中指 SAM 输出语义
（`box|mask|both`），不是存储几何。视频侧有 `useVideoBitmapCache`/`CanvasDrawingLayer` 但无 per-frame raster mask
存储/渲染/插值管线。

### 缺口 5 · 导出全链 bbox-only；「Phase 4.5 DAVIS」零占位
- `services/export_video.py`（MOT/YOLO/KITTI 全部 `frame.get("bbox")`，`:73/:141/:161-228`）——无 segmentation 导出。
- **「DAVIS mask 导出 / Phase 4.5」在平台代码内零实现零占位**（所有 `DAVIS` 命中都在 vendored SAM2/SAM3 脚本，
  不接平台链路；「Phase 4.5」字样仓库无命中）。ROADMAP 原述「DAVIS 导出依赖此项」——**依赖成立，但被依赖方也尚未存在**。

### 关键可复用点
SAM2 backend 传播时**内部已算出 mask** 却在 bbox 边界降级丢弃（`video_predictor.py:157-172` 算 mask →
`_mask_to_bbox_norm:164` 降 bbox；runner `apply_tracker_results:159` 写 bbox）。**mask/polygon track 可直接复用这处
已有 mask，改成保留而非降级**——这是最省的切入点，也与 [v0.21.19 sam3 text 追踪](2026-07-05-v0.21.19-sam3-video-text-tracking.md)
的 AB 耦合点（两链都在 bbox 边界丢 mask）。

## 定稿决策（拟）

- **分层推进，polygon track 先行**：优先级 polygon > polyline > mask。polygon track 可**复用图片 polygon schema**
  （矢量、归一化）+ **SAM2 已算 mask 转 polygon**（`mask_to_multi_polygon`）落 keyframe，避开新建栅格存储；polyline
  次之（无闭合/无 holes，更简单）；真·mask track（栅格）体量最大、单独立项。
- **schema → keyframe 承载泛化。** 把 `VideoTrackKeyframe.bbox`（`:436`）泛化为 `shape` 联合（保留 `bbox` 向后兼容
  别名），`VideoTrackGeometry.type`（`:462`）扩 `video_track_polygon`/`_polyline`/`_mask`。**坐标红线**：新几何 points
  必须归一化 [0,1]（`videoKonvaCoordinates.ts:8`）。
- **插值 → 按几何类型分派 + 顶点对应。** `interpolate`（`videoStageGeometry.ts:133`）/ `lerp_bbox`
  （`video_tracks.py:92`）按 `type` 分派；polygon/polyline 需顶点对应 + 周长/弧长参数化插值（顶点数不等时先重采样
  到公共参数化）；mask 关键帧**不插值**（仅关键帧成立，帧间取最近关键帧）先行，形变插值另议。
- **渲染 → 加 `<Line>` / mask 分支。** `VideoKonvaTrackShape.tsx` 按 type 分派 Rect/Line/mask。
- **回填 → 保留 mask。** `apply_tracker_results`（`runner.py:128-186`）按 track 几何类型保留 SAM2 已算 mask
  （转 polygon 或存 mask），不再无条件降 bbox。与 v0.21.19 协同改这一处。
- **导出 → 增 segmentation。** `export_video.py` 扩 COCO-seg video / YOLO-seg / DAVIS PNG（DAVIS 从头建，可参考
  vendor `vos_inference.py` 的 DAVIS_PALETTE / packed-PNG）。
- **数据体积**：polygon/mask 逐关键帧顶点/栅格会放大 JSONB（对照 `PointMaskGeometry:599-601` 已因体积加 600k 上界）；
  需 compact 存储策略（顶点抽稀 / 关键帧稀疏）。

## 实现分阶段（跨 PR，多版本）

- **PR1 · polygon track schema + 渲染 + 插值**：keyframe `shape` 泛化 + `video_track_polygon` 变体；前端
  `VideoStageGeom` 泛化、`VideoKonvaTrackShape` 加 `<Line>`；polygon 参数化插值（前后端）。图片 polygon schema 复用。
- **PR2 · polygon track 交互 + 回填**：轨迹工具支持画/编辑 polygon 关键帧；`apply_tracker_results` 保留 SAM2 mask→
  polygon（与 v0.21.19 协同）。
- **PR3 · polyline track**：无闭合/holes 的简化路径复用 PR1 基建。
- **PR4 · polygon/seg 导出**：`export_video.py` 扩 COCO-seg / YOLO-seg。
- **PR5 ·（单独立项）真·mask 栅格 track + DAVIS 导出**：栅格存储（RLE/PNG）决策 + 显存/体积评估 + DAVIS packed-PNG
  导出从头建。体量最大，可独立成版本。
- **验证 + 版本**：E2E 每 PR ① 对应几何画/插值/渲染正确、归一化坐标；② bbox track 零回归；③ 导出格式可被下游读。
  CHANGELOG（Added）+ 版本 bump。

## 不在范围（本版本切片）

- **真·mask 栅格 track + DAVIS 导出**：PR5 单独立项，不在首个 polygon 切片。
- **mask 形变插值**：先做「mask 仅关键帧、帧间取最近」；顶点/形变插值另议。
- **sam3 text 追踪本体**：见 v0.21.19（但共享「保留 mask」的回填改造）。
- **3D 点云 track**：`PointMaskGeometry` 是 3D 域，与本 2D 视频 track 无关。

## 风险

- **插值是硬骨头**：顶点数可变的 polygon 需顶点对应 + 参数化重采样，错则插值帧几何扭曲；先 polygon（闭合、可周长
  参数化）验证手感，再 polyline。
- **数据体积**：逐关键帧顶点/栅格放大 JSONB（`PointMaskGeometry` 已因此加 600k 上界）；需 compact + 上界，否则大
  轨迹拖垮落库/传输。
- **红线：坐标零迁移**（`videoKonvaCoordinates.ts:8`）——新几何 points 必须归一化，bbox track 存量零迁移。
- **AB 耦合（与 v0.21.19）**：两链都在 bbox 边界丢 mask（`video_predictor.py:164`、`runner.py:159`）；「保留 mask」
  的回填改造应两计划协同，避免各改一遍。
- **导出下游兼容**：COCO-seg/DAVIS 格式须被真实训练/评测链读得懂；DAVIS 从零建，先对齐 vendor palette/PNG 格式。
- **体量诚实**：本项是 P1 大骨头、非单版本可完结；分 PR/多版本推进，首切片只 polygon，避免一次吞下 schema+插值+渲染+
  导出+栅格全维度。
