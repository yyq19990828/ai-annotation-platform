## §1.6 DuckDB 离线分析视图（2d）

### 设计要点
- Celery beat 每日 02:30 UTC 增量同步 `task_events`（全量）+ `audit_logs`（活动月分区）→ DuckDB。
- Host 路径 `./data/duckdb/analytics.duckdb`，celery-worker 在 docker 内挂同一路径 (`./data/duckdb:/var/lib/duckdb`)，API 跑 host 直接读 host 文件。
- 并发：worker 写、API 只读（`read_only=True`）。
- 三个固定面板（API 接受 `panel_name` enum，**不**接收任意 SQL）：
  - 人均日吞吐（task_events GROUP BY user×day）
  - reject 率按 type 分布（依赖 §1.2 `reject_reason_type` 列）
  - 标注耗时 p50/p95（task_events claim→submit 间隔）
- Python 依赖：`duckdb>=1.1.0,<2.0.0`（不用 `duckdb-engine`，直接 `duckdb.connect()`）。

## §1.7 统一 async_jobs 表 MVP（3d）

### 设计要点
- 新表 `async_jobs(id UUID, kind, project_id, user_id, status, progress_pct, payload JSONB, result JSONB, error_message, celery_task_id, started_at, completed_at, created_at, updated_at)` + 索引 `(user_id, status, created_at)` + `(project_id, kind, status)`。
- 双写双轨：`async_jobs` 是汇总索引层，专表（`prediction_jobs` / `video_tracker_jobs`）保留为 domain 真值。
- 进度上报由 service 层显式调用 `async_job.update_progress(job_id, pct)`；Celery signals **仅做兜底**（task crash → mark failed）。
- 前端铃铛走 polling（5s interval）；WebSocket 推送留 v0.10.17。
- cancel MVP 范围：仅支持 `predictions_import` / `audit_archive` 软 cancel；`batch_predict` / `video_tracker` 留后续。
- retention：30 天 purge `status IN ('completed','failed')` 作 MVP 一部分（cleanup Celery task）。

## 风险与回滚

- **§1.2 schema 变更**：alembic 0070 单列添加无破坏，回滚 `alembic downgrade -1` 即可。
- **§1.6 DuckDB 文件**：sync 出错不影响主业务（独立 query 路径），失败仅 `/admin/analytics` 503。
- **§1.7 Celery signals**：兜底逻辑若 bug 可能让 task 跑完但 `async_jobs.status='running'` —— retention 30d 自动清，业务无影响。
- **双写一致性**：service 层 try/except 包 `async_job.update_progress` 调用，**专表写入失败不阻断业务流程**（仅记日志）。
