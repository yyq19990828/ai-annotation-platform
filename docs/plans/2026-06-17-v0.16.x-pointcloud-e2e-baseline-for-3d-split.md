# 点云工作台 E2E 基线 —— 为拆 3D 整簇铺路

> 立项缘由:`2026-06-17-v0.16.x-deferred-split-test-backfill.md` 第 3 批判定 ——
> `usePsrEditor` / `usePointMask` / `usePointCloudSelection` 整簇因共享 `sceneRef` + `form` +
> 合并键盘 handler **职责纠缠,不可在不改行为前提下干净切分**;且 jsdom 无 WebGL,
> Three.js scene/raycaster/gizmo 整体跑不起来(`vite.config.ts` 已把 `stages/three-d/*` 排除出
> coverage),单测守护不了。**唯一能在拆分前后证明行为等价的手段是 Playwright 端到端基线。**
> 本计划只做"建基线",不在本计划内真正拆 hook(拆是基线绿了之后的后续动作)。

## 0. 现状盘点(基建已存在,缺的是 3D 这一支)

已有(无需新建):
- `@playwright/test ^1.49.0`;`apps/web/playwright.config.ts`(testDir `./e2e`,project = chromium)、
  `playwright.screenshots.config.ts`(截图回归矩阵 desktop-light/dark/tablet/mobile/flows/regression)。
- `apps/web/e2e/fixtures/seed.ts` + 后端 `_test_seed.py` router(非 production 挂载):
  `/seed/reset`(重建固定 fixture)、`/seed/login`(JWT 注入免登录)、`/seed/peek`、
  `/seed/inject-prediction`、`/seed/advance_task`。
- 现成范式 `e2e/tests/workbench-image-konva-smoke.spec.ts`:`seed.reset()` → `advanceTask` →
  `injectToken`(免登录)→ `goto('/projects/:id/annotate')` → testid 选择器 → 交互 → `toHaveScreenshot`
  (`maxDiffPixelRatio: 0.01` 容差抗字体/抗锯齿)。

**缺口(本计划要补的)**:

## 1. 守护目标 → 交互映射(基线必须覆盖这些,拆分才安全)

| 纠缠簇 | 拆分会动的核心 | 基线必须钉死的可观测行为 |
|---|---|---|
| `usePsrEditor`(form 中心态被 8 处共享) | 数值面板 ↔ gizmo ↔ 浮窗 ↔ 渲染共享 `form` | ① 选中框 → 改数值字段 → **几何 PATCH 落库**(已被 `usePsrPatchPipeline` 单测覆盖,e2e 复核接线);② 拖 gizmo(W/E/R 切模式)→ 框变换 → 落库;③ 失焦空字段从当前值恢复 |
| `usePointMask` | polygon 状态在合并键盘 effect 里清理 | ④ point-mask 工具画 polygon(Enter 完成 / Alt 减选)→ **point_mask_3d 几何写入** |
| `usePointCloudSelection` | 框选 marquee + 选中态 | ⑤ 框选 marquee → 多选;⑥ 点选单框 → 选中高亮 + PSR 面板出现 |
| (已拆,回归网) `usePredictionPropagation` | — | ⑦ Shift+→ 跨帧延续 → 导航 + 新框自动补选(已人工验,纳入自动基线防回归) |
| (已拆,回归网) `useCameraPanels` | — | ⑧ 相机面板拖动 / 收起 / 重置(已人工验,纳入自动基线) |

> 守护哲学:**以"交互后的状态断言"为主(GPU 无关、确定性),像素截图为辅。** Three.js 画布像素
> 受 GPU/驱动影响极易 flaky,故点云本体不做像素基线;断言落在 **PATCH 请求 / 标注列表 DOM /
> PSR 面板字段值 / 选中态 class** 上。像素基线只用于**稳定的 2D 相机投影面板**(`<img>` + 投影框
> overlay,DOM 可控)并给高容差 + 必要时 mask 掉点云 canvas 区域。

## 2. 工作分解(P0 基建 → P1 冒烟 → P2 交互断言 → P3 可选视觉 → 解锁拆分)

### P0 · seed + 运行环境(最硬的前置)
1. **后端 seed 扩点云**(`apps/api/app/api/v1/_test_seed.py`):`/seed/reset` 增建或新增
   `/seed/lidar` —— 造 1 个 `type_key=lidar` 项目 + ≥2 帧同 scene 的点云 task(跨帧 spec 需要),
   每 task 带 manifest(`point_cloud_url` 指向一个**极小 .pcd 测试资产** + 至少 1 个相机
   `calibration`/extrinsic 供投影面板)。`SeedData` 增 `lidar_project_id` / `lidar_task_ids`。
   - 测试资产:放 `apps/api/tests/assets/`(或现有 e2e 资产目录),几百个点的最小 pcd 即可,
     不追求真实场景,只要能 `loadPcd` 成功、`stats` 出数、投影面板有图。
2. **前端 fixture**(`e2e/fixtures/seed.ts`):`SeedData` 接口加 lidar 字段;必要时加
   `seedLidar()` helper(若走独立端点)。
3. **WebGL 运行环境**(`playwright.config.ts`):给 chromium 加 launchOptions
   `args: ["--use-gl=angle", "--use-angle=swiftshader", "--enable-unsafe-swiftshader", "--ignore-gpu-blocklist"]`
   (或独立 `project: "pointcloud"` 只对 3D spec 开这些参数,避免影响其它 spec)。**先验证
   `PointCloudScene` 在 headless 能 `loadPcd` 成功**(P1 冒烟即此验收点)。
4. **testid 审计与补齐**(`apps/web/src/pages/Workbench/stages/three-d/*`):为 3D 工具按钮、
   PSR 面板各数值输入、gizmo 模式指示、相机面板、重置布局按钮补 `data-testid`。**纯加 testid,
   不动逻辑**(本身就是 surgical、零行为变化的安全改动)。

### P1 · 冒烟 spec(`e2e/tests/workbench-pointcloud-smoke.spec.ts`)

### P2 · 交互状态基线 spec(`workbench-pointcloud-edit.spec.ts` 等)—— 真正的守护网
- 覆盖 §1 的 ①④⑤⑥⑦⑧:
  - **PSR 数值编辑**:点选框 → 改 `cx`/`l` 输入 → 等 250ms 防抖 → 断言 `PATCH /annotations/:id`
    发出(`page.waitForRequest`)且 payload 几何含新值;

  - **point-mask**:P 工具 → canvas 画 polygon → Enter → 断言 point_mask 几何写入;

### P3 · 可选视觉基线(`screenshots` 矩阵新增 3D 用例)

- 非阻塞:P2 交互断言已是充分守护;P3 是锦上添花。

### P4 · 解锁拆分(本计划之外,基线绿后才做)
- P1+P2 稳定后,逐个拆 `usePsrEditor` / `usePointMask` / `usePointCloudSelection`,每拆一个
  跑 3D e2e 证明行为等价。届时 §deferred 计划的"整簇缓拆"才解除。

## 3. 风险与验收口径
- **WebGL headless flaky / 跑不起来**:P1 是 go/no-go 闸。若 SwiftShader 仍不稳,退路是给 3D spec
  开 `headed`(本地)/ CI 用 `xvfb` + 真 GL;或把 3D e2e 标 `@manual` 暂不入 CI gate,仅本地值守跑。
- **测试时长**:点云加载 + WebGL 比图片 spec 慢;3D spec 单列 project,不拖慢主 e2e。
- **不为像素较真**:点云本体不做像素基线(GPU 依赖),避免 flaky 反噬。
- **验收**:P0 seed/reset 出 lidar 数据;P1 headless 加载点云零 console error;P2 §1 的 ①④⑤⑥⑦⑧
  交互断言全绿且可重复跑 3 次稳定。

## 4. 与既有计划的关系
- 本计划是 `deferred-split-test-backfill` §5/§7 标注的"若将来要拆 3D 整簇,先建 Playwright 端到端
  基线(Epic §7 非目标,需另立项)"的**那个立项**。
- 属 Epic §7 测试基建建设范畴,**独立于"补测试再拆"**(后者已收口:后端 3 + 前端 A 类 7 +
  B 类可单测/可人工回归者 3 = usePredictionPropagation/usePsrPatchPipeline/useAiPopoverFrame)。
