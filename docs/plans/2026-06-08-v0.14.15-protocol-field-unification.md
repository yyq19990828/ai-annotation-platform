# v0.14.15 · 协议字段名统一 & 错误码规范（model_variants 扁平化 / HTTP 状态码统一 / 冗余字段清理）

> Created: 2026-06-08
> Status: Draft
> 依赖：v0.14.14（预标注可观测性 · cache_hit / pool 状态统一）

## 0. 背景与动机

v0.14.12 起协议层支持了 `supported_variants` / `variant_combinations` / `variants_shared_across_tasks` 等富表达，v0.14.13 让前端真正用上 variant 选择，v0.14.14 补上 pool 运行时可观测性。但跨 3 个 backend 检查后，发现协议字段命名仍有显著的不一致问题，这些不一致已经成为前端泛化逻辑的复杂度来源：

| 维度 | yolo-backend | gsam2-backend | sam3-backend | 问题 |
| ---- | ---- | ---- | ---- | ---- |
| variant 字段名 | `context.variants.{series, size}` | `context.{sam_variant, dino_variant}` | `context.model_variant` | 三套命名，前端 VariantSelector 内部需要 backend-specific 映射 |
| 推理参数命名 | `conf` / `iou` / `max_det` | `box_threshold` / `text_threshold` | `score_threshold` | 都是"阈值"语义但名称各异，前端无法统一渲染 |
| 校验错误码 | 非法 (series,size) 返回 400 | 非法 sam_variant 返回 422 | 无校验（单档） | HTTP 状态码不一致，前端 error handling 要写 backend 分支 |
| variant 缺省 | 必须显式传 | 缺省落 env 默认 | 无 variant 概念 | 缺省行为不一致 |

同时 `projects.ai_model` 字段（早期 v0.10.x 留下的冗余字段，实质是 `backend.name` 的字符串副本）在 v0.14.13 已标 deprecated，本版正式删除。

本版本目标：**让协议字段名跨 backend 严格一致**，把"为每个 backend 写一套传参逻辑"的成本压到接近零，同时让 backend SDK / starter 模板有一份明确的"新约定"可以参考。

## 1. 目标 & 验收

### 1.1 协议视角（最核心）

- [ ] **variant 字段扁平化为通用 `model_variants`**：所有 backend `/predict` 接受 `context.model_variants: dict[str, str]`，key 是 axis_key（由 backend 在 `/setup.supported_variants[].axis_key` 声明），value 是 axis_value：
  ```json
  // 新约定（v0.14.15）
  {"context": {"model_variants": {"series": "yolov11", "size": "s"}}}
  {"context": {"model_variants": {"sam_variant": "tiny", "dino_variant": "T"}}}
  {"context": {"model_variants": {"model_variant": "sam3.1"}}}
  ```
  老字段名（`variants`, `sam_variant`, `dino_variant`, `model_variant` 在 context 顶层）保留一版兼容期，backend 收到时 normalize 到新字段并日志 deprecation warning。
- [ ] **推理参数保留 backend 各自命名**：本版不统一参数名（conf/iou/box_threshold/score_threshold），因为这些是模型族特定语义、强行统一会语义损失。**改为在 `/setup.params` 的 JSON Schema 中暴露 `x-platform-role: 'confidence' | 'iou' | 'maxDet' | 'textThreshold' | ...`**，前端用 `x-platform-role` 渲染统一标签（如"置信度阈值"），实际字段名不变。
- [ ] **HTTP 错误码统一**：
  - variant 字段缺失或类型错 → 422 (Unprocessable Entity, pydantic 默认)
  - variant 值合法但不在 `variant_combinations` / `supported_variants` 内 → **422**（schema 校验范畴；不再是 yolo 的 400）
  - variant 合法且组合合法，但当前 backend 状态无法服务（如权重文件丢失 / 显存不足 / 模型未预下载）→ **503 Service Unavailable**，含 `Retry-After` 头
  - 推理本身失败（输入图片解码失败、forward 抛 OOM）→ **422**（输入问题）或 **500**（backend bug）
  - 三 backend 实现统一抽到 `apps/_shared/protocol_v2/errors.py`。
- [ ] **协议版本号声明**：`/setup.protocol_version: '2.1'`（v0.14.12 是 '2.0'，本版 minor bump）。`/setup.compat_protocol_versions: ['2.0']` 声明兼容性。

### 1.2 SDK / Starter 视角

- [ ] `apps/_shared/protocol_v2/` 作为 SSOT，schema + error 类 + helpers 统一暴露。
- [ ] v0.15.2 starter 模板（`apps/ml-backend-starter/`，假设已有；若无本版不创建）使用新约定。

### 1.3 数据库视角

- [ ] 删除 `projects.ai_model` 字段（已在 v0.14.13 标 deprecated）。
- [ ] Alembic 迁移：
  ```python
  def upgrade():
      op.drop_column('projects', 'ai_model')

  def downgrade():
      op.add_column('projects', sa.Column('ai_model', sa.String(), nullable=True))
  ```
- [ ] 前后端代码全量 grep 删除 `ai_model` 引用。

### 1.4 前端视角

- [ ] `VariantSelector` 改造：组件输入只接受 `axis_key` 通用约定，不再有 backend-specific 分支。
- [ ] `usePreannotation` 调用 `/predict` 时使用 `context.model_variants` 扁平字段。
- [ ] `SchemaForm` 参数渲染：识别 `x-platform-role`，按 role 给统一 i18n 标签（如所有 backend 的"置信度阈值"用同一文案）。
- [ ] error handling：422 → "参数错误，请检查输入"；503 → "模型暂不可用，{Retry-After} 秒后重试"；500 → "服务异常"。

### 1.5 验收

- [ ] 后端：3 个 backend 各自的 contract test 覆盖：
  - 新字段名 model_variants 工作正常
  - 老字段名（兼容期）仍能解析 + 日志 warning
  - 非法 variant 组合返回 422 + 标准 error body
  - 模拟"权重缺失"场景返回 503 + Retry-After
- [ ] 前端：vitest VariantSelector 去 backend-specific 分支后的纯函数测试。
- [ ] e2e：跑一遍预标注端到端，老 backend（如外部用户自建未升级的）仍能工作（兼容期保护）。
- [ ] 文档：`ml-backend-protocol.md` 全量重写 §4 章节，标 protocol_version 2.1；老字段名进 §10 "兼容性与迁移"。

- [ ] CHANGELOG v0.14.15。

## 2. 范围 & 不做的事

### 2.1 In scope

- 3 个 backend 的字段名迁移 + 兼容层。
- API 层 normalize 逻辑（如果 API 在 backend 之间做转换；初步检查应是直传，但需确认）。
- 前端 VariantSelector / usePreannotation / useInteractiveAI / SchemaForm 适配。
- `ai_model` 字段删除 + Alembic 迁移 + 全栈代码清理。
- 协议文档 + ADR。

### 2.2 Out of scope

- **推理参数字段名跨 backend 物理统一**（如把 yolo 的 `conf` 改名成 `confidence_threshold`）→ 不做。本版用 `x-platform-role` 元数据层解决前端展示，不动 backend 物理字段名。
- **协议 v3 大版本升级**（如改 setup/predict 整体 schema 结构）→ 不做。本版是 v2.1 minor。
- **多模态 backend（如音频 / 视频）协议扩展** → 由后续版本评估。
- **backend 内部 cache key 命名统一**（v0.14.14 的 `loaded_keys[].key` 仍是 opaque string）→ 不做，保持 backend 自由度。
- **删除 sessionStorage 猜测代码**（v0.14.13 引入，v0.14.14 deprecate）→ 顺手做（小改动）。

   ```python
   class VariantNotSupportedError(HTTPException):
       def __init__(self, axis, value, allowed):
           super().__init__(
               status_code=422,
               detail={
                   "error_code": "variant_not_supported",
                   "axis": axis, "value": value, "allowed": allowed,
               },
           )

   class ModelUnavailableError(HTTPException):
       def __init__(self, key, reason, retry_after_s=30):
           super().__init__(
               status_code=503,
               detail={"error_code": "model_unavailable", "key": key, "reason": reason},
               headers={"Retry-After": str(retry_after_s)},
           )
   ```

## 6. 风险 & Tradeoff

- **兼容期长短**：本版引入兼容层后保留多久？建议至少到 v0.15.0（约 2-3 个 minor），给外部用户（自建 backend）足够迁移时间。`/setup.protocol_version=2.1` + `compat_protocol_versions=['2.0']` 是机器可读的契约，到时主动 grep 文档 + CHANGELOG 提示删除。
- **x-platform-role 增加 schema 维护成本**：每个 backend 要在 JSON Schema 里标 role，但 role 集合需要在 `_shared` 定义一个 enum，否则各家发明不同 role 字符串就白搭。落地：`apps/_shared/protocol_v2/roles.py` 维护 PlatformRole enum + i18n key 映射。
- **删 ai_model 字段是 breaking**：如果有任何外部消费者（SDK / 第三方集成）还在读这个字段会炸。前置检查：grep + 联系下游确认 + 给一版 deprecation 期（v0.14.13 已 deprecated，v0.14.14 又跑了一版）。
- **错误码改动可能影响前端 catch 逻辑**：从 400 改 422 后，前端如果有 `if (err.status === 400)` 的 catch 分支会漏。落地：先全 grep 改 catch 分支，再切 backend。
- **本版改动横跨 6 个层（protocol → 3 backend → API → DB → frontend）**：commit 拆分必须严格按 §4 顺序，每个 commit 独立可回滚。建议在合到 main 前先 rebase 验证每 commit 都能跑通测试。

## 7. 与现有版本的关系

- **依赖 v0.14.14**：pool 可观测性 / cache_hit 真信号。
- **依赖 v0.14.13**：projects.default_variants 已上线（替代 ai_model）。
- **影响 v0.15.x SDK starter**：starter 模板要用新约定。
- **影响外部 backend 集成方**：自建 backend 的用户需要在 2-3 个 minor 内迁移到 2.1。CHANGELOG + 协议文档 + email/通知 一起。

## 8. 后续

完成本版后，0.14.x 系列的预标注交互优化告一段落。下一步可能的方向（不在 0.14.x 内）：

- **v0.14.16+ · 推理参数预设**：用户在「AI 预标注」页可保存命名预设 (variant + params)。
- **v0.15.x · 多模态扩展**：协议扩到音频 / 视频 / 多帧融合。
- **v0.15.x · backend 调度策略**：多副本部署 + 智能路由（按 variant 亲和度路由请求）。
