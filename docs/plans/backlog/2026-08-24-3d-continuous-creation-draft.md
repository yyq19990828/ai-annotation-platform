## 1. 推荐结论

推荐在现有 3D 创建链路外增加一个**显式、可见、可退出的持续 armed 状态**，而不是再造一套 cuboid 创建器。类别、创建方式和拟合参数在成功创建后保持，用户可连续点击、框选或从相机图种框；每个结果仍通过现有 annotation mutation 和 3D history 独立提交。

这个方向借鉴 Supervisely Auto Cuboid 的连续生产循环，但保留本项目已有的点击默认框、屏幕矩形选点拟合、相机视锥种框与撤销语义。

## 2. 当前基线快照

- `ThreeDWorkbench.tsx` 已有三条 `box_3d` 创建路径：点击地面放默认框、屏幕矩形经 `psrFromPoints` 建框、相机图矩形经视锥与 `fitYaw / fitBottom` 建框。
- 现有创建成功后会选中新对象，但点击与框选路径随后调用 `onSetThreeDTool("select")`；点掩码创建也会退出工具。
- `geometry/autofit.ts` 已提供尺寸、底面和 yaw 拟合；`useThreeDHistory.ts` 已能记录创建、编辑与撤销。
- 切换 task 会强制回到选择工具。这是正确的安全边界，持续状态不应跨 task 泄漏。

这些位置只是 2026-08-24 的审计锚点，不是定稿文件清单。

## 3. 用户循环与状态机

```text
选择类别与创建方式
        │
        ▼
  ARMED（持续待命） ── Esc / V ──► SELECT
        │ pointer down
        ▼
  CREATING / FITTING
        │ 成功                    │ 可恢复失败
        ▼                         └────────────┐
  SAVING ── 成功 ──► 选中新对象 ──► ARMED       │
        │ 失败                                  │
        └────────► ERROR（保留类别与工具）───────┘
```

交互合同：

1. armed 状态必须同时展示当前类别、创建方式和“下一次手势会做什么”，不能只靠按钮颜色暗示。
2. 成功创建后继续 armed；`Esc` 或 `V` 明确回到选择工具；切 task、进入只读、类别被禁用或失去编辑锁时自动安全退出。
3. 单击继续生成默认尺寸框，拖框继续走屏幕点集拟合，相机种框继续走视锥拟合；不改变三条几何算法的真值边界。
4. 创建失败不退出工具，不写半成品 annotation，并提供“框内无点、标定不可用、请求失败、权限变化”等可恢复原因。
5. `Space` 只承担“完成当前可提交创建步骤并继续待命”；转定稿时必须核对它与相机、画布和浏览器快捷键的现有冲突。没有进行中的创建步骤时不得制造额外 annotation。
6. 每次成功创建仍是独立 history entry；一次撤销只删除最近一个对象，不一次撤销整个连续会话。

## 4. 范围

- 为 `box_3d` 的三条现有创建路径增加共享的持续模式与 armed 状态提示。
- 保持类别、默认尺寸、自动拟合参数和相机种框方式，直到用户退出或安全边界触发。
- 统一成功、空选区、拟合失败、保存失败和权限变化后的状态恢复。
- 增加键鼠、只读、锁变化、切 task 与 history 的状态机测试。
- 记录连续创建 20 个同类对象的任务耗时和模式切换次数。

## 5. 非范围

- 不在本计划合并 Point Cloud Pen；点掩码混合手势有独立草案。
- 不引入远程 3D 模型、自动类别识别、批量接受预测或跨帧跟踪。
- 不改变 `Annotation.geometry`、API 请求体、数据库表或坐标约定。
- 不让持续工具跨 task、项目或浏览器会话自动恢复。
- 不把自动拟合失败静默降级成看似成功的默认框；若用户选择默认框，必须是明确动作。

## 6. 推荐实现切片（转定稿后执行）

1. **状态机与可见反馈**：先把 `select / armed / creating / saving / recoverable-error` 变成单一前端真值，保持现有单次创建行为不变。
2. **三条 box 创建路径接入**：成功后从“回到 select”改为“按会话策略重新 armed”，并验证每条 mutation 与 history 只发生一次。
3. **快捷键与安全退出**：加入 `Esc / V / Space` 合同，覆盖 task 切换、read-only、锁丢失、类别撤销。
4. **效率验收与文档**：固定 20 对象样本，对比单次模式的激活次数、误建数与中位耗时；只有不增加误操作时才默认开放。

每个切片都应可单独合并和回滚；不得为短期回滚保留第二套长期创建状态。

## 7. 验收方向

- 同一类别连续创建 20 个对象只激活一次工具，且用户全程能读出 armed 状态。
- 点击、框选和相机种框各产生 20 条独立 annotation 与 20 个独立 history entry；无重复 POST。
- 保存失败后继续 armed，重试不会生成重复对象；空框选不会改变已有选择与 history。
- `Esc / V`、切 task、只读切换和编辑锁变化均在一个事件周期内退出创建态。
- 撤销、重做、刷新后数据与单次创建模式一致。
- 对照现状的固定任务中，工具激活次数下降至少 90%，误建与撤销次数不增加。

## 8. 风险与回滚

- 最大风险是用户误以为已回到选择态而连续误建。必须用光标、状态条和退出提示三者共同表达，而不是只高亮工具按钮。
- mutation pending 时继续下一次创建可能造成顺序和选择竞争；推荐第一版保存期间短暂禁止下一次 pointer down，不做并发创建队列。
- 回滚只移除持续会话状态并恢复成功后 `select`，已创建 annotation 与 history 数据无需迁移。
