# v0.13.6 · 点云 RGB 上色 + 深度联动 + 朝向环绕布局

> 状态:草案 v1(2026-06-03)。C0/C1/C2 细化到可实现;**C3 布局先写大概,后续单独详细讨论再定案**。
> 计划归属 epic:点云 + 图像联合标注工作台。前序:v0.13.4 投影联动、v0.13.5 三视图框精修。

## 背景

v0.13.4 已打通「3D 框 → 各相机投影 overlay」(标定逐相机独立)。本切片继续吃满已有的标定投影内核(`geometry/projection.ts`),把融合做深一层:

1. **RGB 上色(图像 → 点云)**:把相机像素颜色「喷」到点云上,标注员靠真实颜色/纹理辨认车/人/标志牌,比靠强度/高度强得多。
2. **深度联动(点云 → 图像)**:在相机图上 hover/点击读出对应点的深度/3D 坐标,或深度热力图叠加。
3. **朝向环绕布局**:相机从「底部一字排 strip」改为「按物理朝向环绕主 3D 视图」(SUSTech 式),解决相机沉底、多相机时拥挤的问题。

研究依据:`docs/research/14-point-cloud-image-fusion.md` §14.4(b) 点云着色/深度反投影、§14.5 关键难点(遮挡)。

## 已定决策(2026-06-03,与用户确认)

- **1a RGB 上色 + 1b 深度联动都做,且都带开关**(默认关:无标定相机本就降级,且省每帧/每帧计算开销)。
- **布局走方案 C(相机按朝向环绕)**,本计划只写大概,细节后续单独讨论。
- 上色**纯前端、实时算不预存**(和投影 overlay 同哲学),后端零改动。
- 上色 MVP **不做遮挡处理**(接受少量穿透串色,留开关 + 后续迭代)。
- 多相机覆盖同一点:**front 优先 / 取最正对相机**;无任何相机覆盖的点保持原色。

## 现状盘点(已就位的地基)

- `geometry/projection.ts::projectPoints(points, calib)`:`extrinsic(4x4) → 可选 rect → intrinsic(3x3) → 透视除法`,返回 `{ pixels, visible }`(`visible=w>0` 剔除相机后方)。**逐点上色 = 把它从「8 角点」喂成「逐点」,算法零改**。
- manifest 逐相机独立携带 `calibration`(`SensorCalibration`:extrinsic[16]/intrinsic[9]/可选 rect[16]),前端 `cameras[].calibration`。
- 主点云 `BufferGeometry` 已有 `color` 顶点属性(`PointsMaterial.vertexColors=true`);三视图 `TriViewRenderer` **复用同一份 geometry** → 主视图上色,三视图自动一起上色(白赚)。
- `seed_pointcloud.py` 幂等导入 SUSTechPOINTS 示例(`third-party/SUSTechPOINTS/data/example`),走真实管线。

### ⚠️ 已发现的陈旧数据问题(C0 处理)

`pc-scene-c3811e` 的 `left/right` 相机标定含 SUSTechPOINTS 示例自带的 `extrinsic_ok` 杂键。该场景是 **v0.13.2「入库剥未建模键」(`pointcloud_import.py:241`)之前**导入的陈旧数据,杂键残留 → manifest 用 `SensorCalibration(extra="forbid")` 校验整份作废 → 返回 null → UI 显示「无标定」、无法投影/上色。**当前导入代码已正确剥键,重导即修好,非活 bug。** front 标定干净故不受影响。

### C1 · RGB 上色内核 + 开关(本切片核心,工作量小)

**纯函数**(`geometry/colorize.ts`,带单测):
```
colorizePoints(positions: Float32Array, cameras: {calib, imageData}[]):
  Float32Array(colors) | null(无可用相机)
  对每点:
    对每个有标定相机 projectPoints 单点 → (u,v,w)
    若 w>0 且 (u,v) 落在 imageData 宽高内 → 候选 {cam, color=采样像素, score}
    多候选取 score 最优(front 优先 / |图像中心距| 最小 / w 最大,择一约定并注释)
    无候选 → 该点保持原色(原 color 或强度灰度)
```
- 像素采样:相机图画到 offscreen `<canvas>` → `getImageData` 一次性取整图 buffer,逐点按 `(round(u),round(v))` 取 RGBA;`intrinsic` 基于原图分辨率,故按原图尺寸建 canvas(与 `CameraProjectionView` 缩放约定一致)。
- 写回:把结果写进主 geometry 的 `color` 属性 → `needsUpdate=true`。**三视图复用同一 geometry 自动上色**。
- **开关**:控件浮条加「相机上色」开关(默认关)。关 → 恢复原始 color(载帧时缓存一份原始 color 备份,切回直接还原,不重算)。
- 触发时机:开关开 / 切帧 / 标定到位时算一次(**非每帧**)。
- 性能:1e6 点 × N 相机的逐点 matvec,一次性 O(N·点数);load 时 web worker 化留作 stretch(MVP 主线程算,加载态提示)。
- MVP **不做遮挡**(背景点可能染到前景色),开关旁注「实验性」或文档说明。
- verify:开上色 → 点云按相机色重染、目标颜色可辨;三视图同步上色;关 → 还原原色无残留;无标定相机不参与(不报错);切帧重算正确。

**待详细讨论的关键设计点(不在本草案定案):**

- **相机数量**:按 ≤4 主向设计;同向多个或超出 → overflow / 并排堆叠。
- **响应式**:窄屏降级(环绕格 → 折叠为可切换 tab?)。
- **与现有三视图右栏的空间分配**。
- verify(占位):相机按朝向就位;无方向元数据的相机进 overflow 不丢失;窄屏不溢出。

## 性能预算

- C1 上色:一次性计算,不进每帧。1e6 点 × 3 相机 ≈ 3e6 次 4x4+3x3 matvec + 一次 `getImageData`,主线程数百 ms 量级(加载态提示);掉帧无关(只在 load/toggle 算)。worker 化留 stretch。
- C2 深度缓存复用 C1 的投影结果,hover 查最近点用屏幕空间近邻(overlay 已有像素坐标)。
- 渲染不变:仍是 GPU 顶点着色,上色只改 `color` 属性。

## 不做(明确排除)

- C1 的**遮挡/可见性 z-buffer**(背景点串色),留迭代。
- 多帧聚合(densification)/ 运动补偿。
- KITTI/nuScenes 等外部数据集 adapter(`.bin→.pcd`、KITTI 标定格式)—— 列为独立 follow-up(本切片用 SUSTechPOINTS 示例足够)。
- 后端 / 数据模型改动(C 纯前端增量;C0 只是重跑既有导入)。

## 风险

- **遮挡串色**(C1 MVP 已知取舍):无 z-test 时背景点可能染前景色。对策:文档/开关注明实验性;迭代加每相机深度图 z-test。
- **多相机覆盖择优约定**(C1):front 优先 vs 最正对 vs 最近,需定一个并注释,避免边界点颜色跳变。
- **C0 重导丢标注**:重跑 seed 若重建 task 会丢现有测试标注。对策:优先「只重跑 attach_calibration 归一化」或新建干净 scene。
- **布局 C 方向推导**(C3,最高,故留详细讨论):缺方向元数据时的兜底;相机数量敏感。
