# v0.20.21 · 非矩形/多几何在推理链路的健壮性整治

日期：2026-07-01

## 背景

排查「上游标注/上游模型输出为非矩形几何」时链路的行为，发现两条链路（**二次推理**单框、**多阶段编排** pipeline）最终都汇聚到同一个几何收窄点 `apps/api/app/workers/roi.py` 的 `_box_bbox_pct`：

- `rectanglelabels`（非旋转）→ 外接框原样；
- `polygonlabels` → `_polygon_bbox_pct` 取轴对齐外接框（降级）；
- 其余（旋转框 / polyline / keypoint / mask / multi_polygon）→ 返回 `None`，计入 `skipped_geometry`。

即下游模型永远只拿得到一个轴对齐矩形。这是 `roi.py` 头部写明的设计（"平台按上游 bbox 裁 crop，backend 无感"），polygon 降级为外接框是有意为之，不是 bug。真正值得修的是三处**静默 / 缺校验 / 无去重**的健壮性缺口。

## 三处问题

### 修复1（本版实施）· 二次推理非矩形几何静默空返回

- 位置：`apps/api/app/services/secondary_inference.py:141-143`。
- 现状：入口 `internal_geometry_to_ls_shape`（门1）能把 `rotated_bbox / polyline / keypoint / multi_polygon` 转成 LS shape，但门2 `_box_bbox_pct` 对它们返回 `None` → `crop_inputs_from_boxes` 跳过 → `batch.inputs` 为空 → **静默 `return annotation, []`**。前端 `SecondaryInferenceBar.tsx` 据此弹「未检出子物 / 无属性产出」的普通（非 error）toast，用户以为跑了没结果，实际几何被无声丢弃。
- 修复：入口处用 `_box_bbox_pct(ls_box)` 预判——几何不可裁 → 明确 `400`（带实际几何类型）；几何可裁但 `batch.inputs` 仍空（框太小 / 贴边退化，`min_crop_side_px=32` 守卫）→ 明确 `422`（提示放大框/换更大对象），不再伪装成「没结果」。前端 `onRun` 已有 `catch → error toast`，后端抛错即正确显示。

### 修复2（本版实施）· 编排配置期缺「上游产出几何能否作 ROI」的对称校验

- 位置：`apps/api/app/services/pipeline_validation.py` + `apps/api/app/api/v1/projects.py`（dispatch `trigger_preannotation` 循环 & save `_compute_pipeline_capability_warnings`）。
- 现状：dispatch 已有一道几何门（`projects.py:1574-1591`，v0.18.15），但它校验的是**下游子模型能不能吃框**（`supported_inputs` 含 `bbox_prompt`/`crop`），缺了对称的另一半——**上游父阶段产出的几何能不能被裁成框**。上游模型自报字段 `supported_geometric_outputs`（`ml_capabilities.py:116` 已规范化进 `model_caps`）现成存在，但校验层从未消费它。后果：上游配 keypoint/polyline-only 模型、下游需 ROI，配置期不拦，运行期靠 `skipped_geometry` 静默降级掉。
- 修复：`pipeline_validation.py` 加纯函数 `check_parent_geometry_roi(parent_caps)`——归一化 `supported_geometric_outputs`（兼容 sam3 等词表外别名 `box→bbox` / `mask→polygon` / `both→bbox+polygon`），若上游**完全不含** `bbox`/`polygon` 可裁几何 → 违例。判据「显式自报才拦，缺省放过」，对老 backend 零退化。
  - dispatch 路径：建 `stage号→caps` map（源阶段 `stage=0` = `_stage_model(backend, body.model_id)`），对每个有 `parent_stage` 的下游取父 caps 校验，违例 → `422` 硬挡。
  - save 路径：同判据，违例 → `capability_warnings` 软提示。
  - 判据「至少能产一种可裁几何就放过」（避免误伤 `["bbox","keypoint"]` 这类可能只产 bbox 的模型；部分不可裁交由运行期 `skipped_geometry` 兜底）。

### 修复3（本版暂不实施，待确认）· `output="both"` 同实例双几何被当两父框重复跑

- 位置：`apps/api/app/workers/tasks.py:337` 之后（喂 `crop_inputs_from_boxes` / `geometry_prompts_from_boxes` 之前）。
- 现状：`output="both"`（grounded-sam2 text / yoloe 开集）对同一实例返回「一条 rect + 一条 polygon」严格交错（`ml-backend-protocol.md:251`），两条 shape **无 instance-id 关联**。编排链路无任何去重，`_box_bbox_pct` 对二者一视同仁 → 成为两个独立父框，下游重复裁剪 / 推理 / 富集（缓存键 `(box_idx, pad)` 不同 idx 必不命中），落库两条独立 region。其余模式（box/mask/segment/box-seg/interactive/onnxtools）天然一实例一几何，不触发。
- 为何暂缓：改的是 worker 执行核心，去重会贯穿下标语义（crop `id` → `merge_classify_attributes` → `transform` 回映 → `dropped` 相对 `root_boxes`），且涉及「富集属性挂在保留的 rect 还是 poly、落库两条 region 是否也要合并」的产品语义决策。风险高于 1、2，且 `both` 默认关闭（默认 `mask`），影响面可控。
- 候选方案（待定）：在取到 `parent_boxes` 后、喂下游前，对「外接框高度重合的相邻 rect+poly」做同实例配对，只保留其一作下游父框（rect 与 poly 外接框作 ROI 等价，留 rect 丢 poly 最简），**只影响下游父框选取，不动 root 落库**（`root_boxes = pred_result.result` 引用落库那份，不可原地删）。或更彻底：协议层给 `both` 配对加 instance 标识，供下游按实例编排。
