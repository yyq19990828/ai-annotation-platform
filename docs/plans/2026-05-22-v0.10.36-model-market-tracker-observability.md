## 1. 任务目标与背景

### 1.1 要做什么

模型市场（`ModelMarket`）现在的观测**只覆盖图像类推理**（GPU / 图片变体池 / cache 命中按 `prompt_type=point/bbox/text`）。v0.10.35 已让 gsam2 把 **video 独立池**暴露进 `/health`，本版本补两件事：

- **A. 模型市场 image/video 标题分类**：观测面板按「图像推理 / 视频追踪」分组展示，显存 / cache / 延迟按模态拆分。
- **B. 视频追踪任务聚合监控**：`video_tracker_jobs` 当前只在工作台单 job badge 显示、**无聚合视图**；新增聚合端点 + 监控页（active/running/completed/failed），形态对齐图片侧 preannotate jobs 监控。

### 1.2 为什么做

- 有了真实 video tracker（v0.10.35）后，运维需要在一个地方看到：哪台 backend 在跑视频、video 池占了多少显存、有多少追踪任务在排队/失败——目前这些信息**散落且无聚合**。
- 模型市场的观测信息架构**无任何模态维度**，image 与 video 混在一起读不清。

### 1.3 关键现状（务必先理解）

| | 现状 | 代码位置 |
|---|---|---|
| 模型市场观测面板 | 经 `apps/api` 的 `/admin/ml-integrations/observe` **代理**探测 backend `/health`+`/setup`（前端不直连） | [`ObserveBackendsPanel.tsx`](../../apps/web/src/pages/ModelMarket/ObserveBackendsPanel.tsx)、[`admin_ml_integrations.py` `observe_backends`](../../apps/api/app/api/v1/admin_ml_integrations.py) |
| 变体明细 | cache 命中按 `sam/dino` 变体桶展示，**无模态维度** | [`VariantPanel.tsx`](../../apps/web/src/pages/ModelMarket/VariantPanel.tsx) |
| 性能浮窗 | 订阅 `/ws/ml-backend-stats`，无 `task_type` 标签 | [`PerfHud.tsx`](../../apps/web/src/components/PerfHud/PerfHud.tsx)、[`useMLBackendStats.ts`](../../apps/web/src/components/PerfHud/useMLBackendStats.ts) |
| video tracker job | 只在工作台单 job badge / track 面板显示，**无聚合查询端点** | [`VideoTrackerJob` 模型](../../apps/api/app/db/models/video_tracker_job.py)、[`video_tracker_jobs.py` API](../../apps/api/app/api/v1/video_tracker_jobs.py)（只有 `GET/{id}` + `DELETE/{id}`） |

## 2. 实现方案

### 2.A 模型市场 image/video 标题分类（前端为主）

1. **API 聚合（轻量）**：`observe_backends`（[admin_ml_integrations.py](../../apps/api/app/api/v1/admin_ml_integrations.py)）的 `_probe_one` 透传 backend `/health` 时，把 v0.10.35 新增的 `video_pool` / 按模态拆分的 cache 一并带回（probe 已读 `/health`，只是把新字段透出，**不新增探测**）。
2. **前端分组**：`ObserveBackendsPanel.tsx` 的 `TargetCard` meta 区，按模态分两组标题：
   - **图像推理**：图片变体池 `loaded_variants`、cache hit、latency（现有内容归到此组）。
   - **视频追踪**：`video_pool` 的已加载 / 会话数 / 显存；若 backend 不支持 video（`/setup.supported_trackers` 为空）则此组显示「不支持」。
3. **`VariantPanel.tsx`**：cache 命中表加模态列 / 或拆「图像 cache / 视频 cache」（视 v0.10.35 `/metrics` 实际拆分粒度而定）。
4. **`PerfHud`（可选）**：`BackendSnapshot` 含 `by_type` 时分栏展示 image cache / video active jobs；无则维持现状。
5. **空态 / 兼容**：旧 backend（未升级、无 `video_pool` 字段）→ 视频追踪组显示「该 backend 未上报 video 观测」，不报错。

### 2.B 视频追踪任务聚合监控（后端 + 前端）

1. **聚合查询端点**：[`video_tracker_jobs.py`](../../apps/api/app/api/v1/video_tracker_jobs.py) 新增 `GET /video-tracker-jobs`（管理员 / 按项目权限）：
   - query：`project_id?` / `status?` / `model_key?` / 分页；
   - 返回 job 列表（`status` / `model_key` / `from_frame`/`to_frame` / `direction` / `error_message` / `started_at`/`completed_at` / `created_by`）+ 聚合计数（按 status 分组）。
   - 复用 `VideoTrackerJob` 模型（[video_tracker_job.py](../../apps/api/app/db/models/video_tracker_job.py)），**只加查询、不改写入链路**。
2. **监控页 / 区块**：在模型市场或仪表板新增「视频追踪任务」视图（参考图片侧 preannotate jobs 监控页的信息架构，照搬其列表 + 状态 chip + 分组形态，不自造）：
   - 计数卡：queued / running / completed / failed / cancelled。
   - 列表：可按 status / model_key / project 过滤；failed 行展开 `error_message`。
   - running 行可选接 `/ws/video-tracker-jobs/{jobId}` 实时进度（现有 [`useVideoTrackerJobs.ts`](../../apps/web/src/hooks/useVideoTrackerJobs.ts) 已有单 job 订阅，复用）。

### 2.3 不做（边界）

- 不改 backend 推理 / 显存池 / 协议（那是 v0.10.35）。
- 不做协议统一 / 模态校验 / 注册流程优化（那是 Phase 3.3 / v0.11.0）。
- 不做跨 backend 全局指标大盘（Prometheus/Grafana 侧，另议）；本版本聚焦平台内可见性。

## 3. 验收口径

1. 模型市场观测面板：支持 video 的 backend 显示「图像推理 / 视频追踪」两组，video 池显存 / 会话数正确（与 backend `/health` 一致）；不支持 video 的 backend 视频组显示「不支持」，不报错。
2. 旧 backend（无 `video_pool` 字段）观测面板不崩、降级显示。
3. `GET /video-tracker-jobs` 返回聚合计数 + 列表，过滤 / 分页正确；权限正确（非授权用户拿不到他项目外的 job）。
4. 监控页计数与 DB 实际 job 状态一致；failed 行可见 `error_message`；running 行进度实时更新。
5. 暗色模式 `pnpm lint:css-tokens` 通过。

## 4. 测试（主进程跑）

- API 单测：`GET /video-tracker-jobs` 的过滤 / 分页 / 聚合计数 / 权限（造多状态 job fixture）。
- 前端单测：`ObserveBackendsPanel` 在「有/无 `video_pool` 字段」两种 payload 下的分组渲染；监控页计数/过滤。
- 浏览器自测（preview）：发起几个 video tracker job（含失败），核对监控页计数与面板分类。
