## 1. 结论

本版在 3D 工作台的放大相机视图增加标定管理 Sheet。所有可见用户可查看当前 revision、digest、矩阵和 append-only 历史；超级管理员或项目 owner 可以通过结构化 JSON 更新标定。提交继续使用现有 expected revision / digest 并发合同、append-only 存储和审计日志。

本版不做在线标定求解、控制点编辑、矩阵可视化调参或自动回滚。恢复历史值也是把该快照作为新 revision 提交，不修改或删除旧行。

## 2. 当前事实

- `sensor_calibration_revisions` 已以 `(dataset_item_id, revision)` 保存不可变快照，存量 metadata 标定按虚拟 revision 1 读取。
- 现有 PATCH 端点已校验项目 owner / super admin、`annotations:write`、expected revision / digest，并写入 `sensor_calibration.update` 审计日志。
- 点云 manifest 已向工作台提供当前 calibration、revision 和 digest；标定改变后，持久化多相机成员会按现有合同读为 `stale`。
- 前端尚无标定读写客户端、历史 query 或可达管理入口，只能依赖 API 调用或重新导入数据。

## 3. 用户合同

1. 放大任意有标定的相机后，用户可打开“标定” Sheet；相机切换时 Sheet 自动跟随当前 role。
2. 顶部固定展示相机名、role、当前 revision 和 digest 短摘要；主体展示 intrinsic、extrinsic 和可选 rect。
3. 所有可见用户可读历史；非 owner 的 project admin、标注员、审核员和 viewer 不显示编辑提交动作。跨项目共享同一相机 DatasetItem 时只允许 super admin 修改。
4. owner / super admin 进入编辑后，Sheet 用当前标定生成格式化 JSON；语法、矩阵长度和有限数值在前端先验证。
5. 提交前显示将从哪个 revision 追加；成功只新增一个 revision 与一条审计记录，无变化提交不新增行。
6. 并发冲突不覆盖他人修改；Sheet 刷新最新 revision 并要求用户重新检查草稿。
7. 从历史恢复时先把快照加载为本地草稿，再经过同一确认与并发提交链追加新 revision。

## 4. 数据流与实体边界

```text
point-cloud manifest
  current calibration / revision / digest
                    │
                    ▼
SensorCalibrationSheet
  current status · history · local JSON draft
                    │ GET /calibration
                    ├─────► append-only revision history
                    │ PATCH /calibration + expected revision/digest
                    ▼
sensor_calibration.update audit + new revision
                    │
                    ▼
invalidate manifest / camera members / quality evidence
```

Entity delta: `+0 / -0`。本版只新增一个读端点、前端 query/mutation 和工作台 Sheet；不增加数据库表、列、迁移、环境变量或依赖。

## 7. 风险与回滚

- **矩阵输入风险**：JSON 适合精确传递，但不适合非专业用户。本版只向已有写权限的 owner / super admin 开放，并在前后端双重校验。
- **并发覆盖**：长时间打开的 Sheet 可能基于过期 revision。不自动重放提交，409 后保留草稿且不推进写入凭据；用户必须显式基于最新版重新编辑。
- **共享数据集边界**：标定是 DatasetItem 级真值。跨项目共享相机禁止 project owner 修改，只允许 super admin 执行全局修正。
- **投影与 stale 反馈**：新标定生效后投影、相机成员关系和 Quality 证据必须刷新，但不改动人工 bbox 坐标。
- **回滚**：隐藏入口并移除 GET 与前端组件即可。已追加的 revision 仍是有效审计历史，不删除。

## 8. 最脆弱假设

本计划假设真实项目需要在平台内修正上游标定。如果生产合同规定标定只能通过不可变数据集重新导入，应停止写 UI，保留只读 revision 检查，并把后续产品资源转向跨相机批量复核。
