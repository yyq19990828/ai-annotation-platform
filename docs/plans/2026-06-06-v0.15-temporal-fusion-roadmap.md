# v0.14.x → v0.15 · 时序与传感器融合 Roadmap(scene 地基的后续消费)

> 规划日期 2026-06-06 · 范围:把 v0.14.0 立起的 scene 模型 + v0.14.1 的跨帧 UX + v0.14.2 的真实多 scene/多相机导入实测中**暴露出来的遗留与缺口**,收敛成一条有依赖关系的版本线。本文件是**索引 + 取舍说明**,每个版本的详细计划见各自 plan 文件。
>
> **触发来源**:本 roadmap 的条目全部来自 ① CHANGELOG `[0.14.0]`/`[0.14.1]`/`[0.14.2]` 的「未尽事项 / 已知问题」段;② v0.14.2 真实 nuScenes-mini 端到端实测中实际踩到的坑(apollo 坐标系、sniffer 多相机漂移、帧 stem 撞键——后两者已在 0.14.2 修掉);③ 读 `services/pointcloud_import.py` / `scene_inference.py` / `axis_convention.py` / `useWorkbenchShellModel.tsx` 时发现的硬编码与导航限制。

## 2. 为什么这样切版本

| 版本 | 性质 | 切分理由 |
|---|---|---|
| **v0.14.3** | 补丁(patch) | 全是「让 0.14.2 已交付能力更稳」的项:去硬编码、补导航缺口、放宽上限。**不加表、不加列**,零数据迁移,可快速发。 |
| **v0.15.0** | 次版本(minor) | 引入 `ego_pose` / 时间戳——这是 nuScenes `sample_data` 的等价物,是平台第一次有「车体随时间的位姿轨迹」。**加表/加列 + 迁移**,语义上是新能力,值 minor。本身**不**改 UX,只立地基(与 v0.14.0 立 scene 地基同款策略)。 |
| **v0.15.1** | 次版本(minor) | 跨帧插值 / 批量 propagate / Kalman 都建立在 ego 地基上,是 v0.14.1 跨帧 UX 的「自动化升级」。独立成版以便单独验证插值精度。 |
| **v0.15.2+ / v0.16** | 待定 | 多 lidar、跨 dataset scene、视频 case C 各自重度且互相独立,等前面落地后按需求优先级再排,本期只留草图不写详细计划。 |

## 4. 留草图(v0.15.2+ / v0.16,本期不写详细计划)

每条都重度且与前三版正交,等真实需求出现再立详细 plan。这里只记「是什么 + 已知最大阻塞 + 触发条件」。

### 4.1 多 lidar 数据集(Waymo 5 路 lidar)
- **是什么**:Waymo 一帧有 1 主 + 4 侧 lidar;当前 `pointcloud_import` 假设一帧一个 `primary_lidar`。
- **最大阻塞**:`TaskDatasetItemLink` 的 role 体系要从「单 primary_lidar」扩成「多 lidar role + 融合策略」;前端点云加载要合并多路点云到同一世界系(需各 lidar→ego 外参,依赖 v0.15.0 ego 地基)。
- **触发**:有人真的要导 Waymo / 多 lidar 自采数据。`TFRecord` 解包是另一重依赖,建议仍走离线转换脚本。

### 4.2 scene 跨多 dataset
- **是什么**:一个 scene 的 lidar 帧在 dataset A、image 帧在 dataset B(企业里 lidar 与 image 常分库)。当前 `scenes.dataset_id` 是单 FK,一 scene 隶属一 dataset。
- **最大阻塞**:`scenes.dataset_id` 单 FK + `(dataset_id, name)` 唯一约束要重构成多对多;neighbors 反查的两条路径(`task.dataset_item_id` / `primary_lidar` link)要跨 dataset。
- **触发**:出现 lidar/image 分库的真实数据集。优先级低(可先要求用户合库)。

### 4.3 视频多段 case C(`Alt+→` 分流 `video_tracker_runner`)
- **是什么**:v0.14.1 的 `Alt+→` 跨帧 propagate 在 videoMode 下是 no-op;多段视频(case C)里段内应走 `video_tracker_runner`(已有的 tracker job),段间才走跨 task propagate。
- **最大阻塞**:要在 `useWorkbenchHotkeys` / 壳层里按「当前是段内还是段边界」分流到两套完全不同的机制(tracker job vs propagate 端点);段内 tracker 是异步 job,UX 反馈模型不同。
- **触发**:多段视频标注成为高频场景(目前点云是主战场)。

## 5. 不在本 roadmap(更远 / 明确不做)

- 通用 importer 注册表(`@importer` 装饰器):格式数 < 3 时是过度设计,延续 v0.14.2 结论。
- `axis_convention` 之外的相机畸变系数(D 矩阵)/ 鱼眼模型:当前 `SensorCalibration` 只建模 pinhole;鱼眼相机投影留更后。
- 在线(非离线脚本)导入任意第三方格式:伪需求,延续 v0.14.2 结论。

## 6. 验证总策略(贯穿三版)

- **回归红线**:v0.14.0 立的 `scenes` 表 + neighbors API + v0.14.1 跨帧 propagate + v0.14.2 nuScenes 脚本,三版都**不得破**。每版 `uv run pytest -q` / `pnpm test` / `pnpm lint` 全绿。
- **真实数据复用**:本机已落 `~/data/nuscenes-mini` + 两个已导入 dataset(`DS-NU-nu-scene-0061` 单 scene、`DS-NU-nu-mini-multi` 三 scene),三版的端到端实测直接复用,无需重新下载 4GB。
- **ego 地基(v0.15.0)单独验证**:ego pose 回填后,逐帧 ego 位姿差分应能复原车辆轨迹(BEV 叠加轨迹线肉眼连续);这是 v0.15.1 插值精度的前提。
