# v0.14.9 · 模型能力目录 + OCR / Doc Layout backend 能力

> 规划日期 2026-06-07 · 范围:借鉴 X-AnyLabeling 的模型目录和多模型族适配,在现有 ML Backend `/setup` 能力协商之上新增**模型能力目录视图**与首个非 SAM 新模型族:OCR / 文档布局。保持平台方向:模型运行在独立 ML Backend,前端不下载模型、不直连本地推理。

## 1. 背景

本平台已有:

- ML Backend `/health` / `/setup` / `/predict`。
- Grounded-SAM2 / SAM3。
- 图像批量预标、交互式点/框/文本 prompt。
- video tracker job。
- prediction import / accept / reject。

X-AnyLabeling 的启发不是“再做一个 SAM”,而是它把 OCR、doc layout、属性识别、pose、OBB、tracker、depth 等都放进一个模型能力目录。平台需要同类目录,但不能照搬桌面端本地模型下载和 Qt 推理。

## 2. 目标

### A. 模型能力目录

后端保存 backend `/setup` 派生出的 capability snapshot:

```text
ml_model_capabilities
  id
  backend_id
  provider
  display_name
  model_family
  supported_prompts[]
  output_geometry_types[]
  output_attribute_types[]
  default_thresholds JSONB
  resource_profile JSONB
  setup_snapshot JSONB
  last_seen_at
```

首版不要求用户手填 manifest。`/setup` 是 SoT,目录是派生缓存 + UI 视图。

### B. OCR 能力

新增 ML Backend 输出约定:

- detected text region: bbox / rotated_bbox / polygon
- recognized text:写入 prediction result 的 `attributes.text` 或 `description`
- confidence
- optional language / orientation

采纳后:

- 生成普通 annotation。
- text 写入 annotation attributes。
- 若项目未配置 text attribute,前端提示“可采纳几何,文本字段不会入库”或要求配置。

### C. Doc Layout 能力

输出:

- region class: title / paragraph / table / figure / formula / list / header / footer
- bbox / polygon
- optional OCR text

目标场景:

- 文档图片标注。
- OCR 校对。
- 表格/版面区域检测。

## 3. 非目标

- 不做前端本地模型下载。
- 不把 X-AnyLabeling YAML 直接作为平台配置格式。
- 不做 Depth/RMBG 派生资产;它需要 asset lifecycle,顺延。
- 不做训练队列。
- 不做 AI Agent 反向拉任务;那是中长期。

## 4. 后端设计

### 4.1 capability 派生

扩 `ml_capabilities` 派生逻辑:

```json
{
  "model_family": "ocr",
  "supported_prompts": ["none", "bbox"],
  "outputs": [
    {"geometry": "rotated_bbox", "attributes": ["text", "language"], "confidence": true}
  ],
  "default_thresholds": {"text_confidence": 0.5},
  "resource_profile": {"device": "cpu|gpu", "batchable": true}
}
```

保持兼容:

- 老 backend 不返回这些字段时,只显示 legacy capabilities。
- 目录刷新由 backend health/setup 轮询或手动 refresh 触发。

### 4.2 prediction result 映射

OCR / layout 输出仍进现有 `Prediction.result` 的 LabelStudio-compatible shape 或 AAP internal adapter,不要新增 prediction 表结构。

建议统一 adapter:

- `ocr_text` → `attributes.text`
- `layout_type` → `class_name`
- `orientation` → `attributes.orientation`

### 4.3 API

```text
GET /ml-backends/capabilities
GET /ml-backends/{id}/capabilities
POST /ml-backends/{id}/capabilities/refresh
```

批量预标入口扩展:

- `task_type=ocr`
- `task_type=doc_layout`
- 可选 `model_family` 过滤。

## 5. 前端设计

### A. 模型市场/后端观察页

新增能力目录视图:

- 按 model_family filter: segmentation / detection / ocr / layout / tracker / depth。
- 显示 prompt 类型、输出几何、输出属性、batchable、资源要求。
- 对当前项目 tool_bindings 做 compatibility check:
  - 输出 class 是否在项目类别内。
  - text attribute 是否存在。
  - geometry 是否被当前 tool_unit 支持。

### B. OCR / Layout 预标入口

在 AI Pre-Annotate 增:

- OCR text regions
- Document layout

Dry-run preview:

- 检测到的区域数。
- 文本字段样例。
- class 映射缺失警告。

### C. Workbench 候选展示

预测列表显示:

- OCR 文本摘要。
- layout type badge。
- confidence。

采纳时把文本写入 attributes。

## 6. 测试与验证

后端:

- setup snapshot 派生 OCR capability。
- 老 backend 缺字段兼容。
- OCR prediction result → internal geometry + attributes 映射。
- dry-run class/attribute compatibility warning。

前端:

- capability catalog filter。
- OCR backend 与项目 schema 兼容/不兼容提示。
- 预测列表展示 text。
- accept 后 attributes payload 正确。

手工:

- mock OCR backend 返回 3 个 text boxes。
- 采纳一个 bbox + text。
- 项目缺 text attribute 时提示正确。

## 7. 后续

- `Depth / RMBG` 派生资产 overlay:需要 task asset 表或 artifact lifecycle。
- `Model pipeline` 能力:GroundingDINO + SAM2 / OCR + layout 后处理。
- `AI Agent`:用户私有 GPU 反向拉任务。
- `Backend SDK/starter`:顺延到 v0.15 SDK 计划。

## 8. 风险

- **schema 膨胀**:不要为每个模型族扩 prediction 表;统一走 result + adapter。
- **文本属性落点**:项目 schema 未配置 text 时不能静默丢文本。
- **目录与真实 backend 漂移**:capability 必须有 `last_seen_at`,UI 标明 stale。
- **模型市场误导**:目录只说明能力,不承诺平台托管权重。
