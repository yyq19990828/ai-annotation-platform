# Plan · 视频 AI 传播 UI 形式统一 + PVS 完整交互

状态：**草拟 2026-07-10 · 版本锚点 v0.21.27**（v0.21.26 = 已完成的 B-pvs 后端/平台/前端选项；本 plan 的「UI 形式统一 + PVS 完整交互」顺延 v0.21.27，并接管 [v0.21.25 多目标 epic](2026-07-07-v0.21.25-video-multi-target-tracking-epic.md) 原「阶段 U」的视频 AI 传播 UI/UX 工作）。

## 目标（经用户校正）

**核心不是「把三处抽成一个共享原语」，而是让视频 AI 传播 UI 的形式对齐图片侧那套已经一致的交互形式**，并补齐 PVS 的完整交互（点/框种子 + 中途纠偏）。

- 图片侧的 **SAM 交互工具集** 与 **选中标注二次推理** 前端形式**已经一致**（顶部居中悬浮工具条 + 画布交互 + 候选/接受流程）；此为**参照形式，不动它**。
- 图片「当前题 AI」面板（整题重推）**保持不变**（作用域是整图、开关是用户级偏好，不强行改成选中标注级）。
- **要重构的是视频侧 AI 传播**：它现在是一个独立顶部对话框（`VideoTrackerPropagateDialog`），与图片侧的交互形式割裂。让它并入同一套**顶部居中悬浮工具条**形式。

**已锁决策（2026-07-10）**：① 定位**保持顶部居中**（非锚定选中标注）；② 中途纠偏**分两步、紧随**（当前版先落点/框种子+多目标+形式统一，纠偏单列下一期）；③ 不抽共享原语、不动「当前题 AI」，目标是形式一致。

## 设计：视频 AI 传播并入「顶部居中悬浮工具条」形式

### 形式统一（不抽原语，共用壳与选择器）
- 视频 tracker 的编排控件（方向/范围/模型/变体）从独立对话框 `VideoTrackerPropagateDialog` **迁到与 `InteractiveToolBar` 同壳同风格的顶部居中工具条**（复用引擎/变体选择器组件、能力状态点、`z-*` 层级约定）。保留「留出底部时间轴」的无背板特性。
- 触发保持现有入口（Ctrl+B / 右键「AI 追踪」/ 选中卡按钮 / 侧栏），但打开的是**新形式工具条**而非对话框。
- **不动**图片「当前题 AI」面板；图片 SAM 交互/二次推理形式作为参照，不改。

- **U1 方向标签消歧（小）**：`forward→「向后」/ backward→「向前」`读起来像倒放。改「更晚帧 →」/「← 更早帧」/「⇆ 双向」+ `title` 悬浮，按钮加 `data-testid=tracker-direction-*`。
- **U3 模型可读名（小）**：下拉裸 key → 人类可读名 + 能力一句话（SAM2·框追踪 / SAM3·文本检测追踪 / SAM3·点框交互追踪 / mock·测试）。只改 `label`，`value` 不动（测试按 value 断言，零回归）。

## 风险 / 边界

- **形式统一别回归现有交互**：视频侧已有的 SAM 帧级交互（`onVideoSamPrompt`）与 tracker 是两条链，工具条统一时别把二者语义混了（帧级分割 vs 跨帧追踪）。工具条按「当前意图」切段。
- **对话框→工具条迁移**：`VideoTrackerPropagateDialog` 的既有入口/键位/提交路径（`openPropagateDialog`/`trackerJobs.propagate`）要平滑迁移，先并存再切换，避免中途破坏可用的追踪。
- **纠偏 (b) 无状态方案的语义**：重发累积 prompt 重跑整窗，纠偏点越加越多时窗内一致性 / 性能需实测；(a) 有状态会话是后备。
- **不碰「当前题 AI」**：整题重推是另一作用域，本 plan 明确不动，避免 scope 蔓延。
- **暗色/token 红线**：新工具条全走语义类 + `--sc-*`（CLAUDE.md §6）。
