# v0.18.20 · onnxtools 预标可见 + 加载/卸载能力暴露

> 草案 (2026-06-25). 独立清理项，与 yolo 开集 epic ([v0.18.21](2026-06-25-v0.18.21-yolo-openvocab-text-detection.md) 起) 解耦，可单独发版。
> 来源: `third-party/plan` 第 3 行 ——「onnxtools 在预标注配置界面没有模型显示(同时暴露出来没有加载 卸载模型的能力)」。

## 1. 背景

onnxtools-backend (车辆属性 vehicle-attribute) 是平台第四个 ML backend。当前有两个用户可见缺口:

- **(A) 预标注配置界面不显示模型** —— 选中 onnxtools backend 后看不到可选模型。
- **(B) 无加载/卸载能力暴露** —— model market 不展示它的预热/已加载/卸载状态，尽管后端实际已实现 `/unload` + idle-unload。

## 2. 根因 (代码核对)

### (A) 模型不显示

前端预标配置用 `GEOMETRIC_TASKS` 白名单过滤模型:

- `apps/web/src/pages/AIPreAnnotate/components/usePreannotateConfig.ts:38` ——
  `GEOMETRIC_TASKS = ["detection", "segmentation", "keypoint", "obb"]`
- 几何路径过滤 (`:146-150`)、文本路径过滤 (`:169-177`) 都要求 `task ∈ GEOMETRIC_TASKS`。
- `primaryModel` 取第一个 `task ∉ [ocr, doc_layout]` 的模型 (`:139-144`)。

onnxtools `/setup` 的纯分类模型声明 `task: "classification"` (`apps/onnxtools-backend/main.py:225`)，**不在 `GEOMETRIC_TASKS` 内** → 被几何/文本路径双双过滤。其检测类模型 (`task: "detection"`) 理论上应显示，**需在实现期实测确认到底哪个模型该出现、是否还有别的过滤把整个 backend 排掉**。

协议词表 `apps/_shared/protocol_v2/src/aap_protocol_v2/vocab.py` 的 `TASK_VALUES` 含 `classification`，但前端 `GEOMETRIC_TASKS` 常量与之脱节。

### (B) 无加载/卸载能力

- 前端 model market 判定 `canGenericWarm = setup?.warmup_endpoint === true`
  (`apps/web/src/pages/ModelMarket/VariantPanel.tsx:156-172`)。
- onnxtools `/setup` (`apps/onnxtools-backend/main.py:243-258`) **未声明 `warmup_endpoint`**(默认 false)，且**未实现 `/warmup` 端点** → `canGenericWarm=false`，model market 不展示预热/已加载。
- 但 onnxtools **已实现 `/unload`** (`main.py:266-272`) + idle-unload (v0.18.13)。**声明与实现不一致**，注释 (`main.py:14`)还写着「无 warmup」。
- 缺 model 级 `supported_variants`/`default_variants`，平台无法统一理解「该模型是否有变体/可否单独加载」。

对照: yolo `/setup` 含 `warmup_endpoint: True` (`apps/yolo-backend/main.py:399`)，sam3 含 `warmup_endpoint: True` (`apps/sam3-backend/main.py:347`)。

## 3. 目标 / 非目标

**目标**
- onnxtools 模型在预标配置界面正确出现且可选。
- model market 正确展示 onnxtools 的预热/已加载/卸载状态。

**非目标**
- 不为 `classification` 引入新的前端渲染器/标注 result type。
- 不重构 `GEOMETRIC_TASKS` 协议语义 (避免牵动其他 backend)。

## 4. 设计与改动

### 4.1 后端 onnxtools `/setup` 与端点 (主改)

`apps/onnxtools-backend/main.py`:
1. 实现 `POST /warmup`: 加载模型句柄到显存，返回协议 §4.4 格式 `{ok, model_load_ms, cache_hit, evicted}`。单档无变体，body 可空。
2. `/setup` 声明 `warmup_endpoint: True`。
3. 各 model 条目补 `supported_variants: []` + `default_variants: {}` (空=无变体)。
4. 修正 `main.py:14` 注释，使其与「`/unload` + idle-unload」实现一致。

### 4.2 模型可见性 (二选一，实现期实测后定)

- **方案 A (推荐)**: onnxtools 把要在预标出现的「检测+属性一锅端」模型保持 `task: "detection"`(语义=ROI 检测框 + 属性)，纯分类的 `vehicle-attr-classify` 若不需进预标则维持 `classification`。**先实测哪个模型该出现**，再决定是否调 task。最小改动，不动前端。
- **方案 B**: 前端 `usePreannotateConfig.ts` 增加 `CLASSIFICATION_TASKS` 路径让分类模型也能进预标。牵动面更大，**仅当确有纯分类预标需求时才做**。

> ⚠️ 开放问题: 「预标配置界面没显示」具体指哪个视图(预标配置表单 / 能力目录 / model market)、期望出现哪几个 model —— 实现首步先在本地栈选中 onnxtools 复现，定位精确过滤点，再选 A/B。

## 5. 验收
- 预标配置选 onnxtools backend → 目标模型出现在可选列表。
- model market 显示 onnxtools 预热按钮 + 已加载状态；点预热触发 `/warmup` 成功，`/unload` 卸载成功。
- `/setup` 字段与 yolo/sam3 对齐 (`warmup_endpoint`、model 级 variants 字段齐备)。

## 6. 风险
- onnxtools GPU 资源: `/warmup` 真加载需确认显存够 (与 yolo/sam3/gsam2 同卡共存)。
- 方案 B 改前端过滤可能影响其他 backend 的预标列表，需回归 yolo/gsam2/sam3 的预标配置。
