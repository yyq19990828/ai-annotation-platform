# v0.21.31 · `yolo-frames-seg` 用户可达

状态：**已核对代码，可实施（2026-07-12）**。多几何 track 尾项中的最小修复版：后端 serializer / 打包 / 模态
校验均已交付并有单测，本版只补前端入口、类型合同和用户文档事实同步，不改 serializer 或导出目录结构。

上游索引：[多几何 track 剩余切片](2026-07-12-multi-geometry-track-remaining-slices.md)。

## 背景与现状（已逐项核对）

- `apps/api/app/services/export_video.py:224` 的 `build_yolo_frame_seg_labels` 已交付：单帧 `video_polygon` 按所属帧
  导出，`video_track_polygon` 按弧长插值展开到项目采样网格，行格式与图片 `yolo-seg` 共用 `yolo_seg_line`。
- `apps/api/app/services/export_packaging.py:80` 已把 `yolo-frames-seg` 加入 `VIDEO_EXPORT_FORMATS`，多目标打包能生成
  `yolo-frames-seg/` 子目录、`data.yaml`、`manifest.json` 与 `fetch_frames.py`。
- `clean_export_targets`（同文件 `:91`）**已做模态白名单**：视频项目接受、图片/点云项目拒绝该 target，端点转 400。
  已有单测 `test_clean_export_targets_accepts_video_yolo_frames_seg` 与
  `test_clean_export_targets_rejects_yolo_frames_seg_for_image_project` 覆盖。
- 后端 ZIP 行为已被 `apps/api/tests/test_export_packaging.py` 覆盖：`test_yolo_frames_seg_keeps_polygon_vertices`、
  `test_yolo_frames_seg_expands_polygon_track_per_frame`、`test_yolo_frames_seg_skips_bbox_and_polyline`。
- `docs-site/user-guide/reference/export-formats.md` 的**格式 × 项目类型对照表**已列出 `yolo-frames-seg`（行 16 / 32 /
  33，以及几何导出说明行 44）。但同文档的**视频详解段**（§357 概览列表、§365 逐帧小节、ZIP 树）仍只提 det。

前端缺口（本版要补的实际差距）：

- `apps/web/src/api/projects.ts` 的 `ExportFormat` / `ExportTarget` 两个手维护字面量联合缺 `yolo-frames-seg`
  （均已含 `yolo-frames-det` 可作添加位参照，非 codegen 生成，无需重跑 codegen）。
- `apps/web/src/pages/Dashboard/ExportModal.tsx` 的 `VIDEO_OPTIONS` 无该项，用户无法从正常 UI 发起。
- `docs-site/user-guide/projects/batch.md` 视频格式表（行 218）与散文（行 228）只提 `yolo-frames-det`。

这不是新格式开发，而是“后端和文档对照表已宣称交付，前端不可达”的产品缺口。

## 目标

- 视频项目导出弹窗出现「YOLO 逐帧分割」并能提交准确 target；
- 图片 / 点云项目不出现该视频专属项；
- 用户文档（batch 表 + export-formats 详解段）与 UI、后端 allowlist 一致；
- 不触碰已经工作的逐帧 polygon 序列化与后端目录结构。

## 工作项

### WS1 · 前端 target 合同

- `apps/web/src/api/projects.ts`
  - `ExportFormat` 在 `yolo-frames-det` 后增 `yolo-frames-seg`；
  - `ExportTarget` 在 `yolo-frames-det` 后增 `yolo-frames-seg`；
  - 保留 `yolo-seg`（图片项目目标）不动，两者不得互相映射。

### WS2 · 导出弹窗

- `apps/web/src/pages/Dashboard/ExportModal.tsx`
  - `VIDEO_OPTIONS` 在 `yolo-frames-det` 之后增一项，`value: "yolo-frames-seg"`；
  - label 用「YOLO 逐帧分割」——与既有「YOLO 逐帧」不同串，避免测试 `getByText` 命中歧义；
  - description 与 det 卡片同风格并点出几何差异，例如：
    「按采样网格抽帧，导出分割训练用 labels（保留多边形顶点；bbox / polyline 跳过）。」
  - 不引入新的帧模式控件：`showFrameMode` 仅在选中 `video_json` 时出现，seg 与 det 一样总按采样网格展开，
    不消费 `keyframes | all_frames`，无需改 `handleExport` 的 `showFrameMode` 透传逻辑。
- 多目标行为沿用现有 `toggleTarget`：与其它 target 同选时后端自动落 `yolo-frames-seg/` 子目录，前端无需特判。

### WS3 · 测试与文档

- `apps/web/src/pages/Dashboard/__tests__/ExportModal.test.tsx` 增用例：
  - video 项目弹窗显示「YOLO 逐帧分割」（沿用现有 `projectTypeKey="video-track"` harness）；
  - 选中后 `exportProject` 的 `targets` 精确等于 `["yolo-frames-seg"]`；
  - 与 `yolo-frames-det` 同选 → `targets` 同时含两者、互不覆盖；
  - 现有 image / lidar 用例已断言不出现视频专属项，保持不回归即可，无需为隐藏另写用例；
  - 现有「视频项目展示视频目标」用例（`queryByText("YOLO")` 断言 image-only YOLO 分组不出现）需保持通过：
    新 label 是「YOLO 逐帧分割」整串，不等于 `"YOLO"`，精确匹配下不受影响，但落地后要跑一遍确认。
- `docs-site/user-guide/projects/batch.md`：视频格式表行补 `yolo-frames-seg`；散文补一句「保留多边形顶点、bbox/
  polyline 跳过」，与 det 段并列。
- `docs-site/user-guide/reference/export-formats.md`：格式对照表已就位，只校准视频详解段——
  - §357 概览列表「YOLO 逐帧」→ 明确为「YOLO 逐帧检测 / YOLO 逐帧分割」；
  - §365 det 小节之后补一段**紧凑**的 `yolo-frames-seg` 说明（行格式=图片 YOLO seg 同构归一化多边形；来源=单帧
    `video_polygon` 按帧 + `video_track_polygon` 弧长展开；bbox/polyline 跳过），不重写整套 ZIP 树叙述。
- `CHANGELOG.md` 在 `Unreleased / Fixed` 记录“已存在的视频逐帧分割导出现在可从导出弹窗发起（此前仅后端与格式表
  存在、UI 不可达）”。

## 验收

- 视频项目弹窗能勾选「YOLO 逐帧分割」并成功派发 `yolo-frames-seg` 异步导出；
- 现有后端测试全绿：polygon labels、空帧 txt、真实采样网格、`manifest.json`、`fetch_frames.py` 不变；
- 图片 / 点云项目提交该 target 仍由前端（不渲染选项）与后端（`clean_export_targets` 400）共同阻止；
- 不修改 `build_yolo_frame_seg_labels` 与现有各格式输出目录结构。

## 非目标

- `coco-frames-seg`（见 v0.21.33）；
- raster mask / DAVIS（见 v0.22.0）；
- polygon holes 的 YOLO 表达；
- 视频导出打包真实帧图；
- 对 ExportModal 做无关视觉重构或帧模式语义变更。
