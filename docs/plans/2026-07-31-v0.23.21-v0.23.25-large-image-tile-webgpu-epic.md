## 1. Epic 目的

本 Epic 同时解决两个相关但不能混为一谈的问题：

1. **超大图浏览**：当前 `ImageStage` 仍以一个 `HTMLImageElement` 解码整张背景图。
   图片达到约 50MP 以上时，下载字节、解码后 RGBA、浏览器纹理与 Konva 重绘都可能成为瓶颈。
2. **大尺寸 Raster Mask 计算**：WebGPU 已可作为客户端大 ROI、方形膨胀
   `square dilate` 的可选计算后端，但仍需优化当前计算核、CPU fallback 数据面、与背景 tile
   的资源竞争，并补齐真实跨平台资格证据。

目标不是把整个图片工作台改成 WebGPU renderer。目标架构是：

```text
服务端源图
  └─ immutable image pyramid
       └─ manifest + authenticated overview/tile URL batch
            └─ viewport/LOD scheduler
                 └─ bounded ImageBitmap/HTMLImageElement LRU
                      └─ Konva background tile layer

canonical Raster Mask RLE
  └─ persistent Dedicated Worker session
       ├─ CPU exact backend（所有客户端必有）
       └─ WebGPU packed square-dilate backend（客户端能力候选）
            └─ existing XOR history patches

共享：full-resolution 坐标、viewport、任务 generation、客户端资源档位、压力信号
隔离：背景 tile 内容、Mask tile 真值、Mask history、GPU buffer
```

## 2. 当前源码事实

### 2.1 已有能力

- Raster Mask 编辑已使用 512px sparse tile、视口 ROI、持久 Worker session、字节预算和
  canonical COCO RLE 保存。
- WebGPU provider 只在大 ROI `square dilate` 时惰性请求客户端 adapter；无
  `navigator.gpu`、adapter 不可用、初始化中、预算不足、device lost 或 runtime failure
  均可精确回退 CPU Worker。
- WebGPU 成功路径已从 immutable base RLE 与 dirty override 构造 packed source，只回读
  dense core XOR words，并用 CPU word-scatter 生成现有 history patches。
- `ImageStage` 已能把 full-resolution viewport bbox 传给 tiled Mask editor，可作为背景 tile
  scheduler 的坐标输入。
- `useRasterMaskRecords` 已有按 `navigator.deviceMemory` 分档的缓存预算与显式
  `ImageBitmap.close()` 资源计数，可复用设计原则。

### 2.2 仍缺失

- `ImageStage` 背景仍通过 `useImage(fileUrl)` 整图解码，并以单个 `Konva.Image` 绘制。
- 邻题预取、Minimap 的原图回退、评论/画布预览等消费者仍可能直接使用 `file_url`，超大图模式下
  会绕过主画布的 tile 优化。
- 服务端只有 thumbnail / blurhash，没有可寻址的 immutable image pyramid、状态模型、
  manifest、tile 授权批签和派生资产清理合同。
- 背景 tile、Raster Mask render cache、Mask edit tiles、history、Worker scratch 与 GPU buffer
  尚无 task-scoped 压力协调；各自满足局部预算时仍可能共同造成峰值。
- 当前 WebGPU shader 在一个 pass 内对每个输出 word 扫描垂直行并执行水平扩张；大 radius
  存在可分离两阶段候选，但尚无 production A/B。
- 大 ROI square dilate 的 CPU fallback 已使用 packed separable winner，并与 GPU 共享同一 packed
  source；CPU/GPU budget、cooldown/page-fixed circuit 与最近 20 次 typed diagnostics 已独立。
- v0.23.19 的 `dense-per-bit` benchmark selector 和旧 per-bit builder 已从 production protocol 删除；
  direct packed kernel 只保留为 test/benchmark oracle。
- macOS Metal、Linux Wayland、Windows D3D12 的无额外 flag 长会话与 dispose 矩阵仍未完成。

## 3. 冻结决策

### D1. 背景 tile 不依赖 WebGPU

超大图背景以浏览器图片解码、`ImageBitmap`/`HTMLImageElement` 与 Konva Canvas2D 绘制。
没有 GPU、WebGPU 被禁用或 adapter 丢失的客户端仍必须完整浏览、缩放、平移和标注超大图。

浏览器可能自行用 GPU 合成 Canvas2D，但这不是产品能力合同，也不做显式依赖。

### D2. WebGPU 的产品边界保持不变

WebGPU 仍是**客户端大尺寸 Raster Mask 方形膨胀的可选计算后端**：

- 不用于 H.264/HEVC 解码；
- 不用于背景 tile 解码或 Konva 通用渲染；
- 不调用 Linux API/Celery 部署机器的 GPU；
- 本 Epic 不扩展到 `erode`、`open`、`close`、disk kernel、component labeling 或 COCO RLE；
- 不建立 GPU-resident mutable current Mask；
- 无能力时使用同一持久 CPU Worker 返回同格式 exact XOR patches。

### D3. 背景 tile 与 Mask tile 是两套资源

两者都采用 512px 逻辑 tile 便于坐标和预算推导，但不得：

- 让背景 tile 成为 Mask 真值；
- 让 Mask tile 缓存负责背景 LOD；
- 将背景编码格式或 overlap 写入 Mask history；
- 因其中一套 eviction 破坏另一套 correctness。

它们只共享：

- full-resolution image coordinate space；
- viewport 与 task/scope generation；
- `editing truth > minimum visible coverage > current detail > prefetch` 优先级原则；
- task-scoped 客户端资源档位与压力/暂停信号。

### D4. 使用平台自有 immutable pyramid v1，不宣称完整 IIIF

首版采用平台自有、content/version-addressed manifest 与预生成 tile：

- manifest 表达 full-resolution 尺寸、tile core、overlap、scale factor、level 尺寸、
  编码和坐标 rect；
- 客户端通过 `ImageTileSource` adapter 消费，不把内部路径写死在 Konva layer；
- manifest 结构借鉴 IIIF Image API 3 `tiles` / `scaleFactors`，但没有实现完整 region/size/
  rotation/quality URI 语义时不得宣称 IIIF compliant；
- 后续确有外部互操作需求时可新增 IIIF adapter，不重写 scheduler。

### D5. libvips 是有退出门的服务端候选

Pillow 当前 thumbnail worker 会把整个对象读入内存，不适合作为 50MP–250MP 金字塔的默认生成器。
v0.23.22 先以 `libvips`/`pyvips` Deep Zoom 能力做 RSS、耗时、格式、色彩与部署 A/B：

- 通过门后作为大图 generator；
- 未通过时不得用无界 Pillow 全图 load 冒充 fallback；
- 小图 thumbnail 现有 Pillow 路径可保持；
- generator 不可用时标记稳定失败并保持 thumbnail/overview；required 大图自动路径不得请求原图，
  只有用户显式 override 且 decoded-byte admission 通过时才允许受控 single-source fallback；
  不写半个 ready manifest。

参考：

- [libvips `dzsave`](https://libvips.github.io/pyvips/vimage.html#pyvips.Image.dzsave)
- [IIIF Image API 3](https://iiif.io/api/image/3.0/)

### D6. full-resolution 坐标是唯一几何真值

标注、Raster Mask RLE、Issue pin、Minimap viewport 与所有工具继续使用 full-resolution
image pixels/normalized coordinates。LOD 只影响背景采样：

- level/tile rect 必须显式映射回 full-resolution 半开区间；
- edge tile、非 2 次幂尺寸、overlap crop、EXIF orientation 与色彩转换必须有 golden fixture；
- 不允许用浮点累计位置推导相邻 tile，避免 seam 与点击偏移；
- 已存在标注的图片若 orientation/dimensions 合同无法证明一致，pyramid v1 不得自动激活。

### D7. 降级是状态机，不是 catch-all

客户端图像源按以下顺序工作：

```text
pyramid ready
  → viewport tiles
  → lower-resolution level coverage
  → thumbnail/blurhash

pyramid unavailable or gate off
  → estimated full decode within client budget ? existing single-image path
  → otherwise thumbnail + explicit unavailable/retry state
```

Raster Mask 计算按以下顺序工作：

```text
operation supported + ROI/limits/budget + WebGPU ready + route winner
  → WebGPU
  → same-request CPU fallback on GPU runtime failure

otherwise
  → CPU Worker directly
```

任何降级都不得产生 partial tile commit、partial history 或跨任务迟到写入。

### D8. 不恢复已被 v0.23.19 否决的复杂度

本 Epic 不重新引入：

- atomic sparse XOR records；
- prefix-sum compaction；
- GPU 直接生成 history tile payload；
- 多 GPU job/readback ring；
- GPU-resident mutable current source；
- 以 timestamp query 为 correctness 或运行依赖。

新 WebGPU candidate 未通过端到端门时删除 shader/buffer/protocol/metrics 分支，不留默认不可达死代码。

## 5. Epic 成功定义

Epic 只有同时满足以下条件才算完成：

1. 50MP 与至少 200MP fixture 在 pyramid 路径不创建 full-resolution
   `HTMLImageElement`/`ImageBitmap`，首屏只请求 manifest、coverage level 与可见 tile。
2. 背景 tile 在 pan/zoom、fit、focus-selection、Minimap 跳转与任务切换中保持 full-resolution
   坐标 exact，无可见 seam、错位或旧任务 tile。
3. tile cache 以解码后字节计费，visible tile pin、prefetch eviction、`ImageBitmap.close()`、
   abort 与 dispose 有显式计数，长会话进入 plateau。
4. `navigator.gpu` 缺失、WebGPU gate off、adapter null、初始化失败、预算不足、
   device lost 与 runtime error 时，超大图浏览不受影响，Mask `square dilate` 使用 CPU
   Worker 且结果与 canonical oracle bit-exact。
5. WebGPU 只保留通过端到端 A/B 的 kernel；候选 no-go 时 production source 不残留
   unused shader/buffer/protocol 分支。
6. 背景 tile prefetch 在 Mask 编辑/计算压力下可暂停或降优先级；共同峰值不突破 task-scoped
   客户端预算，交互 foreground 不被 prefetch 饿死。
7. 小图 single-image 路径的请求数、首屏、交互与视觉回归在门内，不因本 Epic 强制创建
   pyramid 或请求 adapter。
8. 服务端 pyramid generation 有幂等、单飞、超时、重试、半成品清理、source drift、
   鉴权、tile coordinate validation 与派生资产回收合同。
9. Linux X11/Wayland、macOS Metal、Windows D3D12 至少完成计划矩阵；没有相应机器的项必须
   明确记录 `not tested`，不能从其他平台外推。
10. 运维可独立关闭 image pyramid auto-generation/selection 与 Raster Mask WebGPU；
    任一回滚不改变 annotation/Mask 存储格式。
11. 无 GPU 客户端的 packed CPU candidate 若通过门，GPU runtime failure 必须直接复用同一
    packed source 计算 XOR，不再回头构造 dense alpha；若 candidate 未过门，则保留并明确报告
    dense CPU 基线，不以局部 bytes 改善宣称成功。
12. 现有 one-pass WebGPU capability-first gate 保持当前 default true 基线，除非已观测到
    correctness/resource 问题；缺少某平台机器时必须标记 unqualified/not tested，但不据此伪造
    失败或自动关闭既有路径。新的 separable candidate 只有完成计划资格矩阵并通过端到端门才可
    进入 production，否则保持 benchmark-only 并删除 production 分支。

## 6. 联合资源合同

### 6.1 预算类别

task-scoped coordinator 至少观测：

- decoded background tile bytes；
- pending tile decode reservations；
- committed Raster Mask render bitmap/alpha/RLE；
- editable Mask materialized tile；
- Mask history；
- Worker packed base cache 与 scratch；
- WebGPU logical buffer capacity。

浏览器不提供可靠的总 GPU memory 数值，因此预算是应用自身的保守逻辑计账，不伪装成显存实测。

### 6.2 优先级

```text
editing Mask source/history
  > minimum visible lower-resolution coverage
  > visible full-detail background + selected/current Raster Mask render
  > directional neighbor background prefetch
  > adjacent task prefetch
```

- foreground 已 admission 的操作不得被后来 prefetch 挤出；
- tile decode reservation 必须在请求前 prospective admission；
- 任一时刻 `committed + outstanding reserved` 的去重 charged bytes 不得突破 global hard budget；
- Mask operation 开始时暂停新 background prefetch，不销毁已可见 tile；
- pressure 恢复后按 generation 重新评估，不恢复 stale 请求。

## 7. 基线与验收矩阵

### 7.1 Fixture

至少固定：

- 8K/约 33MP：确认不误触大图门；
- 50–67MP：默认激活边界；
- 16K×16K/约 268MP：超大正方形、edge tile 与内存压力；
- 非 2 次幂约 200MP：level/edge/rect golden；
- JPEG、PNG alpha、灰度、ICC、EXIF orientation；
- dense/sparse Raster Mask 与 radius `1/8/31` square dilate；
- corrupt tile、missing tile、expired URL、slow response、decode failure。

fixture 不必全部入 Git；可用 deterministic generator + digest manifest，CI 保留小型等价样本，
production qualification 使用外部大 fixture。

### 7.2 必测客户端状态

| 图片后端     | WebGPU          | 预期                                                     |
| ------------ | --------------- | -------------------------------------------------------- |
| single image | unavailable/off | 现有小图路径等价                                         |
| pyramid      | unavailable/off | tile 浏览完整；Mask CPU exact                            |
| pyramid      | initializing    | 当前 Mask 操作 CPU；tile 不等待 adapter                  |
| pyramid      | ready/winner    | tile 仍走 Canvas2D；仅 eligible square dilate 走 GPU     |
| pyramid      | device lost     | tile 不闪退；同请求 CPU fallback；后续 cooldown          |
| pyramid      | tile failure    | lower LOD/thumbnail 覆盖；Mask truth 与 history 不受影响 |

### 7.3 性能原则

- 只比较同 bundle、同 fixture、同浏览器、同机器的 A/B；
- cold、warm、快速 pan/zoom、Mask foreground 四类场景分开；
- 至少 `3 warmup + 10 measured`、两轮，报告 p50/p95；
- 端到端指标优先于局部 shader、bytes 或 map time；
- Long Task、live bitmap、pending request、Worker session、GPU buffer capacity 与 dispose
  必须共同报告。

## 8. Rollout 与回滚

独立控制面：

- 服务端 `IMAGE_PYRAMID_AUTO_GENERATE`：是否自动为 eligible 图片生成；
- 客户端 `VITE_EXPERIMENTAL_LARGE_IMAGE_TILES`：是否选择 pyramid source；
- 既有 `VITE_EXPERIMENTAL_RASTER_MASK_WEBGPU`：是否包含/尝试 WebGPU provider。

要求：

- 小图从不因 pyramid gate 开启而请求 manifest/tile；
- tile gate 关闭时 WebGPU 行为与当前版本一致；
- WebGPU gate 关闭时 tile 行为与 CPU-only 构建一致；
- 回滚不删除 source、annotation、RLE 或 history，只停止选择派生/加速路径；
- 生成失败的半成品可清理并重建，ready manifest 必须 immutable。

## 9. 明确非目标

- 不实现完整 IIIF level 1/2 动态 region server；
- 不让前端即时切原图生成 tile；
- 不通过 API 进程代理所有 tile body；
- 不用 Service Worker/Cache Storage 作为首版 correctness 依赖；
- 不改变 annotation 几何、Raster Mask RLE 或导入导出格式；
- 不为背景引入 WebGL/WebGPU scene graph；
- 不把 WebGPU 能力与服务端 Linux GPU、ML Backend GPU 仲裁混合；
- 不在本 Epic 扩大 Raster Mask morphology operation 支持面；
- 不加入未经 A/B 的 WASM/SIMD、subgroup 或 vendor extension；
- 不把 performance.memory 当作唯一资源证据。

## 10. 计划维护规则

- 每个版本实施前固定 baseline commit，并把实际 hash 写回对应计划。
- candidate no-go 必须记录数据与删除范围，不能只写“效果不好”。
- 跨版本移交只允许使用本 Epic 已列明的后续项，不把未完成任务悄悄标为 release。
- 每个子计划完成后追加 `## Outcome`，同步 ADR、开发/运维/用户文档与 CHANGELOG。
- v0.23.25 完成后在本文件追加最终默认值、资格矩阵、封版提交和遗留项。
