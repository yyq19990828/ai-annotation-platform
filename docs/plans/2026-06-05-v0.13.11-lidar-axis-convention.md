# v0.13.11 · Lidar 坐标系约定（dataset 级声明 + 加载时归一化）

> 计划日期 2026-06-05 · 范围:3D 点云数据集导入/加载链路,新增「lidar 系约定」声明 + 平台内统一归一化到 ISO 8855(+X 前 / +Y 左 / +Z 上),解决 SUSTechPOINTS 示例(以及任何非 ISO 数据集)进来 BEV「歪」/「车头朝下」/「画框朝向错」的根因。

## 1. 背景与目标

### 1.1 现状

平台 3D 链路全部假设 **lidar/world 系 = ISO 8855(+X 前 / +Y 左 / +Z 上)**:

- `cameraAnchor.ts` 按外参 forward 落 anchor(`extWithForward(1,0,0) → top`)。
- `frontCameraForward`(`ThreeDWorkbench.tsx:167-179`)取 front 相机外参 row 2 作 BEV「正上方」朝向。
- `psrFromPoints`(`autofit.ts:265-302`)框选拟合,新建 PSR 朝向 `rotation=[0,0,0]`,即世界 +X 朝前。
- `applyHeightColors`(`PointCloudScene.ts:179-202`)、`estimateGroundZ`(`ground.ts:18`)用 world Z = 高度。

但 lidar/ego 系约定在业界是**碎片化**的(KITTI、SUSTechPOINTS、Apollo、自研厂商 SDK 各异),仅 nuScenes / Waymo / Autoware 默认 ISO。强制要求所有数据集走 ISO 不现实。

### 1.2 实测案例

SUSTechPOINTS 仓库示例(`third-party/SUSTechPOINTS/data/example/calib/camera/front.json`):

```
R(row-major) =
[-0.9994,  0.0330, -0.0039]
[ 0.0025, -0.0419, -0.9991]
[-0.0332, -0.9986,  0.0418]
```

- row 2 ≈ (-0.033, -0.999, 0.042) → 平台读出 `forward = (-0.033, -0.999)` ≈ **-Y**。
- 反解:该数据集 lidar 系约定为 **+X 车左 / +Y 车后 / +Z 天**(相对 ISO 8855 绕 Z 转 180° 后再镜像)。
- 结果:BEV 渲染呈现车头朝下、AABB 画框沿世界轴对齐 → 看到的是「躺在 -Y 方向的物体被一个沿 +X/+Y 对齐的盒子框住」,所有几何都歪。

### 1.3 目标

**进数据时一次性归一化,渲染/标注/导出全链路都跑 ISO 8855**——既不改源文件,也不让上层几何代码扩散「多约定分支」。

具体:

1. Dataset 级新增 `axis_convention` 声明(枚举,默认 `iso_8855`)。
2. 加载端(前端 + 服务端投影预览)按 convention 把点云坐标 / 相机外参旋转到 ISO 系。
3. UI:数据集设置中暴露该字段,上传向导第一步预览 BEV 时让用户确认/切换。
4. 已标注的框始终存「ISO 系下的 PSR」(归一化后),导出时若用户需要原系再反向旋转一次。

### 1.4 成功判据

1. 一份非 ISO 数据集(用 SUSTechPOINTS 示例作回归基线),在 dataset 设置里选对 convention 后,3D 工作台重新打开:
   - BEV 车头朝屏幕上方;
   - AxesHelper 红(X)朝上、绿(Y)朝左;
   - 框选画框 yaw=0 的初始框正好沿车身长轴对齐(因为车身长轴此时 = 世界 +X)。
2. 历史 ISO 数据集(`axis_convention=null` 或 `iso_8855`)行为完全不变(向后兼容)。
3. 切换 convention 后,已有 PSR 用 metadata 记录所采约定,前端在错配时给出 warning(避免静默把旧框算错)。
4. 新增 `axisConvention.ts` 纯几何函数全有单测;`pnpm lint` / `pnpm test` / `uv run pytest apps/api/tests/test_pointcloud_*` 全绿。

## 3. 纯几何层 — `axisConvention.ts`

### 3.1 枚举与约定表

```ts
// 平台内部约定 = ISO 8855: +X 前 / +Y 左 / +Z 上(右手系)
// 每个 LidarAxisConvention 描述「数据源系 → ISO 系」的旋转 R_norm (3x3)。
// 物理点 p_iso = R_norm · p_src;相机外参 E_iso = E_src · R_normᵀ (旋转部分,平移不变)。
export type LidarAxisConvention =
  | "iso_8855"           // +X 前 / +Y 左 / +Z 上 (Autoware / nuScenes / Waymo / 平台默认)
  | "ros_rep103"         // 同 iso_8855(ROS REP-103 = ISO 8855)— 单独列,UI 上别名更友好
  | "kitti_camera"       // +X 右 / +Y 下 / +Z 前(camera-as-world,KITTI raw)
  | "sustechpoints_demo" // +X 车左 / +Y 车后 / +Z 天(实测此 repo 自带示例)
  | "apollo"             // +X 右 / +Y 前 / +Z 上
  | "opencv_camera"      // +X 右 / +Y 下 / +Z 前(同 KITTI camera 系,别名)
  | "y_forward"          // +X 右 / +Y 前 / +Z 上(常见 Velodyne raw)
  | "raw";               // 不归一化(向后兼容历史数据集)

// 每个 convention 的 R_norm(src → iso)。3x3 列存:R_norm 的 i 列 = ISO 系下 src 第 i 轴的方向。
// 写法约定:对每个 convention 描述「src 的 +X 在 ISO 系里指哪儿」「src 的 +Y / +Z 同理」,
// 三列拼出来就是 R_norm。
const R_NORM: Record<LidarAxisConvention, [number, number, number, number, number, number, number, number, number]> = {
  iso_8855:           [1,0,0,  0,1,0,  0,0,1], // identity
  ros_rep103:         [1,0,0,  0,1,0,  0,0,1], // identity
  // SUSTechPOINTS 示例:src +X = ISO -Y(车左 → -Y);src +Y = ISO -X(车后 → -X);src +Z = ISO +Z
  sustechpoints_demo: [0,-1,0,  -1,0,0,  0,0,1],
  // KITTI camera:src +X(右) = ISO -Y;src +Y(下) = ISO -Z;src +Z(前) = ISO +X
  kitti_camera:       [0,-1,0,  0,0,-1,  1,0,0],
  opencv_camera:      [0,-1,0,  0,0,-1,  1,0,0], // 同 kitti_camera
  // Apollo:src +X(右) = ISO -Y;src +Y(前) = ISO +X;src +Z(上) = ISO +Z
  apollo:             [0,-1,0,  1,0,0,  0,0,1],
  // Velodyne raw:src +X(右) = ISO -Y;src +Y(前) = ISO +X;src +Z(上) = ISO +Z(同 apollo)
  y_forward:          [0,-1,0,  1,0,0,  0,0,1],
  // raw:不旋转,但语义上「平台不为该数据集承诺 ISO」
  raw:                [1,0,0,  0,1,0,  0,0,1],
};

export function rotationMatrixFor(c: LidarAxisConvention): Mat3 { /* return R_NORM[c] */ }
```

### 3.2 工具函数

```ts
// 点云就地旋转:positions 是 [x0,y0,z0, x1,y1,z1, ...],三元为单位左乘 R_norm。
// 在 worker 里大点云会更快;v1 先在主线程做,DECIMATE 后实测 100w 点 < 50ms。
export function applyConventionToPositions(
  positions: Float32Array,
  convention: LidarAxisConvention,
): void;

// 外参合成:E_iso(lidar→camera) = E_src · diag(R_normᵀ, 1)
// 推导:相机物理位姿不变。原 E_src 接收 src 系 lidar 坐标 p_src;归一化后我们接收 p_iso,
// p_src = R_normᵀ · p_iso,故 E_iso · p_iso = E_src · R_normᵀ · p_iso ⇒ E_iso = E_src · diag(R_normᵀ,1)。
// 平移列不变(光心位置在世界系下不变,但世界系换了基,所以平移列也要转:
// t_iso 表达「相机原点在 iso 系下的坐标」≠ t_src 表达的「相机原点在 src 系下的坐标」。
// 完整: 对 4x4 extrinsic(lidar→camera, p_cam = E · p_lidar):
//   E_iso = E_src · M_inv,其中 M = diag(R_norm, 1),M_inv 旋转块 = R_normᵀ。
// 注意 extrinsic 的平移是「相机系下表达的 lidar 原点」,该量与 lidar 系基无关 ⇒ 平移不变。
export function applyConventionToExtrinsic(
  extrinsic: number[], // 长度 16, row-major
  convention: LidarAxisConvention,
): number[];

// 反向:导出时把 ISO 系 PSR 还原回源系(仅在用户勾选「保留原坐标系导出」时用)。
export function unapplyConventionToPsr(psr: Psr, convention: LidarAxisConvention): Psr;
```

### 3.3 单测覆盖

- 每个 convention 的旋转矩阵是合法旋转(`det(R) = +1`, `R · Rᵀ = I`)。
- `iso_8855` / `ros_rep103` / `raw` 是 identity。
- `sustechpoints_demo`:取 SUSTechPOINTS front.json 外参 row 2 = `(-0.033, -0.999, 0.042)`,经 `applyConventionToExtrinsic` 后归一化结果 row 2 应 ≈ `(1, 0, 0)`(±0.05 容差,因为示例数据本身就有几度偏)。
- 点云沿 ISO +X 的拉长棒(`[(1,0,0), (2,0,0), ...]`)在 `apollo` 系下应等价于「在源系沿 +Y 的拉长棒」,反推回去一致。
- 退化:`raw` convention 不改任何点 / 外参。

class Dataset(Base):
    # ... 现有字段 ...
    metadata_: Mapped[dict] = mapped_column("metadata", JSONB, server_default="{}", default=dict)

```python

def upgrade():

def downgrade():
    op.drop_column("datasets", "metadata")
```

### 4.2 metadata 结构

```python
class DatasetMetadata(BaseModel):
    """v0.13.11 · Dataset.metadata_ jsonb 结构化视图(extra='allow' 留给未来扩展)。"""
    axis_convention: LidarAxisConvention | None = None  # 默认 None = 不设;前端按 iso_8855 处理
    model_config = ConfigDict(extra="allow")
```

`Dataset` API schema:

```python
class DatasetRead(BaseModel):
    # ... 既有字段 ...
    axis_convention: LidarAxisConvention | None = Field(default=None, description="点云 lidar 系约定")

class DatasetUpdate(BaseModel):
    axis_convention: LidarAxisConvention | None = None
```

`POST /datasets` / `PATCH /datasets/{id}` 把 `axis_convention` 透到 `metadata_["axis_convention"]`。

### 4.3 回填

历史数据集:`metadata_ = {}` ⇒ `axis_convention = None`。前端拿到 None 时**不旋转**(等价 `iso_8855`),与旧行为完全一致,向后兼容。

## 5. 前端 — 接通归一化

### 5.1 task payload 透出

`/tasks/{id}` 返回的 task payload 里,3D 项额外带:

```ts
type TaskPayload3D = {
  // ... 既有 ...
  axis_convention?: LidarAxisConvention | null;  // 来源 dataset.metadata.axis_convention
};
```

后端 `task.py` 组装时直接读 `dataset.metadata_.get("axis_convention")`,无 join 成本。

### 5.2 PointCloudScene.loadPcd

`loadPcd(url)` → `loadPcd(url, convention: LidarAxisConvention = "iso_8855")`:在第 151 行 `srcGeom.dispose()` 之后、`applyHeightColors` 之前,对 `positions` 调用 `applyConventionToPositions(positions, convention)`。

注意 `baseColors` 在 `applyHeightColors` 内由 z 着色 → 必须在旋转**之后**算,否则色带歪;现有代码顺序正好符合。

### 5.3 ThreeDWorkbench

`cameras` 数组的 `calibration.extrinsic` 在投影/锚点用之前用 `applyConventionToExtrinsic` 旋转一次,缓存到 component state(避免每帧重算):

```ts
const normalizedCameras = useMemo(
  () => cameras.map((c) => c.calibration
    ? { ...c, calibration: { ...c.calibration, extrinsic: applyConventionToExtrinsic(c.calibration.extrinsic, axisConvention) } }
    : c),
  [cameras, axisConvention],
);
```

之后 `frontCameraForward(normalizedCameras)` / `cameraAnchor` / `projectPoints` 全部用归一化后的版本——它们不需要知道 convention 存在。

### 5.4 PSR 一致性

新建框、autofit、TransformControls 拖拽得到的 PSR 都已经在 ISO 系下。落库到 annotation.payload 时,**额外记 `convention_at_create: LidarAxisConvention`**:

```ts
type AnnotationPayload3D = {
  psr: Psr;
  // ... 既有 ...
  convention_at_create?: LidarAxisConvention;  // v0.13.11 新增
};
```

打开旧框时若 `convention_at_create` 缺失,假定 `iso_8855`(因为 v0.13.11 之前的所有标注都是按 ISO 默认假设画的)。若当前 dataset convention 与历史标注的 `convention_at_create` 不一致(用户中途切换),前端 toast warn + 提供「按新 convention 重投影」/「保持原样」按钮——v1 不自动改,留给用户决策。

### 6.3 自动嗅探(辅助,非强制)

`PATCH /datasets/{id}/sniff-axis-convention`:
1. 取数据集第 1 帧 front 相机外参(若存在);
2. 算 row 2 → forward 向量;
3. 与 8 个 convention 的预期 forward 比对(`iso_8855` 期望 (1,0,0)、`sustechpoints_demo` 期望 (0,-1,0)、...);
4. 返回最匹配的 convention(夹角阈值 15°)+ 余弦相似度,前端弹「检测到约定 `sustechpoints_demo`,是否应用?」。

无 front 相机时返回 `null`,用户手选。

## 7. ADR 要点(docs/adr/00NN-lidar-axis-convention.md)

题目:**为什么选「加载时归一化」而非「内部多约定分支」**

| 备选方案 | 优点 | 致命缺点 |
|---|---|---|
| A. 平台内部多约定共存,渲染/标注代码读 convention 走分支 | 不改 PCD 字节 | 6+ 个几何函数(`cameraAnchor` / `frontCameraForward` / `psrFromPoints` / `applyHeightColors` / `estimateGroundZ` / `fitYaw` / ...)全要加 convention 参数,扩散巨大;每次新增 convention 全链路回归 |
| B. 导入时改写 PCD 字节 / 改写外参 JSON | 后续任何工具读到的就是 ISO | 破坏「不动用户原始数据」原则;导出还要反写 |
| **C. 加载侧旋转(本方案)** | 上层代码无感知 / 不动源文件 / convention 是单一开关 | 每次打开页面要旋转一遍(已实测 < 50ms,可忽略) |

选 C。

## 8. 实施顺序(从低风险到高风险)

1. **纯几何 + 单测**:`axisConvention.ts` + 测试,可独立合入,不影响任何渲染。
2. **后端 schema + 迁移**:`Dataset.metadata_` jsonb 列,API 字段透出。后端测试`test_datasets.py` 加 `axis_convention` CRUD 用例。
3. **前端归一化接通**:`PointCloudScene.loadPcd` 接 convention;`normalizedCameras` 落地。**先全部默认 `iso_8855`**,验证 ISO 数据集(现有 `seed_pointcloud.py` 夹具)行为无变化。
4. **UI:AxisConventionPicker + 数据集设置**。
5. **自动嗅探端点**(可后置)。
6. **annotation payload 字段 `convention_at_create`** + 跨约定 toast。
7. **文档 + ADR + CHANGELOG**。

## 9. 风险与未尽事项

- **单数据集多 lidar 不同系**:v1 假定一个数据集只有一个 lidar 系;若未来支持多 lidar(融合标注),要把 `axis_convention` 下沉到 sensor / lidar 子项,而非 dataset 级。
- **标定外参的 column-major / row-major 歧义**:平台 schema 文档已注「row-major」;`applyConventionToExtrinsic` 单测里要覆盖一次 row→col 错认的反例,确保归一化数学不会被布局误读吞掉。
- **导出反向映射**:本期不实现导出端反向;留 v0.13.12 实现 `coco_pcd_export.unapply_convention` 选项。
- **跨帧 `convention_at_create` 漂移**:用户中途切了 convention 但旧框没重投影,V1 只 warn。重投影本身是个矩阵作用(`R_new · R_oldᵀ` 作用到 PSR center/rotation),数学很简单,但需要单独的 batch 任务 UI,延后。
- **PCD intensity / RGB 字段**:旋转只作用于 position xyz,intensity / RGB 不变(它们是标量/无方向量),无需特殊处理。
