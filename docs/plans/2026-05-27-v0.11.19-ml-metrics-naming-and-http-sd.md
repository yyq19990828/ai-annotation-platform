# v0.11.19 · ML 指标命名统一 + Prometheus 自动发现接入

> Epic 切片 1/3 · 见 [observability epic](2026-05-27-v0.11.19-21-ml-backend-observability-epic.md)
> 依赖：无 · 用户可见：否（后端 + 配置层；Grafana Explore 可查到指标）

## 目标

让 Prometheus 真正抓到两个 ML backend 的 `/metrics`，并以 `ml_backends` 表为单一真相源**自动发现**新 backend；同时统一两个 backend 的指标命名、补齐 GPU 显存埋点，为 v0.11.20 的 Grafana 面板铺路。

## 任务

| `sam3_inference_latency_seconds{prompt_type,cache}` | `inference_latency_seconds{prompt_type,cache}` | label 比 grounded-sam2 多，无妨（同名指标 label 集可不同实例不同） |
| `sam3_gpu_utilization_percent` | `gpu_utilization_percent` | |

**先比对**：动手前用 `grep "Counter(\|Gauge(\|Histogram(" apps/grounded-sam2-backend/observability.py` 拿到 grounded-sam2 的确切字符串名（尤其 `embedding_cache_*` / `inference_latency_*` 的 `_total` 后缀、bucket 边界），sam3 完全照抄字符串名，确保跨 backend 同名。

> **指标语义靠 `service` label 区分实例（v0.11.19-C 注入），不靠名字前缀**——这是本切片命名改造的全部理由。

### B. 补 GPU 显存 gauge（两个 backend 都加）

现状：`/metrics` 只有 `gpu_utilization/temperature/power` + `container_cpu/memory_percent`，**没有 GPU 显存**；显存（`memory_used_mb` / `total_mb` / `free_mb`）只在 `/health` 的 `gpu_info`。没有它 v0.11.20 画不了显存趋势。

两个文件各加两个 gauge，在已有的「同步采样一次 GPU + 容器指标」函数里顺手 `.set()`（数据 `/health` 已经在采，零额外开销）：

- `apps/grounded-sam2-backend/observability.py`
- `apps/sam3-backend/observability.py`

```python
GPU_MEMORY_USED = Gauge("gpu_memory_used_mb", "GPU 已用显存 (MB)")
GPU_MEMORY_TOTAL = Gauge("gpu_memory_total_mb", "GPU 总显存 (MB)")
# 采样函数内（已算出 gpu_info 时）:
GPU_MEMORY_USED.set(used_mb); GPU_MEMORY_TOTAL.set(total_mb)
```

> 显存占用率在面板侧用 `gpu_memory_used_mb / gpu_memory_total_mb` 算，不再单独埋 percent gauge。

### C. API http_sd 端点

文件：`apps/api/app/api/v1/`，新增内部路由（命名参考既有 `_test_seed.py` 的 `include_in_schema=False` 约定）。

- 路由：`GET /api/v1/internal/metrics-targets`，`include_in_schema=False`（**不进 OpenAPI 快照**，契合 pre-commit openapi 钩子，避免假 diff）。
- 逻辑：
  ```python
  rows = await db.execute(select(MLBackend).where(MLBackend.state != "disconnected"))
  # ml_backends 是 project-scoped, 同一物理 backend 可能多条 → 按 host:port 去重
  by_target = {}
  for b in rows.scalars():
      hostport = _url_to_hostport(b.url)   # 剥 scheme/path, 取 host:port
      if not hostport: continue
      by_target.setdefault(hostport, b)     # 首条胜出 (或挑 is_interactive/最近 checked)
  return [
      {"targets": [hp],
       "labels": {"service": b.name, "backend_id": str(b.id),
                  "project_id": str(b.project_id)}}
      for hp, b in by_target.items()
  ]
  ```
- 鉴权：与 backend `/metrics`、anno-api `/metrics` 一致——**默认免鉴权**（内网端点，靠 nginx `/metrics`/`/internal` 网段限制，见 deploy §3）。可选 env `METRICS_SD_TOKEN`，设了则校验 `Authorization: Bearer`。
- `service` label 用 `b.name`（用户起的名，可能不唯一）；`backend_id` 才是稳定唯一键，面板/告警按需选用。

### D. prometheus.yml 改 http_sd

文件：`infra/prometheus/prometheus.yml`，新增 job（保留 anno-api / self 不动）：

```yaml
  - job_name: ml-backends
    http_sd_configs:
      - url: http://host.docker.internal:8000/api/v1/internal/metrics-targets
        refresh_interval: 30s
    # 兜底: API 自动发现不可用 (无 host 网络 / 独立 GPU 机) 时手填:
    # static_configs:
    #   - targets: [grounded-sam2-backend:8001]
    #     labels: { service: grounded-sam2 }
    #   - targets: [sam3-backend:8002]
    #     labels: { service: sam3 }
```

> **网络视角风险**（epic 已记）：`ml_backends.url` 是 API 视角地址，Prometheus 是 prometheus 容器视角。初版直接用 `url` 的 host:port，dev 需保证 prometheus 与 backend 同 compose 网可达（service DNS）；不通的 target 表现为 `UP=0`（无害可诊断）。生产 backend 在独立 GPU 机时用兜底 static。

## 验证

1. `docker compose --profile monitoring --profile gpu --profile gpu-sam3 up -d`（+ host 上 API），在超管注册两个 backend。
2. Prometheus `http://localhost:9090/targets`：`ml-backends` job 出现两个 target，`UP`。
3. Grafana Explore：`gpu_utilization_percent{service="grounded-sam2"}` 与 `{service="sam3"}` 都有数据；`gpu_memory_used_mb` 两 backend 均有。
4. 新注册第三个 backend（或改 state），≤30s 后 `/targets` 自动出现，**未改任何配置**。
5. **PerfHud 回归**：超管「模型市场」面板 sam3 的 GPU/cache 实时数仍正常（证明改 `/metrics` 名未碰 `/health`）。

## 风险 / 决策点

- **sam2/sam3 镜像需 rebuild**：改了 `observability.py`（在镜像内，非 volume 挂载），按 CLAUDE.md §8 必须 `docker compose build` 两个 backend。
- **project-scoped 去重策略**：同 url 多条记录时挑哪条的 name 当 label？初版"首条胜出"，如需更稳可挑 `last_checked_at` 最新或 global-scope 优先——记为可迭代点。
- **`/internal` 鉴权**：默认免鉴权依赖网络隔离；若 API `/api/v1/internal/*` 已有统一守卫（如内网中间件），http_sd 端点须沿用，动手前确认。
