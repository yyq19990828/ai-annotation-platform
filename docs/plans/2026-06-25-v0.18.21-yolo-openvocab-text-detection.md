## Epic 总览 (yolo 开集补强)

把现有「纯闭集批量」的 yolo-backend 扩成支持开集。**模型类零新仓**: ultralytics (pin `>=8.4.0,<8.5`，部署容器实测 **8.4.77**) 原生内置 `YOLOWorld` / `YOLOE` 两个模型类，无需拉新仓。
**但非零依赖**: 文本提示需 CLIP / MobileCLIP 文本编码器，当前镜像缺失 → 本版需改 Dockerfile 重建 (见 §3.1bis)。

| 版本 | 能力 | 提示类型 | 平台路由 | is_interactive |
|---|---|---|---|---|
| **v0.18.21 (本版)** | YOLO-World / YOLOE 开集**文本检测** (bbox) | text | 批量文本面板 | false |
| v0.18.22 | YOLOE 开集**文本分割** (mask) | text | 批量文本面板 | false |
| v0.18.23 | YOLOE **visual prompt exemplar** (框样例) | exemplar | 交互工具 | **true** |

依据平台铁律「文本 = 批量」(`docs/plans/2026-06-09-v0.14.18-ml-backend-capability-routing.md`): 文本 prompt 走批量面板，不进交互工具栏。故文本版 (21/22) backend 维持 `is_interactive: false`，只有 exemplar 版 (23) 翻成 true。

## 1. 背景 / API 事实 (源码核对)

ultralytics 源码 (`third-party/onnxtools/third_party/ultralytics/ultralytics/models/yolo/model.py`):
- `YOLOWorld` (`:121`): 开集**仅检测**。`set_classes(["person","bus"])` 写入 CLIP 文本嵌入 → `predict(img)`。"prompt-then-detect"。
- `YOLOE` (`:192`): 开集**检测 + 分割** (`-seg` 权重二者皆可)。文本路径 `get_text_pe(names)`→`set_classes(names, pe)` (`:254`,`:306`)。

关键性能点: `set_classes` 每次会跑 CLIP 文本编码 (`get_text_pe`)，**必须缓存**，否则每张图重算。

## 2. 目标 / 非目标

**目标**: yolo-backend `/setup` 暴露开集文本检测模型；批量文本面板能选中并以文本 prompt 出框；文本嵌入按类名缓存。

**非目标**
- 不做分割 (→ v0.18.22)、不做 visual prompt 交互 (→ v0.18.23)。
- 不把开集权重混进现有闭集 `MODEL_MATRIX` (独立 model id)。
- 不做 YOLOE 免提示开集 (prompt-free 内置词表) —— 价值低，现有 yolo/gsam2 批量已覆盖。

### 3.1bis 文本编码器依赖 (⚠️ 当前镜像跑不通，必须改 Dockerfile 重建)

**实测发现**: 当前 `yolo-backend` 镜像缺全部文本编码器依赖 (`clip`/`ftfy`/`regex`/`mobileclip` 均 MISS)，
且 ultralytics 首次文本推理会**运行时** `pip install git+https://github.com/ultralytics/CLIP.git`，
但容器**连 `git` 都没装** (`apps/yolo-backend/Dockerfile` 只装了 curl/ca-certificates/libgl1/libglib2.0-0)
→ AutoUpdate 直接失败，文本提示完全不可用。

依赖链 (ultralytics `nn/text_model.py`):
- **YOLO-World** `set_classes` → `build_text_model("clip:ViT-B/32")` → 需 `clip` (ultralytics CLIP fork) + 下载 CLIP ViT-B/32 权重。
- **YOLOE** `get_text_pe` → 默认走 `MobileCLIPTS` (TorchScript `mobileclip_blt.ts`)，用 `clip.clip.tokenize` → **也需 `clip`** + 下载 `mobileclip_blt.ts`。

**Dockerfile 改动 (本版必做，属依赖变更 → `docker compose build` 重建，CLAUDE.md §8)**:
1. apt 增 `git` (ultralytics 兜底 git 安装 / 拉 CLIP 仓需要)。
2. `pip install "git+https://github.com/ultralytics/CLIP.git"` (固定到镜像层，不靠运行时 AutoUpdate)。
3. **构建期预下载**文本编码器权重 (CLIP ViT-B/32 + `mobileclip_blt.ts`) 到 `WEIGHTS_DIR`，
   避免首个文本 `/predict` 现场下载 (慢 + 依赖运行时外网)。
4. (按需) `git+https://github.com/ultralytics/mobileclip.git` —— 仅当确认 YOLOE 不走 TS 路径才需要；
   默认 TS 路径只需上面的 `clip` + `.ts` 权重，实现期实测确认。

#### 实测验证 (2026-06-25, 部署容器内端到端跑通)

在运行容器 `ai-annotation-platform-yolo-backend-1` 临时装 `git` + 让 ultralytics 自动装 CLIP fork 后，两条链均跑通 (bus.jpg 测 person/bus)：

| 链路 | 模型权重 | 文本编码器下载 | 文本编码 (含下载) | predict (warm) | 结果 |
|---|---|---|---|---|---|
| YOLO-World `yolov8s-worldv2` | 24.7MB | CLIP ViT-B/32 **338MB** | 23.1s | **0.8s** | person×4 + bus，conf 0.89–0.91 ✅ |
| YOLOE `yoloe-11s-seg` | 26.5MB | MobileCLIP `mobileclip_blt.ts` **572MB** | 12.4s | **0.7s** | person×5 + bus + **masks=True** ✅ |

结论:
- **整条链可行**，predict 本身 <1s；首次慢全在「编码器下载 (合计 ~900MB) + CLIP 现装 14s」—— 故 §3.1bis 的「构建期预装+预下载」是必须的，否则首请求体验极差且依赖运行时外网。
- CLIP fork 现装只额外引入 `clip`/`ftfy`/`regex` 三个纯 Python 包，无 C 扩展，烤进镜像无障碍。
- YOLOE `-seg` 权重 predict 同时返回 masks → **v0.18.22 分割路径同步证实可行** (同权重免再下)。
- ⚠️ 镜像体积: 文本编码器 ~900MB 烤进镜像会显著增大 (当前镜像已 18.2GB)；可考虑放挂载卷预热而非烤进层，实现期定。

### 3.2 `/setup` 新增 model 条目

`apps/yolo-backend/main.py` (`:383-419`): 新增 (示例 id):
- `detect-world`: `task=detection`, `model_family=yolo-world`, `supported_prompts=["text"]`, `supported_geometric_outputs=["bbox"]`, `output_attribute_types=["class"]`, variants 轴 = world 系列档位。
- `detect-yoloe`: `task=detection`, `model_family=yoloe`, `supported_prompts=["text"]`, 同上，variants 轴 = yoloe 系列档位。

backend 级 `is_interactive` 保持 **false** (文本=批量)。

平台侧无需改: capability 提取已逐 model 读 `supported_prompts` (`apps/api/app/services/ml_capabilities.py`)；前端文本路径 (`usePreannotateConfig.ts:169-177`，要求 `task∈GEOMETRIC_TASKS` 且 `supported_prompts` 含 `text`) 会自动收纳这两个 model，与 gsam2 text 同列。

### 3.3 Context schema

`apps/yolo-backend/schemas.py` (`Context`, `:56-82`):
- 新增 `text: str | None = None` 字段 (逗号/换行分隔多类名)。
- 由 variants 的系列值 (world / yoloe) 决定走哪条开集分支；现有 `type=detection` 复用。

> 设计取舍: 复用 `type=detection` + 新 `text` 字段 + 系列变体分流，避免新增 `type` 枚举。实现期若发现与现有 `type` Literal 校验冲突，退化为新增 `type="open_vocab_detection"`。

### 3.4 predictor 开集分支

`apps/yolo-backend/predictor.py`:
- world 分支: `YOLOWorld(weight)` → `set_classes(classes)` → `predict(img, conf, iou)` → 映射 `rectanglelabels` (复用现有 detection 坐标归一化)。
- yoloe 文本分支: `YOLOE(weight)` → `set_classes(classes, get_text_pe(classes))` → `predict` → 同映射。

### 3.5 文本嵌入缓存 (性能关键)

- 新增按 `(model_key, tuple(sorted(classes)))` 的 PE/embedding 缓存，命中则跳过 CLIP 文本编码直接 `set_classes(classes, cached_pe)`。
- 缓存随模型 evict 一并清理，避免与 `model_pool` 生命周期错位。

### 3.6 model_pool

`apps/yolo-backend/model_pool.py`: pool key 由现有 `(task, series, size)` 扩到含 model_family (closed / world / yoloe)，以便闭集与开集权重并存于同一 LRU。开集模型加载类从 `YOLO` 换成 `YOLOWorld`/`YOLOE`。

## 4. 验收
- `/setup` 出现 `detect-world` / `detect-yoloe`，`supported_prompts=["text"]`。

## 5. 风险
- **文本编码器依赖 (最大风险)**: 见 §3.1bis。当前镜像缺 clip/mobileclip + 无 git，必须改 Dockerfile 重建并预下载权重，否则文本提示直接失败。
- **显存**: world/yoloe 权重 + CLIP/MobileCLIP 文本编码器与现有闭集/其他 backend 同卡共存，pool LRU 需覆盖；本机 GPU 仅 8G，开集大档可能跑不动，验收以 s 档为主。
- **权重名**: 已按 release v8.4.0 核对 (§3.1)，文件名确定可下载，风险消除。
- **Context 复用 vs 新 type**: 见 §3.3 取舍，实现期定。
