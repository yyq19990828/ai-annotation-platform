## 1. 背景与目标

### 1.1 要迁的交互(对照现状)

视频交互现在全在 SVG `VideoInteractionLayer.tsx`(裸 `<svg>` + onPointer*):

| 交互 | 现状 | Konva 归宿 |
|---|---|---|
| 画框 draft | `onBeginDraw`(`VideoStage.tsx:1268`)→ drag.kind="draw" | Konva 空白 pointerdown → ToolPointerContext draw |
| 移动框 | `onBeginMove`(`:1283`) | Konva 形状 pointerdown → drag move |
| resize | `onBeginResize`(`:1298`),8 方向句柄 `VideoInteractionLayer:19-28` | Konva 句柄形状 + `applyResize`(纯函数复用) |
| 平移画布 | `onBeginPan`(`:1259`,右键/hand) | Konva Stage drag 或自定义 pan |
| 命中测试 | `pickTopVideoEntryAt`(`videoStagePicking.ts`,纯函数) | **复用**;Konva 只供指针坐标 |
| 选中 | selectedId/selectedIds(共享 state) | 不变,事件源换 Konva |

### 1.2 复用图片工具层范式

- 图片用 `ToolPointerContext + DragInit`(`ImageStage.tsx`,与 Konva 解耦)。视频接同一抽象:`videoTool`(`useWorkbenchState.ts:114`)驱动,draft/move/resize 走同款 drag 状态机。
- **命中判定保持纯函数**:沿用 `pickTopVideoEntryAt` + `applyResize`(已测、行为已知),Konva 只提供 `getRelativePointerPosition()` 坐标,**不**改用 `stage.getIntersection`——避免命中行为漂移(右键菜单可按图片用 getIntersection,但框选/拖拽用几何 pick 保持现状)。

### 1.3 测试迁移(本 epic 最大风险的兑现)

- 视频现有强 RTL(`VideoStage.test.tsx` 查 `video-overlay`/`video-track-shape`/`video-selected-shape` + `fireEvent` 指针,见 v0.16.0 §1)在 Konva 下失效。
- 迁到 v0.16.0 的 **react-konva mock**:形状传 `name` → mock 转 `data-testid`,`fireEvent` 沿用;断言风格基本保留。
- 纯逻辑测试(`videoStagePicking.test.ts`/`ResizeHandles.test.ts`/`drawGuard.test.ts`/几何)**100% 不动**。
- 补 **Playwright 视频交互冒烟**:画框/选中/拖拽/缩放真渲染。

### 1.4 成功判据

1. flag 开 → 视频画框/移动/resize/平移/选中/右键菜单**功能对等**旧栈(逐项手工 + e2e 验收)。
2. 关键帧编辑、track 传播热区、邻帧叠加等视频特有交互行为不变(上层逻辑不动,仅事件源换)。
3. `VideoStage` 系测试迁到新基建后**全绿**;纯逻辑测试零改动仍绿。
4. Playwright 视频交互冒烟通过。
5. 新栈在功能对等检查单上全勾(见 §6),具备 v0.16.4 切默认的条件。

## 3. 设计要点

### 3.1 Konva 事件 vs window 级指针

- 图片混用 Konva 形状事件(选中/拖顶点)+ window pointermove(拖拽过程)。视频沿用:`pointerdown` 在 Konva 形状/句柄/空白上分流,`pointermove`/`pointerup` 挂 window 跟踪 drag,松手 commit。
- draft 实时预览画在 overlay layer(v0.16.2 的 pending draft)。

### 3.2 命中:几何 pick 为主

- 框选/拖拽用 `pickTopVideoEntryAt(entries, point)`(逆序、含 padding),坐标来自 `stage.getRelativePointerPosition()` 经 `videoKonvaCoordinates` 转归一化。**保持现有命中语义**(z 序、padding 容差)。
- 右键上下文菜单可用 `stage.getIntersection`(抄图片 `ImageStage.tsx:897`),二者并存不冲突。

### 3.3 测试 mock 对接

- 所有可被测的 Konva 形状(track 框、句柄、draft)传 `name="video-track-shape"` 等 → mock 转 `data-testid`,**沿用现有选择器名**,使 `VideoStage.test.tsx` 的断言迁移成本最小。
- `fireEvent(getByTestId("video-overlay"), pointer(...))` → 改为对 mock 的 Stage/Layer DOM stand-in 触发;`setRect` mock getBoundingClientRect 仍适用。

### 3.4 邻帧机会项(可裁剪)

- 视频此前邻帧**绘制**能力有限(配置存在,绘制未充分);迁 Konva 后在 tracks layer 顺手补齐可选。**非对等必需**,排期紧可移出本版,不影响切换。

## 5. 已知风险 / 未尽事项

- **拖拽手感漂移**:Konva 事件坐标精度/节流与 SVG 不同,resize/draft 边界可能微差;以纯函数 `applyResize` 守住计算,事件层只调坐标,逐操作 e2e 对照。
- **测试改造工作量**:`VideoStage.test.tsx` 体量大(画框/拖拽/播放/历史/缓存),迁移是本版主要成本;先迁交互相关用例,播放/缓存类若与渲染栈无关可少动。
- **mock 与真渲染差距**:mock 测交互/props,真命中/拖拽精度靠 Playwright 兜底,文档写清分工避免误信 mock。
- **右键 getIntersection × 透明形状**:Konva 命中图对低 alpha 填充的拾取需 `hitStrokeWidth`/`perfectDrawEnabled` 调校,对照图片现状。
