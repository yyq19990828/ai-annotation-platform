# v0.18.22 · YOLOE 开集文本分割 (text → mask, 批量面板)

> 草案 (2026-06-25). **yolo 开集 epic 第 2/3 版**。**依赖 [v0.18.21](2026-06-25-v0.18.21-yolo-openvocab-text-detection.md)** 的共享改造 (Context.text / 开集 model_pool / text PE 缓存) 已落地。
> 本版是小增量: 在 21 的文本路径上加 YOLOE 分割输出。

## 1. 背景

YOLOE 的 `-seg` 权重同时具备检测与**实例分割**能力 (`third-party/onnxtools/third_party/ultralytics/ultralytics/models/yolo/model.py:192`，`task_map` 含 `segment`)。v0.18.21 已接入 YOLOE 文本检测 (bbox)，本版让同一文本路径输出 mask (polygon)，补齐「开集文本分割」。YOLO-World 无分割头，本版仅涉及 YOLOE。

> **已实测证实** (2026-06-25, v0.18.21 §3.1bis): 容器内 `yoloe-11s-seg` 文本推理 `r.masks is not None == True`，
> 同权重免再下、预测 <1s。本版纯属在 21 的文本路径上把 mask 取出并映射，无新模型/新依赖。

## 2. 目标 / 非目标

**目标**: yolo-backend `/setup` 暴露 `segment-yoloe` 开集文本分割模型；批量文本面板选中后以文本 prompt 出多边形 mask。

**非目标**: 不涉及 visual prompt 交互 (→ v0.18.23)；不做 YOLO-World 分割 (无此能力)。

## 3. 设计与改动

### 3.1 `/setup` 新增 model 条目
`apps/yolo-backend/main.py`:
- `segment-yoloe`: `task=segmentation`, `model_family=yoloe`, `supported_prompts=["text"]`, `supported_geometric_outputs=["polygon"]` (或 `mask`，与现有 yolo segment 对齐), `output_attribute_types=["class"]`，variants 轴 = yoloe 系列档位。
- backend `is_interactive` 仍 false。

### 3.2 predictor 分支
`apps/yolo-backend/predictor.py`:
- yoloe 分割分支: `YOLOE(seg_weight)` → `set_classes(classes, get_text_pe(...))` → `predict` → 取 masks。
- mask → polygon 复用**现有 yolo segment 的 mask→polygon 简化链路** (现有 `segmentation` 分支已有 simplify tolerance 处理，见 `docs/research/13-simplify-tolerance-eval.md`)，映射 `polygonlabels`。

### 3.3 复用 21 的基础设施
- Context.text、text PE 缓存、开集 model_pool key (含 yoloe family) 全部复用，无新增。
- yoloe det 与 seg 共用同一 `-seg` 权重时，model_pool 应避免重复加载 (同权重不同 task 复用同一句柄)。

## 4. 验收
- `/setup` 出现 `segment-yoloe`，`supported_prompts=["text"]`，几何输出 polygon。
- 批量文本面板选中 → 文本类名 → 返回 `polygonlabels` mask。
- mask→polygon 简化质量与现有闭集 segment 一致 (无明显锯齿/顶点爆炸)。

## 5. 风险
- 分割比检测更吃显存，8G 卡上大档慎用。
- mask→polygon 简化参数对开集小目标可能需微调 (沿用闭集默认先验证)。
