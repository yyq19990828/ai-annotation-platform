# v0.24.15 持久化多相机人工成员与投影质量闭环

## 状态

- Date: 2026-08-26
- Status: Implemented
- Scope: LiDAR 工作台、SceneTrack、3D Quality、KITTI 导出
- Release target: v0.24.15

## 目标

把相机图上的人工 2D 框从瞬时辅助工具提升为可持久、可并发编辑、可追溯的多模态成员，同时保留 3D 框和各相机 2D 框都是人工真值的语义。实时 3D→2D 投影只作为派生参考，不覆盖人工 2D 成员。

本版同时冻结标定 revision 和投影语义，让投影残差可以进入 3D Quality 治理闭环，并使 KITTI 导出能明确选择人工 2D 真值或派生投影。

## 不做什么

- 不在本版加 polygon / mask 相机成员；只完成 bbox 的端到端闭环。
- 不启用尚未受信的 nuScenes 导出，不伪造 token / pose / timestamp 链。
- 不让标定变更自动改写已存的人工 2D 框。
- 不另造 object ID；跨帧对象身份继续由 `SceneTrack.id + track_id` 权威表示。

## 决策

### 1. 统一成员模型

相机人工 bbox 作为 `annotations` 的一等版本化行：

- `geometry.type = bbox`，坐标按原图尺寸归一化到 `[0,1]`。
- `scene_track_id` / `track_id` / `class_name` 与所属 3D 对象一致。
- 新增显式传感器上下文：`sensor_dataset_item_id`、`sensor_role`、`sensor_visibility`、`calibration_revision`、`calibration_digest`。
- 数据库约束每帧每个 SceneTrack 在同一 `sensor_role` 最多一个活跃人工成员。
- LiDAR 对象类别继续复用 `lidar_box_3d` 工具单元；相机成员是该对象的另一几何表达，不新建一组可与 3D 类别漂移的工具配置。

### 2. 标定历史与关系新鲜度

- 新增 `sensor_calibration_revisions`，以 `(dataset_item_id, revision)` 保存不可变标定快照和 SHA-256 digest。
- 旧 `DatasetItem.metadata.calibration` 保留为当前读模型，兼容现有导入、投影和导出链路。
- 尚无历史行的存量标定以虚拟 revision 1 读取；首次更新时先固化基线，再写入下一 revision。
- 相机成员保存创建/编辑时的 revision 和 digest。当前 digest 变化后，成员保持人工真值不变，关系状态返回 `stale`。

### 3. 单一投影核心

把 KITTI 导出内的投影几何抽为无数据库依赖的服务，导出、相机成员 API 和 3D Quality 共用：

- 统一 ISO 8855 到源坐标系的换算。
- 统一近裁剪面、图像边界裁剪和 truncation 计算。
- 统一像素 bbox 与归一化 bbox 的转换。
- 统一 IoU、边缘差像素值与按图像对角线归一化的残差值。

### 4. Quality 规则

新增 `projection_residual`：

- 对每个活跃 3D 成员与同帧同 SceneTrack 的相机人工成员，使用当前标定计算派生 bbox。
- 默认在 IoU 低于 `0.5` 或最大边缘残差/图像对角线高于 `0.025` 时产生 warning。
- 冻结 3D/2D annotation version、标定 digest、人工/派生 bbox 和残差度量；标定或任一成员变更后 issue 变 stale。
- locator 明确带 `camera` role，工作台能定位到对应相机。
- 冻结的 metric 支持候选阈值回放，安全放松方向是降低最小 IoU 或提高最大残差。

### 5. 写入、权限与并发

- 相机成员创建要求任务可见且可编辑、源 3D 框活跃、相机 role 属于当前 task，且 SceneTrack revision 匹配。
- 更新/删除/恢复要求 annotation version；任一成员变更都令 SceneTrack revision 增加。
- 标定变更只允许项目特权用户，并以 expected revision 串行化，写审计日志。
- 列表端点与 Quality issue 始终复用 task/batch 可见性，不绕过已有安全边界。

### 6. 工作台

- 只在放大相机图与单选 3D 框时开放人工 2D 成员编辑。
- 无成员时可从当前派生投影一键固化，或拖拽新建；已有成员支持移动和边/角缩放。
- 人工 2D 框使用实线，3D 派生投影使用线框/虚线；面板显示 IoU、边缘残差、visibility 和标定过期状态。
- 所有拖动使用本地草稿，pointerup 只提交一次；请求失败恢复服务端值。

### 7. 导出

- KITTI 对当前所选相机优先使用同 SceneTrack 的活跃人工 bbox；没有人工成员时才使用当前标定派生投影。
- 人工 bbox 不改变 KITTI 3D 尺寸、位置和旋转；只替换 2D bbox，truncation 仍由人工框与画面边界的裁剪关系计算。
- 导出报告记录 `manual_bbox_count` 和 `derived_bbox_count`，使真值来源可稽核。

## 实施顺序与验证

1. 模型与迁移
   验证：`0159 → 0160 → 0159 → 0160`；部分唯一索引、上下文 check 和标定 revision 唯一约束通过。
2. 投影核心、标定服务与成员 API
   验证：投影 golden、创建/并发冲突/删除/恢复/过期关系、跨任务与跨相机拒绝。
3. SceneTrack 操作与 Quality 闭环
   验证：拆分/合并/缺席/恢复/撤销包含相机成员；投影残差扫描、stale 和阈值回放通过。
4. KITTI 导出
   验证：人工优先、无人工回退派生、来源计数与现有轴约定回归。
5. 工作台
   验证：nuScenes mini 真实相机图上新建、缩放、移动、刷新持久、标定过期显示与 Quality 定位。
6. 统一发版
   验证：后端/前端全量测试、lint/typecheck、OpenAPI 与文档构建、生产构建、Chromium E2E，再统一切到 `0.24.15`。

## 验收标准

- 同一 3D 对象可在一帧内保存多个相机 bbox，但每个相机最多一个活跃成员。
- 刷新、切帧、SceneTrack 拆分/合并、删除/恢复后成员关系不丢失。
- 标定变更后人工 bbox 不变，API/UI 明确标记 stale，Quality 旧 issue 失效。
- 投影残差规则可从问题列表定位到正确帧、3D 框和相机。
- KITTI 使用人工 bbox 时有可稽核证据，不存在时与现有受信派生路径结果一致。
- 非可见任务不能读取相机成员；不可编辑任务、版本冲突和标定冲突不产生部分写入。
