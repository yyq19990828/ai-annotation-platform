# v0.20.1 · OCR 属性语义角色 + 落点校验硬化

状态：草案（draft）。把 v0.19.2 WS1 里 `language`/`orientation` 落点判定的**字符串约定**升级为
**显式语义角色**，让校验从「猜 key 名」变成「读语义」。依赖 v0.20.0（RapidOCR 提供真实 producer）。

## 背景

v0.19.2 WS1 给 `language`/`orientation` 加了落点校验，但承接位判定是务实的**字符串约定**：

```ts
// useCapabilityValidation.ts (v0.19.2)
type === "language"    ? hasFieldKey("language")     // 项目得有 key 恰为 "language" 的字段
: type === "orientation" ? enabledToolUnits.has("rotated_bbox") || hasFieldKey("orientation")
```

问题：
- 脆弱——用户把字段 key 取成 `lang` / `text_lang` / `语言` 就漏判，校验形同虚设。
- `text` 走 `type==="text"`（字段类型），`language`/`orientation` 走 key 名，**两套判据不统一**。
- 「从 backend 导入属性」（`ImportAttributesFromBackendDialog`）导入的字段无法标记「我就是承接 language 的」。

v0.20.0 RapidOCR 落地后，`text`/`language`/`orientation` 第一次有真实输出，正是把判据做扎实的时机。

## 目标

给 `AttributeField` 加一个可选 `semantic_role`（`text` / `language` / `orientation` / `null`），
WS1 落点校验改读它；「从 backend 导入属性」按 `output_attribute_schema` 自动回填角色。校验从约定变契约。

## 工作项

### WS1 · 数据模型加 `semantic_role`（后端 + 迁移）

- `AttributeField` schema 加 `semantic_role: Literal["text","language","orientation"] | None = None`
  （`apps/api/app/schemas/...` 的 attribute field 定义 + 前端 `types.gen.ts` 随 openapi 重生成）。
- alembic 迁移：`tool_bindings` JSONB 内字段加可选键，**无需回填**（缺省 null = 旧约定回落，见 WS2）。
- 受控值由 SSOT 派生（对齐 `output_attribute_types` 的 `text/language/orientation`）。

### WS2 · WS1 校验改读语义角色（前端，带约定回落）

- `useCapabilityValidation.ts`：落点判定优先读 `semantic_role`，**回落**到 v0.19.2 的字符串约定（零退化、渐进迁移）：
  - `language` 承接位 = 任一字段 `semantic_role==="language"` **或**（回落）`key==="language"`。
  - `orientation` 同理 + `rotated_bbox` 工具仍算承接位。
  - `text` = `semantic_role==="text"` 或 `type==="text"`。
- 三类判据统一成「先看角色、再回落」，消除 text 与 language/orientation 的判据分裂。

### WS3 · 「从 backend 导入属性」回填角色（前端）

- `ImportAttributesFromBackendDialog.tsx`：从 `output_attribute_schema` 导入字段时，按 backend 自报的属性
  类型把 `semantic_role` 一并写入（RapidOCR 自报 `text`/`language`/`orientation` schema → 导入即带角色）。
- 项目「类别与属性」编辑 UI：字段编辑器暴露「语义角色（可选）」下拉，让手工建的字段也能标。

## 风险

中。带迁移（JSONB 加键）+ 跨前后端字段。但有约定回落兜底，老项目零退化。
须确认 `semantic_role` 不与既有字段校验/导出冲突（纯加法元数据，不改取值域）。

## 验收

- 字段标 `semantic_role="language"`（key 任意）→ RapidOCR 输出 language 时画布**不**再误报缺承接位。
- 老项目（字段无 role，key 恰为 "language"）→ 回落约定，行为同 v0.19.2。
- 从 RapidOCR 一键导入属性 → 字段自动带正确 `semantic_role`。

## 排期与依赖

- **依赖 v0.20.0**（RapidOCR 提供真实 `language`/`orientation` 输出供端到端验证）。
- 与 v0.20.2（一键补全）同窗口：二者都动 `ImportAttributesFromBackendDialog` + StageCard 属性链，建议合并迭代或紧邻排。

## 不在范围

- 把 `semantic_role` 提升为**必填/强约束**：保持可选 + 约定回落，避免破坏存量项目。
- 逐框语言（per-line language）落到不同字段：归属取值层，另议。
