# v0.18.4 — M4 · 多阶段预标注后端补强（crop 投递兼容 + 健壮性 + 可观测）

> 状态：**待实施 plan**（不开干）。创建于 2026-06-23。
>
> 定位：路径 B（M1–M3 已落地 v0.18.1–v0.18.3）的后端补强。核心修一个**实质兼容缺口**：下游 crop 用 `data:` base64 内联投递，只有 `onnxtools` / `yolo-backend` 的图像加载支持 `data:`，而 `gsam2`（`apps/grounded-sam2-backend/main.py:748 _fetch_image`）/ `sam3`（`apps/sam3-backend/main.py:546`）只做 `httpx.get(file_path)`，**收到 data URI 直接失败**——ROADMAP「任意现成 classify backend 零改造」目前只对支持 `data:` 的后端成立。本期把 crop 投递改成**所有后端通用**，并顺带补几处健壮性 / 可观测 / 测试缺口。

## 1. 目标 / 非目标

**目标**
1. **crop 投递通用化**：平台裁好的 crop 上传到对象存储（import 桶，短 TTL）→ presigned URL 投递，所有走 `httpx.get` 的后端零改造可作下游。`data:` 内联留作可选快路径（默认 presigned）。
2. **crop 编码复用**：并行兄弟阶段 target 同一批父框时，按 `(box_idx, pad)` 复用已裁 crop，不重复裁剪 + 重编码。
3. **可观测补强**：`PredictionMeta.extra` 记完整 pipeline 拓扑（各阶段 backend/model/写回键）；worker 下游失败由 `print()` 改 logger；逐阶段统计补「因几何不支持（旋转框/多边形）被跳过的父框数」。
4. **测试补强**：`_run_batch` 全链路 staged 集成测试（真 DB + mock client → 落库 + 统计聚合 + extra）；`drop_box` × 并行扇出交叉边界测试。

**非目标**
- 不做 chord 并行（留 v0.18.7）。
- 不做实时逐阶段进度推送（留 v0.18.6）。
- 不动前端（本期纯后端 + 测试）。
- 不改协议（presigned/data URI 都走现有 image input）。

## 2. 详细设计

### 2.1 crop presigned 投递（替换 data URI 默认）

现状 `apps/api/app/workers/roi.py::crop_inputs_from_boxes` 把 crop 编码成 `data:image/jpeg;base64,...` 放进 `inputs[i].file_path`。改为：

- 新增 worker 侧 `upload_crop(buf, key) -> url`：crop JPEG 字节上传 `settings.minio_import_bucket`（已挂 7 天 lifecycle），key 形如 `roi-crops/{job_id}/{task_id}/{box_idx}.jpg`；返回经 `ml_backend_storage_host` 重写的 presigned URL（复用 `apps/api/app/api/v1/ml_backends.py::_resolve_task_url` 的 host 重写逻辑，抽成共用 helper）。
- `crop_inputs_from_boxes` 增 `delivery: Literal["presigned", "data_uri"] = "presigned"`：presigned 时上传并回 URL；data_uri 时维持现状（快路径，仅用于已知支持 `data:` 的后端 / 单测）。
- worker `_run_task_pipeline`（`tasks.py:137`）按全局开关或恒用 presigned 投递；id 仍编码父框下标供回写（`merge_classify_attributes` 不变）。
- 临时 crop 由 import 桶 lifecycle 自动清；可选 job 终态主动删前缀。

> 取舍：presigned 多 N 次上传 I/O，但**对所有后端通用**（base 协议都支持 http(s) URL fetch）；data URI 省上传但只兼容部分后端。默认通用，性能敏感场景可切 data_uri。

### 2.2 crop 编码复用（并行兄弟）

`_run_task_pipeline` 现对每个下游阶段独立调 `crop_inputs_from_boxes`，并行兄弟 target 同一批框时**重复裁剪 + 重编码 JPEG**。改：task 内维护 `crop_cache: dict[(box_idx, pad_rounded), input]`，同 `(box_idx, pad)` 复用（presigned 复用同一 URL / data URI 复用同一串）。仅 `parent_class_filter` 不同的兄弟仍各自筛选 box 子集，但命中的 box crop 走缓存。

### 2.3 pipeline 拓扑落 extra（可追溯）

现 `PredictionMeta.extra.pipeline` 只有 `stage_count` / `enriched_attr_keys`。补 `stages` 数组：每项 `{stage, ml_backend_id, model_id, parent_class_filter, write_keys}`，让「这框的某属性来自哪个 backend/model」可审计。落库点在 `prediction.py::create_from_ml_result` 的 `pipeline_extra`（worker 已构造 extra，扩展其内容即可）。

### 2.4 worker 日志 + 几何跳过统计

- `tasks.py:198` 下游失败 `print(...)` → `logger.warning(...)`（模块已有 logger 约定，对齐）。
- `crop_inputs_from_boxes` 现静默跳过非 bbox / 旋转框；改为回报跳过数，`_run_task_pipeline` 把它累加进 `stats[si]["skipped_geometry"]`，写入 job `result.pipeline_stages`，前端可暴露「N 框因几何不支持未富集」。

## 3. 实施步骤（每步带 verify）

1. `_resolve_task_url` host 重写抽共用 helper + `upload_crop` → verify：单测上传 crop 到 import 桶、presigned URL 可被容器内拉取。
2. `crop_inputs_from_boxes` 增 `delivery` + presigned 路径 → verify：gsam2/sam3 当下游时 crop 能被拉取（此前 data URI 失败），结果带 attributes。
3. crop 缓存 → verify：双并行兄弟同框场景，裁剪/编码只发生一次（计数断言）。
4. extra 拓扑 + logger + 几何跳过统计 → verify：跑多阶段批，`PredictionMeta.extra.pipeline.stages` 完整；旋转框输入下 `skipped_geometry>0`。
5. `_run_batch` 全链路集成测试 + `drop_box`×扇出 → verify：mock 两阶段 client 跑完整 batch，断言落库框带属性、`result.pipeline_stages` 聚合正确、drop_box 阶段失败时框被丢而 keep 兄弟成功的框保留。
6. 版本收尾（CLAUDE.md §10）：bump 四处 + `uv lock` + openapi 快照；重启 celery worker 加载新代码；`curl localhost:8000/health` 验证 0.18.4。

## 4. 验收标准

- 用 gsam2 / sam3 作下游分类阶段，crop 能被拉取、属性正常合并（此前必失败）。
- 并行兄弟同框 crop 只裁一次。
- `PredictionMeta.extra.pipeline.stages` 可追溯每框属性来源 backend/model。
- 旋转框/多边形输入下，跳过数在逐阶段统计可见，不再静默。
- 全链路 staged 集成测试 + drop_box×扇出 边界测试通过。

## 5. 风险 / 开放问题

- **import 桶 crop 堆积**：依赖 lifecycle 清理；高频大批量下 7 天窗内堆积量需观测，必要时 job 终态主动删前缀。
- **presigned 上传 I/O 成本**：每父框一次上传；大批量下是新增 I/O，监控 worker 吞吐，必要时 data_uri 快路径按后端能力自动选。
- **host 重写一致性**：crop URL 与 task URL 共用重写逻辑，抽 helper 时勿改变现有 task 投递行为（回归点）。
