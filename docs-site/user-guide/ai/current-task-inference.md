# 当前题 AI 与二次推理

这两种能力都在图片工作台内完成，但输入和结果不同：**当前题 AI** 对当前整张图片生成待审候选；**二次推理**以已确认的标注为父对象，补写属性或创建子框。它们都只执行项目已有配置，不能在工作台编辑项目编排。

## 运行当前题 AI

使用场景：不需要对整个批次跑预标，只想对正在标注的这一张图片调用模型。

1. 打开图片任务，展开画布右上角的 **当前题 AI** 面板。
2. 选择该项目已启用的模型和可用参数，点击 **运行当前题**。
3. 模型结果会出现在“AI 待审”列表和画布候选层中；检查后接受、拒绝或编辑。

如果项目管理员已在[AI 预标](../projects/ai-preannotate)中保存了项目编排，面板会显示 **运行当前题（按项目编排 · N 阶段）**。它会按保存的阶段顺序执行检测、分类和属性写入，仍然把结果作为候选交给标注员审阅。

当前题 AI 与批量预标的区别是范围：它只作用于当前任务，不改变批次状态，也不会替代批量任务历史。批量运行、并发和幂等模式见[AI 预标](../projects/ai-preannotate)。

## 对已确认标注做二次推理

使用场景：已有一条人工或已采纳的图片标注，希望基于这个父框补全属性，或从中识别子物体。

二次推理只在以下条件同时满足时出现：

- 当前是图片任务；
- 选中的是已落库的人工标注或已采纳标注，不是 AI 待审候选；
- 当前未处于交互式 AI 工具状态；
- 项目已启用能处理该输入和输出的 backend。

操作步骤：

1. 选中父框，打开画布顶部的 **✦ 二次推理** 面板。
2. 选择支持的模型；按需要调整阈值、模型档位或文本提示。
3. 运行后检查结果：模型可以补写父框的缺失属性，也可以创建挂在父框下的子框。
4. 结果会立即出现在标注详情和画布中；超时或 backend 不可达时，面板会提供明确错误与重试入口。

二次推理直接更新已确认标注的属性或子标注，不走“AI 待审”候选列表。因此开始前应确认选中的父框与模型输出类型；要对整图重新生成候选，请使用当前题 AI 或批量预标。

## 控制面板显示

二次推理面板默认常显。若不常使用，可在顶部设置抽屉的“二次推理面板”开关、标注详情浮卡的 ✦ 图标，或标注右键菜单中关闭它。该偏好会跟随账号保存，重新开启后无需刷新页面。

## AI 属性溯源

标注详情中的 `✦ AI` 徽标表示某个属性键由预标、二次推理或多阶段编排写入。悬停可查看写入它的模型；人工编辑该键后，徽标会消失。一个标注的不同属性可以分别保留 AI 和人工来源。

## 与其它 AI 入口的区别

| 需要完成的事 | 入口 |
|---|---|
| 在当前图片用点、框或示例与模型交互 | [图片交互式 AI](../workbench/sam-tool) |
| 对当前整图运行模型并审阅候选 | 本页“当前题 AI” |
| 对已确认父框补属性或检测子框 | 本页“二次推理” |
| 对多个任务或批次运行模型 | [AI 预标](../projects/ai-preannotate) |
| 接受、拒绝或清理图片候选 | [审阅 AI 候选](./candidate-review) |

模型不可用、输出不匹配或入口置灰时，先检查[项目 ML 模型](../projects/ml-backends)中的项目启用、能力路由和工具开关。
