## 1. 架构决策(贯穿全 epic,违反即推倒)

| #      | 决策                                          | 反面(不要走)                                   | 理由                                                                                                               |
| ------ | --------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **J1** | **3D box_3d 是唯一真值;相机图是它的投影视图** | 相机图上单独存一套 2D 框、与 3D 双写           | 双写 = 双真值漂移。2D 操作的产物始终是 box_3d 的增删改,不另立 2D 标注存储                                          |
| **J2** | **2D 框是「瞬态种子」,不持久化**              | 把画的 2D 矩形当独立 annotation 落库           | 2D 矩形只为生成/约束一个 box_3d;落库的只有 box_3d。呼应决策底线「内部稳定 ID」「双数组分开」——不引入半吊子 2D 实体 |
| **J3** | **相机图不引入新标注类型,只引入新交互入口**   | 在相机图上做 2D bbox 工具、keypoint 等独立模态 | 那是图片工作台的活;3D 工作台的相机图只服务于 3D 标注效率。要纯 2D 标注走 image 项目                                |
| **J4** | **复用既有投影 / 拟合 / 标定,不重写**         | 自写一套相机模型                               | `projection.ts`/`autofit.ts`/`SensorCalibration` 已是真值,新代码只加「反投影 + 视锥选点」                          |

## 2. Phase 切片

### Phase 1 · 2D 框种 3D 框(frustum fit)— v0.15.24 ✅ **已落地**

在相机图上拖一个 2D 矩形 → 该相机标定反算视锥 → 框住落在锥内的点云 → `psrFromPoints` 拟合出 3D box 初值 → 切主视图微调。详细计划:[`docs/plans/archive/2026-06-14-v0.15.24-camera-2d-box-to-3d-frustum.md`](../../docs/plans/archive/2026-06-14-v0.15.24-camera-2d-box-to-3d-frustum.md)。

**已落地(v0.15.24)**:`geometry/frustum.ts`(视锥选点 + 深度门控 + 中央射线)+ `CameraProjectionView` 种框拖框交互 + 放大模态「种框」toggle 编排(选点→拟合→落 box_3d→选中)。MVP 收窄为**仅放大相机视图**启用(小浮动面板太小画不准)。详见 [CHANGELOG](../../CHANGELOG.md)。

**价值**:远处/稀疏目标在点云里难直接框,但在相机图上一眼可见、一框即生 3D 框。这是 2D 辅助 3D 的最高杠杆。

### Phase 2 · 投影手柄拖拽微调(2D 约束 3D 编辑)— v0.15.26（原 v0.15.25,主题持久化占用后顺延）

选中 3D 框后,在相机图上拖其投影的角点 / 面 → 反投影约束回 PSR(在射线 + 地面 / 深度约束下解一个自由度)。让「这个框在图上没对齐车尾」能直接在图上推一下修正,而不必切回 3D 主视图找视角。

- 难点:2D→3D 欠定(一个像素位移对应一条射线)。约束策略:锁定地面高度(`fitBottom`)、锁定深度(用 `depthmap` 当前深度)、或只允许沿相机光轴 / 切向某一自由度。MVP 先做「拖整框在像平面平移 → 沿地面平移 3D 框」。

### Phase 3 · 多相机一致性 + 2D 派生导出(可选)— v0.15.27（原 v0.15.26 顺延）

- **多相机交叉验证**:一个目标被多个相机看到,任一相机里画框/拖框,其它相机投影实时一致(已有投影实时性,补「跨相机同源编辑」闭环)。
- **2D 派生框导出**:导出时把 box_3d 投影成各相机的 2D bbox 作为**派生**字段(非独立标注,守 J1/J2),供 2D 检测训练复用。与导出 epic 同窗口。

## 3. 成功判据(epic 级)

1. 远处一辆点云稀疏的车,在相机图上一框 → 生成位置/朝向/尺寸合理的 3D box,微调 < 3 步即可标准。
2. 相机图操作的产物只有 box_3d 增删改;DB 无任何新增 2D 标注实体(守 J1/J2)。
3. 无标定相机:画框入口灰置 + 提示,绝不静默产出错位框。
4. 全程复用 `projection.ts`/`autofit.ts`/`SensorCalibration`,新几何仅 `frustum.ts`(反投影 + 选点)。

## 4. 风险 / 未尽

- **标定质量**:外参/内参不准 → 视锥选点偏、拟合框偏。依赖 `import_nuscenes_scene` 等导入端标定正确;无标定相机不开放写入口。
- **视锥内多目标**:一框圈进前后两辆车 → 选点混。Phase 1 用深度门控(最近簇优先)+ 允许手动收紧;复杂场景留 Phase 2 微调兜底。
- **欠定反投影**(Phase 2):2D→3D 必须加约束(地面 / 深度 / 单自由度),否则手感乱。MVP 只做平移自由度。
- **不滑向 2D 标注平台**:守 J3,抵制「在相机图上也能画 keypoint/polygon」的需求蔓延——那是 image 项目的范畴。
